M10RTAB-Map 3D 비주얼 SLAM

깊이 카메라 기반 RTAB-Map의 구조(메모리 관리·루프 클로저), 3D 지도 작성과 저장, 2D SLAM과의 비교.

선수 챕터: M09 M07

학습 목표#

  • RTAB-Map(Real-Time Appearance-Based Mapping)의 구성(오도메트리, 그래프, 루프 클로저 검출, 그래프 최적화, 지도 생성)을 블록도로 설명할 수 있습니다.
  • 외관 기반(appearance-based) 루프 클로저 검출에서 시각 단어 가방(Bag of Words)과 TF-IDF 유사도가 하는 일을 코드로 확인합니다.
  • 단기 메모리(STM)·작업 메모리(WM)·장기 메모리(LTM)로 나누는 메모리 관리가 왜 "실시간"을 보장하는지 설명합니다.
  • MentorPi의 rtabmap.launch.py 파라미터(Reg/Strategy, Reg/Force3DoF, Grid/RangeMin …)를 해석하고, 3D 지도를 만들고 데이터베이스를 확인합니다.
  • 2D 라이다 SLAM(slam_toolbox)과 RGB-D SLAM(RTAB-Map)을 목적에 맞게 고를 수 있습니다.

RTAB-Map이란#

RTAB-Map은 RGB-D 카메라·스테레오 카메라·라이다를 입력으로 받는 그래프 기반 SLAM 라이브러리입니다. 이름의 두 단어가 핵심입니다.

  • Appearance-Based: "여기 와 본 적 있나?"를 영상의 생김새로 판단합니다(M09의 slam_toolbox는 스캔 모양의 상관으로 판단).
  • Real-Time: 지도가 아무리 커져도 루프 클로저 검출 시간을 정해진 한도 안에 묶어 둡니다. 교재가 "메모리 관리로 지도 크기를 제한해 항상 고정 시간 안에 처리한다"고 설명하는 부분입니다.

외관 기반 루프 클로저#

시각 단어 가방 (Bag of Words)#

  1. 각 키프레임 영상에서 특징점(ORB, SURF 등 모서리·얼룩)을 뽑고, 특징점마다 기술자(descriptor, 주변 무늬를 요약한 벡터)를 계산합니다.
  2. 비슷한 기술자들을 한 시각 단어(visual word)로 묶습니다. RTAB-Map은 들어오는 기술자로 어휘 사전을 점점 키워 갑니다.
  3. 영상 하나는 "어떤 단어가 몇 번 나왔나"라는 히스토그램이 됩니다. 문서 검색처럼, 두 영상의 히스토그램이 비슷하면 같은 장소일 가능성이 높습니다.

흔한 단어(모든 방에 있는 흰 벽 무늬)는 장소를 구별하는 데 도움이 안 되므로 TF-IDF 가중치로 깎습니다.

w(단어 k, 영상 i) = (영상 i에서 k의 비율) × log(전체 영상 수 / k가 나온 영상 수)

아래 코드는 키프레임 다섯 개의 BoW 벡터와, 한 바퀴 돌아와 다시 찍은 영상의 유사도를 계산합니다.

python브라우저 실행
import numpy as np

# 시각 단어(visual word) 8개로 이루어진 작은 어휘. 각 키프레임 = 단어 출현 횟수(BoW 벡터)
frames = {
    "N1 entry":   [5, 0, 2, 0, 1, 0, 0, 3],
    "N2 hall":    [0, 4, 0, 3, 0, 2, 0, 0],
    "N3 kitchen": [1, 0, 0, 0, 6, 0, 4, 0],
    "N4 living":  [0, 1, 5, 0, 0, 0, 1, 4],
    "N5 hall-2":  [0, 3, 1, 4, 0, 2, 0, 0],
}
new = np.array([4, 0, 2, 1, 1, 0, 0, 3], dtype=float)   # 한 바퀴 돌아와 다시 본 현관

names = list(frames)
M = np.array([frames[k] for k in names], dtype=float)
df = (M > 0).sum(axis=0)                                  # 단어가 등장한 키프레임 수
idf = np.log(len(M) / df)                                 # 흔한 단어일수록 가중치↓

def tfidf(v):
    w = v / v.sum() * idf
    return w / np.linalg.norm(w)

sims = np.array([tfidf(m) @ tfidf(new) for m in M])
for n, s in zip(names, sims):
    print("%-10s similarity %.3f" % (n, s))
best = int(np.argmax(sims))
second = np.sort(sims)[-2]
print("best:", names[best], " margin over 2nd: %.3f" % (sims[best] - second))
print("loop closure hypothesis accepted:", bool(sims[best] > 0.5 and sims[best] - second > 0.2))
text
N1 entry   similarity 0.977
N2 hall    similarity 0.133
N3 kitchen similarity 0.258
N4 living  similarity 0.568
N5 hall-2  similarity 0.181
best: N1 entry  margin over 2nd: 0.409
loop closure hypothesis accepted: True
  • N4 living도 0.568로 꽤 높습니다. 거실과 현관이 비슷한 단어(2번, 7번)를 공유하기 때문입니다. 그래서 RTAB-Map은 가장 높은 점수 하나만 보지 않고, 이웃 노드들까지 고려한 베이즈 필터로 "루프 가설"의 확률을 여러 프레임에 걸쳐 누적한 뒤 문턱(기본 Rtabmap/LoopThr 0.11)을 넘을 때 채택합니다.
  • 채택된 가설은 마지막으로 기하 검증(특징점 3D 대응으로 변환을 계산하고 inlier 수 확인, MentorPi는 Reg/Strategy: 1이라 ICP로 정밀화)을 통과해야 그래프에 제약으로 들어갑니다.

메모리 관리: STM · WM · LTM#

루프 클로저 검출은 새 영상을 과거 모든 노드와 비교하므로, 지도가 커지면 처리 시간이 계속 늘어납니다. RTAB-Map은 노드를 세 곳으로 나눠 이 문제를 풉니다.

메모리들어 있는 것루프 검출 대상?
STM (Short-Term Memory)방금 만든 최근 노드 몇 개아니요 — 바로 이웃은 당연히 비슷하므로 제외
WM (Working Memory)STM에서 넘어온 노드예 — 새 영상과 비교하는 대상
LTM (Long-Term Memory)WM에서 내보낸 노드 (SQLite 데이터베이스)아니요 — 단, 루프가 닫힌 노드의 이웃은 WM으로 다시 불러옴(retrieval)

한 번 처리하는 데 걸린 시간이 한도(Rtabmap/TimeThr [ms])를 넘거나 WM 노드 수가 한도(Rtabmap/MemoryThr)를 넘으면, WM에서 가중치가 낮은(자주 다시 보이지 않은) 노드를 LTM으로 내보냅니다. 두 값이 0이면 제한이 없으므로, 설치된 버전의 기본값을 rtabmap --params로 확인합니다. 교재 설명의 "장기 메모리 데이터는 앞으로의 매칭에 쓰이고, 단기 메모리 데이터는 연속된 현재 데이터 매칭에 쓰인다"가 이 구조를 가리킵니다.

`Grid/Sensor` 값 확인하기

최신 RTAB-Map에서 Grid/Sensor는 0(라이다 스캔), 1(깊이 영상), 2(둘 다) 정수입니다. 원본 launch는 문자열 'true'를 넣는데, 설치된 버전이 이를 어떻게 해석하는지는 로봇에서 ros2 param get /rtabmap Grid/Sensor 또는 rtabmap --params | grep Grid/Sensor로 확인합니다. 3D 장애물(책상 상판)을 2D 지도에 넣고 싶다면 깊이 영상을 쓰는 값이어야 합니다.

`-d` 인자: 시작할 때 이전 지도를 지운다

매핑용 rtabmap 노드는 arguments=['-d']로 실행됩니다. -d(--delete_db_on_start)는 **시작할 때 기존 데이터베이스(기본 ~/.ros/rtabmap.db)를 지웁니다.** 3D 지도를 만든 뒤 rtabmap_slam.launch.py를 다시 실행하면 앞의 지도가 사라집니다. 보관하려면 먼저 복사합니다: cp ~/.ros/rtabmap.db ~/rtabmap_room1.db

실습 (실물)#

안전 확인 (실물 실습 전 필수)
  • 3D 매핑 중 로봇은 사람이 키보드로 움직입니다. 로봇 곁에서 계단·케이블·책상 다리를 살피며 진행합니다.
  • 키보드 조종 속도(0.2 m/s, 0.5 rad/s)를 올리지 않습니다. 빠른 회전은 영상 번짐으로 매칭 실패를 일으킵니다.
  • 교재 주의: 매핑 범위와 시간을 너무 크게 잡지 않습니다. 데이터가 많으면 이후 3D 내비게이션에서 라즈베리파이가 버벅이고, 늦은 제어 명령은 충돌로 이어집니다.
  • 멈출 때는 Ctrl+C, 계속 움직이면 ros2 topic pub --once /controller/cmd_vel geometry_msgs/msg/Twist "{}", 최후에는 전원 스위치를 끕니다.
  1. (M09에서 준비한) 가상머신과 로봇을 같은 LAN에 두고, 로봇에서 매핑을 시작합니다.
bash
# 로봇 터미널 1
~/.stop_ros.sh
ros2 launch slam rtabmap_slam.launch.py

# 가상머신 터미널
ros2 launch slam rviz_rtabmap.launch.py

# 로봇 터미널 2
ros2 launch peripherals teleop_key_control.launch.py
  1. W/S로 전·후진 상태를 바꾸고 A/D를 길게 눌러 회전하며 방을 천천히 돕니다. RViz에 점구름 지도와 2D 격자가 함께 자라는지 봅니다.
  2. 출발점 근처로 돌아와 같은 방향으로 카메라가 같은 장면을 보게 합니다(영상 기반 루프 검출은 같은 모습을 봐야 합니다). 루프가 닫히면 지도가 한 번 보정됩니다.
  3. 입력 상태를 확인합니다(새 터미널).
bash
ros2 topic hz /ascamera/camera_publisher/rgb0/image      # 약 15 Hz
ros2 topic hz /scan_raw
ros2 node list | grep -E "rtabmap|rgbd_sync"
ros2 param get /rtabmap Reg/Strategy
  1. 모든 터미널에서 Ctrl+C로 종료하면 지도가 자동 저장됩니다(별도 저장 명령 없음). 데이터베이스를 백업하고 내용을 봅니다.
bash
ls -lh ~/.ros/rtabmap.db
cp ~/.ros/rtabmap.db ~/rtabmap_backup.db
rtabmap-databaseViewer ~/.ros/rtabmap.db     # (GUI 도구가 설치돼 있으면) 노드·루프 확인
  1. 호스트 터미널에서 sudo systemctl restart start_node.service로 앱 서비스를 되돌립니다.

자주 나는 오류와 해결#

증상원인해결
rgbd_sync가 아무것도 발행 안 함컬러·깊이 타임스탬프 차이 > 0.008 s, 카메라 미실행ros2 topic hz로 두 영상 확인, 카메라 드라이버 재시작
"Did not receive data since 5 seconds!"오도메트리·스캔·영상 중 하나 없음, QoS 불일치robot.launch.py 로그 확인, /odom·/scan_raw 발행 확인
지도가 계속 겹치고 루프가 안 닫힘무늬 없는 벽, 어두움, 다른 방향에서 재방문조명 켜기, 포스터 등 특징 추가, 같은 방향으로 재방문
로봇·RViz가 점점 느려짐3D 데이터 누적(교재 경고)매핑 범위·시간 축소, 해상도·fps 낮추기
다시 실행하니 지도가 없음-d로 데이터베이스 삭제매핑 후 rtabmap.db 복사 보관, 내비게이션 launch는 -d 없이 기존 DB 사용
2D 격자에 로봇 앞 빈 원이 생김Grid/RangeMin 0.2 m 이내 제거정상. 로봇 몸체가 지도에 찍히지 않게 하는 설정

과제#

기본 과제
  1. BoW 코드의 new 벡터를 복도(N2)와 비슷하게 바꿔 보고, N2와 N5가 비슷할 때 margin 조건 때문에 가설이 기각되는 경우를 만듭니다. 왜 그런 판정이 안전한지 설명합니다.
  2. slam_toolbox와 RTAB-Map의 루프 클로저 판정 방식(M09 표와 이 장 표)을 각각 세 줄로 요약해 비교합니다.
심화 과제
  1. idf를 쓰지 않고(모든 단어 가중치 1) 코사인 유사도만으로 같은 계산을 해 보고, 결과가 어떻게 달라지는지 설명합니다.
  2. 같은 방을 Reg/Strategy 0(시각)과 1(ICP)로 각각 매핑해(launch 파일 복사본에서 값 변경) 루프 클로저 성공 여부와 CPU 사용률(top)을 비교합니다.
