R06TF2 좌표계와 URDF 모델링

map→odom→base_footprint→base_link→laser_frame 트리, 정적/동적 브로드캐스터와 리스너, URDF link·joint로 로봇을 기술합니다.

선수 챕터: R05
URDF 뷰어ROS 2 Playground

학습 목표#

  • 동차 변환 행렬로 좌표 변환의 합성과 역변환을 계산하고, 라이다 한 점을 odom 좌표로 옮기는 과정을 손으로 풀 수 있습니다.
  • MentorPi의 TF 트리 map → odom → base_footprint → base_link → lidar_frame / imu_link / depth_cam에서 각 변환을 누가 발행하는지 설명합니다.
  • StaticTransformBroadcaster, TransformBroadcaster, Buffer + TransformListener로 좌표 변환을 발행하고 조회합니다. lookup_transform(target, source)의 방향을 헷갈리지 않습니다.
  • URDF의 link(visual·collision·inertial)와 joint(6가지 타입, origin·axis·limit)를 읽고 간단한 모델을 작성하며, xacro 매크로의 쓰임을 이해합니다.
  • robot_state_publisher가 URDF에서 정적 TF를 만들어 내는 원리를 설명합니다.

왜 좌표계를 관리해야 하는가#

라이다는 "라이다 기준으로 정면 1 m에 벽이 있다"고 알려 줍니다. 그러나 로봇이 알고 싶은 것은 "내 몸 중심 기준으로 어디에 있나", 지도를 만들 때는 "지도 기준으로 어디에 있나"입니다. 로봇에는 이런 좌표계(frame)가 여러 개 있고, 어떤 것은 고정(라이다 ↔ 몸체), 어떤 것은 계속 바뀝니다(몸체 ↔ 오도메트리 원점). TF2는 이 관계들을 나무 구조(tree) 로 모아 두고, 임의의 두 좌표계 사이 변환을 시간까지 고려해 계산해 주는 라이브러리입니다.

동차 변환 행렬#

3차원 변환은 회전 R(3×3)과 평행이동 t(3×1)로 이루어지며, 4×4 동차 변환 행렬로 한 번에 씁니다. 평면 운동만 보면 3×3으로 충분합니다.

text
          ┌ cosθ  −sinθ   tx ┐          ┌ x_B ┐     ┌ x_A ┐
T_A_B  =  │ sinθ   cosθ   ty │   ,  T_A_B · │ y_B │  =  │ y_A │
          └  0      0      1 ┘          └  1  ┘     └  1  ┘
  • T_AB는 "좌표계 B의 자세를 A에서 본 것"이고, B 좌표로 적힌 점을 A 좌표로 바꿉니다.
  • 합성: T_AC = T_AB · T_BC — 트리를 따라 행렬을 곱합니다.
  • 역변환: T_BA = (T_AB)⁻¹, 회전 부분은 전치 Rᵀ, 이동 부분은 −Rᵀ·t.

계산 예: 라이다 점을 odom 좌표로#

MentorPi(메카넘) URDF의 고정 변환과 현재 오도메트리가 다음과 같다고 합시다.

변환값 (x, y, z, yaw)출처
odom → base_footprint(1.000, 0.000, 0, 90°)오도메트리(EKF)
base_footprint → base_link(0, 0, 0.070, 0°)URDF base_footprint_to_base_link
base_link → lidar_frame(−0.012, 0, 0.0925, 0°)URDF lidar_Joint

라이다가 정면 1 m에서 벽을 봤습니다: p_lidar = (1, 0, 0).

  1. base_link 기준: (1 − 0.012, 0, 0.0925) = (0.988, 0, 0.0925)
  2. base_footprint 기준: z에 0.070을 더해 (0.988, 0, 0.1625)
  3. odom 기준: yaw 90°이므로 (x, y) → (−y, x)로 회전한 뒤 로봇 위치를 더함 → (1.000 − 0, 0.000 + 0.988) = (1.000, 0.988), z = 0.1625

로봇이 +y 방향을 보고 있으니 벽도 로봇 위쪽(+y)에 있습니다. 실습 ②에서 TF2가 이 계산을 대신하는지 확인합니다.

MentorPi의 TF 트리#

프레임뜻 (REP-105)부모 → 자식 변환을 발행하는 노드
map세계에 고정된 지도 좌표. 연속성은 없지만 장기 오차가 없음—
odom오도메트리 원점. 연속적이지만 시간이 지나면 드리프트map→odom: slam_toolbox 또는 AMCL (M09·M11)
base_footprint로봇 중심을 바닥에 투영한 점odom→base_footprint: EKF(robot_localization) / odom_publisher
base_link로봇 몸체 기준(바닥에서 0.07 m 위)robot_state_publisher (URDF fixed joint)
lidar_frame라이다 중심. 문서에 따라 laser_frame이라고도 부름robot_state_publisher
imu_linkIMU 칩 좌표(URDF에서 yaw −1.57 rad 회전)robot_state_publisher

map → odom을 따로 두는 이유는 두 추정치의 성격이 다르기 때문입니다. 오도메트리는 부드럽지만 오차가 쌓이고, SLAM/AMCL은 가끔 튀지만 오차가 쌓이지 않습니다. 둘을 다른 변환으로 분리하면 제어는 부드러운 odom으로, 전역 위치는 map으로 쓸 수 있습니다. 한 프레임은 부모가 하나뿐이어야 하므로 odom→base_footprint를 두 노드가 동시에 발행하면 안 됩니다.

쿼터니언#

TF는 회전을 쿼터니언 (x, y, z, w)로 저장합니다. 오일러각(roll·pitch·yaw)은 짐벌락과 순서 문제가 있기 때문입니다. z축 회전 ψ만 있으면 q = (0, 0, sin(ψ/2), cos(ψ/2))입니다. 변환은 라이브러리로 합니다.

python
from tf_transformations import quaternion_from_euler, euler_from_quaternion
q = quaternion_from_euler(0.0, 0.0, 1.5708)        # [x, y, z, w] = [0, 0, 0.707, 0.707]
roll, pitch, yaw = euler_from_quaternion(q)        # yaw = 1.5708

StaticTransformBroadcaster(node)변하지 않는 변환(센서 장착 위치). 한 번만 보내면 됨/tf_static (TRANSIENT_LOCAL)

TransformStamped에 header.frame_id(부모), child_frame_id(자식), transform.translation, transform.rotation을 채워 sendTransform()합니다.

lookup_transform의 방향

buffer.lookup_transform(target_frame, source_frame, time)은 source 좌표로 적힌 점을 target 좌표로 바꾸는 변환, 다시 말해 target에서 본 source의 자세를 돌려줍니다. "로봇에서 본 목표물 위치"가 필요하면 lookup_transform('base_footprint', 'target', ...)입니다. 인자를 뒤집으면 부호와 회전이 반대인 값이 나옵니다. rclpy.time.Time()(0)은 "가장 최근 값"이라는 뜻입니다.

원본 tf_demo 해설#

  • static_tf_broadcaster.py: world → home 정적 변환(10, 5, 0)을 한 번 발행합니다. (교재 본문에는 자식 이름이 house로 적힌 곳이 있지만, 예제 코드와 리스너 기본값은 home입니다.)
  • tf_listener.py: 파라미터 source_frame(기본 world), target_frame(기본 home)을 선언하고 1초마다 lookup_transform(target, source, Time())로 조회해 위치와 오일러각을 로그로 찍습니다.
  • turtle_tf_broadcaster.py: /turtleN/pose를 구독해 world → turtleN 동적 변환을 발행합니다.
  • turtle_following.py: Spawn 서비스로 turtle2를 만든 뒤, lookup_transform('turtle2', 'turtle1')로 turtle2에서 본 turtle1의 위치 (x, y)를 얻고 다음 제어 법칙으로 따라갑니다.
text
angular.z = 1.0 · atan2(y, x)        # 목표 쪽으로 머리 돌리기 (방위각 비례)
linear.x  = 0.5 · sqrt(x² + y²)      # 멀수록 빠르게 (거리 비례)
원본 launch의 작은 함정

turtle_following.launch.py는 listener 노드에 target_frame 파라미터를 넘기지만, turtle_following.py가 선언하는 파라미터 이름은 source_frame입니다. 그래서 launch 인자 target_frame:=...을 바꿔도 효과가 없습니다. 따라갈 대상을 바꾸려면 launch 쪽 키를 source_frame으로 고쳐야 합니다. 파라미터 이름 불일치는 오류 없이 조용히 무시되는 대표적인 버그입니다.

URDF: 로봇을 글로 기술하기#

URDF(Unified Robot Description Format)는 로봇의 링크(강체)와 조인트(연결) 를 XML로 적는 형식입니다. RViz2 표시, robot_state_publisher의 TF 생성, Gazebo 시뮬레이션, MoveIt·Nav2의 충돌 모델이 모두 이 파일 하나를 씁니다.

link#

xml
<link name="base_link">
  <visual>                                   <!-- 보이는 모양 -->
    <geometry><cylinder length="0.6" radius="0.2"/></geometry>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <material name="blue"/>
  </visual>
  <collision>                                <!-- 충돌 판정용(보통 단순한 도형) -->
    <geometry><box size="0.25 0.18 0.1"/></geometry>
  </collision>
  <inertial>                                 <!-- 질량·관성(물리 시뮬레이션용) -->
    <mass value="1.2"/>
    <inertia ixx="0.004" ixy="0" ixz="0" iyy="0.006" iyz="0" izz="0.008"/>
  </inertial>
</link>

geometry는 box, cylinder, sphere, mesh(STL/DAE 파일) 중 하나입니다. visual에는 실제와 같은 메시를, collision에는 계산이 가벼운 단순 도형을 쓰는 것이 보통입니다.

joint#

타입운동예
continuous한 축 무한 회전바퀴 (wheel_lf_Joint)
revolute한 축 회전, 각도 제한로봇팔 관절, 조향 서보
prismatic한 축 직선 이동, 위치 제한리니어 액추에이터
fixed움직이지 않음라이다·카메라·IMU 장착 (lidar_Joint)
floating6자유도 자유 운동거의 안 씀
planar평면 내 이동·회전거의 안 씀
xml
<joint name="wheel_lf_Joint" type="continuous">
  <parent link="base_link"/>
  <child link="wheel_lf_Link"/>
  <origin xyz="0.067052 0.07591 -0.018408" rpy="0 0 0"/>   <!-- 부모 기준 자식 원점 -->
  <axis xyz="0 1 0"/>                                        <!-- 회전축(자식 좌표) -->
</joint>

revolute·prismatic에는 <limit lower="-3.14" upper="3.14" effort="1.0" velocity="1.0"/>처럼 한계를 적습니다. 단위는 m, rad, m/s, rad/s입니다(3.14는 180°).

원본 simple_demo.urdf와 xacro#

원본 urdf_demo/urdf/simple_demo.urdf는 파란 원기둥 base_link(길이 0.6, 반지름 0.2)에 흰 상자 다리 두 개를 fixed 조인트로 붙인 모델입니다. 다리 조인트 원점은 (0, ∓0.22, 0.25), 다리 visual은 rpy="0 1.57075 0"으로 세워서 −0.3만큼 내려 둡니다. 조인트 origin은 링크 좌표계의 위치, visual origin은 그 좌표계 안에서 도형의 위치라는 두 층을 구분하는 것이 URDF 읽기의 핵심입니다.

다리 두 개처럼 반복되는 부분은 xacro 매크로로 줄입니다. 원본 simple_demo.xacro는 leg, base_to_leg 매크로를 정의하고 name, xyz만 바꿔 두 번 호출합니다. MentorPi의 실제 모델 mentorpi_description/urdf/mentorpi.xacro도 섀시(mecanum.xacro, ack.xacro), 라이다·IMU 파일을 xacro로 조립합니다.

bash
xacro mentorpi.xacro > mentorpi.urdf          # xacro → 순수 URDF 펼치기
check_urdf mentorpi.urdf                      # 트리 구조 검사 (liburdfdom-tools)

robot_state_publisher#

robot_state_publisher는 robot_description 파라미터(URDF 문자열)를 읽어 **fixed 조인트는 /tf_static으로**, 움직이는 조인트는 /joint_states를 받아 **/tf로** 발행합니다. MentorPi는 controller.launch.py → odom_publisher.launch.py → robot_description.launch.py를 거쳐 이 노드를 자동으로 띄웁니다.

python시뮬 실행 가능
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TransformStamped
import tf_transformations
from tf2_ros import StaticTransformBroadcaster, Buffer, TransformListener
import mentorpi_sim as sim                  # 시뮬 전용
sim.setup(world="empty", duration=3.5)     # 시뮬 전용


class StaticAndListen(Node):
    def __init__(self):
        super().__init__('tf_demo')
        self.static_br = StaticTransformBroadcaster(self)
        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id = 'world'
        t.child_frame_id = 'home'
        t.transform.translation.x, t.transform.translation.y = 10.0, 5.0
        q = tf_transformations.quaternion_from_euler(0.0, 0.0, 0.5)
        t.transform.rotation.x, t.transform.rotation.y, t.transform.rotation.z, t.transform.rotation.w = q
        self.static_br.sendTransform(t)

        self.tf_buffer = Buffer()
        self.tf_listener = TransformListener(self.tf_buffer, self)
        self.create_timer(1.0, self.on_timer)

    def on_timer(self):
        for target, source in [('world', 'home'), ('home', 'world')]:
            try:
                tr = self.tf_buffer.lookup_transform(target, source, rclpy.time.Time())
            except Exception as ex:                      # 실물: tf2_ros.TransformException
                self.get_logger().info('변환 없음: %s' % ex)
                continue
            p, r = tr.transform.translation, tr.transform.rotation
            yaw = tf_transformations.euler_from_quaternion([r.x, r.y, r.z, r.w])[2]
            print('%s에서 본 %s: [%.2f, %.2f, %.2f] yaw=%.2f' % (target, source, p.x, p.y, p.z, yaw))


rclpy.init()
node = StaticAndListen()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.destroy_node()
    rclpy.shutdown()

② MentorPi 센서 프레임: 라이다 점을 odom으로#

URDF 값으로 정적 변환 두 개를 발행하고, 가상 로봇을 1 m 전진시킨 다음 제자리에서 90° 돌린 뒤 odom → lidar_frame 변환을 조회합니다. 위 "계산 예"와 같은 결과가 나오는지 봅니다.

python시뮬 실행 가능
import math
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TransformStamped, Twist
from tf2_ros import StaticTransformBroadcaster, Buffer, TransformListener
from tf_transformations import quaternion_from_euler, euler_from_quaternion
import mentorpi_sim as sim                                                    # 시뮬 전용
sim.setup(world="empty", duration=15.0, start=(0.0, 0.0, 0.0), noise=False)  # 시뮬 전용


def make_tf(parent, child, x, y, z, yaw, stamp):
    t = TransformStamped()
    t.header.stamp, t.header.frame_id, t.child_frame_id = stamp, parent, child
    t.transform.translation.x, t.transform.translation.y, t.transform.translation.z = x, y, z
    q = quaternion_from_euler(0.0, 0.0, yaw)
    t.transform.rotation.x, t.transform.rotation.y, t.transform.rotation.z, t.transform.rotation.w = q
    return t


rclpy.init()
node = Node('sensor_frames')
stamp = node.get_clock().now().to_msg()
static_br = StaticTransformBroadcaster(node)
static_br.sendTransform([make_tf('base_footprint', 'base_link', 0.0, 0.0, 0.070, 0.0, stamp),
                         make_tf('base_link', 'lidar_frame', -0.012, 0.0, 0.0925, 0.0, stamp)])
buf = Buffer()
listener = TransformListener(buf, node)
pub = node.create_publisher(Twist, '/cmd_vel', 10)

def drive(vx, wz, seconds):
    t0 = time.time()
    while time.time() - t0 < seconds:
        cmd = Twist()
        cmd.linear.x, cmd.angular.z = vx, wz
        pub.publish(cmd)
        rclpy.spin_once(node, timeout_sec=0.05)

drive(0.2, 0.0, 5.0)                     # 1 m 전진 (0.2 m/s × 5 s)
drive(0.0, 0.5, math.pi)                 # 반시계 90° 회전 (0.5 rad/s × π s)
pub.publish(Twist())
for _ in range(10):
    rclpy.spin_once(node, timeout_sec=0.05)

tr = buf.lookup_transform('odom', 'lidar_frame', rclpy.time.Time())
p, r = tr.transform.translation, tr.transform.rotation
yaw = euler_from_quaternion([r.x, r.y, r.z, r.w])[2]
print('odom에서 본 lidar_frame: x=%.3f y=%.3f z=%.4f yaw=%.1f deg' % (p.x, p.y, p.z, math.degrees(yaw)))
# 라이다 정면 1 m 점 (1, 0) → odom
px = p.x + math.cos(yaw) * 1.0
py = p.y + math.sin(yaw) * 1.0
print('라이다 정면 1 m 점의 odom 좌표: (%.3f, %.3f, %.4f)' % (px, py, p.z))
node.destroy_node()
rclpy.shutdown()

③ 동적 변환 따라가기: turtle_following의 MentorPi 버전#

움직이는 가상의 목표 프레임 target을 odom 아래에 10 Hz로 발행하고(원본의 turtle1 역할), 로봇(turtle2 역할)이 base_footprint에서 본 target의 위치로 원본과 같은 제어 법칙을 적용해 따라갑니다. 실물 안전을 위해 속도는 제한합니다.

python시뮬 실행 가능
import math
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TransformStamped, Twist
from tf2_ros import TransformBroadcaster, Buffer, TransformListener
import mentorpi_sim as sim                                                    # 시뮬 전용
sim.setup(world="empty", duration=24.0, start=(0.0, 0.0, 0.0))               # 시뮬 전용


class Follower(Node):
    def __init__(self):
        super().__init__('tf_follower')
        self.br = TransformBroadcaster(self)
        self.buf = Buffer()
        self.listener = TransformListener(self.buf, self)
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.t = 0.0
        self.ticks = 0
        self.create_timer(0.1, self.on_timer)

    def publish_target(self):              # 반지름 0.8 m 원 위를 0.1 m/s로 도는 목표
        a = 0.125 * self.t
        tf = TransformStamped()
        tf.header.stamp = self.get_clock().now().to_msg()
        tf.header.frame_id, tf.child_frame_id = 'odom', 'target'
        tf.transform.translation.x = 0.4 + 0.8 * math.cos(a)
        tf.transform.translation.y = 0.8 * math.sin(a)
        tf.transform.rotation.w = 1.0
        self.br.sendTransform(tf)

    def on_timer(self):
        self.ticks += 1
        self.t = self.ticks * 0.1
        self.publish_target()
        try:
            tr = self.buf.lookup_transform('base_footprint', 'target', rclpy.time.Time())
        except Exception:
            return                         # 아직 변환이 없으면 다음 주기에
        x, y = tr.transform.translation.x, tr.transform.translation.y
        dist = math.hypot(x, y)
        cmd = Twist()
        cmd.angular.z = max(-0.5, min(0.5, 1.0 * math.atan2(y, x)))
        if dist > 0.25:
            cmd.linear.x = max(0.0, min(0.2, 0.5 * dist))
        self.pub.publish(cmd)
        if self.ticks % 30 == 0:                 # 3초마다 출력
            print('t=%4.1f s  목표까지 %.2f m  방위 %+5.1f deg' % (self.t, dist, math.degrees(math.atan2(y, x))))


rclpy.init()
node = Follower()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()

Lookup would require extrapolation into the future특정 시각으로 조회했는데 변환이 아직 안 옴rclpy.time.Time()(최신값) 사용, 또는 timeout 인자로 잠시 대기
시작 직후 첫 조회만 실패리스너가 아직 /tf를 받지 못함예외 처리 후 다음 주기에 재시도(③처럼)
변환 값의 부호·회전이 반대lookup_transform 인자 순서 반대(target, source) = "target에서 본 source"
TF_REPEATED_DATA / 트리가 끊겼다 이어짐같은 자식 프레임을 두 노드가 발행부모는 하나뿐. EKF와 odom_publisher의 TF 발행 설정 확인

check_urdf 오류 link has no parent조인트 누락으로 트리가 둘로 나뉨모든 링크가 하나의 루트에 연결되도록 joint 추가
