A09자율주행 준비와 차선 유지

맵 깔기와 소품 설치, 카메라 원근 변환·차선 검출, 차선 중심 오차 PID로 차선을 유지합니다.

선수 챕터: A03 A08
2D 시뮬레이터

학습 목표#

  • 자율주행 맵과 소품(표지판 4개, 신호등 1개)을 올바르게 설치하고, 조명·색 임계값 준비 사항을 점검합니다.
  • lane_detect.py의 차선 검출 파이프라인(LAB 이진화 → 3개 ROI → 최대 윤곽 → 중심 x)을 단계별로 설명하고 재현합니다.
  • self_driving.py의 조향 규칙(설정점 130 px, 회전 문턱 150 px, PID 출력 ±0.1 제한)을 해석하고, 제한 때문에 생기는 뱅뱅 제어 현상을 시뮬레이션으로 확인합니다.
  • 원근 변환(호모그래피)으로 차선을 조감도로 펴고, 픽셀 오차를 미터 단위 횡오차로 바꿉니다.
  • self_driving.launch.py only_line_follow:=true로 실물 차선 유지를 실행하고 튜닝합니다.

맵과 소품 설치#

원본 자율주행 키트는 도로가 인쇄된 맵 한 장과 표지판·신호등 소품으로 이루어집니다. 로봇은 맵 바깥 테두리의 노란 선을 따라 시계 방향으로 돌며, 도중에 만나는 표지판과 신호등에 반응합니다.

소품개수로봇 동작 (A10·A11에서 사용)
직진(go) 표지판2직진 유지
우회전(right) 표지판1교차로에서 우회전
주차(park) 표지판1주차 구역으로 진입
신호등(red/green)1빨간불 정지, 초록불 진행
횡단보도(crosswalk)맵에 인쇄가까워지면 감속

설치 체크리스트:

  1. 평평하고 넓은 바닥에 맵을 주름 없이 폅니다. 주름은 영상에서 그림자 선으로 보여 차선으로 오인됩니다.
  2. 조명은 밝고 고르게. 자연광이 가장 좋고, 강한 직사광·색 조명은 피합니다. 카메라에 빛이 직접 들어오면 노란색이 하얗게 날아갑니다.
  3. 표지판·신호등은 교재의 지정 위치에 주행 방향(시계 방향)을 향하게 세웁니다. 위치가 어긋나면 표지판이 보이는 시점과 주차 동작 타이밍이 맞지 않습니다.
  4. 로봇을 출발점, 차로 가운데에 둡니다.
  5. 주행 전에 A01의 LAB 임계값 도구로 노란색(yellow) 임계값을 현장 조명에서 다시 맞춥니다. 통합 주행(A11)에서는 black·white·red·green·blue·yellow를 모두 점검합니다.
색 임계값이 전부입니다

원본 FAQ의 첫 번째 항목도 "주행이 불안정하면 색 임계값부터 다시 맞추라"입니다. 차선 검출은 모델이 아니라 색 규칙이므로 조명이 바뀌면 바로 무너집니다. 인식이 실패하는 맵 구역에 로봇을 세워 두고 그 자리에서 임계값을 맞추면 효과가 큽니다.

차선 검출 파이프라인#

lane_detect.py의 LaneDetector는 다음 순서로 동작합니다.

1단계: LAB 이진화 (get_binary)#

python
img_lab = cv2.cvtColor(image, cv2.COLOR_RGB2LAB)
img_blur = cv2.GaussianBlur(img_lab, (3, 3), 3)
mask = cv2.inRange(img_blur, lab_min, lab_max)       # lab_config.yaml → lab/Stereo/yellow
eroded = cv2.erode(mask, 3×3 사각 커널)
dilated = cv2.dilate(eroded, 3×3 사각 커널)          # 열림(opening) 연산

LAB 색공간에서 L은 밝기, a는 초록(−)↔빨강(+), b는 파랑(−)↔노랑(+)입니다. 노란 선은 b가 크고 a가 약간 +인 영역입니다. 기본 임계값은 min (135, 129, 132), max (255, 255, 255)로 "밝고(L ≥ 135), 약간 붉고(a ≥ 129), 노란(b ≥ 132)" 픽셀만 남깁니다. 흰 선은 a = 128 근처라 걸러지고, 회색 도로는 L이 낮아 걸러집니다. 침식 후 팽창(열림 연산)은 작은 점 잡음을 지우면서 선 두께는 유지합니다.

2단계: 세 개의 ROI 띠#

ROIy 범위 (ascamera)x 범위가중치의미
가까움338 ~ 3600 ~ 3200.7로봇 바로 앞
중간292 ~ 3150 ~ 3200.2
멀리248 ~ 2700 ~ 3200.1앞으로 올 커브

다른 카메라(DEPTH_CAMERA_TYPE이 ascamera가 아닐 때)는 (450~480), (390~480), (330~480)을 씁니다. 영상 전체가 아니라 가로 띠 세 개만 보는 이유는 두 가지입니다. 계산이 줄고, 띠마다 중심을 따로 구하면 차선의 기울기(곡률)를 알 수 있습니다. x를 왼쪽 절반(0~320)으로 제한한 것은 이 맵에서 따라갈 노란 선이 로봇의 왼쪽에 보이기 때문이며, 오른쪽의 다른 노란 표시를 무시하는 효과도 있습니다.

3단계: 띠마다 중심 x#

각 띠에서 findContours로 윤곽을 찾고, 넓이 30 px² 이상인 것 중 가장 큰 윤곽을 고릅니다. 그 윤곽의 최소 외접 회전 사각형(minAreaRect)의 대각 두 꼭짓점 중점이 그 띠의 선 중심입니다. 선이 없으면 −1을 넣습니다.

4단계: 대표값#

__call__은 두 값을 돌려줍니다.

  • angle: 가중 평균 중심 x̄ = Σ wᵢ xᵢ로 계산한 −atan((x̄ − w/2)/(h/2)) [°]
  • max_center_x: 세 띠 중심 중 가장 큰 x

self_driving.py는 angle은 쓰지 않고 **max_center_x(lane_x)만** 조향에 씁니다. 원근 때문에 왼쪽 차선은 멀수록 영상 가운데 쪽(오른쪽)으로 기울어 보이므로, 보통 가장 먼 띠의 x가 최댓값이 됩니다. 결과적으로 "앞쪽 차선이 얼마나 오른쪽으로 휘어 들어오는가"를 보는 셈입니다.

조향 규칙#

self_driving.py 주 루프(약 33 Hz)의 차선 유지 부분을 정리하면 다음과 같습니다.

조건메카넘 명령애커만 명령
lane_x > 150 (급커브)angular.z = −0.45 (고정 우회전)최대 조향: v·tan(−0.5061)/0.145
lane_x ≤ 150angular.z = clamp(PID, −0.1, 0.1)v·tan(clamp(PID, −0.1, 0.1))/0.145
차선 없음 (lane_x = −1)명령을 발행하지 않음, PID 초기화같음
항상linear.x = normal_speed = 0.1 m/s같음

PID는 PID(0.4, 0.0, 0.05), 설정점 SetPoint = 130입니다. 130은 로봇이 차로 가운데 있을 때 노란 선이 보이는 x 좌표입니다. 원본 FAQ는 이 값을 줄이면 일찍 돌고 키우면 늦게 돈다고 설명합니다. 애커만은 각속도 대신 조향각을 명령해야 하므로 ω = v·tan δ / L (L = 0.145 m)로 바꿔 보냅니다. 0.5061 rad = 29°는 애커만 섀시의 최대 조향각입니다.

lane_x > 150이 6프레임 넘게 이어지면 start_turn 표시를 세우고, 선이 150 아래로 돌아온 뒤에도 표시가 선 지 2초가 지날 때까지는 PID를 쓰지 않습니다(애커만은 최대 조향 유지, 메카넘은 각속도 0으로 직진). 커브를 막 빠져나온 순간 흔들리는 선 위치에 PID가 과하게 반응하지 않게 하는 시간 히스테리시스입니다.

차선을 잃으면 마지막 명령이 계속됩니다

lane_x가 −1이면 코드는 self.pid.clear()만 하고 Twist를 보내지 않습니다. 컨트롤러는 새 명령이 올 때까지 마지막 속도를 유지하므로, 선을 놓친 순간의 명령(예: 우회전 −0.45)으로 계속 달립니다. 실습에서는 반드시 손을 가까이 두고, 개선 과제로 "N프레임 연속 미검출 시 정지"를 넣어 보세요.

실습: 합성 영상으로 lane_x 계산#

맵 사진 대신 OpenCV로 회색 도로에 노란 선과 흰 선을 그린 영상을 만들어, 원본과 같은 임계값·ROI로 lane_x와 조향 명령을 계산합니다.

Playground 열기

python시뮬 실행 가능
import numpy as np
import cv2

LAB_MIN, LAB_MAX = (135, 129, 132), (255, 255, 255)      # lab_config.yaml Stereo/yellow
ROIS = ((338, 360, 0, 320, 0.7), (292, 315, 0, 320, 0.2), (248, 270, 0, 320, 0.1))

def make_road(x_bottom, x_top):
    img = np.full((480, 640, 3), 90, np.uint8)                   # 회색 도로 (RGB)
    cv2.line(img, (x_bottom, 480), (x_top, 200), (250, 190, 20), 18)   # 노란 차선
    cv2.line(img, (600, 480), (470, 200), (230, 230, 230), 14)         # 흰 차선
    return img

def get_binary(rgb):                                    # lane_detect.get_binary
    lab = cv2.GaussianBlur(cv2.cvtColor(rgb, cv2.COLOR_RGB2LAB), (3, 3), 3)
    mask = cv2.inRange(lab, LAB_MIN, LAB_MAX)
    k = cv2.getStructuringElement(cv2.MORPH_RECT, (3, 3))
    return cv2.dilate(cv2.erode(mask, k), k)

def lane_x(binary):                                     # LaneDetector.__call__ 핵심
    xs = []
    for y0, y1, x0, x1, wgt in ROIS:
        cs = cv2.findContours(binary[y0:y1, x0:x1], cv2.RETR_EXTERNAL,
                              cv2.CHAIN_APPROX_TC89_L1)[-2]
        cs = [c for c in cs if cv2.contourArea(c) > 30]
        if not cs:
            xs.append(-1)
            continue
        box = cv2.boxPoints(cv2.minAreaRect(max(cs, key=cv2.contourArea)))
        xs.append(float((box[0, 0] + box[2, 0]) / 2))
    return xs, max(xs)          # self_driving.py 는 가장 오른쪽(최댓값) x를 씀

cases = {"중앙": (120, 133), "왼쪽 치우침": (128, 150),
         "오른쪽 치우침": (100, 115), "우회전 커브": (130, 330)}
for name, (xb, xt) in cases.items():
    xs, lx = lane_x(get_binary(make_road(xb, xt)))
    if lx > 150:
        cmd = "회전 모드 angular.z = -0.45"
    else:
        raw = 0.4 * (130 - lx)                             # Kp=0.4, SetPoint=130
        cmd = "PID raw=%.2f → angular.z = %.2f" % (raw, max(-0.1, min(0.1, raw)))
    print(name, "| ROI x =", [round(x, 1) for x in xs], "| lane_x = %.1f →" % lx, cmd)
text
중앙 | ROI x = [126.5, 128.6, 130.5] | lane_x = 130.5 → PID raw=-0.20 → angular.z = -0.10
왼쪽 치우침 | ROI x = [138.0, 142.0, 145.0] | lane_x = 145.0 → PID raw=-6.00 → angular.z = -0.10
오른쪽 치우침 | ROI x = [107.1, 109.5, 111.4] | lane_x = 111.4 → PID raw=7.44 → angular.z = 0.10
우회전 커브 | ROI x = [224.0, 256.3, 288.3] | lane_x = 288.3 → 회전 모드 angular.z = -0.45

관찰할 점:

  • 흰 선도 영상에 있지만 a 채널이 128이라 임계값(a ≥ 129)을 통과하지 못해 무시됐습니다. 오른쪽 절반은 ROI 밖이기도 합니다.
  • 로봇이 왼쪽으로 치우치면(노란 선에 가까워지면) 선이 영상에서 오른쪽으로 이동해 lane_x가 커지고, 음의 각속도(우회전)가 나옵니다. 부호가 맞습니다.
  • 중앙에서도 0.5 px 오차에 −0.1이 나옵니다. Kp = 0.4는 0.25 px 오차만으로 제한값(±0.1)에 닿는 큰 이득이라, 사실상 좌·우 두 값만 내는 뱅뱅(bang-bang) 제어입니다.

실습: 샘플 영상 lane.png에서 차로 중심 오차 구하기#

Playground의 샘플 lane.png는 왼쪽 흰 선, 오른쪽 노란 선이 있는 원근 도로 영상입니다. MentorPi 맵처럼 한 선만 따라가는 대신, 두 선의 가운데를 차로 중심으로 보고 영상 중앙(320 px)과의 차이를 오차로 씁니다. 먼저 로봇의 기본 노란색 임계값을 그대로 적용해 봅니다.

python시뮬 실행 가능
import numpy as np
import cv2

img = cv2.imread("lane.png")                          # BGR, 640x480 샘플 도로 영상
lab = cv2.cvtColor(img, cv2.COLOR_BGR2LAB)
orig = cv2.inRange(lab, (135, 129, 132), (255, 255, 255))     # 로봇 기본 노란색 임계값
yellow = cv2.inRange(lab, (135, 100, 160), (255, 150, 255))   # 이 영상에 맞춘 값
white = cv2.inRange(lab, (200, 118, 118), (255, 138, 138))    # 밝고 무채색
print("노란 픽셀 수: 기본 임계값 %d, 조정 임계값 %d"
      % (cv2.countNonZero(orig), cv2.countNonZero(yellow)))

w = img.shape[1]
bands = ((400, 420, 0.7), (330, 350, 0.2), (270, 290, 0.1))    # (y0, y1, 가중치)
err_sum = 0.0
for y0, y1, wgt in bands:
    xy = np.nonzero(yellow[y0:y1])[1].mean()          # 노란선 평균 x
    xw = np.nonzero(white[y0:y1])[1].mean()           # 흰선 평균 x
    center = (xy + xw) / 2
    err_sum += wgt * (center - w / 2)
    print("y %d~%d: 흰선 x=%.1f 노란선 x=%.1f 차로 중심=%.1f 오차=%+.1f px"
          % (y0, y1, xw, xy, center, center - w / 2))
print("가중 평균 오차 = %+.1f px" % err_sum)
omega = float(np.clip(-0.004 * err_sum, -0.5, 0.5))   # 중심이 오른쪽(+) → 우회전(−)
print("angular.z = %+.3f rad/s" % omega)

  • 기본 임계값으로는 노란 픽셀이 0개입니다. 이 영상의 노란색은 LAB로 (222, 126, 215)라 a가 129보다 작습니다. 로봇 임계값은 MentorPi 카메라가 찍은 맵의 주황빛 노란색에 맞춘 값이라, 카메라·조명·인쇄가 바뀌면 반드시 다시 맞춰야 한다는 것을 보여 줍니다.
  • 차로 중심이 영상 중앙보다 오른쪽(+)에 있으므로 로봇이 차로 왼쪽에 치우쳐 있다는 뜻이고, 오른쪽으로 도는 음의 각속도가 나옵니다.
  • 가까운 띠일수록 오차가 큽니다. 원근 때문에 같은 횡오차도 가까운 곳에서 더 많은 픽셀로 보이기 때문이며, 이것이 뒤에서 다룰 원근 변환의 동기입니다.

PID 조향과 뱅뱅 제어#

차선 유지의 기본 모델을 세워 봅니다. 차로 중심선에서의 횡오차를 e(왼쪽 +), 차로 방향과 로봇 방향의 차이를 ψ라 하면, 속도 v로 달릴 때

text
ė = v · sin ψ ≈ v · ψ          (방향이 틀어진 만큼 옆으로 밀림)
ψ̇ = ω                          (각속도 명령이 방향을 바꿈)

즉 각속도에서 횡오차까지 적분기 두 개가 이어진 시스템입니다. P 제어만 쓰면 ë = v·K·(−e) 꼴이 되어 감쇠 없이 좌우로 진동하므로, D 항(오차 변화율 = 방향 오차에 해당)이 필요합니다. 원본 PID(0.4, 0, 0.05)에 D가 있는 이유입니다. 카메라 앞쪽(먼 ROI)을 보는 것도 같은 효과를 냅니다. 앞을 보면 e에 ψ가 섞여 들어오기 때문입니다(lane_x ≈ 130 + a·e + b·ψ).

아래 코드는 그 선형 모델(계수 a = 600 px/m, b = 200 px/rad는 설명용 가정값)로 20초 동안 달려 봅니다. 원본 게인·제한과, 제한을 넓히고 이득을 낮춘 설정을 비교합니다.

python시뮬 실행 가능
import math

def run(kp, limit, kd=0.0, T=20.0, dt=1 / 30):
    """직선 차선에서 횡오차 e[m](왼쪽 +), 방향오차 psi[rad] 시뮬레이션."""
    e, psi, v = 0.06, 0.0, 0.1          # 6 cm 왼쪽에서 출발, normal_speed 0.1 m/s
    last, log, flips, last_sign = None, [], 0, 0
    for k in range(int(T / dt) + 1):
        lane_x = 130 + 600 * e + 200 * psi         # 가정한 카메라 모델 [px]
        err = 130 - lane_x
        d = 0.0 if last is None else (err - last) / dt
        last = err
        w = max(-limit, min(limit, kp * err + kd * d))
        s = (w > 0) - (w < 0)
        if s and last_sign and s != last_sign:
            flips += 1                               # 조향 방향이 뒤집힌 횟수
        last_sign = s or last_sign
        if k % 120 == 0:
            log.append("%4.0fs e=%+5.1fcm psi=%+5.1f°" % (k * dt, e * 100, math.degrees(psi)))
        e += v * math.sin(psi) * dt
        psi += w * dt
    return log, flips

for name, kp, lim, kd in (("원본 Kp=0.4 ±0.1", 0.4, 0.1, 0.05),
                          ("완만 Kp=0.004 ±0.3", 0.004, 0.3, 0.004)):
    log, flips = run(kp, lim, kd)
    print(name, "| 조향 반전 %d회" % flips)
    print("   " + " | ".join(log[::2]))
text
원본 Kp=0.4 ±0.1 | 조향 반전 535회
      0s e= +6.0cm psi= +0.0° |    8s e= +0.4cm psi= -1.4° |   16s e= -0.3cm psi= -0.2°
완만 Kp=0.004 ±0.3 | 조향 반전 2회
      0s e= +6.0cm psi= +0.0° |    8s e= +0.6cm psi= -2.0° |   16s e= -0.1cm psi= +0.1°

두 설정 모두 차로 중심으로 돌아오지만, 원본 설정은 20초 동안 조향 방향을 500번 넘게 뒤집습니다(떨림, chattering). 느린 속도(0.1 m/s)와 작은 제한(±0.1 rad/s) 덕분에 로봇이 크게 흔들리지는 않지만, 서보·모터가 계속 좌우로 움찔거리고 애커만 조향 서보에는 부담이 됩니다. 이득을 낮추고 제한을 넓히면 같은 수렴을 부드럽게 얻을 수 있습니다. 실물 튜닝은 이 방향으로 조금씩 시도합니다.

원근 변환으로 조감도 만들기#

원본은 원근을 보정하지 않고 픽셀 좌표로 바로 조향합니다. 그래서 "130 px"은 카메라 높이·각도가 바뀌면 의미가 달라집니다. 이를 일반화하는 방법이 원근 변환(perspective transform)입니다. 바닥 평면의 점 (X, Y)와 영상의 점 (u, v) 사이에는 3×3 행렬 호모그래피 H가 성립합니다.

text
[X', Y', w]ᵀ = H · [u, v, 1]ᵀ ,     X = X'/w,  Y = Y'/w

H의 자유도는 8이므로 대응점 4쌍이면 구할 수 있습니다(cv2.getPerspectiveTransform). 맵 위에 차로 폭과 앞쪽 거리를 아는 직사각형을 표시하고, 영상에서 그 네 꼭짓점을 찍으면 됩니다. 조감도에서는 평행한 차선이 평행하게, 픽셀이 곧 거리가 되므로 횡오차를 미터로 잴 수 있습니다.

python시뮬 실행 가능
import numpy as np
import cv2

# 바닥의 직사각형(차선 폭 × 앞쪽 거리)이 영상에서는 사다리꼴로 보인다
src = np.float32([[250, 260], [430, 260], [620, 470], [60, 470]])   # 영상 좌표
dst = np.float32([[170, 0], [470, 0], [470, 480], [170, 480]])      # 조감도 좌표
M = cv2.getPerspectiveTransform(src, dst)
for row in M:
    print("H 행:", "  ".join("%9.4f" % (round(float(v), 4) + 0.0) for v in row))

# 왼쪽 차선 위의 세 점(영상) → 조감도: 한 직선(x=170)으로 곧게 펴진다
left = np.float32([[[60, 470]], [[155, 365]], [[250, 260]]])
print("왼쪽 차선 → 조감도 x:", np.round(cv2.perspectiveTransform(left, M)[:, 0, 0], 1))

# 조감도에서는 픽셀이 곧 거리. 차선 폭 300 px = 0.45 m 로 두면
m_per_px = 0.45 / 300
robot = cv2.perspectiveTransform(np.float32([[[320, 470]]]), M)[0, 0, 0]
center = (170 + 470) / 2
print("로봇 x = %.1f px, 차선 중심 = %.1f px" % (robot, center))
print("횡방향 오차 = %+.3f m (음수 = 차선 중심보다 왼쪽)" % ((robot - center) * m_per_px))
text
H 행:   -1.0328    -1.9934   671.1475
H 행:    0.0000    -4.4066  1145.7049
H 행:    0.0000    -0.0062     1.0000
왼쪽 차선 → 조감도 x: [170. 170. 170.]
로봇 x = 309.3 px, 차선 중심 = 320.0 px
횡방향 오차 = -0.016 m (음수 = 차선 중심보다 왼쪽)

영상에서 비스듬했던 왼쪽 차선의 세 점이 조감도에서 모두 x = 170에 놓였습니다. 조감도에서 오차를 미터로 재면 PID 이득도 "1 m 벗어나면 몇 rad/s"처럼 물리 단위로 정할 수 있어, 카메라를 바꿔도 이득을 다시 맞출 필요가 줄어듭니다. H의 셋째 행이 (0, −0.0062, 1)인 것은 영상 위쪽(v가 작을수록)일수록 멀리 있는 점이라 더 크게 늘려야 한다는 뜻입니다.
