A03자율 라인 트레이싱

ROI 분할과 색 이진화로 선의 중심을 찾고, PID로 각속도를 계산해 선을 따라가며 라이다로 장애물에서 멈춥니다.

선수 챕터: A01
3D 시뮬레이터2D 시뮬레이터HSV 색 실험실ROS 2 Playground

학습 목표#

  • MentorPi line_following 노드의 구조(서비스로 시작·색 선택·실행, 카메라·라이다 구독, /controller/cmd_vel 발행)를 설명합니다.
  • 클릭한 점의 Lab 색으로 임계값을 만들고, 화면 아래쪽 세 개의 ROI 띠에 가중치를 주어 선의 중심을 구합니다.
  • 중심 오차를 편향각(deflection angle)으로 바꾸고, PID로 각속도를 계산합니다. 메카넘과 애커만의 명령 차이를 설명합니다.
  • 카메라 지연이 있을 때 비례 이득이 너무 크면 진동하는 이유를 시뮬레이션으로 확인하고 이득을 고릅니다.
  • 전방 ±22.5° 라이다 구간에서 0.4 m 안에 물체가 있으면 멈추고, 사라지면 다시 출발하는 안전 로직을 구현합니다.

라인 트레이싱의 전체 흐름#

라인 트레이싱(line following)은 바닥에 붙인 테이프를 카메라로 보고, 선이 화면 가운데에 오도록 계속 방향을 고치는 제어입니다. MentorPi의 구현은 ~/ros2_ws/src/app/app/line_following.py에 있고, 앱의 “라인 트레이싱” 기능도 같은 노드를 씁니다.

구성이름설명
실행 파일ros2 launch app line_following_node.launch.py debug:=truedebug:=true면 카메라·라이다·컨트롤러 launch를 함께 켜고 OpenCV 창을 띄움
서비스/line_following/enter (Trigger)카메라 ascamera/camera_publisher/rgb0/image와 라이다 /scan_raw 구독 시작, PID를 (1.1, 0, 0)으로 초기화
서비스/line_following/set_target_color (interfaces/srv/SetPoint)화면 비율 좌표 (x, y)의 색을 목표로 설정 (debug 모드에서는 창을 클릭)
서비스/line_following/set_running (SetBool)주행 시작/정지
서비스/line_following/set_threshold (interfaces/srv/SetFloat64)색 범위 폭(기본 0.5)
서비스/line_following/exit (Trigger)구독 해제, 정지
발행/controller/cmd_vel (Twist)섀시 속도 명령
발행/line_following/image_result (Image)결과를 그린 영상 (debug가 아닐 때)

노드는 5초 하트비트(/line_following/heartbeat)가 끊기면 스스로 exit를 호출합니다. 앱이 연결을 잃어도 로봇이 계속 달리지 않게 하는 장치입니다.

1단계: 색 고르기 (ColorPicker)#

A01의 색 인식은 미리 정한 임계값 파일을 썼지만, 라인 트레이싱은 현장에서 클릭한 색을 씁니다. 테이프 색·조명이 장소마다 달라지기 때문입니다.

  1. 클릭한 점 주변 2×2 픽셀을 Lab으로 바꿔 평균을 냅니다. 이를 5프레임 모아 목표색 (L_0, a_0, b_0)로 확정합니다(ColorPicker(point, 5)).
  2. 임계값 비율 threshold = 0.5로 범위를 만듭니다. 밝기 L은 두 배 넓게 잡습니다.
text
min = (L0 − 50·t·2,  a0 − 50·t,  b0 − 50·t)        t = threshold (기본 0.5)
max = (L0 + 50·t·2,  a0 + 50·t,  b0 + 50·t)        → L ±50, a·b ±25

A01에서 본 원칙(“색 축은 좁게, 밝기 축은 넓게”)이 그대로 식에 들어 있습니다. 검은 테이프는 a·b가 128 근처인 무채색이라 사실상 L로만 구분되고, 빨간 테이프는 a 축이 주로 가릅니다.

2단계: ROI 가중 중심#

영상 전체에서 선을 찾으면 멀리 있는 선, 옆의 다른 테이프까지 섞입니다. LineFollower는 화면 아래쪽의 가는 띠 세 개만 봅니다.

띠 (영상 높이 비율)가중치의미
0.90 ~ 0.95 (가장 아래)0.7로봇 바로 앞 — 현재 위치
0.80 ~ 0.850.2조금 앞
0.70 ~ 0.75 (가장 위)0.1멀리 — 다가올 곡선의 예고

단안 카메라 버전은 띠가 (0.81~0.83, 0.69~0.71, 0.57~0.59)로 위쪽에 있습니다. 카메라 장착 높이·각도가 달라 같은 거리의 바닥이 영상의 다른 행에 찍히기 때문입니다.

띠마다 **Lab 변환 → 가우시안 3×3 → inRange → 3×3 침식·팽창 → 가장 큰 윤곽(면적 30 초과) → minAreaRect의 중심 x**를 구하고 가중합을 냅니다.

text
center_pos = Σ (띠 중심 x × 가중치) / weight_sum        weight_sum = 1.0
deflection_angle = −atan( (center_pos − w/2) / (h/2) )

편향각은 “영상 아래 가운데에서 선 중심을 바라보는 각도”의 근사입니다. 선이 오른쪽(center_pos > w/2)이면 음수(오른쪽으로 돌아야 함)가 됩니다. 원본 코드는 깊이 카메라일 때 w에 200을 더해 기준점을 오른쪽으로 100 px 옮기는데, 카메라가 섀시 중심에서 비켜 달린 것을 보정하는 값으로 보입니다.

python브라우저 실행
import cv2
import math
import numpy as np

img = cv2.imread("track.png")                          # 원본 노드는 RGB로 받지만 여기서는 BGR로 통일
h, w = img.shape[:2]
ROIS = ((0.9, 0.95, 0, 1, 0.7), (0.8, 0.85, 0, 1, 0.2), (0.7, 0.75, 0, 1, 0.1))  # ascamera 값
K3 = cv2.getStructuringElement(cv2.MORPH_RECT, (3, 3))

# 1) 색 고르기: 선 위의 한 점 (x=0.5, y=0.95)을 "클릭"
px, py = int(0.5 * w), int(0.95 * h)
L0, a0, b0 = cv2.cvtColor(img[py - 1:py + 1, px - 1:px + 1], cv2.COLOR_BGR2LAB).reshape(-1, 3).mean(0)
t = 0.5
lo = (int(L0 - 100 * t), int(a0 - 50 * t), int(b0 - 50 * t))
hi = (int(L0 + 100 * t), int(a0 + 50 * t), int(b0 + 50 * t))
print("목표 Lab (%.0f, %.0f, %.0f) → min %s max %s" % (L0, a0, b0, lo, hi))

# 2) ROI 띠별 중심과 가중합
centroid_sum, view = 0.0, img.copy()
for top, bot, left, right, wgt in ROIS:
    y0 = int(top * h)
    blob = img[y0:int(bot * h), int(left * w):int(right * w)]
    lab = cv2.GaussianBlur(cv2.cvtColor(blob, cv2.COLOR_BGR2LAB), (3, 3), 3)
    mask = cv2.dilate(cv2.erode(cv2.inRange(lab, lo, hi), K3), K3)
    cs = [c for c in cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_TC89_L1)[-2] if cv2.contourArea(c) > 30]
    if cs:
        (cx, cy), _, _ = cv2.minAreaRect(max(cs, key=cv2.contourArea))
        centroid_sum += cx * wgt
        print("띠 %.2f~%.2f  중심 x = %5.1f  (가중치 %.1f)" % (top, bot, cx, wgt))
        cv2.circle(view, (int(cx), int(y0 + cy)), 6, (0, 0, 255), -1)
    cv2.rectangle(view, (0, y0), (w - 1, int(bot * h)), (0, 200, 255), 1)

center_pos = centroid_sum / 1.0
angle = -math.atan((center_pos - w / 2.0) / (h / 2.0))
print("center_pos = %.1f, 편향각 = %+.3f rad (%+.1f°)" % (center_pos, angle, math.degrees(angle)))
print("PID(1.1) → angular.z = %+.3f rad/s" % max(-1.0, min(1.0, 1.1 * angle)))
cv2.imshow("rois", view)
text
목표 Lab (16, 128, 128) → min (-34, 103, 103) max (66, 153, 153)
띠 0.90~0.95  중심 x = 320.0  (가중치 0.7)
띠 0.80~0.85  중심 x = 320.0  (가중치 0.2)
띠 0.70~0.75  중심 x = 325.5  (가중치 0.1)
center_pos = 320.5, 편향각 = -0.002 rad (-0.1°)
PID(1.1) → angular.z = -0.003 rad/s

검은 테이프는 Lab이 (16, 128, 128) — 매우 어둡고 무채색 — 이라 범위가 사실상 L로만 결정됩니다(L 최솟값이 음수여도 0으로 취급될 뿐입니다). track.png의 선은 화면 아래에서는 가운데(x = 320)에 있다가 y = 360 위부터 오른쪽으로 휩니다. 가장 위 띠(y = 336~360)가 곡선의 시작을 살짝 보고 있어 중심이 325.5로 치우치고, 편향각이 작은 음수(오른쪽으로 아주 조금 도는 명령)가 됩니다. 가중치 0.1이라 영향은 작지만, 곡선에 들어가기 전에 미리 방향을 틀기 시작하는 효과가 있습니다.

띠를 놓치면 생기는 편향#

원본은 선을 찾지 못한 띠의 가중치도 그대로 두고 weight_sum = 1.0으로 나눕니다. 가장 아래 띠(0.7)만 놓치면 center_pos가 0 쪽(왼쪽)으로 크게 끌려가 엉뚱하게 왼쪽으로 급회전합니다. 찾은 띠의 가중치 합으로 나누면 이 문제가 사라집니다.

python브라우저 실행
import math

w, h = 640, 480
found = {0.7: 322.0, 0.2: 330.0, 0.1: 380.0}           # 가중치: 띠 중심 x
for missing in (None, 0.1, 0.7):
    use = {k: v for k, v in found.items() if k != missing}
    s = sum(k * v for k, v in use.items())
    orig = s / 1.0                                       # 원본: 항상 1.0으로 나눔
    fixed = s / sum(use)                                 # 개선: 찾은 가중치 합으로
    a_o = -math.atan((orig - w / 2) / (h / 2))
    a_f = -math.atan((fixed - w / 2) / (h / 2))
    print("놓친 띠 %-5s center 원본 %6.1f → %+5.2f rad | 개선 %6.1f → %+5.2f rad"
          % (missing, orig, a_o, fixed, a_f))
text
놓친 띠 None  center 원본  329.4 → -0.04 rad | 개선  329.4 → -0.04 rad
놓친 띠 0.1   center 원본  291.4 → +0.12 rad | 개선  323.8 → -0.02 rad
놓친 띠 0.7   center 원본  104.0 → +0.73 rad | 개선  346.7 → -0.11 rad

3단계: PID로 각속도 만들기#

편향각 θ_d를 오차로 보고 PID(R-트랙의 PID 복습: u = K_p e + K_i \int e\,dt + K_d\,de/dt)를 돌립니다. MentorPi의 sdk/pid.py는 error = SetPoint − feedback이고 SetPoint가 0이므로 오차는 -θ_d입니다. 노드는 angular.z = −output으로 부호를 되돌리므로 결국 다음과 같습니다.

text
메카넘:   linear.x = 0.15 m/s,   angular.z = clamp(Kp·θd, −1.0, +1.0)        Kp = 1.1, Ki = Kd = 0
애커만:   δ = clamp(Kp·θd, ±29°),  R = 0.145 / tan δ,  angular.z = v / R        (조향각 → 회전율)
  • 애커만 섀시는 제자리 회전이 안 되므로 편향각을 조향각으로 보고, 휠베이스 0.145 m로 회전 반경 R을 구해 ω = v/R을 보냅니다. ±29°는 서보 펄스 한계(322/2000×180°)에서 나온 값입니다.
  • 선을 놓치거나(deflection_angle is None) 주행이 꺼지면 pid.clear()로 적분·미분 기억을 지웁니다.
  • 원본은 선속도를 0.15 m/s로 고정합니다. 급한 곡선에서 느려지게 하려면 v = v_0 (1 - k|θ_d|)처럼 편향각에 따라 줄이는 방법이 흔히 쓰입니다.

이득 고르기: 지연이 있으면 큰 이득은 흔들린다#

카메라 노출, 전송, 영상 처리 때문에 명령은 항상 조금 늦은 영상으로 계산됩니다. 지연이 없으면 이득이 클수록 오차가 작아지지만, 지연이 있으면 너무 큰 이득은 선을 지나쳤다가 되돌아오는 진동을 만듭니다.

아래 코드는 바닥의 S자 선을 “내려다보는 가상 카메라” 영상으로 그리고, 위와 같은 ROI 가중 중심 + 편향각 + P 제어로 로봇(0.15 m/s)을 20초 동안 달립니다. 카메라 지연은 0.3초로 둡니다.

python브라우저 실행
import math
from collections import deque
import cv2
import numpy as np
import mentorpi_sim as sim                                   # 시뮬 전용 (그래프)

W, H = 160, 120                                              # 가상 카메라 영상
NEAR, FAR, HALF = 0.10, 0.40, 0.20                           # 전방 0.10~0.40 m, 좌우 ±0.20 m가 보임
ROIS = ((0.9, 0.95, 0.7), (0.8, 0.85, 0.2), (0.7, 0.75, 0.1))
rows, cols = np.mgrid[0:H, 0:W]
fwd = FAR - (FAR - NEAR) * rows / (H - 1)                    # 아래 행일수록 가까움
left = HALF - 2 * HALF * cols / (W - 1)                      # 왼쪽 열일수록 +y

def track_y(x):
    return 0.25 * np.sin(x / 0.7)                            # 바닥의 S자 선

def camera(x, y, th):
    wx = x + fwd * math.cos(th) - left * math.sin(th)
    wy = y + fwd * math.sin(th) + left * math.cos(th)
    img = np.full((H, W), 220, np.uint8)
    img[np.abs(wy - track_y(wx)) < 0.015] = 30               # 폭 3 cm 검은 테이프
    return img

def deflection(img):
    _, mask = cv2.threshold(img, 100, 255, cv2.THRESH_BINARY_INV)
    s = 0.0
    for top, bot, wgt in ROIS:
        m = cv2.moments(mask[int(top * H):int(bot * H)], binaryImage=True)
        if m["m00"] > 0:
            s += m["m10"] / m["m00"] * wgt
    return None if s == 0 else -math.atan((s - W / 2.0) / (H / 2.0))

def run(kp, delay=0.3, T=20.0, dt=0.05, v=0.15):
    x = y = th = 0.0
    q, errs = deque([None] * int(delay / dt)), []
    for _ in range(int(T / dt)):
        q.append(deflection(camera(x, y, th)))
        a = q.popleft()                                      # 지연된 측정
        w = 0.0 if a is None else max(-1.0, min(1.0, kp * a))
        x, y, th = x + v * math.cos(th) * dt, y + v * math.sin(th) * dt, th + w * dt
        errs.append(1000 * (y - float(track_y(x))))          # 선과의 옆 오차 [mm]
    return np.array(errs)

for kp in (0.3, 1.1, 3.0, 8.0):
    e = run(kp)
    print("Kp %.1f  RMS %5.1f mm  최대 %5.1f mm  마지막 5 s RMS %4.1f mm"
          % (kp, np.sqrt((e ** 2).mean()), np.abs(e).max(), np.sqrt((e[-100:] ** 2).mean())))
    sim.plot(np.arange(len(e)) * 0.05, e, "Kp %.1f" % kp)   # 시뮬 전용
cv2.imshow("virtual camera", camera(0.5, 0.0, 0.0))

Kp 1.1  RMS  11.6 mm  최대  37.7 mm  마지막 5 s RMS  1.7 mm
Kp 3.0  RMS   4.5 mm  최대  24.1 mm  마지막 5 s RMS  1.6 mm
Kp 8.0  RMS   6.9 mm  최대  23.9 mm  마지막 5 s RMS  6.1 mm

  • 원본 값 1.1은 안정적이지만 곡선에서 오차가 남고, 3.0이 이 조건에서는 가장 좋습니다.
  • Kp 8.0은 초반 추종은 빠르지만 마지막 5초 오차가 오히려 커집니다. 0.3초 전 영상으로 크게 꺾다 보니 선을 넘나들며 흔들리는 것입니다. 그래프에서 진동을 확인하세요.
  • 실물은 이 시뮬레이션보다 지연·잡음·바퀴 미끄럼이 크므로, 원본처럼 보수적인 값에서 시작해 조금씩 올리는 것이 안전합니다.

2D 시뮬레이터 열기 (라인 트레이싱 모드)

4단계: 라이다로 멈추기#

선을 따라가다 사람이나 물건이 앞에 있으면 멈춰야 합니다. lidar_callback은 라이다(/scan_raw, BEST_EFFORT QoS)의 전방 좌우 22.5°씩(scan_angle = 45°)만 봅니다.

  1. 라이다 종류에 따라 인덱스 0의 방향이 다르므로(G4는 뒤쪽이 0), 왼쪽·오른쪽 절반 배열을 따로 만듭니다. 기구에 항상 가려지는 부분을 빼려고 전체 중 240°(MAX_SCAN_ANGLE)만 씁니다.
  2. 전방 ±22.5°에서 0과 inf/nan을 뺀 최솟값을 좌우 각각 구합니다.
  3. 둘 중 하나라도 stop_threshold = 0.4 m보다 가까우면 self.stop = True → 영상 콜백이 Twist()(정지)를 발행합니다.
  4. 멀어져도 바로 출발하지 않고 6번 연속(count > 5) 비어 있어야 stop = False로 돌아갑니다. 라이다 잡음이나 경계에 걸친 물체 때문에 가다 서다를 반복하지 않게 하는 시간 히스테리시스입니다.

아래 노드는 이 로직만 떼어 Playground에서 돌립니다. 원통(사람 역할)이 로봇 앞을 천천히 가로지릅니다.

python브라우저 실행
import math
import numpy as np
import rclpy
from rclpy.node import Node
from rclpy.qos import qos_profile_sensor_data
from geometry_msgs.msg import Twist
from sensor_msgs.msg import LaserScan
import mentorpi_sim as sim                                   # 시뮬 전용
sim.setup(world="empty", duration=16.0, noise=False)         # 시뮬 전용
sim.add_mover(1.3, -1.0, 0.0, 0.15, 0.1)                     # 시뮬 전용: 앞을 가로지르는 사람(원통)

SCAN_ANGLE = math.radians(45)     # 원본 self.scan_angle: 전방 ±22.5°
STOP_DIST = 0.4                   # 원본 self.stop_threshold [m]


class LineLidarGuard(Node):
    def __init__(self):
        super().__init__('line_lidar_guard')
        self.pub = self.create_publisher(Twist, 'cmd_vel', 1)
        self.create_subscription(LaserScan, 'scan', self.on_scan, qos_profile_sensor_data)  # 실물: /scan_raw
        self.stop, self.count = False, 0

    def on_scan(self, scan):
        ang = scan.angle_min + np.arange(len(scan.ranges)) * scan.angle_increment
        r = np.array(scan.ranges)
        front = r[(np.abs(ang) <= SCAN_ANGLE / 2) & np.isfinite(r) & (r > 0)]
        nearest = front.min() if len(front) else float('inf')
        if nearest < STOP_DIST:
            if not self.stop:
                self.get_logger().warn('장애물 %.2f m → 정지' % nearest)
            self.stop, self.count = True, 0
        elif self.stop:
            self.count += 1
            if self.count > 5:                              # 6번 연속 비어 있어야 재출발
                self.stop = False
                self.get_logger().info('전방 비었음(%.2f m) → 재출발' % nearest)
        cmd = Twist()
        if not self.stop:
            cmd.linear.x = 0.15                             # 원본 라인 트레이싱 속도
        self.pub.publish(cmd)


rclpy.init()
node = LineLidarGuard()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    print('최종 위치 x = %.2f m' % sim.pose()[0])           # 시뮬 전용
    node.destroy_node()
    rclpy.shutdown()

[INFO] [8.500] [line_lidar_guard]: 전방 비었음(0.47 m) → 재출발
[sim] 시뮬레이션 시간 16.0 s 종료 (sim.setup(duration=...)으로 변경)
최종 위치 x = 1.95 m

원통이 전방 부채꼴 0.4 m 안에 들어오자 멈추고, 부채꼴을 벗어난 뒤 6번의 스캔(10 Hz → 약 0.6초)을 더 기다려 다시 출발합니다. 원통이 로봇 옆을 지날 때는 ±22.5° 밖이라 무시합니다. 좁은 통로에서 옆 벽 때문에 서 버리지 않게 하려는 설계이지만, 반대로 비스듬히 다가오는 물체는 늦게 봅니다. 실제 코스에 맞게 scan_angle과 stop_threshold를 조정하세요.

2D 시뮬레이터 열기

2D 시뮬레이터 — 라인 트레이싱 모드
  1. 오른쪽 패널의 라인 트레이싱 탭에서 ▶ 시작을 누릅니다(월드가 자동으로 “라인 트랙”으로 바뀝니다). 로봇 앞 가상 카메라의 ROI 중심점이 화면에 찍히고, 아래 상태 줄에 편향각과 명령이 표시됩니다.
  2. 기본값(Kp 1.10, Kd 0, 속도 0.15)으로 한 바퀴를 돌며 선에서 가장 멀어지는 구간(급곡선)을 찾습니다.
  3. Kp 슬라이더를 0.5 → 1.1 → 2.5 → 4.0으로 바꿔 가며 곡선에서의 모습(늦게 도는지, 흔들리는지)을 비교합니다. 흔들림이 생기면 Kd를 조금 올려 봅니다.
  4. 속도를 0.15 → 0.3으로 올리면 같은 Kp에서도 곡선에서 선을 놓치기 쉬운 이유를 설명합니다.
  5. 상단에서 섀시를 애커만으로 바꿔 같은 이득으로 돌아 봅니다. 최소 회전 반경 때문에 어느 곡선에서 선을 놓치는지 확인합니다.
  6. 트랙 위 장애물을 눌러 장애물을 놓고, 라이다 정지가 동작하는 거리와 재출발 시점을 확인합니다.

과제#

기본 과제
  1. 가상 카메라 루프에서 지연을 0.1, 0.3, 0.5초로 바꾸며 각각 RMS 오차가 가장 작은 Kp를 찾아 표로 정리합니다. 지연과 최적 이득의 관계를 한 문장으로 설명합니다.
  2. ROI 가중치를 (0.7, 0.2, 0.1) 대신 (0.4, 0.3, 0.3)으로 바꾸면 곡선 진입 반응이 어떻게 달라지는지 확인합니다.
심화 과제
  1. 편향각 대신 선 중심의 가로 오차(px)와 선 기울기(위·아래 띠 중심의 차)를 따로 쓰는 2항 제어기 ω = k_1 e_x + k_2 θ_{line}를 설계하고, P 제어와 비교합니다.
  2. 라인 트레이싱 중 QR 표지(A02)를 읽으면 3초 동안 멈추는 기능을 설계합니다. 두 기능이 /controller/cmd_vel을 동시에 발행하지 않도록 어떤 구조로 합칠지 그림으로 설명합니다.
