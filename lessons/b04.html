B04리눅스 기초: 설치·명령어·권한

리눅스 소개, VirtualBox에 Ubuntu 설치와 소스 변경, 디렉터리 구조, 자주 쓰는 명령, 사용자와 권한(chmod·sudo)을 실습합니다.

선수 챕터: B03

학습 목표#

  • 운영체제의 역할과 리눅스 배포판(Ubuntu·Debian 등)의 관계를 설명하고, MentorPi에서 어떤 배포판이 어디에 쓰이는지 구분합니다.
  • VirtualBox/VMware에 Ubuntu를 설치하고 소프트웨어 소스(미러)와 공유 폴더를 설정합니다.
  • 리눅스 디렉터리 트리(/, /home, /dev, /etc …)를 탐색하고 절대·상대 경로를 자유롭게 씁니다.
  • 명령 + 옵션 + 대상 형식을 이해하고 자주 쓰는 명령(ls cd pwd cp mv rm mkdir find …)과 도움말(--help, man, Tab 자동완성)을 활용합니다.
  • rwx 권한과 8진수 표기를 읽고 chmod·sudo·su로 권한을 다룹니다.

운영체제와 리눅스#

컴퓨터는 하드웨어(CPU·메모리·디스크·키보드)와 소프트웨어로 이루어집니다. 운영체제(OS, Operating System)는 그 사이의 중개자로서 프로그램 실행, 메모리·파일·장치 같은 자원 관리, 기본 서비스 제공을 맡습니다.

리눅스(Linux)는 Windows처럼 운영체제이지만 오픈 소스라는 점이 다릅니다. 서버, 임베디드 기기, 데스크톱 세 분야에서 널리 쓰이며, 특히 서버와 로봇(ROS)의 표준 플랫폼입니다.

특징로봇 개발에서의 의미
무료·오픈 소스라즈베리파이 같은 저가 보드에 자유롭게 탑재
다중 사용자·다중 작업여러 ROS 노드가 동시에 돌고, PC와 로봇에서 동시에 원격 접속
강력한 패키지 관리(apt)sudo apt install ros-humble-…처럼 한 줄로 설치
안정성·원격 관리모니터 없는 로봇을 SSH로 운용

주요 배포판#

리눅스 커널에 각종 도구와 패키지 관리 방식을 묶은 것을 배포판(distribution)이라 합니다.

배포판특징MentorPi에서
Debian1993년 출시, 매우 안정적, 3만 개 이상 패키지라즈베리파이 OS(호스트)의 기반(bookworm)
UbuntuDebian 기반, 사용자 친화적 데스크톱, 넓은 하드웨어 지원컨테이너 안(22.04) — ROS 2 Humble의 기준 OS. 실습용 가상 머신
RHEL / CentOS / FedoraRed Hat 계열 서버·데스크톱—
openSUSE유럽에서 인기 있는 배포판—

즉 MentorPi는 Debian(호스트) 위에서 Ubuntu(컨테이너)를 돌리는 구조입니다(B03). 두 배포판 모두 apt 패키지 관리자를 쓰므로 명령은 거의 같습니다.

PC에 실습 환경 만들기: 가상 머신#

가상 머신(VM, Virtual Machine)은 Windows 위에서 다른 OS를 통째로 돌리는 소프트웨어입니다. 로봇을 망가뜨릴 걱정 없이 리눅스 명령을 연습하고, 나중에 PC 쪽 ROS 2(RViz 등)를 설치하는 데 씁니다.

설치 흐름(VirtualBox 기준)#

  1. 교재 폴더의 VirtualBox 설치 파일 실행 → 설치 경로 선택 → 기본값으로 Next → Yes/Install → Finish
  2. Ubuntu 이미지(교재 제공 압축 파일 또는 공식 ISO)로 새 가상 머신 생성: 메모리 4 GB 이상, 디스크 30 GB 이상 권장
  3. 설치 후 로그인

VMware Workstation을 쓸 때도 흐름은 같습니다("Create a New Virtual Machine" → Custom → 단계별 설정). VMware는 30일 평가판입니다.

소프트웨어 소스(미러) 바꾸기#

apt가 패키지를 내려받는 서버를 소스(source) 또는 미러(mirror)라고 합니다. 앱 스토어의 서버와 같은 역할입니다. 기본 서버가 멀어 느리거나 오류가 나면 가까운 미러로 바꿉니다.

  1. Settings → Software & Updates 실행
  2. "Download from" → Other… → 목록에서 국내 미러(예: mirror.kakao.com, ftp.kaist.ac.kr) 선택, 또는 Select Best Server
  3. 비밀번호 입력 → 목록 갱신
bash
sudo apt update          # 새 소스에서 패키지 목록 다시 받기
소스 목록 파일

GUI로 바꾼 내용은 결국 /etc/apt/sources.list(또는 /etc/apt/sources.list.d/*) 파일에 기록됩니다. 라즈베리파이 OS에서는 이 파일을 nano로 직접 편집해 미러를 바꿉니다(B07).

공유 폴더#

PC(호스트)와 가상 머신 사이에 파일을 주고받는 폴더입니다. 처음 설정할 때 공유 폴더는 비어 있어야 설정이 실패하지 않습니다.

VirtualBox

  1. 가상 머신 Settings → Shared Folders → 폴더 경로·이름(share) 지정, Auto-mount 체크, 마운트 지점 /mnt/share
  2. Devices → Insert Guest Additions CD image → 실행·비밀번호 입력 → 설치 완료
  3. 터미널에서
bash
sudo mkdir /mnt/share
sudo mount -t vboxsf share /mnt/share      # 첫 share = 호스트에서 지정한 공유 이름
sudo usermod -aG vboxsf $(whoami)          # 현재 사용자를 vboxsf 그룹에 추가 → 재부팅

VMware

  1. VM 끄기 → Settings → Options → Shared Folders → Always Enabled → Add(예: share_test)
  2. 부팅 후
bash
sudo apt install open-vm-tools
ls /mnt/                                   # hgfs 폴더가 있는지 확인, 없으면 sudo mkdir /mnt/hgfs
sudo mount -t fuse.vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other

재부팅마다 마운트하기 번거로우면 /etc/fstab에 한 줄을 추가해 자동 마운트합니다.

text
.host:/  /mnt/hgfs  fuse.vmhgfs-fuse  auto,allow_other  0  0

터미널과 명령 형식#

GUI로도 파일을 복사·이동할 수 있지만, 로봇은 모니터 없이 원격으로 쓰는 일이 많아 터미널(terminal)이 주 무대입니다. Ctrl+Alt+T로 엽니다.

text
hiwonder@ubuntu:~$
   │       │    │ └─ $ 일반 사용자 / # 관리자(root)
   │       │    └─── 현재 디렉터리 (~ = 홈)
   │       └──────── 호스트 이름
   └──────────────── 사용자 이름

명령은 **명령 [옵션] [대상]** 형식이며 각 부분은 공백으로 구분합니다.

  • 짧은 옵션: - + 한 글자(-l, -a). 여러 개를 합칠 수 있습니다: ls -l -a = ls -la
  • 긴 옵션: -- + 단어(--help). 합칠 수 없습니다.
  • 대상은 여러 개일 수 있습니다: cp a.txt b.txt backup/
  • 리눅스는 대소문자를 구분합니다. Desktop과 desktop은 다른 폴더입니다.

디렉터리 구조#

리눅스는 모든 것을 하나의 트리로 다룹니다. 맨 위는 루트(root) /이고, Windows의 C:·D: 같은 드라이브 구분 대신 저장 장치를 트리의 한 지점에 마운트(mount)합니다.

bash
cd /            # 루트로 이동
sudo apt-get install tree
tree -L 1       # 1단계 하위 폴더만 트리로 표시
디렉터리내용로봇에서의 예
/bin, /sbin기본 명령·시스템 명령ls, cp
/boot부팅 파일라즈베리파이 config.txt(B07)
/dev장치 파일/dev/ttyAMA0(UART), /dev/video0(카메라), /dev/input/js0(조이패드)
/etc시스템 설정 파일/etc/apt/sources.list, /etc/NetworkManager/
/home사용자 홈/home/pi(호스트), /home/ubuntu(컨테이너)
/lib공유 라이브러리
/media, /mnt이동식 저장장치·임시 마운트 지점USB 메모리, 공유 폴더
/opt추가 소프트웨어/opt/ros/humble
/proc, /sys커널이 보여 주는 시스템 정보(가상 파일)/sys/class/thermal/thermal_zone0/temp
/rootroot 사용자의 홈
/tmp임시 파일(재부팅 시 삭제)
/usr사용자 프로그램·라이브러리/usr/bin/python3
/var자주 바뀌는 데이터(로그 등)/var/log
장치도 파일이다

/dev/ttyAMA0에 바이트를 쓰면 UART로 전송되고, /sys/class/thermal/thermal_zone0/temp를 읽으면 CPU 온도가 나옵니다. 리눅스의 "모든 것은 파일" 철학 덕분에, 로봇의 확장보드 SDK도 결국 시리얼 장치 파일을 열고 읽고 쓰는 프로그램입니다(B08).

도움말과 단축키#

  • 명령 --help: 간단한 사용법. 예: ls --help
  • man 명령: 자세한 매뉴얼. Space 다음 쪽, B 이전 쪽, Enter 한 줄 아래, q 종료
  • Tab: 명령·파일 이름 자동완성. 후보가 여러 개면 두 번 눌러 목록 표시. cd Pict + Tab → cd Pictures/
  • ↑/↓: 명령 기록
  • Ctrl+C: 실행 중인 프로그램 중단(ROS 노드 종료에 가장 많이 씀)
  • Ctrl+D: 터미널(셸) 종료
  • Ctrl+A / Ctrl+E: 줄 맨 앞 / 맨 끝으로 커서 이동
rm은 되돌릴 수 없습니다

터미널의 rm은 휴지통을 거치지 않습니다. 특히 sudo rm -rf 뒤에 경로를 잘못 쓰면 시스템이 망가집니다. 지우기 전에 ls로 대상을 먼저 확인하는 습관을 들이세요.

사용자와 권한#

리눅스는 다중 사용자 OS라서 누가 어떤 파일에 무엇을 할 수 있는지를 엄격히 관리합니다. 관리자 root는 거의 모든 것을 할 수 있고, 일반 사용자는 허락된 범위에서만 작업합니다.

사용자 전환#

bash
sudo passwd        # root 비밀번호 설정(Ubuntu는 기본적으로 root 비밀번호가 없음)
su                 # root로 전환 → 프롬프트 끝이 $ 에서 # 로 바뀜
exit               # 원래 사용자로 복귀
sudo 명령          # 한 명령만 관리자 권한으로 실행(권장 방식)

일상 작업은 su로 root에 머무르기보다 **필요한 명령에만 sudo**를 붙이는 편이 안전합니다.

권한 읽기#

bash
touch test.txt
ls -l test.txt
# -rw-rw-r-- 1 hiwonder hiwonder 0 ... test.txt
권한파일에서디렉터리에서
r(4)내용 읽기목록 보기(ls)
w(2)내용 수정안의 파일 생성·삭제·이름 변경
x(1)프로그램으로 실행안으로 들어가기(cd)
8진수문자의미
7rwx읽기·쓰기·실행
6rw-읽기·쓰기
5r-x읽기·실행
4r--읽기만
0---권한 없음

권한 바꾸기: chmod#

bash
chmod 755 run.sh          # 숫자 방식: 소유자 rwx, 그룹 r-x, 기타 r-x
chmod u+x test_1.txt      # 문자 방식: 소유자(u)에 실행 추가
chmod g+x test_1.txt      # 그룹(g)
chmod o-x test_1.txt      # 기타(o)에서 실행 제거
chmod a+w test_1.txt      # 모두(a)에 쓰기 추가

문자 방식은 u/g/o/a + +/-/= + r/w/x 조합이라 일부만 바꿀 때 편하고, 숫자 방식은 전체를 한 번에 정할 때 편합니다.

로봇에서 권한이 문제 되는 순간
  • 파이썬 스크립트를 ./run.py처럼 직접 실행하려면 x 권한과 첫 줄 #!/usr/bin/env python3(셔뱅)이 필요합니다.
  • 시리얼 장치 /dev/ttyAMA0에 일반 사용자가 접근하지 못하면 원본은 sudo chmod 777 /dev/ttyAMA0을 안내합니다. 하지만 이 설정은 재부팅하면 사라지고 모든 사용자에게 쓰기를 열어 줍니다. 더 나은 방법은 사용자를 장치 그룹(dialout)에 넣는 것입니다: sudo usermod -aG dialout $USER 후 재로그인.
  • docker 명령을 sudo 없이 쓰려면 사용자가 docker 그룹에 있어야 합니다(B10).

실습 (실물)#

가상 머신의 Ubuntu 또는 MentorPi 호스트 터미널(VNC/SSH)에서 진행합니다.

안전 확인 (실물 실습 전 필수)
  • 로봇의 시스템 폴더(/etc, /boot, /usr)에서는 읽기만 합니다. 실습 파일은 반드시 홈 아래 ~/linux_lab에서 만듭니다.
  • sudo rm, chmod -R 같은 명령은 대상 경로를 ls로 확인한 뒤에만 실행합니다.
  • 로봇 전원을 끌 때는 스위치를 바로 내리지 말고 sudo shutdown -h now 후 LED가 꺼지면 내립니다(SD 카드 손상 방지).
따라 하기
  1. pwd → cd / → tree -L 1(없으면 sudo apt install tree)로 루트 구조를 확인합니다.
  2. ls /dev | grep -E "tty|video|js"로 로봇에 연결된 장치 파일을 찾습니다.
  3. cat /sys/class/thermal/thermal_zone0/temp로 CPU 온도(1/1000 °C)를 읽습니다.
  4. 홈에서 실습 폴더 만들기: mkdir -p ~/linux_lab/scripts && cd ~/linux_lab
  5. touch notes.txt test.txt → ls -l로 기본 권한을 확인하고, chmod 777 test.txt 후 다시 확인합니다.
  6. echo 'print("hello robot")' > scripts/hello.py → python3 scripts/hello.py 실행
  7. cp scripts/hello.py scripts/hello2.py → mv scripts/hello2.py scripts/hi.py → rm scripts/hi.py
  8. find ~ -name "*.py" 2>/dev/null | head로 홈의 파이썬 파일을 찾습니다.
  9. (로봇) 컨테이너에 들어가 grep -rn "cmd_vel" ~/ros2_ws/src/peripherals/peripherals | head로 조이패드 노드가 어떤 토픽을 쓰는지 찾습니다.
bash
# 참고: 4~7단계를 한 번에
mkdir -p ~/linux_lab/scripts && cd ~/linux_lab
touch notes.txt test.txt && ls -l
chmod 777 test.txt && ls -l test.txt
echo 'print("hello robot")' > scripts/hello.py

과제#

기본
  1. ls -l 결과에서 drwxr-xr--와 -rw-r-----를 각각 8진수로 바꾸고, "그룹 사용자가 할 수 있는 일"을 문장으로 씁니다.
  2. 홈에서 출발해 ~/ros2_ws/src/driver/controller로 가는 절대 경로와, ~/ros2_ws/src/app에서 같은 곳으로 가는 상대 경로를 각각 씁니다.
심화
  1. find와 grep을 조합해 컨테이너의 ~/ros2_ws/src에서 create_publisher가 들어간 파이썬 파일 개수를 세는 한 줄 명령을 만듭니다(힌트: grep -rl … | wc -l).
  2. chmod 777 /dev/ttyAMA0와 usermod -aG dialout의 차이를 지속성과 보안 관점에서 비교합니다.
