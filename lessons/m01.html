M01메카넘 휠 섀시 기구학

45° 롤러가 만드는 전방향 이동, (vx, vy, ωz) → 네 바퀴 속도 역기구학과 순기구학, MentorPi mecanum.py 해설.

선수 챕터: R03 B09
3D 시뮬레이터섀시 기구학 실험실2D 시뮬레이터ROS 2 Playground

학습 목표#

  • 메카넘 휠(Mecanum wheel)의 45° 롤러가 옆 방향 미끄럼을 허용하는 원리를 설명하고, ABAB 배치가 필요한 이유를 말할 수 있습니다.
  • 접지점 속도와 롤러 구속 조건에서 출발해 (v_x, v_y, ω_z) → 네 바퀴 속도의 역기구학(inverse kinematics) 행렬을 직접 유도합니다.
  • MentorPi 원본 mecanum.py의 식, [-m1, -m2, m3, m4] 부호, m/s → rps 변환을 한 줄씩 해석합니다.
  • 의사역행렬로 순기구학(forward kinematics) 을 구하고, 바퀴 속도가 한계를 넘을 때 방향을 유지하며 줄이는 방법을 구현합니다.
  • 시뮬레이터와 실물에서 /cmd_vel의 linear.y로 옆걸음·대각선 주행을 확인합니다.

메카넘 휠의 구조#

메카넘 휠은 바퀴 둘레에 작은 롤러(roller) 가 비스듬히 달린 바퀴입니다. 롤러의 회전축은 바퀴 차축과 45° 를 이룹니다. 롤러는 모터와 연결되지 않고 자유롭게 돌기 때문에, 바퀴가 바닥을 미는 힘은 롤러 축에 수직인 방향으로만 전달됩니다. 롤러 축 방향으로는 롤러가 굴러 버리므로 힘이 전달되지 않습니다(자유 미끄럼).

그 결과 바퀴 하나가 만드는 추진력은 차체 전방에 대해 45° 기울어집니다. 네 바퀴의 추진력 벡터를 더하는 방법에 따라

  • 네 바퀴를 같은 방향으로 돌리면 옆 성분이 서로 상쇄되어 전진,
  • 대각선끼리 짝지어 반대로 돌리면 전후 성분이 상쇄되어 옆걸음(strafe),
  • 좌우를 반대로 돌리면 제자리 회전이 됩니다.

바퀴는 롤러 기울기가 거울상인 A형과 B형이 있습니다. AAAA나 AABB처럼 잘못 조합하면 옆 성분이 상쇄되지 않거나 옆걸음을 만들 수 없습니다. MentorPi는 교재 표현으로 ABAB 조합을 써서, 위에서 봤을 때 대각선 위치의 두 바퀴가 같은 형이 됩니다.

위에서 본 롤러와 바닥에 닿은 롤러

바퀴 위쪽에 보이는 롤러와 바닥에 닿아 있는 롤러는 기울기가 반대입니다(바퀴 반대편이니까요). 기구학에서 의미 있는 것은 바닥에 닿은 롤러의 축 방향입니다. 이 장의 그림과 식은 모두 접지 롤러 기준입니다. 조립할 때는 "위에서 봤을 때 롤러가 X자를 이루는가, O자를 이루는가"로 확인하는데, 제조사마다 부르는 방식이 달라 헷갈리기 쉬우니 옆걸음 시험으로 최종 확인하세요.

좌표계와 기호#

ROS 표준(REP-103)에 따라 차체 좌표계는 x 전방, y 왼쪽, z 위, 회전 ω_z는 위에서 볼 때 반시계가 +입니다.

기호의미MentorPi 값 (odom_publisher_node.py)
awheelbase, 앞·뒤 차축 거리0.1368 m
btrack_width, 좌·우 바퀴 거리0.1446 m
d바퀴 지름0.065 m
l_x = a/2, l_y = b/2중심에서 바퀴까지0.0684 m, 0.0723 m
K = l_x + l_y = (a+b)/2회전 기여 계수0.1407 m

모터 번호는 원본 소스 주석의 그림을 따릅니다: M1 앞·왼쪽, M2 뒤·왼쪽, M3 앞·오른쪽, M4 뒤·오른쪽.

역기구학 유도#

목표: 차체 속도 (v_x, v_y, ω_z)가 주어졌을 때 각 바퀴가 굴러야 할 접지 속도 v_i [m/s]를 구합니다. 가정은 두 가지입니다. ① 바퀴 구동 방향으로는 미끄러지지 않는다. ② 네 바퀴는 직사각형 꼭짓점에 평행하게 놓여 있다.

1단계 — 바퀴 접지점의 속도#

강체 위의 점 r = (r_x, r_y)의 속도는 v + ω × r입니다. 평면에서 풀어 쓰면

text
v_px = vx − ωz · r_y
v_py = vy + ωz · r_x

예를 들어 M1(앞·왼쪽)은 r = (+l_x, +l_y)이므로 v_px = v_x − ω_z·l_y, v_py = v_y + ω_z·l_x입니다.

2단계 — 롤러 구속 조건#

접지점 속도 v_p는 두 성분의 합으로만 만들어질 수 있습니다. 바퀴가 굴러서 생기는 구동 성분 v_w(차체 x 방향)와, 롤러가 자유롭게 돌아서 생기는 미끄럼 성분 v_r(롤러 축 방향 û = (cos α, sin α))입니다.

text
v_p  = v_w · (1, 0) + v_r · (cos α, sin α)
v_px = v_w + v_r · cos α
v_py =       v_r · sin α        →  v_r = v_py / sin α
∴ v_w = v_px − v_py · cot α

롤러가 45°이면 cot(±45°) = ±1이라 식이 아주 간단해집니다.

text
α = +45°  →  v_w = v_px − v_py
α = −45°  →  v_w = v_px + v_py

3단계 — 네 바퀴에 대입#

접지 롤러 축은 M1·M4가 +45°, M2·M3가 −45°입니다(그림의 주황 사선). 각 바퀴의 위치와 α를 넣습니다.

바퀴위치 (r_x, r_y)αv_w 계산결과
M1 앞·왼(+l_x, +l_y)+45°(v_x − ω l_y) − (v_y + ω l_x)v_x − v_y − K ω
M2 뒤·왼(−l_x, +l_y)−45°(v_x − ω l_y) + (v_y − ω l_x)v_x + v_y − K ω
M3 앞·오(+l_x, −l_y)−45°(v_x + ω l_y) + (v_y + ω l_x)v_x + v_y + K ω
M4 뒤·오(−l_x, −l_y)+45°(v_x + ω l_y) − (v_y − ω l_x)v_x − v_y + K ω

행렬로 묶으면 역기구학 행렬 J(4×3)가 됩니다.

text
┌ v1 ┐   ┌ 1  −1  −K ┐
│ v2 │ = │ 1  +1  −K │ ┌ vx ┐
│ v3 │   │ 1  +1  +K │ │ vy │
└ v4 ┘   └ 1  −1  +K ┘ └ ωz ┘

이 결과는 원본 mecanum.py의 motor1 … motor4 식과 글자 그대로 같습니다. 원본은 (self.wheelbase + self.track_width) / 2를 쓰는데 이것이 바로 K = l_x + l_y입니다. 원본 교재(Lesson 1)는 같은 식을 L/2, H/2(좌우·전후 반거리)로 적습니다.

K의 물리적 의미

K는 "차체가 1 rad/s로 돌 때 바퀴가 굴러야 하는 속도"입니다. 45° 롤러 때문에 바퀴에서 회전 중심까지의 x 거리와 y 거리가 모두 기여하므로 단순한 원 반지름 √(l_x² + l_y²) = 0.0995 m가 아니라 l_x + l_y = 0.1407 m가 됩니다.

기본 동작별 바퀴 방향#

v_i의 부호(+ = 바퀴가 전진 방향으로 구름)로 정리하면 아래와 같습니다. 이 표를 외워 두면 실물 조립 오류를 빨리 찾습니다.

동작명령M1M2M3M4
전진v_x > 0++++
왼쪽 옆걸음v_y > 0−++−
제자리 좌회전ω_z > 0−−++
앞·왼 대각선v_x = v_y > 00++0
앞·오른 대각선v_x = −v_y > 0+00+

대각선 주행에서는 두 바퀴가 멈춰 있고 나머지 두 바퀴가 2v로 돕니다. 멈춘 바퀴는 롤러만 굴러가며 끌려갑니다.

원본 mecanum.py 해설#

원본 클래스의 핵심만 추리면 다음과 같습니다(메시지 생성 부분 생략).

python
class MecanumChassis:
    def __init__(self, wheelbase=0.1368, track_width=0.1410, wheel_diameter=0.065):
        ...
    def speed_covert(self, speed):              # m/s → 초당 회전수(rps)
        return speed / (math.pi * self.wheel_diameter)

    def set_velocity(self, linear_x, linear_y, angular_z):
        k = (self.wheelbase + self.track_width) / 2
        motor1 = linear_x - linear_y - angular_z * k
        motor2 = linear_x + linear_y - angular_z * k
        motor3 = linear_x + linear_y + angular_z * k
        motor4 = linear_x - linear_y + angular_z * k
        v_s = [self.speed_covert(v) for v in [-motor1, -motor2, motor3, motor4]]
        # → MotorsState(id 1~4, rps) 로 /ros_robot_controller/set_motor 에 발행

읽을 때 짚어야 할 네 가지입니다.

  1. rps 변환: 바퀴가 한 바퀴 돌면 둘레 π d = 0.2042 m를 갑니다. 따라서 rps = v / (π d)입니다. 0.2 m/s는 약 0.98 rps(59 rpm)입니다. 이 값은 확장보드(RRC Lite)의 STM32로 전달되고, 보드가 엔코더 피드백으로 모터 속도를 맞춥니다(B09 참고). 이름이 speed_covert(convert 오타)인 것도 원본 그대로입니다.
  2. **[-m1, -m2, m3, m4] 부호: 왼쪽 모터(M1·M2)와 오른쪽 모터(M3·M4)는 차체 양쪽에 거울상으로** 장착됩니다. 같은 방향(예: 모터 축을 바라보고 시계방향)으로 돌면 왼쪽 바퀴는 뒤로, 오른쪽 바퀴는 앞으로 굴러가므로, 왼쪽 명령의 부호를 뒤집어 "+ = 전진"을 맞춥니다. 그래서 전진 명령은 rps가 [−, −, +, +]로 나가고, 반대로 제자리 회전은 네 모터 rps가 모두 같은 부호가 됩니다(아래 실습 1에서 확인).
  3. track_width 두 값: 클래스 기본값은 0.1410 m이지만, 실제로 객체를 만드는 odom_publisher_node.py는 MecanumChassis(wheelbase=0.1368, track_width=0.1446, wheel_diameter=0.065)로 0.1446 m를 넘깁니다. 동작에 쓰이는 값은 0.1446 m입니다.
  4. 제한 없음: set_velocity는 속도를 자르지 않습니다. 제한은 한 단계 위, /cmd_vel 콜백(app_cmd_vel_callback)이 |v_x|, |v_y| ≤ 0.2 m/s, |ω_z| ≤ 0.5 rad/s로 합니다. /controller/cmd_vel로 직접 보내면 제한 없이 들어갑니다(M04).

순기구학: 바퀴 속도 → 차체 속도#

오도메트리나 슬립 검출에는 반대 방향, 즉 네 바퀴 속도에서 (v_x, v_y, ω_z)를 구하는 식이 필요합니다. 식은 4개, 미지수는 3개라 J는 정사각행렬이 아닙니다. 최소제곱해인 의사역행렬(pseudo-inverse) J⁺ = (JᵀJ)⁻¹Jᵀ를 쓰면

text
vx =  ( v1 + v2 + v3 + v4) / 4
vy =  (−v1 + v2 + v3 − v4) / 4
ωz =  (−v1 − v2 + v3 + v4) / (4K)

J의 세 열이 서로 직교하기 때문에 JᵀJ가 대각행렬 diag(4, 4, 4K²)이 되어 식이 이렇게 깔끔합니다.

네 번째 식은 어디로? — 슬립 지표

바퀴 4개가 만드는 공간은 4차원인데 차체 운동은 3차원입니다. 남는 한 방향 v_1 − v_2 + v_3 − v_4(대각 바퀴끼리의 차이)는 어떤 차체 운동으로도 만들 수 없는 조합입니다. 측정된 바퀴 속도에서 이 값이 0에서 멀어지면 바퀴가 미끄러지고 있거나 한 바퀴가 바닥에서 떠 있다는 뜻입니다. 간단한 슬립 검출기로 쓸 수 있습니다.

바퀴 속도 포화와 방향 보존#

모터에는 최고 속도가 있습니다. 교재는 선속도를 −0.6 ~ 0.6 m/s 안에서 쓰라고 권장합니다. 예를 들어 v_x = 0.5, v_y = 0.3을 요청하면 M2·M3는 0.8 m/s가 필요합니다. 보드가 각 바퀴를 따로 잘라 버리면 바퀴 사이의 비율이 깨져 방향이 틀어집니다. 올바른 방법은 가장 큰 바퀴 속도가 한계에 맞도록 네 바퀴를 같은 비율로 줄이는 것입니다.

python
def desaturate(wheels, v_max=0.6):
    peak = max(abs(v) for v in wheels)
    scale = min(1.0, v_max / peak) if peak > 0 else 1.0
    return [v * scale for v in wheels]      # 방향은 그대로, 속도만 줄어듦

MentorPi 기본 스택에서는 /cmd_vel의 0.2 m/s 제한 덕분에 이 상황이 잘 생기지 않지만, /controller/cmd_vel을 직접 쓰는 내비게이션(M11~M13)에서는 의미가 있습니다.

실습 (시뮬레이션)#

1. NumPy로 역기구학·순기구학 계산#

원본 식을 행렬로 옮겨 기본 동작의 바퀴 속도와 모터 rps를 계산하고, 의사역행렬로 되돌려 봅니다.

python브라우저 실행
import math
import numpy as np

WHEELBASE, TRACK, D = 0.1368, 0.1446, 0.065   # odom_publisher_node.py 값
K = (WHEELBASE + TRACK) / 2                   # lx + ly

J = np.array([[1, -1, -K],                    # M1 앞·왼
              [1,  1, -K],                    # M2 뒤·왼
              [1,  1,  K],                    # M3 앞·오
              [1, -1,  K]])                   # M4 뒤·오
SIGN = np.array([-1, -1, 1, 1])               # 왼쪽 모터는 거울 장착

def ik_rps(vx, vy, wz):
    v = J @ np.array([vx, vy, wz])            # 바퀴 접지 속도 [m/s]
    return v, SIGN * v / (math.pi * D)        # 모터 명령 [rps]

for name, cmd in [("전진", (0.2, 0, 0)), ("왼쪽 옆", (0, 0.2, 0)),
                  ("제자리 좌회전", (0, 0, 0.5)), ("대각 45°", (0.1414, 0.1414, 0))]:
    v, rps = ik_rps(*cmd)
    print("%-8s v=%s  rps=%s" % (name, np.round(v, 3) + 0.0, np.round(rps, 3) + 0.0))

Jp = np.linalg.pinv(J)                        # 순기구학
v, _ = ik_rps(0.12, -0.05, 0.3)
print("FK 복원:", np.round(Jp @ v, 4) + 0.0)
print("4·J+ =", np.round(4 * Jp, 3).tolist())
print("슬립 지표 v1-v2+v3-v4 =", round(v[0] - v[1] + v[2] - v[3], 6) + 0.0)

2. 옆걸음과 대각선 주행#

가상 메카넘 로봇을 4초 동안 왼쪽으로 옆걸음(0.15 m/s), 이어서 4초 동안 오른쪽 앞 대각선(v_x = 0.1, v_y = −0.1)으로 움직이며 /odom과 실제 위치 /ground_truth를 출력합니다.

python브라우저 실행
import math
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from nav_msgs.msg import Odometry
from tf_transformations import euler_from_quaternion
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=8.5,
          start=(0.0, 0.0, 0.0), noise=False)                     # 시뮬 전용

PLAN = [(0.0, 4.0, 0.0, 0.15), (4.0, 8.0, 0.1, -0.1)]   # (시작 s, 끝 s, vx, vy)

class Strafe(Node):
    def __init__(self):
        super().__init__("strafe_demo")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Odometry, "/odom", self.on_odom, 10)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.odom = self.gt = None
        self.t0 = time.time()
        self.next_print = 0.0
        self.create_timer(0.05, self.tick)

    def on_odom(self, msg):
        p, q = msg.pose.pose.position, msg.pose.pose.orientation
        yaw = euler_from_quaternion([q.x, q.y, q.z, q.w])[2]
        self.odom = (p.x, p.y, yaw)

    def on_gt(self, msg):
        self.gt = (msg.x, msg.y)

    def tick(self):
        t = time.time() - self.t0
        cmd = Twist()
        for t_on, t_off, vx, vy in PLAN:
            if t_on <= t < t_off:
                cmd.linear.x, cmd.linear.y = vx, vy
        self.pub.publish(cmd)
        if t >= self.next_print and self.odom and self.gt:
            ox, oy, oyaw = self.odom
            print("t=%4.1f  odom x=%+.3f y=%+.3f yaw=%+5.1f°  | 실제 x=%+.3f y=%+.3f"
                  % (t, ox, oy, math.degrees(oyaw), self.gt[0], self.gt[1]))
            self.next_print += 2.0

rclpy.init()
node = Strafe()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()

3. 돌면서 직진하기 (세계 좌표 기준 주행)#

메카넘만 할 수 있는 동작입니다. 로봇은 0.5 rad/s로 계속 돌면서, 세계 좌표 +x 방향으로 0.15 m/s 직진합니다. 세계 좌표 속도 (V, 0)을 로봇 좌표로 바꾸려면 현재 yaw만큼 거꾸로 돌리면 됩니다: v_x = Vcos ψ, v_y = −Vsin ψ.

python브라우저 실행
import math
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from nav_msgs.msg import Odometry
from tf_transformations import euler_from_quaternion
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=10.5,
          start=(-1.0, 0.0, 0.0), noise=False)                    # 시뮬 전용

V, W, DT = 0.15, 0.5, 0.05

class FieldCentric(Node):
    def __init__(self):
        super().__init__("field_centric")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Odometry, "/odom", self.on_odom, 10)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.yaw, self.gt, self.n = 0.0, None, 0
        self.create_timer(DT, self.tick)

    def on_odom(self, msg):
        q = msg.pose.pose.orientation
        self.yaw = euler_from_quaternion([q.x, q.y, q.z, q.w])[2]

    def on_gt(self, msg):
        self.gt = msg

    def tick(self):
        psi = self.yaw + W * DT / 2          # 다음 주기 동안의 평균 yaw로 보정
        cmd = Twist()
        cmd.linear.x = V * math.cos(psi)     # 세계 (V, 0) → 로봇 좌표
        cmd.linear.y = -V * math.sin(psi)
        cmd.angular.z = W
        self.pub.publish(cmd)
        self.n += 1
        if self.n % 40 == 0 and self.gt:
            g = self.gt
            print("t=%4.1f  실제 x=%+.3f y=%+.3f  yaw=%+6.1f°" % (
                self.n * DT, g.x, g.y, math.degrees(g.theta)))

rclpy.init()
node = FieldCentric()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()

반 주기 앞선 yaw를 쓰는 이유

명령을 보낸 뒤 다음 명령까지 0.05 s 동안 로봇은 W·DT = 0.025 rad 더 돕니다. 현재 yaw로만 계산하면 속도 벡터가 평균 0.0125 rad씩 늦게 돌아서 궤적이 한쪽으로 휩니다. psi = yaw + W·DT/2는 그 구간의 평균 방향을 쓰는 간단한 지연 보상입니다. 이 줄을 psi = self.yaw로 바꿔 y 오차를 비교해 보세요.
