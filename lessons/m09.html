M09SLAM 원리와 slam_toolbox 지도 작성

위치추정과 지도작성의 닭-달걀 문제, 점유 격자, 스캔 매칭과 루프 클로저, slam_toolbox로 2D 지도 작성·저장.

선수 챕터: M08
2D 시뮬레이터ROS 2 Playground

학습 목표#

  • SLAM(Simultaneous Localization and Mapping)이 왜 "닭이 먼저냐 달걀이 먼저냐" 문제인지 설명하고, 전처리 → 매칭 → 지도 융합 흐름을 말할 수 있습니다.
  • 점유 격자(occupancy grid)의 로그 오즈(log-odds) 갱신식을 유도하고, 라이다 한 빔으로 셀을 갱신하는 코드를 작성합니다.
  • 스캔 매칭(scan matching), 포즈 그래프(pose graph), 루프 클로저(loop closure)의 역할을 설명하고 slam.yaml의 해당 파라미터와 연결합니다.
  • MentorPi에서 slam.launch.py로 지도를 만들고 map_saver_cli로 저장한 뒤, 지도 품질을 기준에 따라 판정합니다.

SLAM 문제#

내비게이션을 하려면 지도가 있어야 하고, 지도에서 내 위치를 알아야 합니다. 그런데

  • 지도를 그리려면 스캔을 찍은 순간의 로봇 위치를 정확히 알아야 하고,
  • 위치를 정확히 알려면 비교할 지도가 있어야 합니다.

바퀴 오도메트리(M03)만 믿고 스캔을 겹치면 어떻게 될까요? 오도메트리는 미끄러짐·바퀴 지름 오차 때문에 이동할수록 오차가 쌓입니다(드리프트). 한 바퀴 돌아 출발점에 왔을 때 복도 끝이 두 겹으로 그려집니다. SLAM은 위치와 지도를 동시에 추정해 이 오차를 잡습니다. 확률로 쓰면 다음 분포를 구하는 문제입니다.

p(x₁…ₜ, m | z₁…ₜ, u₁…ₜ) — 명령 u와 관측 z가 주어졌을 때 궤적 x와 지도 m의 결합 분포

교재는 과정을 세 단계로 요약합니다. 이 장은 각 단계에서 실제로 무슨 계산을 하는지 보강합니다.

단계교재 설명실제 계산 (slam_toolbox 기준)
① 전처리라이다 점구름의 이상치 제거·필터링최소/최대 거리 자르기, 스캔 버퍼링, 움직였을 때만 처리
② 매칭현재 스캔을 기존 지도에 맞춰 위치 찾기상관 스캔 매칭(correlative scan matching)으로 자세 보정
③ 지도 융합새 스캔을 지도에 합침포즈 그래프에 노드·제약 추가, 루프 클로저 후 최적화, 점유 격자 다시 그리기

점유 격자와 로그 오즈#

격자 지도#

2D SLAM의 결과물은 점유 격자 지도(occupancy grid map)입니다. 공간을 해상도 resolution(MentorPi는 0.05 m)의 정사각형 셀로 나누고, 셀마다 "장애물이 있을 확률" p(mᵢ)를 저장합니다. ROS의 nav_msgs/OccupancyGrid는 이 값을 0~100(%)과 −1(모름)로 담고, 파일로 저장하면 PGM 영상 + YAML이 됩니다.

빔 하나가 알려 주는 것#

라이다 빔 하나가 거리 r에서 반사됐다면,

  • 로봇에서 r 직전까지 빔이 지나간 셀은 비어 있을 가능성이 높고,
  • r 지점의 셀은 점유됐을 가능성이 높고,
  • r 너머는 아무 정보가 없습니다(가려짐).

지나간 셀을 찾는 데는 원본 AMCL 레슨에도 나오는 Bresenham 직선 알고리즘이 쓰입니다(정수 덧셈만으로 선 위 셀을 나열). 아래 실습 코드는 더 단순하게 빔을 따라 반 셀 간격으로 표본을 찍습니다.

로그 오즈 갱신식 유도#

셀 하나에 대해 관측 z₁…ₜ가 주어졌을 때의 점유 확률을 베이즈 규칙으로 갱신하면(셀들이 독립이고, 관측이 서로 조건부 독립이라 가정),

p(m | z₁…ₜ) = p(m | zₜ) · p(zₜ) · p(m | z₁…ₜ₋₁) / ( p(m) · p(zₜ | z₁…ₜ₋₁) )

같은 식을 "비어 있음(¬m)"에 대해서도 쓰고 둘을 나누면 번거로운 정규화 항이 사라집니다.

p(m|z₁…ₜ) / p(¬m|z₁…ₜ) = [p(m|zₜ) / p(¬m|zₜ)] · [p(m|z₁…ₜ₋₁) / p(¬m|z₁…ₜ₋₁)] · [p(¬m) / p(m)]

양변에 로그를 취하고 로그 오즈 l = log(p / (1 − p))로 쓰면 곱이 덧셈이 됩니다.

lₜ = lₜ₋₁ + log( p(m|zₜ) / (1 − p(m|zₜ)) ) − l₀

항뜻값 예
lₜ₋₁지금까지의 믿음처음엔 0 (p = 0.5, 모름)
log(p(m|zₜ)/(1−p(m|zₜ)))역센서 모델(inverse sensor model): 이번 빔이 이 셀에 대해 주는 증거끝 셀 p = 0.7 → +0.85, 지나간 셀 p = 0.4 → −0.41
l₀사전 확률의 로그 오즈p(m) = 0.5면 0

장점은 세 가지입니다. ① 갱신이 덧셈 한 번이라 빠르고, ② 0과 1 근처에서 확률이 수치적으로 뭉개지지 않으며, ③ 상한·하한(예: ±5)으로 잘라 두면 한번 벽이던 곳도 여러 번 비어 보이면 다시 빈 곳으로 돌아옵니다(움직이는 사람 지우기). 확률로 돌릴 때는 p = 1 − 1/(1 + e^l)입니다.

지도 파일의 문턱값#

map_saver_cli가 저장한 MentorPi의 slam/maps/map_01.yaml입니다.

yaml
image: map_01.pgm
mode: trinary
resolution: 0.05
origin: [-7.18, -7.41, 0]
negate: 0

free_thresh: 0.25
키뜻
mode: trinary셀을 점유(검정, 0)·빈 곳(흰색, 254)·모름(회색, 205) 세 값으로 저장
resolution픽셀 하나 = 0.05 m. 원본 지도 map_01.pgm은 411 × 315 픽셀 → 약 20.6 m × 15.8 m

occupied_thresh / free_thresh확률 > 0.65면 점유, < 0.25면 빈 곳, 그 사이는 모름

실습: Playground에서 점유 격자 만들기#

가상 MentorPi를 제자리에서 한 바퀴 돌리며 /scan과 실제 자세 /ground_truth로 로그 오즈 격자를 만듭니다. 위치를 정확히 안다고 가정한 "지도 작성(mapping only)"이라서 SLAM의 절반만 푸는 셈입니다. 실물에는 /ground_truth가 없으므로, 이 자리를 SLAM이 추정한 자세가 채웁니다.

Playground 열기

python브라우저 실행Playground ↗
import numpy as np
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from sensor_msgs.msg import LaserScan
import mentorpi_sim as sim                                     # 시뮬 전용
sim.setup(world="empty", duration=17.0, start=(0.0, 0.0, 0.0))  # 시뮬 전용
sim.add_box(1.5, 0.5, 0.6, 0.6); sim.add_cylinder(-1.0, -1.2, 0.25)  # 시뮬 전용
RES, SIZE = 0.1, 70                     # 0.1 m 셀, 7 m x 7 m, 원점 = 격자 중앙
L_OCC, L_FREE, L_MAX = 0.85, -0.4, 5.0  # 로그 오즈 증분과 포화값

class GridMapper(Node):
    def __init__(self):
        super().__init__('grid_mapper')
        self.L = np.zeros((SIZE, SIZE))   # L[ix, iy], 0 = 모름(p = 0.5)
        self.pose, self.scans = None, 0
        self.create_subscription(Pose2D, '/ground_truth', self.on_pose, 10)   # 시뮬 전용
        self.create_subscription(LaserScan, '/scan', self.on_scan, 10)
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_timer(0.1, self.turn)
    def on_pose(self, msg):
        self.pose = (msg.x, msg.y, msg.theta)
    def turn(self):
        t = Twist(); t.angular.z = 0.4; self.pub.publish(t)
    def on_scan(self, msg):
        if self.pose is None: return
        px, py, th = self.pose
        r = np.array(msg.ranges)
        a = msg.angle_min + np.arange(len(r)) * msg.angle_increment + th
        hit = np.isfinite(r)
        r = np.where(hit, r, 4.0)                           # 반사 없음: 4 m까지만 비움
        s = np.arange(0.0, 12.0, RES / 2)                   # 빔 위 표본 거리
        m = s[None, :] < (r[:, None] - RES / 2)
        fx = (px + s[None, :] * np.cos(a)[:, None])[m]
        fy = (py + s[None, :] * np.sin(a)[:, None])[m]
        free = set(zip((fx // RES).astype(int), (fy // RES).astype(int)))
        ox = ((px + r[hit] * np.cos(a[hit])) // RES).astype(int)
        oy = ((py + r[hit] * np.sin(a[hit])) // RES).astype(int)
        free -= set(zip(ox, oy))
        fi, fj = np.array(list(free)).T + SIZE // 2
        self.L[fi, fj] += L_FREE                            # 빔이 지나간 셀: 비어 있음 쪽으로
        self.L[ox + SIZE // 2, oy + SIZE // 2] += L_OCC     # 빔 끝 셀: 점유 쪽으로
        np.clip(self.L, -L_MAX, L_MAX, out=self.L)
        self.scans += 1

rclpy.init()
node = GridMapper()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    P = 1.0 - 1.0 / (1.0 + np.exp(node.L))                  # 로그 오즈 -> 확률
    print("scans:", node.scans, " occupied:", (P > 0.65).sum(), " free:", (P < 0.25).sum(),
          " unknown:", ((P >= 0.25) & (P <= 0.65)).sum())
    for row in P.T[::-5, ::5]:                              # 위쪽 = +y, 한 글자 = 0.5 m
        print("".join("#" if p > 0.65 else "." if p < 0.25 else "?" for p in row))
    node.destroy_node()
    rclpy.shutdown()

  • 가장자리 바깥 ?는 벽 너머 — 빔이 벽에서 멈췄으니 정보가 없습니다.
  • L_OCC를 0.2로 줄이면 벽이 흐려지고, L_FREE를 −1.5로 키우면 한 번 잘못 본 빔에도 벽이 지워집니다. 두 값을 바꿔 가며 결과를 비교해 보세요.
`/ground_truth` 대신 `/odom`을 쓰면?

on_pose를 /odom 구독으로 바꾸고 로봇을 앞뒤로 움직이면서 지도를 그려 보면 드리프트 때문에 벽이 번지는 것이 보입니다. 그 번짐을 없애는 것이 다음 절의 스캔 매칭입니다.

스캔 매칭#

오도메트리가 "대략 여기쯤"이라고 알려 주면, 스캔 매칭은 그 주변을 뒤져서 현재 스캔이 지도(또는 최근 스캔들)와 가장 잘 겹치는 자세를 찾습니다.

x* = argmax_x Σᵢ M( T(x) · pᵢ ) — 스캔 점 pᵢ를 자세 x로 옮겼을 때 지도 M에서 "점유" 값의 합(응답, response)이 가장 큰 x

slam_toolbox는 Karto SLAM의 상관 스캔 매처(correlative scan matcher)를 씁니다. 가능한 (x, y, θ)를 격자처럼 전부 시험하되, 거친 탐색 → 세밀 탐색 두 단계로 나눠 계산을 줄입니다. slam.yaml의 파라미터가 곧 탐색 범위입니다.

파라미터MentorPi 값뜻
correlation_search_space_dimension0.5위치 탐색 창 한 변 [m] (오도메트리 예측 ±0.25 m)
correlation_search_space_resolution0.01위치 탐색 간격 [m]
correlation_search_space_smear_deviation0.1지도 점을 번지게(smear) 하는 폭 — 응답 곡면을 부드럽게
coarse_search_angle_offset0.349거친 각도 탐색 범위 ±0.349 rad (±20°)
coarse_angle_resolution0.0349거친 각도 간격 (2°)
fine_search_angle_offset0.00349세밀 각도 탐색 범위 (0.2°)
distance_variance_penalty / angle_variance_penalty0.5 / 1.0오도메트리 예측에서 멀어질수록 점수 깎기
minimum_distance_penalty / minimum_angle_penalty0.5 / 0.9깎는 양의 하한
link_match_minimum_response_fine0.1이 응답 미만이면 매칭 실패로 보고 연결 안 함
use_response_expansiontrue응답이 낮으면 탐색 창을 넓혀 재시도

탐색 창이 ±0.25 m, ±20°라는 뜻은 스캔 사이에 오도메트리가 이보다 크게 틀리면 매칭이 실패한다는 뜻입니다. 로봇을 빨리 돌리거나(특히 회전), 바퀴가 헛돌면 지도가 찢어지는 이유입니다. 교재가 "천천히 움직일수록 좋은 지도"라고 하는 근거가 이 숫자들입니다.

포즈 그래프와 루프 클로저#

slam_toolbox는 모든 스캔을 지도에 바로 태우지 않습니다. 로봇이 minimum_travel_distance(0.1 m) 또는 minimum_travel_heading(0.5 rad)보다 많이 움직였을 때만 노드(자세 + 그때의 스캔)를 만들고, 노드 사이에 제약(edge, "노드 i에서 본 노드 j는 여기")을 답니다.

  • 연속 제약: 새 노드를 최근 노드들(scan_buffer_size 20개, link_scan_maximum_distance 1.5 m 이내)과 스캔 매칭해 얻습니다.
  • 루프 클로저 제약: 새 노드 근처(loop_search_maximum_distance 3.0 m)에 오래전에 지나간 노드가 있으면, 넓은 창(loop_search_space_dimension 8.0 m, 해상도 0.05 m)으로 매칭을 시도합니다. 연속 체인 loop_match_minimum_chain_size 10개 이상이 거친 응답 0.35, 세밀 응답 0.45를 넘고 분산이 3.0 이하면 "같은 곳에 돌아왔다"고 인정합니다.

루프가 닫히면 최적화기가 모든 노드 자세 x를 동시에 고쳐 제약 오차의 제곱합을 최소화합니다.

x* = argmin_x Σ_(i,j) eᵢⱼ(x)ᵀ Ωᵢⱼ eᵢⱼ(x) ( eᵢⱼ = 제약이 말하는 상대 자세와 현재 추정의 차이, Ωᵢⱼ = 그 제약의 신뢰도(정보 행렬) )

MentorPi는 solver_plugin: solver_plugins::CeresSolver, ceres_linear_solver: SPARSE_NORMAL_CHOLESKY, ceres_trust_strategy: LEVENBERG_MARQUARDT로 이 비선형 최소제곱 문제를 풉니다. 결과로 지도 전체가 "탁" 하고 펴지는 순간이 RViz에서 보입니다.

잘못된 루프 클로저는 지도를 망친다

비슷하게 생긴 두 복도를 같은 곳으로 착각하면 최적화가 지도를 접어 버립니다. 그래서 루프 판정 문턱(0.35/0.45, 체인 10개)이 연속 매칭 문턱(0.1)보다 훨씬 엄격합니다. 반복 구조가 많은 곳에서는 문턱을 높이거나 do_loop_closing을 잠시 끄고 비교해 봅니다.

실습 (시뮬레이션)#

2D 시뮬레이터 열기

  1. 월드를 room 또는 maze로, 섀시를 메카넘으로 고릅니다. 라이다 표시를 켭니다.
  2. SLAM 모드를 켜고 키보드(또는 가상 조이스틱)로 천천히 방을 한 바퀴 돕니다. 회색(모름) 격자가 흰색(빈 곳)·검은색(점유)으로 바뀌는 과정을 관찰합니다.
  3. 오도메트리 오차 표시를 켜고 같은 경로를 빠르게 돌아 봅니다. 추정 경로와 실제 경로가 벌어질 때 지도가 어떻게 번지는지 비교합니다.
  4. 제자리에서 빠르게 회전(0.5 rad/s 이상)한 경우와 천천히 회전한 경우의 지도 선명도를 비교하고, 위 스캔 매칭 탐색 창(±20°)과 연결해 설명합니다.

실습 (실물)#

안전 확인 (실물 실습 전 필수)
  • 지도 작성 중에는 로봇이 계속 움직입니다. 사람이 로봇 옆을 따라다니며 계단·책상 다리·전선 쪽으로 가지 않게 지킵니다.
  • 키보드 조종 속도는 원본 teleop_key_control.py 기준 0.2 m/s, 0.5 rad/s입니다. 속도를 올리지 않습니다(빠를수록 지도도 나빠집니다).
  • 멈출 때는 키보드 노드 터미널에서 정지 키를 누르거나 Ctrl+C. 로봇이 계속 움직이면 ros2 topic pub --once /controller/cmd_vel geometry_msgs/msg/Twist "{}", 최후에는 전원 스위치.
  • 지도에 나중에 치울 물건(가방, 사람)이 찍히지 않게 주변을 정리합니다.

과제#

기본 과제
  1. Playground 코드에서 L_OCC, L_FREE를 (0.85, −0.4), (0.4, −0.4), (0.85, −1.5) 세 가지로 바꿔 점유·빈 곳·모름 셀 수를 표로 정리하고 차이를 설명합니다.
  2. map_01.yaml의 origin과 resolution으로, PGM 영상의 픽셀 (행 100, 열 200)이 map 좌표로 어디인지 계산합니다. (힌트: PGM은 위에서부터 행을 세고, origin은 왼쪽 아래)
심화 과제
  1. Playground 코드의 /ground_truth를 /odom으로 바꾸고(쿼터니언 → yaw는 tf_transformations.euler_from_quaternion), 로봇을 1 m 전진 → 180° 회전 → 1 m 전진시키며 지도를 만들어 벽 번짐을 관찰합니다. 번짐 폭과 오도메트리 오차를 비교합니다.
  2. 두 스캔(1차 자세에서 찍은 스캔과 0.1 m 옮겨 찍은 스캔)의 점들을 numpy로 만들고, (dx, dy)를 ±0.2 m 범위 0.01 m 간격으로 전부 시도해 겹치는 점 수가 최대인 이동을 찾는 초간단 상관 스캔 매처를 작성합니다.
