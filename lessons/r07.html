R07RViz2·RQT·Gazebo 도구

RViz2 디스플레이(TF·LaserScan·Map·Path), rqt_graph·rqt_plot·rqt_console, Gazebo 물리 시뮬레이션 개요.

선수 챕터: R06
2D 시뮬레이터

학습 목표#

  • RViz2·rqt·Gazebo·ros2 bag이 각각 무엇을 대신하거나 보여 주는 도구인지 구분하고 상황에 맞게 고릅니다.
  • RViz2의 Fixed Frame과 디스플레이(TF, RobotModel, LaserScan, Map, Path, Odometry)를 추가·설정하고, 설정을 .rviz 파일로 저장해 launch에서 불러옵니다.
  • rqt의 Console·Message Publisher·Service Caller·Plot·Node Graph 플러그인으로 노드를 디버깅합니다.
  • Gazebo가 실제 하드웨어 드라이버를 대신해 같은 토픽을 내는 구조와 use_sim_time·/clock의 의미를 설명합니다.
  • 이 사이트의 2D 시뮬레이터 화면을 RViz2의 디스플레이와 대응시켜 읽습니다.

로봇이 내는 데이터는 숫자 덩어리입니다. ros2 topic echo /scan으로 360개의 거리값을 보고 벽 모양을 떠올리기는 어렵습니다. 데이터는 계산을 위한 것이고, 시각화는 사람을 위한 것입니다.

Global Options와 Fixed Frame#

Fixed Frame은 3D 뷰의 기준 좌표계입니다. 모든 데이터는 TF로 이 프레임에 변환되어 그려집니다. 가장 흔한 오류가 여기서 납니다.

Fixed Frame언제특징
base_link로봇 모델·센서 장착 확인로봇이 화면 중앙에 고정, 주변이 움직임
odom주행 테스트, 오도메트리 확인로봇이 움직임, 오래 가면 드리프트가 보임
mapSLAM·내비게이션map→odom 변환이 있어야 함

Global Options에는 배경색(Background Color), 프레임 속도(Frame Rate)도 있습니다. Grid 디스플레이는 Reference Frame, Plane Cell Count, Cell Size(m), Line Style, Color, Alpha, Plane, Offset을 설정합니다.

URDF 모델을 RViz2에 띄우는 launch#

원본 urdf_demo/launch/rviz_view.launch.py는 두 노드를 띄웁니다. URDF 문자열을 robot_description 파라미터로 robot_state_publisher에 넘기고, 저장한 설정 파일로 RViz2를 엽니다.

python
from launch import LaunchDescription
from launch_ros.actions import Node
from ament_index_python.packages import get_package_share_directory

def generate_launch_description():
    share = get_package_share_directory('urdf_demo')
    urdf_path = share + '/urdf/simple_demo.urdf'
    return LaunchDescription([
        Node(package='robot_state_publisher', executable='robot_state_publisher',
             parameters=[{'robot_description': open(urdf_path).read()}]),
        Node(package='rviz2', executable='rviz2', output='screen',
             arguments=['-d', share + '/rviz/rviz.rviz']),     # 저장해 둔 설정
    ])

setup.py의 data_files에 launch, urdf, rviz 폴더를 등록해야 share 경로에 복사됩니다(R05).

Gazebo#

Gazebo는 물리 엔진(중력, 마찰, 충돌, 관성)과 센서 모델(라이다, 카메라, IMU)을 가진 3D 시뮬레이터입니다. 화성 탐사차의 지형이나 드론의 비행처럼 실험하기 어렵거나 위험한 상황을 먼저 시뮬레이션에서 검증하고 실물로 옮길 수 있습니다.

핵심은 Gazebo가 하드웨어 드라이버 자리를 대신한다는 점입니다. 시뮬레이션 속 로봇이 /scan, /odom, /tf를 내고 /cmd_vel을 받으므로, 그 토픽을 쓰는 SLAM·내비게이션·RViz2 노드는 코드 수정 없이 그대로 동작합니다.

개념설명
버전Humble은 Gazebo Classic 11 또는 새 Gazebo(Ignition Fortress, ros_gz 패키지)와 연동
브리지ros_gz_bridge가 Gazebo 토픽 ↔ ROS 2 토픽 변환
로봇 모델URDF에 <inertial>, <collision>, Gazebo 플러그인(차동·메카넘 구동, 라이다)이 있어야 함
시뮬레이션 시간Gazebo가 /clock을 발행, 모든 노드는 use_sim_time:=true로 그 시간을 따라야 함

원본 교재의 확인 명령은 공식 데모입니다(PC에서 실행 권장).

bash
sudo apt-get install ros-humble-ros-gz
ros2 launch ros_gz_sim_demos robot_description_publisher.launch.py   # Gazebo + RViz2에 공 모델 표시
이 사이트의 2D 시뮬레이터와의 관계

Gazebo는 3D 물리를 정밀하게 풀지만 설치와 계산이 무겁습니다. 이 사이트의 2D 시뮬레이터와 Playground는 평면 기구학 + 2D 라이다만 흉내 내는 대신 브라우저에서 바로 실행됩니다. 원리를 익히는 단계는 2D, 센서 잡음·물리 효과까지 보려면 Gazebo, 마지막은 실물 — 이 순서로 옮겨 가는 것을 권합니다.

실습 (시뮬레이션)#

2D 시뮬레이터 열기

2D 시뮬레이터 화면을 RViz2 디스플레이와 대응시켜 봅니다.

  1. 수동 주행 모드에서 섀시를 메카넘으로 고르고 키보드로 움직입니다. 로봇 아이콘 = RViz2의 RobotModel, 로봇에 붙은 축 = TF 디스플레이(base_footprint)입니다.
  2. 라이다 표시를 켭니다. 방사형 빔과 끝점 = LaserScan 디스플레이입니다. 벽에 가까이 가면 빔이 짧아지고, 로봇 뒤쪽 물체가 가려지는 것(그림자)도 확인합니다.
  3. 오도메트리 오차 표시를 켜고 한동안 돌아다닙니다. 실제 경로와 오도메트리 경로가 벌어지는 모습이 RViz2에서 Fixed Frame을 odom으로 두었을 때 보이는 드리프트이고, map으로 두면 SLAM/AMCL이 이 차이(map→odom)를 보정합니다(R06).
  4. SLAM 모드에서 방을 한 바퀴 돌며 점유격자 지도를 만듭니다 = RViz2의 Map 디스플레이(/map).
  5. 내비게이션 모드에서 목표를 클릭합니다 = RViz2의 2D Goal Pose 도구. 화면에 그려지는 경로 = Path 디스플레이(/plan).
2D 시뮬레이터 요소RViz2 디스플레이 / 도구토픽
로봇 아이콘과 방향RobotModel + TF/robot_description, /tf
라이다 빔·점LaserScan/scan
오도메트리 궤적Odometry (Keep 수↑)/odom
점유격자 지도Map/map
목표 클릭2D Goal Pose/goal_pose
계획 경로Path/plan

Playground에서는 mentorpi_sim.plot으로 rqt_plot과 비슷한 그래프를 그릴 수 있습니다. 속도 명령과 오도메트리 속도를 함께 그려 명령과 응답의 차이를 봅니다.

python브라우저 실행Playground ↗
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
from nav_msgs.msg import Odometry
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(world="empty", duration=8.0, start=(0.0, 0.0, 0.0))   # 시뮬 전용

rclpy.init()
node = Node('plot_demo')
pub = node.create_publisher(Twist, '/cmd_vel', 10)
log = {'t': [], 'cmd': [], 'odom': []}
state = {'v': 0.0}

def on_odom(msg):
    state['v'] = msg.twist.twist.linear.x

node.create_subscription(Odometry, '/odom', on_odom, 10)
t0 = time.time()
while time.time() - t0 < 6.0:
    t = time.time() - t0
    cmd = Twist()
    cmd.linear.x = 0.15 if 1.0 <= t < 4.0 else 0.0     # 1 s~4 s 동안만 전진
    pub.publish(cmd)
    rclpy.spin_once(node, timeout_sec=0.05)
    log['t'].append(t)
    log['cmd'].append(cmd.linear.x)
    log['odom'].append(state['v'])
pub.publish(Twist())
sim.plot(log['t'], log['cmd'], '/cmd_vel linear.x')      # 시뮬 전용
sim.plot(log['t'], log['odom'], '/odom twist.linear.x')  # 시뮬 전용
print('샘플 %d개, 최대 odom 속도 %.3f m/s' % (len(log['t']), max(log['odom'])))
node.destroy_node()
rclpy.shutdown()

예상 출력(대략, 그래프 패널에 두 선이 그려짐. spin_once는 콜백을 하나 처리하면 바로 돌아오므로 샘플 수는 실행마다 다름):

text
샘플 300개, 최대 odom 속도 0.150 m/s

실물에서는 sim.plot 두 줄을 지우고 ros2 run rqt_plot rqt_plot /cmd_vel/linear/x /odom/twist/twist/linear/x로 같은 그래프를 봅니다. 실물 곡선은 모터 가감속 때문에 계단이 아니라 비스듬한 경사로 올라갑니다.

실습 (실물)#

안전 확인 (실물 실습 전 필수)
  • rqt Message Publisher로 /cmd_vel을 발행할 때는 체크박스를 켜는 순간부터 계속 발행됩니다. 로봇을 받침대 위에 두고, 선속도 0.1 m/s 이하로 시작하며, 멈출 때는 값을 0으로 바꾼 뒤 체크를 해제합니다.
  • Raspberry Pi에서 RViz2·rqt를 오래 띄우면 발열과 CPU 부하로 제어 주기가 흔들릴 수 있습니다. 주행 중 시각화는 PC에서 합니다.
  1. turtlesim으로 rqt 플러그인을 익힙니다(원본 Lesson 20 절차).
bash
ros2 run turtlesim turtlesim_node            # 터미널 1
ros2 run turtlesim turtle_teleop_key         # 터미널 2
rqt                                          # 터미널 3
  • Plugins → Logging → Console: 거북이를 벽에 부딪히게 하면 경고 로그가 뜹니다.
  • Plugins → Topics → Message Publisher: /turtle1/cmd_vel을 추가하고 linear.x, angular.z를 바꿔 체크합니다.
  • Plugins → Services → Service Caller: /spawn에 x, y, name(turtle2)을 넣고 Call합니다.
  • Plugins → Visualization → Plot: /turtle1/pose/x, /turtle1/pose/theta를 추가합니다.
  1. 원본 urdf_demo를 RViz2로 확인합니다(Lesson 19 절차). Fixed Frame을 base_link로 바꾸고 Add → RobotModel, Description Topic을 /robot_description으로 지정한 뒤 File → Save Config As로 rviz/rviz.rviz에 저장합니다. launch 파일의 arguments=['-d', ...]로 다음부터 자동으로 불러옵니다.
bash
cd ~/hiwonder_ws && colcon build --packages-select urdf_demo && source install/setup.bash
ros2 launch urdf_demo rviz_view.launch.py
  1. MentorPi 센서를 봅니다.
bash
~/.stop_ros.sh
ros2 launch controller controller.launch.py          # 터미널 1
ros2 launch peripherals lidar_view.launch.py         # 터미널 2: 라이다 + RViz2
rqt_graph                                            # 터미널 3: 연결 구조
ros2 run rqt_tf_tree rqt_tf_tree                     # TF 트리 (설치되어 있을 때)
  1. (PC) Gazebo 데모를 실행하고, ros2 topic list에 /clock이 생기는 것을 확인합니다.

자주 나는 오류와 해결#

증상원인해결
RViz2 디스플레이마다 No transform from [x] to [fixed frame]Fixed Frame이 TF 트리에 없음 / TF 발행 노드 미실행Fixed Frame을 존재하는 프레임(base_link, odom)으로, view_frames로 트리 확인
LaserScan이 Status: Warn, 점이 안 보임QoS 불일치(드라이버 Best Effort ↔ RViz Reliable)LaserScan의 Topic → Reliability Policy를 Best Effort로
RobotModel이 흰색으로 겹쳐 보임/robot_description만 있고 조인트 TF가 없음robot_state_publisher와 (움직이는 조인트면) joint_state_publisher 실행
Map이 안 보임 (늦게 켠 RViz)Durability VolatileMap 토픽 Durability를 Transient Local로
qt.qpa.xcb: could not connect to display컨테이너에 DISPLAY 미설정호스트 xhost +, 컨테이너 DISPLAY·X11 소켓 마운트 확인. VNC 데스크톱의 Terminator에서 실행
rqt에 새 플러그인이 목록에 없음플러그인 캐시rqt --force-discover
rqt_plot에 선이 안 그려짐필드 경로 오타, 숫자가 아닌 필드/토픽/필드/하위필드 형식, ros2 interface show로 확인
Gazebo 사용 시 TF가 extrapolation 오류일부 노드가 use_sim_time 없이 실행모든 노드에 use_sim_time:=true

과제#

기본 과제
  1. RViz2에서 TF, RobotModel, LaserScan, Odometry 네 디스플레이를 설정한 mentorpi_basic.rviz를 저장하고, 이것을 -d로 불러오는 launch 파일을 작성합니다. Fixed Frame을 odom으로 두고 로봇을 손으로 밀어 오도메트리 궤적이 남는 것을 캡처합니다.
  2. rqt_graph로 controller.launch.py 실행 후의 노드 그래프를 캡처하고, /cmd_vel과 /controller/cmd_vel이 어느 노드로 연결되는지 표시합니다(R03 그림과 비교).
심화 과제
  1. Playground 예제의 명령·응답 그래프에서 지연 시간(명령이 바뀐 뒤 응답이 목표의 63 %에 도달하는 시간)을 계산하는 코드를 추가합니다. 실물에서 ros2 bag record /cmd_vel /odom으로 같은 실험을 녹화하고 값을 비교합니다.
  2. MentorPi의 mentorpi.xacro에 Gazebo 플러그인을 넣으려면 무엇이 더 필요한지(inertial 값, collision, 구동 플러그인, 라이다 센서 플러그인, ros_gz_bridge 설정) 조사해 목록으로 정리합니다.
