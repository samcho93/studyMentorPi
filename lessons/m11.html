Nav2 구성(맵 서버·코스트맵·플래너·컨트롤러·BT), 파티클 필터 AMCL 위치추정, 초기 위치 지정과 목표 전송.

선수 챕터: M09
2D 시뮬레이터ROS 2 Playground

학습 목표#

  • Nav2의 구성 요소(BT Navigator, Planner·Controller·Behavior·Smoother 서버, 코스트맵, 수명주기 관리자)와 MentorPi에서 속도 명령이 모터까지 가는 경로를 설명할 수 있습니다.
  • 파티클 필터의 예측(predict) → 갱신(update) → 재표본(resample) 세 단계를 식과 코드로 구현합니다.
  • AMCL의 움직임 모델(alpha1~5), 가능도장 센서 모델(z_hit, sigma_hit), KLD 적응 표본 수(pf_err, pf_z)를 MentorPi 파라미터 값으로 해석합니다.
  • 코스트맵의 층(static·obstacle·voxel·inflation)과 비용 값(0, 253, 254, 255)의 의미를 말하고, MentorPi 설정의 특징(작은 robot_radius·inflation_radius)을 평가합니다.
  • 실물에서 저장한 지도로 내비게이션을 띄우고 2D Pose Estimate로 초기 위치를 준 뒤 목표를 보냅니다.

내비게이션이 풀어야 할 문제#

교재 표현대로 내비게이션은 "내가 어디 있는지 알고, 어디로 갈지 정하고, 가는 동안 부딪히지 않게 속도를 내는" 일입니다. Nav2(Navigation 2)는 이것을 역할별 서버로 나눈 ROS 2 표준 스택입니다.

Nav2 구조#

BT Navigator와 서버들#

BT Navigator가 "주 서버"이고 나머지는 부품입니다. 행동 트리(behavior tree)는 "경로를 1 Hz로 다시 계산하면서 따라가고, 실패하면 코스트맵을 지우고 → 제자리 회전 → 후진을 시도하라" 같은 절차를 트리로 기술한 XML입니다. nav2_params.yaml의 bt_navigator.plugin_lib_names에 나오는 nav2_compute_path_to_pose_action_bt_node, nav2_follow_path_action_bt_node, nav2_spin_action_bt_node, nav2_recovery_node_bt_node … 가 트리의 잎(leaf) 노드들입니다.

수명주기와 컨테이너#

Nav2 노드는 수명주기 노드(lifecycle node)라서 unconfigured → inactive → active 상태를 거쳐야 일합니다. lifecycle_manager_localization(map_server, amcl)과 lifecycle_manager_navigation(controller_server, smoother_server, planner_server, behavior_server, bt_navigator, waypoint_follower, velocity_smoother)이 autostart: true로 이들을 순서대로 켭니다. MentorPi는 모든 노드를 nav2_container(component_container_isolated) 한 프로세스에 컴포저블 노드로 올려 메모리와 복사 비용을 줄입니다.

위치추정: AMCL#

왜 필요한가#

오도메트리 odom → base_footprint는 부드럽고 빠르지만 드리프트가 쌓입니다. AMCL(Adaptive Monte Carlo Localization)은 라이다 스캔을 저장된 지도와 비교해 지도 기준 위치를 추정하고, 그 차이를 map → odom 변환으로 발행합니다. 결과 TF 체인은 map → odom → base_footprint → lidar_frame입니다. 교재 말대로 map → odom을 내는 것은 AMCL 대신 SLAM, UWB, QR 코드 위치추정 등 무엇이든 될 수 있습니다(M13의 RTAB-Map이 그 예).

베이즈 필터와 파티클#

위치추정은 믿음(belief) bel(xₜ) — "지금 로봇이 xₜ에 있을 확률 분포"를 갱신하는 문제입니다.

단계식뜻
예측bel⁻(xₜ) = ∫ p(xₜ | uₜ, xₜ₋₁) · bel(xₜ₋₁) dxₜ₋₁움직임 모델로 믿음을 옮기고 퍼뜨림
갱신bel(xₜ) = η · p(zₜ | xₜ) · bel⁻(xₜ)관측이 잘 설명되는 곳의 믿음을 키움

분포를 식으로 들고 다니는 대신 표본(파티클) N개로 들고 다니는 것이 파티클 필터입니다. 파티클 하나 = "로봇이 여기 있을지도 모른다"는 가설 (x, y, θ)와 가중치 w.

  1. 예측: 오도메트리가 "0.25 m 전진, 5° 회전"이라고 하면 모든 파티클을 그만큼 옮기되, 각자 다른 잡음을 더합니다. 잡음 크기가 alpha1~5입니다.
  2. 갱신: 각 파티클 자리에서 스캔을 지도에 겹쳐 보고 가능도 p(z | x)를 가중치로 곱합니다. 벽과 잘 맞는 파티클이 무거워집니다.
  3. 재표본: 가중치에 비례해 파티클을 다시 뽑습니다. 무거운 파티클은 여러 번 복제되고 가벼운 것은 사라집니다. 저분산(체계적) 재표본은 난수 하나로 N개를 등간격으로 뽑아 표본 편향을 줄입니다.
  4. 추정: 가중 평균과 공분산이 로봇 위치와 불확실성입니다(RViz의 초록 화살표 구름과 타원).

실습: 1D 파티클 필터#

문 세 개(1.5, 4.0, 7.0 m)가 있는 10 m 복도에서, 로봇이 자기 위치를 전혀 모른 채(파티클을 복도 전체에 균일하게 뿌림) 0.5 m씩 이동하며 "문이 보인다/안 보인다"만으로 위치를 찾습니다. 순수 numpy 코드라 결과가 매번 같습니다.

Playground 열기

python시뮬 실행 가능
import numpy as np

rng = np.random.default_rng(0)
DOORS = np.array([1.5, 4.0, 7.0])       # 복도(0~10 m)의 문 위치 = 지도
N, STEP, SIG_MOVE = 500, 0.5, 0.1        # 파티클 수, 한 번 이동량, 이동 잡음

def near_door(x):                        # 문 앞(±0.3 m)이면 True
    return np.min(np.abs(x[:, None] - DOORS[None, :]), axis=1) < 0.3

def likelihood(z, x):                    # 센서 모델 p(z | x): 적중률 0.9
    w = np.where(near_door(x) == z, 0.9, 0.1)
    return np.where((x < 0.0) | (x > 10.0), 1e-3, w)   # 복도 밖 = 지도상 벽

def low_variance_resample(p, w):         # 체계적(저분산) 재표본
    u = (rng.random() + np.arange(N)) / N
    idx = np.searchsorted(np.cumsum(w), u)
    return p[np.minimum(idx, N - 1)]

true_x = 0.5
p = rng.uniform(0.0, 10.0, N)            # 전역 위치추정: 복도 전체에 균일 분포
w = np.full(N, 1.0 / N)
print("step true   z      mean   std   N_eff")
for k in range(14):
    # 1) 예측: 이동 명령 u = +0.5 m에 잡음을 더해 모든 파티클을 옮김
    true_x += STEP
    p = p + STEP + rng.normal(0.0, SIG_MOVE, N)
    # 2) 갱신: 관측 z(문 보임?)의 가능도로 가중치 곱하고 정규화
    z = bool(near_door(np.array([true_x]))[0])
    w = w * likelihood(z, p)
    w = w / w.sum()
    n_eff = 1.0 / np.sum(w ** 2)
    mean = np.sum(w * p)
    std = np.sqrt(np.sum(w * (p - mean) ** 2))
    print("%4d %5.2f  %-5s %6.2f %5.2f %6.1f" % (k + 1, true_x, z, mean, std, n_eff))
    # 3) 재표본: 유효 파티클 수가 절반 밑으로 떨어지면
    if n_eff < N / 2:
        p = low_variance_resample(p, w)
        w = np.full(N, 1.0 / N)

읽는 법:

  • 2단계에서 첫 문을 봤지만 어느 문인지 모릅니다. 파티클이 세 문 앞에 모여 평균(5.15)은 의미 없고 표준편차가 큽니다(다봉 분포).
  • 7단계에서 두 번째 문을 보면 "문 → 2.5 m 뒤 문" 패턴과 어긋나는 가설이 약해져 표준편차가 2.0 → 1.3 m로 줄고, 13단계 세 번째 문에서 0.47 → 0.23 m로 수렴합니다. 문 간격이 2.5 m와 3.0 m로 다르기 때문에 가능한 일입니다. 모든 간격이 같다면 끝까지 구별하지 못합니다(대칭 환경의 함정).
  • N_eff(유효 파티클 수 1/Σw²)는 가중치가 한쪽에 쏠릴수록 작아집니다. 문을 본 단계(2, 7, 13)에서 크게 떨어지고, 그때 재표본이 일어납니다.
직접 바꿔 보기

N을 50으로 줄이면 올바른 가설 근처에 파티클이 하나도 안 남아 엉뚱한 곳으로 수렴하는 경우가 생깁니다(파티클 고갈). SIG_MOVE를 0으로 두면 재표본 뒤 복제본이 모두 같은 자리에 겹쳐 다양성이 사라집니다. AMCL의 alpha 잡음과 min_particles가 필요한 이유입니다.

가능도장 모델(likelihood field): 지도에서 각 셀과 가장 가까운 벽까지의 거리 d를 미리 계산해 두고, 스캔 끝점이 떨어진 셀의 d로 가능도를 계산합니다.

p(zₖ | x) = z_hit · N(d; 0, sigma_hit²) + z_rand / z_max_range

MentorPi는 z_rand = 0.5로 무작위 성분을 크게 잡았습니다. 지도에 없는 사람·의자가 많은 실내에서 이상한 빔 하나가 가중치를 0으로 만들지 않게 하는 보수적 설정입니다.

KLD 적응 표본 수: 파티클들이 차지하는 격자 칸(bin) 수 k가 많으면(= 위치를 잘 모르면) 파티클을 늘리고, 몰려 있으면 줄입니다. nav2_amcl은 다음 식을 쓰고, pf_z 값을 분위수 z로 그대로 넣습니다.

n = (k − 1)/(2·pf_err) · (1 − 2/(9(k−1)) + √(2/(9(k−1))) · pf_z)³

차지한 bin 수 k계산된 n실제 파티클 수 (500~3000으로 자름)

초기 위치를 잘 찍어 주면 k가 작아 500개로 가볍게 돌고, 위치를 잃으면 최대 3000개까지 늘어납니다. 교재의 "적은 표본으로 실시간성을 높인다"가 이 뜻입니다.

메카넘 로봇인데 Differential 모델?

MentorPi 설정은 섀시와 관계없이 DifferentialMotionModel입니다. 메카넘으로 옆으로 이동하면 이 모델은 횡이동을 예측하지 못해 파티클이 뒤처지고, 스캔이 맞춰 줄 때까지 위치가 튈 수 있습니다. 메카넘에서 횡이동을 많이 쓸 계획이면 nav2_amcl::OmniMotionModel(이때 alpha5 사용)로 바꿔 비교해 볼 만합니다. 기본 DWB 설정은 max_vel_y: 0.0이라 내비게이션 중에는 횡이동을 쓰지 않습니다.

코스트맵#

지도(0/100/−1)는 그대로 경로 계획에 쓰지 못합니다. 로봇은 점이 아니라 크기가 있기 때문입니다. Nav2는 지도를 코스트맵(costmap, 셀당 1바이트 0~255)으로 바꿔 씁니다.

코스트맵은 층(layer) 플러그인을 쌓아 만듭니다. 교재가 설명하는 Costmap2D/Layer 클래스 구조에서 initialize·matchSize는 한 번, updateBounds·updateCosts는 update_frequency마다 호출됩니다. 장애물 층은 스캔 빔을 따라 Bresenham 선으로 셀을 비우고(clearing) 끝점을 채웁니다(marking) — M09의 역센서 모델과 같은 일입니다.

`robot_radius` 0.05 m는 실제 로봇보다 작다

URDF(M08)의 바퀴 위치만 봐도 로봇 중심에서 바퀴까지 약 0.1 m이고, 차체 외곽은 그보다 큽니다. robot_radius: 0.05, inflation_radius: 0.05이면 코스트맵은 로봇을 지름 10 cm 공으로 보고, 팽창도 사실상 없습니다. 좁은 틈으로 경로를 내서 차체 모서리가 벽이나 의자 다리에 걸릴 수 있습니다. 원본 값의 의도(좁은 공간 통과)를 이해하되, 실습 공간이 좁지 않다면 M12에서 robot_radius 0.12~0.15 m, inflation_radius 0.25~0.3 m로 바꿔 비교합니다. 팽창 비용식과 튜닝은 M12에서 다룹니다.

실습 (시뮬레이션)#

2D 시뮬레이터 열기

  1. room 월드에서 SLAM 모드로 지도를 먼저 만듭니다(M09).
  2. 내비게이션 모드로 바꾸고 지도 위를 클릭해 목표를 줍니다. 전역 경로(A*)와 지역 제어(DWA 또는 Pure Pursuit)가 로봇을 움직입니다.
  3. 오도메트리 오차 표시를 켜고 긴 경로를 여러 번 왕복합니다. 오도메트리 추정과 실제 위치가 얼마나 벌어지는지 보고, 실물에서 AMCL이 이 차이를 어떻게 메우는지 설명합니다.
  4. 목표를 벽 바로 옆, 좁은 틈 사이에 찍어 보고 경로가 벽에서 얼마나 떨어지는지 관찰합니다(코스트맵 팽창).

실습 (실물)#

안전 확인 (실물 실습 전 필수)
  • 내비게이션은 로봇이 스스로 움직입니다. 목표를 보내기 전에 경로 주변에 사람·애완동물·깨지기 쉬운 물건이 없는지 확인하고, 한 사람은 항상 로봇 곁에 있습니다.
  • 첫 시험 목표는 1 m 이내, 탁 트인 곳으로 잡습니다.
  • 속도는 app_cmd_vel_callback의 0.2 m/s, 0.5 rad/s로 제한됩니다. 이 제한을 풀지 않습니다.
  • 멈출 때: RViz Navigation 2 패널의 Cancel, 또는 launch 터미널 Ctrl+C. 계속 움직이면 ros2 topic pub --once /controller/cmd_vel geometry_msgs/msg/Twist "{}", 최후에는 전원 스위치.
  • 계단·경사로가 있는 곳에서는 하지 않습니다. 2D 라이다는 아래로 꺼진 곳을 보지 못합니다.
  1. M09에서 저장한 지도(~/ros2_ws/src/slam/maps/map_01.yaml)가 있는지 확인하고 내비게이션을 띄웁니다.
bash
# 로봇
~/.stop_ros.sh
ls ~/ros2_ws/src/slam/maps
ros2 launch navigation navigation.launch.py map:=map_01

# 가상머신 (M09에서 준비한 워크스페이스)
ros2 launch navigation rviz_navigation.launch.py
  1. 약 10 s 뒤 Nav2가 활성화됐는지 확인합니다.
bash
ros2 lifecycle get /amcl                 # active [3]
ros2 lifecycle get /bt_navigator         # active [3]
ros2 param get /amcl max_particles       # 3000
  1. RViz 도구 모음의 2D Pose Estimate를 누르고, 지도에서 로봇의 실제 위치를 클릭한 채 로봇이 바라보는 방향으로 끌었다 놓습니다. 파티클 구름(/particle_cloud)이 그 주변에 모이고, 스캔(빨간 점)이 지도의 벽과 겹치는지 봅니다. 어긋나면 다시 찍습니다. CLI로도 줄 수 있습니다.
bash
ros2 topic pub --once /initialpose geometry_msgs/msg/PoseWithCovarianceStamped \
  "{header: {frame_id: map}, pose: {pose: {position: {x: 0.0, y: 0.0}, orientation: {z: 0.0, w: 1.0}}}}"
  1. 로봇을 제자리에서 조금 회전시키거나 0.3 m쯤 움직이면(update_min_d 0.25 m, update_min_a 0.2 rad) 필터가 갱신되며 구름이 좁아집니다.
  2. Nav2 Goal(교재의 "2D Nav Goal")로 목표를 클릭·드래그합니다. 초록 선(직선 참고선)과 진한 파란 선(계획된 경로)이 나타나고 로봇이 출발합니다. CLI로 목표를 줄 수도 있습니다.
bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 1.0, y: 0.0}, orientation: {w: 1.0}}}}" --feedback
  1. 경로 위에 상자를 놓아 로봇이 돌아가는지(지역 코스트맵의 voxel 층) 확인합니다. 끝나면 Ctrl+C 후 호스트 터미널에서 sudo systemctl restart start_node.service.

과제#

기본 과제
  1. 1D 파티클 필터에서 문 위치를 [1.5, 4.0, 6.5](간격이 모두 2.5 m)로 바꿔 실행하고, 수렴이 어떻게 달라지는지 설명합니다.
  2. KLD 식으로 k = 20, 150일 때 파티클 수를 계산하고, min_particles를 100으로 바꾸면 어떤 장단점이 있을지 씁니다.
심화 과제
  1. 1D 코드에 납치 로봇(kidnapped robot) 상황을 넣습니다: 10단계에서 true_x를 2.0으로 순간 이동시키고, 무작위 파티클을 일부(예: 5 %) 주입하는 코드를 추가해 복구되는지 봅니다. AMCL의 recovery_alpha_slow/fast가 이 기능이며 MentorPi에서는 0(꺼짐)인 이유를 토론합니다.
  2. 로봇에서 ros2 topic echo /amcl_pose의 공분산 대각선(x, y, yaw)을 로봇이 정지했을 때, 0.5 m 움직였을 때 기록해 비교합니다.
