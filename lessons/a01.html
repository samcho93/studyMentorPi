A01색 임계값 조정과 색 인식

LAB/HSV 임계값 도구로 색 범위를 정하고, 마스크·윤곽선·중심점으로 색을 인식해 ROS 2 토픽으로 발행합니다.

선수 챕터: R11
HSV 색 실험실ROS 2 Playground

학습 목표#

  • 조명에 따라 색 값이 변하는 이유를 설명하고, MentorPi가 쓰는 Lab 임계값 파일(lab_config.yaml)의 구조를 읽습니다.
  • LAB_Tool(실물)과 HSV 색 실험실(웹)로 색 범위를 조정하고 저장합니다.
  • color_detect_demo.py의 인식 파이프라인(축소 → 흐림 → Lab → inRange → 침식·팽창 → 최대 윤곽 → 외접원)을 재현합니다.
  • 여러 프레임의 결과를 다수결로 안정화하고, 원본 코드의 평균 방식이 가진 함정을 설명합니다.
  • color_detect 노드의 서비스·토픽(/color_detect/set_param, /color_detect/color_info)으로 인식 결과를 ROS 2에 발행합니다.

왜 임계값을 “조정”해야 하는가#

같은 빨간 공도 형광등 아래, 창가 햇빛, 그늘에서 카메라가 주는 BGR 값이 크게 다릅니다. 광원의 색온도(누런 백열등 vs 푸른 LED), 밝기, 카메라의 자동 노출·화이트밸런스가 모두 픽셀 값을 바꿉니다. 그래서 색 인식 프로그램은 색 범위(임계값)를 설정 파일로 분리해 두고, 환경이 바뀌면 도구로 다시 맞춥니다.

R09에서 본 것처럼 밝기와 색을 분리한 색 공간에서는 조명이 바뀌어도 색 채널은 덜 흔들립니다. MentorPi 예제는 모두 Lab 공간을 씁니다.

Lab 채널OpenCV 8비트 값128보다 작으면128보다 크면조명 영향
L (밝기)0 ~ 255어두움밝음큼 → 범위를 넓게
a0 ~ 255초록빨강(자홍)작음
b0 ~ 255파랑노랑작음

lab_config.yaml#

임계값은 로봇의 /home/ubuntu/software/lab_tool/lab_config.yaml에 있습니다. 카메라 종류별로 Mono(단안 카메라)와 Stereo(깊이 카메라) 두 벌이 있고, 색마다 min/max 세 값(L, a, b)을 가집니다. 깊이 카메라 버전의 기본값 일부는 다음과 같습니다.

text
lab:
  Stereo:
    red:   min [0, 165, 104]   max [255, 255, 255]   # a ≥ 165 (강한 빨강), L은 전 범위
    green: min [47, 0, 135]    max [255, 104, 255]   # a ≤ 104 (초록), b ≥ 135
    blue:  min [0, 0, 0]       max [255, 255, 110]   # b ≤ 110 (파랑)
    black: min [0, 0, 0]       max [90, 255, 255]    # L ≤ 90 (어두움)
    white: min [193, 0, 0]     max [255, 255, 255]   # L ≥ 193 (밝음)
size: {width: [640], height: [480]}

빨강이 L을 0~255로 전 범위 허용하고 a만 좁게 거는 것에 주목하세요. 밝기는 조명에 따라 크게 변하므로 색 축(a, b)으로만 가르는 전략입니다. 반대로 검정·흰색은 색이 아니라 밝기이므로 L로만 가릅니다.

임계값 조정 도구#

LAB_Tool (실물)#

MentorPi 데스크톱의 LAB_Tool(/home/ubuntu/software/lab_tool/main.py, PyQt5)은 카메라 토픽 /ascamera/camera_publisher/rgb0/image를 구독해 왼쪽에 처리 결과(마스크), 오른쪽에 원본 영상을 보여 줍니다. 내부 처리는 GaussianBlur(3×3) → RGB2LAB → inRange(min, max) → 침식 → 팽창으로, 인식 노드와 같습니다.

조정 요령은 다음과 같습니다.

  1. 색 목록에서 조정할 색(예: red)을 고릅니다.
  2. L·A·B의 min을 모두 0, max를 모두 255로 벌려 화면 전체가 흰색이 되게 합니다.
  3. 물체를 화면에 두고, 그 색이 놓인 축부터 좁힙니다. 빨강은 +a 쪽이므로 A의 min을 올려 물체만 흰색이 남을 때까지 조입니다.
  4. 남은 잡음은 L과 B로 정리합니다. 물체가 밝게 보이면 L min을 올리고, 어둡게 보이면 L max를 내립니다. 따뜻한(노란) 빨강이면 B min을 올리고, 차가운(자홍) 빨강이면 B max를 내립니다.
  5. Save를 눌러 lab_config.yaml에 저장합니다. 새 색은 Add로 이름을 붙여 추가합니다.
임계값은 “여유 있게”

물체가 딱 흰색이 되는 순간의 값으로 저장하면 조명이 조금만 바뀌어도 인식이 끊깁니다. 범위를 좁혀 가다가 물체가 사라지기 시작하는 값에서 10~15 정도 되돌려 저장하고, 로봇이 실제로 달릴 장소의 조명에서 조정합니다.

HSV 색 실험실 (웹)#

HSV 색 실험실 열기

이 사이트의 색 실험실은 HSV 슬라이더로 같은 작업을 브라우저에서 합니다. 샘플 이미지나 직접 찍은 스냅숏(R08 실물 실습)을 올려 범위를 찾고, 결과를 inRange 코드로 복사할 수 있습니다. HSV와 Lab은 축이 다르지만 “색 축은 좁게, 밝기 축은 넓게”라는 원칙은 같습니다. 실물에 넣을 값은 LAB_Tool에서 최종 확인합니다.

인식 파이프라인: color_detect_demo.py#

원본 예제 ~/ros2_ws/src/example/example/color_detect/color_detect_demo.py는 카메라 프레임마다 다음을 합니다.

단계코드이유
1. 축소cv2.resize(img, (320, 240), interpolation=cv2.INTER_NEAREST)픽셀 수 1/4 → 4배 빠름
2. 흐림cv2.GaussianBlur(frame, (3, 3), 3)센서 잡음 제거
3. Lab 변환cv2.cvtColor(frame, cv2.COLOR_BGR2LAB)조명에 덜 민감한 색 축
4. 색마다 마스크cv2.inRange(lab, min, max) (red, green, blue)임계값 파일 사용
5. 침식 → 팽창3×3 사각형 커널 한 번씩 (= 열림)작은 잡음 점 제거
6. 가장 큰 윤곽findContours(..., RETR_EXTERNAL) + 면적 50 초과 중 최대잡음 조각 무시
7. 색 결정세 색 중 면적이 가장 큰 색, 단 200 초과일 때만너무 작은 물체 무시
8. 표시minEnclosingCircle → 원래 크기로 좌표 환산 → 원 + "Color: red"결과 확인
9. 안정화3프레임마다 색 코드(1/2/3)의 평균을 반올림깜빡임 억제

아래 코드는 이 파이프라인을 그대로 옮겨 shapes.png(빨간 원, 초록 사각형, 파란 삼각형, 노란 타원)에 적용합니다. 임계값은 로봇의 Stereo 기본값입니다.

python브라우저 실행
import cv2
import math
import numpy as np

LAB = {  # lab_config.yaml → lab: Stereo (min, max)
    "red":   ((0, 165, 104), (255, 255, 255)),
    "green": ((47, 0, 135), (255, 104, 255)),
    "blue":  ((0, 0, 0), (255, 255, 110)),
}
SIZE = (320, 240)
k3 = cv2.getStructuringElement(cv2.MORPH_RECT, (3, 3))

def area_max_contour(contours):              # 원본 getAreaMaxContour와 같은 규칙
    best, best_area = None, 0
    for c in contours:
        a = math.fabs(cv2.contourArea(c))
        if a > best_area:
            best_area = a
            if a > 50:
                best = c
    return best, best_area

img = cv2.imread("shapes.png")
h, w = img.shape[:2]
lab = cv2.cvtColor(cv2.GaussianBlur(cv2.resize(img, SIZE, interpolation=cv2.INTER_NEAREST), (3, 3), 3),
                   cv2.COLOR_BGR2LAB)
winner, win_area, win_cnt = None, 0, None
for name, (lo, hi) in LAB.items():
    mask = cv2.dilate(cv2.erode(cv2.inRange(lab, lo, hi), k3), k3)
    cnt, area = area_max_contour(cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_NONE)[-2])
    print("%-5s 최대 윤곽 면적 %7.1f (320x240 기준)" % (name, area))
    if cnt is not None and area > win_area:
        winner, win_area, win_cnt = name, area, cnt

if win_area > 200:
    (cx, cy), r = cv2.minEnclosingCircle(win_cnt)
    cx, cy, r = cx * w / SIZE[0], cy * h / SIZE[1], r * w / SIZE[0]   # 원래 크기로 환산
    print("결과: %s, 중심 (%.0f, %.0f), 반지름 %.0f px" % (winner, cx, cy, r))
    cv2.circle(img, (int(cx), int(cy)), int(r), (0, 0, 0), 2)
    cv2.putText(img, "Color: " + winner, (10, h - 10), cv2.FONT_HERSHEY_SIMPLEX, 0.65, (0, 0, 0), 2)
cv2.imshow("color detect", img)
text
red   최대 윤곽 면적  3802.0 (320x240 기준)
green 최대 윤곽 면적  6616.0 (320x240 기준)
blue  최대 윤곽 면적  2444.0 (320x240 기준)
결과: green, 중심 (390, 150), 반지름 114 px
  • 세 색이 모두 검출되지만, 원본 규칙은 가장 큰 한 색만 결과로 냅니다. 초록 사각형이 가장 커서 green이 됩니다.
  • 노란 타원은 목록에 없는 색이라 무시됩니다. 노랑을 인식하려면 yellow 항목(Stereo 기본값 min [135, 129, 132])을 추가해야 합니다.
  • 축소 영상에서 구한 좌표를 640/320, 480/240배 해서 원래 영상에 그립니다. 원본은 common.val_map으로 같은 계산을 합니다.

각 픽셀의 Lab 값 확인하기#

임계값이 왜 이 색을 통과시키는지 보려면 물체 한가운데의 Lab 값을 찍어 보면 됩니다. MentorPi 라인 트레이싱·색 추적 앱의 색 고르기(ColorPicker)도 화면을 클릭한 점 주변 2×2 픽셀의 Lab 평균을 여러 프레임 모아 목표색으로 씁니다.

python브라우저 실행
import cv2

LAB = {"red": ((0, 165, 104), (255, 255, 255)), "green": ((47, 0, 135), (255, 104, 255)),
       "blue": ((0, 0, 0), (255, 255, 110))}
img = cv2.imread("colors.png")                 # 회색 배경 + 빨강·초록·파랑 블록
lab = cv2.cvtColor(img, cv2.COLOR_BGR2LAB)
for name, (x, y) in {"red 블록": (130, 240), "green 블록": (320, 240),
                     "blue 블록": (510, 240), "회색 배경": (20, 20)}.items():
    L, a, b = lab[y, x].tolist()
    hits = [c for c, (lo, hi) in LAB.items() if all(lo[i] <= (L, a, b)[i] <= hi[i] for i in range(3))]
    print("%-10s BGR %-15s Lab (%3d, %3d, %3d) → 통과: %s" % (name, img[y, x].tolist(), L, a, b, hits or "없음"))
text
red 블록     BGR [0, 0, 220]     Lab (117, 200, 188) → 통과: ['red']
green 블록   BGR [0, 200, 0]     Lab (180,  56, 197) → 통과: ['green']
blue 블록    BGR [220, 0, 0]     Lab ( 70, 198,  32) → 통과: ['blue']
회색 배경      BGR [128, 128, 128] Lab (137, 128, 128) → 통과: 없음

회색 배경은 a = b = 128이라 어느 색 범위에도 들지 않습니다. 파랑은 b가 110 이하라서 통과하는데, 파랑 범위는 L과 a를 전혀 제한하지 않으므로 어두운 그림자(b가 약간 낮은 회색)가 파랑으로 잡히는 일이 실물에서 자주 생깁니다. 이럴 때 LAB_Tool에서 파랑의 L min을 올립니다.

여러 프레임으로 안정화: 평균의 함정#

원본은 색을 코드(빨강 1, 초록 2, 파랑 3)로 바꿔 3프레임 모은 뒤 평균을 반올림합니다. 빨강과 파랑이 번갈아 보이면 평균이 2가 되어 보이지도 않은 초록이 결과로 나옵니다. 범주형 값은 평균이 아니라 다수결(mode)로 합쳐야 합니다.

python브라우저 실행
from collections import Counter

CODE = {1: "red", 2: "green", 3: "blue"}
for frames in ([1, 1, 1], [1, 3, 3], [1, 3, 1], [3, 1, 2], [1, 3, 0]):
    mean_code = int(round(sum(frames) / len(frames)))          # 원본 방식
    mode, votes = Counter(frames).most_common(1)[0]            # 다수결
    vote = CODE.get(mode, "None") if votes >= 2 else "보류"
    print("프레임 %-11s 평균 → %-6s  다수결 → %s" % (frames, CODE.get(mean_code, "None"), vote))
text
프레임 [1, 1, 1]   평균 → red     다수결 → red
프레임 [1, 3, 3]   평균 → green   다수결 → blue
프레임 [1, 3, 1]   평균 → green   다수결 → red
프레임 [3, 1, 2]   평균 → green   다수결 → 보류

ROS 2 노드로 만들기#

데모 프로그램은 결과를 화면에만 그립니다. 다른 노드(색 추적, 분류)가 쓰게 하려면 토픽으로 발행해야 합니다. MentorPi의 color_detect 노드(color_detect_node.py)가 이 역할을 합니다.

인터페이스이름타입내용
구독/ascamera/camera_publisher/rgb0/imagesensor_msgs/Image카메라 BGR 영상
서비스/color_detect/set_paraminterfaces/srv/SetColorDetectParam찾을 색 목록: color_name, detect_type(circle·rect·line)
서비스/color_detect/start, /color_detect/stopstd_srvs/Trigger영상 구독 시작/중지
서비스/color_detect/set_circle_roi 등interfaces/srv/SetCircleROI탐색 영역 제한 (config/roi.yaml)
발행/color_detect/color_infointerfaces/msg/ColorsInfoColorInfo[]: color, width, height, x, y, radius, angle
발행/color_detect/image_resultsensor_msgs/Image결과를 그린 영상

detect_type이 circle이면 최소 외접원의 중심·반지름을, rect면 최소 회전 사각형의 중심·각도를, line이면 roi.yaml의 세 띠(가중치 0.1·0.2·0.7)에서 구한 선 중심을 발행합니다. A04의 색 추적 노드가 이 ColorsInfo를 구독합니다.

Playground에는 카메라 토픽이 없으므로, 아래 노드는 타이머에서 샘플 이미지를 “프레임”으로 삼아 같은 구조를 흉내 냅니다. 실물에서는 타이머 대신 이미지 구독 콜백에 detect()를 넣으면 됩니다.

python브라우저 실행
import cv2
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
import mentorpi_sim as sim                              # 시뮬 전용
sim.setup(duration=2.0)                                  # 시뮬 전용

LAB = {"red": ((0, 165, 104), (255, 255, 255)), "green": ((47, 0, 135), (255, 104, 255)),
       "blue": ((0, 0, 0), (255, 255, 110))}
K3 = cv2.getStructuringElement(cv2.MORPH_RECT, (3, 3))


def detect(bgr, colors):
    lab = cv2.cvtColor(cv2.GaussianBlur(cv2.resize(bgr, (320, 240)), (3, 3), 3), cv2.COLOR_BGR2LAB)
    best = ("None", 0.0, 0, 0)
    for name in colors:
        mask = cv2.dilate(cv2.erode(cv2.inRange(lab, *LAB[name]), K3), K3)
        for c in cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)[-2]:
            a = cv2.contourArea(c)
            if a > 200 and a > best[1]:
                (x, y), _ = cv2.minEnclosingCircle(c)
                best = (name, a, int(x * 2), int(y * 2))        # 640x480 좌표로
    return best


class ColorDetect(Node):
    def __init__(self):
        super().__init__('color_detect_demo')
        self.pub = self.create_publisher(String, '/color_detect/result', 1)
        self.frames = ['shapes.png', 'colors.png', 'track.png']
        self.i = 0
        self.create_timer(0.5, self.on_timer)

    def on_timer(self):
        name = self.frames[self.i % len(self.frames)]
        self.i += 1
        color, area, x, y = detect(cv2.imread(name), ['red', 'green', 'blue'])
        msg = String()
        msg.data = '%s,%d,%d' % (color, x, y)
        self.pub.publish(msg)
        self.get_logger().info('%-10s → %s (area %.0f)' % (name, msg.data, area))


rclpy.init()
node = ColorDetect()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.destroy_node()
    rclpy.shutdown()

colors.png의 세 블록은 크기가 같지만, 흐림 때문에 생긴 경계 픽셀이 임계값을 통과하는 정도가 색마다 달라 파랑이 조금 더 크게 잡혔습니다. 크기가 비슷한 물체가 여럿이면 “가장 큰 색” 규칙은 프레임마다 결과가 바뀔 수 있습니다. 여러 물체를 모두 알려야 하는 응용이라면 원본 노드처럼 색마다 ColorInfo를 리스트로 발행하는 편이 낫습니다. track.png의 검은 선은 찾는 색 목록에 없으므로 None입니다.

실습 (실물)#

실물 실습 전 확인
  • 색 인식 예제는 바퀴를 움직이지 않습니다. 로봇은 평평한 곳에 두고 카메라 앞에서 물체만 움직입니다.
  • 인식 결과가 흔들리지 않도록 카메라 시야에 같은 색의 다른 물체가 없게 합니다.
  • ~/.stop_ros.sh로 앱 서비스를 끄고 실습하며, 끝나면 컨테이너 밖 시스템 터미널에서 sudo systemctl restart start_node.service로 되살립니다(부저가 울리면 완료).
