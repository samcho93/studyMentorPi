M08MentorPi URDF 모델

URDF 문법 복습, mentorpi_description의 xacro 구조(메카넘/애커만), base_footprint·lidar·imu 링크와 RViz 표시.

선수 챕터: M07
3D 시뮬레이터URDF 뷰어

학습 목표#

  • URDF의 <link>·<joint>·<origin>·<axis>와 관절 종류(fixed, continuous, revolute …)를 읽고, 링크 트리를 그릴 수 있습니다.
  • xacro가 URDF에 더하는 기능(속성, 매크로, 조건부 include)을 설명하고, mentorpi.xacro가 MACHINE_TYPE으로 섀시 모델을 고르는 방식을 해석합니다.
  • mecanum.xacro·ack.xacro의 실제 링크·조인트 이름과 오프셋으로 TF 트리를 그리고, 동차 변환 행렬로 센서 좌표를 로봇 좌표로 바꿉니다.
  • robot_state_publisher가 URDF를 TF로 바꾸는 과정을 이해하고, RViz·URDF 뷰어에서 모델을 확인합니다.

URDF가 하는 일#

URDF(Unified Robot Description Format)는 로봇을 강체(link)와 그 사이 관절(joint)의 트리로 기술하는 XML 파일입니다. SLAM·내비게이션에서 URDF가 중요한 이유는 하나입니다.

라이다는 lidar_frame 기준으로 거리를 재지만, 지도와 경로는 base_footprint 기준으로 계산합니다. 두 좌표계 사이의 변환을 누군가 알려 줘야 합니다.

그 변환을 URDF가 담고, robot_state_publisher 노드가 URDF를 읽어 /tf_static(고정 관절)과 /tf(움직이는 관절)로 발행합니다. 라이다가 로봇 중심에서 1.2 cm 뒤에 달려 있다는 사실을 URDF가 모르면, 지도의 벽이 1.2 cm씩 어긋나게 쌓입니다.

URDF 문법 복습#

link#

xml
<link name="base_link">
  <inertial>   <!-- 질량·관성 (동역학 시뮬레이션용) -->
    <origin xyz="7.8e-05 3.7e-05 0.0068" rpy="0 0 0"/>
    <mass value="0.080358"/>
    <inertia ixx="9.92e-05" ixy="3.2e-08" ixz="1.16e-05" iyy="0.000292" iyz="-2.9e-08" izz="0.000368"/>
  </inertial>
  <visual>     <!-- 화면에 그릴 모양 -->
    <geometry><mesh filename="package://mentorpi_description/meshes/mecanum/base_link.STL"/></geometry>
  </visual>
  <collision>  <!-- 충돌 계산용 모양 (보통 단순화) -->
    <geometry><mesh filename="package://mentorpi_description/meshes/mecanum/base_link.STL"/></geometry>
  </collision>
</link>
태그뜻비고
<inertial>질량(mass, kg), 관성 텐서 6개 성분(ixx ixy ixz iyy iyz izz, kg·m²)관성 텐서는 대칭이라 6개면 충분
<visual>그릴 모양: box, cylinder, sphere, meshmaterial로 색 지정
<collision>충돌 모양메시 대신 상자·원통을 쓰면 계산이 빠름
<origin xyz rpy>링크 좌표계 안에서 그 요소의 위치·자세m, rad

<link name="imu_link"/>처럼 내용이 없는 링크도 쓸 수 있습니다. 센서 좌표계처럼 "위치만 있는 점"을 만들 때입니다.

joint#

xml
<joint name="wheel_lf_Joint" type="continuous">
  <origin xyz="0.067052 0.07591 -0.018408" rpy="0 0 0"/>   <!-- 부모 좌표계에서 본 자식 원점 -->
  <parent link="base_link"/>
  <child link="wheel_lf_Link"/>
  <axis xyz="0.00012228 1 -4.0642E-05"/>                    <!-- 회전축 (자식 좌표계 기준) -->
</joint>
type움직임필요한 태그MentorPi 예
fixed없음origin라이다, 카메라, IMU, base_footprint→base_link
continuous무한 회전axis네 바퀴
revolute범위 있는 회전axis, limit lower upper effort velocity(조향 서보를 모델링한다면)
prismatic직선 이동axis, limit—
floating, planar6/3 자유도—드묾

<origin>의 rpy는 roll(x)·pitch(y)·yaw(z) 순서의 고정축 회전이고 행렬로는 R = Rz(yaw)·Ry(pitch)·Rx(roll)입니다. 교재는 limit의 velocity를 m/s로 설명하지만, 회전 관절에서는 rad/s, 직선 관절에서만 m/s입니다.

xacro#

xacro(XML macro)는 URDF를 만들어 내는 전처리기입니다. xacro 파일.xacro 명령이 순수 URDF를 출력합니다.

기능문법MentorPi에서
속성(상수)<xacro:property name="M_PI" value="3.14159..."/>, ${M_PI/2}imu.urdf.xacro, inertial_matrix.xacro
수식${0.025 - 0.0295 + 0.0965/2 + 0.0678}IMU 높이 계산
매크로<xacro:macro name="cylinder_inertial" params="m r h">원통·구·상자 관성 공식
include<xacro:include filename="$(find pkg)/urdf/x.xacro"/>섀시별 모델 불러오기
조건<xacro:if value="${machine == 'MentorPi_Mecanum'}">섀시 선택
환경 변수$(env MACHINE_TYPE)로봇마다 다른 값

inertial_matrix.xacro의 원통 매크로는 교과서 공식 그대로입니다: Ixx = Iyy = m(3r² + h²)/12, Izz = m r²/2.

읽을거리:

  • **base_footprint** 는 바닥 위(z = 0)에 있는 로봇 중심점입니다. 2D 내비게이션은 모두 이 프레임을 로봇 위치로 씁니다(slam.yaml의 base_frame: base_footprint, nav2_params.yaml의 robot_base_frame: base_footprint). base_link는 그보다 0.07 m 위의 차체 원점입니다.
  • IMU 링크가 z축으로 −90° 돌아가 있습니다. 확장보드의 IMU 칩이 돌려져 장착됐기 때문이고, 이 회전이 있어야 IMU의 가속도·각속도가 로봇 축으로 올바르게 바뀝니다.
  • 라이다 링크 이름은 lidar_frame이고, 원본 slam/launch/include/robot.launch.py가 라이다 드라이버에 lidar_frame = '{}lidar_frame'을 넘겨 스캔 메시지의 frame_id와 URDF가 일치하게 합니다.
  • lidar.urdf.xacro는 lidar_link → lidar_frame을 π만큼 돌리는 조인트를 정의하지만, 최상위 mentorpi.xacro에서 include하지 않으므로 현재 모델에는 쓰이지 않습니다. 파일이 있다고 쓰이는 것은 아닙니다.
URDF의 바퀴 간격 ≠ 기구학 파라미터

URDF 바퀴 조인트로 계산한 메카넘 바퀴 간격은 앞뒤 0.1347 m, 좌우 0.1518 m입니다. 한편 속도 제어 코드(controller/mecanum.py, M01)는 wheelbase 0.1368 m, track_width 0.1446 m를 씁니다. URDF 조인트 원점은 CAD 메시의 좌표 원점(바퀴 축 어딘가)이고, 기구학 값은 바퀴가 바닥에 닿는 점 사이 거리를 보정한 값이라 다릅니다. 모터 명령에는 기구학 값을, 시각화·TF에는 URDF 값을 씁니다.

TF로 센서 좌표 바꾸기#

조인트의 origin은 동차 변환 행렬(homogeneous transform) 하나입니다.

T = [R t; 0 0 0 1], R = Rz(yaw)·Ry(pitch)·Rx(roll), t = (x, y, z)

체인을 따라 곱하면 멀리 떨어진 두 프레임 사이 변환이 됩니다: T(footprint→lidar) = T(footprint→base) · T(base→lidar). 아래 코드는 mecanum.xacro의 값으로 이 계산을 합니다.

URDF 뷰어 열기

python브라우저 실행Playground ↗
import numpy as np
np.set_printoptions(suppress=True)

def T(xyz, rpy=(0.0, 0.0, 0.0)):
    """URDF <origin xyz rpy> -> 4x4 homogeneous matrix (R = Rz(yaw) Ry(pitch) Rx(roll))."""
    r, p, y = rpy
    Rx = np.array([[1, 0, 0], [0, np.cos(r), -np.sin(r)], [0, np.sin(r), np.cos(r)]])
    Ry = np.array([[np.cos(p), 0, np.sin(p)], [0, 1, 0], [-np.sin(p), 0, np.cos(p)]])
    Rz = np.array([[np.cos(y), -np.sin(y), 0], [np.sin(y), np.cos(y), 0], [0, 0, 1]])
    M = np.eye(4)
    M[:3, :3] = Rz @ Ry @ Rx
    M[:3, 3] = xyz
    return M

# mecanum.xacro joint origins
fp_base = T((0, 0, 0.07))                         # base_footprint_to_base_link
base_lidar = T((-0.012242, -8.533e-05, 0.092501)) # lidar_Joint
base_cam = T((0.061376, -0.00013463, 0.051154))   # cam_Joint
base_imu = T((0, 0, 0), (0, 0, -1.57))            # imu_joint

fp_lidar = fp_base @ base_lidar
print("base_footprint -> lidar_frame xyz:", np.round(fp_lidar[:3, 3], 4))
print("base_footprint -> depth_cam  xyz:", np.round((fp_base @ base_cam)[:3, 3], 4))

p_lidar = np.array([1.0, 0.0, 0.0, 1.0])         # 1 m straight ahead of the lidar
print("lidar point in base_footprint   :", np.round(fp_lidar @ p_lidar, 4)[:3])

a_imu = np.array([1.0, 0.0, 0.0])                # IMU x-axis acceleration
print("IMU x-axis in base_link         :", np.round(base_imu[:3, :3] @ a_imu, 3))

wb = wheels["lf"][0] - wheels["lb"][0]

IMU x-axis in base_link         : [ 0.001 -1.     0.   ]
URDF wheelbase 0.1347 m, track 0.1518 m
  • 라이다 스캔 평면은 바닥에서 0.1625 m 높이입니다. 이보다 낮은 물체는 라이다가 못 봅니다(M07의 깊이 카메라가 필요한 이유).
  • 라이다 1 m 앞의 점은 로봇 중심에서 0.9878 m입니다. 1.2 cm 차이지만 한 바퀴 돌며 지도를 그리면 벽이 두 겹으로 보이는 원인이 됩니다.
  • IMU의 x축은 로봇의 −y 방향(오른쪽)을 가리킵니다. −1.57은 −π/2(−1.5708)보다 조금 작아서 0.001의 잔차가 남습니다.

robot_state_publisher와 launch#

launch/display.launch.py는 세 노드를 띄웁니다.

노드역할
robot_state_publisherCommand(['xacro ', urdf_path])로 만든 URDF 문자열을 robot_description 파라미터로 받아, 고정 관절은 /tf_static, 움직이는 관절은 /joint_states를 받아 /tf로 발행
joint_state_publisher_gui바퀴 각도를 슬라이더로 바꿔 /joint_states 발행(시각화용)
rviz2 (rviz.launch.py, 5 s 지연)rviz/view.rviz 설정으로 모델 표시

실제 주행 launch(controller.launch.py 등)에서는 슬라이더 대신 robot_description.launch.py의 joint_state_publisher가 /controller_manager/joint_states를 받아 씁니다.

교재 코드와 실제 파일의 차이

교재 L2의 발췌 코드에는 메시 경로가 package://rosmentor_description/...으로 적혀 있지만, 실제 파일은 package://mentorpi_description/...입니다. 직접 URDF를 만들 때 교재 코드를 복사하면 RViz에 "Could not load resource" 오류가 납니다. 항상 로봇의 실제 파일을 기준으로 합니다.

실습 (실물)#

안전 확인 (실물 실습 전 필수)
  • 이 실습은 모델 파일을 읽기만 합니다. mecanum.xacro·ack.xacro를 고칠 때는 먼저 cp mecanum.xacro mecanum.xacro.bak으로 백업합니다. 잘못 고친 URDF는 SLAM·내비게이션의 TF를 망가뜨립니다.
  • display.launch.py는 모터를 움직이지 않지만, 다른 터미널에서 주행 노드가 떠 있지 않은지 확인합니다.
  • 끝나면 sudo systemctl restart start_node.service로 앱 서비스를 되돌립니다(호스트 터미널에서).
  1. 앱 서비스를 끄고 모델 파일을 엽니다.
bash
~/.stop_ros.sh
colcon_cd mentorpi_description
cd urdf
vim mentorpi.xacro           # MACHINE_TYPE 분기 확인, :q 로 나가기
vim mecanum.xacro            # 애커만 로봇이면 ack.xacro
echo $MACHINE_TYPE           # MentorPi_Mecanum 또는 MentorPi_Acker
  1. xacro를 URDF로 펼쳐 구조를 검사합니다.
bash
xacro mentorpi.xacro > /tmp/mentorpi.urdf
check_urdf /tmp/mentorpi.urdf           # 링크 트리와 오류 출력 (liburdfdom-tools 필요)
grep -c "<link" /tmp/mentorpi.urdf
  1. 모델을 RViz로 봅니다. VNC 데스크톱에서 실행해야 창이 보입니다.
bash
ros2 launch mentorpi_description display.launch.py

RViz에서 Fixed Frame을 base_footprint로 두고 TF 디스플레이를 켜서 축 이름을 확인합니다. joint_state_publisher_gui 슬라이더로 바퀴를 돌려 봅니다.

  1. TF를 숫자로 확인합니다(새 터미널).
bash
ros2 run tf2_ros tf2_echo base_footprint lidar_frame     # Translation: [-0.012, -0.000, 0.163]
ros2 run tf2_ros tf2_echo base_link imu_link              # Rotation RPY (deg): 0, 0, -90
ros2 run tf2_tools view_frames                            # frames_*.pdf 로 TF 트리 저장
  1. 브라우저의 URDF 뷰어에서도 같은 링크 트리를 확인하고, 라이다·카메라 위치를 위 표와 비교합니다.

실습 (3D 시뮬레이터): URDF로 움직이는 MentorPi#

이 장에서 읽은 mecanum.xacro/ack.xacro를 그대로 변환한 URDF(assets/urdf/mentorpi/)가 3D 시뮬레이터의 로봇 모델입니다. 링크·조인트 이름이 실물과 같으므로, 바퀴 조인트 wheel_lf_Joint … 가 섀시 기구학 식에 따라 돌고, 라이다 레이는 lidar_frame 높이(base_footprint 기준 약 0.16 m)에서, 로봇 카메라 화면은 depth_cam 위치에서 렌더링됩니다.

3D 시뮬레이터 열기

  1. 섀시 (URDF) 에서 메카넘/애커만을 바꿔 가며 링크 9개·조인트 8개가 로드되는지 확인합니다.
  2. 시점 → 1인칭(카메라) 으로 바꿔 cam_Joint 원점(x = 0.061 m, z = 0.121 m)에서 보이는 장면을 확인합니다.
  3. 라이다 탭에서 회피를 켜고, 레이가 몸체보다 높은 lidar_frame에서 나가 낮은 장애물(높이 0.25 m 상자)에 맞는 모습을 봅니다. 실물에서 라이다 높이보다 낮은 물체는 보이지 않는다는 점을 떠올리세요.
  4. 애커만에서 ωz를 주면 앞바퀴가 최대 29°까지 꺾입니다. URDF에는 조향 조인트가 없어서 시각화로만 회전시킨다는 점(원본 모델의 한계)도 확인합니다.

자주 나는 오류와 해결#

증상원인해결
xacro: ... KeyError: 'MACHINE_TYPE' 또는 빈 모델환경 변수 없음(컨테이너 밖, 새 셸)export MACHINE_TYPE=MentorPi_Mecanum 후 실행, 로봇 버전 설정 확인(B03)
RViz 모델이 흰색/보이지 않음, "Could not load resource"메시 package:// 경로 오류, 패키지 미빌드실제 패키지 이름 mentorpi_description 확인, colcon build 후 source
바퀴가 공중에 떠 있거나 모델이 바닥에 박힘Fixed Frame을 base_link로 둠Fixed Frame을 base_footprint로 (z 0.07 차이)
check_urdf: command not foundurdfdom 도구 미설치sudo apt install liburdfdom-tools 또는 xacro 출력만 확인
지도에서 벽이 두 겹, 회전할 때 번짐URDF 라이다 오프셋이 실제 장착과 다름장착 위치를 자로 재서 lidar_Joint origin 수정, 스캔 frame_id 확인
joint_state_publisher_gui 창이 안 뜸GUI 없는 SSH 셸에서 실행VNC 데스크톱 터미널에서 실행

과제#

기본 과제
  1. ack.xacro의 값으로 위 코드를 고쳐 애커만 모델의 base_footprint → lidar_frame, base_footprint → depth_cam 변환을 구하고 메카넘과 비교합니다.
  2. mecanum.xacro에서 링크 수와 조인트 수를 세고, 조인트 종류별 개수를 표로 정리합니다. check_urdf 출력과 비교합니다.
심화 과제
  1. 라이다를 20° 기울여 장착했다고 가정하고(lidar_Joint의 rpy = 0 0.349 0), 라이다 1 m 앞의 점이 base_footprint에서 어디에 찍히는지 계산합니다. 이런 오차가 2D SLAM 지도에 어떻게 나타날지 설명합니다.
  2. inertial_matrix.xacro의 box_inertial 매크로로 가로 0.19 m × 세로 0.15 m × 높이 0.05 m, 0.8 kg 상자의 관성 텐서를 계산하고, base_link의 izz와 크기 차이를 비교합니다(원본 값은 차체 셸만의 질량 0.08 kg 기준).
