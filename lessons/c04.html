C04첫 에이전트 만들기: 워크스페이스 규약과 도구 권한

AGENTS.md·SOUL.md·USER.md·IDENTITY.md·TOOLS.md 워크스페이스 규약과 openclaw.json의 agents.list·systemPrompt·tools.allow/deny로 실행형 에이전트를 정의하고, 작업 분해·진행 보고·최종 정리와 로그 추적으로 검증합니다.

선수 챕터: C02 C03
ROS 2 Playground

학습 목표#

  • 에이전트의 워크스페이스(workspace)와 에이전트 전용 디렉터리(agentDir)가 각각 무엇을 담는지 구분하고 직접 만듭니다.
  • AGENTS.md·SOUL.md·USER.md·IDENTITY.md·TOOLS.md 규약 파일의 역할을 설명하고 최소 템플릿을 작성합니다.
  • openclaw.json의 agents.list에 에이전트를 등록하고 tools.allow/tools.deny로 최소 권한을 설계합니다.
  • 작업 분해 → 단계별 보고(Step/Status/Output/Next) → 최종 정리로 이어지는 실행형 에이전트의 동작을 CLI로 검증합니다.
  • Gateway 상태 → 전경 실행 → doctor → 실행 추적 순서로 문제를 좁혀 갑니다.

채팅봇이 아니라 실행형 에이전트#

C02에서 모델(Model)은 두뇌, 도구(Tool)는 손, 에이전트(Agent)는 일을 끝까지 끌고 가는 관리자라고 정리했습니다. 이 장에서는 그 관리자를 하나 직접 만듭니다. 이름은 원본 교재를 따라 **test이고, 성격은 "말 잘하는 비서"가 아니라 실행형 멀티모달 비서(execution-oriented multimodal assistant)입니다. 파일을 쓰고, 스크립트를 돌리고, 웹 페이지를 읽고, 카메라로 사진을 찍은 뒤, 무엇을 했는지 추적 가능한 형태로 보고**하는 것이 목표입니다.

test의 행동은 서로 비교적 독립된 일곱 모듈로 나누어 보면 이해하기 쉽습니다.

#모듈하는 일필요한 도구(tools.allow)
1작업 분해 (task breakdown)큰 목표를 3~7단계로 나누고 단계별 도구를 표시— (프롬프트 규칙)
2파일 관리 (file management)읽기·생성·수정·보관, 경로를 반드시 남김read, write, edit, apply_patch
3카메라 촬영 (camera capture)별칭으로 카메라를 골라 촬영, 저장 경로 보고image, nodes (환경에 따라)
4브라우저 제어 (browser control)페이지 열기·내용 가져오기, 최종 URL 기록browser, web_fetch, web_search
5스크립트 실행 (script execution)정해진 디렉터리에서 실행, 로그·산출물 경로 보고exec, process
6능동 피드백 (proactive feedback)단계가 끝날 때마다 즉시 진행 상황 보고— (프롬프트 규칙)
7정보 정리 (consolidation)끝나면 요약·산출물·로그·미해결을 한 번에 정리— (프롬프트 규칙)

표를 보면 에이전트의 능력은 두 층으로 이루어져 있습니다. 무엇을 할 수 있는가는 openclaw.json의 도구 권한이 정하고, 어떻게 행동하는가는 워크스페이스의 규약 파일과 systemPrompt가 정합니다. 둘 중 하나만 맞아서는 원하는 동작이 나오지 않습니다. 규칙에 "사진을 찍어라"라고 써도 image 권한이 없으면 찍을 수 없고, 권한이 있어도 규칙이 없으면 어디에 저장했는지 말해 주지 않습니다.

두 개의 폴더: workspace와 agentDir#

경로이름담는 것누가 주로 쓰나
~/.openclaw/workspace/testworkspace규약 파일(AGENTS.md 등), skills/, memory/, 작업 산출물(tmp/)사람이 규칙을 쓰고, 에이전트가 결과를 씀
~/.openclaw/agents/test/agentagentDir에이전트 전용 설정·인증 정보, 세션·실행 추적 기록OpenClaw가 관리, 사람은 주로 읽기만

원본 교재는 사용자 이름이 ubuntu인 환경이라 openclaw.json에 /home/ubuntu/.openclaw/... 같은 절대 경로를 적습니다. 여러분의 사용자 이름이 다르면 /home/<사용자>/...로 바꿔야 합니다. echo $HOME으로 확인하세요.

왜 폴더를 둘로 나누나요?

워크스페이스는 에이전트가 읽고 쓰는 작업장이고, agentDir는 에이전트를 운영하는 기록실입니다. 작업장에 인증 정보나 추적 기록이 섞여 있으면, 파일 쓰기 권한을 가진 에이전트가 실수로(또는 악의적인 지시에 속아) 자기 설정을 고칠 수 있습니다. 경계를 나누어 두면 "워크스페이스 밖은 쓰지 않는다"는 한 줄 규칙으로 많은 사고를 막을 수 있습니다.

워크스페이스 규약 파일#

OpenClaw는 세션을 시작할 때 워크스페이스의 약속된 이름의 Markdown 파일을 읽어 모델의 맥락(context)에 넣습니다. 즉 이 파일들은 사람이 쓰는 시스템 프롬프트의 조각입니다. 파일마다 맡는 역할이 정해져 있습니다.

파일역할들어갈 내용 예
AGENTS.md작업 방식(운영 매뉴얼)세션 시작 절차, 작업 분해 규칙, 보고 형식, 정리 형식
SOUL.md성격과 경계"채팅봇이 아니라 실행자", 모르면 묻기, 비밀 노출 금지
USER.md사용자 기본값시간대, 작업 범위, 카메라 별칭, 출력 디렉터리
IDENTITY.md이름·정체성 표시이름, 성격 한 줄, 분위기
TOOLS.md도구 사용 메모(권장)카메라 별칭, 브라우저 기록 규칙, 스크립트 디렉터리

아래는 원본 템플릿을 한국 환경에 맞게 다시 쓴 최소 동작 버전입니다. 처음에는 짧게 시작하고, 실제로 부족한 점이 보일 때 한 줄씩 늘리는 편이 좋습니다. 규칙이 길어질수록 모델이 일부를 무시할 확률도 커지기 때문입니다.

markdown
# AGENTS.md — test 실행형 에이전트 작업 방식

## Session Start
1. SOUL.md, USER.md, IDENTITY.md, TOOLS.md를 읽는다.
2. memory/ 아래 오늘·어제 노트가 있으면 읽는다.

## Task Breakdown
- 복잡한 작업은 실행 전에 3~7단계로 분해한다.
- 각 단계에 목적, 예상 산출물, 사용할 도구를 적는다.
- 파일 쓰기·스크립트 실행·장치 조작이 있으면 위험과 확인 사항을 먼저 적는다.

## Proactive Feedback
- 단계가 끝날 때마다 즉시 Step / Status / Output / Next를 보고한다.

## Information Consolidation
- 마지막에 요약, 산출물 목록, 핵심 로그 요약, 미해결 항목을 출력한다.
markdown
# SOUL.md
나는 채팅봇이 아니라 실행형 에이전트다.
- 실행 전에 작업을 분해한다.
- 확실하지 않으면 묻는다.
- 개인정보나 키를 노출하지 않는다.
- 파괴적인 작업(삭제·덮어쓰기·장치 이동)은 확인을 받은 뒤 한다.
markdown
# USER.md
- Timezone: Asia/Seoul
- 작업 범위(기본 쓰기 위치): workspace/test
- 카메라 별칭: default

- 스크립트 출력 디렉터리: workspace/test/tmp
markdown

- Name: test 실행형 멀티모달 비서
- Creature: 실무형 실행 에이전트

규약 파일이 어떻게 하나의 프롬프트로 합쳐지는지 파이썬으로 흉내 내 봅시다. 실제 OpenClaw는 Node.js로 만들어져 브라우저에서 돌릴 수 없으므로, 아래 코드는 개념 모형입니다. 일부러 TOOLS.md를 빠뜨려 누락 검사가 어떻게 보이는지도 확인합니다.

python브라우저 실행Playground ↗
# 워크스페이스 규약 파일(가상) → 시스템 프롬프트 조립
workspace = {
    "AGENTS.md": "# AGENTS.md\n## Session Start\n1. SOUL/USER/IDENTITY/TOOLS를 읽는다.\n"
                 "## Task Breakdown\n- 복잡한 작업은 3~7단계로 먼저 분해한다.\n"
                 "## Proactive Feedback\n- 단계마다 Step/Status/Output/Next를 보고한다.\n",
    "SOUL.md": "# SOUL.md\n실행형 에이전트다. 모르면 묻고, 파괴적 작업은 확인받는다.\n",
    "USER.md": "# USER.md\n- Timezone: Asia/Seoul\n- 출력 디렉터리: workspace/test/tmp\n",
    "IDENTITY.md": "# IDENTITY.md\n- Name: test 실행형 멀티모달 비서\n",
    # TOOLS.md는 일부러 빠뜨려 본다
}
ORDER = ["AGENTS.md", "SOUL.md", "USER.md", "IDENTITY.md", "TOOLS.md"]
REQUIRED = {"AGENTS.md", "SOUL.md", "USER.md", "IDENTITY.md"}

def headings(text):
    return [ln.lstrip("# ").strip() for ln in text.splitlines() if ln.startswith("## ")]

def assemble(base_rules, files):
    parts, report = [base_rules], []
    for name in ORDER:
        if name not in files:
            level = "누락(필수)" if name in REQUIRED else "누락(권장)"
            report.append(f"{name:12s} {level}")
            continue
        body = files[name].strip()
        parts.append(f"<file name='{name}'>\n{body}\n</file>")
        hs = ", ".join(headings(body)) or "-"
        report.append(f"{name:12s} {len(body):3d}자  섹션: {hs}")
    return "\n\n".join(parts), report

base = "You are agent 'test'. Follow the workspace files below."
prompt, report = assemble(base, workspace)
for r in report:
    print(r)
print("조립된 프롬프트 길이:", len(prompt), "자")
print("USER.md 반영 여부:", "Asia/Seoul" in prompt)

systemPrompt: 실행 규칙#

원본 교재는 test의 systemPrompt에 다음 네 가지 요구를 넣습니다. AGENTS.md와 내용이 겹치는데, 이것은 의도된 이중화입니다. systemPrompt는 모든 요청에 강하게 걸리는 규칙이고, AGENTS.md는 사람이 고치기 쉬운 세부 매뉴얼입니다.

  1. 복잡한 목표는 먼저 3~7단계 작업 분해를 출력하고, 단계마다 필요한 도구를 표시한다.
  2. 실행 중에는 단계가 끝날 때마다 즉시 상태, 산출물(경로·스크린샷·URL·핵심 로그), 다음 단계 또는 확인 질문을 보고한다.
  3. 끝나면 정보를 정리한다: 요약, 산출물 목록, 핵심 로그 요약, 미해결 항목과 다음 단계.
  4. 안전 우선: 매개변수가 불분명하거나 큰 손실이 날 수 있는 작업은 확인을 받고, 개인정보나 키를 노출하지 않는다.

원본은 OpenClaw 2026.3.24 기준입니다. systemPrompt를 에이전트 항목의 어느 키에 두는지, tools.profile과 allow/deny가 어떻게 합쳐지는지는 버전마다 달라질 수 있습니다. 설정을 바꾼 뒤에는 openclaw doctor로 알 수 없는 키 경고가 없는지 확인하고, 경고가 나면 같은 규칙을 AGENTS.md에 두는 쪽으로 대체합니다.

도구 권한: 최소 권한의 원칙#

test의 권한 전략은 한 문장으로 요약됩니다. 작업 실행과 산출물 생성은 허용하되, 시스템 수준의 고위험 능력은 막는다.

구분도구이유
허용 — 파일read, write, edit, apply_patch산출물을 만들고 고쳐야 함
허용 — 실행exec, process스크립트 실행, 프로세스 관리

허용 — 기타message, nodes, image메시지 전송, 연결된 장치, 이미지(카메라)
거부sessions_spawn, subagents에이전트가 다른 에이전트를 낳아 일을 넘기면 권한·비용·추적이 흐려짐
거부cron사람이 보지 않는 시간에 스스로 예약 실행 — 실수가 반복·누적됨

거부canvas이 장의 과제에 필요 없는 UI 기능

최소 권한의 원칙(principle of least privilege)은 "일을 하는 데 꼭 필요한 권한만 준다"는 보안의 기본 원칙입니다. LLM 에이전트에서는 특히 중요합니다. 모델은 확률적으로 동작하고, 웹 페이지나 메일에 숨겨진 문장에 속을 수 있습니다(프롬프트 인젝션, prompt injection). 속았을 때 할 수 있는 일의 최대치를 줄여 두는 것이 권한 설계입니다. cron과 gateway를 막는 이유가 바로 이것입니다. 한 번의 잘못된 판단이 "매일 반복"되거나 "권한 확장"으로 번지는 길을 원천적으로 끊습니다.

allow와 deny가 함께 있을 때는 흔히 다음 규칙으로 판정합니다: deny가 우선하고, allow 목록이 있으면 목록에 없는 도구는 거부합니다. 아래 모형으로 확인해 봅시다.

python브라우저 실행Playground ↗
# tools.allow / tools.deny 판정 (원본 test 에이전트 목록 그대로)
ALLOW = ["read", "write", "edit", "apply_patch", "exec", "process", "browser",
         "web_search", "web_fetch", "memory_search", "memory_get", "session_status",
         "sessions_list", "sessions_history", "message", "nodes", "image"]
DENY = ["sessions_spawn", "subagents", "canvas", "cron", "gateway"]

def decide(tool, allow=ALLOW, deny=DENY):
    if tool in deny:
        return "거부", "deny 목록 — deny가 allow보다 우선"
    if allow and tool not in allow:
        return "거부", "allow 목록에 없음 — 기본 거부"
    return "허용", "allow 목록"

requests = ["write", "exec", "image", "cron", "gateway", "subagents", "tts"]
for t in requests:
    verdict, why = decide(t)
    print(f"{t:10s} → {verdict}  ({why})")

# 같은 도구가 양쪽에 있으면? deny가 이긴다
print("\n충돌 예:", decide("exec", allow=ALLOW, deny=DENY + ["exec"]))

# 최소 권한 점검: 과제에 필요한 도구만 남기면 몇 개가 줄어드는가
need = {"read", "write", "exec", "web_fetch"}
extra = sorted(set(ALLOW) - need)
print(f"\n과제 필요 {len(need)}개 / 허용 {len(ALLOW)}개 → 여분 {len(extra)}개")
print("여분 예:", ", ".join(extra[:6]), "...")

마지막 두 줄이 주는 교훈이 중요합니다. 교재의 test는 여러 능력을 시연하려고 17개를 열어 두었지만, 실제 업무용 에이전트라면 그 업무에 필요한 도구만 남기는 편이 안전합니다. 5장의 브리핑 스킬 예시에서도 원본은 파일 쓰기(write, edit)를 뺀 축소 목록을 함께 보여 줍니다.

권한을 바꾸면 반드시 재시작

tools.allow/deny를 포함해 openclaw.json을 고친 뒤에는 openclaw gateway restart를 실행해야 반영됩니다. "권한을 줬는데 여전히 못 한다"는 문의의 상당수가 재시작 누락입니다.

일곱 모듈 자세히 보기#

1) 작업 분해#

여러 능력이 섞인 목표나 큰 작업이면 실행 전에 Step 목록이 먼저 나와야 합니다. 각 Step에는 목적·예상 산출물·도구 종류(파일/카메라/브라우저/스크립트)가 붙고, 파일 쓰기·스크립트·장치 조작이 있으면 위험과 확인 사항을 먼저 나열한 뒤 매개변수가 분명해져야 실행합니다. 분해가 나타나지 않으면 대개 요청의 매개변수가 부족했거나, systemPrompt와 AGENTS.md의 Task Breakdown 규칙이 로드되지 않은 것입니다.

2) 파일 관리 (읽기·생성·수정·보관)#

동작도구규칙
읽기read먼저 읽고 판단한다
생성·수정write, edit, apply_patch워크스페이스 안에만, 결과 경로를 남긴다
보관(archive)—핵심 결과와 경로를 정리 보고서의 산출물 목록에 쓴다

에이전트에게 파일 작업을 맡길 때는 최소한 ① 대상의 상대 경로(예: workspace/test/tmp/notes.txt), ② 내용 요구(형식·필드·개수), ③ 기대 산출물을 분명히 적어 줍니다.

3) 카메라 촬영#

USER.md의 카메라 별칭(default = 시스템 기본 카메라)을 먼저 확인하고, 촬영 대상·각도·연속 촬영 여부가 빠졌으면 묻습니다. 촬영 뒤에는 이미지 경로나 링크를 정리 보고서에 남기고, 실패하면 이유와 다음 행동(별칭 변경, 재시도, 수동 촬영 후 업로드)을 제시합니다. 카메라 기능이 image 도구로 제공되는 환경이라면 tools.allow에 image가 있어야 합니다.

4) 브라우저 제어#

페이지를 열거나 이동하면 최종 URL을 기록하고, 내용이 필요하면 web_fetch나 브라우저 도구로 가져와 요점만 정리합니다. 페이지 원문을 길게 옮기지 않는 것은 가독성뿐 아니라 민감한 내용 노출을 줄이기 위해서이기도 합니다.

5) 스크립트 실행#

기본 실행 위치는 workspace/test, 산출물은 workspace/test/tmp에 먼저 씁니다. 실행 전에는 명령(또는 스크립트 요약)과 예상 출력 경로를 다시 말하고, 실행 뒤에는 stdout·stderr의 핵심 줄과 출력 경로를 정리합니다. 이 "실행 전 복창"은 사람이 끼어들 수 있는 마지막 기회이므로 로봇 제어로 가면 더욱 중요해집니다.

6) 능동 피드백과 7) 정보 정리#

단계마다 Step / Status / Output / Next 네 줄을 보고하면, 어디서 막혔는지가 대화 기록만 보고도 드러납니다. 모든 단계가 끝나면 정리 보고서에 ① 3~6줄 요약, ② 능력별 산출물 목록(파일·이미지·웹 요점·스크립트 결과), ③ 산출물과 관련된 핵심 로그만, ④ 미해결 항목과 다음 단계를 담습니다. 합격 기준은 "보고서만 보고 결과물을 찾아갈 수 있는가"입니다. 경로·URL·스크린샷 같은 추적 가능한 정보가 없으면 불합격입니다.

아래 모형은 이 사이클 전체를 흉내 냅니다. 도구는 read/write/exec만 허용하고, 파일 쓰기는 메모리 속 딕셔너리에 하되 워크스페이스 밖 경로는 거부합니다. 4단계는 경로 탈출(../../)을, 5단계는 권한 없는 cron을 일부러 시도합니다.

python브라우저 실행Playground ↗
# 실행형 에이전트 모의: 단계 계획 → 단계별 보고 → 최종 정리
import posixpath
WS = "workspace/test"
ALLOW = {"read", "write", "exec"}
fs, log = {}, []                       # 메모리 속 파일 시스템, 핵심 로그

def safe_path(p):
    full = posixpath.normpath(posixpath.join(WS, p))
    if not full.startswith(WS + "/"):
        raise PermissionError(f"워크스페이스 밖 경로 거부: {full}")
    return full

def tool(name, **kw):
    if name not in ALLOW:
        raise PermissionError(f"도구 '{name}' 권한 없음")
    if name == "write":
        path = safe_path(kw["path"]); fs[path] = kw["text"]; return path
    if name == "exec":                  # 스크립트 실행 흉내: 7일치 CSV 생성
        rows = ["day,tempC"] + [f"D-{6-i},{18+i}" for i in range(7)]
        log.append(f"stdout: {len(rows)-1} rows"); return "\n".join(rows)

plan = [("할 일 목록 작성", "write", {"path": "tmp/notes.txt", "text": "2026-09-26 09:00\n1. 배터리 확인\n2. 지도 백업\n3. 로그 정리"}),
        ("CSV 생성 스크립트 실행", "exec", {}),
        ("CSV 저장", "write", {"path": "tmp/small_report.csv"}),
        ("시스템 설정 백업", "write", {"path": "../../.bashrc", "text": "x"}),
        ("매일 자동 실행 예약", "cron", {})]
print("[계획]", " / ".join(f"{i+1}.{p[0]}({p[1]})" for i, p in enumerate(plan)))
outputs, unresolved, last = [], [], None
for i, (title, name, kw) in enumerate(plan, 1):
    if name == "write" and "text" not in kw:
        kw = dict(kw, text=last)        # 이전 단계 결과를 이어받음
    try:
        last = tool(name, **kw); status = "완료"
        out = last if name == "write" else last.splitlines()[1]
        if name == "write": outputs.append(last)
    except PermissionError as e:
        status, out = "실패", str(e); unresolved.append(f"Step {i}: {e}")
    nxt = plan[i][0] if i < len(plan) else "최종 정리"
    print(f"Step {i} | Status: {status} | Output: {out} | Next: {nxt}")

print("\n[최종 정리]")
print(f"요약: {len(plan)}단계 중 {len(plan)-len(unresolved)}단계 완료")
print("산출물:", ", ".join(outputs))
print("핵심 로그:", "; ".join(log))
print("미해결:")
for u in unresolved:
    print("  -", u)

실습 (실물)#

실습 전 확인
  • 이 장의 실습은 바퀴를 움직이지 않습니다. 그래도 exec 권한이 있는 에이전트는 셸 명령을 실행할 수 있으므로, 로봇의 ROS 2 노드가 돌고 있는 컨테이너나 중요한 데이터가 있는 계정에서 처음 시험하지 마세요. 연습용 사용자 계정이나 PC에서 먼저 확인합니다.
  • openclaw.json을 고치기 전에 반드시 백업합니다(cp ~/.openclaw/openclaw.json ~/.openclaw/openclaw.json.bak).
  • 테스트 메시지에 실제 비밀번호·API 키·개인정보를 넣지 않습니다. 대화 기록은 agentDir 추적 파일에 남습니다.
  • 에이전트가 워크스페이스 밖 경로를 쓰거나 삭제 명령을 제안하면 승인하지 말고 규약 파일을 보완합니다.

1) 폴더와 규약 파일 만들기#

bash
mkdir -p ~/.openclaw/workspace/test
mkdir -p ~/.openclaw/agents/test/agent
touch ~/.openclaw/workspace/test/AGENTS.md
touch ~/.openclaw/workspace/test/SOUL.md
touch ~/.openclaw/workspace/test/USER.md
touch ~/.openclaw/workspace/test/IDENTITY.md
touch ~/.openclaw/workspace/test/TOOLS.md

편집기(nano, gedit 등)로 앞 절의 템플릿을 각 파일에 채웁니다. tmp/는 에이전트가 처음 쓸 때 만들어도 되지만, 미리 mkdir -p ~/.openclaw/workspace/test/tmp로 만들어 두면 권한 문제를 한 가지 줄일 수 있습니다.

2) 에이전트 등록과 재시작#

~/.openclaw/openclaw.json의 agents.list 배열에 앞 절의 test 항목을 추가하고(쉼표 위치 주의), 저장한 뒤 재시작합니다.

bash
openclaw gateway restart
openclaw agents list --json

목록에 "id": "test"가 보이면 등록 성공입니다.

3) CLI로 시험하기#

openclaw agent 명령은 채널 없이 터미널에서 특정 에이전트에게 메시지를 보냅니다. --session-id를 같게 주면 같은 대화가 이어지고, 바꾸면 새 대화가 시작됩니다.

bash
# 파일 산출물 + 정리 보고서
openclaw agent --agent test --session-id test-001 --message "workspace/test/tmp에 notes.txt를 만들어 현재 날짜와 시각, 그리고 3개 항목의 할 일 목록 예시를 적어 줘. 끝나면 정리 보고서를 출력하고 생성한 파일 경로를 분명히 알려 줘."

# 스크립트 실행 + 분해·실행·정리 검증
openclaw agent --agent test --session-id test-001 --message "workspace/test/tmp에 small_report.csv를 만드는 스크립트를 작성해 실행해 줘. 열은 day,tempC이고 최근 7일치 행을 넣어 줘. 실행 전에 스크립트 논리와 출력 경로를 먼저 설명하고, 실행 후 CSV 경로와 관련 있는 핵심 로그만 요약해 줘."

# 브라우저(웹) 요약
openclaw agent --agent test --session-id test-001 --message "https://www.hiwonder.com.cn/product.html 을 열어 핵심 내용을 5가지 요점으로 요약하고 최종 URL을 알려 줘."

# 카메라(권한과 장치가 있을 때만)
openclaw agent --agent test --session-id test-001 --message "카메라로 책상 사진을 찍고 저장 경로를 알려 줘."
합격 기준
  • 복잡한 요청에서 Step 목록이 먼저 나온다.
  • 단계마다 Step/Status/Output/Next가 보고된다.
  • 정리 보고서에 실제로 존재하는 경로가 있고, ls ~/.openclaw/workspace/test/tmp로 확인된다.
  • 워크스페이스 밖에 쓰라는 요청에는 확인을 구하거나 거절한다.

로그 분석과 문제 해결 순서#

분해가 안 나온다, 경로가 비어 있다, 파일이 없다, 정리가 불완전하다, 실행이 실패한다 — 어떤 증상이든 아래 순서로 좁혀 갑니다. 바깥(프로세스)에서 안쪽(모델의 판단)으로 들어가는 순서입니다.

bash
openclaw gateway status          # 1. Gateway가 살아 있는가
openclaw gateway run --verbose   # 2. 전경 실행으로 자세한 오류 보기 (Ctrl+C로 종료)
openclaw doctor                  # 3. 설정 전반 진단
ls ~/.openclaw/agents/test/agent # 4. 실행 추적 확인 — 가장 중요

4단계의 agentDir(또는 버전에 따라 그 옆의 세션 디렉터리)에 있는 세션 기록·*.json 추적 파일에는 어떤 도구를 어떤 인자로 언제 불렀는지가 시간순으로 남습니다. 여기서 "Step이 실행되지 않은 이유(매개변수 부족, 안전 확인 대기)"나 "출력 경로가 빈 이유(쓰기 권한, 경로 불일치)"를 찾을 수 있습니다. 모델의 말(보고서)과 실제 도구 호출(추적)을 대조하는 습관이 에이전트 디버깅의 핵심입니다. 보고서에는 "저장했습니다"라고 쓰여 있는데 추적에 write 호출이 없다면, 그것은 모델이 결과를 지어낸 것입니다.
