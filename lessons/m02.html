M02애커만 조향 섀시 기구학

자전거 모델, 회전 반경과 조향각 δ = atan(L·ω/v), 좌·우 바퀴 속도차, 최대 조향각 제한과 최소 회전 반경.

선수 챕터: M01
3D 시뮬레이터섀시 기구학 실험실2D 시뮬레이터ROS 2 Playground

학습 목표#

  • 순수 구름(pure rolling) 조건에서 순간 회전 중심(ICR) 을 찾고, 애커만 섀시를 자전거 모델(bicycle model)로 단순화할 수 있습니다.
  • 회전 반경 R = v/ω, 조향각 δ = atan(Lω/v), 좌·우 뒷바퀴 속도 v_L, v_R = v ∓ ωD/2를 유도합니다.
  • 최대 조향각 29°에서 최소 회전 반경과 속도별 최대 각속도를 계산하고, 정지 상태에서 회전할 수 없는 이유를 설명합니다.
  • 원본 ackermann.py의 서보 펄스 식과 모터 부호를 해석하고, 조향각 제한 코드의 부호 손실 문제를 찾아 고칩니다.
  • 시뮬레이터에서 원 주행 반경을 측정해 이론값과 비교합니다.

애커만 섀시의 구조#

MentorPi 애커만 버전은 자동차와 같은 구조입니다.

  • 앞바퀴: 구동력이 없고 방향만 바꿉니다. PWM 서보(id 3)가 링키지를 밀고 당겨 두 앞바퀴를 함께 꺾습니다.
  • 뒷바퀴: 좌·우 각각 DC 모터(모터 2번·4번)로 구동합니다. 1번·3번 모터 자리는 쓰지 않습니다.

메카넘(M01)은 (v_x, v_y, ω_z) 세 자유도를 모두 직접 만들 수 있지만, 애커만은 옆으로 미끄러지지 않는 바퀴 때문에 v_y = 0이 강제됩니다. 이런 구속을 비홀로노믹(non-holonomic) 구속이라고 합니다. 주차할 때 차를 옆으로 밀 수 없어 앞뒤로 여러 번 움직이는 것과 같은 이유입니다.

순수 구름 조건과 ICR#

바퀴가 옆으로 미끄러지지 않으려면 각 바퀴는 자기 굴러가는 방향으로만 움직여야 합니다. 차체가 회전하고 있다면, 차체 위 모든 점은 한 점(ICR)을 중심으로 원운동하므로 각 바퀴 축(굴러가는 방향에 수직인 선)의 연장선이 모두 ICR에서 만나야 합니다.

  • 뒷바퀴는 꺾이지 않으므로 ICR은 항상 뒷차축 연장선 위에 있습니다.
  • 앞바퀴 두 개의 축 연장선도 같은 점을 지나야 하므로, 안쪽 앞바퀴는 바깥쪽보다 더 많이 꺾여야 합니다. 이 조건을 만족하는 링키지가 원래 의미의 애커만 기하(Ackermann geometry)입니다.

이상적인 안쪽·바깥쪽 조향각은 다음과 같습니다(뒷차축 중심 기준 반경 R, 윤거 D).

text
δ_in  = atan( L / (R − D/2) )
δ_out = atan( L / (R + D/2) )
MentorPi의 실제 링키지

원본 교재(Lesson 2)는 회전할 때 두 앞바퀴가 평행 상태로 같은 각도만큼 꺾인다고 설명합니다. 즉 교육용 섀시는 완전한 애커만 기하가 아니라 평행 조향에 가깝습니다. R = 0.4 m에서 이상적인 두 각도 차이는 약 6°(안쪽 23.5°, 바깥쪽 17.3°)라서, 평행 조향이면 한 바퀴가 조금 옆으로 끌립니다. 저속 소형 로봇에서는 무시할 만하고, 제어 계산은 두 앞바퀴를 가운데 하나로 합친 자전거 모델로 합니다.

자전거 모델 유도#

두 앞바퀴를 앞차축 가운데의 가상 바퀴 하나로, 두 뒷바퀴를 뒷차축 가운데의 가상 바퀴 하나로 합칩니다. 기준점은 뒷차축 중심입니다(오도메트리 base_footprint도 여기에 가깝게 둡니다).

1단계 — 회전 반경#

뒷차축 중심은 반경 R인 원을 속도 v로 돕니다. 원운동에서 v = ωR이므로

text
R = v / ω

2단계 — 조향각#

ICR, 뒷차축 중심, 앞바퀴 중심이 직각삼각형을 이룹니다(밑변 R, 높이 L). 앞바퀴는 ICR-앞바퀴 선에 수직이어야 하므로, 앞바퀴가 차체 축과 이루는 각 δ는 ICR에서의 각과 같습니다.

text
tan δ = L / R = L·ω / v
δ = atan( L·ω / v )

원본 코드 theta = math.atan(self.wheelbase*angular_speed/linear_speed)가 바로 이 식입니다. v < 0(후진)이면 같은 ω에 대해 δ의 부호가 반대가 되는데, 후진할 때 핸들을 반대로 꺾어야 같은 방향으로 도는 자동차 경험과 일치합니다.

3단계 — 좌·우 뒷바퀴 속도#

좌·우 뒷바퀴는 ICR에서 각각 R − D/2, R + D/2 떨어져 있고 같은 각속도 ω로 돕니다.

text
v_L = ω (R − D/2) = v − ω·D/2 = v · (1 − D·tan δ / (2L))
v_R = ω (R + D/2) = v + ω·D/2 = v · (1 + D·tan δ / (2L))

원본 교재의 식(V_L = V(1 − D·tanθ/2H))과 원본 코드(vl = linear_speed - angular_speed*self.track_width/2)가 같은 식을 서로 다른 변수로 쓴 것입니다. 뒷바퀴 속도 차이는 전자식 차동장치(electronic differential) 역할을 합니다. 두 뒷바퀴를 같은 속도로 돌리면 코너에서 한쪽이 끌리며 타이어가 미끄러집니다.

조향 한계: 29°와 최소 회전 반경#

원본은 조향각을 29° 로 제한합니다(서보·링키지의 기계적 한계). 이로부터

ω_max(v) = v · tan 29° / L = 3.823 · v   [rad/s]

원본 키보드 조종의 각속도

원본 teleop_key_control.py는 애커만일 때 ANG_VEL = LIN_VEL/(0.145/math.tan(0.5061))을 씁니다. 0.5061 rad = 29°이므로 0.2 m/s에서 ω = 0.765 rad/s, 즉 최소 회전 반경으로 도는 값을 정확히 계산해 둔 것입니다.

정지 상태에서는 회전할 수 없습니다. v → 0이면 δ = atan(Lω/v)가 ±90°로 발산하고, 실제로는 29°에 막히므로 ω = v·tan δ / L → 0입니다. 원본 코드도 |v| < 10⁻⁸이면 서보 값을 None으로 돌려주고 모든 모터를 0으로 둡니다.

원본 ackermann.py 해설#

python
class AckermannChassis:
    def __init__(self, wheelbase=0.145, track_width=0.133, wheel_diameter=0.067): ...

    def set_velocity(self, linear_speed, angular_speed, reset_servo=True):
        servo_angle = 1500
        if abs(linear_speed) >= 1e-8:
            if abs(angular_speed) >= 1e-8:
                theta = math.atan(self.wheelbase*angular_speed/linear_speed)
                steering_angle = theta
                if abs(steering_angle) > math.radians(29):
                    steering_angle = math.radians(29)          # ← 부호가 사라짐
                servo_angle = 1500 + 2000*math.degrees(-steering_angle)/180
            vr = linear_speed + angular_speed*self.track_width/2
            vl = linear_speed - angular_speed*self.track_width/2
            v_s = [self.speed_covert(v) for v in [0, vl, 0, -vr]]
            return servo_angle, MotorsState(...)
        else:
            return None, MotorsState(모두 0)
항목해석
치수휠베이스 L = 0.145 m, 윤거 D = 0.133 m, 바퀴 지름 0.067 m (둘레 0.2105 m)
서보 펄스중앙 1500 µs, 180°당 2000 µs(1°당 11.1 µs). -steering_angle이므로 좌회전(δ > 0) → 1500보다 작은 펄스
펄스 범위±29° → 1178 ~ 1822 µs. 노드는 int()로 잘라 /ros_robot_controller/pwm_servo/set_state에 id 3으로 발행
모터 목록[0, vl, 0, -vr] → 모터 2번 = 왼쪽 뒤, 모터 4번 = 오른쪽 뒤. 메카넘과 달리 오른쪽의 부호를 뒤집습니다(배선·장착 방향이 다름)
정지v = 0이면 서보 None(서보 명령 없음), 모든 모터 0
원본 코드의 세 가지 함정
  1. 조향 제한에서 부호 손실: |δ| > 29°이면 steering_angle = math.radians(29)로 항상 +29° 가 됩니다. 오른쪽으로 크게 꺾는 요청(예: v = 0.1, ω = −0.5 → δ = −35.9°)이 왼쪽 29° 서보 명령이 되고, 뒷바퀴 속도는 오른쪽 회전용으로 계산되어 서로 싸웁니다. math.copysign(math.radians(29), theta)로 고쳐야 합니다. /cmd_vel을 쓰면 ω ≤ 0.5로 잘리므로 v < 0.13 m/s일 때 이 경우가 생깁니다.
  2. ω = 0일 때 서보를 되돌리지 않음: odom_publisher_node.py의 cmd_vel_callback은 angular.z == 0이면 모터 명령만 보내고 서보 명령은 보내지 않습니다. 회전하다가 ω = 0을 보내면 바퀴가 꺾인 채로 계속 돕니다. 원본 라이다 앱(lidar_controller.py)은 이 때문에 직진할 때 서보 1500을 따로 발행합니다(M06). 여러분의 노드도 직진 전환 시 아주 작은 ω(예: 1e-6)를 보내거나 서보를 직접 가운데로 두세요.
  3. 오도메트리는 요청 ω를 적분: 조향이 29°에서 잘려도 odom_publisher는 요청한 ω를 적분합니다. 한계를 넘는 명령을 보내면 odom의 yaw가 실제보다 빨리 돕니다(M03).

교재 Lesson 6의 주의 문구에 나오는 D = 0.213, 36° 같은 값은 소스의 주석으로 남아 있는 다른(더 큰) 섀시의 값입니다. MentorPi에서 실제로 쓰이는 값은 위 표의 0.145 m, 29°입니다.

실습 (시뮬레이션)#

1. 원본 set_velocity를 Python으로 옮겨 보기#

원본 로직을 그대로 옮기고, 부호 손실 문제를 고친 버전과 비교합니다.

python브라우저 실행Playground ↗
import math

L, T, D = 0.145, 0.133, 0.067          # wheelbase, track_width, wheel_diameter
MAX = math.radians(29)

def ackermann(v, w, fix_sign=False):
    """원본 AckermannChassis.set_velocity() → (서보 펄스, 모터 rps 4개)."""
    if abs(v) < 1e-8:
        return None, [0.0] * 4
    pulse = 1500
    if abs(w) >= 1e-8:
        delta = math.atan(L * w / v)
        if abs(delta) > MAX:
            delta = math.copysign(MAX, delta) if fix_sign else MAX
        pulse = 1500 + 2000 * math.degrees(-delta) / 180
    vr = v + w * T / 2
    vl = v - w * T / 2
    rps = [x / (math.pi * D) for x in (0, vl, 0, -vr)]
    return pulse, rps

print("최소 회전반경 R_min = %.3f m" % (L / math.tan(MAX)))
for v, w in [(0.2, 0.0), (0.2, 0.5), (0.2, -0.5), (0.1, 0.5), (0.1, -0.5), (0.0, 0.5)]:
    p, rps = ackermann(v, w)
    d = math.degrees(math.atan(L * w / v)) if v else float("nan")
    ps = "None" if p is None else "%.0f" % p
    print("v=%+.1f w=%+.1f  delta_req=%+6.1f°  pulse=%s  rps=%s" % (
        v, w, d, ps, [round(x, 3) + 0.0 for x in rps]))
p, _ = ackermann(0.1, -0.5, fix_sign=True)
print("부호 보존 수정 시 v=+0.1 w=-0.5 → pulse=%.0f" % p)

2. 원 주행과 회전 반경 측정#

가상 애커만 로봇에 v = 0.2 m/s, ω = 0.5 rad/s를 한 바퀴(2π/0.5 ≈ 12.6 s) 동안 보내고, 실제 궤적에 원을 맞춰(최소제곱 원 맞춤) 반경을 구합니다. 이론값은 R = v/ω = 0.400 m, 시작점 (0, −0.4)에서 출발하면 원의 중심은 (0, 0)입니다.

python브라우저 실행Playground ↗
import math
import numpy as np
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
import mentorpi_sim as sim                                          # 시뮬 전용
sim.setup(chassis="ackermann", world="empty", duration=12.6,
          start=(0.0, -0.4, 0.0), noise=False)                      # 시뮬 전용

V, W, L = 0.2, 0.5, 0.145

class Circle(Node):
    def __init__(self):
        super().__init__("ackermann_circle")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.xs, self.ys = [], []
        self.create_timer(0.05, self.tick)

    def on_gt(self, msg):
        self.xs.append(msg.x)
        self.ys.append(msg.y)

    def tick(self):
        cmd = Twist()
        cmd.linear.x, cmd.angular.z = V, W
        self.pub.publish(cmd)

rclpy.init()
node = Circle()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    xs, ys = np.array(node.xs), np.array(node.ys)
    node.destroy_node()
    rclpy.shutdown()

# 원 맞춤: x² + y² + D·x + E·y + F = 0 을 최소제곱으로
A = np.column_stack([xs, ys, np.ones_like(xs)])
b = -(xs ** 2 + ys ** 2)
Dc, Ec, F = np.linalg.lstsq(A, b, rcond=None)[0]
cx, cy = -Dc / 2, -Ec / 2
r = math.sqrt(cx ** 2 + cy ** 2 - F)
print("요청 δ = %.1f°, 이론 R = %.3f m" % (math.degrees(math.atan(L * W / V)), V / W))
print("측정 중심 = (%+.3f, %+.3f), 반경 = %.3f m" % (cx, cy, r))
print("끝점과 시작점 거리 = %.3f m" % math.hypot(xs[-1] - xs[0], ys[-1] - ys[0]))
sim.plot(list(xs), list(ys), "애커만 원 주행 (v=0.2, w=0.5)")   # 시뮬 전용

3. 조향 한계와 정지 회전 시험#

ω는 그대로 0.5인데 v를 0.1로 낮추면 요청 δ = 35.9°가 되어 29°에 걸립니다. 세 구간의 실제 각속도를 /imu로 측정합니다.

python브라우저 실행Playground ↗
import math
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
from sensor_msgs.msg import Imu
import mentorpi_sim as sim                                          # 시뮬 전용
sim.setup(chassis="ackermann", world="empty", duration=11.5,
          start=(0.0, 0.0, 0.0), noise=False)                       # 시뮬 전용

L = 0.145
PHASES = [(0.0, 5.0, 0.1, 0.5), (5.0, 8.0, 0.1, -0.5), (8.0, 11.0, 0.0, 0.5)]

class SteerLimit(Node):
    def __init__(self):
        super().__init__("steer_limit")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Imu, "/imu", self.on_imu, 10)
        self.t0 = time.time()
        self.samples = {i: [] for i in range(len(PHASES))}
        self.create_timer(0.05, self.tick)

    def phase(self):
        t = time.time() - self.t0
        for i, (a, b, v, w) in enumerate(PHASES):
            if a <= t < b:
                return i, t - a
        return None, 0.0

    def on_imu(self, msg):
        i, since = self.phase()
        if i is not None and since > 1.0:          # 과도 구간 1초는 버림
            self.samples[i].append(msg.angular_velocity.z)

    def tick(self):
        i, _ = self.phase()
        cmd = Twist()
        if i is not None:
            cmd.linear.x, cmd.angular.z = PHASES[i][2], PHASES[i][3]
        self.pub.publish(cmd)

rclpy.init()
node = SteerLimit()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    for i, (a, b, v, w) in enumerate(PHASES):
        s = node.samples[i]
        wm = sum(s) / len(s) if s else float("nan")
        req = math.degrees(math.atan(L * w / v)) if v else float("nan")
        print("v=%.1f w=%+.1f  δ요청=%+6.1f°  측정 ω=%+.3f rad/s  R=%s" % (
            v, w, req, wm, "%.3f m" % (v / wm) if abs(wm) > 1e-3 else "—"))
    node.destroy_node()
    rclpy.shutdown()

자주 나는 오류와 해결#

증상원인해결
ω만 보냈는데 전혀 움직이지 않음v = 0이면 서보 None, 모터 0애커만은 반드시 v ≠ 0과 함께 ω를 보냄
직진 명령인데 계속 원을 그림ω = 0일 때 서보 명령이 나가지 않아 조향이 남음직진 전환 시 ω = 1e-6 같은 작은 값을 보내거나 서보 1500을 직접 발행
오른쪽으로 급회전하려 했는데 왼쪽으로 꺾임조향 제한 코드의 부호 손실(+29° 고정)명령을 |ω| ≤ v·tan 29°/L로 미리 제한하거나 원본을 copysign으로 수정
같은 ω인데 원이 예상보다 큼29° 제한에 걸림(저속) 또는 바닥 미끄럼R = max(v/ω, 0.262)로 계산해 보고, 속도를 올려 δ를 줄임
직진이 한쪽으로 휨서보 중립 편차서보 편차 조정 후 다시 시험
odom의 yaw가 실제보다 많이 돔odom은 제한 전 요청 ω를 적분한계를 넘는 명령을 보내지 않음, EKF의 IMU 융합 사용(M03)
