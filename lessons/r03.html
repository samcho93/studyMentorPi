R03토픽: 발행과 구독

Publisher/Subscriber, 메시지 타입(std_msgs·geometry_msgs), QoS 기초 — /cmd_vel을 발행해 시뮬레이터 로봇을 움직입니다.

선수 챕터: R02
ROS 2 Playground2D 시뮬레이터

학습 목표#

  • 토픽 통신의 성질(단방향·비동기·다대다·익명)을 설명하고, 연결 조건이 토픽 이름 + 메시지 타입 + 호환되는 QoS라는 것을 말할 수 있습니다.
  • 원본 topic_demo의 발행자(publisher)·구독자(subscriber) 코드를 한 줄씩 해석하고 직접 작성합니다.
  • geometry_msgs/Twist, nav_msgs/Odometry, sensor_msgs/LaserScan의 주요 필드를 읽고 씁니다.
  • MentorPi의 속도 명령 경로(/cmd_vel → odom_publisher → 모터)와 두 입력(/cmd_vel, /controller/cmd_vel)의 차이를 설명합니다.
  • /cmd_vel을 발행해 가상 MentorPi를 움직이고 /odom, /scan을 구독해 결과를 확인합니다.

토픽 통신 모델#

토픽(topic)은 ROS 2에서 가장 많이 쓰는 통신 방식입니다. 발행자가 이름 붙은 토픽에 메시지를 내보내면, 그 토픽을 구독한 모든 노드가 복사본을 받습니다.

성질뜻결과
단방향발행자 → 구독자로만 흐름받았다는 응답이 없음. 응답이 필요하면 서비스(R04)
비동기발행자는 보내고 바로 다음 일을 함센서 스트림처럼 계속 흐르는 데이터에 적합
다대다한 토픽에 발행자·구독자가 여럿일 수 있음앱·조이스틱·내비게이션이 모두 /controller/cmd_vel에 발행 가능
익명발행자는 누가 받는지 모름노드를 교체·추가해도 다른 노드를 고칠 필요 없음

연결되려면 세 가지가 맞아야 합니다.

  1. 토픽 이름: /cmd_vel과 cmd_vel(네임스페이스 없으면 같음)은 같고, /cmd_vel과 /cmdvel은 다릅니다.
  2. 메시지 타입: 이름이 같아도 타입이 다르면(Twist vs TwistStamped) 연결되지 않고 경고가 납니다.
  3. QoS 호환: 발행자가 BEST_EFFORT, 구독자가 RELIABLE이면 연결되지 않습니다(아래 QoS 절, R05).

메시지 타입#

메시지는 .msg 파일로 정의된 필드 묶음입니다. 기본형(bool, int32, float64, string …), 다른 메시지, 배열을 필드로 가질 수 있습니다.

bash
ros2 interface show geometry_msgs/msg/Twist
# Vector3  linear
#     float64 x
#     float64 y
#     float64 z
# Vector3  angular
#     float64 x
#     float64 y
#     float64 z

MentorPi에서 자주 쓰는 타입과 필드입니다(좌표는 REP-103: x 전방, y 좌측, z 위, 반시계 회전이 +).

타입토픽주요 필드단위
std_msgs/String예제 /topicdata문자열
geometry_msgs/Twist/cmd_vel, /controller/cmd_vellinear.x(전진), linear.y(좌측, 메카넘만), angular.z(반시계 회전)m/s, rad/s
nav_msgs/Odometry/odomheader.frame_id(odom), child_frame_id(base_footprint), pose.pose.position, pose.pose.orientation(쿼터니언), twist.twistm, rad/s
sensor_msgs/LaserScan/scan(원본 /scan_raw)angle_min, angle_max, angle_increment, range_min, range_max, ranges[]rad, m
sensor_msgs/Imu/imuorientation, angular_velocity, linear_accelerationrad/s, m/s²

쿼터니언 (x, y, z, w)를 평면 방향각(yaw)으로 바꾸는 식은 평면 운동만 할 때 ψ = atan2(2(wz + xy), 1 − 2(y² + z²))입니다. 코드에서는 tf_transformations.euler_from_quaternion([x, y, z, w])[2]로 얻습니다.

발행자와 구독자 코드 해석#

원본 topic_demo/topic_pub.py의 뼈대입니다(주석은 한국어로 다시 달았습니다).

python
class MinimalPublisher(Node):
    def __init__(self):
        super().__init__('minimal_publisher')
        self.publisher_ = self.create_publisher(String, 'topic', 10)   # (타입, 이름, QoS 깊이)
        self.timer = self.create_timer(0.5, self.timer_callback)      # 2 Hz
        self.i = 0

    def timer_callback(self):
        msg = String()
        msg.data = 'Hello World: %d' % self.i
        self.publisher_.publish(msg)
        self.i += 1
  • create_publisher(String, 'topic', 10)의 세 번째 인자 10은 QoS 깊이(depth) 입니다. 정수만 주면 RELIABLE + VOLATILE + KEEP_LAST(10)의 기본 프로파일이 됩니다.
  • 발행은 타이머 콜백 안에서 합니다. 주기적으로 보내는 데이터는 "타이머 → 메시지 채우기 → publish"가 정석입니다.
  • 구독자 쪽은 create_subscription(String, 'topic', self.listener_callback, 10)으로 만들고, 콜백의 인자로 메시지가 들어옵니다. 구독 객체를 self.subscription처럼 변수에 보관해야 가비지 컬렉션으로 사라지지 않습니다.

QoS 기초#

QoS(Quality of Service)는 "이 토픽을 어떤 품질로 전달할지"에 대한 발행자·구독자 사이의 약속입니다. 처음에는 세 가지만 기억합니다.

정책선택지언제
History / DepthKEEP_LAST(n개 보관), KEEP_ALL처리가 밀릴 때 몇 개까지 쌓아 둘지. 제어 명령은 작게(1~10)
ReliabilityRELIABLE(재전송), BEST_EFFORT(버려도 됨)명령·상태는 RELIABLE, 고속 센서는 BEST_EFFORT
DurabilityVOLATILE, TRANSIENT_LOCAL(나중에 온 구독자에게 마지막 값 전달)지도(/map), 로봇 모델(/robot_description)

라이다·카메라처럼 빠른 센서 토픽은 드라이버가 BEST_EFFORT로 내는 경우가 많습니다. 이때 구독자가 기본값(RELIABLE)이면 아무것도 받지 못합니다. 센서를 구독할 때는 qos_profile_sensor_data(BEST_EFFORT, depth 5)를 쓰면 안전합니다. 호환 규칙은 R05에서 자세히 다룹니다.

MentorPi의 속도 명령 경로#

원본 controller/odom_publisher_node.py는 속도 토픽을 두 개 구독합니다.

토픽콜백처리누가 쓰나
/cmd_velapp_cmd_vel_callback선속도 x·y를 각각 ±0.2 m/s, 각속도를 ±0.5 rad/s 범위로 자른 뒤 아래로 전달사용자 실습, 앱
/controller/cmd_velcmd_vel_callback제한 없이 메카넘/애커만 기구학 → 바퀴 속도조이스틱, 키보드 원격, 라이다 앱, Nav2

cmd_vel_callback은 받은 Twist로 네 바퀴 속도를 계산해 ros_robot_controller/set_motor로 보내고, 같은 속도를 적분해 오도메트리를 냅니다(M01·M03). 학생 코드는 **안전을 위해 /cmd_vel을 쓰는 것이 기본**입니다. Playground의 가상 MentorPi도 똑같이 동작합니다.

속도 명령은 "계속" 보내야 하는 값

Twist 한 번은 "지금부터 이 속도로"라는 뜻입니다. 노드가 정지 명령 없이 죽으면 마지막 속도가 남을 수 있습니다. 제어 노드는 주기적으로(10~20 Hz) 발행하고, 종료할 때 반드시 0 속도 Twist를 발행합니다.

① 원본 topic_demo: 두 노드로 발행·구독#

실물에서는 두 터미널에서 topic_pub, topic_sub를 따로 실행합니다. Playground에서는 한 스크립트에 두 노드를 만들고 spin_once를 번갈아 돌립니다.

python브라우저 실행
import time
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
import mentorpi_sim as sim                  # 시뮬 전용
sim.setup(world="empty", duration=5.0)     # 시뮬 전용


class MinimalPublisher(Node):
    def __init__(self):
        super().__init__('minimal_publisher')
        self.publisher_ = self.create_publisher(String, 'topic', 10)
        self.timer = self.create_timer(0.5, self.timer_callback)
        self.i = 0

    def timer_callback(self):
        msg = String()
        msg.data = 'Hello World: %d' % self.i
        self.publisher_.publish(msg)
        self.i += 1


class MinimalSubscriber(Node):
    def __init__(self):
        super().__init__('minimal_subscriber')
        self.subscription = self.create_subscription(String, 'topic', self.listener_callback, 10)

    def listener_callback(self, msg):
        self.get_logger().info('I heard: "%s"' % msg.data)


rclpy.init()
pub, sub = MinimalPublisher(), MinimalSubscriber()
print('토픽 이름:', pub.publisher_.topic_name)
t0 = time.time()
while rclpy.ok() and time.time() - t0 < 2.6:
    rclpy.spin_once(pub, timeout_sec=0.05)
    rclpy.spin_once(sub, timeout_sec=0.05)
pub.destroy_node()
sub.destroy_node()
rclpy.shutdown()

② /cmd_vel로 로봇 움직이고 /odom 읽기#

3초 전진(0.15 m/s) → 3초 제자리 회전(0.5 rad/s) → 정지하는 시간 기반 상태 기계입니다. 10 Hz 타이머가 속도를 계속 발행하고, 0.5초마다 오도메트리를 출력합니다.

python브라우저 실행
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
from nav_msgs.msg import Odometry
from tf_transformations import euler_from_quaternion
import mentorpi_sim as sim                                                   # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=8.0, start=(0.0, 0.0, 0.0))   # 시뮬 전용


class DriveAndWatch(Node):
    def __init__(self):
        super().__init__('drive_and_watch')
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_subscription(Odometry, '/odom', self.on_odom, 10)
        self.pose = (0.0, 0.0, 0.0)
        self.t = 0.0
        self.create_timer(0.1, self.on_timer)

    def on_odom(self, msg):
        p, q = msg.pose.pose.position, msg.pose.pose.orientation
        yaw = euler_from_quaternion([q.x, q.y, q.z, q.w])[2]
        self.pose = (p.x, p.y, yaw)

    def on_timer(self):
        self.t += 0.1
        cmd = Twist()
        if self.t <= 3.0:
            cmd.linear.x = 0.15          # 전진
        elif self.t <= 6.0:
            cmd.angular.z = 0.5          # 반시계 회전
        self.pub.publish(cmd)            # 6 s 이후는 0 속도(정지)
        if abs(self.t / 0.5 - round(self.t / 0.5)) < 1e-6:
            x, y, yaw = self.pose
            print('t=%.1f  x=%.3f  y=%.3f  yaw=%5.1f deg' % (self.t, x, y, yaw * 57.2958))


rclpy.init()
node = DriveAndWatch()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())            # 종료 시 정지 명령
    node.destroy_node()
    rclpy.shutdown()

이론값은 전진 0.15 × 3 = 0.45 m, 회전 0.5 × 3 = 1.5 rad ≈ 86°입니다. 가상 로봇도 가속·감속 시간이 있어서 전진은 조금 모자라고, 회전은 명령이 바뀐 뒤 관성으로 조금 더 돕니다(명령은 0.1초 주기로만 바뀌므로 경계에서 한 주기 차이도 생깁니다). cmd.linear.x = 0.3으로 바꿔 보면 /cmd_vel의 제한 때문에 0.2 m/s로 잘리는 것도 확인할 수 있습니다.

③ /scan 구독: 앞이 막히면 멈추기#

qos_profile_sensor_data로 라이다를 구독하고, 전방 ±15° 안의 최소 거리가 0.4 m보다 작아지면 멈춥니다. 앞 1.2 m에 상자를 놓았습니다.

python브라우저 실행
import math
import rclpy
from rclpy.node import Node
from rclpy.qos import qos_profile_sensor_data
from geometry_msgs.msg import Twist
from sensor_msgs.msg import LaserScan
import mentorpi_sim as sim                                                  # 시뮬 전용
sim.setup(world="empty", duration=10.0, start=(0.0, 0.0, 0.0), noise=False)   # 시뮬 전용
sim.add_box(1.3, 0.0, 0.2, 0.8)                                             # 시뮬 전용: 전방 장애물


class StopBeforeWall(Node):
    def __init__(self):
        super().__init__('stop_before_wall')
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_subscription(LaserScan, '/scan', self.on_scan, qos_profile_sensor_data)
        self.stopped = False

    def front_min(self, scan, half_deg=15.0):
        best = float('inf')
        for i, r in enumerate(scan.ranges):
            a = scan.angle_min + i * scan.angle_increment
            if abs(a) <= math.radians(half_deg) and scan.range_min < r < scan.range_max:
                best = min(best, r)
        return best

    def on_scan(self, scan):
        d = self.front_min(scan)
        cmd = Twist()
        if d > 0.4 and not self.stopped:
            cmd.linear.x = 0.15
        elif not self.stopped:
            self.stopped = True
            self.get_logger().info('정지! 전방 최소 거리 %.2f m' % d)
        self.pub.publish(cmd)


rclpy.init()
node = StopBeforeWall()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()

/scan이 10 Hz이므로 명령도 0.1초마다 갱신됩니다. 그사이 로봇은 최대 1.5 cm를 더 가므로, 멈춘 거리는 0.4 m보다 조금 짧습니다. 이 "센서 콜백에서 바로 명령 발행" 구조가 M06 라이다 회피의 뼈대입니다.

과제#

기본 과제
  1. ②를 고쳐 한 변 0.5 m 정사각형을 주행합니다(전진 → 90° 회전 × 4). 끝난 뒤 출발점과의 오차(거리, 각도)를 출력합니다.
  2. ③의 정지 거리를 파라미터처럼 쉽게 바꿀 수 있도록 클래스 속성으로 빼고, 0.3/0.5/0.7 m에서 실제 멈춘 위치(/odom)를 표로 정리합니다.
심화 과제
  1. ③을 확장해 앞이 막히면 멈추는 대신 좌·우 중 넓은 쪽으로 회전한 뒤 다시 전진하는 노드를 만듭니다(좌측 60°~90°, 우측 −90°~−60° 평균 거리 비교). M06 라이다 회피와 비교합니다.
  2. std_msgs/String 대신 geometry_msgs/Pose2D로 "현재 자세"를 1 Hz로 발행하는 노드와, 그것을 받아 누적 이동 거리를 계산하는 노드를 만들어 ①처럼 한 스크립트에서 돌려 봅니다.
