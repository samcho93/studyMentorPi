A06손 추종·자세 제어·포즈 감지

손 위치 추종, 손가락 개수/자세로 동작 명령, 인체 포즈 랜드마크로 쓰러짐 감지 등 상호작용 응용.

선수 챕터: A05

학습 목표#

  • 손 랜드마크 네 점으로 손 중심을 구하고, 영상 중심과의 오차를 PID로 줄여 팬·틸트 서보가 손을 따라가게 하는 원리를 설명합니다.
  • MediaPipe Pose의 33개 랜드마크 구조와 거리 비율로 팔·다리를 들었는지 판정하는 방법을 계산으로 확인합니다.
  • 프레임 투표(4번 중 3번, 3번 중 2번)가 오인식을 걸러내는 방식을 설명하고 시뮬레이션합니다.
  • 랜드마크 평균 높이로 쓰러짐을 감지하는 규칙의 장단점을 말하고 개선안을 제시합니다.
  • hand_track_node, body_control, fall_down_detect launch를 실행하고 안전하게 시험합니다.

전체 그림: 인식 노드와 제어 노드#

A05에서는 인식 결과를 화면에 그리기만 했습니다. 이 장의 세 예제는 인식 결과를 로봇 동작으로 바꿉니다.

손 추종은 인식 노드(hand_detect)와 제어 노드(hand_track)를 나눈 2-노드 구조입니다. 인식 노드는 /hand_detect/center(interfaces/msg/Point2D: x, y, width, height)만 발행하고, 제어 노드는 그 점만 보고 서보를 움직입니다. 이렇게 나누면 인식기를 다른 모델(예: YOLO 손 검출)로 바꿔도 제어 노드는 그대로 둘 수 있습니다. 반면 자세 제어·포즈 감지는 한 노드 안에서 인식과 제어를 모두 합니다.

손 추종#

손 중심 계산#

hand_detect_node.py는 손끝이 아니라 손바닥 중심을 추종점으로 씁니다. 손가락을 접었다 폈다 해도 흔들리지 않는 점이 필요하기 때문입니다.

text
c1 = (WRIST + MIDDLE_FINGER_MCP) / 2       # 손목(0)과 중지 뿌리(9)의 중점 — 세로축
c2 = (THUMB_MCP + PINKY_MCP) / 2           # 엄지 뿌리(2)와 새끼 뿌리(17)의 중점 — 가로축
center = (c1 + c2) / 2

네 점 모두 손바닥에 붙은 관절이라 손가락 동작과 거의 무관합니다. 두 중점을 다시 평균하므로 한 점이 튀어도 영향이 1/4로 줄어듭니다. 손이 없으면 width = 0인 빈 메시지를 보내고, 제어 노드는 msg.width != 0으로 손 유무를 판단합니다.

하드웨어 조건

원본 교재는 이 예제가 2D 팬·틸트 단안 카메라 버전 전용이라고 밝힙니다. 깊이 카메라 고정형 MentorPi에는 서보가 없으므로 코드는 돌지만 움직이는 부분이 없습니다. 또 결과 영상 표시가 프로그램을 느리게 할 수 있어, 영상은 rqt_image_view로 따로 보는 것을 권합니다.

PID로 서보 펄스 갱신#

hand_track_node.py의 핵심은 50 Hz 루프 안의 몇 줄입니다.

python
self.pid_y.SetPoint = self.center.width / 2           # 목표: 영상 가로 중앙
self.pid_y.update(self.center.width - self.center.x)  # 좌우 반전 좌표로 입력
self.y_dis += self.pid_y.output                       # 팬 펄스 누적
self.y_dis = min(1900, max(800, self.y_dis))

self.pid_z.SetPoint = self.center.height / 2          # 목표: 영상 세로 중앙
self.pid_z.update(self.center.y)
self.z_dis -= self.pid_z.output                       # 틸트 펄스 누적
self.pwm_controller([self.z_dis, self.y_dis])         # 서보1 = 틸트, 서보2 = 팬

짚어 볼 점:

  • **출력을 누적합니다(+=). PID 출력이 서보 위치 자체가 아니라 위치의 증분**입니다. 오차가 0이 되면 증분도 0이 되어 서보가 그 자리에 머뭅니다. 즉 이 루프는 적분기를 하나 품고 있어, P 제어만으로도 정상상태 오차 없이 손을 가운데로 가져옵니다(속도형 PID).
  • width - x로 넣는 이유는 인식 노드가 영상을 좌우 반전했기 때문입니다. 반전된 x를 다시 뒤집어 실제 카메라 기준 오차로 되돌립니다.
  • 계수 PID(0.1, 0.0002, 0.00001)은 P가 거의 전부입니다. 오차 100 px면 한 주기에 펄스 10씩 움직입니다.
  • 펄스는 800~1900으로 제한합니다. PWM 서보 펄스 500~2500 µs가 약 0~180°이므로, 이 범위는 기구가 부딪히지 않는 안전 구간입니다.

실습: 팬 서보 추종 시뮬레이션#

서보 펄스 1이 약 0.09°(=180°/2000)이고, 초점거리 500 px 카메라에서 0.09°는 약 0.785 px입니다. 손이 펄스 1700 방향에 있을 때 팬 서보가 1500에서 출발해 따라가는 과정을 원본 계수로 계산합니다. sdk/pid.py는 실제 시각(time.time())으로 dt를 재지만, 결과를 재현할 수 있도록 dt를 0.02 s로 고정했습니다.

Playground 열기

python브라우저 실행Playground ↗
import math

class PID:                                   # sdk/pid.py 구조, dt만 고정
    def __init__(self, kp, ki, kd, dt):
        self.kp, self.ki, self.kd, self.dt = kp, ki, kd, dt
        self.SetPoint, self.iterm, self.last_e, self.output = 0.0, 0.0, 0.0, 0.0
    def update(self, feedback):
        e = self.SetPoint - feedback
        self.iterm = max(-20.0, min(20.0, self.iterm + e * self.dt))   # windup guard 20
        d = (e - self.last_e) / self.dt
        self.last_e = e
        self.output = self.kp * e + self.ki * self.iterm + self.kd * d

W, FX = 640, 500.0                           # 영상 폭, 초점거리[px](예시값)
PX_PER_PULSE = FX * math.radians(180 / 2000) # 펄스 1 ≈ 0.09° → 0.785 px
hand_pulse = 1700                            # 손이 있는 방향(펄스로 환산)
pan = 1500                                   # init_action() 중립
pid_y = PID(0.1, 0.0002, 0.00001, 0.02)      # hand_track_node.py 계수, 50 Hz

for step in range(61):
    x = W / 2 + PX_PER_PULSE * (hand_pulse - pan)   # 손 중심의 영상 x
    if step % 10 == 0:
        print("step %2d  pan=%7.1f  x=%6.1f px  오차=%6.1f px" % (step, pan, x, x - W / 2))
    pid_y.SetPoint = W / 2
    pid_y.update(W - x)                      # 원본과 같이 좌우 반전된 좌표로 입력
    pan = min(1900, max(800, pan + pid_y.output))

오차가 10스텝(0.2 s)마다 약 0.44배로 줄어듭니다. 한 스텝의 루프 이득이 K_p × 0.785 ≈ 0.0785이므로 오차는 매 스텝 (1 − 0.0785)배, 10스텝이면 0.9215^{10} ≈ 0.44배입니다. 이득을 키우면 빨라지지만, 이득이 2를 넘으면(한 스텝에 오차보다 더 많이 돌면) 발산합니다. 실제로는 카메라 지연(수십 ms) 때문에 그보다 훨씬 작은 이득에서 흔들림이 시작합니다.

MediaPipe Pose와 자세 제어#

33개 포즈 랜드마크#

MediaPipe Pose(BlazePose)도 Hands와 같은 2단계 구조입니다. 사람 검출기가 얼굴을 기준으로 몸 영역과 회전을 잡고, 랜드마크 모델이 33개 점을 회귀합니다. 각 점에는 x, y, z와 함께 visibility(가려지지 않았을 확률)가 붙습니다.

번호부위번호부위
0~10얼굴(코·눈·귀·입)23, 24왼·오른 엉덩이(HIP)
11, 12왼·오른 어깨(SHOULDER)25, 26왼·오른 무릎(KNEE)
13, 14왼·오른 팔꿈치(ELBOW)27, 28왼·오른 발목(ANKLE)
15, 16왼·오른 손목(WRIST)29~32발뒤꿈치·발끝
17~22손가락 끝(새끼·검지·엄지)

왼쪽(LEFT)은 사람 기준 왼쪽입니다. 사람이 로봇을 마주 보면 사람의 왼팔은 로봇 카메라 영상의 오른쪽에 찍힙니다. 원본 교재가 "로봇 입장에서 왼팔을 들면 오른쪽으로 이동"이라고 설명하는 이유가 이것입니다.

거리 비율로 팔·다리 들기 판정#

body_control.py의 joint_distance()는 네 개의 제곱 거리 비율을 계산합니다.

항목분자분모들었다고 보는 조건
왼팔|HIP − SHOULDER|²|HIP − WRIST|²비율 < 1
오른팔(오른쪽 같은 식)비율 < 1
왼다리|HIP − ANKLE|²|ANKLE − KNEE|²0 < 비율 < 2
오른다리(오른쪽 같은 식)0 < 비율 < 2

팔을 내리면 손목이 엉덩이 옆에 있어 분모가 작고 비율이 큽니다. 팔을 머리 위로 들면 손목이 엉덩이에서 몸통 길이보다 멀어져 비율이 1 아래로 떨어집니다. 다리는 무릎을 들어 올리면 엉덩이–발목 거리가 줄고(분자↓) 비율이 2 아래가 됩니다.

절대 거리 대신 비율을 쓰는 이유: 사람이 카메라에서 1 m에 있든 3 m에 있든 모든 길이가 같은 배율로 줄어들므로 비율은 그대로입니다. 픽셀 문턱값을 쓰면 거리마다 값을 다시 맞춰야 합니다. 제곱 거리를 쓰는 것은 sqrt 계산을 아끼기 위해서이며, 문턱값 1은 제곱해도 1이라 의미가 같습니다(다리 문턱 2는 실제 거리 비율로 √2 ≈ 1.41).

4프레임 투표와 동작#

원본은 4프레임 동안 판정 결과를 모아 3번 이상(> 2) 감지된 동작만 실행합니다. 동작을 한 번 실행하면 stop_flag를 세우고, 그 자세를 풀어서(4번 중 1번 이하) 부저가 울려야 다음 명령을 받습니다. 한 번 든 팔로 명령이 연달아 나가지 않게 하는 에지(edge) 검출입니다.

판정메카넘(MentorPi_Mecanum)애커만(MentorPi_Acker)
왼팔linear.y = -0.3 1 s (로봇 기준 오른쪽 이동)모터 직접 구동으로 오른쪽 선회(약 12 s)
오른팔linear.y = +0.3 1 s (왼쪽 이동)모터 직접 구동으로 왼쪽 선회(약 11 s)
왼다리linear.x = +0.3 1 s (전진)같음
오른다리linear.x = -0.3 1 s (후진)같음

섀시 종류는 환경변수 MACHINE_TYPE으로 구분합니다. 애커만은 옆으로 갈 수 없으므로 좌우 명령을 회전 동작으로 바꿨습니다.

실습: 비율 계산과 투표#

사람이 서 있는 자세의 주요 랜드마크를 픽셀 좌표로 적고, 왼팔·왼다리를 든 경우를 만들어 원본과 같은 비율을 계산합니다.

python브라우저 실행Playground ↗
import numpy as np

# MediaPipe Pose 인덱스
L_SH, R_SH, L_WR, R_WR, L_HIP, R_HIP = 11, 12, 15, 16, 23, 24
L_KNEE, R_KNEE, L_ANK, R_ANK = 25, 26, 27, 28

def ratio(a, b, c, d):                        # |a-b|² / |c-d|², 소수 1자리
    d1, d2 = a - b, c - d
    return round(float(d1 @ d1) / float(d2 @ d2), 1)

def joint_distance(lm):                       # body_control.py 와 같은 4개 비율
    return [ratio(lm[L_HIP], lm[L_SH], lm[L_HIP], lm[L_WR]),
            ratio(lm[R_HIP], lm[R_SH], lm[R_HIP], lm[R_WR]),
            ratio(lm[L_HIP], lm[L_ANK], lm[L_ANK], lm[L_KNEE]),
            ratio(lm[R_HIP], lm[R_ANK], lm[R_ANK], lm[R_KNEE])]

def pose(left_arm_up=False, left_leg_up=False):
    lm = np.zeros((33, 2))
    lm[[L_SH, R_SH]] = (360, 150), (280, 150)
    lm[[L_HIP, R_HIP]] = (350, 270), (290, 270)
    lm[[L_WR, R_WR]] = (375, 280), (265, 280)
    lm[[L_KNEE, R_KNEE]] = (352, 350), (288, 350)
    lm[[L_ANK, R_ANK]] = (354, 430), (286, 430)
    if left_arm_up:
        lm[L_WR] = (380, 60)
    if left_leg_up:
        lm[L_KNEE], lm[L_ANK] = (365, 290), (362, 350)
    return lm

print("차렷     ", joint_distance(pose()))
print("왼팔 듦  ", joint_distance(pose(left_arm_up=True)))
print("왼다리 듦", joint_distance(pose(left_leg_up=True)))

# 4프레임 투표: 4번 중 3번 이상(>2) 감지돼야 명령
frames = [pose(True), pose(True), pose(), pose(True)]
votes = [0, 0, 0, 0]
for lm in frames:
    dl = joint_distance(lm)
    s = [dl[0] < 1, dl[1] < 1, 0 < dl[2] < 2, 0 < dl[3] < 2]
    votes = [v + int(x) for v, x in zip(votes, s)]
names = ["왼팔→오른쪽 이동", "오른팔→왼쪽 이동", "왼다리→전진", "오른다리→후진"]
print("투표", votes, "->", [n for n, v in zip(names, votes) if v > 2])
text
차렷      [20.0, 20.0, 4.0, 4.0]
왼팔 듦   [0.3, 20.0, 4.0, 4.0]
왼다리 듦 [20.0, 20.0, 1.8, 4.0]
투표 [3, 0, 0, 0] -> ['왼팔→오른쪽 이동']

차렷 자세의 팔 비율 20과 든 팔 0.3 사이, 다리 비율 4.0과 1.8 사이에 문턱값이 여유 있게 놓여 있습니다. 세 번째 프레임에서 팔이 내려간 것처럼 인식돼도(순간 오인식) 4번 중 3번이 들렸으므로 명령이 나갑니다.

원본 속도는 권장 한계보다 큽니다

원본은 /controller/cmd_vel(속도 제한 없는 입력)에 0.3 m/s를 1초 보냅니다. 이 강의의 실물 권장 한계는 선속도 0.2 m/s입니다. 실습 공간이 좁다면 소스를 백업한 뒤 0.3을 0.15로 낮춰 쓰세요. 이동 거리는 속도 × 1 s이므로 0.15 m가 됩니다.

쓰러짐 감지#

fall_down_detect.py의 규칙은 아주 단순합니다.

text
h = 33개 랜드마크 y 좌표의 평균
h > 영상 높이 − 120  (480 영상이면 360 px)  →  이번 프레임 '쓰러짐'
3프레임 중 2번 이상 쓰러짐  →  경보: 부저 연속(1000 Hz) + 앞뒤로 0.2 m/s 5회 왕복
경보 후 3프레임 중 1번 이하  →  해제 (부저 한 번, 1900 Hz)

서 있는 사람은 머리부터 발까지 세로로 퍼져 있어 평균 y가 영상 가운데쯤입니다. 바닥에 누우면 모든 점이 영상 아래쪽에 몰려 평균 y가 커집니다.

python브라우저 실행Playground ↗
H = 480                                      # 영상 높이
THRESH = H - 120                             # 평균 y가 360 px보다 아래면 '쓰러짐'

def height_cal(ys):                          # 33개 랜드마크 y의 평균
    return sum(ys) / len(ys)

standing = [150 + 9 * i for i in range(33)]  # 머리(150)~발(438) 세로로 분포
fallen = [380 + (i % 5) * 6 for i in range(33)]  # 바닥 근처에 가로로 누움
seq = [standing] * 3 + [fallen, standing, fallen] + [fallen] * 3

window, alarm = [], False
for i, ys in enumerate(seq):
    h = height_cal(ys)
    window.append(1 if h > THRESH else 0)
    if len(window) == 3:                     # 3프레임마다 판정
        c = sum(window)
        window = []
        if not alarm and c > 1:
            alarm = True
        elif alarm and c <= 1:
            alarm = False
        print("frame %d  평균 y=%.1f  투표=%d  경보=%s" % (i, h, c, alarm))
text
frame 2  평균 y=294.0  투표=0  경보=False
frame 5  평균 y=391.5  투표=2  경보=True
frame 8  평균 y=391.5  투표=3  경보=True

(원본은 경보 동작이 끝날 때까지 새 판정을 멈추지만, 이 시뮬레이션은 투표 규칙만 보이려고 그 부분을 뺐습니다.)

이 규칙의 한계와 개선#

한계예개선 아이디어
카메라 높이·각도에 의존로봇이 사람 가까이 있으면 서 있어도 하체만 보여 평균 y가 큼절대 높이 대신 몸통 기울기 atan2(어깨−엉덩이) 사용
앉기와 구분 못 함원본 교재도 "잠깐 앉아 보라"고 시험함머리 y의 하강 속도를 함께 봄(쓰러짐은 빠름)
가려진 점도 평균에 포함책상 뒤 하체가 엉뚱한 곳으로 추정visibility > 0.5인 점만 평균

자주 나는 오류와 해결#

증상원인해결
손 추종에서 서보가 반대로 도망감서보 장착 방향이 다르거나 영상 반전을 두 번 적용pid_y.update(width - x)를 update(x)로 바꾸거나 증분 부호(+=/-=)를 뒤집음
서보가 손을 따라가며 좌우로 떨림이득이 커서 카메라 지연과 함께 진동P를 0.1 → 0.05로 낮추고 D는 그대로
손 추종 화면이 멈춘 듯 느림결과 영상 표시(enable_display) 부하enable_display:=false로 실행하고 rqt_image_view 사용
자세 제어가 전혀 반응하지 않음몸 일부가 화면 밖. 발목이 안 보이면 다리 비율이 엉뚱함카메라에서 2~3 m 떨어져 전신이 들어오게 섬
로봇이 엉뚱한 방향으로 감사람 기준 왼쪽/로봇 기준 왼쪽 혼동표의 대응을 확인. 필요하면 linear.y 부호를 바꿈
애커만에서 팔 명령 후 11~12초 동안 돎원본이 모터 2·4번을 서로 다른 속도로 직접 구동(/ros_robot_controller/set_motor)하고 11·12 s 대기정상 동작. 줄이려면 move()의 time.sleep(11), time.sleep(12)를 조정
쓰러짐 경보가 서 있을 때 울림로봇이 너무 가까워 하체만 보임로봇과 거리 늘리기, 문턱 120 조정
