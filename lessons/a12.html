A12군집 제어: 마스터-슬레이브

여러 대의 MentorPi 네트워크·환경변수 구성, 네임스페이스와 대형 유지, 조이패드로 군집을 함께 조종합니다.

선수 챕터: A11

학습 목표#

  • 여러 대의 MentorPi가 한 ROS 2 네트워크에서 네임스페이스로 구분되어 동작하는 원리를 설명합니다.
  • 마스터 핫스팟·슬레이브 LAN 모드 Wi-Fi 설정과 HOST·MASTER 환경변수를 구성합니다.
  • multi_controller.launch.py와 joystick_control_multi.py가 조이패드 입력을 모든 로봇의 /robot_N/controller/cmd_vel로 나눠 보내는 흐름을 추적합니다.
  • 리더-팔로워 대형의 좌표 변환(오프셋 회전)과 P 제어 추종의 정상상태 오차를 계산합니다.
  • 두 대 이상의 로봇을 조이패드 하나로 함께 조종하고 시간 동기화의 필요성을 설명합니다.

군집 제어의 원리#

군집 제어(group control, multi-robot control)는 여러 로봇을 한 명령 체계로 움직이는 것입니다. MentorPi의 예제는 가장 단순한 중앙 집중형 마스터-슬레이브 구조입니다.

역할하는 일
마스터(host)Wi-Fi 핫스팟 제공, 조이패드 수신(joy_node), 명령 분배(joystick_control_multi.py), 자기 섀시 제어
슬레이브(slave)마스터 핫스팟에 접속, 자기 섀시 제어(multi_controller.launch.py)만 실행

ROS 2는 마스터 서버가 없는 DDS(Data Distribution Service) 기반이라, 같은 네트워크·같은 ROS_DOMAIN_ID에 있는 노드는 서로를 자동으로 발견합니다. 두 로봇이 모두 /controller/cmd_vel을 쓰면 한 명령에 두 대가 같이 반응하고, /odom도 뒤섞입니다. 그래서 각 로봇의 노드를 네임스페이스(namespace)로 감쌉니다.

text
robot_1 의 컨트롤러:  /robot_1/controller/cmd_vel  →  /robot_1/odom ...
robot_2 의 컨트롤러:  /robot_2/controller/cmd_vel  →  /robot_2/odom ...

컨트롤러 노드(odom_publisher_node.py)는 controller/cmd_vel처럼 **/로 시작하지 않는 상대 이름**으로 구독하므로, launch에서 네임스페이스만 씌우면 코드 수정 없이 토픽이 분리됩니다. R03에서 배운 이름 규칙이 여기서 쓰입니다.

네트워크 구성#

마스터: 핫스팟 모드#

  1. 마스터로 쓸 로봇에 VNC로 접속합니다.
  2. Wi-Fi 설정 파일을 엽니다.
bash
cd hiwonder-toolbox
sudo vim wifi_conf.py
  1. 핫스팟 비밀번호 줄을 원하는 값으로 바꾸고 :wq로 저장한 뒤 재부팅합니다. 원본 예시는 핫스팟 이름 HW-123, 비밀번호 hiwonder입니다.
bash
sudo reboot

슬레이브: LAN(클라이언트) 모드#

  1. 슬레이브 로봇의 wifi_conf.py를 열어 **네트워크 모드를 2(LAN 모드)**로 바꾸고, 접속할 Wi-Fi 이름·비밀번호를 마스터 핫스팟 값으로 적습니다.
  2. 저장 후 반드시 재부팅합니다(건너뛰면 적용 안 됨).

LAN 모드로 부팅하면 확장 보드의 LED2가 빠르게 깜빡이며 지정 네트워크를 찾습니다. 세 번 연속 찾지 못하면 자동으로 직접 연결(AP) 모드로 돌아가고 LED2가 천천히 깜빡입니다. 이때 wifi_conf.py 내용은 LAN 설정 그대로 남아 있어 다음 부팅에 다시 LAN 모드를 시도합니다. 따라서 마스터를 먼저 켜서 핫스팟이 뜬 뒤에 슬레이브를 켜야 합니다.

환경변수: HOST와 MASTER#

각 로봇의 ~/ros2_ws/.typerc에 두 환경변수를 적습니다(셸 시작 시 ~/.zshrc가 불러옴).

변수마스터슬레이브쓰이는 곳
HOSTrobot_1robot_2 (세 번째는 robot_3)이 로봇의 네임스페이스
MASTERrobot_1robot_1마스터가 누구인지
bash
~/.stop_ros.sh
vim /home/ubuntu/ros2_ws/.typerc      # HOST, MASTER 값 수정
source ~/.zshrc
echo $HOST $MASTER                     # 확인

슬레이브의 IP 주소는 휴대폰 앱으로 마스터 핫스팟에 접속해 로봇 아이콘을 길게 누르면 보이며, 그 주소로 VNC 접속해 설정합니다.

multi_controller.launch.py는 이 두 값을 이렇게 씁니다.

python
robot_name = EnvironmentVariable('HOST')          # 기본 인자 robot_name
master     = EnvironmentVariable('MASTER')        # 기본 인자 master
GroupAction([PushRosNamespace(robot_name),         # 이 안의 모든 노드에 /robot_N 접두
             IncludeLaunchDescription(controller.launch.py)])
IncludeLaunchDescription(joy_control.launch.py,
    condition=IfCondition(PythonExpression(['"', master, '" == "', robot_name, '"'])))

같은 launch 파일을 모든 로봇에서 실행하되, HOST == MASTER인 로봇에서만 조이패드 관련 launch가 추가로 켜집니다. 설정은 환경변수가, 역할 분기는 launch 조건식이 맡는 구조라 로봇 수가 늘어도 파일을 복사할 필요가 없습니다.

스틱 값 −1~1은 val_map()으로 속도 범위에 선형 대응되고, |값| < 0.1은 불감대로 0이 됩니다. 애커만이면 오른쪽 스틱을 조향각 ±28.98°(= 322/2000 × 180°, 서보 펄스 ±322)로 바꿔 서보 3번에 직접 보내고, 각속도는 ω = v / R, R = L / tan δ로 계산합니다.

기본 최대 속도가 권장 한계를 넘습니다

joystick_control_multi.py의 파라미터 기본값은 max_linear = 0.7 m/s, max_angular = 3.0 rad/s입니다(이 파일은 launch 없이 python3로 직접 실행하므로 launch의 0.2/0.5 값이 적용되지 않습니다). 여러 대가 동시에 움직이는 실습에서는 반드시 명령줄에서 낮춰 실행합니다.

bash
python3 ros2_ws/src/multi/launch/joystick_control_multi.py --ros-args -p max_linear:=0.2 -p max_angular:=0.5

import math

def val_map(x, in_min, in_max, out_min, out_max):          # sdk/common.py
    return (x - in_min) * (out_max - out_min) / (in_max - in_min) + out_min

MAX_LIN = 0.2                                  # 권장값 (joystick_control_multi.py 기본은 0.7)
MAX_STEER = math.radians(322 / 2000 * 180)     # 애커만 최대 조향 ≈ 29°
for ly, rx in ((0.05, 0.0), (0.5, 0.0), (1.0, 0.5), (1.0, -1.0)):
    ly_ = 0.0 if abs(ly) < 0.1 else ly         # 불감대 0.1
    v = val_map(ly_, -1, 1, -MAX_LIN, MAX_LIN)
    steer = val_map(rx, -1, 1, -MAX_STEER, MAX_STEER)
    if steer == 0:
        w, pulse = 0.0, 1500
    else:
        w = v / (0.145 / math.tan(steer))      # ω = v / R,  R = L / tan δ
        pulse = 1500 + int(math.degrees(-steer) / 180 * 2000)
    print("ly=%+.2f rx=%+.1f → v=%.3f m/s δ=%+.1f° ω=%+.3f rad/s 서보=%d"
          % (ly, rx, v, math.degrees(steer), w, pulse))
text
ly=+0.05 rx=+0.0 → v=0.000 m/s δ=+0.0° ω=+0.000 rad/s 서보=1500
ly=+0.50 rx=+0.0 → v=0.100 m/s δ=+0.0° ω=+0.000 rad/s 서보=1500
ly=+1.00 rx=+0.5 → v=0.200 m/s δ=+14.5° ω=+0.356 rad/s 서보=1339
ly=+1.00 rx=-1.0 → v=0.200 m/s δ=-29.0° ω=-0.764 rad/s 서보=1822

같은 명령을 모두에게 보내는 이 방식은 대형을 유지하지 않습니다. 두 로봇이 같은 Twist를 받아도 바퀴 미끄러짐, 모터 편차, 출발 시각 차이 때문에 시간이 지나면 간격이 벌어집니다. 한 로봇이 회전하면 각자 자기 중심으로 돌기 때문에, 나란히 선 두 로봇은 회전 후 서로 다른 방향을 보게 됩니다. 대형을 유지하려면 다음 절의 리더-팔로워 제어가 필요합니다.

리더-팔로워 대형#

multi 패키지에는 대형 유지용 노드도 들어 있습니다(formation_update, slave_tf_listener, tf_follower.py). 원리는 다음과 같습니다.

  1. 목표점 정의: 리더 좌표계에서 팔로워가 있어야 할 위치(오프셋)를 정합니다. formation_update.py는 이를 정적 TF(point2, point3)로 방송합니다.
대형robot_2 오프셋 (x, y)robot_3 오프셋 (x, y)
row (옆으로 나란히)(0.0, −0.7)(0.0, +0.7)
column (한 줄 종대)(−0.6, 0.0)(−1.2, 0.0)
triangle (삼각)(−0.7, −0.4)(−0.7, +0.4)
  1. 월드 좌표로 변환: 리더 자세가 (x_L, y_L, ψ_L)이면 오프셋 (d_x, d_y)의 월드 좌표는 2D 회전 + 평행이동입니다.
text
x_T = x_L + d_x·cos ψ_L − d_y·sin ψ_L
y_T = y_L + d_x·sin ψ_L + d_y·cos ψ_L
  1. 추종 제어: 팔로워는 자기 좌표계에서 본 목표점 (e_x, e_y)를 줄이도록 속도를 냅니다. slave_tf_listener.py는 P 제어(Kp = 1.5), 불감대 3 cm, 속도 제한 ±0.25 m/s를 씁니다. 메카넘은 x·y를 독립적으로 움직일 수 있어 이 제어가 간단합니다.

import math

FORMATIONS = {                       # formation_update.py: (x2, y2), (x3, y3) [m]
    "row":      [(0.0, -0.7), (0.0, 0.7)],
    "column":   [(-0.6, 0.0), (-1.2, 0.0)],
    "triangle": [(-0.7, -0.4), (-0.7, 0.4)],
}

def to_world(leader, offset):        # tf_follower.py 와 같은 회전 + 평행이동
    x, y, yaw = leader
    ox, oy = offset
    return (x + ox * math.cos(yaw) - oy * math.sin(yaw),
            y + ox * math.sin(yaw) + oy * math.cos(yaw))

leader = (1.0, 0.5, math.radians(30))            # 리더 자세 (x, y, yaw)
for name, offs in FORMATIONS.items():
    pts = ["(%+.3f, %+.3f)" % to_world(leader, o) for o in offs]
    print("%-8s robot_2 → %s  robot_3 → %s" % (name, pts[0], pts[1]))
text

column   robot_2 → (+0.480, +0.200)  robot_3 → (-0.039, -0.100)
triangle robot_2 → (+0.594, -0.196)  robot_3 → (+0.194, +0.496)

리더가 30° 돌아 있으므로 "오른쪽 0.7 m"는 월드 좌표에서 (+0.35, −0.61)만큼 떨어진 곳이 됩니다. 대형은 리더와 함께 회전합니다.

P 제어 추종과 정상상태 오차#

리더가 일정 속도 v로 움직이면, P 제어만 쓰는 팔로워는 목표점을 일정 거리 뒤에서 따라갑니다. 정상상태에서 팔로워 속도 = 리더 속도이어야 하므로 K_p · e_{ss} = v, 즉 e_{ss} = v / K_p입니다.

python브라우저 실행Playground ↗
# slave_tf_listener.py 의 P 제어(Kp=1.5, 불감대 3 cm, 한계 0.25 m/s)로
# 리더를 옆(row 대형, y=-0.7 m)에서 따라가는 추종 로봇 — 30 Hz
KP, DEAD, VMAX, dt = 1.5, 0.03, 0.25, 1 / 30

def p_cmd(err):
    err = 0.0 if abs(err) < DEAD else err
    return max(-VMAX, min(VMAX, KP * err))

leader_x, v_leader = 0.0, 0.10                   # 리더는 x축으로 0.1 m/s 직진
fx, fy = -0.40, -0.30                            # 추종 로봇 출발 위치
for k in range(int(12 / dt) + 1):
    tx, ty = leader_x + 0.0, -0.7                # 목표점 point2 (row: x 오프셋 0)
    ex, ey = tx - fx, ty - fy                    # 추종 로봇 기준 목표까지 오차
    if k % 60 == 0:
        print("t=%4.1fs 오차 x=%+.3f y=%+.3f m" % (k * dt, ex, ey))
    fx += p_cmd(ex) * dt                         # 메카넘: x·y 독립 이동
    fy += p_cmd(ey) * dt
    leader_x += v_leader * dt
print("이론 정상상태 지연 v/Kp = %.3f m" % (v_leader / KP))

  • y 방향은 2.9 cm에서 멈췄습니다. 불감대(3 cm) 안이라 명령이 0이 되었기 때문입니다. 불감대는 떨림을 막지만 그 크기만큼의 오차를 허용합니다.

시간 동기화#

원본 교재는 실행 전에 슬레이브의 시계를 마스터에 맞추게 합니다.

bash
date                                       # 마스터에서 현재 시각 확인
sudo date -s "2024-10-29 22:46:31"         # 슬레이브에서 (마스터 시각 + 입력하는 데 걸린 초)

로봇은 인터넷 없이 핫스팟으로만 연결되므로 NTP로 시계를 맞출 수 없고, 부팅할 때마다 시계가 어긋나 있을 수 있습니다. 단순한 Twist 토픽은 시각을 검사하지 않지만, 메시지 헤더의 타임스탬프를 쓰는 기능(TF 조회, 센서 동기화, 대형 유지의 lookup_transform)은 시계가 몇 초만 어긋나도 "미래/과거 데이터" 오류(ExtrapolationException)를 냅니다. 원본 교재도 조이패드 반응이 로봇마다 어긋나면 이 단계를 다시 하라고 안내합니다. 수동 입력 대신 마스터를 chrony 시간 서버로 두고 슬레이브가 동기화하게 하면 더 정확합니다.

실습 (실물)#

실물 실습 안전 수칙
  • 로봇 여러 대가 동시에 움직입니다. 로봇 사이 간격을 1 m 이상 두고, 전체 공간은 3 m × 3 m 이상 비웁니다.
  • joystick_control_multi.py는 반드시 max_linear:=0.2, max_angular:=0.5로 실행합니다.
  • 조이패드 연결이 끊기면 마지막 명령이 남을 수 있습니다. 한 사람은 각 로봇 옆에서 정지를 도울 준비를 하고, START 버튼과 Ctrl+C 위치를 미리 확인합니다.
  • 슬레이브가 네트워크를 잃으면 명령을 못 받고 마지막 속도로 움직일 수 있으므로, 처음에는 저속으로 짧게 움직여 연결을 확인합니다.
  1. 마스터를 켜고 핫스팟이 뜬 것을 확인한 뒤 슬레이브를 켭니다(LED2가 빠른 깜빡임 → 연결).
  2. 모든 로봇에서 앱 자동 실행을 멈추고, .typerc의 HOST·MASTER를 확인합니다.
bash
~/.stop_ros.sh
echo $HOST $MASTER
  1. 슬레이브 시계를 마스터에 맞춥니다(위 절 참고). 두 로봇에서 date를 연달아 쳐서 차이가 1초 이내인지 봅니다.
  2. 마스터에 USB 조이패드 수신기를 꽂고, 터미널 세 개에서 각각 실행합니다.
bash
ros2 launch multi multi_controller.launch.py
python3 ros2_ws/src/multi/launch/joystick_control_multi.py --ros-args -p max_linear:=0.2 -p max_angular:=0.5
ros2 run joy joy_node
  1. 슬레이브에서 실행합니다.
bash
ros2 launch multi multi_controller.launch.py
  1. 연결을 확인합니다. 네임스페이스가 붙은 토픽이 로봇 수만큼 보여야 합니다.
bash
ros2 topic list | grep controller/cmd_vel
ros2 topic echo /robot_2/controller/cmd_vel
  1. 조이패드 전원을 켜고(빨강·초록 LED 동시 깜빡임) 페어링되면 초록 LED가 켜집니다. START를 눌러 모든 로봇의 부저가 울리는지 확인한 뒤, 스틱을 살짝 밀어 천천히 움직입니다.
  2. 끝나면 모든 터미널에서 Ctrl+C 후, 각 로봇에서 앱 서비스를 복구합니다.
bash
sudo systemctl restart start_node.service
