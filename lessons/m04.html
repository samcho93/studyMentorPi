M04cmd_vel 속도 제어 프로그래밍

geometry_msgs/Twist로 메카넘·애커만 속도 제어 노드를 작성하고, 정사각형·원·8자 주행과 속도 제한을 구현합니다.

선수 챕터: M01 M02 M03
3D 시뮬레이터ROS 2 Playground2D 시뮬레이터

학습 목표#

  • geometry_msgs/Twist의 필드가 메카넘·애커만 섀시에서 각각 어떻게 해석되는지, /cmd_vel과 /controller/cmd_vel의 차이를 원본 소스로 설명합니다.
  • 타이머 기반 상태 기계(state machine) 로 속도 제어 노드를 작성하고, 종료 시 반드시 정지 명령을 보내는 구조를 갖춥니다.
  • 시간 기반(개방 루프)과 /odom 피드백 기반(폐루프) 정사각형 주행의 오차를 비교합니다.
  • 원·8자 주행을 곡률 κ = ω/v로 설계하고, 두 섀시에서 같은 명령이 통하는 조건을 설명합니다.
  • 속도·가속도 제한(slew-rate limiter)을 구현해 안전한 명령을 만듭니다.

Twist 메시지와 두 입력 토픽#

geometry_msgs/msg/Twist는 linear(x, y, z) [m/s]와 angular(x, y, z) [rad/s] 두 벡터입니다. 로봇 좌표계(x 전방, y 왼쪽) 기준이며, 평면 로봇은 세 값만 씁니다.

필드메카넘애커만
linear.x전후 속도 v_x뒷차축 속도 v
linear.y좌우 속도 v_y (+ = 왼쪽)무시
angular.z회전 속도 ω (+ = 반시계)δ = atan(Lω/v)로 바뀌어 서보 조향, v = 0이면 무시
나머지무시무시

원본 odom_publisher_node.py는 속도 명령을 두 토픽에서 받습니다.

토픽콜백제한누가 쓰나
/cmd_velapp_cmd_vel_callback → cmd_vel_callback|v_x|, |v_y| ≤ 0.2 m/s, |ω| ≤ 0.5 rad/s로 자름앱, 조이패드, 학생 코드
/controller/cmd_velcmd_vel_callback없음Nav2, 라이다 앱, 보정 노드, 키보드 노드

교재(Lesson 5·6)는 /controller/cmd_vel로 직접 명령을 보내며 선속도 −0.6 ~ 0.6 m/s, 메카넘 각속도 −2 ~ 2 rad/s 범위를 안내합니다. 처음 작성하는 코드는 **제한이 걸린 /cmd_vel** 을 쓰고, 빠른 반응이 꼭 필요할 때만 /controller/cmd_vel을 쓰세요.

명령은 계속 유지된다#

MentorPi 기본 스택에는 명령 타임아웃(watchdog)이 없습니다. cmd_vel_callback은 받은 속도를 모터 보드에 rps로 보내고, 보드는 새 명령이 올 때까지 그 속도를 유지합니다. 교재 FAQ에 "Ctrl+C를 눌러도 계속 간다"는 항목이 있는 이유입니다. 그래서 모든 주행 노드는 다음 세 가지를 지킵니다.

  1. 주기적으로 발행합니다(10~20 Hz). 한 번만 보내고 기다리는 코드는 중간에 죽으면 멈추지 않습니다.
  2. 종료 경로에서 정지 Twist를 발행합니다. try / except KeyboardInterrupt / finally의 finally에 둡니다.
  3. 가능하면 자체 워치독을 둡니다. 예: 센서 콜백이 0.5초 이상 안 오면 정지.
python
rclpy.init()
node = MyDriver()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())      # 모든 필드 0 = 정지
    node.destroy_node()
    rclpy.shutdown()

속도 제어 노드의 구조#

sleep 루프 대신 타이머 + 상태 기계#

"0.2 m/s로 2.5초 가고, 0.5 rad/s로 3.14초 돌고…"를 time.sleep()으로 나열하면 쉽지만, 그동안 콜백이 돌지 못해 센서(/odom, /scan)를 받을 수 없습니다. ROS 2 노드는 타이머 콜백이 짧게 한 번 판단하고 돌아오는 구조가 기본입니다. 현재 무엇을 하는 중인지는 상태 변수로 기억합니다.

text
          거리 ≥ 0.5 m                  |yaw 오차| < 1°
[drive] ─────────────────▶ [turn] ─────────────────────▶ [drive] … 4번 후 [done]
 vx = P(남은 거리)            ωz = P(yaw 오차)
 ωz = P(방향 유지)

개방 루프와 폐루프#

방식판단 기준장점단점
시간 기반(개방 루프)"2.5초 지났나?"센서 불필요, 단순가감속·미끄럼·배터리 전압에 따라 매번 달라짐, 오차 누적
오도메트리 기반(폐루프)"0.5 m 갔나? 90° 돌았나?"명령 오차·가감속을 자동 보정오도메트리 자체 드리프트(M03)는 못 고침
외부 기준(라이다·지도)"벽에서 0.3 m인가?"드리프트까지 보정센서 처리 필요(M05·M06, M11)

폐루프에서는 목표에 가까워질수록 속도를 줄이는 비례 제어(P control) 를 씁니다: v = min(v_max, k·남은 거리). 그대로 두면 목표 근처에서 속도가 0에 가까워져 영원히 도착하지 못하므로, 작은 최소 속도(예: 0.05 m/s)를 더하거나 허용 오차 안이면 멈춥니다.

원과 8자: 곡률로 설계하기#

원 주행은 v와 ω를 일정하게 두면 됩니다. 반경 R = v/ω, 곡률 κ = 1/R = ω/v입니다.

  • 메카넘·애커만 모두 같은 명령(v = 0.2, ω = 0.5)으로 반경 0.4 m 원을 그립니다. 애커만은 R ≥ 0.262 m(M02)이므로 가능합니다.
  • 8자는 한 바퀴(2πR/v = 12.6 s)마다 ω의 부호만 바꿉니다. 두 원이 출발점에서 접하므로 부호를 바꾸는 순간 로봇 방향이 두 원의 공통 접선 방향입니다.
  • 애커만으로 정사각형을 그리려면 제자리 회전이 불가능하므로 모서리를 반경 ≥ 0.262 m인 원호로 둥글게 돌아야 합니다.

속도·가속도 제한#

속도를 계단처럼 바꾸면 바퀴가 미끄러지고(오도메트리 오차), 차체가 앞뒤로 흔들리고, 애커만은 조향 서보가 크게 튑니다. 가속도 제한(slew-rate limit) 은 한 주기에 바뀔 수 있는 속도의 양을 a_{max}·Δt로 묶습니다.

text
target ← clamp(target, −v_max, +v_max)
cmd    ← cmd + clamp(target − cmd, −a_max·Δt, +a_max·Δt)

참고로 원본 ekf.yaml에도 acceleration_limits: [1.3, …, 3.4](선 1.3 m/s², 회전 3.4 rad/s²)가 적혀 있지만, use_control: false라서 실제 명령을 제한하지는 않습니다. Nav2(M11)에서는 velocity_smoother가 이 역할을 합니다.

실습 (시뮬레이션)#

1. 오도메트리 피드백 정사각형 (메카넘)#

한 변 0.5 m 정사각형을 /odom 기반 상태 기계로 주행합니다. 직진 중에는 목표 방향을 유지하도록 ω에 P 제어를 걸고, 회전 목표는 이전 목표 방향 + 90° 로 잡아 방향 오차가 쌓이지 않게 합니다.

python브라우저 실행
import math
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from nav_msgs.msg import Odometry
from tf_transformations import euler_from_quaternion
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=29.0,
          start=(-0.25, -0.25, 0.0), noise=True)                  # 시뮬 전용

SIDE, V, W = 0.5, 0.2, 0.5

def wrap(a):
    return math.atan2(math.sin(a), math.cos(a))

class Square(Node):
    def __init__(self):
        super().__init__("square")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Odometry, "/odom", self.on_odom, 10)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.pose = self.gt = self.heading = None
        self.state, self.leg = "start", 0
        self.create_timer(0.05, self.tick)

    def on_odom(self, msg):
        p, q = msg.pose.pose.position, msg.pose.pose.orientation
        self.pose = (p.x, p.y, euler_from_quaternion([q.x, q.y, q.z, q.w])[2])

    def on_gt(self, msg):
        self.gt = msg

    def tick(self):
        if self.pose is None or self.gt is None:
            return
        x, y, yaw = self.pose
        cmd = Twist()
        if self.state == "start":
            self.heading = yaw if self.heading is None else self.heading
            self.ref, self.state = (x, y), "drive"
        if self.state == "drive":
            d = math.hypot(x - self.ref[0], y - self.ref[1])
            if d < SIDE:
                cmd.linear.x = min(V, 1.0 * (SIDE - d) + 0.05)     # 끝에서 감속
                cmd.angular.z = 2.0 * wrap(self.heading - yaw)     # 방향 유지
            else:
                self.heading, self.state = wrap(self.heading + math.pi / 2), "turn"
        elif self.state == "turn":
            e = wrap(self.heading - yaw)
            if abs(e) > math.radians(1.0):
                cmd.angular.z = max(-W, min(W, 2.0 * e + math.copysign(0.05, e)))
            else:
                self.leg += 1
                print("변 %d  odom (%+.3f, %+.3f)  실제 (%+.3f, %+.3f)"
                      % (self.leg, x, y, self.gt.x, self.gt.y))
                self.state = "start" if self.leg < 4 else "done"
        if self.state == "done" and self.leg == 4:
            err = math.hypot(self.gt.x + 0.25, self.gt.y + 0.25)
            print("출발점 대비 실제 위치 오차 = %.3f m" % err)
            self.leg = 5
        self.pub.publish(cmd)

rclpy.init()
node = Square()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()

(대략 — 잡음 설정에 따라 실제 좌표는 몇 cm 달라질 수 있습니다)

text
변 1  odom (+0.503, +0.000)  실제 (+0.229, -0.250)
변 2  odom (+0.504, +0.503)  실제 (+0.250, +0.228)
변 3  odom (+0.002, +0.504)  실제 (-0.222, +0.274)
변 4  odom (+0.001, +0.002)  실제 (-0.291, -0.200)
출발점 대비 실제 위치 오차 = 0.065 m

odom 좌표는 출발점이 원점인 odom 프레임 값이라 (0, 0) → (0.5, 0) → (0.5, 0.5) → (0, 0.5) → (0, 0)의 거의 완벽한 정사각형입니다(실물 EKF도 켤 때의 자세를 원점으로 삼습니다). 반면 실제 좌표(출발 (−0.25, −0.25))는 변마다 2 cm 남짓 짧고 방향도 조금씩 틀어져 6~7 cm 벗어났습니다. 제어는 odom을 완벽히 따랐고, 남은 오차는 odom 자체의 오차(M03의 미끄럼)입니다. W와 P 이득을 바꿔 보거나 noise=False로 두고 비교해 보세요.

2. 원과 8자 (애커만)#

같은 명령 체계를 애커만 섀시에서 돌립니다. 한 바퀴 T = 2π/ω = 12.57 s마다 ω의 부호를 바꿉니다.

python브라우저 실행
import math
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="ackermann", world="empty", duration=25.6,
          start=(0.0, 0.0, 0.0), noise=False)                     # 시뮬 전용

V, W = 0.2, 0.5
T_LAP = 2 * math.pi / W

class FigureEight(Node):
    def __init__(self):
        super().__init__("figure_eight")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.xs, self.ys = [], []
        self.t0, self.switched = time.time(), False
        self.create_timer(0.05, self.tick)

    def on_gt(self, msg):
        self.xs.append(msg.x)
        self.ys.append(msg.y)

    def tick(self):
        t = time.time() - self.t0
        cmd = Twist()
        if t < 2 * T_LAP:
            cmd.linear.x = V
            cmd.angular.z = W if t < T_LAP else -W
        if t >= T_LAP and not self.switched and self.xs:
            print("t=%.2f s 부호 전환 지점 (%+.3f, %+.3f)" % (t, self.xs[-1], self.ys[-1]))
            self.switched = True
        self.pub.publish(cmd)

rclpy.init()
node = FigureEight()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    print("y 범위 %+.3f ~ %+.3f m" % (min(node.ys), max(node.ys)))

3. 속도·가속도 제한기#

SafeCmd는 목표 속도를 받아 ① 최대 속도로 자르고 ② 가속도 한계만큼만 따라가게 합니다. 제한 없는 /controller/cmd_vel에 0.5 m/s를 요청해도 제한기를 거치면 안전한 명령만 나갑니다.

python브라우저 실행
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
from nav_msgs.msg import Odometry
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=5.0,
          start=(-2.0, 0.0, 0.0), noise=False)                    # 시뮬 전용

class SafeCmd:
    def __init__(self, v_max=0.2, w_max=0.5, a_max=0.2, alpha_max=1.0):
        self.lim = (v_max, v_max, w_max)
        self.rate = (a_max, a_max, alpha_max)
        self.cur = [0.0, 0.0, 0.0]

    def step(self, target, dt):
        for i in range(3):
            t = max(-self.lim[i], min(self.lim[i], target[i]))
            dv = max(-self.rate[i] * dt, min(self.rate[i] * dt, t - self.cur[i]))
            self.cur[i] += dv
        msg = Twist()
        msg.linear.x, msg.linear.y, msg.angular.z = self.cur
        return msg

class RampDemo(Node):
    def __init__(self):
        super().__init__("ramp_demo")
        self.pub = self.create_publisher(Twist, "/controller/cmd_vel", 10)
        self.create_subscription(Odometry, "/odom", self.on_odom, 10)
        self.safe, self.v_meas, self.n = SafeCmd(), 0.0, 0
        self.t0 = time.time()
        self.create_timer(0.05, self.tick)

    def on_odom(self, msg):
        self.v_meas = msg.twist.twist.linear.x

    def tick(self):
        t = time.time() - self.t0
        want = 0.5 if t < 3.0 else 0.0            # 과한 요청 → 0 요청
        cmd = self.safe.step((want, 0.0, 0.0), 0.05)
        self.pub.publish(cmd)
        if self.n % 10 == 0:
            print("t=%.1f  요청 %.2f  명령 %.3f  측정 %.3f" % (self.n * 0.05, want, cmd.linear.x, self.v_meas))
        self.n += 1

rclpy.init()
node = RampDemo()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()

  • 정사각형·8자는 사방 1.5 m 이상, 애커만 8자는 2 m × 1.2 m 이상의 빈 공간이 필요합니다. 케이블·발이 주행 경로에 없는지 봅니다.

자주 나는 오류와 해결#

증상원인해결
노드를 Ctrl+C로 끝냈는데 로봇이 계속 감finally에서 정지 명령을 안 보냄 또는 보내기 전에 rclpy.shutdown()publish(Twist()) → destroy_node() → shutdown() 순서 지키기
linear.y를 보냈는데 애커만이 옆으로 안 감애커만은 linear.y 무시정상. 옆 이동은 메카넘만 가능
정사각형이 점점 돌아감회전 목표를 "현재 yaw + 90°"로 잡아 오차 누적"이전 목표 방향 + 90°"로 잡기
목표 근처에서 로봇이 안 멈추고 떨림P 제어 + 허용 오차가 너무 작음허용 오차(1°, 1 cm)와 최소 속도 조합 조정
time.sleep() 루프 중 센서 값이 안 바뀜콜백이 실행될 기회가 없음타이머 + 상태 기계 구조로 변경
0.5 m/s를 보냈는데 0.2 m/s만 나옴/cmd_vel 제한의도한 동작. 필요하면 /controller/cmd_vel + 자체 제한기
