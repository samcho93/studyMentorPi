## 학습 목표

- 전원 투입 후 LED·부저 신호로 부팅 완료와 네트워크 모드를 판별합니다.
- **AP 직접 연결 모드**와 **STA(LAN) 모드**의 구조 차이를 설명하고, 상황에 맞는 모드를 골라 WonderPi 앱을 연결합니다.
- 앱의 다섯 가지 게임 모드(로봇 제어·라이다·물체 추적·라인 추종·제스처)를 실행하고 각 기능이 어떤 센서를 쓰는지 연결합니다.
- 무선 조이패드를 페어링하고, 스틱 입력이 `Twist` 속도 명령으로 바뀌는 과정을 설명합니다.
- 2D 시뮬레이터에서 메카넘과 애커만을 수동 주행하며 두 섀시의 조작감 차이를 확인합니다.

## 부팅 순서와 상태 신호

확장보드 스위치를 켜면 약 1분 동안 다음 순서로 부팅합니다(원본 "Get Started").

1. 확장보드 전원 → LED1 점등
2. 라즈베리파이 OS 부팅 → Docker 컨테이너 기동 → ROS 2 노드(앱 서비스, 섀시 제어 등) 자동 실행
3. ROS 구성이 끝나면 **부저가 "삑" 한 번** — 이때부터 앱·조이패드 조작 가능
4. AP 모드라면 `HW`로 시작하는 핫스팟이 뜨고 **LED2가 1초에 한 번** 깜빡임

| LED2 상태 | 의미 |
|---|---|
| 1초 간격으로 천천히 깜빡임 | AP 직접 연결 모드(핫스팟 동작 중) |
| 빠르게 깜빡임 | LAN(STA) 모드에서 지정한 Wi-Fi를 찾는 중 |
| 켜짐 유지 | LAN 모드로 공유기 연결 완료 |

:::info 부팅 중에 앱을 켜면?
부저가 울리기 전에는 앱 서비스 노드가 아직 떠 있지 않아 "장치를 찾을 수 없음"이 나옵니다. 부저 소리를 **"준비 완료" 신호**로 삼으세요. 이 자동 실행 서비스는 B03에서 `~/.stop_ros.sh`로 끄고 켜는 방법을 배웁니다.
:::

## 네트워크 모드: AP와 STA

@fig[b02-network] 두 가지 연결 구조. AP 모드는 로봇이 공유기 역할을 하고, STA 모드는 로봇이 기존 공유기에 손님으로 붙습니다.

| 구분 | AP 직접 연결 모드(기본값) | STA LAN 모드 |
|---|---|---|
| 누가 핫스팟을 만드나 | **로봇**(`HW-…`, 비밀번호 `hiwonder`) | 기존 공유기·휴대폰 핫스팟 |
| 로봇 IP | 고정 `192.168.149.1` | 공유기가 DHCP로 할당(앱에서 아이콘을 길게 눌러 확인) |
| 인터넷 | 불가(휴대폰/PC가 로봇에만 연결됨) | 가능(패키지 설치, 여러 PC 동시 접속) |
| 장점 | 설정 없이 바로 연결, 장소 불문 | 인터넷 + 여러 장치, 군집 제어(A12)의 바탕 |
| 주의 | 여러 로봇이 있으면 핫스팟 이름으로 구분 | 대상 Wi-Fi를 3회 검색해도 못 찾으면 **자동으로 AP 모드로 복귀**(LED2 느린 깜빡임). LAN 모드에서는 로봇 자체 핫스팟이 없음 |

두 모드 모두 앱의 게임 기능은 똑같이 쓸 수 있습니다. 처음에는 **AP 모드로 기능을 익히고**, 인터넷이 필요할 때 LAN 모드로 전환하는 것을 권장합니다.

:::tip LAN 모드 공유기 교체 요령
LAN 모드로 연결했던 휴대폰 핫스팟을 쓸 수 없게 되면, 다른 장치의 핫스팟 **이름과 비밀번호를 이전과 똑같이** 만들어 주면 로봇이 그대로 접속합니다. 로봇은 SSID/비밀번호만 기억하기 때문입니다.
:::

## WonderPi 앱 연결

### 설치

- Android: 교재 폴더의 APK 파일을 휴대폰으로 옮겨 설치
- iOS: App Store에서 "WonderPi" 검색
- 설치할 때 요청하는 권한을 **모두 허용**하고, 앱을 열기 전에 **GPS와 Wi-Fi를 켭니다**(Android는 주변 Wi-Fi 검색에 위치 권한이 필요합니다).

### AP 직접 연결

1. 앱 홈에서 **Advanced → MentorPi-M1**(애커만은 **MentorPi-A1**) 선택
2. 오른쪽 아래 **"+"** → 직접 연결 모드 선택
3. "Go to connect device hotspots" → Wi-Fi 설정에서 `HW-…` 핫스팟 연결, 비밀번호 `hiwonder`
4. 앱으로 돌아오면 자동 검색 → 로봇 아이콘이 나타나면 연결 완료
   - "network unavailable, continue or not" 팝업이 뜨면 **Keep Connection**(핫스팟에는 인터넷이 없어서 휴대폰이 경고하는 것)
   - "검색된 제품 화면으로 전환할까요?"가 나오면 1단계에서 버전을 잘못 고른 것 → OK로 전환
   - iOS는 "Wi-Fi 연결 성공" 표시를 확인한 뒤 앱으로 돌아가야 검색됩니다. 안 보이면 새로고침을 여러 번

### LAN 모드

1. 휴대폰을 목표 Wi-Fi(예: 5 GHz `Hiwonder_5G`)에 먼저 연결
2. 앱에서 MentorPi-M1/A1 → "+" → **LAN 모드** → 그 Wi-Fi의 비밀번호 입력(틀리면 연결 실패)
3. "Go to connect device hotspots"로 `HW-…` 핫스팟에 잠시 연결 → Return
4. 앱이 로봇에 Wi-Fi 정보를 전달하고 로봇이 공유기로 재접속 → 앱 메인에 로봇 아이콘, 확장보드 LED 켜짐 유지
5. 아이콘을 **길게 누르면 IP와 ID**가 보입니다. 이 IP로 VNC 접속(B03)
6. 되돌리려면 팝업의 **"Set to direct connection mode"**

## 앱 게임 모드

| 모드 | 동작 | 쓰는 센서·기술 | 관련 챕터 |
|---|---|---|---|
| Robot Control | 버튼·중력 센서로 주행, 화면 드래그로 팬틸트 회전 | 카메라 스트림, 모터 | M04 |
| Lidar | 장애물 회피 / 라이다 추종 / 라이다 경비 | LD19 라이다 | M06 |
| Object Tracking | 화면에서 색을 찍으면 그 색 물체를 따라감 | 카메라, 색 임계값 | A01, A04 |
| Line Following | 바닥 테이프 색을 찍으면 선을 따라감 | 카메라, 색 이진화 | A03 |
| Gesture Control | 손 궤적(상하좌우)으로 이동 명령(메카넘만) | 카메라, MediaPipe | A05 |

실행 팁(원본 요약):

- **라이다 게임**은 넓은 곳에서. 회피는 계속 전진하다 장애물 앞에서 방향을 틀고, 추종은 물체와 일정 거리를 유지하고, 경비는 물체 쪽으로 몸을 돌립니다(애커만은 경비 미지원).
- **물체 추적·라인 추종**은 Pick 버튼으로 색을 찍고 OK로 확정한 뒤 Start. 색 범위(0.05~1.00)는 너무 넓으면 배경까지 잡히고, 너무 좁으면 대상을 놓칩니다. 화면 안에 비슷한 색 물체가 없어야 합니다.
- **제스처**는 오른손만, 손바닥 전체가 화면에 보이게, 천천히. 주먹 쥐고 화면 중앙 → "삑" 후 손을 펴고 한 방향으로 이동 → 다시 주먹 → "삑" 후 그 방향으로 움직임.
- 단안 카메라 팬틸트는 끝까지 돌리면 **진동 피드백**이 옵니다. 서보 한계 보호가 걸린 것이니 더 돌리지 않습니다.

### 앱 버튼 뒤에서 일어나는 일

앱의 게임 버튼은 결국 로봇 안의 ROS 2 **서비스**를 호출합니다. 원본 "Lidar Obstacle Avoidance"는 같은 게임을 명령으로 실행하는 방법도 보여 줍니다(VNC 터미널, B03 이후 실습).

```bash
~/.stop_ros.sh                                            # 앱 자동 실행 서비스 중지
ros2 launch app lidar_node.launch.py debug:=true          # 라이다 게임 + 섀시 제어 노드 실행
# 새 터미널에서
ros2 service call /lidar_app/enter std_srvs/srv/Trigger {}                    # 게임 진입
ros2 service call /lidar_app/set_running interfaces/srv/SetInt64 "{data: 1}"   # 1 = 장애물 회피 시작
ros2 service call /lidar_app/set_running interfaces/srv/SetInt64 "{data: 0}"   # 정지
```

끝나면 호스트 터미널에서 `sudo systemctl restart start_node.service`(또는 재부팅)로 앱 서비스를 되살립니다. 앱으로 실행하든 명령으로 실행하든 로봇의 동작은 같습니다. 게임을 끄지 않으면 계속 메모리를 차지하므로, 다른 게임으로 넘어가기 전에 반드시 종료하세요.

## 무선 조이패드

### 페어링

1. 로봇 전원을 먼저 켜고(수신기는 출고 시 장착됨), 조이패드 전원 ON → 빨강·초록 LED 동시 깜빡임
2. 몇 초 뒤 자동 페어링 → **초록 LED 켜짐 유지, 빨강 꺼짐**
3. 켠 뒤 30초 안에 연결되지 않거나, 연결 후 5분간 조작이 없으면 절전 모드 → **START** 버튼으로 깨움
4. 조이패드 제어는 앱 자동 실행 서비스에 포함되어 있어 별도 명령 없이 동작합니다.

### 조작과 속도 명령

원본 `peripherals/joystick_control.py`는 `/joy` 메시지를 받아 `controller/cmd_vel`에 `Twist`를 발행합니다. 스틱 값(−1~1)을 선형으로 늘려 속도로 바꾸는 `val_map()`을 쓰며, |값| < 0.1은 0으로 버리는 **데드존(dead zone)**이 있습니다(손을 떼도 스틱이 정확히 0으로 돌아오지 않기 때문).

| 입력 | 메카넘(`MentorPi_Mecanum`) | 애커만(`MentorPi_Acker`) |
|---|---|---|
| 왼쪽 스틱 위/아래 | `linear.x` 전진/후진 | `linear.x` 전진/후진 |
| 왼쪽 스틱 좌/우 | `linear.y` **좌우 평행이동** | (없음) |
| 오른쪽 스틱 좌/우 | `angular.z` 제자리 회전 | **조향각** ±29°(서보 ID 3) → $ω = v·tan δ / L$ |
| START | 정지·자세 복귀(부저 짧게) | 정지·자세 복귀 |

스틱을 살짝만 밀면 저속으로 움직입니다. 이동 거리에 비례한 속도라는 뜻입니다.

```python
# joystick_control.py의 핵심(요약)
twist.linear.x  = val_map(axes['ly'], -1, 1, -max_linear,  max_linear)
twist.linear.y  = val_map(axes['lx'], -1, 1, -max_linear,  max_linear)   # 메카넘만
twist.angular.z = val_map(axes['rx'], -1, 1, -max_angular, max_angular)
```

애커만에서는 오른쪽 스틱이 조향각 δ(최대 322/2000×180 ≈ 29°)를 정하고, 같은 선속도에서의 회전 반경 $R = L / tan δ$(L = 0.145 m)로 각속도를 역산해 발행합니다. 조향 서보에는 펄스 $1500 + 2000·deg(−δ)/180$ µs를 보냅니다. 이 식은 M02에서 유도합니다.

:::warning 여러 대가 같은 공간에 있을 때
조이패드는 켜진 수신기와 자동으로 짝을 짓기 때문에 **다른 로봇과 연결**될 수 있습니다. 수업에서 여러 대를 동시에 켤 때는 조이패드 대신 앱이나 코드로 제어하세요.
:::

## 실습 (시뮬레이션)

실물을 움직이기 전에 2D 시뮬레이터에서 두 섀시의 조작감을 익힙니다.

@btn[~/sim/index.html] 2D 시뮬레이터 열기

:::task 수동 주행 비교
1. 섀시를 **메카넘**으로 두고 수동 주행 모드에서 키보드(또는 가상 조이스틱)로 전진·후진·좌우 평행이동·제자리 회전을 모두 해 봅니다.
2. 섀시를 **애커만**으로 바꿔 같은 동작을 시도합니다. 좌우 평행이동과 제자리 회전이 **불가능**하다는 것을 확인하고, 90° 방향 전환에 필요한 공간(회전 반경)을 눈으로 가늠합니다.
3. 방(room) 월드에서 출발점 → 반대편 벽 → 출발점 왕복을 두 섀시로 각각 해 보고 걸린 시간과 벽 충돌 횟수를 기록합니다.
4. **오도메트리 오차 표시**를 켠 채 사각형을 그리며 한 바퀴 돌아옵니다. 실제 위치(ground truth)와 오도메트리 위치가 얼마나 벌어지는지 관찰합니다. 이 차이가 M03(보정)과 M09(SLAM)가 필요한 이유입니다.
:::

:::check 체크포인트
- [ ] 메카넘은 "옆으로 가기"가 되고 애커만은 안 되는 이유를 바퀴 구조로 설명할 수 있다.
- [ ] 애커만으로 좁은 통로에서 방향을 바꾸려면 전진·후진을 반복해야 함을 확인했다.
- [ ] 수동 주행 후 오도메트리와 실제 위치의 차이를 관찰했다.
:::

## 실습 (실물)

:::safety
- 넓고 평평한 바닥(최소 2 m × 2 m)에서, 주변에 사람·물컵·케이블이 없는지 확인합니다.
- 처음에는 **스틱을 조금만** 밀어 저속으로 움직입니다. 조이패드 기본 최대 선속도는 교재 수업 권장값(0.2 m/s)보다 빠를 수 있습니다.
- 계단·책상 가장자리 근처에서는 주행하지 않습니다.
- 이상하면 즉시 스틱에서 손을 떼고 **START**, 그래도 멈추지 않으면 **확장보드 전원 스위치 OFF**.
:::

1. 로봇 전원 ON → 부저 "삑"과 LED2 느린 깜빡임 확인
2. 휴대폰을 `HW-…` 핫스팟에 연결하고 앱에서 MentorPi-M1/A1 선택 → 직접 연결
3. **Robot Control**에서 전진·후진·회전을 짧게 시험. 카메라 영상이 나오는지 확인
4. **Lidar → Avoid obstacle**을 켜고 상자·책으로 장애물을 만들어 회피 동작 관찰. 끝나면 반드시 끔
5. 앱을 닫고 조이패드 페어링 → 표의 조작을 하나씩 확인(메카넘은 평행이동, 애커만은 조향)
6. (선택) 공유기가 있으면 LAN 모드로 전환해 IP를 확인하고, 다시 직접 연결 모드로 복귀

:::check 체크포인트
- [ ] 앱으로 주행과 라이다 회피를 실행했다.
- [ ] 조이패드 페어링 LED 변화를 확인했다.
- [ ] LAN 모드 IP(또는 AP 모드 192.168.149.1)를 기록해 두었다(B03 VNC에 사용).
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 앱에서 장치가 검색되지 않음 | 부팅 미완료, 핫스팟 미연결, 앱 권한/GPS 꺼짐 | 부저 소리 후 다시 시도. 휴대폰 Wi-Fi가 `HW-…`에 붙었는지 확인. 앱 권한·GPS 켜기. iOS는 연결 성공 표시 후 앱 복귀, 새로고침 반복 |
| "network unavailable" 팝업 | 로봇 핫스팟에 인터넷이 없어서 휴대폰이 경고 | **Keep Connection** 선택 |
| 제품 전환 팝업이 뜸 | M1/A1 선택이 실제 섀시와 다름 | OK를 눌러 올바른 버전으로 전환 |
| LAN 모드 설정 후 연결 실패 | Wi-Fi 비밀번호 오입력, 공유기 탐색 실패 | 3회 검색 실패 시 자동 AP 복귀(LED2 느린 깜빡임) → 핫스팟으로 다시 연결해 재설정 |
| 조이패드가 반응하지 않음 | 절전 모드(30초 미연결/5분 미사용), 수신기 빠짐, 건전지 극성 | START로 깨우기, 수신기 확인, 건전지 방향 확인 |
| 조이패드가 다른 로봇을 조종 | 같은 공간 여러 로봇 자동 페어링 | 한 대씩 켜서 페어링하거나 앱 사용 |
| 스틱을 놓았는데도 천천히 움직임 | 스틱 중립점 오차가 데드존(0.1)보다 큼 | 스틱을 몇 번 돌려 중립 복귀, 계속되면 조이패드 교체 |
| 팬틸트 드래그 시 진동 후 멈춤 | 서보 한계 보호 | 정상. 반대 방향으로 드래그 |

## 과제

:::task 기본
1. AP 모드와 STA 모드 중 (a) 야외 시연, (b) 실습실에서 PC로 코드 개발 + 패키지 설치, (c) 로봇 3대 군집 제어에 알맞은 모드를 고르고 이유를 씁니다.
2. 조이패드 최대 선속도가 0.5 m/s일 때 왼쪽 스틱을 60 % 밀면 `linear.x`는 얼마인지 계산합니다(데드존은 무시).
:::

:::task 심화
3. 애커만에서 조향각 20°, 선속도 0.2 m/s일 때 회전 반경 R과 각속도 ω, 그리고 조향 서보 펄스값을 구합니다(L = 0.145 m).
4. 시뮬레이터에서 애커만으로 폭 1 m 복도 끝에서 U턴을 해 보고, 몇 번의 전진·후진이 필요했는지와 그 이유(최소 회전 반경)를 적습니다.
:::
