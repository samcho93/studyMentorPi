## 학습 목표

- MentorPi-M1(메카넘)과 MentorPi-A1(애커만) 두 섀시의 차이를 **이동 방식**과 **지원 기능** 기준으로 설명합니다.
- 라즈베리파이 5 ↔ RRC Lite 확장보드(STM32) ↔ 모터·서보·센서로 이어지는 **2단 제어 구조**를 그림으로 그리고, 각 층이 맡는 일을 구분합니다.
- 라이다(LD19)·깊이 카메라·IMU·엔코더 모터의 역할과 데이터가 흐르는 경로를 추적합니다.
- 리튬 배터리 충전·보관 규칙과 첫 전원 투입 점검 절차를 수행합니다.

## MentorPi는 어떤 로봇인가

MentorPi는 **Raspberry Pi 5**를 두뇌로 쓰는 교육용 ROS 2 이동로봇입니다. 같은 상판·센서·제어보드를 공유하고 **바닥(섀시)만 다른** 두 가지 버전이 있습니다.

| 항목 | MentorPi-M1 | MentorPi-A1 |
|---|---|---|
| 섀시 | 메카넘 휠(Mecanum wheel) 4륜 | 애커만 조향(Ackermann steering) |
| 움직임 | 전후·좌우 평행이동·제자리 회전(전방향, holonomic) | 자동차처럼 앞바퀴 조향 + 뒷바퀴 구동(비전방향) |
| 조향 장치 | 없음(네 바퀴 속도 차로 방향 결정) | 앞바퀴 조향용 PWM 서보 |
| 기구 파라미터(원본 `controller` 패키지) | wheelbase 0.1368 m, track 0.1446 m, 바퀴 지름 0.065 m | wheelbase 0.145 m, track 0.133 m, 바퀴 지름 0.067 m |
| 앱 기능 차이 | 모든 라이다 게임 지원 | **라이다 경비(Lidar Guarding) 미지원**, 제자리 회전 불가 |
| 앱 선택 메뉴 | `MentorPi-M1` | `MentorPi-A1` |

두 버전 모두 **TOF 라이다**와 **3D 깊이 카메라**(또는 2축 팬틸트 단안 카메라 버전)를 달고 있어서 지도 작성(SLAM), 자율 내비게이션, 경로 계획, 영상 인식, 비전 추적, 사람-로봇 상호작용을 한 플랫폼에서 실습할 수 있습니다.

:::info 왜 섀시를 두 종류로 배우나요?
메카넘은 **어느 방향으로든 바로** 움직일 수 있어 기구학이 선형대수로 깔끔하게 풀리고, 애커만은 실제 자동차와 같은 **비홀로노믹(nonholonomic)** 제약 — "옆으로는 못 간다" — 을 가집니다. 경로 계획·자율주행 알고리즘이 이 제약을 어떻게 다루는지 비교하는 것이 이동로봇 공부의 핵심입니다. M01·M02에서 두 기구학을 각각 유도합니다.
:::

## 시스템 구조: 두 개의 컴퓨터

MentorPi 안에는 성격이 다른 **컴퓨터가 두 대** 있습니다.

@fig[b01-blocks] MentorPi의 2단 제어 구조. 라즈베리파이 5는 "무엇을 할지"를, RRC Lite(STM32)는 "정확히 그렇게 움직이는 것"을 맡습니다.

| 층 | 장치 | 운영 방식 | 하는 일 |
|---|---|---|---|
| 상위(high-level) | Raspberry Pi 5 (Cortex-A76 4코어 2.4 GHz) | Linux + Docker 컨테이너 안의 ROS 2 Humble | 라이다·카메라 처리, SLAM, 내비게이션, 영상 인식, 앱 서버, `/cmd_vel` → 바퀴 속도 변환 |
| 하위(low-level) | RRC Lite 확장보드의 **STM32F407VET6** (Cortex-M4 168 MHz) | 펌웨어(FreeRTOS) | 엔코더 모터 속도 PID, PWM/버스 서보 펄스 생성, IMU(QMI8658) 읽기, 부저·RGB LED·버튼, 배터리 전압 측정 |

두 컴퓨터는 **UART 직렬 통신**(1 Mbps)으로 연결되고, 라즈베리파이 쪽 파이썬 SDK `ros_robot_controller_sdk.py`가 `0xAA 0x55`로 시작하는 패킷을 주고받습니다(B08에서 패킷을 직접 만들어 봅니다).

왜 굳이 나눌까요? 리눅스는 수많은 프로세스를 번갈아 실행하는 **범용 OS**라서 "정확히 1 ms마다 PWM을 바꾼다" 같은 **실시간(real-time)** 보장이 어렵습니다. 반대로 마이크로컨트롤러는 계산력이 약해 SLAM이나 신경망을 돌릴 수 없습니다. 그래서

- **시간에 민감하고 단순한 일**(모터 PID 10 ms 주기, 서보 펄스 20 ms 주기)은 STM32가,
- **계산이 무겁고 복잡한 일**(지도, 경로, 영상)은 라즈베리파이가

맡는 구조가 로봇에서 표준처럼 쓰입니다.

### 명령이 바퀴까지 가는 길

앱에서 "앞으로"를 누르면 다음 순서로 전달됩니다.

1. 앱 → Wi-Fi → 라즈베리파이의 앱 노드가 `geometry_msgs/Twist`를 `/controller/cmd_vel` 등으로 발행
2. `controller` 패키지의 섀시 기구학(`mecanum.py` / `ackermann.py`)이 $(v_x, v_y, ω_z)$를 **바퀴 4개의 회전수 rps**(초당 회전수)로 변환
3. `ros_robot_controller` 노드가 `/ros_robot_controller/set_motor` 메시지를 받아 SDK의 `board.set_motor_speed([[1, rps1], …])` 호출
4. STM32 펌웨어가 엔코더로 실제 회전수를 재면서 PID로 PWM 듀티를 조절
5. 모터 드라이버가 H-브리지로 모터에 전압 인가 → 바퀴 회전

선속도 $v$ [m/s]와 바퀴 회전수의 관계는 원본 `speed_covert()` 그대로 $rps = v / (π·d)$입니다. 메카넘에서 0.2 m/s는 $0.2 / (π × 0.065) ≈ 0.98$ rps, 즉 바퀴가 1초에 약 한 바퀴 돕니다.

## 구성 부품 살펴보기

### RRC Lite 확장보드

라즈베리파이 위(또는 아래)에 붙는 Hiwonder의 제어보드로, 원본 부록 "RRCLite Hardware Introduction"에 정리된 주요 블록은 다음과 같습니다.

| 블록 | 개수·사양 | MentorPi에서의 쓰임 |
|---|---|---|
| 엔코더 모터 포트 | 4채널(M1~M4) | 네 바퀴 구동(애커만은 뒷바퀴 2개 사용) |
| PWM 서보 포트 | 2개씩 2그룹, 그룹별 전원 점퍼(5 V / 배터리 전압) | 애커만 조향 서보, 카메라 팬틸트 서보 |
| 버스 서보 포트 | 2개 | 로봇팔 등 확장용 |
| RGB LED | 2개 | 상태 표시(프로그래밍 가능) |
| 사용자 버튼 | 2개(KEY1, KEY2) + 리셋 | 기능 전환 |
| 부저 | 1개 | 부팅 완료 알림(삑) |
| IMU | QMI8658 6축(가속도·자이로) | 자세·각속도 → `/imu` |
| 전원 | DC 5 V ~ 12.6 V 입력, 라즈베리파이용 5 V 5 A 출력 | 배터리 하나로 전체 공급 |
| 기타 | I2C 확장, GPIO/SWD, USB 시리얼(펌웨어 다운로드) | 확장·디버깅 |

### 센서

- **라이다(LiDAR)**: MentorPi는 LDROBOT **LD19** 계열 펄스(ToF) 라이다를 씁니다. 원본 사양 기준 측정 거리 0.02~12 m, 스캔 주파수 약 10 Hz, 측정 주파수 4500 Hz이므로 한 바퀴에 약 450개의 점을 얻습니다. ROS 2에서는 `sensor_msgs/LaserScan`으로 `/scan` 토픽에 나옵니다(M05).
- **깊이 카메라**: 컬러 영상과 픽셀별 거리(depth)를 동시에 주는 3D 카메라입니다. 버전 설정 도구에서 `ascamera`로 표시됩니다. 단안 카메라 버전(`usb_cam`)은 대신 2축 팬틸트 서보가 달려 있습니다(M07).
- **IMU**: 확장보드의 QMI8658. 회전 각속도를 적분해 방향을 추정하고, 바퀴 오도메트리와 융합합니다(M03).
- **엔코더**: 각 모터 뒤쪽의 홀 센서가 A/B 두 상의 펄스를 내서 회전량과 방향을 알려 줍니다(B09).

### 사람과의 인터페이스

- **WonderPi 앱**(Android/iOS): Wi-Fi로 연결해 주행·라이다·색 추적·라인 추종·제스처 게임 실행(B02)
- **무선 조이패드**: USB 수신기가 로봇에 미리 꽂혀 있음(B02)
- **VNC 원격 데스크톱**: 개발용(B03)

## 배터리와 전원 관리

MentorPi는 **리튬 폴리머(LiPo) 배터리** 하나로 모터·라즈베리파이·센서를 모두 구동합니다. 원본 "Charging & Usage Guide"의 규칙을 이유와 함께 정리합니다.

| 규칙 | 이유 |
|---|---|
| 첫 사용 전 **완전 충전**(약 1시간). 배송 중 안전을 위해 완충되어 있지 않음 | 리튬 배터리는 운송 규정상 부분 충전 상태로 출고됩니다 |
| 충전 순서: 전원 스위치 **OFF** → 배터리 커넥터를 빨강-빨강, 검정-검정으로 연결 → 배터리 DC 플러그에 충전기 연결 | 극성을 반대로 꽂으면 보드가 즉시 손상될 수 있습니다 |
| 충전기 표시등 **빨강 = 충전 중, 초록 = 완충**. 완충 후 바로 분리 | 과충전은 셀 팽창·수명 단축의 주원인입니다 |
| 전압이 **6.4 V 아래**로 떨어지면 충전 | 전압이 낮으면 모터 부하 순간 라즈베리파이 전원이 떨어져 재부팅될 수 있습니다 |
| 장기 보관 시 완충 → 확장보드 스위치 OFF → 배터리 선 분리, 서늘하고 건조한 곳 | 연결된 채로 두면 대기 전류로 과방전됩니다 |
| 충격·투척·밟기 금지, 강한 정전기·자기장 환경 금지 | 셀 내부 단락과 보호 회로 손상 방지 |

:::tip 배터리 전압은 코드로도 읽을 수 있습니다
확장보드는 배터리 전압을 mV 단위 정수로 보고합니다. ROS 2가 돌고 있다면 `ros2 topic echo /ros_robot_controller/battery`로 확인할 수 있습니다(`std_msgs/UInt16`, 예: `7650` → 7.65 V). B08에서 SDK의 `board.get_battery()`로 직접 읽어 봅니다.
:::

## 사용 시 주의사항

원본이 강조하는 운용 수칙입니다. 뒤 챕터와 연결해 이유를 기억해 두세요.

1. **높은 곳 가장자리에 두지 않습니다.** 바닥이 평평한 곳에서 씁니다. 책상 위에서 모터 테스트를 할 때는 바퀴가 뜨도록 받침을 둡니다.
2. **직진이 한쪽으로 휘면** "9. Motion Control — IMU, Linear Velocity, and Angular Velocity Calibration"으로 보정합니다(M03). 보정은 편차를 **줄일 뿐** 없애지는 못합니다. 바퀴 지름 오차·바닥 미끄러짐 같은 하드웨어 편차는 항상 남습니다.
3. **조이패드 수신기**가 꽂혀 있는지 전원 투입 전에 확인합니다.
4. 같은 공간에 로봇이 여러 대 있으면 **조이패드가 엉뚱한 로봇과 짝지어질 수 있습니다.** 여러 대일 때는 조이패드 사용을 피합니다.
5. 애커만 버전은 **라이다 경비** 기능을 지원하지 않습니다(제자리 회전이 불가능하기 때문).
6. 지도 작성을 시작할 때는 로봇이 **평평한 벽이나 닫힌 상자**를 바라보게 합니다. 라이다가 특징점을 많이 얻어야 초기 정합이 안정됩니다(M09).
7. 로봇이 다닐 영역은 **360° 모두** 라이다로 훑어야 지도에 빈 곳이 없습니다. 넓은 곳은 큰 윤곽을 먼저 만들고 세부를 나중에 스캔합니다.

## 실습 (URDF 뷰어)

MentorPi의 3D 모델(URDF)을 열어 부품 배치와 좌표계를 확인합니다. URDF 문법은 R06·M08에서 자세히 다룹니다.

@btn[~/tools/urdf-viewer.html] URDF 뷰어 열기

:::task 모델에서 찾아보기
1. 메카넘 모델과 애커만 모델을 번갈아 불러와 바퀴 배치와 앞바퀴 조향 관절의 유무를 비교합니다.
2. `base_footprint`(바닥 투영점), `base_link`(몸체), `laser_frame`(라이다), `imu_link`, `camera_link`를 찾아 각 원점의 위치를 적어 봅니다.
3. 라이다가 몸체 중심에서 앞/뒤 어느 쪽에, 몇 cm 높이에 있는지 추정합니다. 라이다보다 **낮은 장애물은 스캔에 잡히지 않는다**는 점(M06 라이다 추종 시 물체가 라이다 높이보다 높아야 하는 이유)을 확인합니다.
:::

좌표계 규약은 ROS REP-103을 따릅니다: **x 전방, y 좌측, z 위**, 각도는 **반시계 방향이 +**, 단위는 m·rad·s. 이 규약은 이후 모든 챕터에서 그대로 씁니다.

## 실습 (실물)

:::safety
- 충전·배선 작업은 반드시 **전원 스위치 OFF** 상태에서 합니다.
- 첫 전원 투입은 **바퀴가 바닥에서 뜬 상태**(받침 위)에서 합니다. 앱·조이패드가 예상과 다르게 동작해도 로봇이 달려 나가지 않습니다.
- 배터리 커넥터는 **빨강-빨강, 검정-검정**. 반대로 꽂지 않습니다.
- 배터리가 부풀었거나 뜨겁다면 즉시 사용을 멈추고 담당자에게 알립니다.
:::

### 1. 구성품 확인

포장 목록(원본 "MentorPi Introduction"의 Packing List)과 대조해 로봇 본체, 배터리 충전기, 무선 조이패드, 카드 리더·SD 카드, 드라이버 등 부속을 확인합니다. 단안 카메라 버전은 카메라와 팬틸트 부품을 조립 설명서("Assembly")대로 장착하고, 카메라 전원 핀 헤더의 **5 V 점퍼 캡**이 꽂혀 있는지 봅니다(출고 시 연결됨).

### 2. 충전

1. 전원 스위치 OFF
2. 배터리 커넥터 연결(빨강-빨강, 검정-검정)
3. 섀시 측면/바닥의 DC 플러그를 꺼내 충전기 연결
4. 충전기 표시등이 초록이 되면 분리

### 3. 첫 전원 투입 점검

확장보드 스위치를 켜고 약 1분 기다린 뒤 아래 표로 점검합니다(원본 "Get Started").

| 모듈 | 확인 방법 | 정상 상태 |
|---|---|---|
| 확장보드 LED | LED 관찰 | 기본 AP 직접 연결 모드: **LED1 켜짐 유지, LED2 1초에 한 번 깜빡임** |
| 부저 | 소리 | ROS 구성 완료 시 **"삑" 한 번** → 보드 하드웨어(IMU 포함) 정상 |
| 라이다 | 회전 관찰 | 전원 후 몇 초 안에 회전 시작 |
| 카메라 | 앱 "Robot Control" 화면 | 실시간 영상 표시(팬틸트 버전은 화면 드래그로 카메라 회전) |
| 엔코더 모터 + STM32 | 앱/조이패드로 조작 | 정상 주행 |

전원을 켜면 이름이 **`HW`로 시작하는 Wi-Fi 핫스팟**이 생깁니다(비밀번호 `hiwonder`). 다음 챕터에서 이 핫스팟으로 앱과 연결합니다.

:::check 체크포인트
- [ ] 부팅 후 부저가 한 번 울렸다.
- [ ] 라이다가 회전한다.
- [ ] 휴대폰 Wi-Fi 목록에서 `HW-…` 핫스팟이 보인다.
- [ ] 명령이 바퀴까지 가는 5단계를 순서대로 말할 수 있다.
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 전원을 켜도 부저가 울리지 않음 | IMU·부저 등 보드 하드웨어 이상, 또는 부팅이 아직 끝나지 않음 | 1~2분 더 기다린 뒤 재부팅. 계속되면 판매처 지원(support@hiwonder.com)에 문의 |
| `HW-…` 핫스팟이 보이지 않음 | LAN(STA) 모드로 설정되어 핫스팟을 만들지 않음, 또는 부팅 실패 | LED1이 켜져 있고 LED2가 1초 간격으로 깜빡이는지 확인. 빠르게 깜빡이면 LAN 모드에서 네트워크를 찾는 중(B02) |
| 주행 중 갑자기 재부팅됨 | 배터리 전압 저하로 모터 기동 전류 순간에 5 V가 떨어짐 | 6.4 V 이하면 충전. 완충 후에도 반복되면 배터리 노화 의심 |
| 직진 명령에 한쪽으로 휨 | 바퀴 지름·모터 특성 차이, 바닥 미끄러짐 | M03의 선속도·각속도 보정. 완전히 없앨 수는 없음 |
| 조이패드가 다른 로봇을 조종함 | 여러 로봇이 같은 공간에서 자동 페어링 | 여러 대 운용 시 조이패드 대신 앱/코드로 제어 |
| 애커만에서 라이다 경비 메뉴가 동작하지 않음 | 애커만은 제자리 회전 불가라 미지원 | 정상. 메카넘 버전에서 실습 |

## 과제

:::task 기본
1. MentorPi-M1과 A1 각각에 대해 "할 수 있는 움직임 / 할 수 없는 움직임"을 3개씩 적어 봅니다.
2. 바퀴 지름 0.065 m인 메카넘 섀시가 0.1 m/s, 0.2 m/s, 0.5 m/s로 직진할 때 바퀴 rps를 계산합니다($rps = v/(π·d)$).
:::

:::task 심화
3. 라즈베리파이가 모터 PWM을 직접 만들지 않고 STM32에 맡기는 이유를 **실시간성**, **계산량**, **안전**(라즈베리파이가 멈춰도 모터 정지) 관점에서 한 문단으로 설명합니다.
4. LD19가 10 Hz로 회전하며 초당 4500점을 잰다면 각도 분해능은 몇 도인지 계산하고, 3 m 거리에서 인접한 두 점 사이 간격이 몇 cm인지 구합니다.
:::
