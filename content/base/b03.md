## 학습 목표

- VNC Viewer로 MentorPi 데스크톱에 원격 접속하고, SSH와의 차이를 설명합니다.
- 버전 설정 도구로 **섀시 종류**(`MentorPi_Mecanum`/`MentorPi_Acker`)와 **카메라 종류**(`ascamera`/`usb_cam`)를 바꾸고 적용 순서를 지킵니다.
- 호스트(라즈베리파이 OS)와 **Docker 컨테이너**(ROS 2 Humble)의 경계를 구분하고, 컨테이너에 들어가 `ros2_ws/src`의 패키지 구조를 탐색합니다.
- 앱 자동 실행 서비스를 끄고(`~/.stop_ros.sh`) 다시 켜는 이유와 방법을 익힙니다.
- PWM 서보 편차(offset)를 보정하고, 그 값이 어디에 저장되어 어떻게 적용되는지 추적합니다.

## 원격 접속: VNC와 SSH

로봇에는 모니터가 없으므로 PC에서 원격으로 접속해 개발합니다.

| 방식 | 보이는 것 | 장점 | 도구 |
|---|---|---|---|
| **VNC** | 라즈베리파이 **데스크톱 화면 전체** | GUI 도구(버전 설정, 색 임계값 조정, RViz) 사용 가능 | VNC Viewer |
| **SSH** | 터미널(명령행)만 | 가볍고 빠름, 파일 전송 쉬움 | MobaXterm, `ssh` 명령 |

VNC는 화면 픽셀을 압축해 계속 보내므로 Wi-Fi 대역폭을 많이 씁니다. 원본이 **5 GHz 대역을 지원하는 무선랜**을 권장하는 이유입니다. 코드 편집·명령 실행만 할 때는 SSH가 훨씬 쾌적합니다(B07).

### VNC 접속 절차

1. 교재 폴더의 `VNC-Viewer-6.17.731-Windows` 설치(언어 English → Next → 약관 동의 → Install → Finish)
2. 로봇 전원 ON → LED1 점등, 부저 "삑" 확인
3. PC Wi-Fi를 `HW-…` 핫스팟에 연결(비밀번호 `hiwonder`)
4. VNC Viewer 주소창에 **`192.168.149.1`** 입력(LAN 모드면 앱에서 확인한 IP) → "안전하지 않음" 경고는 Continue
5. 비밀번호 **`raspberrypi`**(계정을 물으면 **`pi`**), "Remember password" 체크 → OK
6. 로그인 후 뜨는 경고 대화상자는 정상 → OK. **검은 화면**만 보이면 라즈베리파이를 재부팅

```bash
# SSH로 접속하는 경우(PC의 터미널/PowerShell)
ssh pi@192.168.149.1        # 비밀번호 raspberrypi
```

### 데스크톱 아이콘

| 아이콘 | 기능 |
|---|---|
| 버전 설정 도구(Robot system configuration) | 섀시·카메라 종류 전환 |
| PC 소프트웨어 | 팬틸트 위치, 색 임계값(LAB) 조정 |
| LX 터미널 / Terminator | 명령행. `Ctrl+Alt+T`로도 열림 |
| 파일 관리자, 휴지통, 브라우저 | 일반 데스크톱 기능 |
| 전원 | 종료·재시작·로그아웃 |

## 버전 설정: 섀시와 카메라

같은 이미지가 여러 하드웨어 조합을 지원하므로, **지금 로봇이 어떤 조합인지** 소프트웨어에 알려 줘야 합니다.

1. 데스크톱의 **로봇 시스템 설정 도구**를 더블클릭 → Execute
2. **카메라 종류**: `ascamera` = 깊이 카메라, `usb_cam` = 2축 팬틸트 단안 카메라
3. **로봇 종류**: `MentorPi_Mecanum` = 메카넘, `MentorPi_Acker` = 애커만
4. **Save → Apply → Exit** 순서로 클릭(이 순서를 지켜야 전환됩니다)
5. 부저가 "삑" 울리면 전환 완료

:::info 이 설정은 어디에 쓰이나요?
선택값은 컨테이너 안에서 **환경 변수**로 모든 ROS 2 노드에 전달됩니다. 예를 들어 조이패드 노드는 `os.environ['MACHINE_TYPE']`이 `MentorPi_Mecanum`이면 왼쪽 스틱 좌우를 평행이동(`linear.y`)으로, `MentorPi_Acker`면 조향으로 해석합니다(B02). 카메라 관련 launch 파일은 `DEPTH_CAMERA_TYPE`이 `ascamera`인지로 분기합니다. 설정이 실제 하드웨어와 다르면 **노드는 떠도 동작이 엉뚱해집니다.**
:::

```bash
# 컨테이너 안에서 현재 설정 확인
echo $MACHINE_TYPE
echo $DEPTH_CAMERA_TYPE
```

## 시스템 구조: 호스트와 컨테이너

@fig[b03-layers] 라즈베리파이 OS(호스트) 위에 Docker 컨테이너가 있고, MentorPi의 ROS 2 워크스페이스는 컨테이너 안에 있습니다.

### 호스트(라즈베리파이 OS)의 홈 디렉터리

VNC로 들어가 터미널에서 `ls`를 치면 보이는 주요 폴더입니다.

| 폴더 | 역할 |
|---|---|
| `MentorPi` | 버전 설정(디버깅) 도구 |
| `hiwonder-toolbox` | Wi-Fi(AP/STA) 관리 도구 |
| `docker` | 컨테이너와 **공유되는 폴더**(호스트 ↔ 컨테이너 파일 교환) |

MentorPi의 기능 프로그램과 소스는 **모두 Docker 컨테이너 안**에 있습니다. 왜 컨테이너일까요? ROS 2 Humble은 Ubuntu 22.04를 기준으로 배포되는데, 라즈베리파이 5 공식 OS는 Debian 계열입니다. 컨테이너에 Ubuntu + ROS 2 환경을 통째로 넣으면 호스트 OS와 무관하게 **똑같은 환경을 재현**할 수 있습니다(자세한 원리는 B10).

### 컨테이너에 들어가기

```bash
docker ps -a                                   # 컨테이너 목록: ID, IMAGE, CREATED, STATUS
docker exec -it -u ubuntu -w /home/ubuntu mentorpi /bin/bash   # 이름(mentorpi) 또는 ID로 진입
```

- `-it`: 대화형 터미널, `-u ubuntu`: ubuntu 사용자로, `-w /home/ubuntu`: 시작 디렉터리
- 컨테이너 ID는 **다른 것과 구별만 되면 앞 몇 글자**만 써도 됩니다(예: `adb8`).
- 나올 때: `exit`. 원본은 `Ctrl+P, Ctrl+Q`(컨테이너는 둔 채 빠져나오기)도 소개합니다. `docker exec`로 연 셸에서 `exit`하면 **그 셸만 끝나고** 컨테이너는 계속 돕니다.

:::tip Terminator가 열릴 때마다 자동으로 컨테이너로
Terminator 창에서 오른쪽 클릭 → Preferences → Profiles → Command → "Run a custom command"를 체크하고
`docker exec -it -u ubuntu -w /home/ubuntu mentorpi /bin/bash`를 넣으면, 새 터미널이 곧바로 컨테이너 안에서 열립니다. 이후 교재의 `ros2 …` 명령은 모두 이 터미널에서 칩니다. 프롬프트의 사용자·호스트 이름으로 **지금 호스트인지 컨테이너인지** 항상 확인하는 습관을 들이세요.
:::

### 컨테이너 안의 구조

```bash
ls ~                  # ros2_ws  share  software ...
cd ~/ros2_ws/src && ls
```

| 경로 | 내용 |
|---|---|
| `~/ros2_ws` | MentorPi 기능을 담은 ROS 2 워크스페이스 |
| `~/share` | 호스트와 공유되는 드라이브 |
| `~/software` | PC 소프트웨어, 색 임계값 조정 도구, 서보 편차 도구 |

`~/ros2_ws/src`의 패키지:

| 패키지 | 역할 | 주로 다루는 챕터 |
|---|---|---|
| `app` | 앱 게임 기능(라이다·추적·라인 등) | M06, A01~A04 |
| `example` | 예제 게임 | A05~A11 |
| `bringup` | 앱 기능 기동 묶음 | — |
| `driver` | 하위 제어: `controller`(기구학·오도메트리), `ros_robot_controller`(STM32 통신), `sdk` | M01~M04, B08, B09 |
| `interfaces` | 커스텀 메시지·서비스 | R04 |
| `peripherals` | 라이다·카메라·조이패드·IMU 드라이버와 launch | M05, M07 |
| `navigation` | Nav2 내비게이션 | M11~M13 |
| `slam` | 지도 작성 | M09, M10 |
| `yolov5_ros2` | YOLOv5 추론 | A07, A08, A10 |
| `simulations` | URDF 모델(`mentorpi_description`) | M08 |

## 자동 실행 서비스 끄고 켜기

로봇이 켜지면 앱 서비스(섀시 제어, 카메라, 조이패드 등)가 **자동으로** 떠 있습니다. 여러분이 직접 노드를 실행하면 같은 장치(시리얼 포트, 카메라)나 같은 토픽을 두 프로그램이 동시에 쓰게 되어 충돌합니다. 그래서 교재의 거의 모든 명령 실습은 이렇게 시작합니다.

```bash
~/.stop_ros.sh                       # 앱 자동 실행 서비스 중지
ros2 launch app lidar_node.launch.py debug:=true   # (예) 필요한 기능만 직접 실행
```

실습이 끝나면 앱 기능을 되살립니다. 이 명령은 **호스트(라즈베리파이 OS) 터미널**에서 실행합니다(컨테이너 안이 아님).

```bash
sudo systemctl restart start_node.service
```

재부팅해도 자동 실행 서비스가 다시 켜집니다. 서비스가 다시 떠서 부저가 울릴 때까지 기다린 뒤 앱을 쓰세요.

## 서보 편차 보정

애커만 섀시(조향 서보)나 단안 카메라(팬틸트 서보) 버전에는 PWM 서보가 있습니다. 조립 공차 때문에 **중립(1500 µs)을 줘도 바퀴가 살짝 틀어져** 직진하지 않을 수 있습니다. 이를 소프트웨어로 보정합니다.

### 편차(offset)의 의미

STM32 펌웨어는 서보에 실제로 내보내는 펄스를 다음처럼 계산합니다(원본 펌웨어 `pwm_servo.c`).

```text
실제 펄스(duty_raw) = 목표 펄스(current_duty) + offset       offset은 −100 ~ +100 µs로 제한
```

1도는 약 11.1 µs이므로(B09) offset ±100은 약 ±9°입니다. 즉 편차 보정은 **조립이 크게 틀어진 것을 고치는 도구가 아니라** 몇 도 이내의 미세 조정 도구입니다. 그 이상 틀어졌으면 서보 혼(horn)을 빼서 중립 위치에 다시 끼워야 합니다.

### 보정 절차

1. VNC 접속 후 터미널에서 자동 실행 서비스 중지: `~/.stop_ros.sh`
2. 편차 조정 스크립트 실행: `./Servo.sh`
3. 창에 나타난 **슬라이더 4개**가 확장보드의 **J3~J6** 서보 포트에 대응합니다. 슬라이더를 움직이면 해당 서보가 실제로 돌아가므로, 바퀴·카메라를 보며 정중앙에 맞춥니다.
4. 마음에 들지 않으면 **Set Center Position**으로 편차를 되돌리고 다시 조정
5. **Save Offsets**로 저장
6. 섀시 제어 노드를 실행해 저장값이 적용되는지 확인

```bash
ros2 launch ros_robot_controller ros_robot_controller.launch.py
```

`ros_robot_controller` 노드는 시작할 때 `/home/ubuntu/software/Servo_upper_computer/servo_config.yaml`을 읽어 ID 1~4 서보에 `board.pwm_servo_set_offset(id, offset)`을 호출합니다. 로그에 서보별 편차 설정 메시지가 찍히면 성공입니다. 이렇게 **저장 → 부팅 시 자동 적용** 구조라서 한 번만 보정하면 이후 모든 기능에 반영됩니다.

## 실습 (실물)

:::safety
- 서보 편차 조정 중에는 서보가 갑자기 움직이므로 **손가락을 조향 링크·팬틸트 사이에 두지 않습니다.**
- 섀시 제어 노드를 직접 실행하면 바퀴가 명령에 반응할 수 있습니다. **바퀴를 띄운 상태**에서 진행합니다.
- 실습 후에는 `sudo systemctl restart start_node.service`(호스트) 또는 재부팅으로 앱 서비스를 복구합니다.
:::

:::task 따라 하기
1. VNC로 접속해 데스크톱 아이콘을 하나씩 확인합니다.
2. 버전 설정 도구를 열어 **현재 설정이 실제 하드웨어와 일치하는지** 확인합니다(바꿀 필요가 없으면 Exit).
3. Terminator에서 `docker ps -a`로 컨테이너 이름·ID·상태를 기록하고, `docker exec`로 들어가 `echo $MACHINE_TYPE`을 확인합니다.
4. `cd ~/ros2_ws/src && ls`로 패키지 목록을 보고, `ls driver/controller/controller`에서 `mecanum.py`, `ackermann.py`를 찾아 `cat`으로 열어 봅니다.
5. 컨테이너 안에서 `ros2 node list`, `ros2 topic list`를 실행해 자동 실행 중인 노드와 토픽을 관찰합니다(`/ros_robot_controller/…`, `/controller/cmd_vel`, `/scan` 등).
6. `~/.stop_ros.sh` 후 다시 `ros2 node list` → 노드가 사라진 것을 확인하고, 호스트 터미널에서 `sudo systemctl restart start_node.service`로 복구합니다.
7. (애커만/단안 버전) `./Servo.sh`로 편차를 보정하고 저장 후 `ros2 launch ros_robot_controller ros_robot_controller.launch.py`로 적용을 확인합니다.
:::

:::check 체크포인트
- [ ] VNC와 SSH의 쓰임새 차이를 설명할 수 있다.
- [ ] 프롬프트를 보고 지금 호스트인지 컨테이너인지 구분할 수 있다.
- [ ] `~/.stop_ros.sh`를 먼저 실행해야 하는 이유(장치·토픽 충돌)를 말할 수 있다.
- [ ] 서보 편차가 저장되는 파일 경로와 적용 시점을 안다.
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| VNC 접속 후 검은 화면에 마우스만 보임 | 데스크톱 세션이 제대로 시작되지 않음 | 라즈베리파이 재부팅 후 재접속 |
| VNC가 `192.168.149.1`에 연결 안 됨 | PC가 로봇 핫스팟이 아닌 다른 Wi-Fi에 연결, 또는 LAN 모드 | PC Wi-Fi 확인. LAN 모드라면 앱에서 IP 확인 |
| 화면이 끊기고 느림 | 2.4 GHz 혼잡, VNC 대역폭 | 5 GHz 무선랜 사용, 창 크기·화질 낮추기, 명령 작업은 SSH로 |
| `ros2: command not found` | 호스트 터미널에서 실행함 | `docker exec …`로 컨테이너에 들어간 뒤 실행 |
| `Error: No such container: …` | 컨테이너 이름/ID 오타, 컨테이너 중지 상태 | `docker ps -a`로 확인, 중지 상태면 `docker start mentorpi` |
| 직접 실행한 노드가 시리얼 포트 오류·중복 동작 | 자동 실행 서비스가 같은 장치를 쓰고 있음 | 먼저 `~/.stop_ros.sh` |
| 버전을 바꿨는데 동작이 그대로 | Save → Apply → Exit 순서 누락 | 순서대로 다시, 부저 확인 |
| 편차 슬라이더를 끝까지 움직여도 중앙이 안 맞음 | offset 한계(±100 µs ≈ ±9°) 초과 | 서보 혼을 빼서 중립 위치에 다시 조립 |
| 실습 후 앱이 연결 안 됨 | 자동 실행 서비스를 끈 상태 | 호스트에서 `sudo systemctl restart start_node.service` 또는 재부팅 |

1. 호스트의 `docker` 폴더와 컨테이너의 `~/share`에 각각 파일을 만들어, 반대쪽에서 보이는지 확인하고 어떤 경로끼리 연결되어 있는지 정리합니다.
2. `ros2 topic list` 결과에서 `/ros_robot_controller/`로 시작하는 토픽을 모두 적고, 각각 무엇을 제어/보고하는지 이름으로 추측합니다(B08·B09에서 확인).
:::

:::task 심화
3. 서보 편차 offset = +45일 때 1500 µs 명령에 실제 나가는 펄스와 대략의 각도 변화를 계산합니다.
4. `~/ros2_ws/src/driver/ros_robot_controller`의 노드 소스를 열어 어떤 토픽을 구독하고 어떤 SDK 함수를 호출하는지 표로 만듭니다.
:::
