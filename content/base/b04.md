## 학습 목표

- 운영체제의 역할과 리눅스 배포판(Ubuntu·Debian 등)의 관계를 설명하고, MentorPi에서 어떤 배포판이 어디에 쓰이는지 구분합니다.
- VirtualBox/VMware에 Ubuntu를 설치하고 **소프트웨어 소스(미러)**와 **공유 폴더**를 설정합니다.
- 리눅스 디렉터리 트리(`/`, `/home`, `/dev`, `/etc` …)를 탐색하고 절대·상대 경로를 자유롭게 씁니다.
- `명령 + 옵션 + 대상` 형식을 이해하고 자주 쓰는 명령(`ls cd pwd cp mv rm mkdir find …`)과 도움말(`--help`, `man`, Tab 자동완성)을 활용합니다.
- `rwx` 권한과 8진수 표기를 읽고 `chmod`·`sudo`·`su`로 권한을 다룹니다.

## 운영체제와 리눅스

컴퓨터는 하드웨어(CPU·메모리·디스크·키보드)와 소프트웨어로 이루어집니다. **운영체제(OS, Operating System)**는 그 사이의 중개자로서 프로그램 실행, 메모리·파일·장치 같은 자원 관리, 기본 서비스 제공을 맡습니다.

리눅스(Linux)는 Windows처럼 운영체제이지만 **오픈 소스**라는 점이 다릅니다. 서버, 임베디드 기기, 데스크톱 세 분야에서 널리 쓰이며, 특히 서버와 로봇(ROS)의 표준 플랫폼입니다.

| 특징 | 로봇 개발에서의 의미 |
|---|---|
| 무료·오픈 소스 | 라즈베리파이 같은 저가 보드에 자유롭게 탑재 |
| 다중 사용자·다중 작업 | 여러 ROS 노드가 동시에 돌고, PC와 로봇에서 동시에 원격 접속 |
| 강력한 패키지 관리(`apt`) | `sudo apt install ros-humble-…`처럼 한 줄로 설치 |
| 안정성·원격 관리 | 모니터 없는 로봇을 SSH로 운용 |

### 주요 배포판

리눅스 **커널**에 각종 도구와 패키지 관리 방식을 묶은 것을 **배포판(distribution)**이라 합니다.

| 배포판 | 특징 | MentorPi에서 |
|---|---|---|
| **Debian** | 1993년 출시, 매우 안정적, 3만 개 이상 패키지 | 라즈베리파이 OS(호스트)의 기반(bookworm) |
| **Ubuntu** | Debian 기반, 사용자 친화적 데스크톱, 넓은 하드웨어 지원 | **컨테이너 안(22.04)** — ROS 2 Humble의 기준 OS. 실습용 가상 머신 |
| RHEL / CentOS / Fedora | Red Hat 계열 서버·데스크톱 | — |
| openSUSE | 유럽에서 인기 있는 배포판 | — |

즉 MentorPi는 **Debian(호스트) 위에서 Ubuntu(컨테이너)**를 돌리는 구조입니다(B03). 두 배포판 모두 `apt` 패키지 관리자를 쓰므로 명령은 거의 같습니다.

## PC에 실습 환경 만들기: 가상 머신

**가상 머신(VM, Virtual Machine)**은 Windows 위에서 다른 OS를 통째로 돌리는 소프트웨어입니다. 로봇을 망가뜨릴 걱정 없이 리눅스 명령을 연습하고, 나중에 PC 쪽 ROS 2(RViz 등)를 설치하는 데 씁니다.

### 설치 흐름(VirtualBox 기준)

1. 교재 폴더의 VirtualBox 설치 파일 실행 → 설치 경로 선택 → 기본값으로 Next → Yes/Install → Finish
2. Ubuntu 이미지(교재 제공 압축 파일 또는 공식 ISO)로 새 가상 머신 생성: 메모리 4 GB 이상, 디스크 30 GB 이상 권장
3. 설치 후 로그인

VMware Workstation을 쓸 때도 흐름은 같습니다("Create a New Virtual Machine" → Custom → 단계별 설정). VMware는 30일 평가판입니다.

### 소프트웨어 소스(미러) 바꾸기

`apt`가 패키지를 내려받는 서버를 **소스(source)** 또는 **미러(mirror)**라고 합니다. 앱 스토어의 서버와 같은 역할입니다. 기본 서버가 멀어 느리거나 오류가 나면 가까운 미러로 바꿉니다.

1. Settings → **Software & Updates** 실행
2. "Download from" → **Other…** → 목록에서 국내 미러(예: `mirror.kakao.com`, `ftp.kaist.ac.kr`) 선택, 또는 **Select Best Server**
3. 비밀번호 입력 → 목록 갱신

```bash
sudo apt update          # 새 소스에서 패키지 목록 다시 받기
```

:::info 소스 목록 파일
GUI로 바꾼 내용은 결국 `/etc/apt/sources.list`(또는 `/etc/apt/sources.list.d/*`) 파일에 기록됩니다. 라즈베리파이 OS에서는 이 파일을 `nano`로 직접 편집해 미러를 바꿉니다(B07).
:::

### 공유 폴더

PC(호스트)와 가상 머신 사이에 파일을 주고받는 폴더입니다. **처음 설정할 때 공유 폴더는 비어 있어야** 설정이 실패하지 않습니다.

**VirtualBox**

1. 가상 머신 Settings → Shared Folders → 폴더 경로·이름(`share`) 지정, Auto-mount 체크, 마운트 지점 `/mnt/share`
2. Devices → **Insert Guest Additions CD image** → 실행·비밀번호 입력 → 설치 완료
3. 터미널에서

```bash
sudo mkdir /mnt/share
sudo mount -t vboxsf share /mnt/share      # 첫 share = 호스트에서 지정한 공유 이름
sudo usermod -aG vboxsf $(whoami)          # 현재 사용자를 vboxsf 그룹에 추가 → 재부팅
```

**VMware**

1. VM 끄기 → Settings → Options → Shared Folders → Always Enabled → Add(예: `share_test`)
2. 부팅 후

```bash
sudo apt install open-vm-tools
ls /mnt/                                   # hgfs 폴더가 있는지 확인, 없으면 sudo mkdir /mnt/hgfs
sudo mount -t fuse.vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other
```

재부팅마다 마운트하기 번거로우면 `/etc/fstab`에 한 줄을 추가해 자동 마운트합니다.

```text
.host:/  /mnt/hgfs  fuse.vmhgfs-fuse  auto,allow_other  0  0
```

## 터미널과 명령 형식

GUI로도 파일을 복사·이동할 수 있지만, 로봇은 모니터 없이 원격으로 쓰는 일이 많아 **터미널(terminal)**이 주 무대입니다. `Ctrl+Alt+T`로 엽니다.

```text
hiwonder@ubuntu:~$
   │       │    │ └─ $ 일반 사용자 / # 관리자(root)
   │       │    └─── 현재 디렉터리 (~ = 홈)
   │       └──────── 호스트 이름
   └──────────────── 사용자 이름
```

명령은 **`명령 [옵션] [대상]`** 형식이며 각 부분은 공백으로 구분합니다.

- 짧은 옵션: `-` + 한 글자(`-l`, `-a`). 여러 개를 합칠 수 있습니다: `ls -l -a` = `ls -la`
- 긴 옵션: `--` + 단어(`--help`). 합칠 수 없습니다.
- 대상은 여러 개일 수 있습니다: `cp a.txt b.txt backup/`
- 리눅스는 **대소문자를 구분**합니다. `Desktop`과 `desktop`은 다른 폴더입니다.

## 디렉터리 구조

리눅스는 모든 것을 **하나의 트리**로 다룹니다. 맨 위는 루트(root) `/`이고, Windows의 `C:`·`D:` 같은 드라이브 구분 대신 저장 장치를 트리의 한 지점에 **마운트(mount)**합니다.

```bash
cd /            # 루트로 이동
sudo apt-get install tree
tree -L 1       # 1단계 하위 폴더만 트리로 표시
```

| 디렉터리 | 내용 | 로봇에서의 예 |
|---|---|---|
| `/bin`, `/sbin` | 기본 명령·시스템 명령 | `ls`, `cp` |
| `/boot` | 부팅 파일 | 라즈베리파이 `config.txt`(B07) |
| `/dev` | **장치 파일** | `/dev/ttyAMA0`(UART), `/dev/video0`(카메라), `/dev/input/js0`(조이패드) |
| `/etc` | 시스템 설정 파일 | `/etc/apt/sources.list`, `/etc/NetworkManager/` |
| `/home` | 사용자 홈 | `/home/pi`(호스트), `/home/ubuntu`(컨테이너) |
| `/lib` | 공유 라이브러리 | |
| `/media`, `/mnt` | 이동식 저장장치·임시 마운트 지점 | USB 메모리, 공유 폴더 |
| `/opt` | 추가 소프트웨어 | `/opt/ros/humble` |
| `/proc`, `/sys` | 커널이 보여 주는 시스템 정보(가상 파일) | `/sys/class/thermal/thermal_zone0/temp` |
| `/root` | root 사용자의 홈 | |
| `/tmp` | 임시 파일(재부팅 시 삭제) | |
| `/usr` | 사용자 프로그램·라이브러리 | `/usr/bin/python3` |
| `/var` | 자주 바뀌는 데이터(로그 등) | `/var/log` |

@fig[b04-tree] 절대 경로는 `/`에서, 상대 경로는 현재 위치에서 출발합니다. `.`은 현재, `..`은 상위 디렉터리, `~`는 홈입니다.

:::tip 장치도 파일이다
`/dev/ttyAMA0`에 바이트를 쓰면 UART로 전송되고, `/sys/class/thermal/thermal_zone0/temp`를 읽으면 CPU 온도가 나옵니다. 리눅스의 "모든 것은 파일" 철학 덕분에, 로봇의 확장보드 SDK도 결국 **시리얼 장치 파일을 열고 읽고 쓰는** 프로그램입니다(B08).
:::

## 자주 쓰는 명령

| 명령 | 원말 | 기능 | 예 |
|---|---|---|---|
| `ls` | list | 목록 | `ls -la`(숨김 포함 자세히) |
| `cd` | change directory | 이동 | `cd ~/ros2_ws/src`, `cd ..` |
| `pwd` | print working directory | 현재 위치 | |
| `mkdir` | make directory | 폴더 생성 | `mkdir -p a/b/c` |
| `touch` | | 빈 파일 생성·시간 갱신 | `touch hello.py` |
| `cp` | copy | 복사 | `cp -r src/ backup/` |
| `mv` | move | 이동·이름 바꾸기 | `mv old.py new.py` |
| `rm` | remove | 삭제(휴지통 없음!) | `rm file`, `rm -r dir` |
| `cat` | concatenate | 파일 내용 출력 | `cat /etc/hostname` |
| `echo` | | 문자열 출력 | `echo $HOME` |
| `find` | | 파일 찾기 | `find ~ -name "*.launch.py"` |
| `grep` | | 내용 검색 | `grep -rn "cmd_vel" ~/ros2_ws/src/app` |
| `man` | manual | 매뉴얼 | `man cp` |
| `sudo` | superuser do | 관리자 권한으로 실행 | `sudo apt update` |
| `ping` | | 네트워크 연결 확인 | `ping 192.168.149.1` |
| `date` | | 날짜·시간 | |
| `clear` | | 화면 지우기 | `Ctrl+L`도 같음 |
| `shutdown`, `reboot` | | 종료·재시작 | `sudo shutdown -h now` |

### 도움말과 단축키

- `명령 --help`: 간단한 사용법. 예: `ls --help`
- `man 명령`: 자세한 매뉴얼. **Space** 다음 쪽, **B** 이전 쪽, **Enter** 한 줄 아래, **q** 종료
- **Tab**: 명령·파일 이름 자동완성. 후보가 여러 개면 두 번 눌러 목록 표시. `cd Pict` + Tab → `cd Pictures/`
- **↑/↓**: 명령 기록
- **Ctrl+C**: 실행 중인 프로그램 중단(ROS 노드 종료에 가장 많이 씀)
- **Ctrl+D**: 터미널(셸) 종료
- **Ctrl+A / Ctrl+E**: 줄 맨 앞 / 맨 끝으로 커서 이동

:::warning rm은 되돌릴 수 없습니다
터미널의 `rm`은 휴지통을 거치지 않습니다. 특히 `sudo rm -rf` 뒤에 경로를 잘못 쓰면 시스템이 망가집니다. 지우기 전에 `ls`로 대상을 먼저 확인하는 습관을 들이세요.
:::

## 사용자와 권한

리눅스는 다중 사용자 OS라서 **누가 어떤 파일에 무엇을 할 수 있는지**를 엄격히 관리합니다. 관리자 **root**는 거의 모든 것을 할 수 있고, 일반 사용자는 허락된 범위에서만 작업합니다.

### 사용자 전환

```bash
sudo passwd        # root 비밀번호 설정(Ubuntu는 기본적으로 root 비밀번호가 없음)
su                 # root로 전환 → 프롬프트 끝이 $ 에서 # 로 바뀜
exit               # 원래 사용자로 복귀
sudo 명령          # 한 명령만 관리자 권한으로 실행(권장 방식)
```

일상 작업은 `su`로 root에 머무르기보다 **필요한 명령에만 `sudo`**를 붙이는 편이 안전합니다.

### 권한 읽기

```bash
touch test.txt
ls -l test.txt
# -rw-rw-r-- 1 hiwonder hiwonder 0 ... test.txt
```

@fig[b04-perm] 권한 문자열 10글자 = 파일 종류 1글자 + (소유자·그룹·기타) × (r·w·x). 각 세 글자를 r=4, w=2, x=1로 더하면 8진수 한 자리가 됩니다.

| 권한 | 파일에서 | 디렉터리에서 |
|---|---|---|
| `r`(4) | 내용 읽기 | 목록 보기(`ls`) |
| `w`(2) | 내용 수정 | 안의 파일 생성·삭제·이름 변경 |
| `x`(1) | 프로그램으로 실행 | 안으로 들어가기(`cd`) |

| 8진수 | 문자 | 의미 |
|---|---|---|
| 7 | `rwx` | 읽기·쓰기·실행 |
| 6 | `rw-` | 읽기·쓰기 |
| 5 | `r-x` | 읽기·실행 |
| 4 | `r--` | 읽기만 |
| 0 | `---` | 권한 없음 |

### 권한 바꾸기: chmod

```bash
chmod 755 run.sh          # 숫자 방식: 소유자 rwx, 그룹 r-x, 기타 r-x
chmod u+x test_1.txt      # 문자 방식: 소유자(u)에 실행 추가
chmod g+x test_1.txt      # 그룹(g)
chmod o-x test_1.txt      # 기타(o)에서 실행 제거
chmod a+w test_1.txt      # 모두(a)에 쓰기 추가
```

문자 방식은 `u/g/o/a` + `+/-/=` + `r/w/x` 조합이라 **일부만** 바꿀 때 편하고, 숫자 방식은 **전체를 한 번에** 정할 때 편합니다.

:::info 로봇에서 권한이 문제 되는 순간
- 파이썬 스크립트를 `./run.py`처럼 직접 실행하려면 `x` 권한과 첫 줄 `#!/usr/bin/env python3`(셔뱅)이 필요합니다.
- 시리얼 장치 `/dev/ttyAMA0`에 일반 사용자가 접근하지 못하면 원본은 `sudo chmod 777 /dev/ttyAMA0`을 안내합니다. 하지만 이 설정은 재부팅하면 사라지고 모든 사용자에게 쓰기를 열어 줍니다. 더 나은 방법은 사용자를 장치 그룹(`dialout`)에 넣는 것입니다: `sudo usermod -aG dialout $USER` 후 재로그인.
- `docker` 명령을 `sudo` 없이 쓰려면 사용자가 `docker` 그룹에 있어야 합니다(B10).
:::

## 실습 (실물)

가상 머신의 Ubuntu 또는 MentorPi 호스트 터미널(VNC/SSH)에서 진행합니다.

:::safety
- 로봇의 시스템 폴더(`/etc`, `/boot`, `/usr`)에서는 **읽기만** 합니다. 실습 파일은 반드시 홈 아래 `~/linux_lab`에서 만듭니다.
- `sudo rm`, `chmod -R` 같은 명령은 대상 경로를 `ls`로 확인한 뒤에만 실행합니다.
- 로봇 전원을 끌 때는 스위치를 바로 내리지 말고 `sudo shutdown -h now` 후 LED가 꺼지면 내립니다(SD 카드 손상 방지).
:::

:::task 따라 하기
1. `pwd` → `cd /` → `tree -L 1`(없으면 `sudo apt install tree`)로 루트 구조를 확인합니다.
2. `ls /dev | grep -E "tty|video|js"`로 로봇에 연결된 장치 파일을 찾습니다.
3. `cat /sys/class/thermal/thermal_zone0/temp`로 CPU 온도(1/1000 °C)를 읽습니다.
4. 홈에서 실습 폴더 만들기:
   `mkdir -p ~/linux_lab/scripts && cd ~/linux_lab`

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `command not found` | 오타, 대소문자 틀림, 패키지 미설치 | 철자 확인, Tab 자동완성 사용, `sudo apt install 패키지` |
| `No such file or directory` | 현재 위치 기준 상대 경로가 틀림 | `pwd`로 위치 확인, 절대 경로 사용 |
| `Permission denied` | 권한 부족(시스템 파일, 실행 권한 없음, 장치 접근) | `sudo`, `chmod +x`, 장치는 그룹(`dialout`) 추가 |
| `apt update` 중 연결 오류·매우 느림 | 기본 소스가 멀거나 네트워크 불량 | 미러 변경, 네트워크 확인(로봇 AP 모드는 인터넷 없음) |
| `Unable to locate package` | `apt update`를 안 함 | `sudo apt update` 후 다시 설치 |
| 공유 폴더가 안 보임 | Guest Additions/open-vm-tools 미설치, 미마운트, 첫 설정 시 폴더가 비어 있지 않음 | 도구 설치 → mount 명령 → 비어 있는 새 공유 폴더로 재설정 |
| 재부팅 후 공유 폴더가 사라짐 | 수동 마운트는 일시적 | `/etc/fstab`에 자동 마운트 줄 추가 |
| `su: Authentication failure` | root 비밀번호 미설정 | `sudo passwd`로 먼저 설정 |

## 과제

:::task 기본
1. `ls -l` 결과에서 `drwxr-xr--`와 `-rw-r-----`를 각각 8진수로 바꾸고, "그룹 사용자가 할 수 있는 일"을 문장으로 씁니다.
2. 홈에서 출발해 `~/ros2_ws/src/driver/controller`로 가는 절대 경로와, `~/ros2_ws/src/app`에서 같은 곳으로 가는 상대 경로를 각각 씁니다.
:::

:::task 심화
3. `find`와 `grep`을 조합해 컨테이너의 `~/ros2_ws/src`에서 `create_publisher`가 들어간 파이썬 파일 개수를 세는 한 줄 명령을 만듭니다(힌트: `grep -rl … | wc -l`).
4. `chmod 777 /dev/ttyAMA0`와 `usermod -aG dialout`의 차이를 **지속성**과 **보안** 관점에서 비교합니다.
:::
