## 학습 목표

- 라즈베리파이 5의 GPIO로 디지털 입력·출력을 하고, 풀업/풀다운 저항이 왜 필요한지 전기적으로 설명합니다.
- UART와 I2C의 신호 구조(시작·정지 비트, 주소·ACK)를 비교하고, 명령행 도구와 파이썬으로 통신을 시험합니다.
- 확장보드 SDK `ros_robot_controller_sdk.py`의 **패킷 형식(0xAA 0x55 …)과 CRC8**을 이해하고 패킷을 직접 만들어 검증합니다.
- `board.set_rgb()`, `set_buzzer()`, `set_led()`, 버튼 입력으로 RGB LED·부저·버튼을 제어하고, 같은 일을 ROS 2 토픽으로도 수행합니다.

## 두 갈래의 입출력

MentorPi에서 "핀을 제어한다"는 말은 두 가지 경로를 뜻합니다.

| 경로 | 누가 핀을 움직이나 | 예 | 도구 |
|---|---|---|---|
| ① 라즈베리파이 GPIO 직접 | 리눅스 커널의 GPIO 드라이버 | 확장보드의 KEY1/KEY2 버튼 읽기, 팬 모듈 방향 제어 | `gpiod`, `gpiozero` |
| ② 확장보드(STM32) 경유 | STM32 펌웨어 | RGB LED, 부저, 사용자 LED, 모터, 서보, IMU | `ros_robot_controller_sdk` (UART 패킷) |

①은 리눅스 프로그램이 핀을 직접 올리고 내리므로 간단하지만 타이밍이 정확하지 않습니다. ②는 라즈베리파이가 "RGB를 빨강으로" 같은 **명령 패킷**만 보내고 실제 신호는 STM32가 만듭니다. 이 챕터에서 두 경로를 모두 다루고, B09에서 ②로 서보와 모터를 움직입니다.

## GPIO 기초

@fig[b08-header] 40핀 헤더에서 이 챕터가 쓰는 핀. 핀 번호(물리 위치)와 GPIO 번호(BCM, 칩 내부 번호)는 다릅니다.

### 핀 번호 두 가지

- **물리 핀 번호(board)**: 헤더에서의 위치 1~40. 배선할 때 씀
- **GPIO 번호(BCM)**: 칩 내부 번호 GPIO0~27. 코드에서 씀. 예: 물리 11번 핀 = GPIO17

터미널의 `pinout` 명령이 두 번호를 함께 보여 줍니다. 헷갈리면 항상 이 표를 확인하세요.

### 출력과 입력

- **출력(output)**: 핀을 1(3.3 V) 또는 0(0 V)으로 만든다. LED를 켤 때는 LED와 **직렬 저항(220~330 Ω)**을 넣어 전류를 제한합니다. GPIO 한 핀이 안전하게 낼 수 있는 전류는 수 mA 수준입니다.
- **입력(input)**: 핀 전압을 읽어 1/0으로 판단한다.

### 풀업·풀다운이 필요한 이유

버튼을 핀과 GND 사이에 연결했다고 합시다. 버튼을 누르면 핀이 GND(0)에 연결되지만, **떼면 핀이 아무 데도 연결되지 않은 떠 있는(floating)** 상태가 됩니다. 이때 핀은 주변 잡음을 받아 0과 1 사이를 무작위로 오갑니다.

- **풀업(pull-up)**: 핀을 저항을 통해 3.3 V에 약하게 연결. 버튼을 떼면 1, 누르면 GND로 강하게 끌려 0 → **"누르면 0"(active-low)**
- **풀다운(pull-down)**: 핀을 저항을 통해 GND에 연결. 버튼을 3.3 V 쪽에 달면 누를 때 1

라즈베리파이 칩 안에 이 저항이 내장되어 있어 코드로 켤 수 있습니다. 원본 확장보드 버튼 예제(`key.py`)가 `LINE_REQ_FLAG_BIAS_PULL_UP`을 쓰고 `if key1_state == 0:`으로 눌림을 판단하는 것이 바로 active-low 풀업 구조입니다. 원본 강의의 풀업 실험에서 입력 핀을 멀티미터로 재면 약 3.33 V가 나오는 것도 같은 원리입니다.

### gpiod로 제어하기

원본은 리눅스 표준 GPIO 문자 장치 인터페이스를 쓰는 **libgpiod**(`gpiod` 모듈)를 사용합니다. 라즈베리파이 5에서는 40핀 GPIO가 RP1 칩에 있어서 원본 예제가 `gpiod.Chip("gpiochip4")`를 엽니다.

```bash
gpiodetect          # GPIO 칩 목록 — pinctrl-rp1 이 40핀 헤더
gpioinfo gpiochip4 | head   # 라인(핀)별 사용 상태
pinout              # 핀 배치 그림
```

다음은 원본 `key.py`, `gpio_control.py`와 같은 **libgpiod v1 API** 스타일입니다.

```python robot
import time
import gpiod

chip = gpiod.Chip("gpiochip4")                 # RP1 (40핀 헤더)

# 출력: GPIO17 (물리 11번 핀) — LED + 330 Ω 저항
led = chip.get_line(17)
led.request(consumer="led", type=gpiod.LINE_REQ_DIR_OUT)

# 입력: GPIO13 (확장보드 KEY1), 내부 풀업 → 누르면 0
key1 = chip.get_line(13)
key1.request(consumer="key1", type=gpiod.LINE_REQ_DIR_IN,
             flags=gpiod.LINE_REQ_FLAG_BIAS_PULL_UP)

try:
    for _ in range(50):                        # 약 5초
        pressed = (key1.get_value() == 0)
        led.set_value(1 if pressed else 0)
        print("\rKEY1:", "pressed " if pressed else "released", end="", flush=True)
        time.sleep(0.1)
finally:
    led.set_value(0)
    led.release(); key1.release(); chip.close()
    print()
```

:::info gpiod 버전 차이
원본 예제는 Debian 패키지 `python3-libgpiod`(v1 API: `Chip.get_line`, `LINE_REQ_DIR_OUT`)를 기준으로 합니다. `pip install gpiod`로 설치되는 최신 2.x는 API가 다릅니다(`gpiod.request_lines(...)`, `LineSettings(direction=Direction.OUTPUT, bias=Bias.PULL_UP)`). `AttributeError: module 'gpiod' has no attribute 'LINE_REQ_DIR_OUT'`가 나면 2.x가 설치된 것입니다. 또 최신 커널에서는 RP1 칩이 `gpiochip0`로 번호가 바뀌었을 수 있으니 `gpiodetect`로 확인하세요.
:::

더 간단한 고수준 라이브러리로 **gpiozero**도 있습니다. 라즈베리파이 5에서도 동작하며, `Button`은 기본이 풀업입니다.

```python robot
from gpiozero import LED, Button
from signal import pause

led = LED(17)             # BCM 번호
btn = Button(13)          # pull_up=True 기본 → 눌림 = GND 연결
btn.when_pressed = led.on
btn.when_released = led.off
pause()                   # Ctrl+C 로 종료
```

:::warning 확장보드 버튼은 서비스가 쓰고 있습니다
KEY1(GPIO13)·KEY2(GPIO23)는 부팅 시 `hw_button_scan` 서비스가 점유합니다. 원본 절차대로 **먼저 서비스를 멈추고**, 실습 후 **다시 켭니다.** 멈추지 않으면 `key.py`가 "按键默认被 hw_button_scan 占用"(버튼이 hw_button_scan에 점유됨) 메시지를 출력합니다.

```bash
sudo systemctl stop hw_button_scan.service
python3 key.py
sudo systemctl start hw_button_scan.service
```
:::

## UART: 비동기 직렬 통신

**UART**(Universal Asynchronous Receiver/Transmitter)는 TX(송신)와 RX(수신) **두 선**으로 바이트를 한 비트씩 보내는 방식입니다. 공통 클록선이 없어서(**비동기**) 양쪽이 **같은 보레이트(baud rate, 초당 비트 수)**를 미리 맞춰야 합니다.

한 바이트 프레임(가장 흔한 8N1 설정):

```text
 idle(1) ─┐ start ┌ D0 D1 D2 D3 D4 D5 D6 D7 ┐ (parity) ┌ stop ─ idle(1)
          └─ 0 ───┘      LSB 먼저 전송          └ 없음 ──┘   1
```

- **시작 비트**: 평소 1(High)인 선을 한 비트 동안 0으로 내려 "시작"을 알림
- **데이터**: 5~8비트(보통 8), **최하위 비트(LSB)부터**
- **패리티(parity)**: 선택. 1의 개수가 짝수/홀수인지로 간단한 오류 검출
- **정지 비트**: 1~2비트 동안 1

8N1이면 1바이트에 10비트가 필요하므로 전송 시간은 `10 / 보레이트`입니다. 115200 bps에서 약 86.8 µs, 확장보드 SDK가 쓰는 **1,000,000 bps**에서 10 µs입니다.

### 배선과 설정

| 라즈베리파이 5 | USB-TTL 변환기 |
|---|---|
| 8번 핀 TXD (GPIO14) | RXD |
| 10번 핀 RXD (GPIO15) | TXD |
| 6번 핀 GND | GND |

TX와 RX는 **엇갈려** 연결하고 GND는 반드시 공유합니다. 변환기의 신호 전압은 3.3 V여야 합니다.

1. `sudo apt-get install python3-serial`
2. Raspberry Pi Configuration → Interfaces → **Serial Port 켜기, Serial Console 끄기**(콘솔이 켜져 있으면 리눅스 로그인 프롬프트가 같은 포트를 씀) → 재부팅
3. `ls -l /dev/ttyAMA*`로 장치 확인

:::info 원본의 config.txt 설정에 대해
원본은 `config.txt`에 `dtoverlay=pi3-miniuart-bt`, `force_turbo=1`을 추가하라고 합니다. 이는 블루투스가 주 UART를 차지하던 **라즈베리파이 3/4 시절의 설정**입니다. 라즈베리파이 5는 40핀 UART0(GPIO14/15)가 블루투스와 분리되어 있어, `raspi-config`로 Serial Port를 켜면 `dtparam=uart0=on`이 추가되고 `/dev/ttyAMA0`로 나타납니다.
:::

```python robot
import serial, time

ser = serial.Serial("/dev/ttyAMA0", 115200, timeout=0.5)   # 8N1 기본
ser.write(b"hello from MentorPi\r\n")
t0 = time.time()
while time.time() - t0 < 10:                               # 10초 동안 수신
    line = ser.readline()
    if line:
        print("PC says:", line.decode(errors="replace").strip())
ser.close()
```

PC 쪽 시리얼 터미널(원본: Serial Port Utility, CH340 드라이버)을 115200 bps로 열면 문자열이 보이고, PC에서 보낸 글자가 라즈베리파이 터미널에 찍힙니다.

## I2C: 주소로 부르는 2선 버스

**I2C**(Inter-Integrated Circuit)는 **SDA(데이터)와 SCL(클록)** 두 선에 여러 장치를 병렬로 매다는 버스입니다. 마스터가 클록을 만들고, 각 장치(슬레이브)는 **7비트 주소**로 구분됩니다. 반이중(half-duplex)이며 원본 설명처럼 여러 마스터도 허용합니다.

| 신호 | 정의 |
|---|---|
| 시작(S) | SCL이 High일 때 SDA가 High → Low |
| 정지(P) | SCL이 High일 때 SDA가 Low → High |
| 주소 + R/W | 시작 뒤 7비트 주소 + 방향 1비트(0 = 쓰기, 1 = 읽기) |
| ACK | 매 바이트 뒤 9번째 클록에서 수신 측이 SDA를 Low로 당김. High면 NACK |
| 규칙 | 시작·정지를 제외한 SDA 변화는 SCL이 Low일 때만 |

UART는 선이 1:1이지만, I2C는 선 두 개로 IMU·EEPROM·디스플레이 등 **여러 장치**를 연결할 수 있어 센서 확장에 많이 씁니다(RRC Lite의 IMU QMI8658도 STM32와 I2C로 연결).

배선(원본 예: MPU6050 가속도·자이로 모듈): 3번 핀 SDA(GPIO2) ↔ SDA, 5번 핀 SCL(GPIO3) ↔ SCL, 6번 핀 GND ↔ GND, 모듈 VCC ↔ 1번 핀 3.3 V.

```bash
sudo apt-get update && sudo apt-get install -y i2c-tools
sudo raspi-config                      # Interface Options → I2C → Yes
sudo i2cdetect -l                      # I2C 버스 목록
sudo i2cdetect -y 1                    # 1번 버스 스캔 → 0x68 에 장치 표시
sudo i2cdump -y 1 0x68                 # 0x68 장치의 레지스터 전체
sudo i2cget -y 1 0x68 0x6b             # 레지스터 0x6B (PWR_MGMT_1) 1바이트 읽기
sudo i2ctransfer -f -y 1 w2@0x68 0x01 0x6b r16   # 16비트 주소 0x016B부터 16바이트(2바이트 주소 장치용)
```

파이썬에서는 `smbus2`로 같은 일을 합니다(`pip install smbus2` 또는 `sudo apt install python3-smbus2`).

```python robot
from smbus2 import SMBus

with SMBus(1) as bus:
    who = bus.read_byte_data(0x68, 0x75)      # MPU6050 WHO_AM_I 레지스터
    print("WHO_AM_I = 0x%02X" % who)          # 0x68 이면 정상
    bus.write_byte_data(0x68, 0x6B, 0x00)     # 슬립 해제
```

## 확장보드 SDK: 패킷 통신

### SDK 구조

원본 `board_demo/ros_robot_controller_sdk.py`는 라즈베리파이와 STM32 사이 직렬 통신을 감싼 클래스 `Board` 하나입니다.

| 구성 | 역할 |
|---|---|
| `Board(device, baudrate=1000000)` | 시리얼 포트 열기, 기능별 큐 생성, 수신 스레드 시작 |
| `buf_write(func, data)` | 패킷 조립 + CRC8 + 전송 |
| `set_*`, `pwm_servo_*`, `bus_servo_*` | 기능별 명령 → `buf_write` 호출 |
| `recv_task()` | 수신 스레드. 상태 기계로 패킷을 조립해 기능별 큐에 넣음 |
| `get_battery/imu/button/gamepad/sbus()` | 큐에서 최신 값을 꺼냄(없으면 `None`) — **`enable_reception()`을 먼저 호출해야 함** |

`PacketFunction` 번호: SYS 0, LED 1, BUZZER 2, MOTOR 3, PWM_SERVO 4, BUS_SERVO 5, KEY 6, IMU 7, GAMEPAD 8, SBUS 9, OLED 10, RGB 11.

### 패킷 형식과 CRC8

@fig[b08-packet] SDK가 보내는 패킷. CRC8은 기능 코드부터 데이터 끝까지 계산합니다.

실제 `buf_write` 코드는 `[0xAA, 0x55, 기능, 길이, 데이터…, CRC8]` 순서로 바이트를 만듭니다. 원본 문서는 "0xAA 0x55 Length Function ID Data Checksum"이라고 적었지만, **코드와 펌웨어의 실제 순서는 기능 → 길이**이고 별도 ID 바이트는 데이터 안에 들어 있습니다.

- **헤더 `0xAA 0x55`**: 바이트 흐름에서 패킷 시작을 찾는 표식. 두 바이트를 연속으로 요구해 우연히 일치할 확률을 줄임
- **길이**: 데이터 바이트 수. 수신 측이 어디까지 읽을지 앎
- **CRC8**: 전송 중 비트가 뒤집혔는지 검사. SDK는 256칸 표를 써서 `check = table[check ^ b]`를 반복합니다. 이 표는 **Dallas/Maxim CRC-8**(다항식 x⁸+x⁵+x⁴+1, 반사형 0x8C)과 같습니다.

아래 코드는 표를 직접 만들어 SDK 표와 같은지 확인하고, 네 가지 명령의 실제 바이트열을 계산합니다. 로직은 SDK와 같고, 시리얼 포트에 쓰는 대신 화면에 출력합니다.

```python run
import struct

def make_crc8_table():                 # Maxim/Dallas CRC-8, 반사 다항식 0x8C
    table = []
    for i in range(256):
        crc = i
        for _ in range(8):
            crc = (crc >> 1) ^ 0x8C if crc & 1 else crc >> 1
        table.append(crc)
    return table

CRC8 = make_crc8_table()
print("table[:6] =", CRC8[:6], "  (SDK: 0, 94, 188, 226, 97, 63)")

def checksum_crc8(data):               # SDK 함수와 동일
    check = 0
    for b in data:
        check = CRC8[check ^ b]
    return check & 0xFF

def buf_write(func, data):             # SDK Board.buf_write 의 바이트 순서
    buf = [0xAA, 0x55, int(func), len(data)] + list(data)
    buf.append(checksum_crc8(bytes(buf[2:])))
    return bytes(buf)

def hexs(b):
    return " ".join(f"{x:02X}" for x in b)

# board.set_rgb([[1, 255, 0, 0], [2, 255, 0, 0]])   RGB = 11
data = [0x01, 2]
for index, r, g, b in [[1, 255, 0, 0], [2, 255, 0, 0]]:
    data += struct.pack("<BBBB", index - 1, r, g, b)
print("set_rgb    :", hexs(buf_write(11, data)))

# board.set_buzzer(1900, 0.1, 0.9, 1)                BUZZER = 2
print("set_buzzer :", hexs(buf_write(2, struct.pack("<HHHH", 1900, 100, 900, 1))))

# board.pwm_servo_set_position(1, [[1, 1500]])       PWM_SERVO = 4
dur = int(1 * 1000)
data = [0x01, dur & 0xFF, 0xFF & (dur >> 8), 1] + list(struct.pack("<BH", 1, 1500))
print("pwm_servo  :", hexs(buf_write(4, data)))

# board.set_motor_speed([[1, 0.5]])                  MOTOR = 3
data = [0x01, 1] + list(struct.pack("<Bf", 1 - 1, 0.5))
print("motor_speed:", hexs(buf_write(3, data)))

# 전송 시간 (8N1: 1바이트 = 10비트)
n = len(buf_write(11, [0x01, 2] + [0] * 8))
for baud in (115200, 1000000):
    print(f"{n} bytes @ {baud} bps = {n * 10 / baud * 1e6:.0f} us")
```

```text
table[:6] = [0, 94, 188, 226, 97, 63]   (SDK: 0, 94, 188, 226, 97, 63)
set_rgb    : AA 55 0B 0A 01 02 00 FF 00 00 01 FF 00 00 5A
set_buzzer : AA 55 02 08 6C 07 64 00 84 03 01 00 5D
pwm_servo  : AA 55 04 07 01 E8 03 01 01 DC 05 87
motor_speed: AA 55 03 07 01 01 00 00 00 00 3F D0
15 bytes @ 115200 bps = 1302 us
15 bytes @ 1000000 bps = 150 us
```

읽는 법 — `set_rgb` 패킷 `AA 55 0B 0A 01 02 00 FF 00 00 01 FF 00 00 ..`:
`0B`=RGB 기능(11), `0A`=데이터 10바이트, `01`=하위 명령, `02`=LED 2개, `00 FF 00 00`=LED 인덱스 0(사용자가 준 1에서 1을 뺌)·R 255·G 0·B 0, 이어서 인덱스 1의 값, 마지막이 CRC8입니다. 멀티바이트 수는 `struct`의 `<`(리틀 엔디언)로 **하위 바이트가 먼저** 나갑니다: 1900 = 0x076C → `6C 07`.

### 수신 상태 기계

반대로 STM32가 보내는 배터리·IMU·버튼 데이터는 수신 스레드가 한 바이트씩 읽어 **상태 기계(state machine)**로 조립합니다. 중간에 쓰레기 바이트가 끼거나 CRC가 틀리면 버리고 다음 `0xAA`를 기다립니다.

```python run
import struct

CRC8 = []
for i in range(256):
    c = i
    for _ in range(8):
        c = (c >> 1) ^ 0x8C if c & 1 else c >> 1
    CRC8.append(c)

def crc8(data):
    ck = 0
    for b in data:
        ck = CRC8[ck ^ b]
    return ck

def packet(func, data):
    body = [func, len(data)] + list(data)
    return [0xAA, 0x55] + body + [crc8(bytes(body))]

# 배터리 보고(SYS=0, 하위 0x04, uint16 mV) + 잡음 + CRC 깨진 패킷 + IMU 보고(IMU=7, 6 float)
battery = packet(0, [0x04] + list(struct.pack("<H", 7650)))
broken = packet(0, [0x04] + list(struct.pack("<H", 7000))); broken[-1] ^= 0xFF
imu = packet(7, struct.pack("<6f", 0.0, 0.0, 9.8, 0.0, 0.0, 0.25))
stream = [0x13, 0xAA, 0x00] + battery + [0x55] + broken + imu

state, frame, count = "START1", [], 0
for dat in stream:                         # SDK recv_task 와 같은 순서의 상태 기계
    if state == "START1":
        state = "START2" if dat == 0xAA else "START1"
    elif state == "START2":
        state = "FUNC" if dat == 0x55 else "START1"
    elif state == "FUNC":
        frame, state = ([dat, 0], "LEN") if dat < 12 else ([], "START1")
    elif state == "LEN":
        frame[1], count = dat, 0
        state = "DATA" if dat else "CHECK"
    elif state == "DATA":
        frame.append(dat); count += 1
        if count >= frame[1]:
            state = "CHECK"
    elif state == "CHECK":
        func, data = frame[0], bytes(frame[2:])
        if crc8(bytes(frame)) != dat:
            print("checksum failed -> drop")
        elif func == 0 and data[0] == 0x04:
            print("battery:", struct.unpack("<H", data[1:])[0], "mV")
        elif func == 7:
            print("imu ax,ay,az,gx,gy,gz =", [round(v, 2) for v in struct.unpack("<6f", data)])
        state = "START1"
```

```text
battery: 7650 mV
checksum failed -> drop
imu ax,ay,az,gx,gy,gz = [0.0, 0.0, 9.8, 0.0, 0.0, 0.25]
```

:::tip 원본 SDK를 읽을 때
SDK 상태 기계의 enum 이름은 `…STARTBYTE1 → STARTBYTE2 → FUNCTION → LENGTH → DATA → CHECKSUM` 순으로 전이합니다(enum 정의의 번호 순서와 다르니 전이 코드를 따라 읽으세요). CRC가 틀리면 원본은 "校验失败"(검증 실패)를 출력합니다.
:::

### 장치 파일과 선점 문제

- SDK의 기본 장치는 `board_demo` 버전이 `/dev/ttyAMA0`, 컨테이너 ROS 드라이버(`ros_robot_controller`)와 `RRCLite_demo` 버전이 **`/dev/rrc`**입니다. `/dev/rrc`는 확장보드 직렬 장치를 가리키는 고정 이름(심볼릭 링크)입니다. `ls -l /dev/rrc`로 실제 대상 장치를 확인하고, 예제가 포트를 못 열면 `rrc.Board(device="/dev/rrc")`처럼 지정합니다.
- 한 직렬 포트를 두 프로그램이 동시에 열면 바이트를 나눠 가져가 **둘 다 오동작**합니다. 자동 실행 중인 `ros_robot_controller` 노드가 포트를 쓰고 있으므로 SDK 예제를 직접 돌리기 전에는 `~/.stop_ros.sh`로 앱 서비스를 멈추는 것이 안전합니다.

## RGB LED·부저·버튼

### RGB LED: `set_rgb(pixels)`

```python
board.set_rgb([[1, 255, 0, 0], [2, 255, 0, 0]])   # [LED 번호, R, G, B] 목록
```

- LED 번호는 1, 2(보드의 RGB 두 개). 각 채널 0~255, **값이 클수록 밝음**
- 여러 LED를 한 패킷에 담아 동시에 바꿈
- 색 섞기: 빨강 (255,0,0), 초록 (0,255,0), 파랑 (0,0,255), 노랑 (255,255,0), 끄기 (0,0,0)

원본 예제 두 개의 차이: `rgb_control_demo.py`는 빨강→초록→파랑→노랑을 1초씩 바꾸고, `rgb_flashing.py`는 각 색 사이에 **끄기(0,0,0)**를 0.5초씩 넣어 깜빡이게 합니다. 깜빡임 주기는 `time.sleep` 값으로 정해집니다.

### 부저: `set_buzzer(freq, on_time, off_time, repeat)`

| 인자 | 의미 | 단위 |
|---|---|---|
| `freq` | 소리 주파수(음 높이) | Hz |
| `on_time`, `off_time` | 울림·쉼 시간 | 초(SDK가 ms로 변환해 전송) |
| `repeat` | 반복 횟수, **0 = 계속 반복** | 회 |

원본 `buzzer_control_demo.py`:

```python robot
import time
import ros_robot_controller_sdk as rrc

board = rrc.Board()
board.set_buzzer(1900, 0.1, 0.9, 1)   # 1900 Hz, 0.1 s 울림 + 0.9 s 쉼, 1회
time.sleep(2)
board.set_buzzer(1000, 0.5, 0.5, 0)   # 1000 Hz, 0.5 s / 0.5 s, 계속 반복
time.sleep(3)                         # → 약 3번 울림
board.set_buzzer(1000, 0.0, 0.0, 1)   # 끄기
```

비슷하게 STM32의 사용자 LED는 `board.set_led(on_time, off_time, repeat=1, led_id=1)`로 깜빡입니다.

### 버튼 두 가지 방식

1. **라즈베리파이 GPIO로 직접**(원본 `key.py`): KEY1 = GPIO13, KEY2 = GPIO23, 풀업, 눌리면 0. 서비스 `hw_button_scan`을 멈춰야 함
2. **STM32 경유**: `board.enable_reception()` 후 `board.get_button()`이 `(버튼 ID, 이벤트)` 또는 `None`을 반환. 펌웨어가 클릭·길게 누르기·더블 클릭 등을 판별해 보고(`PacketReportKeyEvents`)

### 종합 예제: 버튼으로 RGB 바꾸고 배터리 보기

```python robot
import time
import signal
import gpiod
import ros_robot_controller_sdk as rrc

board = rrc.Board()                         # 포트 오류 시 rrc.Board(device="/dev/rrc")
board.enable_reception()                    # get_battery() 등에 필요
running = True

def stop(signum, frame):
    global running
    running = False
signal.signal(signal.SIGINT, stop)

chip = gpiod.Chip("gpiochip4")
keys = {}
for name, pin in (("key1", 13), ("key2", 23)):
    line = chip.get_line(pin)
    line.request(consumer=name, type=gpiod.LINE_REQ_DIR_IN,
                 flags=gpiod.LINE_REQ_FLAG_BIAS_PULL_UP)
    keys[name] = line

try:
    while running:
        if keys["key1"].get_value() == 0:
            board.set_rgb([[1, 255, 0, 0], [2, 255, 0, 0]])     # 빨강
            board.set_buzzer(1900, 0.05, 0.01, 1)
        if keys["key2"].get_value() == 0:
            board.set_rgb([[1, 0, 0, 255], [2, 0, 0, 255]])     # 파랑
        mv = board.get_battery()
        if mv is not None:
            print(f"\rbattery {mv / 1000:.2f} V", end="", flush=True)
        time.sleep(0.02)
finally:
    board.set_rgb([[1, 0, 0, 0], [2, 0, 0, 0]])                 # 끄기
    for line in keys.values():
        line.release()
    chip.close()
    print()
```

### 같은 일을 ROS 2 토픽으로

자동 실행 서비스가 켜져 있으면 `ros_robot_controller` 노드가 이미 포트를 열고 **토픽 인터페이스**를 제공합니다. 컨테이너 안에서 다음처럼 명령합니다(메시지 정의: `ros_robot_controller_msgs`).

```bash
ros2 topic pub --once /ros_robot_controller/set_rgb ros_robot_controller_msgs/msg/RGBStates \
  "{states: [{index: 1, red: 0, green: 255, blue: 0}, {index: 2, red: 0, green: 255, blue: 0}]}"

ros2 topic pub --once /ros_robot_controller/set_buzzer ros_robot_controller_msgs/msg/BuzzerState \
  "{freq: 1900, on_time: 0.1, off_time: 0.9, repeat: 1}"

ros2 topic echo /ros_robot_controller/battery      # std_msgs/UInt16, mV
ros2 topic echo /ros_robot_controller/button       # ButtonState
```

노드는 이 메시지를 받아 그대로 `board.set_rgb()`, `board.set_buzzer()`를 호출합니다. 즉 **SDK = 하드웨어 계층, 노드 = ROS 2 어댑터**입니다. 원본 `RRCLite_demo/rgb_controller_node.py`, `buzzer_control_node.py`는 이 토픽에 발행하는 rclpy 예제입니다(R03 이후 직접 작성).

## 실습 (실물)

:::safety
- GPIO 배선은 **라즈베리파이 전원을 끈 상태**에서 합니다. 3.3 V와 GND를 직접 잇는 단락, 5 V 핀과 GPIO의 접촉을 조심합니다.
- LED에는 반드시 220~330 Ω 저항을 직렬로 연결합니다.
- MentorPi에서는 UART0(8·10번 핀)·I2C 핀이 다른 장치에 쓰이고 있을 수 있습니다. 외부 모듈 실험은 **담당자 확인 후** 하거나 별도 라즈베리파이에서 합니다.
- SDK 예제 전에 `~/.stop_ros.sh`, 버튼 예제 전에 `sudo systemctl stop hw_button_scan.service`. 실습 후 두 서비스를 다시 켭니다.
- 부저를 `repeat=0`으로 켠 채 프로그램을 끝내면 계속 울립니다. `set_buzzer(1000, 0, 0, 1)`로 끕니다.
:::

:::task 따라 하기
1. `gpiodetect`, `pinout`으로 칩 이름과 핀 배치를 확인합니다.
2. `~/.stop_ros.sh` → `cd ~/board_demo` → `python3 rgb_control_demo.py`, `python3 rgb_flashing.py`를 실행하고 차이를 관찰합니다(Ctrl+C로 종료, 안 되면 반복).
3. `python3 buzzer_control_demo.py` — 짧게 1번, 이어서 약 3번 울리고 끝나는지 확인합니다.
4. `sudo systemctl stop hw_button_scan.service` → `python3 key.py` — KEY1 빨강, KEY2 파랑, 터미널에 `key1: 1 key2: 1`이 눌림에 따라 0으로 바뀌는지 봅니다 → `sudo systemctl start hw_button_scan.service`
5. 종합 예제를 `~/board_demo/my_keys.py`로 저장해 실행하고, 배터리 전압이 표시되는지 확인합니다.
6. 앱 서비스를 다시 켠 뒤(`sudo systemctl restart start_node.service`, 호스트) 컨테이너에서 `ros2 topic pub`으로 RGB·부저를 제어합니다.
:::

:::check 체크포인트
- [ ] 풀업 입력에서 "누르면 0"인 이유를 설명할 수 있다.
- [ ] `AA 55 02 08 6C 07 64 00 84 03 01 00 ..` 패킷이 어떤 명령인지 해석할 수 있다.
- [ ] SDK 예제와 ROS 노드가 같은 포트를 동시에 쓰면 안 되는 이유를 안다.
- [ ] `ros2 topic pub`으로 RGB를 바꿨다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `could not open port /dev/ttyAMA0` | 장치 이름이 다름, 권한 부족 | `ls -l /dev/rrc /dev/ttyAMA*` 확인 후 `Board(device=…)` 지정, 사용자를 `dialout` 그룹에 추가 |
| 명령이 가끔 무시되거나 "校验失败" 출력 | 다른 프로그램(ROS 노드)이 같은 포트 사용 | `~/.stop_ros.sh` 후 실행 |
| `get_battery()`가 항상 `None` | `enable_reception()` 미호출, 아직 보고가 안 옴 | 생성 직후 `board.enable_reception()`, 루프에서 여러 번 시도 |
| `key.py`가 "hw_button_scan 占用" 출력 | 버튼 핀을 서비스가 점유 | `sudo systemctl stop hw_button_scan.service` |
| `OSError: [Errno 16] Device or resource busy` (gpiod) | 다른 프로세스가 그 라인을 요청 중 | 이전 프로그램 종료, `gpioinfo`로 consumer 확인 |
| `AttributeError: module 'gpiod' has no attribute 'Chip'`/`'LINE_REQ_DIR_OUT'` | gpiod 2.x API | `python3-libgpiod`(v1) 사용 또는 2.x API로 수정 |
| 버튼이 안 눌러도 가끔 눌린 것으로 읽힘 | 풀업 없음(플로팅), 채터링 | 풀업 플래그 설정, 소프트웨어 디바운스(연속 N회 확인) |
| UART로 깨진 글자 수신 | 보레이트 불일치, TX/RX 직결, GND 미연결 | 양쪽 115200 확인, TX↔RX 엇갈림, GND 공유 |
| `i2cdetect`에 장치가 안 보임 | I2C 미활성, 배선(SDA/SCL 뒤바뀜), 전원 없음 | raspi-config에서 I2C 켜기, 배선·VCC 확인 |
| Ctrl+C로 프로그램이 안 끝남 | 시그널 핸들러가 플래그만 바꾸고 루프가 sleep 중 | 원본 안내대로 여러 번 누름, 루프 주기 확인 |
