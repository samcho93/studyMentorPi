## 학습 목표

- 원본 `self_driving.py`가 교차로 회전을 **차선 기하(lane_x)**로 결정하는 방식과, 우회전 표지 검출(`turn_right`)의 역할을 구분해 설명합니다.
- 주차 시작 조건(주차 표지 + 횡단보도 y 문턱 + 15프레임 확인)과 섀시별 `park_action()`을 해석하고, 애커만 주차 궤적을 운동학으로 계산합니다.
- 여러 불리언 플래그로 흩어진 상태를 **명시적 유한 상태 기계(FSM)**로 다시 설계하고 시뮬레이션합니다.
- 통합 자율주행 launch를 실행하고 서비스로 일시정지·재개하며, 주차 위치를 튜닝합니다.

## 원본의 통합 구조

`self_driving.py`는 A09·A10에서 본 기능을 **한 개의 주 루프**(약 33 Hz)에서 차례로 처리합니다.

```text
while 실행 중:
    영상 ← 큐
    binary ← 노란색 이진화
    ① 횡단보도 감속 판단   (crosswalk_distance, count_crosswalk, start_slow_down)
    ② 신호등 정지/출발      (traffic_signs_status, stop)
    ③ 주차 판단            (park_x, crosswalk_distance, count_park, start_park)
    ④ 차선 유지·회전        (lane_x, count_turn, start_turn, PID)
    Twist 발행 (④에서 차선이 보일 때만)
```

상태가 `start_slow_down`, `stop`, `start_turn`, `start_park` 같은 **플래그 여러 개**에 흩어져 있습니다. 플래그 4개면 조합이 $2⁴ = 16$가지인데, 그중 "주차 중이면서 회전 중" 같은 조합은 의미가 없고, 어떤 조합이 가능한지는 코드를 끝까지 읽어야 알 수 있습니다. 이 장의 후반에서 이것을 명시적인 상태 기계로 정리합니다.

## 회전 판단

### 원본은 차선이 휘는 것을 보고 돈다

A09에서 본 규칙이 그대로 회전 판단입니다.

| 조건 | 판단 | 명령 (메카넘 / 애커만) |
|---|---|---|
| lane_x > 150 | 앞쪽 차선이 크게 휨 → 회전 구간 | `angular.z = −0.45` / 최대 조향 29° |
| 6프레임 넘게 지속 | `start_turn = True`, 시각 기록 | |
| lane_x ≤ 150 이고 회전 시작 후 2 s 이내 | 회전 마무리 | 각속도 0 / 조향 유지 |
| 그 외 | 직선 | PID |

맵의 노란 선은 로봇이 따라가는 차로의 왼쪽 경계입니다. 우회전 교차로에 가까워지면 노란 선이 오른쪽으로 꺾여 들어오고, 그 결과 lane_x가 150을 넘습니다. 즉 **맵 자체가 "여기서 우회전"을 선의 모양으로 알려 주는 구조**입니다.

### 우회전 표지는 무엇을 하나

`get_object_callback()`은 `right` 표지를 5번 이상 보면 `turn_right = True`를 세우지만, 주 루프에서 이 값을 읽는 곳은 없습니다. 원본 교재의 "우회전 표지를 보면 우회전한다"는 설명은 결과적으로 맞지만(그 표지가 있는 곳에서 선이 꺾이므로), 표지 인식이 회전을 **결정**하지는 않습니다.

실제 도로처럼 "선이 양쪽으로 갈라지는 교차로에서 표지를 보고 방향을 고르는" 구조를 만들려면, 표지가 조건(guard)이 되어야 합니다.

```python
# 개선 예: 교차로 판단 시 표지를 조건으로 사용
if lane_x > 150 and (self.turn_right or self.no_left_branch):
    twist.angular.z = -0.45          # 우회전
elif lane_x > 150:
    twist.angular.z = common.set_range(self.pid.output, -0.1, 0.1)   # 직진 유지
```

`turn_right`는 회전을 마친 뒤 반드시 `False`로 되돌려야 다음 교차로에서 잘못 쓰이지 않습니다. 이렇게 **이벤트를 소비(consume)**하는 처리가 빠지는 것이 플래그 방식에서 자주 나는 버그입니다.

## 자율 주차

### 주차 시작 조건

```python
if 0 < self.park_x and 135 < self.crosswalk_distance:        # 주차 표지 보임 + 횡단보도 가까움
    twist.linear.x = self.slow_down_speed                     # 서행
    if not self.start_park and 180 < self.crosswalk_distance: # 더 가까움
        self.count_park += 1
        if self.count_park >= 15:                             # 15프레임 연속 ≈ 0.5 s
            self.mecanum_pub.publish(Twist())                 # 정지
            self.start_park = True
            self.stop = True
            threading.Thread(target=self.park_action).start()
    else:
        self.count_park = 0
```

주차 칸은 횡단보도 바로 옆에 있으므로, 원본은 **횡단보도의 영상 y(가까움)**를 주차 위치의 기준으로 씁니다. A10의 가정 카메라로 환산하면 135 px ≈ 0.53 m, 180 px ≈ 0.37 m 앞입니다. 원본 교재는 이 문턱(180)을 **줄이면 횡단보도에 더 가깝게**, 키우면 더 멀리서 멈춘다고 설명합니다. `park_action()`은 별도 스레드에서 돌고, `stop = True`가 유지되므로 주차 후에는 차선 유지 명령이 더 이상 나가지 않습니다(주행 종료).

### 섀시별 주차 동작

@fig[a11-parking] 두 섀시의 `park_action()`. 애커만은 원본 명령값을 자전거 모델로 적분한 궤적이고, 메카넘은 옆으로 평행 이동합니다.

| 섀시 (`MACHINE_TYPE`) | 동작 |
|---|---|
| `MentorPi_Mecanum` | `linear.y = −0.2` m/s로 0.38/0.2 = 1.9 s → 오른쪽으로 0.38 m 평행 이동 |
| `MentorPi_Acker` | ① 0.15 m/s 전진 + 우조향 3 s → ② 전진 + 좌조향 2 s → ③ 0.15 m/s 후진 + 우조향 1.5 s |
| 그 밖 (차동 구동) | 제자리 우회전 1.5 s → 전진 0.65 m → 제자리 좌회전 1.5 s |

메카넘은 **옆으로 갈 수 있으므로**(M01의 역기구학) 주차가 한 줄입니다. 애커만은 옆으로 갈 수 없어 사람의 평행 주차처럼 전진·후진을 섞습니다. 애커만 명령의 각속도는 $ω = v·tan δ / L$이고 δ = −0.5061 rad(−29°), L = 0.145 m이므로 최소 회전 반경은 $R = L/tan 29° ≈ 0.262$ m입니다.

```python run
import math

L, DELTA = 0.145, -0.5061                 # 애커만 축간거리[m], 조향 -29°(오른쪽)
def w_of(v, delta):                        # park_action(): angular.z = v·tan(δ)/L
    return v * math.tan(delta) / L

steps = [(0.15, w_of(0.15, DELTA), 3.0),   # ① 전진하며 우회전
         (0.15, -w_of(0.15, DELTA), 2.0),  # ② 전진하며 좌회전
         (-0.15, w_of(-0.15, DELTA), 1.5)] # ③ 후진하며 자세 정리
x = y = th = 0.0
dt = 0.001
for i, (v, w, T) in enumerate(steps, 1):
    for _ in range(int(round(T / dt))):    # 단순 오일러 적분 (1 ms)
        x += v * math.cos(th) * dt
        y += v * math.sin(th) * dt
        th += w * dt
    print("단계%d v=%+.2f ω=%+.3f rad/s %.1fs → x=%+.3f y=%+.3f θ=%+.1f°"
          % (i, v, w, T, x, y, math.degrees(th)))
print("회전 반경 R = L/tan|δ| = %.3f m" % (L / math.tan(abs(DELTA))))
print("메카넘: linear.y=-0.2 m/s × %.1f s → 오른쪽으로 %.2f m" % (0.38 / 0.2, 0.38))
```

```text
단계1 v=+0.15 ω=-0.573 rad/s 3.0s → x=+0.259 y=-0.300 θ=-98.6°
단계2 v=+0.15 ω=+0.573 rad/s 2.0s → x=+0.376 y=-0.559 θ=-32.9°
단계3 v=-0.15 ω=+0.573 rad/s 1.5s → x=+0.160 y=-0.528 θ=+16.4°
회전 반경 R = L/tan|δ| = 0.262 m
메카넘: linear.y=-0.2 m/s × 1.9 s → 오른쪽으로 0.38 m
```

이상적인 운동학대로라면 1단계에서 약 99° 돌아 오른쪽으로 0.3 m 들어가고, 마지막에 차체가 16° 틀어진 채 끝납니다. 실제 로봇은 조향 서보가 29°까지 가는 데 시간이 걸리고 바퀴가 미끄러지므로 이보다 덜 돕니다. 원본 시간값(3 s, 2 s, 1.5 s)은 **실물에서 맞춘 값**이라 계산과 다를 수 있으며, 이런 개루프(open-loop) 동작은 배터리 전압·바닥 마찰에 따라 결과가 달라진다는 점을 기억해야 합니다. 더 정확한 주차는 오도메트리(M03)나 주차 칸 선 검출로 **폐루프** 제어해야 합니다.

:::warning 명령값과 안전 한계
애커만 주차의 각속도 0.573 rad/s는 이 강의의 권장 한계(0.5 rad/s)를 조금 넘습니다. 원본은 속도 제한이 없는 `/controller/cmd_vel`을 쓰기 때문입니다. 좁은 공간에서 시험할 때는 속도를 0.1 m/s로 낮추고 시간을 1.5배로 늘리면 같은 궤적을 더 천천히 그립니다(각속도도 v에 비례해 줄어듦).
:::

## 유한 상태 기계로 다시 설계하기

**유한 상태 기계(FSM, Finite-State Machine)**는 시스템이 **한 번에 하나의 상태**에 있고, **사건(event)**이 일어나면 전이표에 따라 다음 상태로 옮겨 가는 모델입니다. 로봇 행동 설계에서 가장 기본적인 도구입니다.

| 요소 | 뜻 | 자율주행 예 |
|---|---|---|
| 상태 (state) | 지금 하고 있는 일 | LANE, SLOW, STOP, TURN, APPROACH, PARK, DONE |
| 사건 (event) | 인식 결과를 요약한 신호 | crosswalk, red, green, passed, curve, straight, park_sign, at_spot, done |
| 전이 (transition) | (상태, 사건) → 다음 상태 | (SLOW, red) → STOP |
| 진입 동작 (entry action) | 상태에 들어갈 때 한 번 | PARK 진입 시 `park_action()` 시작 |
| 상태 출력 | 상태에 있는 동안 계속 | 상태별 속도: LANE 0.10, SLOW 0.06, STOP 0 |

@fig[a11-fsm] 통합 자율주행 FSM. 전이표에 없는 (상태, 사건) 조합은 무시되므로, 예를 들어 회전 중에 횡단보도를 봐도 상태가 흔들리지 않습니다.

FSM 설계에서 지킬 원칙:

1. **사건은 인식 계층에서 한 번 걸러서 만든다.** "crosswalk" 사건은 "횡단보도 y > 70이 3프레임 연속"처럼 디바운싱된 뒤에 발생해야 합니다. FSM은 원시 검출값을 직접 보지 않습니다.
2. **모든 (상태, 사건) 조합을 표로 검토한다.** 7상태 × 9사건 = 63칸 중 의미 있는 칸만 채우고, 나머지가 "무시"로 괜찮은지 하나씩 확인합니다.
3. **안전 사건이 우선한다.** 어떤 상태에서든 "장애물 매우 가까움"이나 "비상 정지"는 STOP으로 가게 공통 전이를 둡니다.
4. **시간 제한(timeout)을 둔다.** STOP에서 초록불이 영영 안 보이면? 예: 30 s 뒤 경고음 + 운영자 호출 상태로.

```python run
# 통합 자율주행을 '상태 × 사건 → 다음 상태' 표로 정리한 유한 상태 기계
SPEED = {"LANE": 0.10, "SLOW": 0.06, "STOP": 0.0, "TURN": 0.10,
         "APPROACH": 0.06, "PARK": 0.0, "DONE": 0.0}
TABLE = {("LANE", "crosswalk"): "SLOW",
         ("SLOW", "red"): "STOP",
         ("STOP", "green"): "SLOW",
         ("SLOW", "passed"): "LANE",
         ("LANE", "curve"): "TURN",
         ("TURN", "straight"): "LANE",
         ("LANE", "park_sign"): "APPROACH",
         ("APPROACH", "at_spot"): "PARK",
         ("PARK", "done"): "DONE"}

timeline = [(2.0, "red"), (3.1, "crosswalk"), (3.6, "red"), (9.0, "green"),
            (13.2, "passed"), (18.0, "curve"), (18.5, "crosswalk"),
            (21.0, "straight"), (30.0, "park_sign"), (34.5, "at_spot"),
            (40.0, "done")]

state, dist, t_prev = "LANE", 0.0, 0.0
for t, ev in timeline:
    dist += SPEED[state] * (t - t_prev)          # 이전 상태 속도로 달린 거리
    t_prev = t
    nxt = TABLE.get((state, ev))
    if nxt is None:
        print("%5.1fs %-9s 무시 (상태 %s)" % (t, ev, state))
        continue
    print("%5.1fs %-9s %s → %s  (누적 %.2f m)" % (t, ev, state, nxt, dist))
    state = nxt
print("최종 상태:", state)
```

```text
  2.0s red       무시 (상태 LANE)
  3.1s crosswalk LANE → SLOW  (누적 0.31 m)
  3.6s red       SLOW → STOP  (누적 0.34 m)
  9.0s green     STOP → SLOW  (누적 0.34 m)
 13.2s passed    SLOW → LANE  (누적 0.59 m)
 18.0s curve     LANE → TURN  (누적 1.07 m)
 18.5s crosswalk 무시 (상태 TURN)
 21.0s straight  TURN → LANE  (누적 1.37 m)
 30.0s park_sign LANE → APPROACH  (누적 2.27 m)
 34.5s at_spot   APPROACH → PARK  (누적 2.54 m)
 40.0s done      PARK → DONE  (누적 2.54 m)
최종 상태: DONE
```

첫 줄처럼 횡단보도에 닿기 전 멀리서 본 빨간불은 무시되고, 회전 중에 본 횡단보도도 무시됩니다. 이것이 **의도한 동작인지** 표를 보며 판단하는 것이 설계자의 몫입니다. 예를 들어 회전 직후 바로 횡단보도가 있는 맵이라면 (TURN, crosswalk) → SLOW 칸을 채워야 합니다.

### 실물 노드 골격

원본의 `LaneDetector`와 YOLOv5 결과를 입력으로, 위 FSM을 쓰는 노드의 뼈대입니다. 사건 생성(디바운싱)과 상태 전이를 분리했습니다.

```python robot
import rclpy, numpy as np
from rclpy.node import Node
from cv_bridge import CvBridge
from sensor_msgs.msg import Image
from geometry_msgs.msg import Twist
from interfaces.msg import ObjectsInfo
from example.self_driving.lane_detect import LaneDetector

SPEED = {"LANE": 0.10, "SLOW": 0.06, "STOP": 0.0}
TABLE = {("LANE", "crosswalk"): "SLOW", ("SLOW", "red"): "STOP",
         ("STOP", "green"): "SLOW", ("SLOW", "passed"): "LANE"}

class FsmDriver(Node):
    def __init__(self):
        super().__init__('fsm_driver')
        self.state, self.t_enter, self.hits = "LANE", self.now(), {}
        self.lane = LaneDetector("yellow")
        self.bridge = CvBridge()
        self.pub = self.create_publisher(Twist, '/controller/cmd_vel', 1)
        self.create_subscription(Image, '/ascamera/camera_publisher/rgb0/image', self.on_image, 1)
        self.create_subscription(ObjectsInfo, '/yolov5_ros2/object_detect', self.on_objects, 10)

    def now(self):
        return self.get_clock().now().nanoseconds * 1e-9

    def event(self, name, need=3):             # 같은 관측이 need번 쌓이면 사건 발생
        self.hits[name] = self.hits.get(name, 0) + 1
        if self.hits[name] >= need:
            self.hits[name] = 0
            nxt = TABLE.get((self.state, name))
            if nxt:
                self.get_logger().info('%s --%s--> %s' % (self.state, name, nxt))
                self.state, self.t_enter = nxt, self.now()

    def on_objects(self, msg):
        for o in msg.objects:
            cy = (o.box[1] + o.box[3]) / 2
            if o.class_name == 'crosswalk' and cy > 70:
                self.event('crosswalk')
            elif o.class_name in ('red', 'green'):
                self.event(o.class_name, need=1 if o.class_name == 'red' else 5)

    def on_image(self, msg):
        if self.state == "SLOW" and self.now() - self.t_enter > 0.4 / SPEED["SLOW"]:
            self.event('passed', need=1)
        img = np.array(self.bridge.imgmsg_to_cv2(msg, "rgb8"), dtype=np.uint8)
        _, _, lane_x = self.lane(self.lane.get_binary(img), img.copy())
        t = Twist()
        t.linear.x = SPEED[self.state]
        if lane_x >= 0 and t.linear.x > 0:
            t.angular.z = float(np.clip(0.004 * (130 - lane_x), -0.3, 0.3))
        elif lane_x < 0:
            t.linear.x = 0.0                    # 차선을 잃으면 정지
        self.pub.publish(t)

def main():
    rclpy.init()
    node = FsmDriver()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.pub.publish(Twist())
        node.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```

빨간불은 1번(빠르게 정지), 초록불은 5번(신중히 출발) 확인하게 한 것이 A10의 비대칭 원칙입니다. 차선을 잃으면 정지하도록 A09의 문제도 고쳤습니다.

## 실습 (시뮬레이션)

## 실습 (실물)

:::safety 실물 실습 안전 수칙
- 통합 주행은 차선 유지·정지·주차가 모두 자동으로 일어납니다. 맵 주변 1 m를 비우고 **한 사람은 로봇 옆에서 따라가며** 언제든 들어 올릴 준비를 합니다.
- 주차 동작은 개루프이므로 맵 밖으로 나갈 수 있습니다. 처음에는 주차 칸 옆에 손을 두고 시험합니다.
- 원본 명령은 최대 0.15 m/s, 회전 0.45~0.57 rad/s입니다. 속도를 올리는 수정은 하지 않습니다.
- 멈추지 않으면 `ros2 service call /self_driving/set_running std_srvs/srv/SetBool "{data: false}"` 또는 `Ctrl+C`, 그래도 안 되면 전원 스위치를 끕니다.
:::

1. 맵에 표지판 4개·신호등을 교재 위치에 시계 방향으로 세우고, A01 도구로 black·white·red·green·blue·yellow 임계값을 점검합니다.

ros2 service call /self_driving/set_running std_srvs/srv/SetBool "{data: true}"

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 커브를 못 돌고 직진해 버림 | 노란 선이 ROI에서 사라짐(조명·임계값) 또는 설정점이 큼 | 임계값 재조정, 설정점 130을 줄임(일찍 회전) |
| 교차로가 아닌데 급회전 | 맵 무늬나 표지 받침의 노란색이 ROI에 들어옴 | 임계값 L·b 최소값 올리기, 소품 위치 확인 |
| 주차 표지를 지나쳐도 주차 안 함 | 횡단보도 y가 180을 못 넘음(횡단보도 인식 실패) 또는 15프레임 미달 | 횡단보도가 보이는지 `/result_img`로 확인, 문턱을 낮춤 |
| 주차 후 칸을 벗어남 | 개루프 시간·속도가 현장과 안 맞음, 배터리 전압 | `park_action()`의 시간·속도 조정, 충전 |
| 빨간불인데 통과 | 신호 판단이 감속 상태 안에서만 이뤄짐, 면적 조건 | A10의 규칙 개선 적용 |
| `set_running` 서비스가 없음 | 노드가 YOLOv5 `init_finish`를 기다리는 중 | YOLOv5 노드 로그 확인 후 잠시 대기 |
