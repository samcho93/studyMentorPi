## 학습 목표

- 자율주행용 YOLOv5 모델(`traffic_signs_640s_7_0`)의 6개 클래스와 검출 결과 메시지 구조를 설명합니다.
- `self_driving.py`의 `get_object_callback()`이 검출 결과를 "횡단보도까지 거리·신호 상태·주차 표지 위치"로 요약하는 방식을 따라갑니다.
- 영상 y 좌표로 바닥 거리를 추정하는 기하(카메라 높이·기울기)와 박스 크기로 거리를 추정하는 핀홀 모델을 계산합니다.
- 연속 프레임 확인, 면적 조건, 시간 조건으로 이루어진 정지·감속 규칙을 시뮬레이션하고, 원본 규칙의 허점을 찾아 개선안을 냅니다.
- 카메라·YOLOv5 노드를 실행해 표지판·신호등 검출을 `rqt`로 확인합니다.

## 모델과 클래스

자율주행 예제는 A08과 같은 `yolov5_ros2` 노드에 표지판 전용 모델을 넣어 씁니다.

| 항목 | 값 |
|---|---|
| 모델 파일 | `yolov5_ros2/config/traffic_signs_640s_7_0.pt` (이름으로 보아 입력 640, yolov5**s** 기반) |
| 클래스 (순서대로) | `go`, `right`, `park`, `red`, `green`, `crosswalk` |
| 추론 장치 | `device: cpu` (Raspberry Pi 5) |
| 결과 토픽 | `/yolov5_ros2/object_detect` (`ObjectsInfo`), `/result_img` |
| 시작/정지 서비스 | `/yolov5/start`, `/yolov5/stop` (`std_srvs/Trigger`) |

`self_driving.launch.py`는 YOLOv5 노드에 `classes` 목록도 파라미터로 넘기지만, `.pt` 파일 안에 클래스 이름이 저장되어 있어 실제 이름은 모델에서 나옵니다. **모델을 새로 학습할 때 클래스 이름을 똑같이** 써야 `self_driving.py`의 문자열 비교(`class_name == 'crosswalk'` 등)가 동작합니다.

예제 폴더(`yolov5_detect/`)에는 같은 모델의 TensorRT 엔진(`traffic_signs_640s_7_0.engine`)과 `yolov5_trt.py`도 있습니다. 원본 교재의 "`yolov5_trt.py`에서 클래스 줄의 주석을 바꾸라"는 단계는 이 TensorRT 경로(NVIDIA Jetson 계열)용입니다. Raspberry Pi에서는 `yolov5_ros2`의 `.pt` 경로를 씁니다.

## 검출 결과를 상황으로 요약하기

@fig[a10-decision] 검출 결과 → 상황 변수 → 주행 명령. 인식(YOLO)과 판단(규칙)을 분리하면 각각 따로 시험하고 고칠 수 있습니다.

`get_object_callback(msg)`은 메시지가 올 때마다 다음 변수들을 갱신합니다.

| 클래스 | 갱신하는 변수 | 의미 |
|---|---|---|
| `crosswalk` | `crosswalk_distance` = 박스 중심 y의 **최댓값** | 영상 아래쪽일수록 가까움. **거리의 대리값(proxy)** |
| `right` | `count_right += 1`, 5번 이상이면 `turn_right = True` | 우회전 표지 확인 |
| `park` | `park_x` = 박스 중심 x | 주차 표지의 좌우 위치 |
| `red`, `green` | `traffic_signs_status` = 그 검출 객체 | 신호 상태(박스 포함) |
| (빈 메시지) | `traffic_signs_status = None`, `crosswalk_distance = 0` | 아무것도 안 보임 |

:::info 원본 코드 읽기 팁
- A08에서 본 대로 YOLOv5 노드는 **물체마다 메시지를 따로** 보냅니다. 그래서 한 프레임에 횡단보도와 신호등이 함께 보여도 콜백은 두 번 불리고, 신호등 메시지가 올 때는 횡단보도가 없으므로 `crosswalk_distance`가 0으로 덮어써집니다. 두 물체가 번갈아 들어오며 값이 깜빡일 수 있다는 뜻입니다.
- `turn_right` 표시는 세워지지만 주 루프에서 쓰이지 않습니다. 실제 우회전은 A09의 lane_x > 150 규칙(차선이 휘는 것)으로 일어납니다(A11에서 자세히).
:::

## 거리 추정: 영상 좌표에서 미터로

원본은 "횡단보도 중심 y > 70이면 가깝다"처럼 **픽셀 값을 그대로** 씁니다. 이 숫자가 실제 몇 m인지 알면 규칙을 설계하고 다른 카메라로 옮기기 쉬워집니다.

@fig[a10-ground-ray] 바닥 평면 위 점의 거리. 카메라 높이 h, 아래로 기운 각 θ, 영상 y에 해당하는 광선 각을 더하면 바닥과 만나는 거리 Z가 나옵니다.

### 바닥 평면 모델

카메라가 높이 $h$에서 수평보다 $θ$만큼 아래를 보고, 초점거리 $f$ [px], 영상 중심 $c_y$라 하면 영상 행 $y$로 들어오는 광선은 수평선 아래 $θ + atan((y − c_y)/f)$ 각도로 내려갑니다. 평평한 바닥과 만나는 전방 거리는

```text
Z = h / tan( θ + atan((y − c_y) / f) )
```

입니다. 광선 각이 0 이하이면(수평선 위) 바닥과 만나지 않습니다.

### 핀홀 크기 모델

실제 높이 $H$인 표지판이 영상에서 $h_{px}$ 픽셀이면 $Z = f · H / h_{px}$입니다. 박스 높이가 절반이 되면 거리가 두 배입니다. 박스 **면적**은 거리의 제곱에 반비례합니다.

아래 계산의 카메라 높이 0.12 m, 기울기 25°, 초점거리 480 px, 표지판 높이 0.10 m는 **설명용 가정값**입니다. 실제 값은 카메라 보정(`camera_info`)과 줄자로 재야 합니다.

@btn[~/tools/playground.html] Playground 열기

```python run
import math

# 가정값: 카메라 높이 h, 아래로 기운 각 tilt, 초점거리 f, 영상 중심 cy (640x480)
h, tilt, f, cy = 0.12, math.radians(25), 480.0, 240.0

def ground_distance(y):
    """영상 y(px)에 보이는 바닥 점까지의 전방 거리 [m] — 평평한 바닥 가정"""
    ray = tilt + math.atan((y - cy) / f)          # 수평선 아래로 내려간 각
    return h / math.tan(ray) if ray > 0 else float("inf")

for y in (70, 135, 180, 240, 400):
    print("횡단보도 중심 y=%3d px → 약 %.2f m 앞" % (y, ground_distance(y)))

def sign_distance(h_px, H_real=0.10):              # 핀홀: Z = f·H / h
    return f * H_real / h_px
for hp in (30, 60, 120):
    print("표지판 박스 높이 %3d px → 약 %.2f m" % (hp, sign_distance(hp)))
```

```text
횡단보도 중심 y= 70 px → 약 1.25 m 앞
횡단보도 중심 y=135 px → 약 0.53 m 앞
횡단보도 중심 y=180 px → 약 0.37 m 앞
횡단보도 중심 y=240 px → 약 0.26 m 앞
횡단보도 중심 y=400 px → 약 0.13 m 앞
표지판 박스 높이  30 px → 약 1.60 m
표지판 박스 높이  60 px → 약 0.80 m
표지판 박스 높이 120 px → 약 0.40 m
```

원본 규칙의 세 문턱값 70·135·180 px(감속 시작, 주차 준비, 주차 시작)이 이 가정에서는 약 1.25 m, 0.53 m, 0.37 m에 해당합니다. 영상 y와 거리의 관계는 **비선형**이어서, 영상 위쪽(먼 곳)에서는 1 px이 수 cm에 해당하고 아래쪽(가까운 곳)에서는 1 px이 1 mm 정도입니다. 먼 곳의 판단일수록 검출 박스가 몇 px만 흔들려도 거리 추정이 크게 흔들리므로 **여러 프레임 확인**이 필요합니다.

## 정지·감속 규칙

주 루프의 횡단보도·신호등 규칙을 정리합니다.

| 단계 | 조건 | 동작 |
|---|---|---|
| 감속 시작 | `crosswalk_distance > 70`이 **3프레임 연속** | `start_slow_down = True`, 시각 기록 |
| 빨간불 | 감속 중 + `red` + 박스 면적 < 1000 px² | 정지 명령, `stop = True` |
| 초록불 | 감속 중 + `green` | `stop = False`, 서행 |
| 감속 해제 | 정지 아님 + 감속 시작 후 `crosswalk_length / v` 초 경과 | `start_slow_down = False` |
| 평상시 | | `linear.x = normal_speed` |

`crosswalk_length = 0.1 + 0.3 = 0.4 m`는 "횡단보도 폭 + 로봇 길이"입니다. 로봇 **꼬리까지** 횡단보도를 벗어나려면 그만큼 더 가야 하므로, 서행 속도 0.1 m/s면 4초 동안 감속을 유지합니다.

```python run
# self_driving.py 의 횡단보도·신호등 규칙만 떼어 낸 시뮬레이션 (프레임 간격 0.1 s)
def obj(name, box):
    return {"class_name": name, "box": box}

frames = ([[obj("crosswalk", [200, 40, 440, 60])]] * 3 +                       # 멀리
          [[obj("crosswalk", [200, 70, 440, 100]), obj("red", [500, 60, 520, 100])]] * 4 +
          [[obj("red", [500, 60, 520, 100])]] * 5 +                             # 빨간불 대기
          [[obj("green", [500, 60, 520, 100])]] * 2 + [[]] * 40)

normal, slow, cross_len = 0.1, 0.1, 0.1 + 0.3     # 원본 값: 횡단보도+로봇 길이 0.4 m
count_cw, slowing, stop, t_slow, light = 0, False, False, None, None
for i, objs in enumerate(frames):
    t = i * 0.1
    ys = [(o["box"][1] + o["box"][3]) / 2 for o in objs if o["class_name"] == "crosswalk"]
    cw_dist = max(ys) if ys else 0                 # 가장 가까운(아래쪽) 횡단보도 y
    lights = [o for o in objs if o["class_name"] in ("red", "green")]
    light = lights[-1] if lights else (None if not objs else light)
    if 70 < cw_dist and not slowing:
        count_cw += 1
        if count_cw == 3:                          # 3프레임 연속 확인
            count_cw, slowing, t_slow = 0, True, t
            print("%.1fs 감속 시작 (y=%.0f)" % (t, cw_dist))
    else:
        count_cw = 0
    v = normal
    if slowing:
        if light:
            b = light["box"]
            area = abs(b[0] - b[2]) * abs(b[1] - b[3])
            if light["class_name"] == "red" and area < 1000:
                if not stop: print("%.1fs 빨간불 정지 (면적 %d)" % (t, area))
                stop = True
            elif light["class_name"] == "green":
                if stop: print("%.1fs 초록불 출발" % t)
                stop = False
        if not stop:
            v = slow
            if t - t_slow > cross_len / v:         # 0.4 / 0.1 = 4 s 뒤 감속 해제
                slowing = False
                print("%.1fs 감속 해제" % t)
    if stop:
        v = 0.0
print("마지막 속도 %.1f m/s" % v)
```

```text
0.5s 감속 시작 (y=85)
0.5s 빨간불 정지 (면적 800)
1.2s 초록불 출발
4.6s 감속 해제
마지막 속도 0.1 m/s
```

### 원본 규칙의 허점

시뮬레이션을 돌려 보면 원본 규칙에서 고칠 점이 보입니다. 실제 자율주행 시스템 설계에서도 이런 **규칙 검토(rule review)**가 중요한 단계입니다.

| 관찰 | 원인 | 개선안 |
|---|---|---|
| "감속"해도 속도가 그대로 0.1 m/s | `normal_speed`와 `slow_down_speed`가 둘 다 0.1 | 서행을 0.05~0.06으로 낮춤 |
| 빨간불 대기 시간까지 감속 시간 4 s에 포함 | 시각을 감속 **시작** 시점에만 기록 | 초록불 출발 시점에 시각을 다시 기록 |
| 빨간불 박스가 **작을 때만**(면적 < 1000) 정지 | 이 맵에서 신호등이 보이는 크기에 맞춘 값 | 면적 대신 바닥 거리(신호등 받침 y)나 박스 높이로 조건을 만들고 범위(최소~최대)로 지정 |
| 빨간불을 한 프레임만 봐도 정지 | 신호등에는 연속 확인이 없음 | 빨간불도 3프레임 확인. 반대로 **초록불 출발은 더 신중하게**(5프레임) |
| 횡단보도가 안 보이면 신호등을 무시 | 신호 판단이 감속 상태 안에만 있음 | 신호등 거리가 가까우면 횡단보도와 무관하게 판단 |

:::tip 비대칭 확인 횟수
안전과 관련된 판단은 **틀렸을 때의 손해가 비대칭**입니다. 빨간불을 놓치는 것(멈춰야 할 때 안 멈춤)은 초록불을 늦게 보는 것(갈 수 있는데 조금 늦게 감)보다 훨씬 위험합니다. 그래서 "정지로 가는 판단"은 빠르게, "출발로 가는 판단"은 여러 프레임 확인 후에 내리는 것이 원칙입니다.
:::

### 신호 상태를 한 번 더 확인하기

YOLO가 `red`와 `green`을 헷갈리는 일이 드물게 있습니다. 박스 안의 색을 A01의 방법(HSV/LAB 임계값)으로 한 번 더 세어 보면 교차 검증이 됩니다.

```python robot
import cv2
import numpy as np

def light_color(bgr_image, box):
    """YOLO 신호등 박스 안에서 빨강·초록 픽셀 수를 비교해 색을 확인한다."""
    x1, y1, x2, y2 = box
    roi = cv2.cvtColor(bgr_image[y1:y2, x1:x2], cv2.COLOR_BGR2HSV)
    red = cv2.inRange(roi, (0, 120, 120), (10, 255, 255)) | \
          cv2.inRange(roi, (170, 120, 120), (180, 255, 255))    # 빨강은 H 양 끝
    green = cv2.inRange(roi, (45, 100, 100), (90, 255, 255))
    r, g = int(np.count_nonzero(red)), int(np.count_nonzero(green))
    if max(r, g) < 20:
        return "unknown"
    return "red" if r > g else "green"
```

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 표지판을 전혀 못 찾음 | 신뢰도 문턱이 높거나 조명이 어두움 | 조명 개선, 노드 코드에서 검출 신뢰도 문턱을 낮춤 |
| 없는 표지판이 자꾸 검출됨 | 신뢰도 문턱이 낮음, 배경에 비슷한 무늬 | 문턱을 올리고, 오검출 배경 사진을 넣어 재학습(A08) |
| `red`/`green` 뒤바뀜 | 신호등 LED가 과노출되어 흰색으로 찍힘 | 카메라 노출 조정, 위의 색 재확인 함수 사용 |
| `model:=...`을 바꿔도 같은 모델 | launch가 모델명을 고정 | launch 파일 수정 또는 `ros2 run yolov5_ros2 yolo_detect --ros-args -p model:=...` |
| 검출이 1초에 한두 번뿐 | CPU 추론 부하, 결과 영상 발행 | `pub_result_img`를 끄고 확인, 다른 무거운 노드 종료 |
| 신호등 가까이서 빨간불인데 안 멈춤 | 박스 면적이 1000 px²를 넘어 조건 불만족 | 면적 조건을 범위로 바꾸거나 거리 기반 조건 사용 |
