## 인공지능, 머신러닝, 딥러닝

**인공지능(AI, Artificial Intelligence)**은 사람의 지능을 흉내 내고 확장하는 기술 전체를 말합니다. 그 안에서 **머신러닝(Machine Learning)**은 규칙을 사람이 적는 대신 **데이터로부터 규칙(모델)을 학습**하는 방법이고, **딥러닝(Deep Learning)**은 머신러닝 가운데 여러 층의 신경망을 쓰는 방법입니다. 바둑에서 세계 챔피언을 이긴 AlphaGo가 대표적인 딥러닝 사례입니다.

A01에서 만든 색 인식은 사람이 LAB 임계값이라는 **규칙**을 정했습니다. 반면 이 장의 YOLOv5는 "이 사진의 이 상자가 우회전 표지판"이라는 **예시**를 수백 장 보여 주면 규칙을 스스로 찾습니다. 조명·각도·배경이 다양할수록 규칙을 사람이 적기 어려워지므로 학습이 유리해집니다.

### 학습의 세 종류

| 종류 | 데이터 | 목표 | 로봇 예 |
|---|---|---|---|
| **지도 학습** (Supervised) | 입력 + 정답 라벨 | 새 입력의 정답 예측 | 표지판 사진 + 상자 라벨 → YOLOv5 |
| **비지도 학습** (Unsupervised) | 입력만 | 데이터 속 구조(군집 등) 발견 | 라이다 점들을 물체별로 묶기(군집화) |
| **강화 학습** (Reinforcement) | 행동 → 보상 | 누적 보상 최대화 정책 | 시뮬레이터에서 넘어지지 않는 보행 학습 |

지도 학습은 네 단계로 이루어집니다.

1. **모델 선택**: 선형 회귀, 로지스틱 회귀, 결정 트리, SVM, 심층 신경망 등 문제에 맞는 모델을 고릅니다.
2. **특징 공학(feature engineering)**: 데이터 정리, 결측값 처리, 정규화 등. 딥러닝은 특징을 스스로 배우지만 입력 크기·정규화 같은 전처리는 여전히 필요합니다(YOLOv5의 레터박스, 0~1 정규화).
3. **학습과 최적화**: 손실 함수를 정하고 경사 하강법(gradient descent)이나 확률적 경사 하강법(SGD)으로 파라미터를 조금씩 바꿔 손실을 줄입니다.
4. **평가**: 학습에 쓰지 않은 데이터로 정확도·정밀도·재현율·F1 등을 잽니다.

## YOLO: 한 번 보고 모두 찾기

**YOLO(You Only Look Once)**가 나오기 전에는 R-CNN 계열 **2단계(two-stage)** 검출기가 주류였습니다. 1단계에서 물체가 있을 법한 후보 영역 수천 개를 뽑고, 2단계에서 후보마다 분류했기 때문에 정확하지만 느렸습니다. YOLO는 검출을 **하나의 회귀 문제**로 바꿔, 영상 전체를 한 번 통과시켜 모든 상자와 클래스를 동시에 출력하는 **1단계(one-stage)** 검출기입니다.

### YOLOv5 구조

@fig[a07-yolo-arch] YOLOv5 구조와 640 입력에서의 세 출력 격자. 작은 물체는 촘촘한 80×80 격자(P3)가, 큰 물체는 20×20 격자(P5)가 맡습니다.

| 부분 | 하는 일 | YOLOv5의 선택 |
|---|---|---|
| **입력** | 크기 맞추기, 데이터 증강 | 레터박스(비율 유지 + 회색 패딩), Mosaic 증강(학습 시 4장 합성), 적응형 앵커 계산 |
| **백본(Backbone)** | 특징 추출 | Conv(합성곱+BN+SiLU), C3(CSP 잔차 묶음). 원본 교재가 설명한 Focus는 v6.0부터 6×6 합성곱으로 대체 |
| **넥(Neck)** | 여러 크기 특징 섞기 | SPPF(연속 최대 풀링), FPN(위→아래) + PAN(아래→위) |
| **헤드(Head)** | 박스·점수 예측 | 3개 스케일(stride 8/16/32) × 격자 셀마다 앵커 3개 |

원본 교재가 소개하는 구성 요소를 정리하면 다음과 같습니다. **합성곱층**은 작은 커널을 영상 위로 밀며 특징을 뽑고, **풀링층**(최대 풀링)은 크기를 줄이며 강한 특징만 남기고, **업샘플링층**은 크기를 키워 다른 층과 합칠 수 있게 합니다. **배치 정규화(BN)**는 층 출력의 분포를 고르게 해 학습을 안정시키고, **활성화 함수**(ReLU, SiLU 등)는 비선형성을 넣어 층을 여러 개 쌓는 의미를 만듭니다. **Add**는 잔차 연결처럼 텐서를 더하고, **Concat**은 채널 방향으로 이어 붙입니다.

### 출력 텐서 읽기

입력이 640×640이면 세 격자의 셀 수는 $80² + 40² + 20² = 8400$개이고, 셀마다 앵커 3개이므로 **예측은 25,200개**입니다. 예측 하나는 `5 + nc`개의 숫자입니다.

```text
[ tx, ty, tw, th,  obj,  p_0, p_1, ..., p_(nc-1) ]
  └ 박스 4개 ┘  객체성   클래스 확률 nc개
```

자율주행 표지판 모델(`traffic_signs_640s_7_0`)은 클래스가 6개(`go, right, park, red, green, crosswalk`)이므로 25,200 × 11 행렬이 나옵니다. 박스는 격자 셀 위치 $(c_x, c_y)$, stride $s$, 앵커 크기 $(p_w, p_h)$로 복원합니다(σ는 시그모이드).

```text
b_x = (2·σ(t_x) − 0.5 + c_x) · s          b_w = p_w · (2·σ(t_w))²
b_y = (2·σ(t_y) − 0.5 + c_y) · s          b_h = p_h · (2·σ(t_h))²
최종 점수 = obj × p_class
```

중심은 자기 셀에서 −0.5~1.5칸까지, 크기는 앵커의 0~4배까지 움직일 수 있습니다. 이 "4배"가 뒤에 나올 `anchor_t = 4.0`과 짝을 이룹니다.

## IoU와 NMS

@fig[a07-iou-nms] 왼쪽: IoU = 교집합 ÷ 합집합. 오른쪽: NMS는 점수 순으로 하나를 채택하고, 같은 클래스에서 많이 겹치는 상자를 지웁니다.

한 물체 주변의 여러 셀·앵커가 동시에 "여기 있다"고 답하므로 25,200개 예측에는 중복이 많습니다. 이를 정리하는 것이 **NMS(Non-Maximum Suppression)**이고, 겹침 정도를 재는 척도가 **IoU(Intersection over Union)**입니다.

```text
IoU(A, B) = |A ∩ B| / |A ∪ B| = 교집합 넓이 / (A 넓이 + B 넓이 − 교집합 넓이)
```

`yolov5_trt.py`의 `non_max_suppression()` 순서는 다음과 같습니다.

1. 신뢰도 < `conf_thres`(원본 기본 0.8, 노드 파라미터 `conf`)인 예측을 버립니다.
2. 중심·크기 표기(cx, cy, w, h)를 모서리 표기(x1, y1, x2, y2)로 바꾸고, 레터박스 패딩을 빼서 원본 영상 좌표로 되돌립니다.
3. 신뢰도 내림차순으로 정렬합니다.
4. 맨 위 상자를 채택하고, **같은 클래스이면서** IoU > `nms_thres`(0.4)인 상자를 모두 지웁니다. 남은 상자가 없을 때까지 반복합니다.

클래스가 다르면 겹쳐도 지우지 않으므로(class-aware NMS), 신호등 상자와 그 옆 표지판 상자가 겹쳐도 둘 다 살아남습니다.

### 실습: IoU와 NMS 구현

@btn[~/tools/playground.html] Playground 열기

```python run
import numpy as np

def iou(box, boxes):
    """box: (4,), boxes: (N,4)  [x1, y1, x2, y2] → (N,) IoU"""
    ix1 = np.maximum(box[0], boxes[:, 0])
    iy1 = np.maximum(box[1], boxes[:, 1])
    ix2 = np.minimum(box[2], boxes[:, 2])
    iy2 = np.minimum(box[3], boxes[:, 3])
    inter = np.clip(ix2 - ix1, 0, None) * np.clip(iy2 - iy1, 0, None)
    a1 = (box[2] - box[0]) * (box[3] - box[1])
    a2 = (boxes[:, 2] - boxes[:, 0]) * (boxes[:, 3] - boxes[:, 1])
    return inter / (a1 + a2 - inter + 1e-16)

def nms(det, conf_thres=0.5, iou_thres=0.4):
    """det: (N,6) [x1,y1,x2,y2,conf,cls] → 남은 행 (yolov5_trt.py 와 같은 순서)"""
    det = det[det[:, 4] >= conf_thres]          # ① 신뢰도 필터
    det = det[np.argsort(-det[:, 4])]           # ② 신뢰도 내림차순
    keep = []
    while len(det):
        keep.append(det[0])                     # ③ 가장 높은 것 채택
        same = det[:, 5] == det[0, 5]           # ④ 같은 클래스 중
        over = iou(det[0, :4], det[:, :4]) > iou_thres
        det = det[~(same & over)]               #    많이 겹치는 것 제거(자기 자신 포함)
    return np.array(keep)

a = np.array([100, 100, 200, 200.])
print("IoU 예:", np.round(iou(a, np.array([[150, 150, 250, 250.],
                                            [110, 100, 210, 200.],
                                            [300, 300, 350, 350.]])), 4))
names = ["go", "right", "park", "red", "green", "crosswalk"]
det = np.array([[100, 100, 200, 200, 0.92, 1],   # right
                [110, 105, 205, 210, 0.85, 1],   # right (중복)
                [150, 150, 250, 250, 0.60, 1],   # right (조금 겹침)
                [105, 100, 200, 205, 0.80, 2],   # park (다른 클래스)
                [400, 50, 430, 120, 0.45, 3]])   # red (신뢰도 낮음)
for r in nms(det):
    print(names[int(r[5])], r[:4].astype(int).tolist(), r[4])
```

```text
IoU 예: [0.1429 0.8182 0.    ]
right [100, 100, 200, 200] 0.92
park [105, 100, 200, 205] 0.8
right [150, 150, 250, 250] 0.6
```

- 절반씩 어긋난 두 정사각형의 IoU는 $2500 / (10000 + 10000 − 2500) = 0.1429$로 생각보다 작습니다. IoU 0.5는 "상당히 겹친다"는 뜻입니다.
- 0.85짜리 `right`는 0.92짜리와 IoU 0.748이라 지워졌고, 0.60짜리 `right`는 IoU 0.143이라 **다른 물체로 보고** 남았습니다.
- `park`는 첫 상자와 거의 겹치지만 클래스가 달라 남습니다. 0.45짜리 `red`는 1단계에서 탈락했습니다.

:::info +1 픽셀 관례
`yolov5_trt.py`의 `bbox_iou()`는 넓이를 `(x2 − x1 + 1) × (y2 − y1 + 1)`로 계산합니다. 픽셀 좌표를 "양 끝 포함"으로 보는 옛 PASCAL VOC 관례입니다. 위 구현은 연속 좌표 관례(+1 없음)를 썼으며, 상자가 수십 픽셀 이상이면 차이는 무시할 만합니다.
:::

## 성능 지표: 정밀도, 재현율, mAP

검증 이미지에서 예측 상자가 정답 상자와 IoU ≥ 0.5이면 **TP(참 양성)**, 아니면 **FP(거짓 양성)**, 찾지 못한 정답은 **FN(거짓 음성)**입니다.

```text
정밀도 P = TP / (TP + FP)     "찾았다고 한 것 중 맞은 비율"
재현율 R = TP / (TP + FN)     "실제 물체 중 찾아낸 비율"
```

신뢰도 문턱을 낮추면 R은 오르고 P는 떨어집니다. 문턱을 1에서 0까지 내리며 그린 **P–R 곡선 아래 넓이가 AP(Average Precision)**이고, 클래스별 AP의 평균이 **mAP**입니다. YOLOv5가 출력하는 두 지표는 다음과 같습니다.

- `mAP_0.5`: IoU 문턱 0.5에서의 mAP
- `mAP_0.5:0.95`: IoU 문턱 0.5, 0.55, …, 0.95 (10개)의 mAP 평균 — 상자를 **정확히** 그려야 높음

```python run
import numpy as np

# 검증 세트: 정답(GT) 8개, 예측 10개 (IoU≥0.5로 이미 TP/FP 판정됨)
scores = np.array([0.95, 0.91, 0.88, 0.80, 0.74, 0.66, 0.60, 0.52, 0.41, 0.30])
is_tp  = np.array([1,    1,    0,    1,    1,    0,    1,    1,    0,    1])
n_gt = 8

order = np.argsort(-scores)                 # 신뢰도 높은 것부터 누적
tp = np.cumsum(is_tp[order])
fp = np.cumsum(1 - is_tp[order])
recall = tp / n_gt
precision = tp / (tp + fp)
for k in (0, 2, 4, 7, 9):
    print("상위 %2d개: P=%.3f R=%.3f" % (k + 1, precision[k], recall[k]))

mrec = np.concatenate(([0.0], recall, [1.0]))
mpre = np.concatenate(([1.0], precision, [0.0]))
mpre = np.flip(np.maximum.accumulate(np.flip(mpre)))   # 정밀도 포락선(오른쪽 최대)
x = np.linspace(0, 1, 101)                             # COCO 101점 보간
y = np.interp(x, mrec, mpre)
ap = np.sum((y[1:] + y[:-1]) / 2 * np.diff(x))         # 사다리꼴 적분
print("AP@0.5 = %.4f" % ap)

# 앵커 매칭: anchor_t = 4.0 (hyp.scratch-low.yaml)
anchors = {"P3/8":  [(10, 13), (16, 30), (33, 23)],
           "P4/16": [(30, 61), (62, 45), (59, 119)],
           "P5/32": [(116, 90), (156, 198), (373, 326)]}
gw, gh = 60, 60                                         # 640 입력에서 표지판 60x60 px
for level, anc in anchors.items():
    ok = [a for a in anc if max(gw / a[0], a[0] / gw, gh / a[1], a[1] / gh) < 4.0]
    print(level, "매칭 앵커:", ok)
```

```text
상위  1개: P=1.000 R=0.125
상위  3개: P=0.667 R=0.250
상위  5개: P=0.800 R=0.500
상위  8개: P=0.750 R=0.750
상위 10개: P=0.700 R=0.875
AP@0.5 = 0.7672
P3/8 매칭 앵커: [(16, 30), (33, 23)]
P4/16 매칭 앵커: [(30, 61), (62, 45), (59, 119)]
P5/32 매칭 앵커: [(116, 90), (156, 198)]
```

AP 계산은 `software/yolov5/utils/metrics.py`의 `compute_ap()`와 같은 방식입니다. **정밀도 포락선**은 "재현율이 이보다 높은 구간에서 얻을 수 있는 최대 정밀도"로 곡선을 계단 모양으로 펴 주는 단계입니다. 정답 8개 중 1개는 끝까지 못 찾았으므로(R 최대 0.875) AP는 1이 될 수 없습니다.

## 앵커와 손실 함수

### 앵커 매칭

**앵커(anchor)**는 격자마다 미리 정해 둔 기준 상자 크기입니다. `models/yolov5n.yaml`에 스케일마다 3개씩 적혀 있습니다(위 코드의 `anchors`). 학습 때 정답 상자는 **가로·세로 비가 앵커의 1/4~4배 안에 드는 모든 앵커**에 배정됩니다. 위 결과처럼 60×60 표지판은 세 스케일의 앵커 7개가 동시에 배우므로 한 물체에서 양성 샘플이 여러 개 생깁니다. 원본 교재가 말하는 "사전 상자(prior box)"가 바로 이 앵커입니다.

학습 시작 시 YOLOv5는 데이터셋 라벨 크기와 기본 앵커가 잘 맞는지 검사하고(`AutoAnchor`), 맞지 않으면 k-means로 앵커를 새로 계산합니다. 원본 교재의 "적응형 앵커 계산"이 이것입니다.

### 손실 함수

| 손실 | 무엇을 벌하나 | 방법 | 가중치(`hyp.scratch-low.yaml`) |
|---|---|---|---|
| `box_loss` | 상자 위치·크기 오차 | 1 − CIoU | `box: 0.05` |
| `obj_loss` | 물체 유무 판단 오차 | BCE(이진 교차 엔트로피), 목표값 = IoU | `obj: 1.0`, 스케일별 4.0/1.0/0.4 배 |
| `cls_loss` | 클래스 판단 오차 | BCE | `cls: 0.5` |

**CIoU**는 IoU에 중심 거리 항과 가로세로비 항을 더한 척도입니다. 상자가 전혀 겹치지 않으면 IoU는 0이라 기울기가 없지만, 중심 거리 항 덕분에 CIoU는 "어느 쪽으로 옮겨야 하는지" 알려 줍니다. 원본 교재는 GIoU를 언급하는데, 이는 초기 버전 설명이고 현재 코드(`utils/loss.py`)는 `CIoU=True`입니다. 클래스가 하나뿐인 데이터셋에서는 `cls_loss`가 항상 0으로 기록됩니다(A08).

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 같은 표지판에 상자가 여러 개 겹쳐 나옴 | NMS IoU 문턱이 너무 높음 | `iou_thres`를 0.45 → 0.3으로 낮춤 |
| 가까이 붙은 두 표지판 중 하나가 사라짐 | NMS IoU 문턱이 너무 낮아 다른 물체까지 지움 | `iou_thres`를 올리거나 표지판 간격을 넓힘 |
| 엉뚱한 곳에 낮은 점수 상자가 뜸 | 신뢰도 문턱이 낮음 | `conf`를 올림. 대신 먼 표지판은 늦게 잡힘 |
| mAP_0.5는 높은데 mAP_0.5:0.95가 낮음 | 상자 위치가 대충 맞음 | 라벨 상자를 물체에 딱 맞게 다시 그림, 학습 epoch 증가 |
| 상자 좌표가 위아래로 일정하게 어긋남 | 레터박스 패딩을 빼지 않고 좌표 변환 | `xywh2xyxy`처럼 `(640 − 480·r)/2`를 빼고 비율로 나눔 |
| `Arrays of 2-dimensional vectors are deprecated` 경고 | NumPy 2에서 2D `np.cross` 사용 | 외적을 `a[0]*b[1] − a[1]*b[0]`로 직접 계산 |
