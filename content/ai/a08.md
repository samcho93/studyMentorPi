## 학습 목표

- 사진 수집(`collect_picture`) → 라벨링(`labelImg`) → 변환(`xml2yolo.py`) → 학습(`train.py`) → 배포(`yolov5_ros2`) 전체 흐름을 직접 수행합니다.
- PASCAL VOC XML 라벨과 YOLO txt 라벨의 차이를 알고, 정규화 좌표 변환을 손으로 계산합니다.
- `--img`, `--batch`, `--epochs`, `--weights`와 `hyp.scratch-low.yaml`의 주요 하이퍼파라미터(학습률·워밍업·증강)가 무엇을 바꾸는지 설명합니다.
- `results.csv`의 손실·mAP 곡선을 읽고 과적합·과소적합을 판단합니다.
- 학습한 `best.pt`를 로봇의 YOLOv5 노드에 넣고 `/yolov5_ros2/object_detect` 토픽으로 결과를 확인합니다.

## ① 사진 수집

`collect_picture/main.py`는 카메라 토픽(`/ascamera/camera_publisher/rgb0/image`)을 받아 보여 주는 Qt 프로그램입니다. `Save(space)`를 누르거나 스페이스바를 치면 현재 프레임을 `config.ini`의 크기(640×480)로 맞춰 `저장경로/JPEGImages/`에 저장합니다. 화면 왼쪽 위의 `save number`는 이번 사진 번호, `existing`은 폴더에 있는 사진 수입니다.

좋은 데이터셋의 조건:

- **다양성**: 거리(30 cm ~ 1.5 m), 각도(정면·비스듬히), 기울기, 조명(밝음·어두움·역광), 배경을 골고루 섞습니다. 모델은 **본 적 있는 조건만** 잘 맞힙니다.
- **실제 사용 조건과 같게**: 자율주행 표지판이라면 로봇 카메라 높이에서, 맵 위에 놓인 상태로 찍습니다. 손에 들고 찍은 사진만으로 학습하면 맵 위에서 성능이 떨어집니다.
- **양**: 원본 교재 권장은 **클래스당 200장 이상**입니다. 클래스 사이 장수가 크게 차이 나면(예: `go` 500장, `park` 50장) 모델이 많은 쪽으로 치우칩니다.
- **음성 예**: 표지판이 없는 맵 사진도 일부 넣으면 "아무것도 없음"을 배워 오검출이 줄어듭니다. 단, `xml2yolo.py`는 **XML 파일이 있는 사진만** 학습 목록에 넣으므로 음성 예에도 물체 없는 라벨 파일이 있어야 합니다.

## ② labelImg 라벨링

| 단축키 | 기능 |
|---|---|
| `Ctrl+U` | 사진 폴더(JPEGImages) 열기 |
| `Ctrl+R` | 라벨 저장 폴더(Annotations) 지정 |
| `W` | 상자 그리기 시작 |
| `Ctrl+S` | 현재 사진 라벨 저장 |
| `A` / `D` | 이전 / 다음 사진 |

상자를 그린 뒤 뜨는 창에 클래스 이름(예: `right`, `turn_around`)을 입력합니다. 이름은 대소문자·밑줄까지 `classes.names`와 **글자 하나 다르지 않게** 맞춰야 합니다. 상자는 물체 테두리에 딱 붙게 그립니다. 여백을 크게 잡으면 모델도 여백까지 물체로 배워 `mAP_0.5:0.95`가 낮아집니다.

labelImg는 PASCAL VOC 형식 XML을 저장합니다. 사진 한 장당 파일 하나이고, 물체마다 `<object>`가 하나씩 들어갑니다.

```text
<annotation>
  <filename>12.jpg</filename>
  <size><width>640</width><height>480</height><depth>3</depth></size>
  <object>
    <name>right</name><pose>Unspecified</pose><truncated>0</truncated><difficult>0</difficult>
    <bndbox><xmin>250</xmin><ymin>120</ymin><xmax>330</xmax><ymax>210</ymax></bndbox>
  </object>
</annotation>
```

## ③④ YOLO 형식으로 변환

@fig[a08-yolo-label] VOC(픽셀 모서리 좌표)에서 YOLO(정규화 중심·크기)로의 변환.

YOLOv5는 사진과 **같은 이름의 `.txt`** 파일을 라벨로 읽습니다. 한 줄이 물체 하나이고, 모든 좌표는 영상 크기로 나눈 0~1 값입니다.

```text
<클래스번호> <x_center> <y_center> <width> <height>
x_center = (xmin + xmax) / (2·W)      width  = (xmax − xmin) / W
y_center = (ymin + ymax) / (2·H)      height = (ymax − ymin) / H
```

정규화하는 이유는 학습 때 사진 크기를 바꾸거나(`--img 640`) 뒤집고 잘라도(증강) 라벨을 쉽게 따라 바꾸기 위해서입니다. 클래스 번호는 `classes.names`의 **줄 순서(0부터)**입니다.

`xml2yolo.py`가 하는 일을 그대로 옮긴 코드로 확인합니다.

@btn[~/tools/playground.html] Playground 열기

```python run
import xml.etree.ElementTree as ET

xml_text = """<annotation>
  <folder>JPEGImages</folder><filename>12.jpg</filename>
  <size><width>640</width><height>480</height><depth>3</depth></size>
  <object><name>right</name><pose>Unspecified</pose><truncated>0</truncated>
    <difficult>0</difficult>
    <bndbox><xmin>250</xmin><ymin>120</ymin><xmax>330</xmax><ymax>210</ymax></bndbox>
  </object>
  <object><name>park</name><pose>Unspecified</pose><truncated>0</truncated>
    <difficult>0</difficult>
    <bndbox><xmin>420</xmin><ymin>100</ymin><xmax>500</xmax><ymax>196</ymax></bndbox>
  </object>
</annotation>"""
class_names = ["go", "right", "park", "red", "green", "crosswalk"]   # classes.names 순서

root = ET.fromstring(xml_text)
W = int(root.find("size")[0].text)
H = int(root.find("size")[1].text)
for member in root.findall("object"):            # xml2yolo.single_xml_to_txt 와 같은 계산
    cls = class_names.index(member[0].text)
    xmin, ymin, xmax, ymax = (int(member[4][k].text) for k in range(4))
    xc = (xmin + xmax) / (2 * W)
    yc = (ymin + ymax) / (2 * H)
    bw = (xmax - xmin) / W
    bh = (ymax - ymin) / H
    print(cls, xc, yc, bw, bh)

def split_counts(n):                              # xml2yolo.split(): 5 % / 15 % / 80 %
    o1, o2 = int(n * 0.05), int(n * 0.2)
    return {"test": o1, "val": o2 - o1, "train": n - o2}
for n in (37, 200, 1200):
    print(n, "장 →", split_counts(n))
```

```text
1 0.453125 0.34375 0.125 0.1875
2 0.71875 0.30833333333333335 0.125 0.2
37 장 → {'test': 1, 'val': 6, 'train': 30}
200 장 → {'test': 10, 'val': 30, 'train': 160}
1200 장 → {'test': 60, 'val': 180, 'train': 960}
```

`xml2yolo.py`에서 알아 둘 동작:

- `member[4]`처럼 **자식 순서**로 `bndbox`를 찾습니다. labelImg가 만든 XML은 순서가 `name, pose, truncated, difficult, bndbox`로 고정이라 동작하지만, 다른 도구로 만든 XML은 순서가 달라 실패할 수 있습니다. 오류는 `except: pass`로 **조용히 무시**되므로 변환 후 클래스별 개수 출력(`right:120` 등)을 꼭 확인합니다.
- 사진을 무작위로 섞은 뒤 **test 5 %, val 15 %, train 80 %**로 나눕니다. `random.seed`를 고정하지 않아 실행할 때마다 분할이 달라집니다.
- `.txt` 라벨은 `Annotations`가 아니라 **`JPEGImages` 폴더의 사진 옆**에 씁니다. YOLOv5는 사진 경로의 `/images/`를 `/labels/`로 바꿔 라벨을 찾는데, 경로에 `images` 폴더가 없으면 사진과 같은 폴더에서 찾기 때문입니다.
- `train.txt`에는 `--data`로 준 경로를 이어 붙인 사진 경로가 들어갑니다. **상대 경로로 실행하면 상대 경로가 기록**되어, 다른 폴더에서 학습을 돌릴 때 사진을 못 찾습니다. 원본 교재가 `data.yaml`·`train.txt`·`val.txt`를 절대 경로로 고치게 하는 이유입니다. 처음부터 절대 경로로 실행하면 수정이 필요 없습니다.

```bash
python3 ~/software/collect_picture/xml2yolo.py \
  --data /home/ubuntu/software/collect_picture/my_data \
  --yaml /home/ubuntu/software/collect_picture/my_data/data.yaml
```

생성된 `data.yaml`은 다음과 같습니다(키 순서는 yaml.dump가 알파벳순으로 씀).

```text
names:
- turn_around
nc: 1
train: /home/ubuntu/software/collect_picture/my_data/ImageSets/train.txt
val: /home/ubuntu/software/collect_picture/my_data/ImageSets/val.txt
```

## ⑤ 학습

```bash
unzip software/yolov5.zip -d software/        # 처음 한 번
python3 software/yolov5/train.py --img 640 --batch 8 --epochs 300 \
  --data software/collect_picture/my_data/data.yaml --weights software/yolov5/yolov5n.pt
```

| 인자 | 의미 | 고르는 법 |
|---|---|---|
| `--img 640` | 학습·검증 입력 크기(정사각형, 32의 배수) | 작은 표지판을 멀리서 잡아야 하면 크게. 추론 속도는 크기²에 비례 |
| `--batch 8` | 한 번에 넣는 사진 수 | 메모리가 허락하는 만큼. 작으면 BN 통계가 흔들림 |
| `--epochs 300` | 전체 데이터를 몇 바퀴 학습 | 데이터가 적을수록 많이. `--patience 100`이면 100 epoch 동안 개선 없을 때 조기 종료 |
| `--weights yolov5n.pt` | 시작 가중치 | COCO로 미리 학습한 가중치에서 출발(전이 학습). `n`(nano)은 가볍고 `s`(small)는 정확 |
| `--data` | `data.yaml` 경로 | 클래스 수 `nc`와 경로 확인 |

**전이 학습(transfer learning)**이 핵심입니다. `yolov5n.pt`는 COCO 80개 클래스로 이미 "모서리·원·글자 모양" 같은 일반 특징을 배운 상태입니다. 백본의 이 지식을 그대로 두고 헤드를 새 클래스에 맞추므로 수백 장만으로도 학습이 됩니다. 처음부터(`--weights ''`) 학습하면 수만 장이 필요합니다.

### 하이퍼파라미터와 학습률 일정

`--hyp`를 주지 않으면 `data/hyps/hyp.scratch-low.yaml`을 씁니다.

| 항목 | 값 | 의미 |
|---|---|---|
| `lr0` / `lrf` | 0.01 / 0.01 | 시작 학습률, 마지막 학습률 = lr0 × lrf |
| `momentum`, `weight_decay` | 0.937, 0.0005 | SGD 관성, 가중치 크기 벌점(과적합 억제) |
| `warmup_epochs` | 3.0 | 처음에는 학습률을 0에서 천천히 올림 |
| `box`, `cls`, `obj` | 0.05, 0.5, 1.0 | 세 손실의 가중치(A07) |
| `anchor_t` | 4.0 | 앵커 매칭 비율 한계 |
| `hsv_h/s/v` | 0.015/0.7/0.4 | 색상·채도·명도 무작위 변형 → 조명 변화에 강해짐 |
| `translate`, `scale` | 0.1, 0.5 | 위치 ±10 %, 크기 ±50 % 변형 |
| `fliplr` | 0.5 | 좌우 뒤집기 확률 |
| `mosaic` | 1.0 | 4장을 한 장으로 합치는 모자이크 증강 |

:::danger 좌우 뒤집기와 방향 표지판
`fliplr: 0.5`는 사진의 절반을 좌우 반전합니다. **우회전 표지판을 뒤집으면 좌회전 표지판**이 됩니다. `left`와 `right`를 모두 학습하는 데이터셋이라면 두 클래스가 서로 섞여 버리므로, `hyp.yaml`을 복사해 `fliplr: 0.0`으로 바꾸고 `--hyp`로 지정해야 합니다. 원본 표지판 세트는 `right`만 있어 큰 문제가 드러나지 않을 뿐입니다.
:::

학습률은 워밍업 뒤 **선형으로 감소**합니다(`train.py`의 `lf = (1 − e/epochs)·(1 − lrf) + lrf`). 또 YOLOv5는 명목 배치 64(`nbs`)를 기준으로 **기울기 누적(gradient accumulation)**을 합니다. 배치 8이면 8번 모아서 한 번 가중치를 갱신하므로 작은 배치에서도 학습이 안정됩니다.

```python run
import math

epochs, lr0, lrf = 300, 0.01, 0.01            # hyp.scratch-low.yaml
warmup_epochs, warmup_bias_lr = 3.0, 0.1
n_train, batch, nbs = 160, 8, 64             # 학습 이미지 160장, --batch 8

nb = math.ceil(n_train / batch)              # epoch당 반복(iteration) 수
nw = max(round(warmup_epochs * nb), 100)     # 워밍업 반복 수 (최소 100)
accumulate = max(round(nbs / batch), 1)      # 몇 배치마다 가중치를 갱신?
print("epoch당 반복 %d, 워밍업 %d회(= %.1f epoch), %d배치마다 1회 갱신"
      % (nb, nw, nw / nb, accumulate))

lf = lambda e: (1 - e / epochs) * (1.0 - lrf) + lrf    # 선형 감소
for e in (0, 5, 50, 150, 250, 299):
    print("epoch %3d  lr = %.6f" % (e, lr0 * lf(e)))
```

```text
epoch당 반복 20, 워밍업 100회(= 5.0 epoch), 8배치마다 1회 갱신
epoch   0  lr = 0.010000
epoch   5  lr = 0.009835
epoch  50  lr = 0.008350
epoch 150  lr = 0.005050
epoch 250  lr = 0.001750
epoch 299  lr = 0.000133
```

사진이 적으면 워밍업이 설정값 3 epoch보다 길어집니다(최소 100회 반복 규칙). 160장·배치 8이면 5 epoch 동안 워밍업합니다.

### 결과 읽기: results.csv

학습이 끝나면 `runs/train/expN/`에 `weights/best.pt`(검증 성능이 가장 좋았던 가중치), `weights/last.pt`(마지막 가중치), `results.csv`, 곡선 그림(`results.png`, `PR_curve.png`, `confusion_matrix.png`)이 생깁니다. 로봇 이미지에 들어 있는 예시 학습(`yolov5/runs/train/exp4`, 클래스 1개 `turn_around`, yolov5n, 배치 8)의 마지막 줄은 다음과 같습니다.

| 열 | 값 | 해석 |
|---|---|---|
| epoch | 253 | 300으로 시작했으나 253에서 멈춤(중단 또는 조기 종료) |
| train/box_loss | 0.0586 | 상자 손실 |
| train/cls_loss | 0 | **클래스가 하나라 분류할 것이 없음** |
| metrics/precision, recall | 0.918, 1.0 | 검증 세트의 모든 물체를 찾음 |
| mAP_0.5 | 0.995 | 거의 완벽하게 찾음 |
| mAP_0.5:0.95 | 0.249 | 하지만 상자 위치는 정밀하지 않음 |
| val/box_loss | 0.0335 | 검증 상자 손실 |

`mAP_0.5`가 0.995인데 `mAP_0.5:0.95`가 0.25라는 것은 "어디 있는지는 알지만 테두리를 정확히 못 맞춘다"는 뜻입니다. 라벨 상자를 일관되게 그리지 않았거나 검증 사진이 너무 적을 때 흔히 나옵니다. 곡선으로는 이렇게 판단합니다.

| 곡선 모양 | 진단 | 대응 |
|---|---|---|
| train 손실↓, val 손실↓, mAP↑ | 정상 학습 중 | epoch 유지 또는 증가 |
| train 손실↓, **val 손실↑**, mAP 정체·하락 | **과적합**(외워 버림) | 데이터 추가, 증강 강화, epoch 줄이기(`best.pt` 사용) |
| 둘 다 높게 정체 | **과소적합** | 더 큰 모델(`yolov5s`), epoch 증가, 라벨 품질 점검 |

## ⑥ 로봇에 배포

YOLOv5 ROS 2 노드(`yolov5_ros2/yolo_detect.py`)는 다음처럼 동작합니다.

1. 파라미터 `model`로 `<패키지 share>/config/<model>.pt`를 불러옵니다(pip `yolov5` 패키지의 `YOLOv5` 클래스).
2. `image_topic`(기본 `/ascamera/camera_publisher/rgb0/image`) 영상이 올 때마다 추론합니다.
3. 결과를 세 토픽으로 냅니다.

| 토픽 | 타입 | 내용 |
|---|---|---|
| `/yolov5_ros2/object_detect` | `interfaces/ObjectsInfo` | `class_name`, `box`[x1,y1,x2,y2], `score`, 영상 `width`·`height` |
| `/yolo_result` | `vision_msgs/Detection2DArray` | 표준 검출 메시지(중심·크기·점수) |
| `/result_img` | `sensor_msgs/Image` | 상자를 그린 결과 영상 (`pub_result_img: True`일 때) |

:::warning ObjectsInfo는 물체마다 한 번씩 발행됩니다
`yolo_detect.py`는 검출 루프 **안에서** `objects_info = []`를 새로 만들고 메시지를 발행합니다. 그래서 한 프레임에 표지판 3개가 보이면 `/yolov5_ros2/object_detect`에 **물체 1개짜리 메시지가 3번** 옵니다. 한 프레임의 모든 물체를 한꺼번에 받아야 하는 코드라면 `/yolo_result`(Detection2DArray)를 구독하거나, 노드를 고쳐 발행을 루프 밖으로 옮기세요. 물체가 없으면 이 토픽에는 아무것도 오지 않습니다.
:::

배포 절차:

```bash
~/.stop_ros.sh
cd ~/software/yolov5/runs/train/exp5/weights     # 자신의 expN 폴더
cp best.pt ~/ros2_ws/src/yolov5_ros2/config/
ros2 launch peripherals depth_camera.launch.py
```

새 터미널에서 노드를 실행합니다. 원본 교재의 명령은 다음과 같습니다.

```bash
ros2 launch yolov5_ros2 yolov5_ros2.launch.py model:="best"
```

그런데 현재 `yolov5_ros2.launch.py`는 `model` 인자를 선언하지 않고 파라미터를 `"traffic_signs_640s_7_0"`으로 **고정**해 두었습니다. 위 명령으로 내 모델이 안 불린다면 launch 파일의 `"model"` 값을 `"best"`로 고치거나, 노드를 직접 실행합니다.

```bash
ros2 run yolov5_ros2 yolo_detect --ros-args -p model:=best -p device:=cpu -p pub_result_img:=true
ros2 topic echo /yolov5_ros2/object_detect
rqt_image_view /result_img
```

:::info 모델은 install 폴더에서 읽습니다
노드는 `get_package_share_directory('yolov5_ros2')` + `/config/<model>.pt`, 즉 **`~/ros2_ws/install/yolov5_ros2/share/yolov5_ros2/config/`**에서 모델을 찾습니다. `setup.py`가 빌드할 때 `src/.../config/` 파일을 그곳으로 복사하므로, `--symlink-install`로 빌드한 환경이 아니라면 모델을 넣거나 launch를 고친 뒤 다시 빌드해야 반영됩니다.

```bash
cd ~/ros2_ws && colcon build --packages-select yolov5_ros2 && source install/setup.zsh
```
:::

검출 결과를 받아 가장 점수 높은 물체만 출력하는 확인용 노드입니다.

```python robot
import rclpy
from rclpy.node import Node
from interfaces.msg import ObjectsInfo

class BestObject(Node):
    def __init__(self):
        super().__init__('best_object')
        self.create_subscription(ObjectsInfo, '/yolov5_ros2/object_detect', self.cb, 10)

    def cb(self, msg):
        for o in msg.objects:
            if o.score < 0.5:
                continue
            x1, y1, x2, y2 = o.box
            area = (x2 - x1) * (y2 - y1)
            self.get_logger().info('%s %.2f 중심=(%d,%d) 면적=%d px²' % (
                o.class_name, o.score, (x1 + x2) // 2, (y1 + y2) // 2, area))

def main():
    rclpy.init()
    node = BestObject()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 변환 후 `클래스:0`으로 나옴 | `classes.names`와 labelImg 이름 불일치(대소문자·공백) | 두 이름을 똑같이 맞추고 다시 변환 |
| `No labels found` / `images not found` | `train.txt`·`data.yaml`이 상대 경로 | 절대 경로로 다시 변환하거나 파일 안 경로를 `pwd` 결과로 수정 |
| 학습 시작 시 다운로드 오류 | `--weights yolov5n.pt`처럼 이름만 주면 인터넷에서 받으려 함 | 로컬 파일 경로 `software/yolov5/yolov5n.pt`를 지정 |
| 학습 중 OpenCV 버전 경고에서 멈춤 | 원본 교재가 언급한 호환성 검사 | `Ctrl+C`를 **한 번만** 누르면 계속 진행. 반복되면 `train.py`의 해당 검사 줄을 주석 처리 |
| `CUDA out of memory` (PC) | 배치가 큼 | `--batch 4` 또는 `--img 512` |
| `model:="best"`를 줬는데 기존 모델이 뜸 | launch 파일이 모델 이름을 고정 | launch 수정 또는 `ros2 run ... -p model:=best` |
| `FileNotFoundError: .../share/yolov5_ros2/config/best.pt` | `src`에만 복사하고 다시 빌드하지 않음 | `colcon build --packages-select yolov5_ros2` 후 `source` |
| 로봇에서 추론이 1~2 fps로 느림 | CPU 추론 + 640 입력 | `yolov5n` 사용, 입력 크기 축소(`--img 416`로 학습), 불필요한 결과 영상 발행 끄기 |
