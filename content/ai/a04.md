## 학습 목표

- 목표 색 물체의 **화면 x 오차**를 회전 명령으로, **크기(면적·반지름) 또는 화면 y 위치**를 전후진 명령으로 바꾸는 추적 제어 구조를 설명합니다.
- MentorPi의 두 추적 프로그램 — 섀시로 쫓아가는 `object_tracking`과 팬·틸트 서보로 바라보는 `color_track` — 의 차이를 비교합니다.
- 핀홀 카메라 모델로 “면적 ∝ 1/거리²”를 유도하고, $\sqrt{면적}$ 오차로 거리를 선형화합니다.
- 불감대(dead zone), 출력 제한, 표적 상실 시 정지를 넣어 안전한 추적 노드를 만들고 가상 카메라로 시험합니다.
- 로봇 네트워크(AP 직접 연결 / STA 공유기 연결) 모드를 바꾸는 방법을 압니다.

## 추적 제어의 구조

색 추적은 “보이는 물체를 화면 가운데, 적당한 크기로 유지”하는 제어입니다. 영상에서 두 개의 오차를 뽑아 서로 다른 축을 움직입니다.

@fig[a04-errors] 영상에서 뽑는 두 오차: 가로 오차 → 회전(ω), 크기·높이 오차 → 전후진(v)

| 오차 | 측정 | 의미 | 움직이는 축 |
|---|---|---|---|
| 가로 오차 $e_x = u - u_{ref}$ | 물체 중심의 열 좌표 $u$ | 물체가 오른쪽(+)/왼쪽(−)에 있음 | 섀시 회전 $ω$ 또는 팬 서보 |
| 거리 오차 | 반지름 $r$·면적 $A$, 또는 중심의 행 좌표 $v$ | 물체가 멀다/가깝다 | 섀시 전후진 $v$ 또는 틸트 서보 |

두 오차는 대략 서로 독립이라 **PID 두 개를 따로** 돌려도 잘 동작합니다. 이것이 A03의 라인 트레이싱(오차 하나 → 회전 하나)과의 차이입니다.

### 거리를 무엇으로 잴까: 면적 vs 화면 높이

핀홀 카메라에서 반지름 $R$인 공이 거리 $d$에 있으면 영상 속 반지름은 $r = fR/d$, 면적은 $A = π f^2 R^2 / d^2$입니다($f$: 픽셀 단위 초점거리).

- **면적은 거리의 제곱에 반비례**합니다. 가까울수록 같은 거리 변화에 면적이 훨씬 크게 변하므로, 면적 오차에 바로 P 제어를 걸면 가까이서 과민하고 멀리서 둔합니다.
- $\sqrt{A} ∝ r ∝ 1/d$라서 **제곱근(또는 반지름)**을 쓰면 비선형성이 한 단계 줄어듭니다. 목표 거리 $d_{ref}$에서 $e_A = \sqrt{A_{ref}} - \sqrt{A}$를 오차로 씁니다(멀면 +, 가까우면 −).
- 물체가 **바닥에 놓여** 있고 카메라가 아래를 비스듬히 본다면, 가까울수록 물체가 **화면 아래쪽**에 찍힙니다. 이때는 중심의 행 좌표 $v$가 거리와 단조 관계라 좋은 거리 신호가 됩니다. 물체가 가려져 윤곽이 작아져도 $v$는 크게 흔들리지 않는 장점이 있습니다.

MentorPi의 `object_tracking`은 바닥 위 물체를 가정해 **화면 높이 $v$**를 쓰고, 이 강의의 Playground 예제는 공중에 있는 공을 가정해 **면적**을 씁니다.

## MentorPi의 두 추적 프로그램

### object_tracking: 섀시로 쫓아가기

`~/ros2_ws/src/app/app/object_tracking.py`는 라인 트레이싱과 같은 틀(서비스 `enter`·`set_target_color`·`set_running`, 색 고르기 `ColorPicker`, 하트비트)에 추적기 `ObjectTracker`를 넣은 노드입니다.

| 단계 | 내용 (깊이 카메라 기준) |
|---|---|
| 전처리 | 320×180으로 축소 → `RGB2LAB` → `GaussianBlur(5×5, σ=5)` |
| 색 범위 | 클릭한 색 ± (L 50·t·2, a·b 50·t), `enter` 시 t = 0.5 |
| 마스크 정리 | `inRange` → 3×3 침식·팽창 → 외곽 윤곽, 면적 40 초과만 |
| 물체 선택 | 가장 큰 윤곽의 최소 외접원 → 원래 해상도로 환산 |
| 기준점 | `x_stop = 320`, `y_stop = 300` (단안 카메라는 400) |
| 거리 제어 | $|v - 300| > 20$ px일 때 `pid_dist = PID(0.002, 0, 0)` → `linear.x`, ±0.35 m/s로 제한 |
| 회전 제어 | $|u - 320| > 20$ px일 때 `pid_yaw = PID(0.006, 0, 0)` → `angular.z`, ±2 rad/s로 제한 |
| 발행 | `/controller/cmd_vel` |

`sdk/pid.py`는 `error = SetPoint − feedback`이고 SetPoint가 0이므로, 물체가 오른쪽($u > 320$)이면 출력이 음수 → `angular.z` 음수(시계 방향, 오른쪽으로 회전)입니다. 물체가 화면 위쪽($v < 300$, 멀리 있음)이면 출력이 양수 → 전진합니다. **±20 px 불감대** 안에서는 PID를 `clear()`하고 명령을 0으로 둬, 목표 근처에서 로봇이 미세하게 떨지 않게 합니다.

애커만 섀시는 제자리 회전을 못 하므로 회전 출력을 조향각(±29°)으로 보고 $ω = -v/R$, $R = 0.145/\tan δ$로 바꿉니다. **전진하고 있을 때만 방향을 바꿀 수 있다**는 뜻이라, 물체가 거리 불감대 안에 있으면 옆으로 돌지 못합니다.

:::info 소스 코드 읽기 포인트
`ObjectTracker`에는 직전 원(`last_color_circle`)과 가장 가까운 윤곽을 고르는 코드가 있지만, `last_color_circle`에 값을 넣는 곳이 없어 실제로는 **항상 가장 큰 윤곽**을 고릅니다. 비슷한 색 물체가 둘이면 크기가 바뀔 때 표적이 튈 수 있습니다. 과제 3에서 이 부분을 고쳐 봅니다.
:::

### color_track: 팬·틸트 서보로 바라보기

`~/ros2_ws/src/example/example/color_track/color_track_node.py`는 **2축 팬·틸트 단안 카메라 버전**용입니다. 섀시는 움직이지 않고 카메라 서보만 돌려 빨간 공을 화면 가운데에 둡니다.

- 색 인식은 A01의 `color_detect` 노드가 하고, 이 노드는 `/color_detect/color_info`(`ColorsInfo`)를 구독합니다. 시작할 때 `/color_detect/set_param`에 `{color_name: 'red', detect_type: 'circle'}`을 보내고, 반지름 10 px 초과만 씁니다.
- 가로·세로에 `PID(0.1, 0.0002, 0.0001)`를 하나씩 둡니다(`pid_y`, `pid_z`).
- 출력을 서보 펄스에 **누적**합니다: `y_dis -= pid_y.output`, `z_dis -= pid_z.output`, 각각 800~1900 µs로 제한. 픽셀 오차가 “서보 각도의 변화량”을 정하므로 서보 쪽에서 적분이 한 번 일어나고, 오차가 0이 되는 자리에서 서보가 멈춥니다.
- 결과를 `ros_robot_controller/pwm_servo/set_state`(`SetPWMServoState`, 서보 1 = 틸트, 2 = 팬, `duration` 0.2 s)로 약 50 Hz(0.02 s 주기) 발행합니다.

| 항목 | object_tracking | color_track |
|---|---|---|
| 움직이는 것 | 섀시 (`/controller/cmd_vel`) | 카메라 팬·틸트 서보 (PWM) |
| 색 인식 | 노드 안에서, 클릭한 색 | `color_detect` 노드, yaml의 `red` |
| 거리 신호 | 화면 높이 $v$ | 없음 (틸트로 높이만 맞춤) |
| 제어 형태 | 위치 오차 → 속도 (P) | 위치 오차 → 서보 각도 증분 (누적) |
| 실행 | `ros2 launch app object_tracking_node.launch.py` | `ros2 launch example color_track_node.launch.py` |

## Playground: 원본 규칙으로 명령 계산하기

먼저 정지 영상 한 장에서 `object_tracking`의 규칙대로 명령을 계산해 봅니다. `shapes.png`의 빨간 원을 목표로 삼습니다.

```python run
import cv2
import math
import numpy as np

img = cv2.imread("shapes.png")
h, w = img.shape[:2]
PRO = (320, 180)                                      # 깊이 카메라 처리 크기
X_STOP, Y_STOP, DEAD = 320, 300, 20

# 색 고르기: 빨간 원 중심 부근을 "클릭"
L0, a0, b0 = cv2.cvtColor(img[149:151, 139:141], cv2.COLOR_BGR2LAB).reshape(-1, 3).mean(0)
t = 0.5
lo = (L0 - 100 * t, a0 - 50 * t, b0 - 50 * t)
hi = (L0 + 100 * t, a0 + 50 * t, b0 + 50 * t)

small = cv2.GaussianBlur(cv2.cvtColor(cv2.resize(img, PRO), cv2.COLOR_BGR2LAB), (5, 5), 5)
k3 = cv2.getStructuringElement(cv2.MORPH_RECT, (3, 3))
mask = cv2.dilate(cv2.erode(cv2.inRange(small, lo, hi), k3), k3)
cs = [c for c in cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_NONE)[-2] if cv2.contourArea(c) > 40]
(x, y), r = cv2.minEnclosingCircle(max(cs, key=cv2.contourArea))
x, y, r = x / PRO[0] * w, y / PRO[1] * h, r / PRO[0] * w
print("목표 Lab (%.0f, %.0f, %.0f), 원 중심 (%.0f, %.0f) 반지름 %.0f px" % (L0, a0, b0, x, y, r))

def p_out(kp, feedback):                              # sdk.pid: error = 0 - feedback
    return kp * (0.0 - feedback)

ex, ey = x - X_STOP, y - Y_STOP
lin = max(-0.35, min(0.35, p_out(0.002, ey))) if abs(ey) > DEAD else 0.0
ang = max(-2.0, min(2.0, p_out(0.006, ex))) if abs(ex) > DEAD else 0.0
print("오차 ex = %+.0f px, ey = %+.0f px" % (ex, ey))
print("메카넘: linear.x = %+.2f m/s, angular.z = %+.2f rad/s" % (lin, ang))
delta = max(-math.radians(29), min(math.radians(29), -p_out(0.006, ex)))
print("애커만: 조향 %.1f°, R = %.2f m, angular.z = %+.2f rad/s"
      % (math.degrees(delta), 0.145 / math.tan(delta), -lin / (0.145 / math.tan(delta))))
cv2.circle(img, (int(x), int(y)), int(r), (0, 0, 0), 2)
cv2.circle(img, (X_STOP, Y_STOP), 5, (255, 255, 0), -1)
cv2.imshow("target", img)
```

```text
목표 Lab (136, 208, 195), 원 중심 (139, 149) 반지름 68 px
오차 ex = -181 px, ey = -151 px
메카넘: linear.x = +0.30 m/s, angular.z = +1.08 rad/s
애커만: 조향 -29.0°, R = -0.26 m, angular.z = +1.15 rad/s
```

빨간 원은 기준점보다 왼쪽·위쪽에 있으므로 “왼쪽으로 돌며(+ω) 앞으로(+v)” 가라는 명령이 나옵니다. 애커만은 조향 출력이 ±29° 한계에 걸리고(원본 코드의 부호 규약으로 −29°), $ω = -v/R$로 바꾸면 역시 왼쪽 회전(+)입니다. 오차가 크면 선속도 0.30 m/s, 각속도 1 rad/s 이상이 곧바로 나옵니다. 실물에서 추적 시작 순간 로봇이 **급출발·급회전**하는 이유이며, 이 사이트의 안전 기준(0.2 m/s, 0.5 rad/s)으로 쓰려면 제한값을 낮춰야 합니다.

## Playground: 가상 카메라로 움직이는 공 쫓기

이제 제어 루프를 닫아 봅니다. 아래 노드는 로봇의 자세(시뮬 전용 `sim.pose()`)로 **가상 카메라 영상**(핀홀 모델, 320×240, 초점거리 260 px)을 그리고, 그 영상에서 빨간 공을 찾아 PID로 `/cmd_vel`을 발행합니다. 공은 로봇 앞 1 m에서 출발해 0.08 m/s로 멀어지며 좌우로 흔들립니다. 거리 제어에는 $\sqrt{면적}$ 오차를, 회전 제어에는 가로 오차를 씁니다.

```python run
import math
import cv2
import numpy as np
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
import mentorpi_sim as sim                                   # 시뮬 전용
sim.setup(world="empty", duration=20.0, noise=False)        # 시뮬 전용
W, H, F = 320, 240, 260.0                                   # 영상 크기, 초점거리 [px]
A_REF = math.pi * (F * 0.04 / 0.5) ** 2                     # 반지름 4 cm 공이 0.5 m에 있을 때의 면적
KX, KA, LO, HI = 0.006, 0.02, (0, 160, 130), (255, 255, 255)   # 이득(ω, v), 빨강 Lab 범위

def ball_xy(t):                                             # 시뮬 전용: 움직이는 빨간 공
    return 1.0 + 0.08 * t, 0.4 * math.sin(0.35 * t)

def camera(t):                                              # 시뮬 전용: 로봇 자세로 그린 가상 카메라 프레임
    x, y, th = sim.pose()
    dx, dy = ball_xy(t)[0] - x, ball_xy(t)[1] - y
    xc, yc = dx * math.cos(th) + dy * math.sin(th), -dx * math.sin(th) + dy * math.cos(th)
    img = np.full((H, W, 3), 150, np.uint8)
    if xc > 0.05:                                           # 핀홀: u = W/2 − F·y/x, r = F·R/x
        u, v = W / 2 - F * yc / xc, H / 2 + F * 0.08 / xc  # 카메라가 공 중심보다 8 cm 높음
        cv2.circle(img, (int(round(u)), int(round(v))), max(1, int(round(F * 0.04 / xc))), (30, 30, 200), -1)
    return img

class ColorTracker(Node):
    def __init__(self):
        super().__init__('color_tracker')
        self.pub = self.create_publisher(Twist, 'cmd_vel', 1)
        self.k, self.t0 = 0, self.get_clock().now().nanoseconds * 1e-9
        self.create_timer(0.1, self.on_frame)               # 실물: 카메라 이미지 콜백
    def on_frame(self):
        t = self.get_clock().now().nanoseconds * 1e-9 - self.t0
        lab = cv2.cvtColor(cv2.GaussianBlur(camera(t), (5, 5), 5), cv2.COLOR_BGR2LAB)
        cs = [c for c in cv2.findContours(cv2.inRange(lab, LO, HI), cv2.RETR_EXTERNAL,
                                          cv2.CHAIN_APPROX_NONE)[-2] if cv2.contourArea(c) > 40]
        cmd, ex, ea = Twist(), float('nan'), float('nan')
        if cs:                                              # 못 찾으면 cmd = 0 (정지)
            (u, v), r = cv2.minEnclosingCircle(max(cs, key=cv2.contourArea))
            ex, ea = u - W / 2, math.sqrt(A_REF) - math.sqrt(math.pi) * r
            cmd.angular.z = max(-0.5, min(0.5, -KX * ex)) if abs(ex) > 5 else 0.0
            cmd.linear.x = max(-0.2, min(0.2, KA * ea)) if abs(ea) > 2 else 0.0
        self.pub.publish(cmd)
        if self.k % 20 == 0:
            d = math.dist(ball_xy(t), sim.pose()[:2])       # 시뮬 전용: 실제 거리
            self.get_logger().info('t=%4.1f 거리 %.2f m  가로오차 %+5.0f px  √면적오차 %+5.1f  v=%+.2f ω=%+.2f'
                                   % (t, d, ex, ea, cmd.linear.x, cmd.angular.z))
        self.k += 1

rclpy.init()
node = ColorTracker()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()
```

읽는 법:

- 처음 1 m에서는 $\sqrt{면적}$ 오차가 커서 선속도가 제한값(0.2 m/s)으로 다가갑니다. 목표 거리 0.5 m에 가까워지면 속도가 줄어듭니다.
- 공이 계속 0.08 m/s로 멀어지므로, P 제어만으로는 “0.08 m/s를 내기 위한 오차”가 항상 남아 거리가 0.5 m보다 조금 먼 곳에서 유지됩니다. 이것이 **정상상태 오차**이며, I 항을 더하면 줄어듭니다.
- 가로 오차는 공이 좌우로 흔들리는 주기를 따라 늦게 쫓아갑니다. 회전 이득을 올리면 줄지만, A03에서 본 것처럼 영상 지연이 있으면 너무 큰 이득은 흔들림을 만듭니다.

## 실습 (실물)

:::safety 실물 실습 전 확인
- `object_tracking`은 로봇이 **실제로 달려** 물체를 쫓습니다. 주변 1.5 m 안을 비우고, 물체를 든 사람은 로봇 정면에 서지 말고 옆에서 막대 등으로 물체를 움직입니다.
- 원본의 선속도 제한은 ±0.35 m/s, 각속도 제한은 ±2 rad/s로 이 사이트의 권장(0.2 m/s, 0.5 rad/s)보다 큽니다. 처음에는 물체를 가까이(기준점 근처) 두어 급출발을 피하고, 코드를 수정해 쓸 때는 제한값을 낮춥니다.
- 비슷한 색의 물체가 시야에 없게 합니다. 표적이 튀면 로봇이 급회전합니다.
- 멈출 때는 `set_running`에 `False`를 보내고, `Ctrl+C` 후 바퀴가 멈췄는지 확인합니다.
:::

### 1) 섀시 추적 (object_tracking)

```bash
~/.stop_ros.sh
ros2 launch app object_tracking_node.launch.py debug:=true
# 새 터미널
ros2 service call /object_tracking/enter std_srvs/srv/Trigger {}
# 카메라 창에서 추적할 물체를 클릭 (10프레임 동안 색을 모아 확정)
ros2 service call /object_tracking/set_running std_srvs/srv/SetBool "{data: True}"
# 정지
ros2 service call /object_tracking/set_running std_srvs/srv/SetBool "{data: False}"
```

화면의 하늘색 점이 기준점 `(320, 300)`입니다. 물체를 그 점에 맞춰 두면 로봇이 멈추고, 물체를 멀리(화면 위쪽) 하면 다가오며, 옆으로 옮기면 돌아서 따라옵니다.

### 2) 팬·틸트 추적 (color_track, 2축 팬·틸트 단안 카메라 버전만)

```bash
~/.stop_ros.sh
ros2 launch example color_track_node.launch.py
```

launch 파일이 컨트롤러와 `color_detect` 노드를 함께 켜고, `start:=true`(기본값)면 바로 빨간색 추적을 시작합니다. 빨간 공을 움직이면 카메라가 따라 돕니다. 끝나면 `Ctrl+C` 후 서보가 가운데(1500)로 돌아오는지 확인하고, 컨테이너 밖에서 앱 서비스를 되살립니다.

```bash
sudo systemctl restart start_node.service
```

:::check 체크포인트
- [ ] 물체를 기준점 ±20 px 안에 두면 로봇이 완전히 멈추는 불감대를 확인했다.
- [ ] 물체를 시야 밖으로 빼면 로봇이 정지하는지 확인했다.
- [ ] 애커만 섀시에서는 물체가 옆에만 있고 거리가 맞을 때 돌지 못하는 현상을 설명할 수 있다.
:::

## 네트워크 설정: AP 모드와 STA 모드

추적 영상을 PC에서 보거나 여러 로봇을 함께 쓰려면 네트워크 구성을 알아야 합니다. Hiwonder 라즈베리파이 로봇은 두 모드를 지원합니다.

| 모드 | 동작 | 인터넷 | 쓰임 |
|---|---|---|---|
| AP (직접 연결, 기본) | 로봇이 `HW`로 시작하는 핫스팟을 만듦 (비밀번호 `hiwonder`) | 안 됨 | 앱·VNC로 로봇 한 대를 바로 조작 |
| STA (LAN 모드) | 로봇이 지정한 공유기(Wi-Fi)에 접속 | 됨 | 패키지 설치, 여러 로봇·PC가 같은 네트워크 사용 |

앱(WonderPi)에서 **LAN 모드**를 고르고 공유기 비밀번호를 입력하는 방법이 가장 쉽습니다. 설정 파일로 바꾸려면 로봇에서 다음을 편집합니다.

```bash
cd ~/hiwonder-toolbox
vim wifi_conf.py
#   HW_WIFI_MODE = 2                 # 1: 직접 연결(AP), 2: LAN(STA), 3: 직접 연결 + 공유
#   HW_WIFI_STA_SSID = "공유기 이름"
#   HW_WIFI_STA_PASSWORD = "공유기 비밀번호"
sudo systemctl restart wifi.service
```

AP 모드로 되돌리려면 설정 줄을 모두 주석 처리하고 서비스를 다시 시작하거나, 확장보드의 KEY1을 파란 LED가 깜빡일 때까지 길게 누릅니다. 근처에 로봇이 여러 대면 `HW_WIFI_AP_SSID`/`HW_WIFI_AP_PASSWORD`로 핫스팟 이름을 서로 다르게 정합니다. STA 모드에서는 로봇 IP가 공유기에서 배정되므로, 앱에서 로봇 아이콘을 길게 눌러 IP를 확인한 뒤 VNC로 접속합니다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 클릭했는데 추적이 시작되지 않음 | `set_running`을 안 켬, 색 확정 전(10프레임) | 잠시 기다린 뒤 `set_running {data: True}` |
| 로봇이 물체 반대 방향으로 돔 | 회전 출력 부호 반대(카메라 좌우 반전, 코드 수정 실수) | 물체가 오른쪽일 때 `angular.z < 0`인지 확인 |
| 목표 근처에서 앞뒤로 떨림 | 불감대 없음, 거리 이득 과다 | ±20 px 불감대 유지, 이득 낮춤 |
| 가까이 가면 급하게 후진 | 면적 오차를 그대로 사용(거리² 반비례) | $\sqrt{A}$ 또는 반지름 사용, 출력 제한 |
| 표적이 옆의 비슷한 색으로 튐 | 항상 가장 큰 윤곽 선택 | 직전 위치와 가까운 윤곽 우선, 색 범위 좁힘 |
| 팬·틸트가 끝까지 돌아 멈춤 | 서보 누적값이 800/1900 한계에 걸림 | 표적 상실 시 가운데(1500)로 복귀하는 로직 추가 |
| `color_track`이 시작하지 않음 | `/color_detect/set_param` 서비스 대기 중 | `color_detect` 노드가 떴는지 `ros2 node list`로 확인 |
| PC에서 로봇 토픽이 안 보임 | AP/STA 네트워크가 다름, `ROS_DOMAIN_ID` 불일치 | 같은 네트워크 확인, 도메인 ID 맞춤 |

## 과제

:::task 기본 과제
1. 정지 영상 예제를 함수 `track_cmd(img, target_lab)`로 만들어, 물체가 화면 네 모서리와 가운데에 있을 때의 명령 다섯 쌍을 표로 정리합니다(합성 영상 사용).
2. 추적 노드의 불감대(5 px, √면적 2)를 없애고 결과를 비교해, 불감대가 명령의 “떨림”을 얼마나 줄이는지 `v`, `ω` 변화 횟수로 보여 줍니다.
:::

:::task 심화 과제
3. `ObjectTracker`의 표적 선택을 고쳐, 직전 프레임의 원과 가장 가까운 윤곽(100 px 이내)을 우선 고르고 없으면 가장 큰 윤곽을 고르도록 구현합니다. Playground 영상에 같은 색의 두 번째 공을 추가해 효과를 확인합니다.
4. 라이다(M06)와 결합해, 추적 중 전방 0.3 m 안에 장애물이 있으면 전진 명령만 0으로 막는(회전은 허용) 안전 필터 노드를 설계합니다.
:::
