## MediaPipe란

**MediaPipe**는 Google이 공개한 멀티미디어 머신러닝 프레임워크입니다. 카메라 영상이 들어오면 여러 단계의 모델과 전처리·후처리를 **그래프(graph)**로 묶어 실시간으로 돌립니다. 그래프의 각 노드를 **계산기(calculator)**라고 부르고, 계산기 사이를 흐르는 데이터 묶음을 **패킷(packet)**이라고 합니다. 사용자는 이 그래프를 직접 짜지 않아도 되도록 미리 조립된 **솔루션(Solutions)**을 씁니다.

| 솔루션 | 출력 | MentorPi 예제 파일 (`mediapipe_example/`) |
|---|---|---|
| Hands (손) | 손마다 21개 3D 랜드마크, 왼손/오른손 | `hand.py`, `hand_gesture.py` |
| Pose (자세) | 33개 몸 랜드마크 | `pose.py` |
| Face Detection | 얼굴 박스 + 6개 특징점 | `face_detect.py` |
| Face Mesh | 468개 얼굴 메시 점 | `face_mesh.py` |
| Holistic | 손 + 자세 + 얼굴 동시 | `holistic.py` |
| Selfie Segmentation | 사람/배경 마스크 | `self_segmentation.py` |
| Objectron | 물체 3D 상자 | `objectron.py` |

원본 교재는 장점으로 **여러 플랫폼 지원(Android·iOS·C++·Python·JavaScript), 실시간 속도, 높은 재사용성**을, 단점으로 **모바일에서 10 MB 이상 차지, TensorFlow 의존, 그래프 내부 오류를 찾기 어렵다**는 점을 꼽습니다. 영상 입출력은 OpenCV, 모델 추론은 TensorFlow Lite가 맡으므로 R08~R11의 OpenCV 기초가 그대로 쓰입니다.

:::info 두 가지 Python API
MentorPi 예제에는 두 세대의 API가 섞여 있습니다.
- **레거시 Solutions API**: `mp.solutions.hands.Hands(...)` → `process(rgb)` → `results.multi_hand_landmarks`. `hand_gesture.py`, `hand_trajectory_node.py`, `hand_detect_node.py`가 이 방식입니다.
- **Tasks API**: `mediapipe.tasks.python.vision.HandLandmarker` + `model/hand_landmarker.task` 파일. `hand.py`가 이 방식이며 모델 파일(`.task`)을 직접 지정합니다.

결과 좌표 형식(정규화 x, y, z)은 같으므로 이 장의 알고리즘은 어느 쪽에나 적용됩니다.
:::

## 손 인식 파이프라인

@fig[a05-pipeline] MediaPipe Hands의 두 단계 모델과 추적 루프. 추적이 잘 되는 동안은 손바닥 검출기를 건너뜁니다.

MediaPipe Hands는 모델 두 개를 이어 붙인 구조입니다.

1. **손바닥 검출기(BlazePalm)**: 영상 전체에서 손바닥 상자를 찾습니다. 손가락은 모양이 제각각이지만 손바닥·주먹은 거의 **정사각형이고 단단한(rigid)** 물체라서 검출이 쉽습니다. 상자와 함께 손목·손가락 뿌리 같은 점 몇 개를 내놓아 **손의 회전 각도**까지 추정합니다.
2. **손 랜드마크 모델**: 회전을 바로잡아 잘라 낸 손 영역(ROI)에서 **21개 점의 (x, y, z)**를 회귀(regression)로 한 번에 출력합니다. 동시에 "이 ROI에 손이 정말 있는가"를 나타내는 **존재 점수(presence score)**와 왼손/오른손 분류도 냅니다.
3. **추적 루프**: 동영상 모드(`static_image_mode=False`)에서는 이번 프레임의 랜드마크로 다음 프레임 ROI를 예측합니다. 존재 점수가 `min_tracking_confidence`보다 낮아질 때만 1단계 검출기를 다시 돌립니다. 검출기는 무겁고 랜드마크 모델은 가벼우므로 이 구조 덕분에 라즈베리파이에서도 실시간이 됩니다.

원본 노드의 설정값에는 이유가 있습니다.

| 파라미터 | `hand_gesture.py` 값 | 의미와 선택 이유 |
|---|---|---|
| `static_image_mode` | `False` | 동영상 추적 모드. `True`면 매 프레임 검출기를 돌려 느려집니다. |
| `max_num_hands` | `1` | 한 손만. 궤적·제스처는 한 사람의 한 손이면 충분하고 연산도 줄어듭니다. |
| `min_detection_confidence` | `0.6` | 손바닥 검출 채택 기준. 낮추면 잘못된 검출↑, 높이면 손을 늦게 잡습니다. |
| `min_tracking_confidence` | `0.05` | 추적 유지 기준. **매우 낮게** 두어 한 번 잡은 손을 거의 놓지 않게(재검출 최소화) 했습니다. |

:::tip 조정 범위
원본 교재는 두 신뢰도 값을 ±0.1 정도씩 조정하라고 권합니다. 손을 자주 놓치면 `min_tracking_confidence`를 올리는 것이 아니라 **내려야** 한다는 점에 주의합니다(추적 유지 문턱이 낮을수록 덜 놓칩니다).
:::

## 21개 손 랜드마크

@fig[a05-landmarks] 손 랜드마크 번호와 손가락 각도를 재는 두 벡터. 각 손가락은 "손목→중간 관절" 벡터와 "끝 두 관절" 벡터의 각도로 판단합니다.

| 번호 | 부위 | 번호 | 부위 |
|---|---|---|---|
| 0 | 손목 WRIST | 9~12 | 중지 MCP·PIP·DIP·TIP |
| 1~4 | 엄지 CMC·MCP·IP·TIP | 13~16 | 약지 MCP·PIP·DIP·TIP |
| 5~8 | 검지 MCP·PIP·DIP·TIP | 17~20 | 새끼 MCP·PIP·DIP·TIP |

MCP는 손가락 뿌리 관절, PIP·DIP는 가운데·끝 관절, TIP은 손끝입니다. **손끝은 4의 배수(4, 8, 12, 16, 20)**라고 기억하면 편합니다.

모델 출력은 **정규화 좌표**입니다. x·y는 영상 폭·높이로 나눈 0~1 값이고, z는 손목을 기준으로 한 상대 깊이(작을수록 카메라에 가까움)입니다. 원본은 모든 노드에서 같은 함수로 픽셀 좌표로 바꿉니다.

```python
def get_hand_landmarks(img, landmarks):
    h, w, _ = img.shape
    return np.array([(lm.x * w, lm.y * h) for lm in landmarks])   # (21, 2) 픽셀 좌표
```

### 영상 좌우 반전

노드는 인식 전에 `cv2.flip(image, 1)`로 영상을 좌우 반전합니다. 카메라가 사람을 마주 보고 있으므로 반전하지 않으면 사용자가 오른쪽으로 손을 움직일 때 화면 속 손은 왼쪽으로 갑니다. **거울처럼 보여야** 궤적을 그리기 자연스럽기 때문에 반전합니다. 그 대가로 MediaPipe가 판단한 왼손/오른손 라벨도 뒤바뀌므로, 손 종류를 쓰는 코드를 짤 때는 이 점을 기억해야 합니다.

## 손가락 판정: 두 벡터의 각도

손가락이 펴졌는지는 관절 좌표 사이의 **각도**로 판단합니다. 원본 `hand_angle()`은 손가락마다 벡터 두 개를 만듭니다.

| 손가락 | 벡터 v1 | 벡터 v2 |
|---|---|---|
| 엄지 | `lm[3] - lm[4]` (TIP → IP) | `lm[0] - lm[2]` (MCP → 손목) |
| 검지 | `lm[0] - lm[6]` (PIP → 손목) | `lm[7] - lm[8]` (TIP → DIP) |
| 중지·약지·새끼 | `lm[0] - lm[10/14/18]` | `lm[11]-lm[12]`, `lm[15]-lm[16]`, `lm[19]-lm[20]` |

손가락을 쭉 펴면 손목, 가운데 관절, 손끝이 거의 한 직선 위에 있으므로 두 벡터가 **같은 방향**(각도 ≈ 0°)입니다. 손가락을 접으면 끝마디가 손바닥 쪽으로 꺾여 두 벡터가 **반대 방향**(각도 → 180°)이 됩니다.

두 벡터 사이 각은 `sdk/common.py`의 `vector_2d_angle()`이 계산합니다.

```text
cos θ = (v1 · v2) / (|v1| |v2|)          (내적)
sin θ = (v1 × v2) / (|v1| |v2|)          (2D 외적 = v1x·v2y − v1y·v2x)
θ = atan2(sin θ, cos θ)   → −180° ~ 180°,  hand_angle()은 절댓값 사용
```

`acos`만 쓰지 않고 `atan2`를 쓰는 이유는 수치 안정성 때문입니다. `acos`는 입력이 1에 가까울 때(각이 0°에 가까울 때) 기울기가 무한대로 커져 작은 잡음에도 각도가 크게 흔들립니다.

### 문턱값과 제스처 표

`h_gesture()`는 다섯 각도를 세 문턱값과 비교합니다.

| 상수 | 값 | 의미 |
|---|---|---|
| `thr_angle` | 65° | 이보다 크면 "접힘" |
| `thr_angle_thumb` | 53° | 엄지가 접혔다고 보는 기준 |
| `thr_angle_s` | 49° | 이보다 작으면 "펴짐" |

"펴짐" 기준(49°)과 "접힘" 기준(65°) 사이에 **빈 구간**이 있다는 점이 중요합니다. 각도가 50~64°인 애매한 손가락은 어느 조건도 만족하지 않아 `"none"`이 되고, 덕분에 제스처가 경계에서 깜빡이지 않습니다. 이는 온도조절기의 **히스테리시스(hysteresis)**와 같은 원리입니다.

| 제스처 | 엄지 | 검지 | 중지 | 약지 | 새끼 |
|---|---|---|---|---|---|
| `one` | > 5° | 펴짐 | 접힘 | 접힘 | 접힘 |
| `two` | 접힘 | 펴짐 | 펴짐 | 접힘 | 접힘 |
| `three` | 접힘 | 펴짐 | 펴짐 | 펴짐 | 접힘 |
| `four` | 접힘 | 펴짐 | 펴짐 | 펴짐 | 펴짐 |
| `five` | 펴짐 | 펴짐 | 펴짐 | 펴짐 | 펴짐 |
| `fist` | 접힘 | 접힘 | 접힘 | 접힘 | 접힘 |

원본에는 이 밖에 `OK`, `six`, `hand_heart`, `nico-nico-ni`도 있습니다. `if/elif` 순서대로 검사하므로 **먼저 나온 조건이 이깁니다.**

### 실습: 하드코딩한 랜드마크로 제스처 판정

카메라 없이도 알고리즘을 확인할 수 있게, 손을 편 자세(FIVE)와 검지만 편 자세(ONE)의 21점을 직접 적어 넣었습니다. 계산 함수는 원본과 같은 식입니다.

@btn[~/tools/playground.html] Playground 열기

```python run
import numpy as np

def vector_2d_angle(v1, v2):                      # sdk/common.py 와 같은 식
    d = np.linalg.norm(v1) * np.linalg.norm(v2)
    cos = v1.dot(v2) / d
    sin = (v1[0] * v2[1] - v1[1] * v2[0]) / d
    return np.degrees(np.arctan2(sin, cos))

def hand_angle(lm):
    pairs = [((3, 4), (0, 2)),                     # 엄지
             ((0, 6), (7, 8)), ((0, 10), (11, 12)),  # 검지, 중지
             ((0, 14), (15, 16)), ((0, 18), (19, 20))]  # 약지, 새끼
    return [abs(vector_2d_angle(lm[a] - lm[b], lm[c] - lm[d]))
            for (a, b), (c, d) in pairs]

# 640x480 영상의 픽셀 좌표 (x, y) — 0 손목, 4·8·12·16·20 손끝
FIVE = np.array([(320, 420), (280, 395), (250, 365), (230, 335), (215, 305),
                 (290, 320), (285, 275), (282, 245), (280, 215),
                 (320, 315), (320, 265), (320, 232), (320, 200),
                 (350, 322), (355, 277), (358, 248), (360, 220),
                 (378, 338), (388, 303), (394, 282), (400, 260)], float)
ONE = FIVE.copy()
ONE[1:5] = [(285, 398), (265, 370), (285, 350), (310, 350)]      # 엄지 접음
ONE[9:13] = [(320, 315), (320, 280), (322, 300), (322, 320)]     # 중지 접음
ONE[13:17] = [(350, 322), (352, 288), (352, 305), (350, 322)]    # 약지 접음
ONE[17:21] = [(378, 338), (382, 310), (382, 325), (378, 340)]    # 새끼 접음

THR, THR_THUMB, THR_S = 65.0, 53.0, 49.0
def gesture(a):
    if a[0] > 5 and a[1] < THR_S and all(x > THR for x in a[2:]):
        return "one"
    if all(x < THR_S for x in a):
        return "five"
    if a[0] > THR_THUMB and all(x > THR for x in a[1:]):
        return "fist"
    return "none"

for name, lm in (("FIVE", FIVE), ("ONE", ONE)):
    a = hand_angle(lm)
    n = sum(x < THR_S for x in a)                  # 펴진 손가락 수
    print(name, [round(float(x), 1) for x in a], "->", gesture(a), "/ 펴진 손가락", n)
```

```text
FIVE [25.3, 9.8, 0.0, 9.7, 14.9] -> five / 펴진 손가락 5
ONE [137.7, 9.8, 180.0, 173.1, 165.5] -> one / 펴진 손가락 1
```

결과 읽기:

- 편 손가락은 0~25°, 접은 손가락은 137~180°로 **두 무리가 뚜렷이 갈립니다.** 문턱값 49°·65°는 이 두 무리 사이에 놓인 값입니다.
- 엄지는 다른 손가락과 달리 옆으로 벌어지므로 편 상태에서도 25° 정도가 나옵니다. 그래서 엄지만 별도 문턱값(53°)을 씁니다.
- **손가락 개수 세기**는 "각도 < 49°인 손가락 수"로 간단히 구할 수 있습니다. 원본 제스처 표를 몰라도 개수만으로 명령을 고를 수 있습니다(A06 과제).

:::warning 각도 판정의 한계
2D 좌표만 쓰므로 **손바닥이 카메라를 정면으로 향할 때** 가장 잘 됩니다. 손을 옆으로 세우면 접힌 손가락이 겹쳐 보여 각도가 작게 나옵니다. z 좌표까지 쓰는 3D 각도로 바꾸면 개선되지만, z는 x·y보다 잡음이 커서 평균 필터가 필요합니다.
:::

## 손끝 궤적 기록: 상태 기계

@fig[a05-trajectory-fsm] 손끝 궤적 노드의 상태 전이. "1"을 6프레임 연속 유지하면 기록을 시작하고, "5"를 보이면 점을 발행하고 지웁니다.

`hand_gesture.py`와 `hand_trajectory_node.py`는 `enum.Enum`으로 상태 `NULL`, `START`, `TRACKING`, `RUNNING`을 정의하지만 실제로는 두 상태만 씁니다.

| 현재 상태 | 조건 | 동작 |
|---|---|---|
| `NULL` | 제스처가 `one` | `count += 1`, `count > 5`면 `TRACKING`으로, 점 목록 초기화 |
| `NULL` | 그 외 | `count = 0` (연속이 끊기면 처음부터) |
| `TRACKING` | 제스처가 `two`가 아님 | 검지 끝(8번)이 마지막 점에서 **5 px 이상** 움직였으면 점 추가 |
| 모든 상태 | 제스처가 `five` | (궤적 노드는 점들을 `~/points`로 발행) → 점 비우기, `NULL`로 |

두 필터의 의미를 짚어 봅니다.

- **`count > 5` (6프레임 연속)**: 한 프레임짜리 오인식으로 기록이 시작되지 않게 하는 **디바운싱(debouncing)**입니다. 카메라가 약 30 fps이면 0.2 s 동안 같은 제스처를 유지해야 합니다. 원본 교재는 5~7프레임을 권장합니다.
- **`distance(last_point, tip) < 5`**: 손이 멈춰 있을 때 랜드마크가 1~3 px씩 떨리는데, 그 떨림을 점으로 쌓지 않는 **최소 이동 거리 필터**입니다. 빠른 동작을 놓치지 않으려면 값을 키우되 10을 넘기지 말라고 원본은 권합니다.
- **`two`에서는 점을 추가하지 않음**: 손가락 두 개를 펴면 "펜을 든" 상태가 되어 손을 옮겨도 선이 그어지지 않습니다.

### 실습: 궤적 상태 기계 시뮬레이션

```python run
import math

def distance(p, q):
    return math.hypot(p[0] - q[0], p[1] - q[1])

# 프레임마다 (인식된 제스처, 검지 끝 좌표) — 카메라 30 fps 가정
frames = [("one", (300, 240))] * 7                       # ① "1"을 7프레임 유지
for k in range(20):                                      # ② 손끝으로 오른쪽 위로 긋기
    frames.append(("one", (300 + 8 * k, 240 - 3 * k)))
frames += [("one", (452, 183))] * 4                      # ③ 잠깐 멈춤(떨림 < 5 px)
frames += [("five", (450, 185))]                         # ④ "5"로 지우기

state, count, points = "NULL", 0, []
for i, (g, tip) in enumerate(frames):
    if state != "TRACKING":
        if g == "one":
            count += 1
            if count > 5:                    # 6번째 연속 프레임에서 확정
                count, state, points = 0, "TRACKING", []
                print("frame %2d: TRACKING 시작" % i)
        else:
            count = 0
    elif g != "two":
        if points and distance(points[-1], tip) < 5:
            count += 1                       # 거의 안 움직임 → 점 추가 안 함
        else:
            count = 0
            points.append(tip)
    if g == "five":
        print("frame %2d: five → 점 %d개 발행 후 지움" % (i, len(points)))
        state, points = "NULL", []
print("최종 상태:", state, "/ 남은 점", len(points))
```

```text
frame  5: TRACKING 시작
frame 31: five → 점 20개 발행 후 지움
최종 상태: NULL / 남은 점 0
```

프레임은 32개지만 점은 20개만 저장됩니다. 시작 직후 제자리 프레임, 멈춘 4프레임, 마지막 `five` 프레임이 모두 5 px 필터에 걸러졌기 때문입니다.

## 궤적을 로봇 명령으로: 방향 분류

`hand_gesture_control_node.py`는 `/hand_trajectory/points`를 구독해 궤적의 **방향**을 판정합니다(원본 동작은 로봇팔 버전용 액션 그룹이지만 분류 방법은 섀시에도 그대로 쓸 수 있습니다).

1. 점이 6개 이상일 때만 처리합니다.
2. `cv2.fitLine(points, cv2.DIST_L2, ...)`으로 점들에 **최소제곱 직선**을 맞춥니다. 결과의 방향 벡터 $(v_x, v_y)$에서 $θ = |acos(v_x)|$를 구하면 0°는 수평, 90°는 수직입니다.
3. 60° < θ ≤ 90°이면 **세로 동작**, 0° ≤ θ < 30°이면 **가로 동작**입니다. 30~60°는 대각선이라 판단하지 않습니다(여기에도 불감 구간).
4. 위/아래, 왼/오른쪽은 이웃한 점의 x·y 증감 부호를 +1/−1로 더한 **다수결**로 정합니다.

```python run
import math
import numpy as np
import cv2

def classify(points):
    pts = np.array(points, dtype=np.int32)
    lr = sum(1 if b[0] - a[0] > 0 else -1 for a, b in zip(pts[:-1], pts[1:]))
    ud = sum(1 if b[1] - a[1] > 0 else -1 for a, b in zip(pts[:-1], pts[1:]))
    vx, vy, x0, y0 = cv2.fitLine(pts, cv2.DIST_L2, 0, 0.01, 0.01).flatten()
    angle = int(abs(math.degrees(math.acos(vx))))   # 0 = 수평, 90 = 수직
    if 90 >= angle > 60:
        return angle, "아래" if ud > 0 else "위"
    if 30 > angle >= 0:
        return angle, "오른쪽" if lr > 0 else "왼쪽"
    return angle, "판단 보류(대각선)"

strokes = {
    "좌→우": [(100 + 20 * i, 240 + (i % 2)) for i in range(10)],
    "위→아래": [(320 + (i % 3), 100 + 25 * i) for i in range(10)],
    "우→좌": [(500 - 30 * i, 200 + 2 * i) for i in range(10)],
    "대각선": [(100 + 20 * i, 100 + 20 * i) for i in range(10)],
}
for name, pts in strokes.items():
    print(name, "->", classify(pts))
```

```text
좌→우 -> (0, '오른쪽')
위→아래 -> (89, '아래')
우→좌 -> (3, '왼쪽')
대각선 -> (45, '판단 보류(대각선)')
```

`fitLine`의 방향 벡터는 선의 **기울기만** 알려 주고 진행 방향(앞/뒤)은 알려 주지 않습니다. 그래서 방향은 부호 다수결로 따로 정합니다. 다수결은 중간에 몇 점이 튀어도 결과가 바뀌지 않는 장점이 있습니다.

### 섀시 명령으로 연결하기

아래는 분류 결과를 MentorPi 섀시의 짧은 이동으로 바꾸는 예시 노드입니다. `interfaces.msg.Points`는 MentorPi 워크스페이스의 사용자 정의 메시지(`points[].x`, `points[].y`)라 실물에서만 동작합니다.

```python robot
import math, time
import numpy as np, cv2, rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
from interfaces.msg import Points

class TrajectoryDrive(Node):
    def __init__(self):
        super().__init__('trajectory_drive')
        self.pub = self.create_publisher(Twist, '/controller/cmd_vel', 1)
        self.create_subscription(Points, '/hand_trajectory/points', self.cb, 1)

    def cb(self, msg):
        if len(msg.points) <= 5:
            return
        pts = np.array([(p.x, p.y) for p in msg.points], np.int32)
        vx = cv2.fitLine(pts, cv2.DIST_L2, 0, 0.01, 0.01).flatten()[0]
        angle = abs(math.degrees(math.acos(vx)))
        d = np.sign(np.diff(pts, axis=0)).sum(axis=0)       # (x 다수결, y 다수결)
        t = Twist()
        if angle > 60:
            t.linear.x = 0.15 if d[1] < 0 else -0.15        # 위로 그으면 전진
        elif angle < 30:
            t.angular.z = -0.4 if d[0] > 0 else 0.4         # 오른쪽으로 그으면 우회전
        else:
            return
        self.pub.publish(t); time.sleep(1.0); self.pub.publish(Twist())

def main():
    rclpy.init()
    node = TrajectoryDrive()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.pub.publish(Twist())
        node.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```

콜백 안에서 `time.sleep(1.0)`을 쓰면 그동안 다른 콜백이 멈춥니다. 한 번에 한 명령만 처리하는 이 예제에서는 괜찮지만, 여러 토픽을 다루는 노드라면 타이머로 정지 시각을 예약하는 방식이 좋습니다(R05 참고).

## 실습 (실물)

:::safety 실물 실습 안전 수칙
- 이 장의 기본 예제(`hand_gesture.py`, `hand_trajectory`)는 **바퀴를 움직이지 않습니다.** 위의 `TrajectoryDrive`처럼 섀시 명령을 붙일 때만 로봇이 움직이므로, 그때는 바닥에 내려놓고 주변 1 m를 비웁니다.
- 속도는 선속도 0.15 m/s, 각속도 0.4 rad/s 이하로 두고 1초 뒤 반드시 정지 명령을 보냅니다.
- 카메라 앞에서 손을 움직이다가 로봇에 부딪히지 않도록 손과 로봇 사이 40 cm 이상을 유지합니다.
:::

1. VNC로 로봇 데스크톱에 접속하고 터미널에서 앱 자동 실행 서비스를 멈춥니다.

```bash
~/.stop_ros.sh
```

2. 깊이 카메라 노드를 켭니다.

```bash
ros2 launch peripherals depth_camera.launch.py
```

3. 새 터미널에서 제스처·궤적 예제를 실행합니다. 창이 뜨면 손을 카메라 앞 40~60 cm에 둡니다.

```bash
cd ros2_ws/src/example/example/mediapipe_example
python3 hand_gesture.py
```

4. 검지만 편 "1"을 잠시 유지하면 기록이 시작되고, 손끝을 움직이면 선이 그려집니다. 손을 펴서 "5"를 보이면 지워집니다. `q` 또는 `Esc`로 창을, 터미널에서 `Ctrl+C`로 프로그램을 끝냅니다.

5. 궤적 점을 **토픽으로** 받고 싶으면 ROS 2 노드 버전을 launch로 실행합니다. 이 launch는 카메라·컨트롤러·초기 자세 노드를 함께 켜므로 2번 카메라 노드는 먼저 끕니다.

```bash
ros2 launch example hand_trajectory_node.launch.py
# 다른 터미널
ros2 topic echo /hand_trajectory/points
ros2 service call /hand_trajectory/stop std_srvs/srv/Trigger {}
```

6. 실습을 마치면 앱 서비스를 다시 켭니다(부저가 한 번 울리면 완료).

```bash
sudo systemctl restart start_node.service
```

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 창은 뜨는데 손 점이 전혀 안 그려짐 | 카메라 토픽 이름 불일치. `hand_gesture.py`는 `/ascamera/camera_publisher/rgb0/image`, `hand_trajectory_node.py`는 `/depth_cam/rgb/image_raw`를 구독 | `ros2 topic list`로 실제 이름을 보고 `--ros-args -r /depth_cam/rgb/image_raw:=/ascamera/camera_publisher/rgb0/image`로 리매핑 |
| 제스처가 `none`으로만 나옴 | 손바닥이 옆을 향함, 손이 너무 멀어 랜드마크가 뭉개짐 | 손바닥을 카메라 정면으로, 거리 40~60 cm, 밝은 조명 |
| "1"인데 `two`/`hand_heart`로 나옴 | 엄지 각도가 문턱값 근처 | 엄지를 확실히 접거나, `thr_angle_s`를 ±5 범위에서 조정 |
| 궤적이 끊겨서 점선처럼 그려짐 | 손을 빨리 움직여 프레임 사이 이동이 크고, 추적이 끊겨 재검출 | 천천히 움직이기, 조명 개선. 필요하면 `distance` 문턱을 10 이하에서 키움 |
| `ModuleNotFoundError: fps` | `hand_gesture.py`는 같은 폴더의 `fps.py`를 import | 반드시 `mediapipe_example` 폴더로 `cd`한 뒤 실행 |
| 앱 기능이 동작하지 않음 | `~/.stop_ros.sh`로 앱 서비스를 멈춘 상태 | `sudo systemctl restart start_node.service` 또는 재부팅 |
