## 학습 목표

- Ubuntu(또는 Windows의 WSL2)에서 nvm으로 Node.js 22를 설치하고 기본 버전으로 고정합니다.
- `openclaw@2026.3.24`를 전역 설치하고, `openclaw` 명령을 찾지 못할 때 `PATH`를 고칩니다.
- `openclaw onboard` 마법사로 API 키와 모델을 연결하고, 생성된 `~/.openclaw/openclaw.json`의 주요 필드를 읽습니다.
- Gateway를 띄워 첫 메시지를 보내고, `gateway status`·`doctor`·`dashboard`·같은 `session-id` 재사용으로 설치를 검증합니다.
- OpenClaw를 PC에서 돌릴지 Raspberry Pi 5에서 돌릴지 자원·비용·보안 측면에서 판단하고, API 비용을 어림합니다.

## 설치 전에 이해할 것

설치 과정 전체를 관통하는 생각은 하나입니다. **OpenClaw의 핵심은 Gateway**이고, Gateway는 여러 채널에서 온 메시지를 알맞은 에이전트로 보내며 세션(Session)에 대화 맥락을 유지합니다. 이 장이 끝나면 Gateway가 실행 중이고, 모델 공급자가 설정되어, 첫 대화가 올바른 답을 돌려주는 상태가 됩니다.

@fig[c03-install] 이 장의 설치 흐름(①~⑦)과 onboard가 만드는 `~/.openclaw/` 폴더 구조.

:::info 버전에 관하여
이 장의 명령과 화면은 원본 교재의 기준 버전 **`openclaw@2026.3.24`**를 따릅니다. OpenClaw는 빠르게 바뀌는 프로젝트라 다른 버전에서는 명령 옵션, 마법사 메뉴, 설정 필드 이름이 다를 수 있습니다. 막히면 설치한 버전의 `openclaw --help`, `openclaw <명령> --help`를 먼저 확인하세요.
:::

### 준비물

1. 컴퓨터 한 대 (이 장은 **Ubuntu를 기준 환경**으로 씁니다)
2. 설치와 모델 호출을 위한 안정적인 네트워크
3. 텍스트 편집기 (VS Code 권장)
4. Git (선택: 사용자 스킬이나 설정 파일을 버전 관리할 때)
5. 클라우드 모델을 쓸 경우 **결제가 활성화된 공급자 계정과 API 키**, 또는 로컬 모델을 돌릴 여유 자원(Ollama)

### Windows 사용자: WSL2

Windows에서는 **WSL2(Windows Subsystem for Linux 2) + Ubuntu**에서 OpenClaw를 돌리는 것을 권장합니다. 운영체제 차이(경로 구분자, 셸, 서비스 관리)로 생기는 문제를 피할 수 있고, 이 장의 명령을 그대로 쓸 수 있습니다. 관리자 PowerShell에서 한 번 설치합니다.

```bash
# Windows PowerShell(관리자)에서 실행 — 설치 후 재부팅, Ubuntu 사용자 이름/암호 설정
wsl --install -d Ubuntu
```

이후 모든 명령은 WSL의 Ubuntu 터미널에서 실행합니다. WSL 안에서 띄운 Gateway의 `127.0.0.1:18789`는 보통 Windows 브라우저에서도 열립니다.

### Python인가 Node.js인가

OpenClaw CLI와 핵심 런타임은 **Node.js 생태계** 기반입니다. 기본 설치에는 Node.js만 있으면 됩니다. 파일 파싱이나 보고서 내보내기 같은 보조 스크립트를 쓰고 싶다면 Python을 함께 설치해도 되지만, 이 장에서는 코드를 작성하지 않으므로 Node.js로 충분합니다. (C08에서 ROS 2와 연결할 때는 Python 쪽 코드도 다룹니다.)

## 어디에 설치할까: PC인가, MentorPi인가

원본 교재는 Ubuntu PC를 기준으로 설명하고 로봇 본체에 설치하는 방법은 다루지 않습니다. 아래는 이 강의의 **권장 지침**이며 원본 교재의 내용은 아닙니다.

| 항목 | 개발 PC / 서버 | MentorPi의 Raspberry Pi 5 |
|---|---|---|
| 자원 | 여유 있음. 로컬 모델(Ollama)도 가능 | RAM·CPU를 ROS 2 노드(라이다, 카메라, SLAM, 내비)가 이미 많이 사용 |
| 아키텍처 | x86_64 (WSL2 포함) | ARM64. Node.js 22는 지원되지만 일부 네이티브 모듈은 빌드가 필요할 수 있음 |
| 로컬 모델 | 작은 모델은 CPU, 큰 모델은 GPU로 가능 | 1~3B급 소형 모델만 현실적, 응답이 느리고 발열·전력 증가 |
| 보안 | 로봇과 분리되어 사고 범위가 작음 | 에이전트가 모터를 직접 다루는 기기에 상주 |
| 권장 용도 | **학습과 개발의 기본 위치** | 클라우드 모델만 쓰는 가벼운 Gateway, 네트워크 없이 동작해야 할 때 |

처음에는 **PC(또는 WSL2)에 OpenClaw를 설치해 개념을 익히고**, C08에서 로봇과 연결할 때 "Gateway는 PC, 로봇 제어는 MentorPi의 ROS 2 쪽 작은 브리지"로 나누는 구성을 권장합니다. 그래야 에이전트가 실수해도 로봇 쪽 안전 코드가 마지막 방어선이 됩니다.

## Node.js 설치 (nvm)

먼저 이미 설치된 Node가 있는지 확인합니다.

```bash
node -v
npm -v
```

OpenClaw에는 **Node 22 이상**이 필요합니다. 버전이 낮거나 없으면 **nvm(Node Version Manager)**으로 설치합니다. nvm은 사용자 홈 디렉터리에 Node를 설치하므로 `sudo` 없이 전역 패키지를 설치할 수 있고, 여러 버전을 오갈 수 있습니다. 운영체제 패키지(`apt install nodejs`)는 버전이 오래된 경우가 많아 권장하지 않습니다.

```bash
# 1) nvm 설치 후 셸 환경 다시 읽기
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc

# 2) Node 22 설치 → 사용 → 새 터미널에서도 기본값이 되도록 고정
nvm install 22
nvm use 22
nvm alias default 22

node -v   # v22.x.x 이면 성공
```

:::tip `curl … | bash` 습관
인터넷 스크립트를 바로 셸로 넘기는 방식은 편하지만, 주소가 공식 저장소(`github.com/nvm-sh/nvm`)인지 반드시 확인하세요. 불안하면 먼저 내려받아 내용을 읽은 뒤 실행해도 됩니다.
:::

## OpenClaw 설치

원본 교재와 같은 버전을 **버전 고정**으로 설치합니다. 강의 자료와 화면을 맞추려면 `@latest`보다 고정 버전이 안전합니다.

```bash
npm install -g openclaw@2026.3.24
openclaw --version
```

`openclaw: command not found`가 나오면 대개 npm 전역 설치 경로가 `PATH`에 없는 것입니다.

```bash
npm config get prefix          # 예: /home/ubuntu/.nvm/versions/node/v22.x.x
ls "$(npm config get prefix)/bin"   # openclaw 가 보여야 함
# 보이는데 명령을 못 찾으면 PATH에 추가 (nvm 사용 시 보통 불필요)
echo 'export PATH="$(npm config get prefix)/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

nvm을 쓰면 `nvm use`가 PATH를 자동으로 맞추므로, 명령을 못 찾는 가장 흔한 원인은 **새 터미널에서 기본 버전이 22가 아닌 경우**입니다. `nvm alias default 22`를 했는지 확인하세요.

## 온보딩 마법사로 API 키 연결

```bash
openclaw onboard
```

마법사는 터미널 메뉴로 진행됩니다(화살표로 이동, Space로 선택, Enter로 확정). 원본 교재 기준의 선택 순서는 다음과 같습니다.

| 단계 | 선택 | 이유 |
|---|---|---|
| 시작 확인 | **Yes** | 설정 진행 |
| 설치 방식 | **QuickStart** | 기본값 위주로 빠르게 |
| 기존 설정 처리 | **Reset** | 깨끗한 상태에서 시작(기존 설정이 있으면 먼저 백업) |
| 범위 | **Config Only** | 전체 설치 흐름 없이 설정만 완료 |
| 모델 공급자 | 예: **OpenAI** → API 키 입력 | 공급자 콘솔에서 미리 키 발급 |
| 모델 | 대상 모델 선택 | 비용·속도·품질 고려 |
| 메시지 채널 | **건너뛰기** | C06에서 Telegram 연결 |
| 검색 공급자 | **설정 안 함** | 나중에 필요할 때 |
| 스킬 | **건너뛰기** | C05에서 필요한 것만 |
| 훅(hooks) | **Skip for now**를 Space로 선택 후 Enter | 나중에 설정 |
| 마무리 | **Restart** | Gateway 설치·시작 대기 |
| 인터페이스 | **TUI** (또는 Web UI) | 바로 대화 시험 |

:::warning API 사용료
OpenAI 같은 클라우드 모델은 **토큰 사용량만큼 과금**되며, 계정에 결제 수단이 활성화되어 있어야 호출됩니다. 공급자 콘솔에서 **월 사용 한도(budget/limit)**를 먼저 걸어 두세요. 에이전트는 도구 호출 루프 때문에 질문 하나에 모델을 여러 번 부를 수 있습니다.
:::

마법사가 끝나면 홈 디렉터리에 `~/.openclaw/`가 생기고 그 안에 `openclaw.json`이 만들어집니다. 모든 설정의 중심이므로 **편집 전에 항상 백업**합니다.

```bash
cp ~/.openclaw/openclaw.json ~/.openclaw/openclaw.json.bak
```

### openclaw.json 훑어보기

실제 파일은 길지만 이 장에서 알아야 할 부분만 추리면 다음과 같습니다(원본 교재 설정을 줄이고 비밀값을 자리표시자로 바꾼 것입니다).

```json
{
  "models": {
    "providers": {
      "deepseek": {
        "baseUrl": "https://api.deepseek.com",
        "api": "openai-completions",
        "models": [ { "id": "deepseek-chat" }, { "id": "deepseek-reasoner" } ]
      }
    }
  },
  "agents": {
    "defaults": { "model": { "primary": "deepseek/deepseek-chat" } },
    "list": [
      { "id": "main", "default": true,
        "workspace": "/home/ubuntu/.openclaw/workspace/main",
        "agentDir": "/home/ubuntu/.openclaw/agents/main/agent" }
    ]
  },
  "gateway": {
    "port": 18789,
    "mode": "local",
    "bind": "loopback",
    "auth": { "mode": "token", "token": "<GATEWAY_TOKEN>" }
  }
}
```

| 경로 | 의미 |
|---|---|
| `models.providers` | 공급자별 엔드포인트와 사용할 모델 목록 |
| `agents.defaults.model.primary` | 모델을 따로 지정하지 않은 에이전트가 쓰는 기본 모델(`공급자/모델ID`) |
| `agents.list` | 에이전트 목록. `default: true`인 것이 기본 에이전트(보통 `main`) |
| `gateway.port` | Gateway 포트(기본 18789). 대시보드 주소도 이 값을 따름 |
| `gateway.bind` | `loopback`이면 이 컴퓨터에서만 접속 가능 |
| `gateway.auth` | Gateway 접속 인증. 토큰은 비밀번호처럼 취급 |

API 키는 onboard 과정에서 인증 프로필(`auth.profiles`)로 관리됩니다. 키나 토큰이 들어 있는 `openclaw.json`을 스크린샷·채팅·Git 저장소에 그대로 올리지 마세요.

## 로컬 Ollama 모델 (선택)

클라우드 API 키 대신 **로컬 대형 언어 모델**을 쓸 수도 있습니다. 비용이 들지 않고 대화가 밖으로 나가지 않는 대신, 컴퓨터 자원이 많이 들고 작은 모델은 도구 호출 품질이 떨어질 수 있습니다.

```bash
# 1) Ollama 설치
curl -fsSL https://ollama.com/install.sh | sh
# 2) 모델 받기 (실제로 필요한 모델 이름을 사용)
ollama pull llama3.2
# 3) 로컬에서 실행해 대화가 되는지 확인 (종료: /bye)
ollama run llama3.2
```

그다음 `openclaw onboard`에서 모델 공급자로 local 또는 Ollama 항목을 고릅니다(해당 선택지가 있는 경우). 필드 구성은 버전에 따라 조금씩 다르므로 **마법사 화면에 나오는 선택지를 기준**으로 삼으세요.

:::tip 로컬 모델과 도구 호출
C02의 도구 호출 루프는 모델이 형식에 맞는 도구 호출을 돌려줘야 동작합니다. 작은 로컬 모델은 이 형식을 자주 틀리므로, 도구가 많은 에이전트(C04~C07)에서는 클라우드 모델로 먼저 동작을 확인한 뒤 로컬 모델로 바꿔 비교하는 순서를 권장합니다.
:::

## 첫 Hello World

```bash
# 1) Gateway 시작
openclaw gateway start

# 2) 기본 에이전트(main)에게 메시지 보내기
openclaw agent --agent main --session-id hello-001 --message "Hello! Please give a brief self-introduction."

# 3) TUI로 대화 확인
openclaw tui
```

기본 에이전트 ID는 대부분 `main`입니다. 다르다면 `openclaw agents list --json`으로 확인합니다. 답이 돌아오면 핵심 루프의 첫 부분이 완성된 것입니다.

1. Gateway가 실행 중이다.
2. 메시지가 세션(`hello-001`)에 들어갔다.
3. 에이전트가 모델 응답을 만들어 돌려주었다.

## 첫 설치 검증

메시지 하나가 우연히 성공한 "거짓 양성"을 피하려면 전체를 한 번 점검합니다.

```bash
# 1) Gateway 실행 상태
openclaw gateway status
# 2) 전체 건강 검진 (지원하면 --deep 도)
openclaw doctor
openclaw doctor --deep
# 3) 웹 대시보드 열기 → 브라우저에서 http://127.0.0.1:18789/
openclaw dashboard
# 4) 같은 session-id로 두 번 보내 맥락이 이어지는지 확인
openclaw agent --agent main --session-id hello-001 --message "Summarize what OpenClaw is in one sentence."
openclaw agent --agent main --session-id hello-001 --message "Make the summary more beginner-friendly and list the next step."
# 5) 에이전트 목록
openclaw agents list --json
```

대시보드 포트가 다르면 `openclaw.json`의 `gateway.port` 값을 씁니다. 세션이 정상이면 4번의 두 번째 메시지가 첫 번째 요약을 이어받아 "더 쉽게" 바꿉니다.

## 실습 (시뮬레이션): 미니 doctor와 세션

### 설정 파일 점검기

`openclaw doctor`가 하는 일 가운데 "설정 파일이 앞뒤가 맞는가"를 흉내 내는 검사기를 만들어 봅니다. 일부러 문제를 심어 둔 설정을 넣었습니다. 실제 `doctor`의 검사 항목과 메시지는 이것과 다르며, 여기서는 **설정을 읽는 눈**을 기르는 것이 목적입니다.

@btn[~/tools/playground.html] Playground 열기

```python run
# 미니 doctor: openclaw.json 구조를 점검합니다 (실제 openclaw doctor를 흉내 낸 교육용 검사기).
import json
CONFIG = """{
  "models": {"providers": {"deepseek": {"baseUrl": "https://api.deepseek.com",
      "models": [{"id": "deepseek-chat"}, {"id": "deepseek-reasoner"}]}}},
  "agents": {
    "defaults": {"model": {"primary": "deepseek/deepseek-chat"}},
    "list": [
      {"id": "main", "default": true, "workspace": "~/.openclaw/workspace/main"},
      {"id": "test", "model": "deepseek/deepseek-reasoner", "workspace": "~/.openclaw/workspace/test",
       "tools": {"allow": ["read", "exec", "web_fetch"], "deny": ["exec", "cron"]}},
      {"id": "robot", "model": "openai/gpt-robot", "workspace": "~/.openclaw/workspace/main"}
    ]},
  "gateway": {"port": 18789, "bind": "loopback", "auth": {"mode": "token", "token": ""}}
}"""

def doctor(text):
    try:
        cfg = json.loads(text)
    except json.JSONDecodeError as e:
        return ["[FAIL] JSON 문법 오류: %s (줄 %d)" % (e.msg, e.lineno)]
    out = []
    gw = cfg.get("gateway", {})
    port = gw.get("port")
    ok = isinstance(port, int) and 1024 <= port <= 65535
    out.append("[%s] gateway.port = %s" % ("OK  " if ok else "FAIL", port))
    if gw.get("bind") != "loopback":
        out.append("[WARN] gateway.bind = %s (외부 노출 주의)" % gw.get("bind"))
    if not gw.get("auth", {}).get("token"):
        out.append("[WARN] gateway.auth.token 비어 있음")
    known = {"%s/%s" % (p, m["id"])
             for p, prov in cfg.get("models", {}).get("providers", {}).items()
             for m in prov.get("models", [])}
    agents = cfg.get("agents", {}).get("list", [])
    defaults = [a["id"] for a in agents if a.get("default")]
    out.append("[%s] 기본 에이전트: %s" % ("OK  " if len(defaults) == 1 else "FAIL", defaults))
    primary = cfg["agents"].get("defaults", {}).get("model", {}).get("primary")
    seen = {}
    for a in agents:
        ref = a.get("model", primary)
        if ref not in known:
            out.append("[FAIL] %s: 모델 '%s'가 models.providers에 없음" % (a["id"], ref))
        t = a.get("tools", {})
        both = sorted(set(t.get("allow", [])) & set(t.get("deny", [])))
        if both:
            out.append("[WARN] %s: allow와 deny에 동시에 있음 %s" % (a["id"], both))
        ws = a.get("workspace")
        if ws in seen:
            out.append("[WARN] %s: workspace를 %s 에이전트와 공유" % (a["id"], seen[ws]))
        seen.setdefault(ws, a["id"])
    return out

for line in doctor(CONFIG):
    print(line)
print("--- 쉼표 하나 빠뜨린 경우 ---")
print(doctor('{"gateway": {"port": 18789 "bind": "loopback"}}')[0])
```

```text
[OK  ] gateway.port = 18789
[WARN] gateway.auth.token 비어 있음
[OK  ] 기본 에이전트: ['main']
[WARN] test: allow와 deny에 동시에 있음 ['exec']
[FAIL] robot: 모델 'openai/gpt-robot'가 models.providers에 없음
[WARN] robot: workspace를 main 에이전트와 공유
--- 쉼표 하나 빠뜨린 경우 ---
[FAIL] JSON 문법 오류: Expecting ',' delimiter (줄 1)
```

- `auth.token`이 비어 있으면 같은 컴퓨터의 다른 프로그램이 Gateway를 쓸 수 있습니다.
- `test`의 `exec`는 allow와 deny에 모두 있어 결과를 예측하기 어렵습니다(C02).
- `robot`은 등록되지 않은 모델을 가리켜 첫 메시지에서 실패합니다. 이런 오류는 Gateway가 시작될 때가 아니라 **그 에이전트가 처음 불릴 때** 드러나는 경우가 많아, 미리 점검하는 습관이 중요합니다.
- JSON은 쉼표 하나로 파일 전체가 무효가 됩니다. 손으로 고친 뒤에는 반드시 `openclaw doctor`를 돌리고, 망가지면 `.bak`으로 되돌립니다.

### 세션 연속성과 비용

같은 `session-id`로 보내면 이전 대화가 **함께 모델로 전송**되어 맥락이 이어집니다. 그 대가로 입력 토큰이 늘어납니다. 아래 예제는 단가를 가정해 호출마다 비용을 어림합니다(단가는 예시이며 실제 요금은 공급자 요금표를 확인하세요).

```python run
# 세션 연속성과 토큰 비용: 같은 session-id면 이전 대화가 함께 모델로 전송됩니다.
PRICE_IN, PRICE_OUT = 0.28, 0.42     # 가상의 단가: 100만 토큰당 USD (공급자 요금표를 확인하세요)
SYSTEM_PROMPT_TOKENS = 1500          # 워크스페이스 규약 파일 등이 매번 포함된다고 가정
sessions = {}

def tokens(text):
    return max(1, len(text) // 2)    # 아주 거친 근사 (실제는 모델별 토크나이저)

def agent(agent_id, session_id, message):
    hist = sessions.setdefault((agent_id, session_id), [])
    if "쉽게" in message and hist:
        answer = "앞 요약을 쉽게: 채팅앱과 AI를 이어 주는 관리실. 다음 단계는 설치."
    elif "쉽게" in message:
        answer = "무엇을 쉽게 바꿀까요? 앞선 대화가 없습니다."
    else:
        answer = "OpenClaw는 모델·에이전트·도구·채널을 잇는 자체 호스팅 게이트웨이입니다."
    tin = SYSTEM_PROMPT_TOKENS + sum(tokens(m) for m in hist) + tokens(message)
    tout = tokens(answer)
    hist += [message, answer]
    return answer, tin, tout

calls = [("main", "hello-001", "OpenClaw를 한 문장으로 요약해 줘"),
         ("main", "hello-001", "더 쉽게 바꾸고 다음 단계를 알려 줘"),
         ("main", "hello-002", "더 쉽게 바꾸고 다음 단계를 알려 줘")]
total = 0.0
for a, s, m in calls:
    ans, tin, tout = agent(a, s, m)
    cost = tin / 1e6 * PRICE_IN + tout / 1e6 * PRICE_OUT
    total += cost
    print("%s | %s" % (s, ans))
    print("          입력 %d 토큰, 출력 %d 토큰, 약 $%.6f" % (tin, tout, cost))
print("합계 약 $%.6f, 하루 1,000회면 약 $%.2f" % (total, total / 3 * 1000))
```

```text
hello-001 | OpenClaw는 모델·에이전트·도구·채널을 잇는 자체 호스팅 게이트웨이입니다.
          입력 1511 토큰, 출력 22 토큰, 약 $0.000432
hello-001 | 앞 요약을 쉽게: 채팅앱과 AI를 이어 주는 관리실. 다음 단계는 설치.
          입력 1543 토큰, 출력 20 토큰, 약 $0.000440
hello-002 | 무엇을 쉽게 바꿀까요? 앞선 대화가 없습니다.
          입력 1510 토큰, 출력 12 토큰, 약 $0.000428
합계 약 $0.001301, 하루 1,000회면 약 $0.43
```

`hello-002`는 새 세션이라 "더 쉽게"가 무엇을 가리키는지 모릅니다. 비용 면에서는 시스템 프롬프트(워크스페이스 규약 파일 등)가 매 호출에 포함되어 입력 토큰의 대부분을 차지한다는 점에 주목하세요. 실제로는 도구 호출 루프가 한 질문에 모델을 여러 번 부르고, 도구 결과(웹 페이지 등)가 길면 비용이 빠르게 늘어납니다.

## 실습 (실물)

:::safety 실물 설치 전 안전 수칙
- **API 키는 비밀번호입니다.** Git 저장소, 스크린샷, 채팅, 교재 과제물에 절대 넣지 마세요. 실수로 노출했다면 즉시 공급자 콘솔에서 폐기(revoke)하고 새로 발급합니다.
- 공급자 콘솔에서 **월 사용 한도**를 설정한 뒤 실습합니다. 반복 루프 버그 하나로 요금이 쌓일 수 있습니다.
- `gateway.bind`는 **`loopback`을 유지**합니다. 다른 기기에서 접속해야 한다면 방화벽과 토큰 인증을 먼저 갖추고, 공유기 포트 포워딩으로 인터넷에 직접 열지 마세요.
- 이 장에서는 **로봇 제어 도구를 연결하지 않습니다.** MentorPi 연결은 안전 계층을 갖춘 뒤 C08에서 합니다.
:::

:::mission 설치 체크리스트
1. `node -v`가 v22 이상을 보인다.
2. `openclaw --version`이 `2026.3.24`(또는 설치한 버전)를 보인다.
3. `~/.openclaw/openclaw.json`과 `openclaw.json.bak`이 있다.

5. `http://127.0.0.1:18789/` 대시보드가 열린다.
6. 같은 `hello-001` 세션의 두 번째 메시지가 첫 번째 답을 이어받는다.
7. (선택) `ollama run llama3.2`가 로컬에서 답한다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `openclaw: command not found` | npm 전역 `bin`이 PATH에 없음, 새 터미널의 Node 버전이 다름 | `npm config get prefix`로 경로 확인 후 PATH 추가, `nvm alias default 22` |
| `npm install -g` 중 권한 오류(EACCES) | 시스템 Node(`/usr`)에 설치하려 함 | `sudo` 대신 nvm으로 Node 재설치 |
| 설치 중 엔진 버전 오류 | Node 22 미만 | `nvm install 22 && nvm use 22` |
| onboard 후 Gateway가 시작되지 않음 | 설정 오류, 포트 충돌 | 설정 파일을 고치기 전에 `openclaw doctor` → `openclaw gateway run --verbose`로 전경 실행해 핵심 오류 줄 기록 |
| 대시보드가 안 열림 | Gateway 미실행, 포트 변경, 방화벽 | `openclaw gateway status`, `gateway.port` 확인, LAN 접속이면 방화벽 허용 여부 확인 |
| 모델 호출 시 401/403 | API 키 오류·만료 | 공급자 콘솔에서 키 재발급 후 `openclaw onboard`로 다시 입력 |
| 모델 호출 시 429 또는 결제 오류 | 결제 미활성, 한도 초과, 속도 제한 | 공급자 결제·한도 확인, 잠시 후 재시도 |
| 두 번째 메시지가 앞 대화를 모름 | 다른 `session-id` 사용 | 같은 ID로 다시 전송 |
| JSON 편집 후 전부 동작 안 함 | 쉼표·따옴표 누락 | `openclaw doctor`로 확인, `openclaw.json.bak`으로 복원 |
| Ollama 모델이 도구를 제대로 못 씀 | 소형 모델의 도구 호출 형식 오류 | 더 큰 모델 또는 클라우드 모델로 비교 시험 |
