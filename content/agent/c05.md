## 학습 목표

- 트리거 문구 → 스킬 선택 → 도구 호출 → 고정 형식 응답으로 이어지는 **최소 폐루프(minimum closed loop)**를 설명합니다.
- SKILL.md의 YAML 머리말(name·description·version)과 본문 네 섹션(When to Activate·Fixed Output Format·Execution Steps·Constraints)을 직접 작성합니다.
- 스킬을 에이전트에 등록하고 `openclaw skills list -v`, `openclaw skills check --json`, 트리거 문구로 합동 디버깅(joint debugging)합니다.
- description 문장이 스킬 선택을 어떻게 좌우하는지 이해하고, 좋은 트리거 설명과 시험 표(testing matrix)를 설계합니다.
- 가져오기에 실패했을 때 지어내지 않고 `Not available yet`을 돌려주는 규칙을 검증합니다.

## 최소 폐루프

C04에서 만든 `test` 에이전트는 파일·스크립트·웹을 다룰 수 있지만, 매번 "날씨를 wttr.in에서 가져와서 이런 형식으로…"라고 설명해 주어야 합니다. 자주 하는 일을 **한 번 적어 두고 재사용**하는 단위가 **스킬(Skill)**입니다. 이 장에서는 `daily-briefing-weather`라는 스킬을 처음부터 만들어, 가장 짧은 폐루프 하나를 완성합니다.

@fig[c05-loop] 이 장의 최소 폐루프. 트리거 문구가 들어오면 에이전트가 스킬을 고르고, 스킬의 절차대로 web_fetch(실패 시 web_search)를 호출한 뒤 고정 형식으로 답합니다.

| 구성 요소 | 이 루프에서 하는 일 |
|---|---|
| **Gateway** | 들어온 메시지를 `test` 에이전트로 라우팅 |
| **Agent** | 언제 스킬을 쓸지, 어떤 도구가 필요한지 결정 |
| **Skill** | 활성화 조건, 출력 형식, 실행 단계, 제약을 정의 |
| **Tool** | 웹에서 날씨와 주요 뉴스를 실제로 가져옴 (`web_fetch`, `web_search`) |

원본 교재는 날씨를 wttr.in에서, 화제 뉴스를 중국의 인민망(People's Daily Online, `people.com.cn`) 첫 화면에서 가져옵니다. 이 강의에서는 구조를 그대로 두고 도시를 서울로, 뉴스 사이트를 국내 뉴스 포털로 바꾸어 설명합니다. 어떤 사이트를 쓰든 **폐루프의 모양**은 같습니다.

## 준비

스킬은 에이전트에 묶여야 동작하므로, 먼저 Gateway와 에이전트가 살아 있는지 확인합니다.

```bash
openclaw gateway status        # 실행 중인지 확인
openclaw gateway start         # 멈춰 있으면 시작
openclaw doctor                # 설정 빠른 점검
openclaw agents list --json    # "id": "test" 항목이 있어야 함
```

마지막 명령에서 `test`가 보이지 않으면 C04의 등록 절차부터 다시 합니다. 스킬 설정은 에이전트 `id`에 연결되므로, 이 id가 없으면 합동 디버깅을 진행할 수 없습니다. `test`의 워크스페이스에는 C04에서 만든 AGENTS.md·SOUL.md·USER.md·IDENTITY.md·TOOLS.md가 이미 있어야 합니다. 이 장은 규약 파일이 아니라 **스킬 → 도구 호출 → 합동 디버깅** 흐름에 집중합니다.

## SKILL.md의 구조

@fig[c05-skillmd] SKILL.md는 두 단계에서 쓰입니다. 머리말(특히 description)은 스킬을 고를 때, 본문은 스킬이 선택된 뒤 실행할 때 읽힙니다.

스킬 하나는 폴더 하나이고, 그 안의 `SKILL.md`가 모델에게 네 가지를 알려 줍니다.

1. **활성화 조건**: 어떤 문구·요청 표현일 때 이 스킬을 쓰는가
2. **출력 형식**: 매번 같은 틀로 답하게 하는 고정 템플릿
3. **실행 단계**: 날씨 먼저, 뉴스 다음, 마지막에 조립
4. **제약**: 가져오기에 실패하면 지어내지 않는다

C02에서 본 것처럼 스킬에는 코드 구현(예: `index.js`)이 붙을 수도 있지만, 이 장의 스킬은 **SKILL.md 하나만으로** 동작합니다. 실제 일은 기존 도구(`web_fetch`, `web_search`)가 하고, SKILL.md는 그 도구를 **어떤 순서로, 어떤 규칙으로** 부를지 적은 절차서입니다.

### 머리말: 선택의 열쇠

```markdown
---
name: daily-briefing-weather
description: >-
  '오늘의 브리핑', '오늘 뭐가 화제야', '화제 뉴스 브리핑', "Today's briefing" 요청에
  일일 브리핑을 만든다. '<도시> 날씨', '오늘 <도시> 날씨 어때' 같은 도시 날씨 질문에도 답한다.
  날씨는 웹(wttr.in), 화제 뉴스는 뉴스 사이트 첫 화면에서 가져와 고정 형식
  "Daily briefing: 1. Weather: {result}. Hot topics: {Title 1: summary, ...}"으로 출력한다.
version: "1.0.0"
---
```

| 필드 | 역할 | 규칙 |
|---|---|---|
| `name` | 스킬 식별자 | 소문자·하이픈. 에이전트의 `skills` 배열 문자열과 **글자 하나까지 같아야** 함 |
| `description` | 언제 쓰고 무엇을 내는지 | 모델이 스킬을 고를 때 보는 **거의 유일한 정보** |
| `version` | 변경 추적 | 따옴표로 감싼 문자열 권장 (`"1.0.0"`) |

일반적으로 에이전트는 매 요청마다 **스킬 목록(이름 + description)**만 프롬프트에 받고, 요청이 어떤 스킬과 맞는다고 판단하면 그때 SKILL.md 본문을 읽어 따릅니다. 그래서 본문을 아무리 잘 써도 **description이 요청과 연결되지 않으면 스킬은 영영 선택되지 않습니다**. 원본의 description이 트리거 문구와 출력 형식을 한 문단에 몰아 적은 이유가 이것입니다.

### 본문: 실행 절차서

전체 SKILL.md는 다음과 같습니다. 원본 템플릿의 구조를 유지하고 도시·뉴스 사이트·트리거 문구를 한국 환경에 맞게 바꾸었습니다.

```markdown
# Daily Briefing and City Weather

## When to Activate
- 요청이 `오늘의 브리핑`, `오늘 뭐가 화제야`, `화제 뉴스 브리핑`, `Today's briefing`일 때
- 요청이 `오늘 <도시> 날씨 어때?`, `<도시> 날씨`, `How is the weather in <city> today?`일 때

## Fixed Output Format
항상 아래 구조를 유지한다(한 줄 또는 같은 내용의 여러 줄).
`Daily briefing: 1. Weather: {result}. Hot topics: {Title 1: brief summary, Title 2: brief summary...}`

규칙:
- 날씨에는 그날의 핵심(날씨 상태, 기온 범위, 강수, 바람 또는 체감 조언)을 넣는다.
- 화제는 최소 3개, 보통 3~6개. 각 항목은 `제목: 한 문장 요약`.
- 어떤 항목이든 가져오지 못하면 `Not available yet`이라고 분명히 쓴다. 지어내지 않는다.

## Execution Steps
1. 의도 파악
   - `오늘의 브리핑`류: 화제를 기본으로 하고, 세션의 도시를 알면 날씨도 넣는다.
   - `<도시> 날씨`류: 요청의 도시를 `<city>`로 두고 화제 요약도 함께 넣는다.
2. 날씨 가져오기
   - `web_fetch` 우선: `https://wttr.in/<city>?format=j1` (또는 `?lang=ko`)
   - 실패하면 `web_search`로 `<city> 오늘 날씨`를 검색하고 공신력 있는 출처에서 당일 정보만 뽑는다.
3. 화제 뉴스 가져오기
   - `web_fetch`로 뉴스 사이트 첫 화면(예: `https://www.yna.co.kr/`)을 가져온다.
   - 주요 뉴스·경제·기술·사회·국제 섹션에서 당일 헤드라인을 고른다.
   - 페이지에 보이는 요약만 근거로 한 문장씩 쓴다. 추측하지 않는다.
4. 조립과 응답
   - 고정 형식을 엄격히 따른다. 간결하게, 불필요한 인사말 없이.

## Constraints
- 사이트에 실제로 보이는 정보를 우선한다. 세부 사항을 지어내지 않는다.
- 날씨만 물어도 고정 형식을 유지하고 화제를 덧붙인다.
- 화제만 물어도 날씨 칸을 채운다. 도시를 알 수 없으면 `No city specified. Weather is not available yet`.
```

네 섹션은 각각 다른 실패를 막습니다. **When to Activate**는 "안 불림"을, **Fixed Output Format**은 "매번 형식이 다름"을, **Execution Steps**는 "도구를 안 쓰고 기억으로 답함"을, **Constraints**는 "실패를 날조로 덮음"을 막습니다. 특히 마지막 규칙은 LLM이 빈칸을 그럴듯한 말로 채우려는 성향이 있기 때문에 **명시적으로** 적어야 합니다.

### 모형: SKILL.md 파싱과 skills check

`openclaw skills check`가 하는 일을 흉내 내 봅시다. 머리말과 섹션을 파싱한 뒤, ① 이름이 에이전트의 `skills` 배열과 같은지, ② 필수 섹션이 있는지, ③ 본문이 요구하는 도구가 `tools.allow`에 있는지 검사합니다.

```python run
# SKILL.md 파서 + skills check 흉내
SKILL_MD = """---
name: daily-briefing-weather
description: >-
  '오늘의 브리핑', '오늘 뭐가 화제야', '<도시> 날씨' 요청에 답한다.
  날씨는 wttr.in, 뉴스는 뉴스 사이트에서 가져와 고정 형식으로 출력한다.
version: "1.0.0"
---
# Daily Briefing and City Weather
## When to Activate
- 오늘의 브리핑
- 오늘 뭐가 화제야
- <도시> 날씨
## Fixed Output Format
Daily briefing: 1. Weather: {result}. Hot topics: {...}
## Execution Steps
1. 의도 파악 2. web_fetch 날씨(실패 시 web_search) 3. web_fetch 뉴스 4. 조립
## Constraints
- 가져오지 못하면 Not available yet. 지어내지 않는다.
"""

def parse_skill(text):
    _, fm, body = text.split("---\n", 2)
    meta, key = {}, None
    for ln in fm.splitlines():
        if ln.startswith("  ") and key:                 # 접힌 여러 줄 값(>-)
            meta[key] = (meta[key] + " " + ln.strip()).strip()
        elif ":" in ln:
            key, val = ln.split(":", 1)
            meta[key] = val.strip().strip('"').replace(">-", "")
    sections, cur = {}, None
    for ln in body.splitlines():
        if ln.startswith("## "):
            cur = ln[3:].strip(); sections[cur] = []
        elif cur and ln.strip():
            sections[cur].append(ln.strip())
    return meta, sections

def skills_check(meta, sections, agent):
    errs = []
    if meta.get("name") not in agent["skills"]:
        errs.append(f"이름 불일치: SKILL.md '{meta.get('name')}' vs agent {agent['skills']}")
    for need in ("When to Activate", "Fixed Output Format", "Execution Steps", "Constraints"):
        if need not in sections: errs.append(f"섹션 없음: {need}")
    body = " ".join(sum(sections.values(), []))
    for t in ("web_fetch", "web_search"):
        if t in body and t not in agent["tools_allow"]:
            errs.append(f"도구 권한 없음: {t}")
    return errs or ["OK"]

meta, sec = parse_skill(SKILL_MD)
print("name:", meta["name"], "| version:", meta["version"])
print("description:", meta["description"][:40], "...")
print("sections:", list(sec))
good = {"skills": ["daily-briefing-weather"], "tools_allow": ["read", "web_fetch", "web_search"]}
bad = {"skills": ["daily_briefing_weather"], "tools_allow": ["read"]}
print("\n[check good]", skills_check(meta, sec, good))
print("[check bad]")
for e in skills_check(meta, sec, bad):
    print("  -", e)
```

```text
name: daily-briefing-weather | version: 1.0.0
description: '오늘의 브리핑', '오늘 뭐가 화제야', '<도시> 날씨' 요청에 답한 ...
sections: ['When to Activate', 'Fixed Output Format', 'Execution Steps', 'Constraints']

[check good] ['OK']
[check bad]
  - 이름 불일치: SKILL.md 'daily-briefing-weather' vs agent ['daily_briefing_weather']
  - 도구 권한 없음: web_fetch
  - 도구 권한 없음: web_search
```

`bad` 설정의 오류 두 종류가 실제 현장에서 가장 흔합니다. 하이픈(`-`)과 밑줄(`_`) 하나 차이로 스킬이 연결되지 않고, 권한이 없으면 스킬이 선택되어도 **말로만 설명하고 실제로는 가져오지 않습니다**.

## 에이전트에 스킬 등록하기

### 1) skills 배열 추가

`openclaw.json`의 `agents.list`에서 `id: "test"` 항목을 찾아 다음 필드를 추가합니다. 배열의 문자열은 SKILL.md 머리말의 `name`과 정확히 같아야 합니다.

```json
"skills": ["daily-briefing-weather"]
```

추가한 뒤의 `test` 항목은 대략 다음 모양입니다(C04의 도구 목록은 그대로 두고 `skills`만 늘어남).

```json
{
  "id": "test",
  "name": "test, execution-focused multimodal assistant",
  "workspace": "/home/ubuntu/.openclaw/workspace/test",
  "agentDir": "/home/ubuntu/.openclaw/agents/test/agent",
  "model": "deepseek/deepseek-reasoner",
  "skills": ["daily-briefing-weather"],
  "identity": { "name": "test, execution-focused multimodal assistant" },
  "tools": {
    "allow": ["read", "write", "edit", "apply_patch", "exec", "process", "browser",
              "web_search", "web_fetch", "memory_search", "memory_get", "session_status",
              "sessions_list", "sessions_history", "message", "nodes", "image"],
    "deny": ["sessions_spawn", "subagents", "canvas", "cron", "gateway"]
  }
}
```

### 2) 도구 권한 확인

같은 항목의 `tools.allow`에 **최소한 `web_fetch`와 `web_search`**가 있어야 합니다. 이 둘이 없으면 잘 쓴 스킬도 "날씨는 wttr.in에서 확인할 수 있습니다" 같은 **설명만** 내놓습니다. 원본 교재는 브리핑 전용이라면 파일 쓰기를 뺀 축소 목록으로도 충분하다는 예를 함께 보여 줍니다. C04에서 배운 최소 권한 원칙과 같은 방향입니다.

```json
"allow": ["read", "exec", "process", "web_search", "web_fetch",
          "memory_search", "memory_get", "session_status",
          "sessions_list", "sessions_history", "message"]
```

### 3) systemPrompt에 트리거를 못 박기 (선택, 강력 권장)

스킬 선택을 더 안정적으로 만들려면 `test`의 systemPrompt에 다음과 같은 **강제 규칙(hard rule)**을 넣습니다.

```text
요청에 "오늘의 브리핑", "오늘 뭐가 화제야", "오늘 <도시> 날씨 어때?"가 있으면
daily-briefing-weather 스킬을 먼저 사용한다.
```

description은 모델이 **스스로 판단**하게 하는 힌트이고, systemPrompt 규칙은 **판단 이전에 거는 명령**입니다. 둘을 함께 쓰면 선택 누락이 크게 줄어듭니다. 다만 스킬이 많아질수록 systemPrompt가 비대해지므로, 꼭 필요한 핵심 스킬에만 씁니다.

## description이 선택을 좌우한다

모델이 스킬을 고르는 과정은 "요청 문장과 각 스킬 설명 사이의 의미적 유사도"를 따지는 일에 가깝습니다. 실제 모델은 의미를 이해하지만, 설명에 **없는 표현**일수록 연결에 실패할 확률이 올라갑니다. 아래 모형은 이 현상을 아주 단순하게(글자 2-gram 겹침 비율로) 흉내 냅니다. 점수가 0.6 이상이면 스킬을 선택합니다.

```python run
# 트리거 매칭 흉내: 메시지 ↔ 스킬의 활성화 문구(글자 2-gram 겹침)
CITIES = ["서울", "부산", "대전", "제주"]
SKILLS = {
    "daily-briefing-weather": ["오늘의 브리핑", "오늘 뭐가 화제야", "<도시> 날씨", "오늘 <도시> 날씨 어때"],
    "mail-summary": ["메일 요약", "받은 편지함 정리", "새 메일 확인"],
}
THRESHOLD = 0.6

def normalize(msg):
    city = next((c for c in CITIES if c in msg), None)
    return (msg.replace(city, "<도시>") if city else msg), city

def grams(s):
    s = s.replace(" ", "")
    return {s[i:i+2] for i in range(len(s) - 1)}

def coverage(trigger, msg):             # 트리거 2-gram 중 메시지에 있는 비율
    t = grams(trigger)
    return len(t & grams(msg)) / len(t)

def route(msg):
    norm, city = normalize(msg)
    best = max(((coverage(tr, norm), name, tr) for name, trs in SKILLS.items() for tr in trs))
    score, name, tr = best
    chosen = name if score >= THRESHOLD else "(스킬 없음 → 일반 대화)"
    return score, chosen, tr, city

tests = ["오늘의 브리핑 부탁해", "서울 날씨 어때?", "오늘 제주 날씨 어때", "새 메일 확인해 줘",
         "요즘 화제인 뉴스 좀", "날씨라는 단어의 어원은?", "Today's briefing"]
for m in tests:
    score, chosen, tr, city = route(m)
    why = f"'{tr}'" if score >= THRESHOLD else "-"
    print(f"{score:.2f} | {chosen} | 근거 {why} | 도시={city} | {m}")
```

```text
1.00 | daily-briefing-weather | 근거 '오늘의 브리핑' | 도시=None | 오늘의 브리핑 부탁해
1.00 | daily-briefing-weather | 근거 '<도시> 날씨' | 도시=서울 | 서울 날씨 어때?
1.00 | daily-briefing-weather | 근거 '오늘 <도시> 날씨 어때' | 도시=제주 | 오늘 제주 날씨 어때
1.00 | mail-summary | 근거 '새 메일 확인' | 도시=None | 새 메일 확인해 줘
0.17 | (스킬 없음 → 일반 대화) | 근거 - | 도시=None | 요즘 화제인 뉴스 좀
0.20 | (스킬 없음 → 일반 대화) | 근거 - | 도시=None | 날씨라는 단어의 어원은?
0.00 | (스킬 없음 → 일반 대화) | 근거 - | 도시=None | Today's briefing
```

결과에서 세 가지를 읽을 수 있습니다. "요즘 화제인 뉴스 좀"은 사용자 의도로는 브리핑인데 **표현이 달라** 놓쳤습니다(미탐, false negative). "날씨라는 단어의 어원은?"은 '날씨'가 들어 있지만 **선택되지 않아야 맞는** 경우입니다(올바른 거부). "Today's briefing"은 영어 문구가 트리거 목록에 없어서 놓쳤습니다. 실제 LLM은 이보다 훨씬 유연하지만, 같은 방향의 실수를 합니다.

좋은 description을 쓰는 요령은 다음과 같습니다.

- **실제 사용자 표현을 그대로** 넣습니다. 설계자가 상상한 문장보다 채팅 기록에서 본 문장이 낫습니다.
- 여러 언어로 부를 가능성이 있으면 **각 언어 표현**을 넣습니다(원본은 영어, 이 강의는 한국어+영어).
- **무엇을 출력하는지**를 함께 적습니다. 모델은 "이 스킬을 쓰면 원하는 답이 나오는가"로도 판단합니다.
- 헷갈리기 쉬운 **비대상**을 적습니다. 예: "단어 뜻·날씨의 과학적 원리 질문에는 쓰지 않는다."
- 다른 스킬과 **겹치는 문구를 피합니다**. `mail-summary`가 "오늘의 요약"을 트리거로 쓰면 브리핑과 충돌합니다.

## 실패를 날조하지 않기

마지막 모형은 스킬 실행 자체입니다. 네트워크 대신 미리 준비한 응답(wttr.in의 `format=j1` JSON을 줄인 모양)을 돌려주는 가짜 `web_fetch`를 쓰고, 응답이 없는 도시와 접속 실패한 뉴스 사이트에서 **`Not available yet`**이 나오는지 확인합니다.

```python run
# 스킬 실행 흉내: web_fetch(가짜 응답) → 고정 형식 조립, 실패 시 "Not available yet"
import json
CANNED = {   # 네트워크 대신 미리 준비한 응답 (wttr.in ?format=j1 모양을 줄인 것)
    "https://wttr.in/Seoul?format=j1": json.dumps({"current_condition": [{
        "weatherDesc": [{"value": "Partly cloudy"}], "temp_C": "24"}],
        "weather": [{"mintempC": "18", "maxtempC": "27",
                     "hourly": [{"chanceofrain": "10"}, {"chanceofrain": "30"}]}]}),
    "https://news.example.kr/": json.dumps([
        {"title": "로봇 전시회 개막", "summary": "서비스 로봇 200여 종이 공개됐다"},
        {"title": "태풍 북상", "summary": "주말 남부 지방에 강한 비가 예상된다"},
        {"title": "반도체 수출 증가", "summary": "전년 대비 12% 늘었다"}]),
}

def web_fetch(url):
    if url not in CANNED:
        raise ConnectionError(f"fetch failed: {url}")
    return CANNED[url]

def get_weather(city):
    if city is None:
        return "No city specified. Weather is not available yet"
    try:
        d = json.loads(web_fetch(f"https://wttr.in/{city}?format=j1"))
        cur, day = d["current_condition"][0], d["weather"][0]
        rain = max(int(h["chanceofrain"]) for h in day["hourly"])
        return (f"{city} {cur['weatherDesc'][0]['value']}, {cur['temp_C']}°C "
                f"({day['mintempC']}~{day['maxtempC']}°C), 강수확률 최대 {rain}%")
    except (ConnectionError, KeyError, ValueError):
        return "Not available yet"          # 지어내지 않는다

def get_topics(url="https://news.example.kr/"):
    try:
        items = json.loads(web_fetch(url))[:6]
        return ", ".join(f"{it['title']}: {it['summary']}" for it in items)
    except ConnectionError:
        return "Not available yet"

def briefing(city, news_url="https://news.example.kr/"):
    return f"Daily briefing: 1. Weather: {get_weather(city)}. Hot topics: {{{get_topics(news_url)}}}"

print(briefing("Seoul"))
print(briefing("Busan"))                        # 날씨 응답 없음
print(briefing(None, "https://down.example/"))  # 도시 미지정 + 뉴스 실패
```

```text
Daily briefing: 1. Weather: Seoul Partly cloudy, 24°C (18~27°C), 강수확률 최대 30%. Hot topics: {로봇 전시회 개막: 서비스 로봇 200여 종이 공개됐다, 태풍 북상: 주말 남부 지방에 강한 비가 예상된다, 반도체 수출 증가: 전년 대비 12% 늘었다}
Daily briefing: 1. Weather: Not available yet. Hot topics: {로봇 전시회 개막: 서비스 로봇 200여 종이 공개됐다, 태풍 북상: 주말 남부 지방에 강한 비가 예상된다, 반도체 수출 증가: 전년 대비 12% 늘었다}
Daily briefing: 1. Weather: No city specified. Weather is not available yet. Hot topics: {Not available yet}
```

파이썬 코드에서는 예외 처리로 날조를 **구조적으로** 막을 수 있지만, LLM 스킬에서는 SKILL.md의 Constraints 문장이 그 역할을 대신합니다. 그래서 실물 시험에서는 **일부러 실패를 만들어** 이 규칙이 지켜지는지 확인해야 합니다(아래 시험 표의 5번).

## 실습 (실물)

:::safety 실습 전 확인
- 이 실습은 로봇을 움직이지 않지만, 에이전트가 **외부 웹사이트에 접속**합니다. 짧은 시간에 같은 요청을 반복해 사이트에 부담을 주지 마세요. 시험은 몇 번으로 충분합니다.
- 뉴스 사이트를 바꿀 때는 그 사이트의 이용 약관과 `robots.txt`를 확인합니다. 가져온 기사 내용은 요약만 쓰고 원문을 재배포하지 않습니다.
- `openclaw.json`을 고치기 전에 백업하고, 설정 파일이나 로그를 공유할 때는 API 키·토큰을 `<GATEWAY_TOKEN>` 같은 자리표시자로 바꿉니다.
:::

### 2) 등록, 재시작, 자가 점검

`openclaw.json`에 `skills` 배열과 도구 권한을 넣었으면 재시작하고, 스킬이 **발견되고 사용 가능한지** 확인합니다.

`skills list`에 `daily-briefing-weather`가 없으면 폴더 위치(워크스페이스의 `skills/` 아래인지)와 머리말 형식(`---`로 시작하고 끝나는지)을 확인합니다. `check`가 문제를 보고하면 메시지대로 고칩니다.

### 3) 트리거 문구로 합동 디버깅

```bash
openclaw agent --agent test --session-id test-002 --message "Today's briefing."
openclaw agent --agent test --session-id test-002 --message "오늘 서울 날씨 어때?"
```

응답이 `Daily briefing: 1. Weather: ... Hot topics: {...}` 구조를 지키는지, 날씨와 뉴스 제목이 **실제 사이트 내용과 맞는지** 브라우저로 직접 대조합니다.

### 4) 시험 표 만들기

스킬 하나를 "된다"고 말하려면 성공 사례 한 번이 아니라 아래 같은 **시험 표**를 통과해야 합니다. 새 세션 id(`test-003`, `test-004`…)로 하나씩 실행하고 결과를 기록하세요.

| # | 입력 | 기대 결과 | 확인할 것 |
|---|---|---|---|
| 1 | `오늘의 브리핑` | 스킬 선택, 뉴스 3~6개 | 도시 없음 → `No city specified…` |
| 2 | `오늘 부산 날씨 어때?` | 부산 날씨 + 뉴스 | `<city>` 추출 |
| 3 | `How is the weather in Seoul today?` | 영어 트리거도 선택 | 다국어 description |
| 4 | `날씨라는 단어의 어원이 뭐야?` | 스킬 **미선택** | 과잉 선택(false positive) 없음 |
| 5 | `오늘 없는도시123 날씨` | Weather: `Not available yet` | 날조 금지 |
| 6 | 권한에서 `web_fetch`를 잠시 뺀 뒤 1번 | `web_search`로 대체 또는 명시적 실패 | 도구 대체 경로 |

6번처럼 **설정을 일부러 망가뜨려 보는 시험**은 운영 중 문제가 생겼을 때 증상을 알아보는 눈을 길러 줍니다. 시험이 끝나면 설정을 원래대로 돌리고 다시 재시작하는 것을 잊지 마세요.

## 문제 해결 가이드

원본 교재가 정리한 네 가지 상황을 증상별로 다시 정리합니다.

1. **스킬이 선택되지 않음** — description에 실제로 쓰는 트리거 문구가 들어 있는지, `test`의 systemPrompt가 이 스킬 이름을 부르는지 확인합니다.
2. **선택은 되는데 가져오지 않음** — `tools.allow`에 `web_fetch`, `web_search`가 있는지 확인합니다. 추적 기록에서 실제 도구 호출이 있었는지도 봅니다.
3. **고쳤는데 반영이 안 됨** — `openclaw.json`을 수정했으면 반드시 `openclaw gateway restart`. 같은 세션 id는 이전 맥락을 끌고 오므로 새 세션 id로 시험합니다.
4. **가져오기 실패를 날조로 덮음** — Execution Steps와 Constraints를 다시 읽고, "실패 시 `Not available yet`" 문장이 모호하지 않은지 확인합니다. 필요하면 Fixed Output Format 규칙에도 같은 문장을 반복합니다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `skills list`에 스킬이 없음 | 폴더 위치가 워크스페이스 `skills/` 밖, 파일명이 `skill.md` | 경로와 대소문자 `SKILL.md` 확인 |
| 목록에는 있는데 `test`가 안 씀 | `skills` 배열 문자열과 `name` 불일치(`_` vs `-`) | 두 문자열을 복사해 붙여 일치시킴 |
| 머리말 파싱 오류 | `---` 누락, 들여쓰기 오류, `version: 1.0.0`을 숫자로 해석 | YAML 형식 확인, 버전은 따옴표 |
| "wttr.in에서 확인하세요"라는 설명만 옴 | `web_fetch`/`web_search` 권한 없음 | `tools.allow`에 추가 후 재시작 |
| 형식이 매번 다름 | Fixed Output Format이 모호, 모델이 인사말 추가 | 템플릿을 백틱으로 감싸고 "인사말 없이" 명시 |
| 없는 뉴스·날씨가 나옴 | 제약 문구 약함, 실패 경로 미시험 | Constraints 강화, 시험 표 5번 반복 |
| 영어 요청에만 반응 | description에 한국어 트리거 없음 | 실제 사용 언어 표현 추가 |
