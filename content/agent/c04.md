## 학습 목표

- 에이전트의 **워크스페이스(workspace)**와 **에이전트 전용 디렉터리(agentDir)**가 각각 무엇을 담는지 구분하고 직접 만듭니다.
- AGENTS.md·SOUL.md·USER.md·IDENTITY.md·TOOLS.md 규약 파일의 역할을 설명하고 최소 템플릿을 작성합니다.
- `openclaw.json`의 `agents.list`에 에이전트를 등록하고 `tools.allow`/`tools.deny`로 **최소 권한**을 설계합니다.
- 작업 분해 → 단계별 보고(Step/Status/Output/Next) → 최종 정리로 이어지는 실행형 에이전트의 동작을 CLI로 검증합니다.
- Gateway 상태 → 전경 실행 → doctor → 실행 추적 순서로 문제를 좁혀 갑니다.

## 채팅봇이 아니라 실행형 에이전트

C02에서 모델(Model)은 두뇌, 도구(Tool)는 손, 에이전트(Agent)는 일을 끝까지 끌고 가는 관리자라고 정리했습니다. 이 장에서는 그 관리자를 하나 직접 만듭니다. 이름은 원본 교재를 따라 **`test`**이고, 성격은 "말 잘하는 비서"가 아니라 **실행형 멀티모달 비서(execution-oriented multimodal assistant)**입니다. 파일을 쓰고, 스크립트를 돌리고, 웹 페이지를 읽고, 카메라로 사진을 찍은 뒤, 무엇을 했는지 **추적 가능한 형태로 보고**하는 것이 목표입니다.

`test`의 행동은 서로 비교적 독립된 일곱 모듈로 나누어 보면 이해하기 쉽습니다.

| # | 모듈 | 하는 일 | 필요한 도구(tools.allow) |
|---|---|---|---|
| 1 | 작업 분해 (task breakdown) | 큰 목표를 3~7단계로 나누고 단계별 도구를 표시 | — (프롬프트 규칙) |
| 2 | 파일 관리 (file management) | 읽기·생성·수정·보관, 경로를 반드시 남김 | `read`, `write`, `edit`, `apply_patch` |
| 3 | 카메라 촬영 (camera capture) | 별칭으로 카메라를 골라 촬영, 저장 경로 보고 | `image`, `nodes` (환경에 따라) |
| 4 | 브라우저 제어 (browser control) | 페이지 열기·내용 가져오기, 최종 URL 기록 | `browser`, `web_fetch`, `web_search` |
| 5 | 스크립트 실행 (script execution) | 정해진 디렉터리에서 실행, 로그·산출물 경로 보고 | `exec`, `process` |
| 6 | 능동 피드백 (proactive feedback) | 단계가 끝날 때마다 즉시 진행 상황 보고 | — (프롬프트 규칙) |
| 7 | 정보 정리 (consolidation) | 끝나면 요약·산출물·로그·미해결을 한 번에 정리 | — (프롬프트 규칙) |

표를 보면 에이전트의 능력은 두 층으로 이루어져 있습니다. **무엇을 할 수 있는가**는 `openclaw.json`의 도구 권한이 정하고, **어떻게 행동하는가**는 워크스페이스의 규약 파일과 systemPrompt가 정합니다. 둘 중 하나만 맞아서는 원하는 동작이 나오지 않습니다. 규칙에 "사진을 찍어라"라고 써도 `image` 권한이 없으면 찍을 수 없고, 권한이 있어도 규칙이 없으면 어디에 저장했는지 말해 주지 않습니다.

## 두 개의 폴더: workspace와 agentDir

@fig[c04-layout] agents.list의 한 항목이 두 폴더를 가리킵니다. workspace는 모델이 읽는 행동 규약과 작업 공간, agentDir는 에이전트 전용 설정과 실행 추적이 쌓이는 곳입니다.

| 경로 | 이름 | 담는 것 | 누가 주로 쓰나 |
|---|---|---|---|
| `~/.openclaw/workspace/test` | **workspace** | 규약 파일(AGENTS.md 등), `skills/`, `memory/`, 작업 산출물(`tmp/`) | 사람이 규칙을 쓰고, 에이전트가 결과를 씀 |
| `~/.openclaw/agents/test/agent` | **agentDir** | 에이전트 전용 설정·인증 정보, 세션·실행 추적 기록 | OpenClaw가 관리, 사람은 주로 읽기만 |

원본 교재는 사용자 이름이 `ubuntu`인 환경이라 `openclaw.json`에 `/home/ubuntu/.openclaw/...` 같은 **절대 경로**를 적습니다. 여러분의 사용자 이름이 다르면 `/home/<사용자>/...`로 바꿔야 합니다. `echo $HOME`으로 확인하세요.

:::tip 왜 폴더를 둘로 나누나요?
워크스페이스는 에이전트가 **읽고 쓰는 작업장**이고, agentDir는 **에이전트를 운영하는 기록실**입니다. 작업장에 인증 정보나 추적 기록이 섞여 있으면, 파일 쓰기 권한을 가진 에이전트가 실수로(또는 악의적인 지시에 속아) 자기 설정을 고칠 수 있습니다. 경계를 나누어 두면 "워크스페이스 밖은 쓰지 않는다"는 한 줄 규칙으로 많은 사고를 막을 수 있습니다.
:::

## 워크스페이스 규약 파일

OpenClaw는 세션을 시작할 때 워크스페이스의 약속된 이름의 Markdown 파일을 읽어 모델의 맥락(context)에 넣습니다. 즉 이 파일들은 **사람이 쓰는 시스템 프롬프트의 조각**입니다. 파일마다 맡는 역할이 정해져 있습니다.

| 파일 | 역할 | 들어갈 내용 예 |
|---|---|---|
| **AGENTS.md** | 작업 방식(운영 매뉴얼) | 세션 시작 절차, 작업 분해 규칙, 보고 형식, 정리 형식 |
| **SOUL.md** | 성격과 경계 | "채팅봇이 아니라 실행자", 모르면 묻기, 비밀 노출 금지 |
| **USER.md** | 사용자 기본값 | 시간대, 작업 범위, 카메라 별칭, 출력 디렉터리 |
| **IDENTITY.md** | 이름·정체성 표시 | 이름, 성격 한 줄, 분위기 |
| **TOOLS.md** | 도구 사용 메모(권장) | 카메라 별칭, 브라우저 기록 규칙, 스크립트 디렉터리 |

아래는 원본 템플릿을 한국 환경에 맞게 다시 쓴 **최소 동작 버전**입니다. 처음에는 짧게 시작하고, 실제로 부족한 점이 보일 때 한 줄씩 늘리는 편이 좋습니다. 규칙이 길어질수록 모델이 일부를 무시할 확률도 커지기 때문입니다.

```markdown
# AGENTS.md — test 실행형 에이전트 작업 방식

## Session Start
1. SOUL.md, USER.md, IDENTITY.md, TOOLS.md를 읽는다.
2. memory/ 아래 오늘·어제 노트가 있으면 읽는다.

## Task Breakdown
- 복잡한 작업은 실행 전에 3~7단계로 분해한다.
- 각 단계에 목적, 예상 산출물, 사용할 도구를 적는다.
- 파일 쓰기·스크립트 실행·장치 조작이 있으면 위험과 확인 사항을 먼저 적는다.

## Proactive Feedback
- 단계가 끝날 때마다 즉시 Step / Status / Output / Next를 보고한다.

## Information Consolidation
- 마지막에 요약, 산출물 목록, 핵심 로그 요약, 미해결 항목을 출력한다.
```

```markdown
# SOUL.md
나는 채팅봇이 아니라 실행형 에이전트다.
- 실행 전에 작업을 분해한다.
- 확실하지 않으면 묻는다.
- 개인정보나 키를 노출하지 않는다.
- 파괴적인 작업(삭제·덮어쓰기·장치 이동)은 확인을 받은 뒤 한다.
```

```markdown
# USER.md
- Timezone: Asia/Seoul
- 작업 범위(기본 쓰기 위치): workspace/test
- 카메라 별칭: default
- 스크립트 기본 실행 디렉터리: workspace/test
- 스크립트 출력 디렉터리: workspace/test/tmp
```

```markdown
# IDENTITY.md
- Name: test 실행형 멀티모달 비서
- Creature: 실무형 실행 에이전트
- Vibe: 구조적이고, 감사(audit) 가능하며, 계획 중심
```

```markdown
# TOOLS.md
## Cameras
- default: 시스템 기본 카메라
## Browser
- 최종 URL과 페이지 핵심 요점을 기록한다.
## Script Execution
- 기본 작업 디렉터리: workspace/test
- 출력 디렉터리: workspace/test/tmp
- 파괴적인 명령은 실행 전에 확인받는다.
```

규약 파일이 어떻게 하나의 프롬프트로 합쳐지는지 파이썬으로 흉내 내 봅시다. 실제 OpenClaw는 Node.js로 만들어져 브라우저에서 돌릴 수 없으므로, 아래 코드는 **개념 모형**입니다. 일부러 TOOLS.md를 빠뜨려 누락 검사가 어떻게 보이는지도 확인합니다.

```python run
# 워크스페이스 규약 파일(가상) → 시스템 프롬프트 조립
workspace = {
    "AGENTS.md": "# AGENTS.md\n## Session Start\n1. SOUL/USER/IDENTITY/TOOLS를 읽는다.\n"
                 "## Task Breakdown\n- 복잡한 작업은 3~7단계로 먼저 분해한다.\n"
                 "## Proactive Feedback\n- 단계마다 Step/Status/Output/Next를 보고한다.\n",
    "SOUL.md": "# SOUL.md\n실행형 에이전트다. 모르면 묻고, 파괴적 작업은 확인받는다.\n",
    "USER.md": "# USER.md\n- Timezone: Asia/Seoul\n- 출력 디렉터리: workspace/test/tmp\n",
    "IDENTITY.md": "# IDENTITY.md\n- Name: test 실행형 멀티모달 비서\n",
    # TOOLS.md는 일부러 빠뜨려 본다
}
ORDER = ["AGENTS.md", "SOUL.md", "USER.md", "IDENTITY.md", "TOOLS.md"]
REQUIRED = {"AGENTS.md", "SOUL.md", "USER.md", "IDENTITY.md"}

def headings(text):
    return [ln.lstrip("# ").strip() for ln in text.splitlines() if ln.startswith("## ")]

def assemble(base_rules, files):
    parts, report = [base_rules], []
    for name in ORDER:
        if name not in files:
            level = "누락(필수)" if name in REQUIRED else "누락(권장)"
            report.append(f"{name:12s} {level}")
            continue
        body = files[name].strip()
        parts.append(f"<file name='{name}'>\n{body}\n</file>")
        hs = ", ".join(headings(body)) or "-"
        report.append(f"{name:12s} {len(body):3d}자  섹션: {hs}")
    return "\n\n".join(parts), report

base = "You are agent 'test'. Follow the workspace files below."
prompt, report = assemble(base, workspace)
for r in report:
    print(r)
print("조립된 프롬프트 길이:", len(prompt), "자")
print("USER.md 반영 여부:", "Asia/Seoul" in prompt)
```

```text
AGENTS.md    166자  섹션: Session Start, Task Breakdown, Proactive Feedback
SOUL.md       43자  섹션: -
USER.md       62자  섹션: -
IDENTITY.md   38자  섹션: -
TOOLS.md     누락(권장)
조립된 프롬프트 길이: 498 자
USER.md 반영 여부: True
```

핵심은 **규약 파일의 내용이 곧 모델이 보는 글자**라는 점입니다. 파일을 고쳤는데 행동이 바뀌지 않는다면, 먼저 그 글자가 실제로 프롬프트에 들어갔는지(경로가 맞는지, 새 세션인지)를 의심해야 합니다. 또 파일이 길어지면 매 요청마다 토큰 비용이 늘어나므로 규약은 짧고 구체적으로 씁니다.

## openclaw.json에 등록하기

규약 파일만으로는 에이전트가 존재하지 않습니다. `~/.openclaw/openclaw.json`의 `agents.list`에 항목을 추가해야 Gateway가 `test`라는 에이전트를 알게 됩니다. 원본 교재의 항목은 다음과 같습니다(경로의 `ubuntu`는 여러분의 사용자 이름으로 바꿉니다).

```json
{
  "id": "test",
  "name": "test (execution-oriented multimodal assistant)",
  "workspace": "/home/ubuntu/.openclaw/workspace/test",
  "agentDir": "/home/ubuntu/.openclaw/agents/test/agent",
  "model": "deepseek/deepseek-reasoner",
  "identity": {
    "name": "test (execution-oriented multimodal assistant)"
  },
  "tools": {
    "allow": [
      "read", "write", "edit", "apply_patch",
      "exec", "process",
      "browser", "web_search", "web_fetch",
      "memory_search", "memory_get",
      "session_status", "sessions_list", "sessions_history",
      "message", "nodes", "image"
    ],
    "deny": [
      "sessions_spawn", "subagents", "canvas", "cron", "gateway"
    ]
  }
}
```

| 필드 | 의미 | 주의 |
|---|---|---|
| `id` | CLI·라우팅에서 쓰는 식별자 (`--agent test`) | 영문 소문자, 다른 에이전트와 겹치지 않게 |
| `name`, `identity.name` | 사람이 보는 표시 이름 | 자유롭게 |
| `workspace`, `agentDir` | 위에서 만든 두 폴더의 절대 경로 | `~`보다 절대 경로가 안전 |
| `model` | 이 에이전트만 쓸 모델 (`provider/model`) | 생략하면 `agents.defaults.model` 사용. 원본은 추론형 `deepseek-reasoner` |
| `tools.allow` / `tools.deny` | 호출 가능한/금지된 도구 목록 | 아래 절에서 자세히 |

같은 파일의 `agents.defaults`에는 기본 모델(`deepseek/deepseek-chat`)과 기본 워크스페이스가, `list`의 첫 항목에는 기본 에이전트 `main`이 이미 있을 것입니다. `test`는 그 **뒤에 한 항목을 추가**하는 것이지, 파일 전체를 교재 예시로 덮어쓰는 것이 아닙니다.

:::danger openclaw.json을 통째로 복사하거나 공유하지 마세요
`openclaw.json`에는 모델 API 키 프로필, 채널 앱 비밀값(appSecret, 봇 토큰), **Gateway 인증 토큰**(`gateway.auth.token`)이 함께 들어 있습니다. 교재·블로그의 예시 파일을 그대로 붙여 넣으면 남의 비밀값이 섞이거나, 반대로 여러분의 파일을 질문 게시판에 올리면서 비밀값이 새어 나갑니다. 공유할 때는 `<GATEWAY_TOKEN>`, `<TELEGRAM_BOT_TOKEN>`처럼 반드시 자리표시자로 바꿉니다.
:::

### systemPrompt: 실행 규칙

원본 교재는 `test`의 **systemPrompt**에 다음 네 가지 요구를 넣습니다. AGENTS.md와 내용이 겹치는데, 이것은 의도된 이중화입니다. systemPrompt는 모든 요청에 강하게 걸리는 규칙이고, AGENTS.md는 사람이 고치기 쉬운 세부 매뉴얼입니다.

1. 복잡한 목표는 먼저 **3~7단계 작업 분해**를 출력하고, 단계마다 필요한 도구를 표시한다.
2. 실행 중에는 **단계가 끝날 때마다 즉시** 상태, 산출물(경로·스크린샷·URL·핵심 로그), 다음 단계 또는 확인 질문을 보고한다.
3. 끝나면 **정보를 정리**한다: 요약, 산출물 목록, 핵심 로그 요약, 미해결 항목과 다음 단계.
4. **안전 우선**: 매개변수가 불분명하거나 큰 손실이 날 수 있는 작업은 확인을 받고, 개인정보나 키를 노출하지 않는다.

:::info 버전 차이
원본은 OpenClaw 2026.3.24 기준입니다. systemPrompt를 에이전트 항목의 어느 키에 두는지, `tools.profile`과 allow/deny가 어떻게 합쳐지는지는 버전마다 달라질 수 있습니다. 설정을 바꾼 뒤에는 `openclaw doctor`로 알 수 없는 키 경고가 없는지 확인하고, 경고가 나면 같은 규칙을 AGENTS.md에 두는 쪽으로 대체합니다.
:::

## 도구 권한: 최소 권한의 원칙

`test`의 권한 전략은 한 문장으로 요약됩니다. **작업 실행과 산출물 생성은 허용하되, 시스템 수준의 고위험 능력은 막는다.**

| 구분 | 도구 | 이유 |
|---|---|---|
| 허용 — 파일 | `read`, `write`, `edit`, `apply_patch` | 산출물을 만들고 고쳐야 함 |
| 허용 — 실행 | `exec`, `process` | 스크립트 실행, 프로세스 관리 |
| 허용 — 웹 | `browser`, `web_search`, `web_fetch` | 페이지 읽기·검색 |
| 허용 — 기억·세션 | `memory_search`, `memory_get`, `session_status`, `sessions_list`, `sessions_history` | 맥락 참조(읽기 위주) |
| 허용 — 기타 | `message`, `nodes`, `image` | 메시지 전송, 연결된 장치, 이미지(카메라) |
| **거부** | `sessions_spawn`, `subagents` | 에이전트가 **다른 에이전트를 낳아** 일을 넘기면 권한·비용·추적이 흐려짐 |
| **거부** | `cron` | 사람이 보지 않는 시간에 **스스로 예약 실행** — 실수가 반복·누적됨 |
| **거부** | `gateway` | Gateway 설정 변경·재시작 = 에이전트가 **자기 권한을 스스로 넓힐 수 있음** |
| **거부** | `canvas` | 이 장의 과제에 필요 없는 UI 기능 |

**최소 권한의 원칙(principle of least privilege)**은 "일을 하는 데 꼭 필요한 권한만 준다"는 보안의 기본 원칙입니다. LLM 에이전트에서는 특히 중요합니다. 모델은 확률적으로 동작하고, 웹 페이지나 메일에 숨겨진 문장에 속을 수 있습니다(프롬프트 인젝션, prompt injection). 속았을 때 **할 수 있는 일의 최대치**를 줄여 두는 것이 권한 설계입니다. `cron`과 `gateway`를 막는 이유가 바로 이것입니다. 한 번의 잘못된 판단이 "매일 반복"되거나 "권한 확장"으로 번지는 길을 원천적으로 끊습니다.

allow와 deny가 함께 있을 때는 흔히 다음 규칙으로 판정합니다: **deny가 우선**하고, allow 목록이 있으면 **목록에 없는 도구는 거부**합니다. 아래 모형으로 확인해 봅시다.

```python run
# tools.allow / tools.deny 판정 (원본 test 에이전트 목록 그대로)
ALLOW = ["read", "write", "edit", "apply_patch", "exec", "process", "browser",
         "web_search", "web_fetch", "memory_search", "memory_get", "session_status",
         "sessions_list", "sessions_history", "message", "nodes", "image"]
DENY = ["sessions_spawn", "subagents", "canvas", "cron", "gateway"]

def decide(tool, allow=ALLOW, deny=DENY):
    if tool in deny:
        return "거부", "deny 목록 — deny가 allow보다 우선"
    if allow and tool not in allow:
        return "거부", "allow 목록에 없음 — 기본 거부"
    return "허용", "allow 목록"

requests = ["write", "exec", "image", "cron", "gateway", "subagents", "tts"]
for t in requests:
    verdict, why = decide(t)
    print(f"{t:10s} → {verdict}  ({why})")

# 같은 도구가 양쪽에 있으면? deny가 이긴다
print("\n충돌 예:", decide("exec", allow=ALLOW, deny=DENY + ["exec"]))

# 최소 권한 점검: 과제에 필요한 도구만 남기면 몇 개가 줄어드는가
need = {"read", "write", "exec", "web_fetch"}
extra = sorted(set(ALLOW) - need)
print(f"\n과제 필요 {len(need)}개 / 허용 {len(ALLOW)}개 → 여분 {len(extra)}개")
print("여분 예:", ", ".join(extra[:6]), "...")
```

```text
write      → 허용  (allow 목록)
exec       → 허용  (allow 목록)
image      → 허용  (allow 목록)
cron       → 거부  (deny 목록 — deny가 allow보다 우선)
gateway    → 거부  (deny 목록 — deny가 allow보다 우선)
subagents  → 거부  (deny 목록 — deny가 allow보다 우선)
tts        → 거부  (allow 목록에 없음 — 기본 거부)

충돌 예: ('거부', 'deny 목록 — deny가 allow보다 우선')

과제 필요 4개 / 허용 17개 → 여분 13개
여분 예: apply_patch, browser, edit, image, memory_get, memory_search ...
```

마지막 두 줄이 주는 교훈이 중요합니다. 교재의 `test`는 여러 능력을 시연하려고 17개를 열어 두었지만, 실제 업무용 에이전트라면 **그 업무에 필요한 도구만** 남기는 편이 안전합니다. 5장의 브리핑 스킬 예시에서도 원본은 파일 쓰기(`write`, `edit`)를 뺀 축소 목록을 함께 보여 줍니다.

:::warning 권한을 바꾸면 반드시 재시작
`tools.allow`/`deny`를 포함해 `openclaw.json`을 고친 뒤에는 `openclaw gateway restart`를 실행해야 반영됩니다. "권한을 줬는데 여전히 못 한다"는 문의의 상당수가 재시작 누락입니다.
:::

## 일곱 모듈 자세히 보기

@fig[c04-feedback] 실행형 에이전트의 한 사이클. 분해한 Step마다 실행과 즉시 보고가 반복되고, 마지막에 추적 가능한 정리 보고서가 나옵니다.

### 1) 작업 분해

여러 능력이 섞인 목표나 큰 작업이면 실행 전에 **Step 목록**이 먼저 나와야 합니다. 각 Step에는 목적·예상 산출물·도구 종류(파일/카메라/브라우저/스크립트)가 붙고, 파일 쓰기·스크립트·장치 조작이 있으면 **위험과 확인 사항**을 먼저 나열한 뒤 매개변수가 분명해져야 실행합니다. 분해가 나타나지 않으면 대개 요청의 매개변수가 부족했거나, systemPrompt와 AGENTS.md의 Task Breakdown 규칙이 로드되지 않은 것입니다.

### 2) 파일 관리 (읽기·생성·수정·보관)

| 동작 | 도구 | 규칙 |
|---|---|---|
| 읽기 | `read` | 먼저 읽고 판단한다 |
| 생성·수정 | `write`, `edit`, `apply_patch` | 워크스페이스 안에만, 결과 경로를 남긴다 |
| 보관(archive) | — | 핵심 결과와 **경로**를 정리 보고서의 산출물 목록에 쓴다 |

에이전트에게 파일 작업을 맡길 때는 최소한 ① 대상의 상대 경로(예: `workspace/test/tmp/notes.txt`), ② 내용 요구(형식·필드·개수), ③ 기대 산출물을 분명히 적어 줍니다.

### 3) 카메라 촬영

USER.md의 카메라 별칭(`default` = 시스템 기본 카메라)을 먼저 확인하고, 촬영 대상·각도·연속 촬영 여부가 빠졌으면 묻습니다. 촬영 뒤에는 이미지 경로나 링크를 정리 보고서에 남기고, 실패하면 이유와 다음 행동(별칭 변경, 재시도, 수동 촬영 후 업로드)을 제시합니다. 카메라 기능이 `image` 도구로 제공되는 환경이라면 `tools.allow`에 `image`가 있어야 합니다.

### 4) 브라우저 제어

페이지를 열거나 이동하면 **최종 URL**을 기록하고, 내용이 필요하면 `web_fetch`나 브라우저 도구로 가져와 요점만 정리합니다. 페이지 원문을 길게 옮기지 않는 것은 가독성뿐 아니라 **민감한 내용 노출을 줄이기 위해서**이기도 합니다.

### 5) 스크립트 실행

기본 실행 위치는 `workspace/test`, 산출물은 `workspace/test/tmp`에 먼저 씁니다. 실행 전에는 명령(또는 스크립트 요약)과 예상 출력 경로를 다시 말하고, 실행 뒤에는 `stdout`·`stderr`의 핵심 줄과 출력 경로를 정리합니다. 이 "실행 전 복창"은 사람이 끼어들 수 있는 마지막 기회이므로 로봇 제어로 가면 더욱 중요해집니다.

### 6) 능동 피드백과 7) 정보 정리

단계마다 **Step / Status / Output / Next** 네 줄을 보고하면, 어디서 막혔는지가 대화 기록만 보고도 드러납니다. 모든 단계가 끝나면 정리 보고서에 ① 3~6줄 요약, ② 능력별 산출물 목록(파일·이미지·웹 요점·스크립트 결과), ③ 산출물과 관련된 핵심 로그만, ④ 미해결 항목과 다음 단계를 담습니다. **합격 기준**은 "보고서만 보고 결과물을 찾아갈 수 있는가"입니다. 경로·URL·스크린샷 같은 추적 가능한 정보가 없으면 불합격입니다.

아래 모형은 이 사이클 전체를 흉내 냅니다. 도구는 `read`/`write`/`exec`만 허용하고, 파일 쓰기는 메모리 속 딕셔너리에 하되 **워크스페이스 밖 경로는 거부**합니다. 4단계는 경로 탈출(`../../`)을, 5단계는 권한 없는 `cron`을 일부러 시도합니다.

```python run
# 실행형 에이전트 모의: 단계 계획 → 단계별 보고 → 최종 정리
import posixpath
WS = "workspace/test"
ALLOW = {"read", "write", "exec"}
fs, log = {}, []                       # 메모리 속 파일 시스템, 핵심 로그

def safe_path(p):
    full = posixpath.normpath(posixpath.join(WS, p))
    if not full.startswith(WS + "/"):
        raise PermissionError(f"워크스페이스 밖 경로 거부: {full}")
    return full

def tool(name, **kw):
    if name not in ALLOW:
        raise PermissionError(f"도구 '{name}' 권한 없음")
    if name == "write":
        path = safe_path(kw["path"]); fs[path] = kw["text"]; return path
    if name == "exec":                  # 스크립트 실행 흉내: 7일치 CSV 생성
        rows = ["day,tempC"] + [f"D-{6-i},{18+i}" for i in range(7)]
        log.append(f"stdout: {len(rows)-1} rows"); return "\n".join(rows)

plan = [("할 일 목록 작성", "write", {"path": "tmp/notes.txt", "text": "2026-09-26 09:00\n1. 배터리 확인\n2. 지도 백업\n3. 로그 정리"}),
        ("CSV 생성 스크립트 실행", "exec", {}),
        ("CSV 저장", "write", {"path": "tmp/small_report.csv"}),
        ("시스템 설정 백업", "write", {"path": "../../.bashrc", "text": "x"}),
        ("매일 자동 실행 예약", "cron", {})]
print("[계획]", " / ".join(f"{i+1}.{p[0]}({p[1]})" for i, p in enumerate(plan)))
outputs, unresolved, last = [], [], None
for i, (title, name, kw) in enumerate(plan, 1):
    if name == "write" and "text" not in kw:
        kw = dict(kw, text=last)        # 이전 단계 결과를 이어받음
    try:
        last = tool(name, **kw); status = "완료"
        out = last if name == "write" else last.splitlines()[1]
        if name == "write": outputs.append(last)
    except PermissionError as e:
        status, out = "실패", str(e); unresolved.append(f"Step {i}: {e}")
    nxt = plan[i][0] if i < len(plan) else "최종 정리"
    print(f"Step {i} | Status: {status} | Output: {out} | Next: {nxt}")

print("\n[최종 정리]")
print(f"요약: {len(plan)}단계 중 {len(plan)-len(unresolved)}단계 완료")
print("산출물:", ", ".join(outputs))
print("핵심 로그:", "; ".join(log))
print("미해결:")
for u in unresolved:
    print("  -", u)
```

```text
[계획] 1.할 일 목록 작성(write) / 2.CSV 생성 스크립트 실행(exec) / 3.CSV 저장(write) / 4.시스템 설정 백업(write) / 5.매일 자동 실행 예약(cron)
Step 1 | Status: 완료 | Output: workspace/test/tmp/notes.txt | Next: CSV 생성 스크립트 실행
Step 2 | Status: 완료 | Output: D-6,18 | Next: CSV 저장
Step 3 | Status: 완료 | Output: workspace/test/tmp/small_report.csv | Next: 시스템 설정 백업
Step 4 | Status: 실패 | Output: 워크스페이스 밖 경로 거부: .bashrc | Next: 매일 자동 실행 예약
Step 5 | Status: 실패 | Output: 도구 'cron' 권한 없음 | Next: 최종 정리

[최종 정리]
요약: 5단계 중 3단계 완료
산출물: workspace/test/tmp/notes.txt, workspace/test/tmp/small_report.csv
핵심 로그: stdout: 7 rows
미해결:
  - Step 4: 워크스페이스 밖 경로 거부: .bashrc
  - Step 5: 도구 'cron' 권한 없음
```

`safe_path()`가 `normpath`로 `..`를 먼저 풀어낸 뒤 접두사를 검사한다는 점에 주목하세요. 문자열에 `workspace/test`가 들어 있는지만 보면 `workspace/test/../../.bashrc` 같은 경로 탈출(path traversal)을 놓칩니다. 실패한 단계도 숨기지 않고 **미해결 항목**으로 보고서에 남는 것이 실행형 에이전트다운 행동입니다.

```bash
# 브라우저(웹) 요약

# 카메라(권한과 장치가 있을 때만)
openclaw agent --agent test --session-id test-001 --message "카메라로 책상 사진을 찍고 저장 경로를 알려 줘."
```

:::check 합격 기준
- 복잡한 요청에서 **Step 목록**이 먼저 나온다.
- 단계마다 Step/Status/Output/Next가 보고된다.
- 정리 보고서에 **실제로 존재하는 경로**가 있고, `ls ~/.openclaw/workspace/test/tmp`로 확인된다.
- 워크스페이스 밖에 쓰라는 요청에는 확인을 구하거나 거절한다.
:::

## 로그 분석과 문제 해결 순서

분해가 안 나온다, 경로가 비어 있다, 파일이 없다, 정리가 불완전하다, 실행이 실패한다 — 어떤 증상이든 아래 순서로 좁혀 갑니다. 바깥(프로세스)에서 안쪽(모델의 판단)으로 들어가는 순서입니다.

```bash
openclaw gateway status          # 1. Gateway가 살아 있는가
openclaw gateway run --verbose   # 2. 전경 실행으로 자세한 오류 보기 (Ctrl+C로 종료)
openclaw doctor                  # 3. 설정 전반 진단
ls ~/.openclaw/agents/test/agent # 4. 실행 추적 확인 — 가장 중요
```

4단계의 agentDir(또는 버전에 따라 그 옆의 세션 디렉터리)에 있는 세션 기록·`*.json` 추적 파일에는 **어떤 도구를 어떤 인자로 언제 불렀는지**가 시간순으로 남습니다. 여기서 "Step이 실행되지 않은 이유(매개변수 부족, 안전 확인 대기)"나 "출력 경로가 빈 이유(쓰기 권한, 경로 불일치)"를 찾을 수 있습니다. 모델의 말(보고서)과 실제 도구 호출(추적)을 **대조**하는 습관이 에이전트 디버깅의 핵심입니다. 보고서에는 "저장했습니다"라고 쓰여 있는데 추적에 `write` 호출이 없다면, 그것은 모델이 결과를 지어낸 것입니다.

## 로봇 에이전트로 가는 길

이 장의 `test`는 C08에서 만들 MentorPi 제어 에이전트의 연습판입니다. 대응 관계를 미리 보아 두면 설계 의도가 분명해집니다.

| 이 장 (test) | C08 로봇 에이전트 |
|---|---|
| `exec`로 스크립트 실행 | ROS 2 브리지 스크립트만 실행(허용 명령 목록) |
| 워크스페이스 밖 쓰기 거부 | 속도·거리 상한 밖 명령 거부 (선속도 ≤ 0.2 m/s) |
| 파괴적 작업 전 확인 | 이동 명령 전 확인 게이트, 비상 정지 우선 |
| `cron`·`gateway`·`subagents` 거부 | 무인 반복 주행·권한 확장 원천 차단 |
| Step/Status/Output/Next | "이동 0.3 m / 완료 / 오도메트리 값 / 다음: 사진" |

행동 규약(무엇을 어떻게)과 권한(무엇을 할 수 있나)을 분리하고, 권한은 좁게, 보고는 추적 가능하게 — 이 세 원칙은 대상이 파일이든 로봇이든 같습니다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `openclaw agent --agent test` 가 "unknown agent" | `agents.list`에 항목이 없거나 JSON 문법 오류, 재시작 누락 | 쉼표·괄호 확인, `openclaw doctor`, `openclaw gateway restart`, `openclaw agents list --json` |
| 규약 파일을 고쳤는데 행동이 그대로 | `workspace` 경로가 다른 폴더를 가리킴, 같은 세션 재사용 | 경로를 절대 경로로 확인, `--session-id`를 새 값으로 |
| 작업 분해 없이 바로 실행 | 요청이 단순하거나 매개변수 부족, 규칙 미로드 | 요청에 경로·형식을 명시, systemPrompt와 AGENTS.md의 Task Breakdown 확인 |
| "파일을 만들었다"는데 파일이 없음 | `write` 권한 없음 또는 모델의 날조 | `tools.allow`에 `write` 확인, 추적 파일에서 실제 `write` 호출 여부 대조 |
| 스크립트가 엉뚱한 폴더에서 실행 | USER.md·TOOLS.md에 기본 디렉터리 미기재 | 기본 작업·출력 디렉터리를 두 파일에 명시 |
| 권한을 추가했는데도 도구를 못 씀 | Gateway 재시작 누락, deny 목록에 같은 이름 존재 | `openclaw gateway restart`, deny 우선 규칙 확인 |
| 카메라 촬영 실패 | 장치 없음, 별칭 불일치, `image` 권한 없음 | `ls /dev/video*`, USER.md 별칭 확인, allow 목록 확인 |

## 과제

:::task 과제
1. **(기본)** 규약 파일 조립 모형에서 TOOLS.md를 추가하고, AGENTS.md에 `## Safety` 섹션(삭제 명령 금지)을 넣은 뒤 출력이 어떻게 바뀌는지 확인하세요.
2. **(기본)** "매일 아침 사진 한 장 찍어 요약하기" 업무만 하는 에이전트를 가정해 `tools.allow`/`deny`를 최소 권한으로 설계하고, 각 도구를 넣거나 뺀 이유를 한 줄씩 쓰세요.
3. **(심화)** 실행형 모의 코드에 "확인 게이트"를 추가하세요. 도구가 `write`이고 이미 존재하는 파일을 덮어쓰는 경우 Status를 `확인 필요`로 두고 실행을 멈춘 뒤, 정리 보고서의 미해결 항목에 남기도록 합니다.
4. **(심화)** 실물에서 CSV 과제를 실행한 뒤 agentDir의 추적 기록에서 도구 호출 순서를 찾아, 에이전트의 Step 보고와 1:1로 대조한 표를 만드세요.
:::
