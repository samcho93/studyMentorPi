## 학습 목표

- SLAM(Simultaneous Localization and Mapping)이 왜 "닭이 먼저냐 달걀이 먼저냐" 문제인지 설명하고, 전처리 → 매칭 → 지도 융합 흐름을 말할 수 있습니다.
- 점유 격자(occupancy grid)의 **로그 오즈(log-odds) 갱신식**을 유도하고, 라이다 한 빔으로 셀을 갱신하는 코드를 작성합니다.
- 스캔 매칭(scan matching), 포즈 그래프(pose graph), 루프 클로저(loop closure)의 역할을 설명하고 `slam.yaml`의 해당 파라미터와 연결합니다.
- MentorPi에서 `slam.launch.py`로 지도를 만들고 `map_saver_cli`로 저장한 뒤, 지도 품질을 기준에 따라 판정합니다.

## SLAM 문제

내비게이션을 하려면 **지도**가 있어야 하고, 지도에서 **내 위치**를 알아야 합니다. 그런데

- 지도를 그리려면 스캔을 찍은 순간의 로봇 위치를 정확히 알아야 하고,
- 위치를 정확히 알려면 비교할 지도가 있어야 합니다.

바퀴 오도메트리(M03)만 믿고 스캔을 겹치면 어떻게 될까요? 오도메트리는 미끄러짐·바퀴 지름 오차 때문에 **이동할수록 오차가 쌓입니다**(드리프트). 한 바퀴 돌아 출발점에 왔을 때 복도 끝이 두 겹으로 그려집니다. SLAM은 위치와 지도를 **동시에** 추정해 이 오차를 잡습니다. 확률로 쓰면 다음 분포를 구하는 문제입니다.

$p(x₁…ₜ, m | z₁…ₜ, u₁…ₜ)$  — 명령 u와 관측 z가 주어졌을 때 궤적 x와 지도 m의 결합 분포

교재는 과정을 세 단계로 요약합니다. 이 장은 각 단계에서 **실제로 무슨 계산을 하는지** 보강합니다.

| 단계 | 교재 설명 | 실제 계산 (slam_toolbox 기준) |
|---|---|---|
| ① 전처리 | 라이다 점구름의 이상치 제거·필터링 | 최소/최대 거리 자르기, 스캔 버퍼링, 움직였을 때만 처리 |
| ② 매칭 | 현재 스캔을 기존 지도에 맞춰 위치 찾기 | **상관 스캔 매칭**(correlative scan matching)으로 자세 보정 |
| ③ 지도 융합 | 새 스캔을 지도에 합침 | 포즈 그래프에 노드·제약 추가, **루프 클로저** 후 최적화, 점유 격자 다시 그리기 |

## 점유 격자와 로그 오즈

### 격자 지도

2D SLAM의 결과물은 **점유 격자 지도**(occupancy grid map)입니다. 공간을 해상도 `resolution`(MentorPi는 0.05 m)의 정사각형 셀로 나누고, 셀마다 "장애물이 있을 확률" $p(mᵢ)$를 저장합니다. ROS의 `nav_msgs/OccupancyGrid`는 이 값을 0~100(%)과 −1(모름)로 담고, 파일로 저장하면 PGM 영상 + YAML이 됩니다.

### 빔 하나가 알려 주는 것

라이다 빔 하나가 거리 r에서 반사됐다면,

- 로봇에서 r 직전까지 빔이 **지나간 셀은 비어 있을** 가능성이 높고,
- r 지점의 셀은 **점유**됐을 가능성이 높고,
- r 너머는 **아무 정보가 없습니다**(가려짐).

지나간 셀을 찾는 데는 원본 AMCL 레슨에도 나오는 **Bresenham 직선 알고리즘**이 쓰입니다(정수 덧셈만으로 선 위 셀을 나열). 아래 실습 코드는 더 단순하게 빔을 따라 반 셀 간격으로 표본을 찍습니다.

@fig[m09-raycast] 라이다 빔 한 개로 셀을 갱신하는 역센서 모델: 빔이 지나간 셀은 l_free(음수), 끝 셀은 l_occ(양수)를 더하고, 너머는 그대로 둡니다.

### 로그 오즈 갱신식 유도

셀 하나에 대해 관측 $z₁…ₜ$가 주어졌을 때의 점유 확률을 베이즈 규칙으로 갱신하면(셀들이 독립이고, 관측이 서로 조건부 독립이라 가정),

$p(m | z₁…ₜ) = p(m | zₜ) · p(zₜ) · p(m | z₁…ₜ₋₁) / ( p(m) · p(zₜ | z₁…ₜ₋₁) )$

같은 식을 "비어 있음(¬m)"에 대해서도 쓰고 둘을 나누면 번거로운 정규화 항이 사라집니다.

$p(m|z₁…ₜ) / p(¬m|z₁…ₜ) = [p(m|zₜ) / p(¬m|zₜ)] · [p(m|z₁…ₜ₋₁) / p(¬m|z₁…ₜ₋₁)] · [p(¬m) / p(m)]$

양변에 로그를 취하고 **로그 오즈** $l = log(p / (1 − p))$로 쓰면 곱이 덧셈이 됩니다.

$lₜ = lₜ₋₁ + log( p(m|zₜ) / (1 − p(m|zₜ)) ) − l₀$

| 항 | 뜻 | 값 예 |
|---|---|---|
| $lₜ₋₁$ | 지금까지의 믿음 | 처음엔 0 (p = 0.5, 모름) |
| $log(p(m\|zₜ)/(1−p(m\|zₜ)))$ | **역센서 모델**(inverse sensor model): 이번 빔이 이 셀에 대해 주는 증거 | 끝 셀 p = 0.7 → +0.85, 지나간 셀 p = 0.4 → −0.41 |
| $l₀$ | 사전 확률의 로그 오즈 | p(m) = 0.5면 0 |

장점은 세 가지입니다. ① 갱신이 **덧셈 한 번**이라 빠르고, ② 0과 1 근처에서 확률이 수치적으로 뭉개지지 않으며, ③ 상한·하한(예: ±5)으로 잘라 두면 한번 벽이던 곳도 여러 번 비어 보이면 다시 빈 곳으로 돌아옵니다(움직이는 사람 지우기). 확률로 돌릴 때는 $p = 1 − 1/(1 + e^l)$입니다.

### 지도 파일의 문턱값

`map_saver_cli`가 저장한 MentorPi의 `slam/maps/map_01.yaml`입니다.

```yaml
image: map_01.pgm
mode: trinary
resolution: 0.05
origin: [-7.18, -7.41, 0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.25
```

| 키 | 뜻 |
|---|---|
| `mode: trinary` | 셀을 점유(검정, 0)·빈 곳(흰색, 254)·모름(회색, 205) 세 값으로 저장 |
| `resolution` | 픽셀 하나 = 0.05 m. 원본 지도 `map_01.pgm`은 411 × 315 픽셀 → 약 20.6 m × 15.8 m |
| `origin` | 영상 **왼쪽 아래** 픽셀의 map 좌표 (x, y, yaw) |
| `occupied_thresh` / `free_thresh` | 확률 > 0.65면 점유, < 0.25면 빈 곳, 그 사이는 모름 |

### 실습: Playground에서 점유 격자 만들기

가상 MentorPi를 제자리에서 한 바퀴 돌리며 `/scan`과 실제 자세 `/ground_truth`로 로그 오즈 격자를 만듭니다. **위치를 정확히 안다고 가정**한 "지도 작성(mapping only)"이라서 SLAM의 절반만 푸는 셈입니다. 실물에는 `/ground_truth`가 없으므로, 이 자리를 SLAM이 추정한 자세가 채웁니다.

@btn[~/tools/playground.html] Playground 열기

```python run
import numpy as np
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from sensor_msgs.msg import LaserScan
import mentorpi_sim as sim                                     # 시뮬 전용
sim.setup(world="empty", duration=17.0, start=(0.0, 0.0, 0.0))  # 시뮬 전용
sim.add_box(1.5, 0.5, 0.6, 0.6); sim.add_cylinder(-1.0, -1.2, 0.25)  # 시뮬 전용
RES, SIZE = 0.1, 70                     # 0.1 m 셀, 7 m x 7 m, 원점 = 격자 중앙
L_OCC, L_FREE, L_MAX = 0.85, -0.4, 5.0  # 로그 오즈 증분과 포화값

class GridMapper(Node):
    def __init__(self):
        super().__init__('grid_mapper')
        self.L = np.zeros((SIZE, SIZE))   # L[ix, iy], 0 = 모름(p = 0.5)
        self.pose, self.scans = None, 0
        self.create_subscription(Pose2D, '/ground_truth', self.on_pose, 10)   # 시뮬 전용
        self.create_subscription(LaserScan, '/scan', self.on_scan, 10)
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_timer(0.1, self.turn)
    def on_pose(self, msg):
        self.pose = (msg.x, msg.y, msg.theta)
    def turn(self):
        t = Twist(); t.angular.z = 0.4; self.pub.publish(t)
    def on_scan(self, msg):
        if self.pose is None: return
        px, py, th = self.pose
        r = np.array(msg.ranges)
        a = msg.angle_min + np.arange(len(r)) * msg.angle_increment + th
        hit = np.isfinite(r)
        r = np.where(hit, r, 4.0)                           # 반사 없음: 4 m까지만 비움
        s = np.arange(0.0, 12.0, RES / 2)                   # 빔 위 표본 거리
        m = s[None, :] < (r[:, None] - RES / 2)
        fx = (px + s[None, :] * np.cos(a)[:, None])[m]
        fy = (py + s[None, :] * np.sin(a)[:, None])[m]
        free = set(zip((fx // RES).astype(int), (fy // RES).astype(int)))
        ox = ((px + r[hit] * np.cos(a[hit])) // RES).astype(int)
        oy = ((py + r[hit] * np.sin(a[hit])) // RES).astype(int)
        free -= set(zip(ox, oy))
        fi, fj = np.array(list(free)).T + SIZE // 2
        self.L[fi, fj] += L_FREE                            # 빔이 지나간 셀: 비어 있음 쪽으로
        self.L[ox + SIZE // 2, oy + SIZE // 2] += L_OCC     # 빔 끝 셀: 점유 쪽으로
        np.clip(self.L, -L_MAX, L_MAX, out=self.L)
        self.scans += 1

rclpy.init()
node = GridMapper()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    P = 1.0 - 1.0 / (1.0 + np.exp(node.L))                  # 로그 오즈 -> 확률
    print("scans:", node.scans, " occupied:", (P > 0.65).sum(), " free:", (P < 0.25).sum(),
          " unknown:", ((P >= 0.25) & (P <= 0.65)).sum())
    for row in P.T[::-5, ::5]:                              # 위쪽 = +y, 한 글자 = 0.5 m
        print("".join("#" if p > 0.65 else "." if p < 0.25 else "?" for p in row))
    node.destroy_node()
    rclpy.shutdown()
```

## 스캔 매칭

오도메트리가 "대략 여기쯤"이라고 알려 주면, 스캔 매칭은 그 **주변을 뒤져서** 현재 스캔이 지도(또는 최근 스캔들)와 가장 잘 겹치는 자세를 찾습니다.

$x* = argmax_x Σᵢ M( T(x) · pᵢ )$  — 스캔 점 pᵢ를 자세 x로 옮겼을 때 지도 M에서 "점유" 값의 합(응답, response)이 가장 큰 x

slam_toolbox는 Karto SLAM의 **상관 스캔 매처**(correlative scan matcher)를 씁니다. 가능한 (x, y, θ)를 격자처럼 **전부 시험**하되, 거친 탐색 → 세밀 탐색 두 단계로 나눠 계산을 줄입니다. `slam.yaml`의 파라미터가 곧 탐색 범위입니다.

| 파라미터 | MentorPi 값 | 뜻 |
|---|---|---|
| `correlation_search_space_dimension` | 0.5 | 위치 탐색 창 한 변 [m] (오도메트리 예측 ±0.25 m) |
| `correlation_search_space_resolution` | 0.01 | 위치 탐색 간격 [m] |
| `correlation_search_space_smear_deviation` | 0.1 | 지도 점을 번지게(smear) 하는 폭 — 응답 곡면을 부드럽게 |
| `coarse_search_angle_offset` | 0.349 | 거친 각도 탐색 범위 ±0.349 rad (±20°) |
| `coarse_angle_resolution` | 0.0349 | 거친 각도 간격 (2°) |
| `fine_search_angle_offset` | 0.00349 | 세밀 각도 탐색 범위 (0.2°) |
| `distance_variance_penalty` / `angle_variance_penalty` | 0.5 / 1.0 | 오도메트리 예측에서 멀어질수록 점수 깎기 |
| `minimum_distance_penalty` / `minimum_angle_penalty` | 0.5 / 0.9 | 깎는 양의 하한 |
| `link_match_minimum_response_fine` | 0.1 | 이 응답 미만이면 매칭 실패로 보고 연결 안 함 |
| `use_response_expansion` | true | 응답이 낮으면 탐색 창을 넓혀 재시도 |

탐색 창이 ±0.25 m, ±20°라는 뜻은 **스캔 사이에 오도메트리가 이보다 크게 틀리면 매칭이 실패**한다는 뜻입니다. 로봇을 빨리 돌리거나(특히 회전), 바퀴가 헛돌면 지도가 찢어지는 이유입니다. 교재가 "천천히 움직일수록 좋은 지도"라고 하는 근거가 이 숫자들입니다.

## 포즈 그래프와 루프 클로저

@fig[m09-posegraph] 포즈 그래프: 노드는 스캔을 찍은 자세, 실선은 연속 스캔 매칭 제약, 점선은 루프 클로저 제약. 최적화가 누적 오차를 고리 전체로 나눠 줍니다.

slam_toolbox는 모든 스캔을 지도에 바로 태우지 않습니다. 로봇이 `minimum_travel_distance`(0.1 m) 또는 `minimum_travel_heading`(0.5 rad)보다 많이 움직였을 때만 **노드**(자세 + 그때의 스캔)를 만들고, 노드 사이에 **제약**(edge, "노드 i에서 본 노드 j는 여기")을 답니다.

- **연속 제약**: 새 노드를 최근 노드들(`scan_buffer_size` 20개, `link_scan_maximum_distance` 1.5 m 이내)과 스캔 매칭해 얻습니다.
- **루프 클로저 제약**: 새 노드 근처(`loop_search_maximum_distance` 3.0 m)에 **오래전에 지나간 노드**가 있으면, 넓은 창(`loop_search_space_dimension` 8.0 m, 해상도 0.05 m)으로 매칭을 시도합니다. 연속 체인 `loop_match_minimum_chain_size` 10개 이상이 거친 응답 0.35, 세밀 응답 0.45를 넘고 분산이 3.0 이하면 "같은 곳에 돌아왔다"고 인정합니다.

루프가 닫히면 최적화기가 모든 노드 자세 $x$를 동시에 고쳐 제약 오차의 제곱합을 최소화합니다.

$x* = argmin_x Σ_(i,j) eᵢⱼ(x)ᵀ Ωᵢⱼ eᵢⱼ(x)$   ( $eᵢⱼ$ = 제약이 말하는 상대 자세와 현재 추정의 차이, $Ωᵢⱼ$ = 그 제약의 신뢰도(정보 행렬) )

MentorPi는 `solver_plugin: solver_plugins::CeresSolver`, `ceres_linear_solver: SPARSE_NORMAL_CHOLESKY`, `ceres_trust_strategy: LEVENBERG_MARQUARDT`로 이 비선형 최소제곱 문제를 풉니다. 결과로 지도 전체가 "탁" 하고 펴지는 순간이 RViz에서 보입니다.

:::warning 잘못된 루프 클로저는 지도를 망친다
비슷하게 생긴 두 복도를 같은 곳으로 착각하면 최적화가 지도를 접어 버립니다. 그래서 루프 판정 문턱(0.35/0.45, 체인 10개)이 연속 매칭 문턱(0.1)보다 훨씬 엄격합니다. 반복 구조가 많은 곳에서는 문턱을 높이거나 `do_loop_closing`을 잠시 끄고 비교해 봅니다.
:::

## MentorPi의 SLAM 구성

### launch 구조

`ros2 launch slam slam.launch.py`는 다음을 순서대로 띄웁니다(원본 `slam/launch/slam.launch.py`).

| 단계 | 포함 파일 | 내용 |
|---|---|---|
| base_launch | `slam/launch/include/robot.launch.py` | `controller.launch.py`(모터·오도메트리·IMU·**EKF**), `lidar.launch.py`(LD19 → `/scan_raw`, 프레임 `lidar_frame`), `depth_camera.launch.py`, 조이스틱 |
| 10 s 후 slam_launch | `slam/launch/include/slam_base.launch.py` | `slam_toolbox` 패키지의 **`sync_slam_toolbox_node`** (이름 `slam_toolbox`), 파라미터 `config/slam.yaml` |

`sync`(동기) 모드는 들어온 스캔을 **빠짐없이 순서대로** 처리합니다. 처리 시간이 밀리면 지연이 쌓이지만 지도 품질은 좋습니다. 비동기(`async_slam_toolbox_node`)는 늦으면 스캔을 건너뜁니다. 오도메트리 `odom → base_footprint`는 `robot_localization` EKF가 바퀴 오도메트리(`odom_raw`), 라이다 오도메트리(`odom_rf2o`), IMU를 융합해 발행하고, slam_toolbox는 그 위에 `map → odom`을 발행합니다.

### slam.yaml 주요 파라미터

| 파라미터 | 값 | 뜻 |
|---|---|---|
| `mode` | `mapping` | `localization`으로 바꾸면 저장된 지도에서 위치추정만 |
| `odom_frame` / `map_frame` / `base_frame` | `odom` / `map` / `base_footprint` | TF 프레임 (M08) |
| `scan_topic` | `scan_raw` | 라이다 토픽 (필터 전 원본) |
| `resolution` | 0.05 | 지도 셀 크기 [m] |
| `max_laser_range` | 12.0 | 지도에 그릴 최대 거리 [m] (LD19 사양) |
| `minimum_time_interval` | 0.5 | 노드 사이 최소 시간 [s] |
| `minimum_travel_distance` / `minimum_travel_heading` | 0.1 / 0.5 | 새 노드를 만드는 최소 이동 [m] / 회전 [rad] |
| `map_update_interval` | 0.2 | `/map` 격자 재생성 주기 [s] |
| `transform_publish_period` | 0.02 | `map → odom` TF 발행 주기 [s] (50 Hz) |
| `throttle_scans` | 1 | 스캔을 몇 개마다 하나씩 쓸지 (1 = 전부) |
| `use_scan_matching` / `use_scan_barycenter` | true / true | 스캔 매칭 사용, 스캔 무게중심으로 거리 계산 |
| `do_loop_closing` | true | 루프 클로저 사용 |
| `stack_size_to_use` | 40000000 | 큰 지도 직렬화용 스택 크기 |
| `enable_interactive_mode` | true | RViz 플러그인에서 노드를 끌어 수동 보정 |

## 실습 (시뮬레이션)

@btn[~/sim/index.html] 2D 시뮬레이터 열기

1. 월드를 **room** 또는 **maze**로, 섀시를 메카넘으로 고릅니다. **라이다 표시**를 켭니다.
2. **SLAM** 모드를 켜고 키보드(또는 가상 조이스틱)로 천천히 방을 한 바퀴 돕니다. 회색(모름) 격자가 흰색(빈 곳)·검은색(점유)으로 바뀌는 과정을 관찰합니다.
3. **오도메트리 오차 표시**를 켜고 같은 경로를 빠르게 돌아 봅니다. 추정 경로와 실제 경로가 벌어질 때 지도가 어떻게 번지는지 비교합니다.
4. 제자리에서 빠르게 회전(0.5 rad/s 이상)한 경우와 천천히 회전한 경우의 지도 선명도를 비교하고, 위 스캔 매칭 탐색 창(±20°)과 연결해 설명합니다.

## 실습 (실물)

:::safety
- 지도 작성 중에는 로봇이 계속 움직입니다. **사람이 로봇 옆을 따라다니며** 계단·책상 다리·전선 쪽으로 가지 않게 지킵니다.
- 키보드 조종 속도는 원본 `teleop_key_control.py` 기준 0.2 m/s, 0.5 rad/s입니다. 속도를 올리지 않습니다(빠를수록 지도도 나빠집니다).
- 멈출 때는 키보드 노드 터미널에서 정지 키를 누르거나 Ctrl+C. 로봇이 계속 움직이면 `ros2 topic pub --once /controller/cmd_vel geometry_msgs/msg/Twist "{}"`, 최후에는 전원 스위치.
- 지도에 **나중에 치울 물건**(가방, 사람)이 찍히지 않게 주변을 정리합니다.
:::

### 1) 가상머신 준비 (처음 한 번)

교재 방식은 로봇에서 SLAM을 돌리고 **같은 LAN의 PC 가상머신**에서 RViz로 봅니다. 먼저 로봇의 패키지를 가상머신으로 옮깁니다.

```bash
# 로봇 (컨테이너 터미널)
~/.stop_ros.sh
cd ros2_ws/src/
zip -r src.zip navigation slam simulations
mv src.zip /home/ubuntu/shared
cd .. && cp .typerc /home/ubuntu/shared      # 로봇 종류 환경 파일
```

WinSCP로 로봇(`192.168.149.1`, 교재의 기본 계정)에 접속해 `docker/tmp`의 `src.zip`과 숨김 파일 `.typerc`를 PC로 내려받고, 가상머신 홈으로 끌어다 놓습니다.

```bash
# 가상머신 (HiWonder_ros2_humble 이미지)
mkdir -p ros2_ws/src
unzip src.zip
mv simulations slam navigation /home/ubuntu/ros2_ws/src/
mv .typerc ros2_ws/
cd ros2_ws/ && colcon build
gedit ~/.bashrc      # 아래 두 줄 추가
#   source /home/ubuntu/ros2_ws/.typerc
#   source /home/ubuntu/ros2_ws/install/setup.bash
source ~/.bashrc
```

로봇을 **LAN 모드**로 바꿔(`vim hiwonder-toolbox/wifi_conf.py`에서 모드·SSID·비밀번호 수정 후 `sudo systemctl restart wifi.service` 또는 재부팅) 가상머신과 같은 공유기에 붙이고, 두 쪽의 `ROS_DOMAIN_ID`가 같은지(기본 0) 확인합니다. 가상머신 네트워크는 **브리지** 모드여야 합니다.

### 2) 지도 작성

```bash
# 로봇 터미널 1
~/.stop_ros.sh
ros2 launch slam slam.launch.py

# 가상머신 터미널
ros2 launch slam rviz_slam.launch.py

# 로봇 터미널 2
ros2 launch peripherals teleop_key_control.launch.py
```

| 키 | 동작 |
|---|---|
| W | 짧게 누르면 전진 상태로 전환 (계속 전진) |
| S | 짧게 누르면 후진 상태로 전환 |
| A | 길게 누르면 전·후진을 끊고 좌회전 |
| D | 길게 누르면 전·후진을 끊고 우회전 |

지도 작성 요령(교재 주의사항 + 이 장의 원리):

1. 긴 **직선 벽 앞**이나 막힌 공간에서 시작합니다. 첫 스캔에 점이 많아야 첫 노드가 튼튼합니다.
2. 제자리에서 **천천히 360°** 돌아 주변을 한 번 훑습니다.
3. 넓은 공간은 먼저 **큰 고리(loop)를 한 바퀴** 돌아 루프 클로저를 일으킨 뒤, 작은 구석을 채웁니다.
4. 같은 곳을 다시 지날 때 RViz에서 지도가 살짝 "펴지는" 순간이 루프 클로저입니다.

### 3) 지도 저장

```bash
cd ~/ros2_ws/src/slam/maps && ros2 run nav2_map_server map_saver_cli -f "map_01" --ros-args -p map_subscribe_transient_local:=true
ls ~/ros2_ws/src/slam/maps        # map_01.pgm, map_01.yaml
```

원본 `slam/slam/map_save.py`도 `/slam_toolbox/save_map` 서비스 요청을 받으면 같은 명령을 실행합니다. 지도 이름을 바꾸면(`map_02`) M11의 내비게이션 명령에서도 `map:=map_02`로 바꿉니다. 끝나면 모든 터미널에서 Ctrl+C 후, 호스트 터미널에서 `sudo systemctl restart start_node.service`로 앱 서비스를 되돌립니다.

### 4) 지도 품질 판정

| 기준 | 확인 방법 |
|---|---|
| 장애물 가장자리가 선명한가 | 벽이 한 줄(1~2셀)인지, 두 겹·번짐이 없는지 |
| 실제 환경과 어긋남이 없는가 | 복도가 휘거나 고리가 닫히지 않은 곳이 없는지 |
| 로봇이 다닐 영역에 회색이 없는가 | 모름(205) 영역이 통로에 남으면 내비게이션이 경로를 못 냄 |
| 나중에 없어질 물체가 찍히지 않았는가 | 사람·가방이 벽처럼 남으면 AMCL 위치추정을 방해 |
| 로봇이 다닐 전체 범위를 덮는가 | 목표를 찍을 곳이 모두 흰색인지 |

:::info 지도 품질 올리기
SLAM은 오도메트리를 초기값으로 씁니다. IMU 보정과 선속도·각속도 보정(M03, 교재 *9. Motion Control Lesson — Lesson 3*)을 하면 스캔 매칭 탐색 창 안에 들어오는 비율이 올라가 지도가 좋아집니다.
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| RViz에 지도가 안 뜸, "No map received" | slam_toolbox가 10 s 지연 후 시작, 도메인 ID·네트워크 불일치 | 10 s 이상 기다림, `ros2 topic list`에 `/map`이 보이는지 가상머신에서 확인, `ROS_DOMAIN_ID`·LAN 확인 |
| "Message Filter dropping message: frame 'lidar_frame'" | TF(`odom → base_footprint` 또는 URDF) 없음, 시계 차이 | `controller.launch.py`가 떠 있는지, 로봇과 PC 시간 동기 확인 |
| 회전할 때 지도가 찢어지거나 겹침 | 스캔 사이 회전이 탐색 창(±20°)을 넘음, 바퀴 미끄러짐 | 회전을 천천히, 바닥 미끄럼 확인, IMU 보정 |
| 한 바퀴 돌았는데 고리가 안 닫힘 | 루프 후보가 3 m 밖, 응답 문턱 미달 | 같은 경로를 더 가깝게 다시 지나기, 특징 많은 곳에서 고리 만들기 |
| 지도가 갑자기 크게 접힘 | 잘못된 루프 클로저 | 처음부터 다시, 반복 구조 구역은 천천히, 필요하면 `loop_match_minimum_response_fine` 상향 |
| `map_saver_cli` 시간 초과 | `/map`을 transient local로 못 받음 | 교재 명령의 `-p map_subscribe_transient_local:=true`를 빠뜨리지 않음 |
| 저장한 지도 위치가 엉뚱함 | 다른 폴더에서 저장 | `cd ~/ros2_ws/src/slam/maps`에서 실행 (내비게이션이 이 폴더를 읽음) |

## 과제

:::task 기본 과제
1. Playground 코드에서 `L_OCC`, `L_FREE`를 (0.85, −0.4), (0.4, −0.4), (0.85, −1.5) 세 가지로 바꿔 점유·빈 곳·모름 셀 수를 표로 정리하고 차이를 설명합니다.
2. `map_01.yaml`의 `origin`과 `resolution`으로, PGM 영상의 픽셀 (행 100, 열 200)이 map 좌표로 어디인지 계산합니다. (힌트: PGM은 위에서부터 행을 세고, origin은 왼쪽 아래)
:::

:::task 심화 과제
3. Playground 코드의 `/ground_truth`를 `/odom`으로 바꾸고(쿼터니언 → yaw는 `tf_transformations.euler_from_quaternion`), 로봇을 1 m 전진 → 180° 회전 → 1 m 전진시키며 지도를 만들어 벽 번짐을 관찰합니다. 번짐 폭과 오도메트리 오차를 비교합니다.
4. 두 스캔(1차 자세에서 찍은 스캔과 0.1 m 옮겨 찍은 스캔)의 점들을 numpy로 만들고, (dx, dy)를 ±0.2 m 범위 0.01 m 간격으로 전부 시도해 겹치는 점 수가 최대인 이동을 찾는 **초간단 상관 스캔 매처**를 작성합니다.
:::
