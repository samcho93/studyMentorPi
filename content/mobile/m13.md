## 학습 목표

- Nav2의 세 가지 목표 액션(`navigate_to_pose`, `navigate_through_poses`, `follow_waypoints`)의 차이를 설명하고, RViz의 단일·다중 목표 도구를 사용합니다.
- `waypoint_follower`의 파라미터(`stop_on_failure`, `wait_at_waypoint`)와 목표 판정(`xy_goal_tolerance`) 값을 해석합니다.
- 주행 중 새 장애물이 나타났을 때 지역 코스트맵 → 컨트롤러 → 행동 트리 재계획·복구가 어떤 순서로 반응하는지 설명합니다.
- Python(Nav2 Simple Commander)으로 여러 목표를 보내는 스크립트를 작성하고, Playground에서 오도메트리 기반 경유점 추종기를 구현합니다.
- RTAB-Map 3D 내비게이션(`rtabmap_navigation.launch.py`)이 2D 내비게이션과 어떻게 다른지(위치추정 주체, 지도 형식) 설명합니다.

## 목표를 주는 세 가지 방법

Nav2는 목표를 **액션**(action, R07)으로 받습니다. 액션은 오래 걸리는 작업에 맞게 목표 → 진행 피드백 → 결과를 주고받고, 도중에 취소할 수 있습니다.

| 액션 서버 | 타입 | 목표 | 동작 | RViz |
|---|---|---|---|---|
| `/navigate_to_pose` | `nav2_msgs/action/NavigateToPose` | 자세 1개 | 전역 계획 → 추종 → 필요 시 복구 | **Nav2 Goal** (교재 "2D Nav Goal") |
| `/navigate_through_poses` | `nav2_msgs/action/NavigateThroughPoses` | 자세 여러 개 | **한 번에** 모든 점을 지나는 경로를 계획해 멈추지 않고 통과. 각 점의 방향도 고려 | 웨이포인트 모드 → **Start Nav Through Poses** |
| `/follow_waypoints` | `nav2_msgs/action/FollowWaypoints` | 자세 여러 개 | 점마다 `navigate_to_pose`를 **차례로** 호출. 도착하면 작업(대기 등) 수행 | 웨이포인트 모드 → **Start Waypoint Following** |

@fig[m13-actions] 두 가지 다중 목표 방식: navigate_through_poses는 경로 하나로 부드럽게 통과하고, follow_waypoints는 점마다 도착·정지·대기한 뒤 다음 점으로 갑니다.

교재는 두 버튼의 차이를 "Nav Through Poses는 각 점에서 로봇의 **자세(방향)** 를 제어하고, Waypoint Following은 신경 쓰지 않는다"고 설명합니다. 구현 관점에서 더 큰 차이는 **멈추느냐**입니다.

- `navigate_through_poses`: BT가 남은 점들을 지나는 경로를 계획하고, 지나간 점은 `nav2_remove_passed_goals_action_bt_node`로 지웁니다. 중간에 멈추지 않으므로 순찰·배달 경로에 적합합니다.
- `follow_waypoints`: 점마다 완전한 내비게이션 한 번입니다. 각 점에서 목표 판정(`xy_goal_tolerance` 0.25 m, `yaw_goal_tolerance` 0.25 rad)을 통과해야 다음으로 넘어가고, 도착 후 **작업 플러그인**을 실행할 수 있습니다.

### waypoint_follower 설정 (MentorPi 값)

| 파라미터 | 값 | 뜻 |
|---|---|---|
| `loop_rate` | 20 | 진행 확인 주기 [Hz] |
| `stop_on_failure` | false | 한 점에서 실패해도 **다음 점으로 계속** (결과에 실패한 점 번호가 남음) |
| `waypoint_task_executor_plugin` | `wait_at_waypoint` | 도착 후 할 일 |
| `wait_at_waypoint.plugin` | `nav2_waypoint_follower::WaitAtWaypoint` | 정해진 시간 대기 |
| `wait_at_waypoint.waypoint_pause_duration` | 200 | 대기 시간 [**ms**] — 0.2 s |

사진 찍기처럼 도착 후 할 일을 바꾸려면 `nav2_waypoint_follower::PhotoAtWaypoint` 플러그인을 쓰거나 직접 플러그인을 만듭니다. `stop_on_failure: false` 덕분에 막힌 점 하나 때문에 순찰 전체가 멈추지는 않습니다.

## 주행 중 장애물 회피의 흐름

교재 L4는 "장애물을 만나면 돌아가며 자세와 경로를 계속 조정한다"고만 설명합니다. 내부에서는 층마다 반응 속도가 다릅니다.

| 단계 | 누가 | 주기 | 하는 일 |
|---|---|---|---|
| ① 감지 | 지역 코스트맵 `voxel_layer` | 5 Hz | `/scan_raw` 끝점을 표시(marking, `obstacle_max_range` 2.5 m), 빔 경로를 비움(clearing, `raytrace_max_range` 3.0 m) |
| ② 회피 | Controller Server (DWB) | 10 Hz | 새 장애물 셀을 지나는 궤적을 `BaseObstacle`이 폐기 → 옆으로 비켜 가는 궤적 선택 |
| ③ 재계획 | BT Navigator + Planner | 기본 BT에서 약 1 Hz | 전역 코스트맵(`obstacle_layer`)에 장애물이 반영되면 새 전역 경로 |
| ④ 복구 | Behavior Server | 진행 실패 시 | `progress_checker`(10 s 동안 0.5 m 미만 이동) 또는 유효 궤적 없음 → 코스트맵 지우기 → spin → backup/wait |

그래서 사람이 **잠깐** 앞을 지나가면 ②에서 비켜 가고, 상자로 통로를 **막으면** ③에서 다른 길을 찾고, 길이 아예 없으면 ④의 회전·후진을 반복하다 실패를 보고합니다. 사람이 지나간 뒤 자리가 비면 clearing이 셀을 지워 다시 지나갈 수 있게 됩니다.

:::warning 라이다 높이 밑의 장애물
코스트맵 입력은 `/scan_raw` 하나입니다(깊이 카메라 점구름은 넣지 않음). 라이다 스캔 평면(바닥에서 약 0.16 m, M08)보다 낮은 물체 — 신발, 낮은 상자, 로봇 청소기 — 는 보이지 않아 그대로 들이받습니다. 순찰 경로는 이런 물체가 없는 곳으로 정합니다.
:::

## Python으로 목표 보내기 (Nav2 Simple Commander)

RViz 클릭 대신 코드로 목표를 보내면 순찰·배달을 자동화할 수 있습니다. Nav2의 `nav2_simple_commander` 패키지는 액션 클라이언트를 감싼 `BasicNavigator` 클래스를 제공합니다. MentorPi 원본 소스에는 이 예제가 없으므로, 로봇 컨테이너에 패키지가 설치돼 있는지 먼저 확인합니다(`ros2 pkg list | grep simple_commander`, 없으면 `sudo apt install ros-humble-nav2-simple-commander`).

```python robot
#!/usr/bin/env python3
# patrol.py — navigation.launch.py 실행 + 초기 위치 지정 후 실행
import rclpy
from geometry_msgs.msg import PoseStamped
from nav2_simple_commander.robot_navigator import BasicNavigator, TaskResult
from tf_transformations import quaternion_from_euler

def make_pose(nav, x, y, yaw):
    p = PoseStamped()
    p.header.frame_id = 'map'
    p.header.stamp = nav.get_clock().now().to_msg()
    p.pose.position.x, p.pose.position.y = x, y
    q = quaternion_from_euler(0.0, 0.0, yaw)
    p.pose.orientation.x, p.pose.orientation.y, p.pose.orientation.z, p.pose.orientation.w = q
    return p

def main():
    rclpy.init()
    nav = BasicNavigator()
    nav.waitUntilNav2Active()                     # amcl·bt_navigator가 active 될 때까지 대기
    points = [(1.0, 0.0, 0.0), (1.0, 1.0, 1.57), (0.0, 1.0, 3.14), (0.0, 0.0, 0.0)]
    goals = [make_pose(nav, *p) for p in points]
    nav.followWaypoints(goals)                    # 또는 nav.goThroughPoses(goals)
    try:
        while not nav.isTaskComplete():
            fb = nav.getFeedback()
            if fb:
                print('waypoint %d/%d' % (fb.current_waypoint + 1, len(goals)))
            rclpy.spin_once(nav, timeout_sec=1.0)
    except KeyboardInterrupt:
        nav.cancelTask()                          # Ctrl+C면 목표 취소 → 로봇 정지
    result = nav.getResult()
    print('result:', {TaskResult.SUCCEEDED: 'succeeded', TaskResult.CANCELED: 'canceled',
                      TaskResult.FAILED: 'failed'}.get(result, result))
    nav.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

- 좌표는 **map 프레임**입니다. RViz의 **Publish Point** 도구로 지도 위를 클릭하면 `/clicked_point`에 좌표가 찍히므로(`ros2 topic echo /clicked_point`), 이것으로 순찰 점을 모읍니다.
- `followWaypoints` 피드백의 `current_waypoint`로 진행 상황을, 결과의 `missed_waypoints`로 실패한 점을 알 수 있습니다.
- `goToPose(pose)`는 단일 목표, `goThroughPoses(poses)`는 멈추지 않는 통과입니다.

CLI로도 같은 액션을 보낼 수 있습니다.

```bash
ros2 action send_goal /follow_waypoints nav2_msgs/action/FollowWaypoints \
  "{poses: [{header: {frame_id: map}, pose: {position: {x: 1.0, y: 0.0}, orientation: {w: 1.0}}},
            {header: {frame_id: map}, pose: {position: {x: 0.0, y: 0.0}, orientation: {w: 1.0}}}]}" --feedback
```

## 실습: Playground 경유점 추종기

Playground에는 Nav2가 없으므로, `follow_waypoints`의 핵심 — "현재 점에 도착(허용오차 안)하면 다음 점으로" — 을 오도메트리로 직접 구현합니다. 메카넘 섀시는 옆으로도 움직일 수 있으므로 방향은 0 rad로 유지한 채 x·y 속도로 바로 이동합니다(횡이동을 쓰지 않는 DWB 설정과 다른 점). 속도는 안전 상한이 걸린 `/cmd_vel`로 보냅니다.

@btn[~/tools/playground.html] Playground 열기

```python run
import math
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from nav_msgs.msg import Odometry
from tf_transformations import euler_from_quaternion
import mentorpi_sim as sim                                       # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=30.0, start=(0.0, 0.0, 0.0))  # 시뮬 전용

WAYPOINTS = [(1.0, 0.0), (1.0, 1.0), (0.0, 1.0), (0.0, 0.0)]    # odom 좌표 [m]
KP, V_MAX, TOL = 1.2, 0.2, 0.05                                  # P 이득, 속도 상한, 도착 허용오차

class WaypointFollower(Node):
    def __init__(self):
        super().__init__('waypoint_follower_demo')
        self.pose, self.truth, self.idx, self.t0 = None, None, 0, None
        self.create_subscription(Odometry, '/odom', self.on_odom, 10)
        self.create_subscription(Pose2D, '/ground_truth', self.on_truth, 10)   # 시뮬 전용
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_timer(0.05, self.control)
    def on_odom(self, m):
        q = m.pose.pose.orientation
        yaw = euler_from_quaternion([q.x, q.y, q.z, q.w])[2]
        self.pose = (m.pose.pose.position.x, m.pose.pose.position.y, yaw)
    def on_truth(self, m):
        self.truth = (m.x, m.y)
    def control(self):
        if self.pose is None:
            return
        now = self.get_clock().now().nanoseconds * 1e-9
        self.t0 = now if self.t0 is None else self.t0
        gx, gy = WAYPOINTS[self.idx]
        x, y, yaw = self.pose
        ex, ey = gx - x, gy - y                                  # odom 좌표 오차
        if math.hypot(ex, ey) < TOL:
            err = math.hypot(self.truth[0] - gx, self.truth[1] - gy) if self.truth else float('nan')
            self.get_logger().info('WP%d (%.1f, %.1f) reached t=%.1f s  true error %.3f m' % (
                self.idx + 1, gx, gy, now - self.t0, err))
            self.idx += 1
            if self.idx == len(WAYPOINTS):
                self.pub.publish(Twist()); rclpy.shutdown()
            return
        bx = math.cos(yaw) * ex + math.sin(yaw) * ey             # odom -> 로봇 좌표
        by = -math.sin(yaw) * ex + math.cos(yaw) * ey
        s = min(1.0, V_MAX / max(1e-6, KP * math.hypot(bx, by)))  # 속도 벡터 크기 제한
        t = Twist()
        t.linear.x, t.linear.y = KP * bx * s, KP * by * s        # 메카넘: 옆으로도 이동
        t.angular.z = -1.0 * yaw                                 # 방향은 0 rad 유지
        self.pub.publish(t)

rclpy.init()
node = WaypointFollower()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    if rclpy.ok(): node.pub.publish(Twist())
    node.destroy_node()
    if rclpy.ok(): rclpy.shutdown()
```

읽는 법:

- 한 변 1 m를 최고 0.2 m/s로 가므로 점 사이 약 5 s입니다. 도착 직전에는 P 제어라 속도가 줄어듭니다.
- **true error**는 오도메트리로는 도착했다고 판단한 순간 실제 위치(`/ground_truth`)와 목표의 거리입니다. 오도메트리 드리프트가 그대로 드러납니다. 실물 Nav2는 AMCL이 `map → odom`을 보정하므로 이 오차가 쌓이지 않습니다(M11).
- `TOL`을 0.25(Nav2의 `xy_goal_tolerance`)로 바꾸면 각 점을 훨씬 일찍 "도착"으로 판정해 모서리를 크게 깎고 지나갑니다. `navigate_through_poses`가 점을 부드럽게 통과하는 모습과 비슷해집니다.

## RTAB-Map 3D 내비게이션

M10에서 만든 RTAB-Map 데이터베이스로 내비게이션을 합니다. 원본 `navigation/launch/rtabmap_navigation.launch.py`의 구성은 2D 내비게이션과 이렇게 다릅니다.

| 항목 | 2D (`navigation.launch.py`) | 3D (`rtabmap_navigation.launch.py`) |
|---|---|---|
| 지도 | `slam/maps/map_01.yaml` (`map_server`) | `~/.ros/rtabmap.db` (RTAB-Map이 `/map` 발행) |
| 위치추정 (`map → odom`) | AMCL (라이다 + 격자 지도) | **RTAB-Map 위치추정 모드** (영상 + 스캔) |
| `bringup.launch.py` 인자 | `rtabmap: false` → `localization.launch.py` 포함 | `rtabmap: 'true'` → `localization.launch.py` **제외**(UnlessCondition) |
| RTAB-Map 파라미터 | — | M10과 같은 값 + `Mem/IncrementalMemory: 'False'`, `Mem/InitWMWithAllNodes: 'True'`, `grid_size: '20'`; `-d` 인자 **없음** |
| 플래너·컨트롤러 | NavFn + DWB (같은 `nav2_params.yaml`) | 같음 |
| 초기 위치 | 2D Pose Estimate로 직접 지정 | 필요 없음 — 카메라가 아는 장면을 보면 **스스로** 위치를 찾음(전역 위치추정) |

- `Mem/IncrementalMemory: False`는 "지도를 더 키우지 말고 **위치추정만**" 하라는 뜻입니다.
- `Mem/InitWMWithAllNodes: True`는 시작할 때 데이터베이스의 모든 노드를 작업 메모리(WM)에 올려 **어디서든** 루프(재위치추정)를 찾게 합니다.
- 매핑 launch와 달리 `-d`가 없어서 M10에서 만든 데이터베이스를 지우지 않고 읽습니다.
- 교재 L5는 이 launch의 구성을 "rtabmap_launch(3D 내비게이션 알고리즘), navigation_launch(2D 내비게이션 알고리즘), bringup_launch(초기화)"로 설명합니다. 즉 **경로 계획·제어는 2D Nav2 그대로**이고, 지도와 위치추정만 RTAB-Map이 맡습니다.

## 실습 (시뮬레이션)

@btn[~/sim/index.html] 2D 시뮬레이터 열기

1. **room** 월드에서 SLAM으로 지도를 만든 뒤 **내비게이션** 모드로 바꿉니다.
2. 목표를 차례로 네 곳 클릭해 순찰 경로를 만들어 봅니다(한 목표에 도착하면 다음 목표를 클릭). 각 구간의 전역 경로(A*)와 실제 궤적을 비교합니다.
3. 로봇이 주행하는 도중 경로 앞에 장애물을 두어(가능하면) 지역 제어가 비켜 가는지, 전역 경로가 다시 계산되는지 관찰합니다.
4. **오도메트리 오차 표시**를 켠 채로 순찰을 여러 바퀴 돌리고, 오차가 쌓이는 모습을 위 Playground 결과(true error)와 비교합니다.

## 실습 (실물)

:::safety
- 다중 지점 주행은 로봇이 **오래, 멀리** 스스로 움직입니다. 경로 전체를 먼저 걸어 보며 계단·문턱·케이블·낮은 물체(라이다에 안 보임)를 치웁니다.
- 첫 순찰은 1 m 간격 2~3점, 사람 한 명이 로봇을 따라다니며 멈출 준비를 합니다.
- 멈추는 방법을 미리 확인합니다: RViz Navigation 2 패널의 **Cancel**, 스크립트 터미널 Ctrl+C(`cancelTask`), 그래도 움직이면 `ros2 topic pub --once /controller/cmd_vel geometry_msgs/msg/Twist "{}"`, 최후에는 전원 스위치.
- 속도 상한(0.2 m/s, 0.5 rad/s)을 풀지 않습니다. 3D 내비게이션은 계산이 무거워 명령이 늦을 수 있으니 더 넓은 공간에서 합니다.
:::

### 1) 단일·다중 목표 (2D)

```bash
# 로봇
~/.stop_ros.sh
ros2 launch navigation navigation.launch.py map:=map_01

# 가상머신
ros2 launch navigation rviz_navigation.launch.py
```

1. **2D Pose Estimate**로 초기 위치를 지정합니다(M11).
2. **단일 목표**: **Nav2 Goal**로 한 점을 찍습니다. 초록 선(직선)과 진한 파란 선(계획 경로)을 확인합니다.
3. **다중 목표**: Navigation 2 패널에서 **Waypoint / Nav Through Poses Mode** 버튼을 누르고, **Nav2 Goal** 도구로 점을 여러 개 찍습니다(화살표로 방향까지 지정).
4. **Start Nav Through Poses**와 **Start Waypoint Following**을 번갈아 실행해, 점에서 멈추는지·방향을 맞추는지 비교합니다.
5. 주행 중에 상자를 경로에 놓았다 치워 보며 회피·재계획을 관찰합니다.
6. 위 `patrol.py`를 로봇에 저장해 실행합니다(좌표는 `/clicked_point`로 확인한 값으로 수정).

```bash
ros2 topic echo /clicked_point            # RViz Publish Point로 클릭한 좌표 확인
python3 ~/patrol.py
```

### 2) RTAB-Map 3D 내비게이션

M10에서 만든 `~/.ros/rtabmap.db`가 있어야 합니다.

```bash
# 로봇
~/.stop_ros.sh
ros2 launch navigation rtabmap_navigation.launch.py

# 가상머신
ros2 launch navigation rviz_rtabmap_navigation.launch.py
```

1. 로봇을 매핑 때 지나간 곳에 두고 카메라가 아는 장면을 보게 합니다. RViz에 지도와 로봇 위치가 나타나면 위치추정 성공입니다(초기 위치 지정 불필요).
2. **Nav2 Goal**로 목표를 찍습니다. 교재 설명대로 파란 사각형으로 된 직선 참고선과 진한 파란 계획 경로가 표시되고 로봇이 출발합니다. 다중 목표는 **Publish Point**/웨이포인트 모드로 줍니다.
3. `ros2 topic hz /map`, `top`으로 부하를 보고, 2D 내비게이션과 반응 속도를 비교합니다.
4. 끝나면 모든 터미널 Ctrl+C, 호스트에서 `sudo systemctl restart start_node.service`.

:::check 체크포인트
- [ ] `navigate_through_poses`와 `follow_waypoints`의 차이를 "멈춤·방향·작업 플러그인" 세 관점으로 말할 수 있다.
- [ ] 주행 중 장애물이 나타났을 때 ①감지 ②회피 ③재계획 ④복구가 각각 어느 노드에서 일어나는지 설명할 수 있다.
- [ ] RTAB-Map 내비게이션에서 AMCL이 실행되지 않는 이유(launch 조건)를 찾았다.
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| Waypoint 모드 버튼이 없음 | RViz에 Navigation 2 패널이 안 보임 | 원본 `rviz_navigation.launch.py`로 실행(설정 파일에 패널 포함), Panels 메뉴에서 추가 |
| 순찰 중 한 점을 건너뜀 | 그 점이 막힘 → `stop_on_failure: false`라 다음 점으로 | 결과의 `missed_waypoints` 확인, 점 위치를 빈 곳으로 |
| 각 점에서 오래 제자리 회전 | `follow_waypoints`가 점마다 `yaw_goal_tolerance` 0.25 rad 판정 | 방향이 중요 없으면 `navigate_through_poses` 사용 |
| `patrol.py`가 `waitUntilNav2Active`에서 멈춤 | 초기 위치 미지정으로 amcl이 준비 안 됨 | RViz 2D Pose Estimate 먼저, 또는 `nav.setInitialPose(...)` |
| `ModuleNotFoundError: nav2_simple_commander` | 패키지 미설치 | `sudo apt install ros-humble-nav2-simple-commander` (컨테이너 안) |
| 3D 내비게이션에서 위치가 안 잡힘 | 매핑 때와 다른 방향·조명, DB 없음 | 매핑 경로 위에서 같은 방향으로 카메라를 향함, `~/.ros/rtabmap.db` 확인 |
| 3D 내비게이션이 끊기고 늦게 반응 | 큰 DB, 라즈베리파이 부하 | 매핑 범위 축소(M10 경고), 다른 무거운 노드 끄기 |
| 낮은 물체에 부딪힘 | 코스트맵 입력이 라이다 한 평면뿐 | 경로에서 치우기, (심화) 깊이 카메라 점구름을 voxel 층 관측원으로 추가 |

## 과제

:::task 기본 과제
1. Playground 추종기의 `TOL`을 0.05, 0.15, 0.25로 바꿔 총 주행 시간과 각 점의 true error를 표로 정리하고, Nav2 `xy_goal_tolerance` 선택과 연결해 설명합니다.
2. 실물(또는 시뮬레이터)에서 같은 네 점을 `navigate_through_poses`와 `follow_waypoints`로 각각 돌고 총 시간을 비교합니다.
:::

:::task 심화 과제
3. Playground 추종기를 **애커만 섀시**(`chassis="ackermann"`)용으로 바꿉니다. 횡이동 대신 목표 방향으로 조향하는 Pure Pursuit(전방 주시 거리 0.3 m, 곡률 $κ = 2·sin α / L_d$, $ω = v·κ$)로 구현합니다.
4. `patrol.py`를 확장해 순찰을 **무한 반복**하되, 각 점 도착 시 `/scan_raw`의 전방 최소 거리를 기록해 CSV로 저장하는 "경비 순찰" 노드를 만듭니다. 순찰 중 Ctrl+C로 안전하게 멈추는지 확인합니다.
:::
