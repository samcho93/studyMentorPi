## 학습 목표

- 휠 오도메트리(wheel odometry)의 적분 식을 쓰고, 거리 오차와 방향 오차가 위치 오차로 커지는 과정을 수치로 설명합니다.
- MentorPi의 `/odom_raw` → EKF → `/odom` 파이프라인과 IMU 보정·필터 체인을 원본 소스 기준으로 그릴 수 있습니다.
- 원본 보정 노드(`calibrate_linear`, `calibrate_angular`)의 알고리즘을 해석하고, 보정 계수 = 실제 이동량 / 오도메트리 이동량을 측정합니다.
- 공분산(covariance)과 칼만 이득으로 "EKF가 어떤 센서를 얼마나 믿는가"를 설명합니다.
- 시뮬레이터의 `/ground_truth`와 비교해 오도메트리 드리프트를 측정하고 IMU 융합 효과를 확인합니다.

## 추측 항법과 오차의 성장

오도메트리는 **추측 항법(dead reckoning)** 입니다. 시작 자세에서 출발해 매 순간의 속도를 적분해 현재 자세를 추정합니다.
시간 간격 $Δt$마다 차체 속도 $(v_x, v_y, ω)$로 자세 $(x, y, ψ)$를 갱신하는 식은 다음과 같습니다.

```text
x ← x + (vx·cos ψ − vy·sin ψ)·Δt
y ← y + (vx·sin ψ + vy·cos ψ)·Δt
ψ ← ψ + ω·Δt
```

속도는 로봇 좌표계 값이므로 현재 yaw $ψ$로 회전시켜 세계(odom) 좌표계에 더합니다(R06의 2D 회전 변환). 적분이라서 **오차도 함께 쌓이고, 한 번 생긴 오차는 사라지지 않습니다.**

| 오차 원인 | 무엇이 틀어지나 | 크기 감각 |
|---|---|---|
| 바퀴 지름 오차(타이어 눌림, 마모) | 이동 거리 | 지름 1 % 오차 → 10 m에 10 cm |
| 좌우 바퀴 지름 차이, 윤거 오차 | 회전량(yaw) | 직진인데 odom은 똑바로, 실제는 휨 |
| 바퀴 미끄럼(메카넘 롤러, 매끄러운 바닥) | 거리·yaw 모두 | 옆걸음·급가속에서 큼 |
| 로봇이 막혀 바퀴만 헛돔 / 들어 올림 | 거리 | 명령 적분형 odom은 계속 증가 |

가장 무서운 것은 **yaw 오차**입니다. yaw가 $δψ$만큼 틀리면 그 뒤로 가는 거리 $d$마다 옆으로 $d · sin δψ$씩 벗어납니다.
1°만 틀려도 1 m에 1.7 cm, 10 m에 17 cm입니다. 그래서 yaw는 바퀴보다 정확한 **자이로(IMU)** 로 보강합니다.

## MentorPi 오도메트리 파이프라인

`ros2 launch controller controller.launch.py`는 세 부분을 함께 띄웁니다: `odom_publisher_node`(휠 오도메트리), `imu_filter.launch.py`(IMU 보정·필터), `robot_localization`의 `ekf_node`(융합).

@fig[m03-pipeline] 원본 `controller.launch.py` 기준 데이터 흐름. EKF가 휠 속도·IMU·(선택) 레이저 오도메트리를 융합해 `/odom`과 TF를 발행합니다.

### odom_publisher_node.py — /odom_raw

원본의 적분 스레드(`cal_odom_fun`)는 50 Hz로 돌며 아래 계산을 합니다(요약).

```python
dt = now - last_time                               # time.time() 기준
self.x += self.linear_x * dt * math.cos(self.pose_yaw)
self.y += self.linear_x * dt * math.sin(self.pose_yaw)
self.pose_yaw += self.angular_z * dt
odom.pose.pose.position.x = self.linear_factor * self.x
odom.pose.pose.position.y = self.linear_factor * self.y
odom.twist.twist.linear.x, .linear.y, .angular.z = linear_x, linear_y, angular_z
self.odom_pub.publish(odom)                        # 토픽 이름 'odom_raw', TF는 발행하지 않음
```

소스를 읽으면 교재에 없는 사실이 몇 가지 보입니다.

1. **엔코더가 아니라 명령 속도를 적분합니다.** `linear_x`, `angular_z`는 `cmd_vel_callback`에서 받은 **명령값**입니다. 모터 보드는 엔코더로 rps를 맞추지만(M01), 이 노드는 실제 회전수를 읽지 않습니다.
   로봇이 벽에 막혀도 `/odom_raw`의 위치는 계속 늘어납니다.
2. **위치 적분에 `linear_y`가 빠져 있습니다.** 메카넘 옆걸음은 `/odom_raw`의 자세에 반영되지 않고, twist(`linear.y`)에만 들어갑니다.
3. **보정 계수는 자세의 x, y에만 곱해집니다.** twist(속도)에는 곱해지지 않고, `angular_correction_factor`는 읽기만 하고 적분에 쓰이지 않습니다(이 소스 버전 기준).
4. **공분산으로 신뢰도를 알립니다.** 움직일 때 twist 공분산은 vx·vy 0.001, **vyaw 1000**입니다. 정지 명령(모두 0)일 때는 1e-9로 바꿔 "지금은 확실히 서 있다"고 알립니다.

2번과 3번은 문제처럼 보이지만, 아래 EKF 설정을 보면 이유가 드러납니다. **EKF는 `/odom_raw`의 자세를 쓰지 않고 속도(vx, vy, vyaw)만 씁니다.**
속도는 옆걸음 `linear.y`를 포함하므로 EKF 출력 `/odom`에는 옆걸음이 제대로 들어갑니다.

### IMU 체인 — /imu

`imu_filter.launch.py`(5초 지연 후 시작)는 두 노드를 연결합니다.

| 단계 | 노드 | 입력 → 출력 | 하는 일 |
|---|---|---|---|
| 1 | `imu_calib/apply_calib` | `/ros_robot_controller/imu_raw` → `imu_corrected` | `calibration/config/imu_calib.yaml`의 3×3 행렬 SM과 bias 벡터로 가속도계의 축 정렬·스케일·영점 보정 |
| 2 | `imu_complementary_filter` | `imu_corrected` → `/imu` | 자이로 적분 + 가속도계 기울기로 자세(쿼터니언) 추정. `use_mag: False`, `do_bias_estimation: True`, `do_adaptive_gain: True` |

**상보 필터(complementary filter)** 는 "빠른 변화는 자이로, 느린 기준은 가속도계"라는 생각입니다. 자이로 적분은 짧은 시간엔 정확하지만 바이어스 때문에 천천히 흐르고,
가속도계는 중력 방향으로 roll·pitch의 절대 기준을 주지만 진동에 약합니다. 둘을 주파수로 나눠 섞습니다.

```text
θ ← α·(θ + ω_gyro·Δt) + (1 − α)·θ_accel        (α ≈ 0.98)
```

단, **yaw에는 중력 기준이 없습니다.** 지자기(mag)를 쓰지 않으므로 `/imu`의 yaw는 자이로 적분이고 천천히 드리프트합니다.
`do_bias_estimation`은 로봇이 정지해 있다고 판단될 때 자이로 바이어스를 추정해 이 드리프트를 줄여 줍니다. 그래서 **시작 직후 몇 초는 로봇을 움직이지 않는 것**이 좋습니다.

### EKF 융합 — /odom

`controller/config/ekf.yaml`의 핵심 설정입니다. 설정 배열 15칸의 순서는 `x, y, z, roll, pitch, yaw, vx, vy, vz, vroll, vpitch, vyaw, ax, ay, az`입니다.

| 입력 | 토픽 | 사용 항목 | 옵션 |
|---|---|---|---|
| odom0 | `odom_raw` | vx, vy, vyaw | differential false |
| imu0 | `imu` | yaw, vyaw | relative true (시작 yaw를 0으로) |
| odom1 | `odom_rf2o` | x, y, yaw | relative true, 레이저 오도메트리가 실행 중일 때만 |
| 공통 | — | `frequency: 100.0`, `two_d_mode: true`, `publish_tf: true` | 출력 `odometry/filtered` → `odom`으로 remap |

즉 최종 `/odom`과 TF `odom → base_footprint`는 EKF가 만듭니다. `odom_publisher`는 TF를 발행하지 않습니다.
`rf2o_laser_odometry.launch.py`(`/scan_raw` → `/odom_rf2o`, 10 Hz)는 기본 `controller.launch.py`에 포함되어 있지 않아, 따로 켜지 않으면 odom1 입력은 들어오지 않습니다.

### EKF는 누구를 믿는가 — 칼만 이득

EKF는 매 주기 **예측(predict)** 과 **갱신(update)** 을 반복합니다. 2D 상태 $(x, y, ψ, v_x, v_y, ω)$에서

```text
예측:  x̂⁻ = f(x̂, Δt)            등속 운동 모델로 한 걸음 전진
       P⁻ = F P Fᵀ + Q          불확실성은 커짐 (Q = process_noise_covariance)
갱신:  K  = P⁻ Hᵀ (H P⁻ Hᵀ + R)⁻¹   R = 측정 공분산 (메시지의 covariance)
       x̂ = x̂⁻ + K (z − H x̂⁻)
       P = (I − K H) P⁻
```

한 변수만 보면 이득은 $K = P / (P + R)$입니다. 측정 분산 $R$이 크면 $K ≈ 0$(무시), 작으면 $K ≈ 1$(그대로 수용)입니다.
MentorPi는 `/odom_raw`의 vyaw 분산을 **1000**으로 적어 보내므로, yaw 각속도는 사실상 **IMU만** 반영되고 선속도 vx·vy는 휠(분산 0.001)을 믿습니다.
"거리는 바퀴, 회전은 자이로" — 이것이 저가 이동로봇의 표준 조합입니다.

:::info 절대 자세를 두 번 넣지 않는 이유
휠 오도메트리 자세와 IMU yaw는 각자 다른 방향으로 드리프트합니다. 두 **절대값**을 그대로 융합하면 EKF 추정이 둘 사이에서 튀게 됩니다.
그래서 드리프트하는 센서는 **속도**로 넣거나(odom0), 시작값 기준 **상대값**으로 넣습니다(imu0, odom1의 `relative: true`).
:::

## 보정: IMU, 선속도, 각속도

원본 교재는 "출고 시 보정되어 있으니 한쪽으로 휘거나 직진이 안 될 때만 하라"고 안내합니다. 애커만 버전은 선속도·각속도 보정이 필요 없다고 되어 있습니다.

### IMU 보정 (가속도계 6면)

`imu_calib`의 `do_calib`는 로봇을 **여섯 방향**(앞·뒤·왼·오른쪽이 아래로, 위를 보게, 아래를 보게)으로 차례로 놓고 Enter를 눌러 각 자세의 중력 벡터를 기록합니다.
중력은 크기 1 g로 알려져 있으므로 여섯 측정으로 각 축의 스케일·교차축 오차(SM 3×3)와 영점(bias 3개)을 최소제곱으로 풉니다. 결과는 `imu_calib.yaml`에 저장되고 `apply_calib`가 매 샘플에 적용합니다.

### 선속도 보정 — calibrate_linear

원본 노드의 알고리즘(파라미터 기본값: `test_distance` 1.0 m, `speed` 0.2 m/s, `tolerance` 0.03 m, `odom_linear_scale_correction` 1.0):

1. `start_test`가 false인 동안 TF `odom → base_footprint`의 현재 위치를 **시작점**으로 계속 갱신합니다.
2. `start_test`가 true가 되면 20 Hz로 시작점에서의 거리를 계산하고, `보정 거리 = 거리 × odom_linear_scale_correction`을 구합니다.
3. `오차 = 보정 거리 − test_distance`가 tolerance보다 크면 `/controller/cmd_vel`로 `copysign(speed, −오차)` 속도를 냅니다(지나치면 후진).
4. 오차가 tolerance 안이면 `start_test`를 false로 되돌리고 `finish`를 출력합니다.

로봇은 **오도메트리가 1 m라고 믿는 지점**에서 멈춥니다. 줄자로 잰 실제 거리가 $d$라면

```text
보정 계수 = 실제 이동 거리 / 오도메트리 거리 = d / 1.0
```

예: 실제로 0.93 m만 갔다면 계수는 0.93입니다(원본 기본값 `linear_correction_factor: 0.93`이 이런 값). `odom_linear_scale_correction`에 이 값을 넣고 다시 돌리면
오도메트리가 1/0.93 = 1.075 m를 셀 때까지 가므로 실제로 1 m에 멈춥니다. 교재는 0.01씩 바꿔 가며 맞추라고 합니다. 맞춘 값을 `calibrate_params.yaml`의 `linear_correction_factor`에 적습니다.

### 각속도 보정 — calibrate_angular

같은 구조로 `test_angle` 360°, `speed` 0.5 rad/s, `tolerance` 1.5°입니다. TF에서 yaw를 읽어 이전 값과의 차이(−π ~ π로 정규화)에 `odom_angular_scale_correction`을 곱해 누적하고,
360°에 도달하면 멈춥니다. **실행할 때마다 회전 방향이 바뀝니다**(`self.reverse = -self.reverse`). 앞에 표시한 테이프를 기준으로 실제로 한 바퀴를 넘었는지 모자랐는지 보고 계수를 조정합니다.

:::warning 소스 읽기 노트 — 계수가 실제로 어디에 쓰이나
이 소스 버전에서 `linear_correction_factor`는 `/odom_raw`의 **자세(x, y)** 에만 곱해지는데, EKF는 `/odom_raw`의 **속도**만 씁니다. 따라서 계수를 바꿔도 EKF 출력 `/odom`의 거리는 바뀌지 않고,
보정 노드는 EKF가 낸 TF를 기준으로 거리를 잽니다. `angular_correction_factor`는 적분에 쓰이지 않습니다(회전은 IMU가 주도하므로 영향이 작습니다).
또한 `controller/load_calibrate_param` 서비스는 ROS 1식 `~linear_correction_factor` 이름을 쓰므로 ROS 2에서는 제대로 동작하지 않을 수 있습니다. **yaml을 고친 뒤에는 노드를 다시 시작**하세요.
보정 결과를 `/odom`에 반영하려면 twist의 `linear.x`, `linear.y`에도 계수를 곱하도록 고치는 것이 맞습니다(과제 3).
:::

## 실습 (시뮬레이션)

시뮬레이터의 `/odom`은 잡음과 드리프트가 누적되는 추정값이고, `/ground_truth`는 시뮬 전용 **실제 자세**입니다. 실물에서 줄자와 테이프가 하는 일을 이 토픽이 대신합니다.

### 1. 직진 1 m — 선속도 보정 계수 구하기

0.2 m/s로 5초 직진한 뒤 멈추고, 오도메트리 거리와 실제 거리를 비교합니다.

```python run
import math
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from nav_msgs.msg import Odometry
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=7.0,
          start=(-1.5, 0.0, 0.0), noise=True)                     # 시뮬 전용

class LinearCalib(Node):
    def __init__(self):
        super().__init__("linear_calib_sim")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Odometry, "/odom", self.on_odom, 10)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.o0 = self.o = self.g0 = self.g = None
        self.t0 = time.time()
        self.create_timer(0.05, self.tick)

    def on_odom(self, msg):
        p = msg.pose.pose.position
        self.o = (p.x, p.y)
        self.o0 = self.o0 or self.o

    def on_gt(self, msg):
        self.g = (msg.x, msg.y)
        self.g0 = self.g0 or self.g

    def tick(self):
        cmd = Twist()
        if time.time() - self.t0 < 5.0:
            cmd.linear.x = 0.2
        self.pub.publish(cmd)

rclpy.init()
node = LinearCalib()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    d_odom = math.dist(node.o0, node.o)
    d_true = math.dist(node.g0, node.g)
    print("오도메트리 거리 = %.3f m" % d_odom)
    print("실제 거리       = %.3f m" % d_true)
    print("linear_correction_factor ≈ %.3f" % (d_true / d_odom))
    print("실제 옆 방향 벗어남 = %+.3f m" % (node.g[1] - node.g0[1]))
    node.destroy_node()
    rclpy.shutdown()
```

(대략 — 잡음이 켜져 있어 실행마다 달라집니다)

```text
오도메트리 거리 = 0.988 m
실제 거리       = 0.939 m
linear_correction_factor ≈ 0.950
실제 옆 방향 벗어남 = +0.001 m
```

주행 시간을 바꿔(0.5 m, 1 m, 2 m) 다시 측정해 보세요. 계수가 거리와 상관없이 일정하면 **체계 오차**(보정으로 고칠 수 있음), 들쭉날쭉하면 **무작위 오차**(보정으로 못 고침, 융합이 필요)입니다.
이 시뮬레이터는 잡음을 켜면 실제 바퀴가 인코더가 센 것보다 조금 덜 가도록(미끄럼) 모델링되어 있어 계수가 1보다 작게 나옵니다. 원본 기본값 0.93과 같은 방향입니다.

### 2. 제자리 360° — 각속도 보정 계수 구하기

원본 `calibrate_angular`처럼 0.5 rad/s로 한 바퀴(2π/0.5 ≈ 12.57 s)를 돌고, 매 샘플의 yaw 변화를 −π ~ π로 정규화해 누적합니다.

```python run
import math
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from nav_msgs.msg import Odometry
from tf_transformations import euler_from_quaternion
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=14.0, noise=True)   # 시뮬 전용

def wrap(a):
    return math.atan2(math.sin(a), math.cos(a))

class AngularCalib(Node):
    def __init__(self):
        super().__init__("angular_calib_sim")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Odometry, "/odom", self.on_odom, 10)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.last_o = self.last_g = None
        self.sum_o = self.sum_g = 0.0
        self.t0 = time.time()
        self.create_timer(0.05, self.tick)

    def on_odom(self, msg):
        q = msg.pose.pose.orientation
        yaw = euler_from_quaternion([q.x, q.y, q.z, q.w])[2]
        if self.last_o is not None:
            self.sum_o += wrap(yaw - self.last_o)
        self.last_o = yaw

    def on_gt(self, msg):
        if self.last_g is not None:
            self.sum_g += wrap(msg.theta - self.last_g)
        self.last_g = msg.theta

    def tick(self):
        cmd = Twist()
        if time.time() - self.t0 < 2 * math.pi / 0.5:
            cmd.angular.z = 0.5
        self.pub.publish(cmd)

rclpy.init()
node = AngularCalib()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    print("오도메트리 회전 = %.1f°" % math.degrees(node.sum_o))
    print("실제 회전       = %.1f°" % math.degrees(node.sum_g))
    print("angular_correction_factor ≈ %.3f" % (node.sum_g / node.sum_o))
    node.destroy_node()
    rclpy.shutdown()
```

(대략)

```text
오도메트리 회전 = 359.2°
실제 회전       = 348.5°
angular_correction_factor ≈ 0.970
```

단순히 `yaw_끝 − yaw_시작`을 하면 360° 회전이 0°가 됩니다. 원본 노드도 같은 이유로 **작은 변화량을 정규화해 누적**합니다.

### 3. yaw 추정 비교 — 휠, IMU, 분산 가중 융합

반경 0.375 m 원을 한 바퀴(약 15.7 s) 돈 뒤 멈추고, yaw를 네 가지로 추정해 실제 yaw와의 오차를 비교합니다. 마지막 추정은 휠 각속도와 IMU 각속도를 **분산의 역수로 가중 평균**한 것으로, EKF 갱신 단계의 1차원 버전입니다.

```python run
import math
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from nav_msgs.msg import Odometry
from sensor_msgs.msg import Imu
from tf_transformations import euler_from_quaternion
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=20.0, noise=True)   # 시뮬 전용

R_ODOM, R_IMU, DT = 0.05, 0.005, 0.02       # 각속도 측정 분산 가정 [(rad/s)²]

def yaw_of(q):
    return euler_from_quaternion([q.x, q.y, q.z, q.w])[2]

class YawCompare(Node):
    def __init__(self):
        super().__init__("yaw_compare")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Odometry, "/odom", self.on_odom, 10)
        self.create_subscription(Imu, "/imu", self.on_imu, 10)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.w_odom = self.w_imu = 0.0
        self.yaw = {"odom 자세": 0.0, "IMU 쿼터니언": 0.0, "IMU 자이로 적분": 0.0, "분산 가중 융합": 0.0}
        self.gt = 0.0
        self.t0 = time.time()
        self.create_timer(DT, self.tick)

    def on_odom(self, msg):
        self.w_odom = msg.twist.twist.angular.z
        self.yaw["odom 자세"] = yaw_of(msg.pose.pose.orientation)

    def on_imu(self, msg):
        self.w_imu = msg.angular_velocity.z
        self.yaw["IMU 쿼터니언"] = yaw_of(msg.orientation)

    def on_gt(self, msg):
        self.gt = msg.theta

    def tick(self):
        t = time.time() - self.t0
        cmd = Twist()
        if t < 2 * math.pi / 0.4:                  # 한 바퀴 돈 뒤 정지하고 비교
            cmd.linear.x, cmd.angular.z = 0.15, 0.4
        self.pub.publish(cmd)
        w_fused = (self.w_odom / R_ODOM + self.w_imu / R_IMU) / (1 / R_ODOM + 1 / R_IMU)
        self.yaw["IMU 자이로 적분"] += self.w_imu * DT
        self.yaw["분산 가중 융합"] += w_fused * DT

rclpy.init()
node = YawCompare()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    print("실제 yaw = %+.1f°" % math.degrees(node.gt))
    for name, yaw in node.yaw.items():
        err = math.atan2(math.sin(yaw - node.gt), math.cos(yaw - node.gt))
        print("%-12s 오차 %+5.1f°" % (name, math.degrees(err)))
    node.destroy_node()
    rclpy.shutdown()
```

(대략 — 잡음 모델에 따라 크기는 달라지지만 경향은 같습니다)

```text
실제 yaw = -10.9°
odom 자세    오차 +10.7°
IMU 쿼터니언   오차  -0.0°
IMU 자이로 적분  오차  -0.2°
분산 가중 융합   오차  +0.8°
```

휠 오도메트리는 한 바퀴(360°) 도는 동안 약 3 %의 회전 미끄럼이 **10.7°** 오차로 쌓였습니다. IMU는 바퀴가 아니라 차체의 실제 회전을 재므로 오차가 거의 없고,
분산 가중 융합은 가중치가 IMU 10 : 휠 1이라 0.8°로 IMU 쪽에 붙습니다.
`R_ODOM`을 1000(원본 `/odom_raw`의 vyaw 분산)으로 바꾸면 융합 결과가 IMU 자이로 적분과 같아지고, `R_IMU`를 크게 하면 휠 쪽으로 기웁니다. 이득 $K = P/(P+R)$의 직관을 숫자로 확인하세요.

## 실습 (실물)

:::safety 실물 보정 전 확인
- IMU 보정에서 로봇을 세우거나 뒤집을 때 **깊이 카메라와 팬틸트가 부딪치지 않도록 손으로 받칩니다.** 배터리 케이블이 빠지지 않게 주의합니다.
- 선속도 보정은 로봇 앞쪽 1.5 m 이상, 각속도 보정은 사방 0.5 m 이상 비웁니다. 보정 노드는 **제한 없는 `/controller/cmd_vel`** 로 움직입니다.
- 멈추지 않으면 `rqt_reconfigure`의 `start_test` 체크를 풀거나 0 명령을 발행합니다.
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `imu_filter.launch.py`가 `FileNotFoundError: Calibration file not found` | `calibration/config/imu_calib.yaml` 없음 | IMU 보정을 먼저 실행하거나 백업 yaml을 복사 |
| 켜자마자 `/odom` yaw가 천천히 돎 | 자이로 바이어스 추정 전 움직임, 책상 진동 | 켠 뒤 5~10초 정지, 단단한 바닥에 놓기 |
| 보정 노드가 `TF Exception`만 출력 | EKF가 아직 TF를 안 냄(IMU 필터 5초 지연) | 잠시 기다리거나 `ros2 run tf2_ros tf2_echo odom base_footprint`로 확인 |
| 보정 계수를 바꿨는데 `/odom` 거리가 그대로 | 계수는 `/odom_raw` 자세에만 적용, EKF는 속도만 사용(소스 기준) | twist에도 계수를 곱하도록 수정하거나 `/odom_raw` 자세로 확인 |
| yaml을 고쳤는데 반영 안 됨 | 노드는 시작할 때만 읽음, `load_calibrate_param` 서비스가 ROS 2에서 불안정 | `controller.launch.py` 재시작 |
| 막힌 상태에서 odom만 계속 증가 | 명령 속도 적분형 오도메트리 | 정상 동작. 라이다 오도메트리(rf2o)·SLAM으로 보강 |
