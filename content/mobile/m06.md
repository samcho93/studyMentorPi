## 학습 목표

- 원본 `lidar_controller.py`의 서비스 구조(enter / set_running / set_param / exit)와 데이터 전처리(240° 사용, 좌우 45° 창)를 설명합니다.
- 장애물 회피의 네 가지 판단, **타임스탬프 잠금**(non-blocking timed action), `last_act` 히스테리시스를 코드 수준에서 재현합니다.
- 추종·경비의 PD 제어(각도 Kp 1.6 Kd 0.16, 거리 Kp 1.7 Kd 0.16)를 해석하고, 움직이는 목표에서 생기는 정상상태 오차를 계산합니다.
- 임계거리·속도·반응 시간으로 정지 거리를 계산해 안전한 파라미터를 고릅니다.
- 시뮬레이터에서 세 행동을 직접 구현·실행하고, 실물에서 원본 앱을 명령행으로 실행합니다.

## 반응형 행동이란

이 장의 세 행동은 지도도 경로 계획도 없이 **매 스캔마다 "보고 → 판단하고 → 움직이는"** 반응형 행동(reactive behavior)입니다.

| 행동 | `running_mode` | 한 줄 요약 | 애커만 지원 |
|---|---|---|---|
| 장애물 회피 (Obstacle Avoidance) | 1 | 앞 좌우 45° 안에 임계거리보다 가까운 것이 있으면 반대쪽으로 튼다 | 지원(다른 동작) |
| 추종 (Following) | 2 | 가장 가까운 물체를 향해 돌고, 일정 거리를 유지한다 | 지원(다른 파라미터) |
| 경비 (Guarding) | 3 | 가장 가까운 물체를 향해 제자리에서 방향만 맞춘다 | **미지원** |

반응형 행동은 빠르고 단순하지만 "막다른 골목"이나 "U자 장애물"에서 갇힐 수 있습니다. 이 한계를 넘는 것이 지도 기반 내비게이션(M11~M12)입니다.

## 원본 lidar_controller.py 구조

노드 이름은 `lidar_app`입니다. 앱(WonderPi)과 명령행이 같은 서비스를 호출합니다.

| 서비스 | 타입 | 하는 일 |
|---|---|---|
| `/lidar_app/enter` | `std_srvs/srv/Trigger` | 파라미터 초기화(`reset_value`), `/scan_raw` 구독 시작(QoS BEST_EFFORT, depth 1) |
| `/lidar_app/set_running` | `interfaces/srv/SetInt64` | 0 정지, 1 회피, 2 추종, 3 경비. 바꿀 때마다 정지 Twist 1회 발행 |
| `/lidar_app/set_param` | `interfaces/srv/SetFloat64List` | `[threshold(0.3~1.5 m), scan_angle(0~90°), speed(>0)]` |
| `/lidar_app/exit` | `std_srvs/srv/Trigger` | 초기화 + 정지 Twist |
| `/lidar_app/heartbeat` | `std_srvs/srv/SetBool` | 앱이 5초마다 보내는 생존 신호. 끊기면 자동 exit (명령행에서는 보내지 않으면 무관) |

출력은 **`/controller/cmd_vel`**(속도 제한 없음)과, 애커만일 때 서보 명령 `ros_robot_controller/pwm_servo/set_state`입니다.

### 초기값과 데이터 전처리

| 변수 | `enter` 후 값 | 의미 |
|---|---|---|
| `threshold` | 0.6 m | 회피 판단 거리, 추종·경비의 반응 거리 |
| `scan_angle` | 90° (생성자에서는 360°였다가 `reset_value`에서 90°로) | 전방 판단 창 전체 폭 → 좌·우 각 45° |
| `speed` | 0.2 m/s | 직진 속도, 회전 속도의 기준(×6) |
| `MAX_SCAN_ANGLE` | 240° (상수) | 차체에 늘 가리는 뒤쪽 120°를 버림 |

콜백은 먼저 `ranges`를 전방 기준 **왼쪽 120°**(`left_ranges`)와 **오른쪽 120°**(`right_ranges`, 배열을 뒤집어 전방부터)로 나누고,
다시 각각 앞에서부터 `scan_angle/2`만큼(`angle_index = int(angle / angle_increment + 0.5)`)만 잘라 씁니다. 그 뒤 0과 `inf`/`nan`을 걸러 냅니다(M05).

## 행동 1: 장애물 회피 (mode 1, 메카넘)

@fig[m06-sectors] 회피 판단에 쓰는 좌우 섹터와 네 가지 규칙. 섹터 안 최소거리를 threshold와 비교합니다.

### 판단 규칙

`w = speed × 6 = 1.2 rad/s`, 회전 중 전진 속도는 `speed / 6 ≈ 0.033 m/s`입니다(“돌 때는 앞으로 조금만, 회전은 크게”).

| 조건 (L = 왼쪽 최소, R = 오른쪽 최소) | 명령 | 잠금 시간 | `last_act` |
|---|---|---|---|
| L ≤ thr, R > thr (왼쪽 막힘) | ωz = −w (우회전). 단 직전 `last_act`가 2 또는 3이면 +w | (π/2) / w / 2 = 0.65 s | 1 |
| L ≤ thr, R ≤ thr (양쪽 막힘) | ωz = +w (좌회전) | π / w / 2 = 1.31 s | 3 |
| L > thr, R ≤ thr (오른쪽 막힘) | ωz = +w (좌회전). 단 직전 `last_act`가 1 또는 3이면 −w | 0.65 s | 2 |
| 둘 다 > thr | vx = speed (직진) | 없음 | 0 |

### 타임스탬프 잠금 — 기다리지 않고 기다리기

회전 명령을 보낸 뒤 `self.timestamp = time.time() + 잠금 시간`을 기록하고, 다음 스캔부터는 `self.timestamp <= time.time()`이 될 때까지 **판단을 건너뜁니다.**
`time.sleep()`으로 기다리면 콜백 스레드가 멈추지만, 이 방식은 콜백이 즉시 돌아오므로 다른 서비스 호출도 처리됩니다. 잠금 동안은 아무것도 발행하지 않는데,
모터 보드가 **마지막 명령을 유지**하므로(M04) 로봇은 계속 돕니다.

원본 주석은 "90° 회전", "180° 회전"이라고 적었지만 잠금 시간을 2로 나누므로 실제 회전량은 w × 시간 = **45°**, **90°** 입니다.
45° 돌고 나서도 여전히 막혀 있으면 다음 판단에서 다시 돌기 때문에 결과적으로 필요한 만큼 돕니다.

### last_act 히스테리시스

모서리에서 "왼쪽 막힘 → 우회전 → 이제 오른쪽 막힘 → 좌회전 → 다시 왼쪽 막힘…"처럼 **좌우로 떨며 갇히는** 현상을 막기 위해, 직전에 다른 이유로 돌고 있었다면 새 판단을 무시하고
**같은 방향으로 계속 돌게** 합니다. 표의 "단 …" 조건이 그것입니다. 한 번 방향을 정하면 빠져나갈 때까지(직진 판단으로 `last_act = 0`이 될 때까지) 그 방향을 유지합니다.
(양쪽 막힘 뒤 오른쪽 막힘이면 −w로 도는 등 완전히 대칭은 아닙니다. 원본 그대로입니다.)

### 애커만 버전의 회피

애커만은 제자리에서 돌 수 없어 규칙이 다릅니다(원본 `else` 분기).

- 왼쪽·오른쪽 막힘: `vx = speed`, `ωz = −vx / 0.1`(반경 0.1 m 우회전 요청 → 실제로는 29° 최대 조향), 1초 잠금.
- 양쪽 막힘: 서보를 가운데(1500)로 두고 **0.3 m/s 후진** 1초 → 이어서 0.5초 우회전 전진 → 0.1초 → 다시 판단.
- 직진: `vx = 0.3` 이고 **서보 1500을 따로 발행**합니다. ω = 0 명령만으로는 조향이 돌아오지 않는 문제(M02 함정 2) 때문입니다.

## 행동 2: 추종 (mode 2)

@fig[m06-follow] 추종·경비의 제어 구조. 최근접점의 각도와 거리가 각각 PD 제어기를 거쳐 ωz와 vx가 됩니다.

좌·우 창을 이어 붙여(`np.append(right_range[::-1], left_range)`) 오른쪽 45°부터 왼쪽 45°까지 한 배열을 만들고, 유효한 값 중 최솟값 `dist`와 그 인덱스로 각도를 구합니다.

```text
angle = −scan_angle/2 + angle_increment · index        (−45° ~ +45°, + = 왼쪽)
```

| 제어 | 조건 | 계산 (원본) | 출력 제한 |
|---|---|---|---|
| 방향 | dist < thr 그리고 \|angle\| > 5° | `pid_yaw.update(-angle)` → 오차 = 0 − (−angle) = **angle** | ±speed·6 = ±1.2 rad/s |
| 거리 | dist < thr 그리고 \|0.2 − dist\| > 0.02 | `pid_dist.update(thr/2 − dist)` → 오차 = **dist − thr/2** | ±speed = ±0.2 m/s |
| 데드밴드 | — | \|ωz\| < 0.008 → 0, \|vx\| < 0.05 → 0 | — |

PID는 `sdk/pid.py`의 `PID(P, I, D)`로, `output = Kp·e + Ki·∫e + Kd·de/dt`(적분 누적 한계 ±20)입니다. 여기서는 Ki = 0이라 **PD 제어**입니다.

- 목표 거리는 **thr/2 = 0.3 m**입니다(교재 설명은 "약 0.35 m"). 거리 조건식의 0.2는 목표(0.3)와 다른 값이 남아 있는 것으로, 동작에는 큰 영향이 없습니다.
- 반응 범위 밖(dist ≥ thr)으로 물체가 멀어지면 추종을 포기합니다. 멀리 있는 사람을 따라가게 하려면 `set_param`으로 threshold를 키웁니다(최대 1.5 m → 목표 0.75 m).
- `|vx| < 0.05` 데드밴드 때문에 오차가 0.05 / 1.7 ≈ 3 cm 안이면 멈춥니다. 떨림을 없애는 대신 3 cm 정도의 오차를 허용하는 설계입니다.

:::info 움직이는 목표와 정상상태 오차
목표가 속도 $v_t$로 멀어지면, 로봇이 같은 속도로 따라가려면 $vx = K_p · e = v_t$여야 하므로 **오차가 $e = v_t / K_p$만큼 남습니다.**
$v_t$ = 0.1 m/s, $K_p$ = 1.7이면 약 5.9 cm, 즉 목표 0.3 m보다 약 0.36 m 떨어져 따라갑니다. 교재가 말하는 "약 0.35 m"와 가깝습니다. 이 오차를 없애려면 적분항(Ki)이 필요합니다.
:::

애커만 추종은 목표 거리 0.5 m, 반응 거리 2 m, 속도 ±0.35 m/s, 조향각 ±0.316 rad(18.1°)로 제한하고 `ωz = vx · tan(조향각) / 0.145`로 바꿉니다(자전거 모델, M02).
각도 이력 15개로 평균·표준편차를 계산하는 코드가 있지만 결과는 쓰이지 않고 최신 각도가 그대로 쓰입니다.

## 행동 3: 경비 (mode 3)

추종에서 **거리 제어를 뺀 것**입니다. 가장 가까운 물체가 threshold 안에 있고 5°보다 옆에 있으면 방향 PD로 회전만 합니다. 메카넘은 제자리 회전이 되므로 카메라가 늘 물체를 향합니다.
애커만은 제자리 회전이 불가능해 원본 교재도 "애커만 버전은 경비를 지원하지 않는다"고 명시합니다(코드의 애커만 분기에도 mode 3이 없습니다).

## 파라미터 설계: 정지 거리

임계거리는 "멈추거나 돌기 시작해서 부딪히기 전까지 필요한 거리"보다 커야 합니다.

```text
d_필요 = r_로봇 + v·t_반응 + v² / (2·a)
t_반응 ≈ 스캔 주기 0.1 s + 처리·통신 0.05 s
```

v = 0.2 m/s, a = 1.2 m/s², 로봇 반경 0.13 m이면 0.13 + 0.03 + 0.017 ≈ **0.18 m**입니다. 기본 0.6 m는 여유가 크고, 회피가 45°씩 돌며 판단을 반복할 시간을 줍니다.
speed를 0.4로 올리면 필요 거리가 0.26 m로 늘고 회전 속도도 2.4 rad/s가 되어 스캔 한 장(0.1 s) 동안 14°를 돕니다. threshold와 speed는 **함께** 조정해야 합니다.

## 실습 (시뮬레이션)

시뮬레이터의 `/scan`은 인덱스 0이 후방이므로(M05), 원본의 인덱스 슬라이싱 대신 **각도로 좌·우 창을 고르는** 방식으로 같은 알고리즘을 옮깁니다.

### 1. 장애물 회피 재현

원본 mode 1(메카넘)의 판단·잠금·히스테리시스를 그대로 옮겼습니다. 원본처럼 `/controller/cmd_vel`에 발행합니다(ω = 1.2 rad/s는 `/cmd_vel`의 0.5 제한에 걸리기 때문).

```python run
import math
import time
import numpy as np
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from sensor_msgs.msg import LaserScan
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="arena", duration=30.0,
          start=(-1.5, -1.5, math.radians(45)), noise=True)       # 시뮬 전용

THRESHOLD, SCAN_ANGLE, SPEED = 0.6, math.radians(90), 0.2
NAMES = {0: "직진", 1: "왼쪽 막힘", 2: "오른쪽 막힘", 3: "양쪽 막힘"}

class Avoid(Node):
    def __init__(self):
        super().__init__("lidar_avoid")
        self.pub = self.create_publisher(Twist, "/controller/cmd_vel", 1)
        self.create_subscription(LaserScan, "/scan", self.on_scan, 1)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.last_act, self.timestamp = 0, 0.0
        self.count = {k: 0 for k in NAMES}
        self.closest, self.path, self.prev = 9.9, 0.0, None

    def on_gt(self, msg):
        if self.prev:
            self.path += math.hypot(msg.x - self.prev[0], msg.y - self.prev[1])
        self.prev = (msg.x, msg.y)

    def on_scan(self, msg):
        r = np.array(msg.ranges)
        th = msg.angle_min + np.arange(len(r)) * msg.angle_increment
        ok = np.isfinite(r) & (r > 0)
        left = r[ok & (th >= 0) & (th <= SCAN_ANGLE / 2)]
        right = r[ok & (th < 0) & (th >= -SCAN_ANGLE / 2)]
        if time.time() < self.timestamp or len(left) < 2 or len(right) < 2:
            return                                    # 잠금 중 또는 데이터 부족
        dl, dr = left.min(), right.min()
        self.closest = min(self.closest, dl, dr)
        tw, w = Twist(), SPEED * 6.0
        if dl <= THRESHOLD and dr > THRESHOLD:
            tw.linear.x, tw.angular.z = SPEED / 6, (w if self.last_act in (2, 3) else -w)
            self.last_act, self.timestamp = 1, time.time() + (math.pi / 2) / w / 2
        elif dl <= THRESHOLD and dr <= THRESHOLD:
            tw.linear.x, tw.angular.z = SPEED / 6, w
            self.last_act, self.timestamp = 3, time.time() + math.pi / w / 2
        elif dr <= THRESHOLD:
            tw.linear.x, tw.angular.z = SPEED / 6, (-w if self.last_act in (1, 3) else w)
            self.last_act, self.timestamp = 2, time.time() + (math.pi / 2) / w / 2
        else:
            self.last_act, tw.linear.x = 0, SPEED
        self.count[self.last_act] += 1
        self.pub.publish(tw)

rclpy.init()
node = Avoid()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    print("판단 횟수:", {NAMES[k]: v for k, v in node.count.items()})
    print("판단 시점 최소 거리 %.2f m, 실제 이동 거리 %.2f m" % (node.closest, node.path))
    node.destroy_node()
    rclpy.shutdown()
```

(대략)

```text
판단 횟수: {'직진': 209, '왼쪽 막힘': 4, '오른쪽 막힘': 7, '양쪽 막힘': 1}
판단 시점 최소 거리 0.52 m, 실제 이동 거리 4.22 m
```

30초 동안 대부분은 직진 판단이고, 장애물 근처에서 좌·우 회피가 몇 번 일어납니다. 판단 시점의 최소 거리가 threshold(0.6 m)보다 조금 작은 0.5 m 안팎인 것은, 판단 사이(0.1 s 스캔 주기와 잠금 시간) 동안 로봇이 더 다가가기 때문입니다.
충돌이 나면 시뮬레이터가 `[sim …] 충돌!` 줄을 출력합니다. `THRESHOLD`를 0.3으로 줄이거나 `SPEED`를 0.4로 올려 충돌이 생기는지, `last_act` 조건을 지우면(항상 기본 방향) 모서리에서 떨림이 생기는지 비교해 보세요.

### 2. 추종 — 움직이는 원통 따라가기

`sim.add_mover(0.8, 0, 0.1, 0)`은 로봇 앞 0.8 m에서 +x 방향으로 0.1 m/s로 움직이는 원통(반지름 0.1 m)입니다. `set_param`으로 threshold를 1.0 m로 키운 상황(목표 0.5 m)을 재현합니다.

```python run
import math
import time
import numpy as np
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
from sensor_msgs.msg import LaserScan
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=20.0,
          start=(0.0, 0.0, 0.0), noise=True)                      # 시뮬 전용
sim.add_mover(0.8, 0.0, 0.1, 0.0)                                 # 시뮬 전용

THRESHOLD, HALF, SPEED = 1.0, math.radians(45), 0.2

class PD:                                  # sdk/pid.py PID(P, 0, D)와 같은 계산
    def __init__(self, kp, kd):
        self.kp, self.kd, self.last_t = kp, kd, time.time()
        self.clear()
    def clear(self):
        self.last_err, self.output = 0.0, 0.0
    def update(self, feedback):
        err, now = 0.0 - feedback, time.time()
        dt = now - self.last_t
        self.output = self.kp * err + (self.kd * (err - self.last_err) / dt if dt > 0 else 0.0)
        self.last_err, self.last_t = err, now

class Follow(Node):
    def __init__(self):
        super().__init__("lidar_follow")
        self.pub = self.create_publisher(Twist, "/controller/cmd_vel", 1)
        self.create_subscription(LaserScan, "/scan", self.on_scan, 1)
        self.pid_yaw, self.pid_dist = PD(1.6, 0.16), PD(1.7, 0.16)
        self.t0, self.next_print = time.time(), 0.0

    def on_scan(self, msg):
        r = np.array(msg.ranges)
        th = msg.angle_min + np.arange(len(r)) * msg.angle_increment
        m = np.isfinite(r) & (r > 0) & (np.abs(th) <= HALF)
        if not m.any():
            return
        i = np.argmin(np.where(m, r, np.inf))
        dist, angle, tw = r[i], th[i], Twist()
        if dist < THRESHOLD and abs(math.degrees(angle)) > 5:
            self.pid_yaw.update(-angle)
            tw.angular.z = max(-SPEED * 6, min(SPEED * 6, self.pid_yaw.output))
        else:
            self.pid_yaw.clear()
        if dist < THRESHOLD and abs(0.2 - dist) > 0.02:
            self.pid_dist.update(THRESHOLD / 2 - dist)
            tw.linear.x = max(-SPEED, min(SPEED, self.pid_dist.output))
        else:
            self.pid_dist.clear()
        tw.angular.z = 0.0 if abs(tw.angular.z) < 0.008 else tw.angular.z
        tw.linear.x = 0.0 if abs(tw.linear.x) < 0.05 else tw.linear.x
        self.pub.publish(tw)
        t = time.time() - self.t0
        if t >= self.next_print:
            print("t=%4.1f  거리 %.3f m  각도 %+5.1f°  vx %+.3f" % (t, dist, math.degrees(angle), tw.linear.x))
            self.next_print += 3.0

rclpy.init()
node = Follow()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()
```

`PD(1.7, 0.16)`의 1.7을 3.4로 바꾸면 오차가 절반이 되는지 확인하세요.

### 3. 경비 — 지나가는 물체를 향해 돌기

원통이 로봇 앞을 가로질러 (0.7, 0.4)에서 −y 방향으로 0.08 m/s로 지나갑니다. 경비는 **방향 제어만** 하므로 로봇은 제자리에서 돕니다.
원통의 실제 방향은 `atan2(0.4 − 0.08t, 0.7)`로 계산할 수 있어 로봇 yaw와 비교합니다. threshold는 최대값 1.5 m로 둡니다.

```python run
import math
import time
import numpy as np
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist, Pose2D
from sensor_msgs.msg import LaserScan
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(chassis="mecanum", world="empty", duration=20.0,
          start=(0.0, 0.0, 0.0), noise=True)                      # 시뮬 전용
sim.add_mover(0.7, 0.4, 0.0, -0.08)                               # 시뮬 전용

THRESHOLD, HALF, SPEED, KP, KD = 1.5, math.radians(45), 0.2, 1.6, 0.16

class Guard(Node):
    def __init__(self):
        super().__init__("lidar_guard")
        self.pub = self.create_publisher(Twist, "/controller/cmd_vel", 1)
        self.create_subscription(LaserScan, "/scan", self.on_scan, 1)
        self.create_subscription(Pose2D, "/ground_truth", self.on_gt, 10)
        self.gt, self.last_err, self.last_t = None, 0.0, time.time()
        self.t0, self.next_print = time.time(), 0.0

    def on_gt(self, msg):
        self.gt = msg

    def on_scan(self, msg):
        r = np.array(msg.ranges)
        th = msg.angle_min + np.arange(len(r)) * msg.angle_increment
        m = np.isfinite(r) & (r > 0) & (np.abs(th) <= HALF)
        if not m.any() or self.gt is None:
            return
        i = np.argmin(np.where(m, r, np.inf))
        dist, angle, tw = r[i], th[i], Twist()
        now = time.time()
        if dist < THRESHOLD and abs(math.degrees(angle)) > 5:
            err = angle                                   # = 0 − (−angle)
            d = (err - self.last_err) / (now - self.last_t) if now > self.last_t else 0.0
            tw.angular.z = max(-SPEED * 6, min(SPEED * 6, KP * err + KD * d))
            self.last_err = err
        else:
            self.last_err = 0.0
        self.last_t = now
        self.pub.publish(tw)
        t = now - self.t0
        if t >= self.next_print:
            bearing = math.atan2(0.4 - 0.08 * t - self.gt.y, 0.7 - self.gt.x)
            print("t=%4.1f  물체 방향 %+6.1f°  로봇 yaw %+6.1f°  라이다 각도 %+5.1f°" % (
                t, math.degrees(bearing), math.degrees(self.gt.theta), math.degrees(angle)))
            self.next_print += 4.0

rclpy.init()
node = Guard()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()
```

처음 29° 옆에 있던 물체를 향해 돈 뒤, 로봇 yaw가 물체 방향을 **4~8° 뒤처져** 따라갑니다. ±5° 안에서는 제어하지 않는 **데드밴드** 때문에 오차가 0이 되지 않고,
물체가 움직이는 동안은 P 제어의 지연까지 더해집니다. 라이다 각도는 원통 **표면의 최근접점** 방향이라 중심 방향(물체 방향)과 1~2° 다를 수 있습니다.

## 실습 (실물)

:::safety 실물 라이다 앱 실행 전 확인
- 라이다 앱은 **제한 없는 `/controller/cmd_vel`** 로 회전 1.2 rad/s까지 냅니다. 사방 1.5 m를 비우고 깨지기 쉬운 물건을 치웁니다.
- 장애물은 라이다 높이(약 16 cm)보다 **높은** 물체(책, 상자)를 씁니다. 낮은 물체는 보이지 않아 그대로 부딪힙니다.
- 추종 실습에서 사람 다리를 따라가게 할 때 로봇이 발에 닿지 않도록 threshold를 너무 작게 하지 않습니다.
- 끝나면 반드시 `set_running 0` → `exit` 순서로 멈춥니다. Ctrl+C만 누르면 마지막 명령이 남아 로봇이 계속 갈 수 있습니다.
:::

원본 Lesson 3~5의 명령행 절차입니다. `debug:=true`는 라이다(`lidar.launch.py`)와 섀시(`controller.launch.py`)까지 함께 띄웁니다.

```bash
~/.stop_ros.sh
ros2 launch app lidar_node.launch.py debug:=true
```

새 터미널에서 게임에 들어가고 모드를 고릅니다.

```bash
ros2 service call /lidar_app/enter std_srvs/srv/Trigger {}
ros2 service call /lidar_app/set_running interfaces/srv/SetInt64 "{data: 1}"   # 1 회피, 2 추종, 3 경비
```

파라미터는 `[threshold, scan_angle(°), speed]` 순서입니다. 예: 임계 0.5 m, 창 90°, 속도 0.15 m/s.

```bash
ros2 service call /lidar_app/set_param interfaces/srv/SetFloat64List "{data: [0.5, 90.0, 0.15]}"
```

원본 코드는 값을 정상 적용한 경우에도 응답의 `success`를 True로 채우지 않아 `success=False`로 보입니다. 범위를 벗어난 경우에만 `message`에 이유가 담기므로 메시지로 판단하세요.
정지와 종료, 앱 서비스 복구:

```bash
ros2 service call /lidar_app/set_running interfaces/srv/SetInt64 "{data: 0}"
ros2 service call /lidar_app/exit std_srvs/srv/Trigger {}
sudo systemctl restart start_node.service        # Docker 밖 시스템 터미널에서
```

여러분이 시뮬레이터에서 만든 노드(실습 1~3)를 실물에서 돌리려면 `# 시뮬 전용` 줄과 `/ground_truth` 관련 줄을 지우고, 토픽을 `/scan_raw`로, QoS를 `qos_profile_sensor_data`로 바꿉니다.
원본 앱과 **동시에 실행하지 않습니다**(두 노드가 같은 `/controller/cmd_vel`에 서로 다른 명령을 보냄).

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `set_running`을 불렀는데 로봇이 안 움직임 | `enter`를 먼저 호출하지 않아 `/scan_raw` 구독이 없음 | `enter` → `set_running` 순서 |
| 추종 모드에서 터미널이 숫자로 가득 참 | 원본 mode 2가 매 스캔 `ranges` 전체를 로그로 출력 | 정상(디버그 출력). 성능이 문제면 해당 로그 줄을 주석 처리 |
| 추종을 시작해도 물체를 따라가지 않음 | 물체가 threshold(기본 0.6 m) 밖 또는 ±45° 창 밖 | 물체를 앞 0.5 m 안에 두거나 `set_param`으로 threshold 증가 |
| 모서리에서 좌우로 떨며 갇힘 | 직접 구현에서 `last_act` 히스테리시스 누락 | 직전 회전 방향 유지 규칙 추가 |
| 회피 중 벽에 스침 | 라이다보다 낮은 부분·차체 폭, 너무 높은 speed | threshold 증가, speed 감소, 정지 거리 식으로 점검 |
| 앱으로 켠 게임이 몇 초 뒤 저절로 꺼짐 | 앱 하트비트(5 s) 끊김 | 앱 연결 유지, 명령행 사용 시에는 무관 |
| 애커만에서 mode 3이 아무 반응 없음 | 원본에 애커만 경비 분기가 없음 | 정상. 메카넘에서만 지원 |
