## 학습 목표

- 구조광(structured light)·스테레오(stereo)·ToF(Time of Flight) 깊이 측정 방식의 원리와 장단점을 비교할 수 있습니다.
- 핀홀 카메라 모델로 깊이 영상의 픽셀 $(u, v, Z)$를 3D 점 $(X, Y, Z)$로 **역투영(back-projection)** 하는 식을 유도하고 코드로 구현합니다.
- MentorPi 깊이 카메라 드라이버(`ascamera`)의 launch 구성, RGB·Depth·PointCloud2 토픽과 TF 프레임을 확인합니다.
- `rqt_image_view`, RViz2로 컬러·깊이 영상과 포인트 클라우드를 띄우고, 웹 브라우저로 실시간 영상을 모니터링합니다.
- 광학 좌표계(optical frame)와 로봇 좌표계(REP-103)의 차이를 설명하고, 둘 사이 회전을 정적 TF로 표현합니다.

## 왜 깊이 카메라인가

2D 라이다(M05)는 **센서 높이의 한 평면**만 봅니다. 라이다보다 낮은 상자, 테이블 상판처럼 위에 떠 있는 물체, 계단 아래로 꺼지는 바닥은 스캔 평면에 걸리지 않습니다. 깊이 카메라(depth camera, RGB-D 카메라)는 영상의 **모든 픽셀마다 거리**를 재서 시야 전체를 3D로 봅니다.

| 항목 | 2D 라이다 (LD19) | 깊이 카메라 |
|---|---|---|
| 측정 공간 | 한 평면, 360° | 시야각 안의 3D 원뿔(대략 수평 60~70°) |
| 거리 범위 | 약 0.05~12 m | 대략 0.2~3 m 부근이 정확 (모델마다 다름) |
| 데이터 양 | 한 바퀴 수백 점 | 640 × 480 = 307,200 픽셀/프레임 |
| 추가 정보 | 반사 강도 | 컬러(RGB) 영상과 정렬됨 |
| 쓰임 | 2D SLAM, 장애물 회피 | 3D SLAM(M10), 물체 인식·집기, 높이 있는 장애물 |

그래서 MentorPi는 2D 지도는 라이다로, 3D 지도(RTAB-Map, M10)와 비전 응용(A 트랙)은 깊이 카메라로 만듭니다.

## 깊이를 재는 세 가지 방법

### 구조광 (structured light)

적외선(IR) 프로젝터가 알고 있는 점 패턴을 쏘고, 옆에 떨어진 IR 카메라가 그 패턴을 찍습니다. 물체가 가까울수록 패턴이 옆으로 더 많이 밀려 보입니다(시차). 프로젝터-카메라 사이 거리(기준선, baseline) $b$와 초점거리 $f$를 알면 삼각측량으로

$Z = f · b / d$ ( $d$ = 패턴이 밀린 픽셀 수, 시차 disparity )

를 얻습니다. 실내·근거리에 강하지만 **햇빛 속 적외선**이 패턴을 지워 버리므로 야외에서는 약합니다.

### 스테레오 (stereo)

두 카메라로 같은 장면을 찍고 좌우 영상에서 **같은 점을 찾아** 시차를 구합니다. 식은 구조광과 같지만, 무늬 없는 흰 벽처럼 대응점을 못 찾는 곳은 깊이가 비어 버립니다. 그래서 많은 제품이 IR 패턴 프로젝터를 더한 **능동 스테레오**(active stereo)를 씁니다.

### ToF (Time of Flight)

변조된 적외선을 쏘고 되돌아오는 **시간(위상차)** 으로 거리를 잽니다. $Z = c · Δt / 2$. 텍스처와 무관하고 빠르지만, 여러 번 반사된 빛(다중 경로)이 모서리를 흐리게 만듭니다.

:::info 깊이 오차는 거리의 제곱에 비례
삼각측량식 $Z = f·b/d$를 $d$로 미분하면 $|ΔZ| = Z² · |Δd| / (f·b)$입니다. 시차를 0.1 픽셀 틀리게 찾을 때 오차는 1 m에서보다 **2 m에서 4배** 커집니다. 깊이 카메라로 만든 지도가 멀리 갈수록 번지는 이유이고, RTAB-Map 같은 3D SLAM이 먼 점을 잘라 내는(최대 깊이 제한) 이유입니다.
:::

## 핀홀 모델과 역투영

@fig[m07-pinhole] 핀홀 모델: 픽셀 (u, v)와 깊이 Z로 광학 좌표계의 3D 점 (X, Y, Z)를 복원합니다. 광학 좌표계는 z가 앞, x가 오른쪽, y가 아래입니다.

카메라 내부 파라미터(intrinsics)는 초점거리 $fx, fy$ [픽셀]와 주점(principal point) $cx, cy$입니다. 3D 점이 영상에 맺히는 **투영**은

$u = fx · X / Z + cx$,   $v = fy · Y / Z + cy$

이고, 깊이 카메라는 픽셀마다 $Z$를 알려 주므로 이 식을 거꾸로 풀면 됩니다(**역투영**).

$X = (u − cx) · Z / fx$,   $Y = (v − cy) · Z / fy$,   $Z = depth(u, v)$

이 값들은 `sensor_msgs/CameraInfo`의 `K` 행렬 `[fx 0 cx; 0 fy cy; 0 0 1]`에 들어 있습니다. 드라이버가 발행하는 `PointCloud2`는 드라이버 안에서 정확히 이 계산을 한 결과입니다.

### 깊이 영상의 인코딩

| 인코딩 | 픽셀 값 | 단위 | 측정 실패 |
|---|---|---|---|
| `16UC1` | 0~65535 정수 | **밀리미터** | 0 |
| `32FC1` | 실수 | **미터** | NaN 또는 0 |

`rqt_image_view`에서 깊이 영상이 거의 검게 보이는 것은 16비트 mm 값(예: 800)을 0~65535 범위로 정규화해서 보여 주기 때문입니다. 교재가 깊이 맵을 볼 때 표시 범위를 바꾸라고 하는 것도 이 때문입니다.

### PointCloud2 메시지 구조

`sensor_msgs/PointCloud2`는 점들을 **바이트 배열**로 담고, 그 배열을 어떻게 해석할지를 `fields`로 설명합니다.

| 필드 | 뜻 | 예 (컬러 점구름) |
|---|---|---|
| `height`, `width` | 정렬된(organized) 구름이면 영상 크기, 아니면 1 × N | 480 × 640 또는 1 × N |
| `fields` | 점 하나의 필드 목록(이름·오프셋·타입) | `x`(0, FLOAT32) `y`(4) `z`(8) `rgb`(12 또는 16) |
| `point_step` | 점 하나의 바이트 수 | 16 또는 32 |
| `row_step` | 한 행의 바이트 수 = `point_step × width` | |
| `is_dense` | NaN 점이 없으면 True | |
| `data` | 실제 바이트 | |

640 × 480 컬러 점구름은 한 프레임에 307,200점 × 16 B ≈ 4.9 MB이고, 15 fps면 **초당 70 MB 이상**입니다. 원격 PC의 RViz로 점구름을 보면 화면이 끊기는 이유입니다(아래 오류 표).

### 실습: numpy로 역투영하기

아래 코드는 합성한 깊이 영상(가운데 80 × 80 픽셀 상자가 0.8 m, 오른쪽 벽 한 점이 1.5 m)을 3D 점으로 바꿉니다. 내부 파라미터는 640 × 480 카메라의 **예시 값**입니다. 실제 값은 로봇에서 `camera_info` 토픽으로 확인합니다.

```python run
import numpy as np

# 640x480 depth camera intrinsics (illustrative values)
fx, fy, cx, cy = 460.0, 460.0, 320.0, 240.0

# 16UC1 depth image in millimetres, 0 = no measurement
depth = np.zeros((480, 640), dtype=np.uint16)
depth[200:280, 280:360] = 800        # box face 0.8 m away (80x80 px)
depth[240, 600] = 1500               # a single wall point

v, u = np.nonzero(depth)             # pixel rows / cols that have data
z = depth[v, u].astype(np.float32) / 1000.0   # mm -> m
x = (u - cx) * z / fx                # optical frame: x right
y = (v - cy) * z / fy                #                y down, z forward
pts = np.stack([x, y, z], axis=1)
box = pts[u < 600]
print("valid points :", len(pts), "/", depth.size)
print("box centre   :", np.round(box.mean(axis=0), 3))
print("box width [m]: %.3f" % (box[:, 0].max() - box[:, 0].min()))
print("wall point   :", np.round(pts[u == 600][0], 3))

# optical frame (x right, y down, z fwd) -> ROS body frame (x fwd, y left, z up)
R = np.array([[0, 0, 1], [-1, 0, 0], [0, -1, 0]], dtype=np.float32)
body = pts @ R.T
print("wall in body :", np.round(body[u == 600][0], 3))
print("PointCloud2 size: %d bytes (16 B/point)" % (len(pts) * 16))
```

```text
valid points : 6401 / 307200
box centre   : [-0.001 -0.001  0.8  ]
box width [m]: 0.137
wall point   : [0.913 0.    1.5  ]
wall in body : [ 1.5   -0.913  0.   ]
PointCloud2 size: 102416 bytes (16 B/point)
```

읽는 법:

- 상자 폭 0.137 m는 $79 픽셀 × 0.8 m / 460$입니다. **같은 픽셀 수라도 멀면 더 넓은 실제 폭**이 됩니다.
- 깊이 0(측정 실패)인 픽셀은 `np.nonzero`로 빠졌습니다. 실제 드라이버도 이런 점을 버리거나 NaN으로 채웁니다(`is_dense`).
- 벽 점은 광학 좌표로 $(0.913, 0, 1.5)$ — 오른쪽(+x)으로 0.913 m, 앞(+z)으로 1.5 m입니다. 로봇 좌표로 바꾸면 $(1.5, −0.913, 0)$, 즉 **앞 1.5 m, 오른쪽 0.913 m**(y가 음수)입니다.

## 광학 좌표계와 TF

ROS에서 카메라 영상의 좌표계는 **광학 좌표계**(REP-103의 `_optical_frame` 규약: z 앞, x 오른쪽, y 아래)이고, 로봇 몸체는 **x 앞, y 왼쪽, z 위**입니다. 두 좌표계는 회전만 다릅니다. 위 코드의 행렬 `R`이 그 회전입니다.

MentorPi의 `peripherals/launch/include/ascamera.launch.py`는 이 회전을 **정적 TF**로 발행합니다.

```python
Node(package='tf2_ros', executable='static_transform_publisher',
     arguments=['0', '0', '0', '-1.57', '0', '-1.57', 'depth_cam', 'ascamera_camera_link_0'])
Node(package='tf2_ros', executable='static_transform_publisher',
     arguments=['0', '0', '0', '-1.57', '0', '-1.57', 'depth_cam', 'ascamera_color_0'])
```

`static_transform_publisher`의 옛 인자 순서는 `x y z yaw pitch roll 부모 자식`입니다. 즉 yaw = −90°, roll = −90°로 로봇 쪽 프레임 `depth_cam`(URDF의 카메라 링크, M08)에서 광학 프레임 `ascamera_color_0`·`ascamera_camera_link_0`으로 돌립니다. RViz에서 **Fixed Frame을 `ascamera_color_0`** 으로 두라는 교재 지시는 점구름이 이 프레임 기준으로 발행되기 때문입니다.

TF 체인은 `base_footprint → base_link → depth_cam → ascamera_color_0`입니다. 이 체인이 끊기면(URDF를 발행하는 `robot_state_publisher`가 안 떠 있으면) Fixed Frame을 `base_link`로 둘 때 점구름이 안 보입니다.

## MentorPi 깊이 카메라 드라이버

MentorPi 이미지에서 깊이 카메라는 환경 변수 `DEPTH_CAMERA_TYPE`으로 고릅니다. `peripherals/launch/depth_camera.launch.py`는 값이 `ascamera`이면 Angstrong 카메라 드라이버(`ascamera` 패키지)를, 아니면 USB 카메라(`usb_cam.launch.py`)를 띄웁니다.

`ascamera.launch.py`의 드라이버 파라미터:

| 파라미터 | 값 | 뜻 |
|---|---|---|
| namespace | `ascamera` | 모든 토픽이 `/ascamera/...` 아래에 생김 |
| `depth_width` × `depth_height` | 640 × 480 | 깊이 해상도 |
| `rgb_width` × `rgb_height` | 640 × 480 | 컬러 해상도 |
| `fps` | 15 | 프레임률 |
| `color_pcl` | True | 컬러가 입혀진 점구름 발행 |
| `pub_tfTree` | True | 카메라 내부 TF 발행 |
| `confiPath` | `/home/ubuntu/third_party_ros2/third_party_ws/src/ascamera/configurationfiles` | 보정·설정 파일 |
| `respawn` | True | 드라이버가 죽으면 자동 재시작 |

자주 쓰는 토픽(원본 `slam/launch/include/rtabmap.launch.py`의 remapping에서 확인한 이름):

| 토픽 | 타입 | 쓰임 |
|---|---|---|
| `/ascamera/camera_publisher/rgb0/image` | `sensor_msgs/Image` | 컬러 영상 |
| `/ascamera/camera_publisher/rgb0/camera_info` | `sensor_msgs/CameraInfo` | 내부 파라미터 K |
| `/ascamera/camera_publisher/depth0/image_raw` | `sensor_msgs/Image` | 깊이 영상 |
| `.../depth0/points` | `sensor_msgs/PointCloud2` | 점구름 (교재 RViz 경로: ascamera → … → depth0 → points) |

:::tip 토픽 이름은 항상 직접 확인
드라이버 버전에 따라 중간 이름(`camera_publisher` 등)이 다를 수 있습니다. `ros2 topic list | grep ascamera`로 실제 이름을 확인한 뒤 RViz·코드에 씁니다.
:::

## 실습 (실물)

:::safety
- 이 실습은 로봇을 **움직이지 않습니다**. 바퀴가 바닥에 닿지 않게 받침대에 올려 두면 실수로 주행 명령이 나가도 안전합니다.
- 깊이 카메라는 USB 대역폭과 전력을 많이 씁니다. 배터리 전압이 낮으면 드라이버가 반복 재시작(`respawn`)하므로 충전된 상태에서 합니다.
- 카메라 렌즈·IR 프로젝터를 손으로 만지지 않습니다. 지문은 IR 패턴을 번지게 해 깊이에 구멍을 만듭니다.
- 실습이 끝나면 앱 서비스를 다시 켜서(`start_node.service`) 다른 사람이 앱을 쓸 수 있게 합니다.
:::

### 1) 깊이 카메라 서비스와 RViz

VNC로 로봇 데스크톱에 접속해 터미널을 엽니다. 앱 자동 시작 서비스가 카메라를 이미 쓰고 있으므로 먼저 끕니다(교재 L4에는 `~/.stop_sh`로 적힌 곳이 있지만 다른 레슨과 같은 `~/.stop_ros.sh`가 맞습니다).

```bash
~/.stop_ros.sh
ros2 launch peripherals depth_camera.launch.py      # 터미널 1: 깊이 카메라 드라이버
```

새 터미널에서 토픽과 주기를 확인합니다.

```bash
ros2 topic list | grep ascamera
ros2 topic hz /ascamera/camera_publisher/depth0/image_raw      # 약 15 Hz
ros2 topic echo --once /ascamera/camera_publisher/rgb0/camera_info | grep -A1 "^k:"
ros2 run tf2_ros tf2_echo depth_cam ascamera_color_0            # 광학 프레임 회전 확인
```

RViz2를 띄웁니다.

```bash
rviz2
```

1. **Global Options → Fixed Frame**을 `ascamera_color_0`으로 바꿉니다.
2. **Add → By topic**에서 `.../depth0/points`의 **PointCloud2**를 추가합니다.
3. PointCloud2의 **Color Transformer**를 `RGB8`로 두면 컬러 점구름, `AxisColor`(Z)로 두면 거리별 색으로 보입니다.
4. **Add → By topic**에서 `rgb0/image`의 **Image**를 추가하면 컬러 영상이 함께 보입니다.

### 2) rqt로 2D 영상 보기

```bash
rqt       # Plugins → Visualization → Image View
```

드롭다운에서 컬러 영상, 깊이 영상을 차례로 고릅니다. 깊이 영상이 검게 보이면 Image View의 표시 범위(최대값)를 수 m 정도로 줄입니다.

### 3) 웹 실시간 모니터링

앱 자동 시작 서비스에는 웹 영상 서버가 포함돼 있습니다. 서비스를 다시 켜고 브라우저로 접속합니다.

```bash
sudo systemctl restart start_node.service     # Docker 컨테이너가 아니라 호스트 터미널에서, 부저가 울릴 때까지 대기
```

- 로봇 핫스팟(직접 연결 모드)에 붙은 PC·휴대폰 브라우저에서 `http://192.168.149.1:8080/`을 엽니다.
- 목록에서 `image_raw`의 **Snapshot** 또는 스트림을 누르면 컬러 영상이 보입니다. 이 페이지는 RGB 영상만 지원합니다.
- "사이트에 연결할 수 없음"이 뜨면 서비스를 다시 재시작합니다.

### 4) (선택) PC 가상머신에 SDK 설치

교재 L1·L2는 카메라를 **PC 가상머신(Ubuntu 20.04 + ROS 2 Foxy)** 에 직접 꽂아 쓰는 방법도 설명합니다. 순서만 정리합니다.

```bash

cd ~/ros_ws/ascamera/scripts/
sudo cp angstrong-camera.rules /etc/udev/rules.d
sudo ./gettarget.sh
sudo udevadm control --reload-rules && sudo udevadm trigger
# launch/ascamera.launch.py 의 설정 경로를 ~/ros_ws/ascamera/configurationfiles 로 수정
cd ~/ros_ws && ./build.sh && . ./install/setup.bash
./run_ascamera_node.sh
```

가상머신은 **브리지(Bridged) 네트워크**로 두고, USB 장치를 가상머신 쪽으로 연결해야 카메라가 보입니다.

:::check 체크포인트
- [ ] 깊이 영상 주기가 약 15 Hz로 나온다.
- [ ] `camera_info`의 K에서 $fx, cx, cy$를 읽고, 위 역투영 코드의 예시 값을 실제 값으로 바꿔 보았다.
- [ ] RViz에서 컬러 점구름을 보고, Fixed Frame을 바꿨을 때 무엇이 달라지는지 설명할 수 있다.
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| RViz에 점구름이 안 보이고 "No transform from ..." | Fixed Frame과 점구름 프레임 사이 TF 없음 | Fixed Frame을 `ascamera_color_0`으로. 또는 URDF(`robot_state_publisher`)를 함께 띄움 |
| 드라이버가 계속 재시작 (`respawn`) | 앱 서비스가 카메라를 점유, USB 전력 부족 | `~/.stop_ros.sh` 먼저 실행, 배터리 충전, USB 3.0 포트 확인 |
| 깊이 영상이 새까맣게 보임 | 16UC1(mm) 값을 0~65535로 정규화해 표시 | rqt Image View의 최대값을 줄이거나 컬러맵 사용 |
| 유리·거울·검은 물체 자리에 구멍 | IR이 투과·정반사·흡수됨 | 센서 한계. 라이다와 함께 쓰거나 해당 영역을 무시 |
| 원격 PC RViz가 끊기고 느림 | 점구름 대역폭(수십 MB/s)이 Wi-Fi를 넘음 | RViz를 로봇에서 실행하거나, 점구름 대신 영상만 보거나, 해상도·fps를 낮춤 |
| 웹 페이지 `192.168.149.1:8080` 접속 불가 | 앱 서비스가 꺼짐, LAN 모드라 IP가 다름 | `sudo systemctl restart start_node.service`, LAN 모드면 앱에 표시된 IP 사용 |
| 가상머신에서 카메라 장치 없음 | USB가 호스트 Windows에 붙어 있음, udev 규칙 없음 | VMware 메뉴에서 USB를 가상머신에 연결, `angstrong-camera.rules` 복사 후 udev 재적용 |

## 과제

:::task 기본 과제
1. 로봇에서 `camera_info`를 읽어 실제 $fx, fy, cx, cy$로 역투영 코드를 고치고, 1 m 앞 A4 용지(0.297 m)의 가로 픽셀 수를 예측한 뒤 컬러 영상에서 실제로 세어 비교합니다.
2. 깊이 오차식 $|ΔZ| = Z²|Δd|/(f·b)$에서 기준선 $b$ = 0.05 m, $f$ = 460 px, $|Δd|$ = 0.2 px일 때 0.5·1·2·3 m의 깊이 오차를 표로 계산합니다.
:::

:::task 심화 과제
3. 깊이 영상의 가운데 한 행(`v = 240`)만 골라 각 픽셀의 $(X, Z)$를 구하고, $r = √(X²+Z²)$, $θ = atan2(−X, Z)$로 바꿔 **가짜 LaserScan**을 만드는 함수를 작성합니다(`depthimage_to_laserscan` 패키지의 원리). 라이다 `/scan_raw`와 같은 방향의 거리를 비교합니다.
4. RViz에서 점구름의 **Decay Time**을 5 s로 두고 로봇을 손으로 천천히 돌려 봅니다. 점들이 겹쳐 쌓이면서 어긋나는 모습을 관찰하고, 왜 3D SLAM(M10)이 필요한지 한 문단으로 설명합니다.
:::
