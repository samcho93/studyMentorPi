## 학습 목표

- RGB·GRAY·HSV·Lab·YCrCb 색 공간의 성질을 비교하고, 조명 변화에 강한 색 공간을 골라 `cvtColor`로 변환합니다.
- OpenCV의 HSV(H 0~179)와 Lab(0~255로 이동한 a·b) 값 범위를 계산하고, 빨강처럼 **색상이 0°를 걸치는** 색의 임계값을 두 구간으로 나눕니다.
- 크기 조정·이동·회전·어파인·원근 변환을 2×3 / 3×3 행렬로 설명하고 `warpAffine`·`warpPerspective`로 적용합니다.
- 평균·가우시안·미디언·양방향 필터의 원리를 비교하고, 잡음 종류에 맞는 필터를 고릅니다.

## 색 공간 (Color Space)

색 공간은 색을 숫자 몇 개로 나타내는 규칙입니다. 카메라가 주는 BGR은 **밝기와 색이 세 채널에 섞여** 있어서, 조명이 조금만 바뀌어도 세 값이 함께 변합니다. 그래서 색으로 물체를 찾을 때는 **밝기와 색을 분리한 색 공간**(HSV, Lab, YCrCb)으로 바꾼 뒤 임계값을 겁니다.

| 색 공간 | 채널 | OpenCV 8비트 범위 | 성질 | 로봇에서 쓰임 |
|---|---|---|---|---|
| BGR (RGB) | B, G, R | 각 0~255 | 가산 혼합. 밝기·색이 섞임 | 카메라 원본, 표시 |
| GRAY | 밝기 1채널 | 0~255 | $Y = 0.299R + 0.587G + 0.114B$ | 엣지·이진화·특징점 |
| HSV | 색상 H, 채도 S, 명도 V | H 0~179, S·V 0~255 | 색상이 한 채널에 모임, 직관적 | 색 임계값(이 사이트의 색 실험실) |
| Lab (CIE L\*a\*b\*) | 밝기 L, 초록↔빨강 a, 파랑↔노랑 b | L = L\*·255/100, a·b = +128 이동 | 사람 지각에 가까움, 장치 독립 | **MentorPi 색 인식·라인 트레이싱** |
| YCrCb | 밝기 Y, 빨강 차 Cr, 파랑 차 Cb | 각 0~255 | 영상 압축(JPEG)과 같은 분리 | 피부색 검출 |

`cv2.cvtColor(src, code)`의 `code`는 `COLOR_BGR2GRAY`, `COLOR_BGR2HSV`, `COLOR_BGR2LAB`, `COLOR_BGR2YCrCb`, `COLOR_BGR2RGB`처럼 “원본2목표” 형식이고, 반대 방향(`COLOR_HSV2BGR` 등)도 있습니다. 입력이 RGB 배열이면 `COLOR_RGB2LAB`처럼 **RGB 쪽 코드를 써야** 합니다. MentorPi 라인 트레이싱 노드는 `"rgb8"`로 받아 `COLOR_RGB2LAB`를 씁니다.

### HSV — 색상환을 반으로 접은 H

H(Hue, 색상)는 원래 0~360°의 각도지만, 8비트에 넣기 위해 OpenCV는 **2로 나눠 0~179**로 저장합니다. 빨강은 0° 근처라서 **179 쪽과 0 쪽 양 끝**에 걸쳐 있습니다. S(Saturation, 채도)는 흰빛이 얼마나 섞였는지, V(Value, 명도)는 얼마나 밝은지입니다. 조명이 어두워지면 주로 V가 변하고 H는 비교적 유지되므로, H와 S로 색을 고르고 V는 넓게 잡는 것이 기본 전략입니다.

@fig[r09-hsv] OpenCV HSV의 H 범위(0~179)와 빨강이 두 구간으로 나뉘는 이유

### Lab — MentorPi가 쓰는 색 공간

Lab은 L(밝기)과 두 개의 색 축 a(−: 초록, +: 빨강), b(−: 파랑, +: 노랑)로 색을 나타냅니다. 8비트 영상에서 OpenCV는 L을 0~255로 늘리고 a·b에 128을 더해 **회색이 (L, 128, 128)**이 되게 합니다. 따라서

- 빨강: a가 128보다 **크다**, 초록: a가 128보다 **작다**
- 노랑: b가 128보다 **크다**, 파랑: b가 128보다 **작다**

MentorPi의 색 임계값 파일(`lab_config.yaml`)이 빨강을 `a ≥ 165`, 파랑을 `b ≤ 110`처럼 잡는 것도 이 축 때문입니다(A01).

```python run
import cv2
import numpy as np

names = ["red", "green", "blue", "yellow", "white", "gray", "dark red"]
bgr = np.array([[[0, 0, 255], [0, 255, 0], [255, 0, 0], [0, 255, 255],
                 [255, 255, 255], [128, 128, 128], [0, 0, 120]]], np.uint8)
gray = cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)[0]
hsv = cv2.cvtColor(bgr, cv2.COLOR_BGR2HSV)[0]
lab = cv2.cvtColor(bgr, cv2.COLOR_BGR2LAB)[0]
print("%-9s %-15s %4s  %-15s %-15s" % ("색", "BGR", "GRAY", "HSV", "Lab"))
for i, n in enumerate(names):
    print("%-9s %-15s %4d  %-15s %-15s" % (n, bgr[0, i].tolist(), gray[i],
                                          hsv[i].tolist(), lab[i].tolist()))
```

읽는 법:

- 빨강과 **어두운 빨강**은 BGR에서 R 값이 255 → 120으로 크게 다르지만, HSV의 H는 둘 다 0이고 V만 다릅니다. Lab에서는 L이 크게 줄고 a가 여전히 128보다 큽니다. 조명이 바뀌어도 “색”을 유지하는 채널이 있다는 뜻입니다.
- 흰색과 회색은 HSV의 S가 0이라 H 값이 의미가 없습니다. 채도가 낮은 픽셀은 H로 색을 판별하면 안 됩니다.

### 색으로 영역 고르기: inRange

`cv2.inRange(img, lower, upper)`는 세 채널이 모두 범위 안인 픽셀을 255, 나머지를 0으로 만든 **마스크(mask)**를 돌려줍니다. 빨강은 H가 양 끝에 걸치므로 두 마스크를 OR로 합칩니다.

```python run
import cv2
import numpy as np

img = cv2.imread("shapes.png")   # 빨간 원, 초록 사각형, 파란 삼각형, 노란 타원
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
ranges = {
    "red":    [((0, 120, 70), (10, 255, 255)), ((170, 120, 70), (179, 255, 255))],
    "green":  [((40, 80, 60), (85, 255, 255))],
    "blue":   [((100, 120, 60), (130, 255, 255))],
    "yellow": [((20, 100, 100), (35, 255, 255))],
}
total = img.shape[0] * img.shape[1]
for name, rs in ranges.items():
    mask = np.zeros(img.shape[:2], np.uint8)
    for lo, hi in rs:
        mask = cv2.bitwise_or(mask, cv2.inRange(hsv, lo, hi))
    n = cv2.countNonZero(mask)
    print("%-6s 픽셀 %6d (%.1f %%)" % (name, n, 100.0 * n / total))
    if name == "red":
        cv2.imshow("red mask", mask)
        cv2.imshow("red only", cv2.bitwise_and(img, img, mask=mask))
```

```text
red    픽셀  15373 (5.0 %)
green  픽셀  25521 (8.3 %)
blue   픽셀   9301 (3.0 %)
yellow 픽셀  20971 (6.8 %)
```

## 기하 변환 (Geometric Transformation)

기하 변환은 픽셀 값은 그대로 두고 **픽셀의 위치를 옮기는** 연산입니다. 출력 픽셀 $(x', y')$마다 원본의 어느 위치 $(x, y)$에서 값을 가져올지 계산하고, 그 위치가 정수가 아니면 주변 픽셀로 **보간(interpolation)**합니다.

### 크기 조정: resize

```python
dst = cv2.resize(src, (new_w, new_h), interpolation=cv2.INTER_AREA)   # 크기를 직접 지정
dst = cv2.resize(src, None, fx=0.5, fy=0.5)                            # 배율로 지정
```

`dsize`는 **(너비, 높이)** 순서이고, `dsize`를 주면 `fx`, `fy`는 무시됩니다. MentorPi 색 인식 예제는 처리 속도를 위해 프레임을 `(320, 240)`으로 줄여 계산한 뒤 좌표를 원래 크기로 되돌립니다.

| 보간 방법 | 원리 | 언제 |
|---|---|---|
| `INTER_NEAREST` | 가장 가까운 픽셀 값 | 가장 빠름, 마스크·라벨 영상 |
| `INTER_LINEAR` (기본) | 주변 2×2 선형 보간 | 일반적인 확대·축소 |
| `INTER_AREA` | 영역 평균 | **축소**할 때 계단 현상(aliasing) 적음 |
| `INTER_CUBIC` | 주변 4×4 3차 보간 | 확대 품질 우선 |
| `INTER_LANCZOS4` | 주변 8×8 Lanczos | 최고 품질, 느림 |

### 어파인 변환: 2×3 행렬

어파인(affine) 변환은 **직선과 평행성을 보존**하는 변환으로, 이동·회전·확대·기울임(shear)을 모두 하나의 2×3 행렬 $M$으로 표현합니다.

| 변환 | 행렬 $M$ | 만드는 법 |
|---|---|---|
| 이동 $(t_x, t_y)$ | `[[1, 0, tx], [0, 1, ty]]` | `np.float32(...)` 직접 작성 |
| 중심 $c$ 기준 회전 θ, 배율 s | `[[α, β, (1−α)cx − β·cy], [−β, α, β·cx + (1−α)cy]]`, α = s·cosθ, β = s·sinθ | `cv2.getRotationMatrix2D(c, θ°, s)` |
| 일반 어파인 | 점 3쌍으로 결정 | `cv2.getAffineTransform(src3, dst3)` |

변환된 좌표는 $[x', y']^T = M \cdot [x, y, 1]^T$입니다. `getRotationMatrix2D`의 각도는 **양수가 반시계 방향**(화면 기준)입니다. 이미지의 y축이 아래를 향하므로 행렬 부호가 수학 교과서의 회전 행렬과 반대로 보입니다.

```python run
import cv2
import numpy as np

img = cv2.imread("shapes.png")
h, w = img.shape[:2]

T = np.float32([[1, 0, 100], [0, 1, 50]])                  # 오른쪽 100, 아래 50
moved = cv2.warpAffine(img, T, (w, h), borderValue=(255, 255, 255))

R = cv2.getRotationMatrix2D((w / 2, h / 2), 30, 0.8)       # 중심 기준 반시계 30°, 0.8배
rotated = cv2.warpAffine(img, R, (w, h), borderValue=(255, 255, 255))
np.set_printoptions(precision=3, suppress=True)
print("회전 행렬 M =\n", R)

pts = np.float32([[[w / 2, h / 2]], [[w / 2 + 100, h / 2]]])   # 중심, 중심에서 오른쪽 100 px
print("변환된 점:", cv2.transform(pts, R).reshape(-1, 2))
print("이동 행렬로 (0, 0) →", (T @ np.array([0, 0, 1], np.float32)).tolist())
cv2.imshow("moved", moved)
cv2.imshow("rotated", rotated)
```

```text
회전 행렬 M =
 [[  0.693   0.4     2.297]
 [ -0.4     0.693 201.723]]
변환된 점: [[320.    240.   ]
 [389.282 200.   ]]
이동 행렬로 (0, 0) → [100.0, 50.0]
```

중심은 그대로 있고, 오른쪽 100 px 떨어진 점은 거리 80 px(0.8배)로 줄면서 **위쪽(y 감소)**으로 30° 돌아갔습니다. 화면에서 반시계 방향입니다.

### 원근 변환: 3×3 호모그래피

카메라가 바닥을 비스듬히 보면 평행한 차선이 위쪽에서 모여 보입니다. 원근(perspective) 변환은 **3×3 행렬 $H$(호모그래피)**로 이 기울어짐을 되돌려 위에서 내려다본 영상(bird's-eye view)을 만듭니다.

```text
[x', y', w']ᵀ = H · [x, y, 1]ᵀ        (u, v) = (x' / w', y' / w')
```

마지막에 $w'$로 나누는 것이 어파인과의 차이입니다. 이 나눗셈 때문에 직선은 직선으로 남지만 **평행성은 보존되지 않습니다**. $H$는 자유도가 8이므로 **점 4쌍**이 필요하고, `cv2.getPerspectiveTransform(src4, dst4)`로 구합니다.

@fig[r09-warp] 어파인 변환(점 3쌍, 평행 유지)과 원근 변환(점 4쌍, 사다리꼴 → 직사각형)

```python run
import cv2
import numpy as np

img = cv2.imread("lane.png")
h, w = img.shape[:2]
# 두 차선이 이루는 사다리꼴: 왼쪽 아래, 오른쪽 아래, 오른쪽 위, 왼쪽 위
src = np.float32([[150, 479], [520, 479], [360, 250], [290, 250]])
dst = np.float32([[200, 479], [440, 479], [440, 0], [200, 0]])
H = cv2.getPerspectiveTransform(src, dst)
bird = cv2.warpPerspective(img, H, (w, h))

np.set_printoptions(precision=4, suppress=True)
print("H =\n", H.round(4) + 0.0)
check = cv2.perspectiveTransform(src.reshape(-1, 1, 2), H).reshape(-1, 2)
print("src 네 점의 변환 결과:\n", check.round(1) + 0.0)
cv2.polylines(img, [src.astype(np.int32)], True, (0, 0, 255), 2)
cv2.imshow("lane + ROI", img)
cv2.imshow("bird's-eye", bird)
```

```text
H =
 [[ -0.932   -1.5872 612.7251]
 [  0.      -3.0054 751.3566]
 [  0.      -0.0051   1.    ]]
src 네 점의 변환 결과:
 [[200. 479.]
 [440. 479.]
 [440.   0.]
 [200.   0.]]
```

네 점이 정확히 `dst` 위치로 옮겨졌는지 확인하는 것이 원근 변환 디버깅의 첫 단계입니다. 이 기법은 A09(차선 유지)에서 차선 곡률을 계산할 때 다시 씁니다.

### remap: 좌표 표를 직접 주는 변환

`cv2.remap(img, map_x, map_y, interpolation)`은 출력 픽셀 $(i, j)$의 값을 원본의 `(map_x[i, j], map_y[i, j])`에서 가져옵니다. 행렬로 표현할 수 없는 변환(렌즈 왜곡 보정, 어안 펼치기)도 가능합니다. 원본 교재는 이중 `for` 반복문으로 표를 채우지만, NumPy로 한 번에 만들면 수백 배 빠릅니다.

```python
ys, xs = np.indices((h, w), dtype=np.float32)       # 각 픽셀의 (행, 열) 좌표 표
flip_lr = cv2.remap(img, (w - 1) - xs, ys, cv2.INTER_LINEAR)   # 좌우 뒤집기 (= cv2.flip(img, 1))
half = cv2.remap(img, xs, 2 * ys, cv2.INTER_LINEAR)           # 위쪽 절반에 세로로 압축
```

## 스무딩 (Smoothing)

카메라 영상에는 두 종류의 잡음이 섞입니다.

- **소금-후추 잡음(salt-and-pepper)**: 무작위 위치의 픽셀이 0 또는 255로 튀는 점 잡음. 전송 오류·불량 화소에서 생깁니다.
- **가우시안 잡음(Gaussian)**: 모든 픽셀에 정규분포 오차가 더해지는 잡음. 어두운 곳에서 센서 증폭(ISO)을 높이면 커집니다.

스무딩은 신호의 **고주파 성분(급한 변화)을 줄이고 저주파 성분을 남기는** 필터입니다. 커널(kernel) 창을 한 픽셀씩 옮기며 창 안의 값으로 가운데 픽셀을 새로 계산합니다.

| 필터 | 가운데 픽셀 = | 함수 | 장점 | 단점 |
|---|---|---|---|---|
| 평균 (mean) | 창 안의 산술 평균 | `cv2.blur(img, (k, k))` | 가장 단순·빠름 | 엣지가 흐려짐, 점 잡음이 번짐 |
| 가우시안 | 거리에 따른 가우스 가중 평균 | `cv2.GaussianBlur(img, (k, k), σ)` | 자연스러운 흐림, 가우시안 잡음에 적합 | 엣지가 흐려짐 |
| 미디언 (median) | 창 안 값의 **중앙값** | `cv2.medianBlur(img, k)` | 소금-후추 잡음 제거에 탁월, 엣지 보존 | 계산량 큼, 가는 선이 사라질 수 있음 |
| 양방향 (bilateral) | 거리 **와** 밝기 차이로 가중 | `cv2.bilateralFilter(img, d, σc, σs)` | 엣지 보존하며 평탄화 | 느림 |

예를 들어 3×3 창의 값이 `[12, 15, 13, 14, 255, 16, 11, 14, 13]`(가운데 255는 튄 점)이면 평균은 40.3이라 점이 **주변으로 번지고**, 중앙값은 14라 점이 **사라집니다**. 커널 크기 `k`는 홀수여야 하며, 클수록 더 흐려집니다. 가우시안의 `σ`를 0으로 주면 커널 크기에서 자동으로 계산합니다. MentorPi 예제는 대부분 `cv2.GaussianBlur(img, (3, 3), 3)`으로 가볍게 흐린 뒤 색 임계값을 겁니다.

```python run
import cv2
import numpy as np

rng = np.random.default_rng(0)
clean = np.full((120, 160), 60, np.uint8)
cv2.rectangle(clean, (40, 30), (120, 90), 200, -1)            # 밝은 사각형 하나

noisy = clean.copy()
r = rng.random(clean.shape)
noisy[r < 0.05] = 0                                            # 후추 5 %
noisy[r > 0.95] = 255                                          # 소금 5 %

def err(img):
    return np.abs(img.astype(int) - clean.astype(int)).mean()

results = {
    "noisy": noisy,
    "blur 5x5": cv2.blur(noisy, (5, 5)),
    "gauss 5x5": cv2.GaussianBlur(noisy, (5, 5), 0),
    "median 5": cv2.medianBlur(noisy, 5),
    "bilateral": cv2.bilateralFilter(noisy, 9, 75, 75),
}
for name, img in results.items():
    edge = int(img[60, 38]) - int(img[60, 42])                 # 사각형 왼쪽 경계의 밝기 차
    print("%-10s 평균 오차 %5.1f   경계 대비 %4d" % (name, err(img), edge))
cv2.imshow("noisy | median", np.hstack([noisy, results["median 5"]]))
```

```text
noisy      평균 오차  12.9   경계 대비 -140
blur 5x5   평균 오차  10.8   경계 대비 -109
gauss 5x5  평균 오차  10.8   경계 대비 -116
median 5   평균 오차   0.2   경계 대비 -140
bilateral  평균 오차   9.2   경계 대비 -136
```

미디언 필터가 오차를 가장 크게 줄이고 경계 대비도 원래 값(−140)에 가깝게 지킵니다. 평균·가우시안은 튄 점을 주변에 퍼뜨려 오차가 남고 경계도 무뎌집니다. 소금-후추 잡음에는 미디언, 전체적인 자글자글한 잡음에는 가우시안이 기본 선택입니다.

새 터미널에서 아래 노드를 `~/hsv_tuner.py`로 저장해 실행합니다. 트랙바를 움직여 원하는 물체만 흰색이 되게 맞추고, `p` 키로 현재 범위를 출력합니다.

```python robot
import cv2
import rclpy
from rclpy.node import Node
from cv_bridge import CvBridge
from sensor_msgs.msg import Image

WIN = 'mask'
NAMES = ['H_min', 'S_min', 'V_min', 'H_max', 'S_max', 'V_max']
INIT = [0, 120, 70, 10, 255, 255]


class HsvTuner(Node):
    def __init__(self):
        super().__init__('hsv_tuner')
        self.bridge = CvBridge()
        cv2.namedWindow(WIN)
        for n, v in zip(NAMES, INIT):
            cv2.createTrackbar(n, WIN, v, 179 if n.startswith('H') else 255, lambda _: None)
        self.create_subscription(Image, '/ascamera/camera_publisher/rgb0/image', self.on_image, 1)

    def on_image(self, msg):
        frame = cv2.resize(self.bridge.imgmsg_to_cv2(msg, 'bgr8'), (320, 240))
        hsv = cv2.cvtColor(cv2.GaussianBlur(frame, (3, 3), 3), cv2.COLOR_BGR2HSV)
        v = [cv2.getTrackbarPos(n, WIN) for n in NAMES]
        mask = cv2.inRange(hsv, tuple(v[:3]), tuple(v[3:]))
        cv2.imshow('frame', frame)
        cv2.imshow(WIN, mask)
        key = cv2.waitKey(1) & 0xFF
        if key == ord('p'):
            self.get_logger().info('lower=%s upper=%s' % (v[:3], v[3:]))
        elif key == ord('q'):
            raise KeyboardInterrupt


def main():
    rclpy.init()
    node = HsvTuner()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        cv2.destroyAllWindows()
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 빨강이 반쪽만 잡힘 | H가 0 근처와 179 근처로 나뉨 | 두 구간 `inRange` 결과를 `bitwise_or`로 합치기 |
| HSV 도구의 값을 넣었는데 전혀 안 잡힘 | 다른 프로그램은 H를 0~360, S·V를 0~100 %로 표시 | OpenCV 범위로 변환: H/2, S·V × 2.55 |
| 흰색·회색 벽이 특정 색으로 잡힘 | 채도가 낮으면 H 값이 불안정 | S 최소값을 올림(예: 80 이상) |
| `resize` 결과가 가로세로 뒤바뀜 | `dsize`에 `(높이, 너비)`를 넣음 | `dsize`는 `(너비, 높이)`, `shape`는 `(높이, 너비)` |
| 회전 후 모서리가 잘림 | 출력 크기를 원본과 같게 둠 | 회전된 네 꼭짓점의 경계 상자를 구해 `dsize`와 행렬의 이동 항을 키움 |
| `getPerspectiveTransform` 오류 | 점이 `float32`가 아니거나 4개가 아님, 세 점이 한 직선 위 | `np.float32`로 정확히 4점, 네 점이 사각형을 이루게 |
| `GaussianBlur` Assertion 오류 | 커널 크기가 짝수 | `(3, 3)`, `(5, 5)`처럼 홀수 |
