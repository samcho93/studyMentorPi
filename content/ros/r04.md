## 학습 목표

- 토픽·서비스·액션을 "응답이 필요한가, 오래 걸리는가, 중간 경과가 필요한가"로 구분해 알맞은 통신 방식을 고릅니다.
- `create_service`/`create_client`로 서비스 서버와 클라이언트를 만들고, `call_async` + `spin_until_future_complete`로 결과를 받습니다.
- `ActionServer`/`ActionClient`로 목표(goal) → 피드백(feedback) → 결과(result)가 오가는 액션을 작성합니다.
- `.msg`·`.srv`·`.action` 파일을 정의하고 `ament_cmake` 인터페이스 패키지(`demo_interfaces`)로 빌드해 Python 노드에서 import합니다.
- MentorPi의 실제 서비스(`/controller/load_calibrate_param`)를 명령행에서 호출합니다.

## 세 가지 통신 방식

| | 토픽 | 서비스 | 액션 |
|---|---|---|---|
| 모델 | 발행/구독 | 요청/응답 (client/server) | 목표/피드백/결과 (+취소) |
| 방향 | 단방향 | 양방향, 1회 | 양방향, 여러 번 |
| 응답 | 없음 | 요청마다 1개 | 최종 결과 1개 + 피드백 여러 개 |
| 걸리는 시간 | — | **짧아야 함**(수 ms~수백 ms) | 수 초~수 분 |
| 도중 취소 | — | 불가 | 가능 |
| MentorPi 예 | `/cmd_vel`, `/odom`, `/scan` | `/controller/load_calibrate_param` | Nav2 `navigate_to_pose` |
| 정의 파일 | `.msg` | `.srv` (요청 `---` 응답) | `.action` (목표 `---` 결과 `---` 피드백) |

@fig[r04-comm] 시간축으로 본 서비스와 액션 — 서비스는 요청 하나에 응답 하나, 액션은 목표를 수락한 뒤 피드백을 여러 번 보내고 마지막에 결과를 보냅니다

판단 기준을 정리하면 다음과 같습니다.

- 계속 흐르는 데이터(센서, 속도 명령) → **토픽**
- "지금 이것 좀 해 줘/알려 줘"처럼 금방 끝나는 일(보정값 다시 읽기, 모드 전환, 계산) → **서비스**
- "저기까지 가", "이 파일 받아"처럼 오래 걸리고 진행률이 궁금하며 중간에 취소할 수 있어야 하는 일 → **액션**

액션은 내부적으로 서비스 3개(목표 보내기, 결과 받기, 취소)와 토픽 2개(피드백, 상태)로 구현됩니다. 새로운 통신 기술이 아니라 **토픽과 서비스를 조합한 약속**입니다.

## 서비스(Service)

서비스는 웹 브라우저와 웹 서버의 관계와 같습니다. 클라이언트가 요청(request)을 보내면 서버가 처리해 응답(response)을 돌려줍니다. 한 서비스 이름에는 서버가 **하나**만 있어야 하고, 클라이언트는 여럿일 수 있습니다.

### 서비스 정의: AddInts.srv

원본 `demo_interfaces/srv/AddInts.srv`입니다. `---` 위가 요청, 아래가 응답입니다.

```text
int32 num1
int32 num2
---
int32 sum
```

ROS 2에는 같은 역할의 표준 서비스 `example_interfaces/srv/AddTwoInts`(필드 `a`, `b` → `sum`, 타입 int64)가 있습니다. Playground는 이 표준 타입을 씁니다.

### 서버와 클라이언트의 흐름

서버는 `create_service(타입, 이름, 콜백)`으로 만들고, 콜백은 `(request, response)`를 받아 **response를 채워 반환**합니다. 클라이언트는 다음 순서입니다.

1. `cli = node.create_client(타입, 이름)`
2. `cli.wait_for_service(timeout_sec=1.0)`이 True가 될 때까지 기다림(서버 탐색)
3. `req = 타입.Request()`에 값을 채움
4. `future = cli.call_async(req)` — **즉시 반환**되는 "나중에 결과가 들어올 상자"
5. `rclpy.spin_until_future_complete(node, future)` — 응답이 올 때까지 콜백 처리
6. `future.result()`로 응답을 꺼냄

:::danger 콜백 안에서 서비스를 기다리지 말 것
타이머나 구독 콜백 **안에서** `spin_until_future_complete`나 동기 `call()`로 응답을 기다리면, 단일 스레드 실행기가 그 콜백에 붙잡혀 응답을 처리하지 못하고 **영원히 멈춥니다(교착, deadlock).** 콜백 안에서는 `call_async(req)` 후 `future.add_done_callback(함수)`로 결과를 나중에 받습니다.
:::

### MentorPi의 서비스 호출해 보기

`odom_publisher` 노드는 `std_srvs/srv/Trigger` 타입 서비스 `/controller/load_calibrate_param`을 제공합니다. M03에서 보정값(YAML)을 고친 뒤 **노드를 재시작하지 않고** 다시 읽게 할 때 씁니다.

```bash
ros2 service list -t | grep controller
ros2 interface show std_srvs/srv/Trigger          # 요청 없음 --- bool success, string message
ros2 service call /controller/load_calibrate_param std_srvs/srv/Trigger
```

## 액션(Action)

액션 한 번의 수명은 다음과 같습니다.

1. 클라이언트가 **목표(goal)** 를 보냄 → 서버가 수락(accept) 또는 거절(reject)
2. 수락되면 서버의 `execute_callback(goal_handle)`이 실행됨
3. 실행 중 `goal_handle.publish_feedback(fb)`로 **피드백**을 여러 번 보냄
4. 끝나면 `goal_handle.succeed()`(또는 `abort()`, 취소 시 `canceled()`) 후 **결과(result)** 를 반환
5. 클라이언트는 `get_result_async()`로 결과를 받음. 도중에 `cancel_goal_async()`로 취소 요청 가능

### 액션 정의: FileDownload.action

원본 `demo_interfaces/action/FileDownload.action`입니다. 구획이 세 개입니다.

```text
int32 file_size                 # 목표: 받을 파일 크기
---
int32 current_size              # 결과: 최종 크기
---
float32 completion_percentage   # 피드백: 진행률 %
```

원본 서버는 `while current_size < file_size:` 루프에서 무작위(1~10)로 크기를 늘리며 진행률을 피드백으로 보내고, 루프 안에서 `rclpy.spin_once(self, timeout_sec=1.0)`로 1초씩 시간을 보냅니다. 클라이언트는 `send_goal_async(goal, feedback_callback=...)` → `goal_response_callback` → `get_result_async()` → `get_result_callback`의 **콜백 사슬**로 결과를 받습니다.

Playground에는 같은 구조의 표준 액션 `example_interfaces/action/Fibonacci`(목표 `order`, 피드백·결과 `sequence`)가 있습니다.

## 커스텀 인터페이스 만들기

표준 타입으로 표현하기 어려운 데이터는 직접 정의합니다. **인터페이스 패키지는 `ament_cmake`로 따로** 만들고, 노드 패키지(ament_python)는 그것을 의존합니다.

### 필드 문법

| 형태 | 예 | 설명 |
|---|---|---|
| 기본형 | `bool`, `int32`, `uint8`, `float32`, `float64`, `string` | C++/Python 타입으로 자동 변환 |
| 다른 메시지 | `geometry_msgs/Point position` | 패키지/타입 이름 |
| 가변 배열 | `float32[] ranges` | Python에서 리스트(또는 array) |
| 고정 배열 | `float64[9] covariance` | 길이 고정 |
| 기본값 | `int32 age 18` | 필드 뒤에 값 |
| 상수 | `int32 MAX_SPEED=2` | 대문자 이름 = 값 |

파일 이름은 **대문자로 시작하는 CamelCase**(`Student.msg`), 필드 이름은 **소문자 snake_case**여야 합니다. 원본의 `Student.msg`는 `string name`, `int32 age`, `float64 height` 세 필드입니다.

### demo_interfaces 패키지

```bash
cd ~/hiwonder_ws/src
ros2 pkg create demo_interfaces --build-type ament_cmake
mkdir -p demo_interfaces/msg demo_interfaces/srv demo_interfaces/action
# msg/Student.msg, srv/AddInts.srv, action/FileDownload.action 작성
```

`CMakeLists.txt`에 생성기를 등록합니다(`ament_package()` 위).

```cmake
find_package(rosidl_default_generators REQUIRED)
rosidl_generate_interfaces(${PROJECT_NAME}
  "msg/Student.msg"
  "srv/AddInts.srv"
  "action/FileDownload.action"
)
```

`package.xml`에 빌드·실행 의존성과 그룹을 추가합니다. 액션이 있으면 `action_msgs`도 필요합니다.

```xml
<buildtool_depend>rosidl_default_generators</buildtool_depend>
<depend>action_msgs</depend>
<exec_depend>rosidl_default_runtime</exec_depend>
<member_of_group>rosidl_interface_packages</member_of_group>
```

빌드하면 C++ 헤더와 Python 모듈이 생성됩니다. 사용하는 쪽 패키지의 `package.xml`에 `<depend>demo_interfaces</depend>`를 넣고 `from demo_interfaces.srv import AddInts`로 import합니다.

```bash
cd ~/hiwonder_ws
colcon build --packages-select demo_interfaces
source install/setup.bash
ros2 interface show demo_interfaces/msg/Student
ros2 interface package demo_interfaces        # 세 인터페이스 목록
```

:::info Playground와 커스텀 인터페이스
브라우저 Playground는 `colcon`으로 인터페이스를 생성할 수 없어서, 아래 실습은 같은 모양의 **표준 인터페이스**(`AddTwoInts`, `Trigger`, `SetBool`, `Fibonacci`)로 합니다. 코드 구조는 `demo_interfaces`를 쓸 때와 똑같고, import 줄과 필드 이름만 다릅니다.
:::

### ① 덧셈 서비스: 서버와 클라이언트

실물에서는 서버와 클라이언트가 별도 프로세스지만, 여기서는 한 노드에 둘 다 만듭니다(단일 스레드 실행기에서도 `spin_until_future_complete`가 서버 콜백까지 처리하므로 동작합니다).

```python run
import rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts
import mentorpi_sim as sim                  # 시뮬 전용
sim.setup(world="empty", duration=5.0)     # 시뮬 전용


class AddServer(Node):
    def __init__(self):
        super().__init__('minimal_service')
        self.srv = self.create_service(AddTwoInts, 'add_two_ints', self.add_two_ints_callback)

    def add_two_ints_callback(self, request, response):
        response.sum = request.a + request.b
        self.get_logger().info('Incoming request a=%d b=%d' % (request.a, request.b))
        return response


rclpy.init()
node = AddServer()
cli = node.create_client(AddTwoInts, 'add_two_ints')
while not cli.wait_for_service(timeout_sec=1.0):
    node.get_logger().info('service is connecting...')

for a, b in [(1, 2), (40, 2), (-7, 10)]:
    req = AddTwoInts.Request()
    req.a, req.b = a, b
    future = cli.call_async(req)
    rclpy.spin_until_future_complete(node, future, timeout_sec=2.0)
    if future.done():
        print('%d + %d = %d' % (a, b, future.result().sum))
    else:
        print('응답 없음(시간 초과)')
node.destroy_node()
rclpy.shutdown()
```

예상 출력(대략):

```text
[INFO] [minimal_service]: Incoming request a=1 b=2
1 + 2 = 3
[INFO] [minimal_service]: Incoming request a=40 b=2
40 + 2 = 42
[INFO] [minimal_service]: Incoming request a=-7 b=10
-7 + 10 = 3
```

### ② 로봇 제어 서비스: SetBool로 주행 켜기/끄기, Trigger로 상태 조회

실제 로봇 앱들도 `~/enter`, `~/set_running` 같은 서비스로 기능을 켜고 끕니다. 같은 구조를 만들어 봅니다. 노드는 10 Hz로 `/cmd_vel`을 발행하되, `SetBool` 서비스로 `True`를 받았을 때만 전진합니다.

```python run
import time
import rclpy
from rclpy.node import Node
from std_srvs.srv import SetBool, Trigger
from geometry_msgs.msg import Twist
from nav_msgs.msg import Odometry
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(world="empty", duration=10.0, start=(0.0, 0.0, 0.0))  # 시뮬 전용


class MotionSwitch(Node):
    def __init__(self):
        super().__init__('motion_switch')
        self.running = False
        self.x = 0.0
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_subscription(Odometry, '/odom', self.on_odom, 10)
        self.create_service(SetBool, 'motion_switch/set_running', self.on_set_running)
        self.create_service(Trigger, 'motion_switch/status', self.on_status)
        self.create_timer(0.1, self.on_timer)

    def on_odom(self, msg):
        self.x = msg.pose.pose.position.x

    def on_set_running(self, req, res):
        self.running = req.data
        res.success, res.message = True, 'running=%s' % self.running
        return res

    def on_status(self, req, res):
        res.success, res.message = True, 'running=%s x=%.2f m' % (self.running, self.x)
        return res

    def on_timer(self):
        cmd = Twist()
        cmd.linear.x = 0.1 if self.running else 0.0
        self.pub.publish(cmd)


def call(node, cli, req):
    fut = cli.call_async(req)
    rclpy.spin_until_future_complete(node, fut, timeout_sec=2.0)
    return fut.result()


rclpy.init()
node = MotionSwitch()
set_cli = node.create_client(SetBool, '/motion_switch/set_running')
st_cli = node.create_client(Trigger, '/motion_switch/status')
set_cli.wait_for_service(timeout_sec=2.0)
print('시작  :', call(node, st_cli, Trigger.Request()).message)
print('켜기  :', call(node, set_cli, SetBool.Request(data=True)).message)
t0 = time.time()
while time.time() - t0 < 3.0:
    rclpy.spin_once(node, timeout_sec=0.1)
print('3초 후:', call(node, st_cli, Trigger.Request()).message)
print('끄기  :', call(node, set_cli, SetBool.Request(data=False)).message)
t0 = time.time()
while time.time() - t0 < 1.0:
    rclpy.spin_once(node, timeout_sec=0.1)
print('정지 후:', call(node, st_cli, Trigger.Request()).message)
node.pub.publish(Twist())
node.destroy_node()
rclpy.shutdown()
```

예상 출력(대략):

```text
시작  : running=False x=0.00 m
켜기  : running=True
3초 후: running=True x=0.30 m
끄기  : running=False
정지 후: running=False x=0.31 m
```

서비스 이름을 `노드이름/기능`으로 지은 것은 공식 앱의 관례를 따른 것입니다. 실물 rclpy에서는 **private 이름** `'~/set_running'`으로 써도 노드 이름이 붙어 똑같이 `/motion_switch/set_running`이 됩니다. 실물에서는 `ros2 service call /motion_switch/set_running std_srvs/srv/SetBool "{data: true}"`로 똑같이 켤 수 있습니다.

### ③ 피보나치 액션: 피드백과 결과

원본 FileDownload 액션과 같은 구조입니다. 서버는 0.2초마다 수열을 하나씩 늘려 피드백으로 보내고, 클라이언트는 피드백 콜백으로 진행 상황을 봅니다.

```python run
import time
import rclpy
from rclpy.node import Node
from rclpy.action import ActionServer, ActionClient
from example_interfaces.action import Fibonacci
import mentorpi_sim as sim                  # 시뮬 전용
sim.setup(world="empty", duration=10.0)    # 시뮬 전용


class FibServer(Node):
    def __init__(self):
        super().__init__('fibonacci_server')
        self._server = ActionServer(self, Fibonacci, 'fibonacci', self.execute_callback)

    def execute_callback(self, goal_handle):
        order = goal_handle.request.order
        self.get_logger().info('목표 수신: order=%d' % order)
        fb = Fibonacci.Feedback()
        fb.sequence = [0, 1]
        for i in range(1, order):
            fb.sequence.append(fb.sequence[i] + fb.sequence[i - 1])
            goal_handle.publish_feedback(fb)
            time.sleep(0.2)                     # 오래 걸리는 작업 흉내
        goal_handle.succeed()
        result = Fibonacci.Result()
        result.sequence = fb.sequence
        return result


def on_feedback(fb_msg):
    print('피드백:', list(fb_msg.feedback.sequence))


rclpy.init()
node = FibServer()
client = ActionClient(node, Fibonacci, 'fibonacci')
client.wait_for_server()
goal = Fibonacci.Goal()
goal.order = 6
send_future = client.send_goal_async(goal, feedback_callback=on_feedback)
rclpy.spin_until_future_complete(node, send_future)
goal_handle = send_future.result()
print('수락됨:', goal_handle.accepted)
result_future = goal_handle.get_result_async()
rclpy.spin_until_future_complete(node, result_future)
print('결과:', list(result_future.result().result.sequence))
node.destroy_node()
rclpy.shutdown()
```

예상 출력(대략, 피드백과 로그의 순서는 실행 환경에 따라 섞일 수 있음):

```text
수락됨: True
[INFO] [fibonacci_server]: 목표 수신: order=6
피드백: [0, 1, 1]
피드백: [0, 1, 1, 2]
피드백: [0, 1, 1, 2, 3]
피드백: [0, 1, 1, 2, 3, 5]
피드백: [0, 1, 1, 2, 3, 5, 8]
결과: [0, 1, 1, 2, 3, 5, 8]
```

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `service is connecting...`이 계속 출력 | 서버 미실행, 이름 불일치(`add_two_ints` vs `/add_two_ints_srv`) | `ros2 service list -t`로 이름·타입 확인 |
| 프로그램이 응답을 기다리며 멈춤 | 콜백 안에서 `spin_until_future_complete`/`call()` 사용 → 교착 | 콜백 안에서는 `call_async` + `add_done_callback` |
| `ModuleNotFoundError: No module named 'demo_interfaces'` | 인터페이스 패키지 빌드·source 안 함, `package.xml` 의존성 누락 | `colcon build --packages-select demo_interfaces` 후 source, `<depend>` 추가 |
| 인터페이스 빌드 오류 `is not a valid message name` | 파일명이 소문자로 시작 또는 필드명에 대문자 | `Student.msg`, 필드는 `snake_case` |
| `rosidl_generate_interfaces` 관련 CMake 오류 | `find_package(rosidl_default_generators REQUIRED)` 누락, `<member_of_group>` 누락 | CMakeLists·package.xml 두 곳 모두 확인 |
| 액션 결과가 `None` 또는 속성 오류 | `future.result()`가 GetResult 응답 래퍼임 | 결과는 `future.result().result.필드`, 피드백은 `fb_msg.feedback.필드` |
| 액션 서버가 피드백을 보내는데 클라이언트에 한꺼번에 도착 | 단일 스레드 실행기에서 execute_callback이 실행기를 붙잡음 | 실물에서는 서버와 클라이언트를 **다른 프로세스**로 실행하거나 MultiThreadedExecutor 사용 |
| `ros2 service call` YAML 오류 | 필드 이름 틀림(`num1` vs `a`) | `ros2 interface show`로 필드 이름 확인 |

## 과제

:::task 기본 과제
1. `demo_interfaces`에 `srv/Distance.srv`(요청 `float64 x`, `float64 y` / 응답 `float64 distance`)를 추가하고, 원점까지의 거리를 계산하는 서버를 만들어 `ros2 service call`로 시험합니다.
2. ②를 고쳐 `Trigger` 서비스 `motion_switch/reset`을 추가합니다. 호출하면 누적 주행 거리를 0으로 되돌리고 `message`에 이전 거리값을 담아 돌려줍니다.
:::

:::task 심화 과제
3. "지정 거리만큼 전진" 동작을 액션처럼 설계합니다. 목표(거리 m), 피드백(남은 거리), 결과(실제 이동 거리)를 갖는 `DriveDistance.action`을 정의하고, 실물에서 `/odom`을 보며 목표에 도달하면 멈추는 서버를 작성합니다. 취소 요청이 오면 즉시 정지하도록 합니다.
4. 원본 `action_server.py`는 execute 루프 안에서 `rclpy.spin_once(self, ...)`를 호출합니다. 이 방식의 문제점(재진입, 다른 콜백 실행 순서)을 조사하고 `time.sleep` 또는 `rate`를 쓰는 방식과 비교해 정리합니다.
:::
