## 학습 목표

- 워크스페이스의 네 폴더(`src`, `build`, `install`, `log`)의 역할과 **언더레이(underlay)/오버레이(overlay)** 관계를 설명합니다.
- `ros2 pkg create --build-type ament_python`으로 패키지를 만들고, `package.xml`·`setup.py`·`setup.cfg`가 각각 무엇을 정하는지 말할 수 있습니다.
- `setup.py`의 `entry_points`에 실행 진입점을 등록하고 `colcon build` → `source` → `ros2 run`으로 노드를 실행합니다.
- `rclpy.init()` → `Node` 생성 → `spin()` → `destroy_node()` → `shutdown()`으로 이어지는 노드 수명주기를 코드로 작성합니다.
- `while` + `sleep` 루프 대신 **타이머 콜백**을 써야 하는 이유(실행기·콜백 처리)를 실험으로 확인합니다.

## 워크스페이스(Workspace)

로봇 기능 하나를 개발하려면 소스 코드, 설정 파일, launch 파일, 모델 파일이 함께 필요합니다. ROS에서는 이런 파일들을 **워크스페이스**라는 폴더 하나에 모아 관리하고 한꺼번에 빌드합니다. 원본 교재는 `~/hiwonder_ws`라는 이름을 씁니다(이름은 자유).

```bash
mkdir -p ~/hiwonder_ws/src      # src 폴더까지 한 번에 생성
cd ~/hiwonder_ws
colcon build                    # 빈 워크스페이스도 빌드된다 → build/ install/ log/ 생성
source ~/hiwonder_ws/install/setup.bash
tree -L 1                       # (sudo apt-get install tree 필요)
```

| 폴더 | 이름 | 내용 | 직접 손대나? |
|---|---|---|---|
| `src/` | 소스 공간 | 패키지 소스. **여기에서만 작업** | 예 |
| `build/` | 빌드 공간 | 빌드 중간 산출물 | 아니오 (문제 생기면 통째로 삭제) |
| `install/` | 설치 공간 | 실행 파일·라이브러리·`setup.bash` | 아니오 (`source`만) |
| `log/` | 로그 공간 | 빌드·테스트 로그 | 오류 분석할 때만 |

@fig[r02-workspace] 워크스페이스 구조와 빌드·실행 흐름 — src에서 작성하고, colcon이 install을 만들고, source로 셸에 등록한 뒤 ros2 run으로 실행합니다

### 언더레이와 오버레이

`source`는 "이 워크스페이스의 패키지를 찾을 수 있게 환경변수(`AMENT_PREFIX_PATH`, `PYTHONPATH` 등)에 경로를 추가"하는 일입니다. 순서가 중요합니다.

1. `/opt/ros/humble` — ROS 2 자체(언더레이)
2. `~/ros2_ws` — MentorPi 공식 패키지(오버레이 1)
3. `~/hiwonder_ws` — 내가 만든 패키지(오버레이 2)

**나중에 source한 워크스페이스가 앞선 것을 덮습니다.** 같은 이름의 패키지가 두 곳에 있으면 마지막 것이 쓰입니다. 공식 패키지를 고쳐 쓰고 싶을 때 원본을 건드리지 않고 내 워크스페이스에 같은 이름으로 복사하는 방법이 이것입니다.

:::tip 매번 source하기 귀찮다면
`echo "source ~/hiwonder_ws/install/setup.bash" >> ~/.bashrc` 로 등록해 두면 새 터미널마다 자동으로 실행됩니다. 단, **빌드 직후 이미 열려 있던 터미널**은 다시 source해야 새 실행 파일이 보입니다.
:::

워크스페이스는 여러 개 둘 수 있습니다(로봇 A용 `ws_a`, 로봇 B용 `ws_b`). IDE에서 프로젝트를 여러 개 만드는 것과 같습니다.

### colcon build 옵션

| 명령 | 용도 |
|---|---|
| `colcon build` | `src/` 아래 모든 패키지를 의존성 순서대로 빌드 |
| `colcon build --packages-select topic_demo` | 한 패키지만 빌드(시간 절약) |
| `colcon build --symlink-install` | Python 파일을 복사하지 않고 링크 → **소스를 고쳐도 재빌드 불필요** |
| `colcon build --packages-up-to app` | 해당 패키지와 그것이 의존하는 패키지까지 |
| `rm -rf build install log` | 빌드가 꼬였을 때 초기화(반드시 워크스페이스 최상위에서) |

:::warning 빌드는 워크스페이스 최상위에서
`src/` 안이나 패키지 폴더 안에서 `colcon build`를 실행하면 그 자리에 `build/ install/ log/`가 또 생깁니다. 항상 `cd ~/hiwonder_ws` 후에 빌드합니다.
:::

## 패키지(Package)

로봇에는 섀시 제어, 비전, 내비게이션 같은 기능이 여럿 있습니다. 이것을 한 폴더에 섞어 두면 일부만 떼어 다른 사람에게 주기 어렵습니다. **패키지**는 기능 단위로 코드를 나눠 결합도를 낮추고 재사용하게 해 주는 단위입니다. MentorPi의 `~/ros2_ws/src`에도 `app`, `bringup`, `driver/controller`, `peripherals`, `navigation`, `slam` 같은 패키지가 나뉘어 있습니다.

### 빌드 타입

| 빌드 타입 | 언어 | 빌드 설정 파일 | 쓰임 |
|---|---|---|---|
| `ament_python` | Python | `setup.py`, `setup.cfg` | 이 강의의 노드 대부분 |
| `ament_cmake` | C++ (또는 인터페이스) | `CMakeLists.txt` | C++ 노드, **`.msg/.srv/.action` 정의 패키지**(R04) |

### 패키지 만들기

```bash
cd ~/hiwonder_ws/src
ros2 pkg create hello_world_demo --build-type ament_python \
    --dependencies rclpy --node-name hello_world
```

`--node-name`을 주면 `hello_world.py` 뼈대와 진입점 등록까지 자동으로 해 줍니다. 만들어진 구조는 다음과 같습니다.

```text
hello_world_demo/
├── hello_world_demo/          ← Python 모듈(노드 소스가 여기)
│   ├── __init__.py
│   └── hello_world.py
├── package.xml                ← 매니페스트: 이름·버전·관리자·라이선스·의존성
├── resource/hello_world_demo  ← ament 인덱스용 표식 파일(빈 파일)
├── setup.cfg                  ← 실행 파일 설치 위치(lib/<패키지>)
├── setup.py                   ← 설치 규칙과 entry_points
└── test/                      ← flake8·pep257 등 테스트
```

### package.xml과 setup.py

`package.xml`의 `<depend>rclpy</depend>`처럼 적은 의존성은 `rosdep`이 설치하고, `colcon`이 빌드 순서를 정하는 데 씁니다. 새 메시지 패키지를 import하면(예: `geometry_msgs`) 여기에도 추가해야 다른 컴퓨터에서 빌드가 됩니다.

```xml
<depend>rclpy</depend>
<depend>std_msgs</depend>
<depend>geometry_msgs</depend>
```

`setup.py`의 핵심은 **entry_points**입니다. `실행파일이름 = 패키지.모듈:함수` 형식으로, `ros2 run <패키지> <실행파일이름>`을 입력하면 그 모듈의 함수(보통 `main`)가 호출됩니다.

```python
entry_points={
    'console_scripts': [
        'hello_world = hello_world_demo.hello_world:main',
        'topic_pub = topic_demo.topic_pub:main',      # 다음 챕터에서 추가하는 형태
    ],
},
```

launch 파일, YAML 설정, URDF처럼 **Python 모듈이 아닌 파일**은 `data_files`에 적어야 `install/<패키지>/share/<패키지>/`로 복사됩니다(R05·R06).

```python
import os
from glob import glob
data_files=[
    ('share/ament_index/resource_index/packages', ['resource/' + package_name]),
    ('share/' + package_name, ['package.xml']),
    (os.path.join('share', package_name, 'launch'), glob(os.path.join('launch', '*.launch.py'))),
],
```

## 노드(Node)

**노드는 ROS 2 통신의 주체**입니다. 토픽·서비스·액션·파라미터는 모두 어떤 노드에 속해 만들어집니다. 보통 노드 하나가 기능 하나(라이다 드라이버, 카메라 드라이버 …)를 맡고, 실행 파일 하나에 노드가 하나 이상 들어갈 수 있습니다.

### rclpy 노드의 수명주기

| 단계 | 코드 | 하는 일 |
|---|---|---|
| ① 초기화 | `rclpy.init(args=args)` | 컨텍스트 생성, 명령행 ROS 인자(`--ros-args`) 해석 |
| ② 노드 생성 | `node = MyNode()` → `super().__init__('이름')` | DDS 참여자 생성, 이름 등록 |
| ③ 통신 객체 | `create_publisher / create_subscription / create_timer ...` | 그래프에 연결 |
| ④ 실행 | `rclpy.spin(node)` | **실행기(executor)** 가 도착한 메시지·만료된 타이머의 콜백을 차례로 호출 |
| ⑤ 정리 | `node.destroy_node()`, `rclpy.shutdown()` | 연결 해제, 자원 반납 |

④가 핵심입니다. rclpy는 **콜백 기반**입니다. 메시지가 도착해도 누군가 `spin`(또는 `spin_once`)을 돌려 주지 않으면 콜백은 호출되지 않습니다.

### while 루프 대신 타이머를 쓰는 이유

원본 `hello_world.py`는 `while rclpy.ok(): log(); time.sleep(0.5)`로 작성되어 있습니다. 로그만 찍을 때는 문제가 없지만, 이 노드에 구독자를 하나 추가하는 순간 문제가 드러납니다. `while` 루프가 스레드를 붙잡고 있어 **spin이 한 번도 돌지 않으므로 구독 콜백이 영원히 호출되지 않습니다.**

| 방식 | 구조 | 구독·서비스 콜백 | 권장 |
|---|---|---|---|
| `while` + `time.sleep` | 사용자가 루프를 소유 | 호출 안 됨 (따로 `spin_once` 필요) | 아주 단순한 예제만 |
| `while` + `rclpy.spin_once(node, timeout_sec=...)` | 사용자가 루프를 소유, 틈틈이 콜백 처리 | 처리됨 | 순차 절차(“3초 전진 후 정지”)에 편리 |
| `create_timer` + `rclpy.spin` | 실행기가 루프를 소유 | 처리됨 | **기본 형태** |

### ① 타이머 두 개와 로그 레벨

타이머는 여러 개 만들 수 있고, 주기가 서로 달라도 실행기가 알아서 순서를 맞춥니다. `get_clock().now()`로 노드 시계를 읽는 법도 함께 봅니다.

```python run
import rclpy
from rclpy.node import Node
import mentorpi_sim as sim                     # 시뮬 전용
sim.setup(world="empty", duration=3.2)        # 시뮬 전용


class TwoTimers(Node):
    def __init__(self):
        super().__init__('two_timers')
        self.fast = 0
        self.slow = 0
        self.t0 = self.get_clock().now().nanoseconds
        self.create_timer(0.2, self.on_fast)     # 5 Hz
        self.create_timer(1.0, self.on_slow)     # 1 Hz

    def elapsed(self):
        return (self.get_clock().now().nanoseconds - self.t0) / 1e9

    def on_fast(self):
        self.fast += 1
        self.get_logger().debug('fast %d' % self.fast)   # 기본 레벨(INFO)에서는 안 보임

    def on_slow(self):
        self.slow += 1
        self.get_logger().info('t=%.1f s  fast=%d  slow=%d' % (self.elapsed(), self.fast, self.slow))
        if self.fast < 4 * self.slow:
            self.get_logger().warn('fast 타이머가 밀리고 있습니다')


rclpy.init()
node = TwoTimers()
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    print('합계: fast=%d, slow=%d' % (node.fast, node.slow))
    node.destroy_node()
    rclpy.shutdown()
```

예상 출력(대략):

```text
[INFO] [two_timers]: t=1.0 s  fast=5  slow=1
[INFO] [two_timers]: t=2.0 s  fast=10  slow=2
[INFO] [two_timers]: t=3.0 s  fast=15  slow=3
합계: fast=15, slow=3
```

`debug` 로그는 보이지 않습니다. 실물에서는 `ros2 run hello_world_demo hello_world --ros-args --log-level debug`로 레벨을 낮추면 나타납니다.

### ② 블로킹 루프 실험: spin이 없으면 콜백도 없다

같은 3초 동안 `/odom`을 구독하면서, 앞 절반은 `time.sleep`만 하고 뒤 절반은 `spin_once`를 돌려 받은 메시지 수를 비교합니다.

```python run
import time
import rclpy
from rclpy.node import Node
from nav_msgs.msg import Odometry
import mentorpi_sim as sim                     # 시뮬 전용
sim.setup(world="room", duration=10.0)        # 시뮬 전용

rclpy.init()
node = Node('blocking_test')
got = {'n': 0}

def on_odom(msg):
    got['n'] += 1

node.create_subscription(Odometry, '/odom', on_odom, 10)

# (가) sleep만 하는 루프 — 원본 hello_world의 방식
t0 = time.time()
while time.time() - t0 < 1.5:
    time.sleep(0.1)
print('(가) sleep 루프 1.5 s 동안 받은 /odom:', got['n'])

# (나) spin_once를 돌리는 루프
got['n'] = 0
t0 = time.time()
while time.time() - t0 < 1.5:
    rclpy.spin_once(node, timeout_sec=0.1)
print('(나) spin_once 루프 1.5 s 동안 받은 /odom:', got['n'])

node.destroy_node()
rclpy.shutdown()
```

예상 출력(대략):

```text
(가) sleep 루프 1.5 s 동안 받은 /odom: 0
(나) spin_once 루프 1.5 s 동안 받은 /odom: 80
```

(나)는 /odom이 50 Hz이므로 약 75~85개입니다(루프 경계에 따라 조금 다름). (가)에서 0이 나오는 것은 버그가 아니라 **rclpy의 설계**입니다. 콜백은 실행기가 호출할 때만 실행됩니다.

### ③ 패키지 진입점 모양 그대로 쓰기

`ros2 run`이 부르는 것은 `setup.py`에 등록한 `main(args=None)` 함수입니다. 실물 패키지에 그대로 넣을 수 있는 모양으로 작성해 봅니다. 노드 이름을 인자로 받게 하면 같은 클래스로 여러 노드를 만들 수 있습니다.

```python run
import rclpy
from rclpy.node import Node
import mentorpi_sim as sim                     # 시뮬 전용
sim.setup(world="empty", duration=2.2)        # 시뮬 전용


class HelloWorldNode(Node):
    def __init__(self, name):
        super().__init__(name)
        self.n = 0
        self.timer = self.create_timer(0.5, self.timer_callback)

    def timer_callback(self):
        self.n += 1
        self.get_logger().info('Hello World (%d)' % self.n)
        if self.n == 3:
            self.get_logger().info('3번 출력했으므로 타이머를 멈춥니다')
            self.timer.cancel()


def main(args=None):
    rclpy.init(args=args)
    node = HelloWorldNode('hello_world_demo')
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()
        print('rclpy.ok() =', rclpy.ok())


if __name__ == '__main__':
    main()
```

예상 출력(대략):

```text
[INFO] [hello_world_demo]: Hello World (1)
[INFO] [hello_world_demo]: Hello World (2)
[INFO] [hello_world_demo]: Hello World (3)
[INFO] [hello_world_demo]: 3번 출력했으므로 타이머를 멈춥니다
rclpy.ok() = False
```

:::check 체크포인트
- [ ] `hello_world = hello_world_demo.hello_world:main`의 세 부분이 각각 무엇인지 말할 수 있다.
- [ ] ② 실험에서 (가)가 0인 이유를 "실행기"라는 단어를 써서 설명할 수 있다.
- [ ] `timer.cancel()` 뒤에도 노드는 살아 있고 spin은 계속된다는 것을 확인했다.
:::

## 실습 (실물)

:::safety
- 이 실습은 로봇을 움직이지 않지만, 공식 앱이 자동 실행 중이면 조이스틱·앱 명령으로 **로봇이 움직일 수 있습니다.** 로봇을 받침대 위에 두거나 `~/.stop_ros.sh`로 자동 실행을 멈춘 뒤 진행합니다.
- `rm -rf build install log`는 반드시 `~/hiwonder_ws`에서만 실행합니다. `~/ros2_ws`(공식 워크스페이스)에서 실행하면 공식 기능을 다시 빌드해야 합니다.
:::

1. 컨테이너 터미널에서 워크스페이스와 패키지를 만듭니다.

```bash
mkdir -p ~/hiwonder_ws/src && cd ~/hiwonder_ws/src
ros2 pkg create hello_world_demo --build-type ament_python --dependencies rclpy --node-name hello_world
```

2. 노드 파일을 Playground ③의 코드로 바꿉니다(`import mentorpi_sim`, `sim.setup` 두 줄은 지웁니다).

```bash
vim ~/hiwonder_ws/src/hello_world_demo/hello_world_demo/hello_world.py
```

3. `setup.py`의 `console_scripts`에 `'hello_world = hello_world_demo.hello_world:main'`이 있는지 확인합니다(`--node-name`을 썼다면 이미 있음).
4. 빌드하고 실행합니다.

```bash
cd ~/hiwonder_ws
colcon build --packages-select hello_world_demo --symlink-install
source install/setup.bash
ros2 run hello_world_demo hello_world
```

5. 다른 터미널에서 노드를 관찰하고, 실행 인자로 이름과 로그 레벨을 바꿔 봅니다.

```bash
ros2 node list                                      # /hello_world_demo
ros2 pkg executables hello_world_demo               # hello_world_demo hello_world
ros2 pkg prefix hello_world_demo                    # ~/hiwonder_ws/install/hello_world_demo
ros2 run hello_world_demo hello_world --ros-args -r __node:=hello2 --log-level debug
```

6. 공식 워크스페이스도 둘러봅니다. 앞으로 볼 기능 패키지들의 위치입니다.

```bash
ls ~/ros2_ws/src
ros2 pkg executables controller
```

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `Package 'hello_world_demo' not found` | 빌드 후 `source install/setup.bash`를 안 함, 또는 다른 터미널 | 워크스페이스 최상위에서 `source install/setup.bash` |
| `No executable found` | `setup.py`의 `console_scripts`에 등록 안 함 / 오타 / 등록 후 재빌드 안 함 | 진입점 확인 후 `colcon build` 다시 |
| `ModuleNotFoundError: No module named 'hello_world_demo.hello_world'` | 파일 이름·폴더 이름과 진입점의 모듈 경로 불일치 | `패키지폴더/패키지폴더/파일.py` 구조와 `패키지.파일:main` 맞추기 |
| 소스를 고쳤는데 실행 결과가 그대로 | `--symlink-install` 없이 빌드 → install에 복사본이 있음 | 다시 빌드하거나 `--symlink-install`로 빌드 |
| `src/` 안에 `build/ install/`이 또 생김 | 잘못된 위치에서 `colcon build` | 잘못 생긴 폴더를 지우고 `cd ~/hiwonder_ws`에서 빌드 |
| `colcon build` 중 `setup.py install is deprecated` 경고 | Humble의 setuptools 버전 경고 | 동작에는 영향 없음. 무시해도 됨 |
| 구독 콜백이 한 번도 불리지 않음 | `while`+`sleep` 루프가 spin을 막음 | 타이머 + `spin`, 또는 루프 안에서 `spin_once` |
| Ctrl+C 때 `ExternalShutdownException`/스택 트레이스 | `shutdown()`을 두 번 호출하거나 예외 처리 없음 | `try/except KeyboardInterrupt/finally` 구조 사용 |

## 과제

:::task 기본 과제
1. `hello_world_demo` 패키지에 두 번째 실행 파일 `counter`를 추가합니다. 1 Hz로 1부터 세며 5가 되면 `warn` 로그를 남기고, 10이 되면 스스로 `rclpy.shutdown()`을 호출해 종료합니다. `setup.py` 등록부터 `ros2 run`까지 수행하고 터미널 출력을 캡처합니다.
2. `package.xml`에 `<depend>std_msgs</depend>`를 추가하고, `rosdep check --from-paths src --ignore-src`의 결과를 확인합니다.
:::

:::task 심화 과제
3. Playground ② 실험을 확장해, 타이머 콜백 안에서 `time.sleep(1.0)`을 호출하면 같은 노드의 다른 타이머와 구독 콜백이 어떻게 되는지 측정합니다. 콜백 안에서 오래 걸리는 일을 하면 안 되는 이유를 정리합니다.
4. 오버레이 실험: `~/hiwonder_ws/src`에 공식 패키지와 이름이 같은 빈 패키지(예: `peripherals`)를 만들어 빌드·source하면 `ros2 pkg prefix peripherals`가 어떻게 바뀌는지 확인합니다. 실험 후 반드시 그 패키지를 지우고 `build/ install/`을 정리한 뒤 새 터미널을 엽니다.
:::
