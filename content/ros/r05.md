## 학습 목표

- `declare_parameter` / `get_parameter` / `set_parameters`로 노드 설정값을 다루고, `add_on_set_parameters_callback`으로 **위험한 값을 거부**하는 검증기를 만듭니다.
- `ros2 param list/get/set/dump/load`와 YAML 파라미터 파일의 형식을 설명합니다.
- Python launch 파일로 여러 노드를 한 번에 띄우고, 리매핑(remapping)·launch 인자·YAML 파라미터·다른 launch 포함(include)을 사용합니다.
- DDS의 데이터 중심 구조와 QoS 정책(신뢰성·이력·내구성·기한)을 설명하고, 발행자·구독자 QoS의 **호환 규칙**을 실험으로 확인합니다.
- `ROS_DOMAIN_ID`로 PC와 MentorPi를 같은 그룹으로 묶어 분산 통신을 구성합니다.

## 파라미터(Parameter)

파라미터는 **노드가 가진 이름-값 설정**입니다. 코드를 고치지 않고 실행할 때(또는 실행 중에) 속도 한계, 프레임 이름, 보정 계수 같은 값을 바꿀 수 있게 해 줍니다.

:::info ROS 1과의 차이
ROS 1에는 모든 노드가 공유하는 중앙 "파라미터 서버"가 있었습니다. ROS 2에서는 **각 노드가 자기 파라미터를 소유**하고, 다른 노드는 서비스(`/노드/get_parameters`, `/노드/set_parameters` …)를 통해 읽고 씁니다. 그래서 `ros2 param` 명령에는 항상 노드 이름이 들어갑니다.
:::

### 선언과 사용

| 코드 | 하는 일 |
|---|---|
| `self.declare_parameter('speed', 0.1)` | 이름과 **기본값**을 등록. 기본값의 타입(double)이 파라미터 타입이 됨 |
| `self.get_parameter('speed').value` | 현재 값 읽기 (원본은 `.get_parameter_value().string_value`처럼 타입별 필드로 읽음) |
| `self.set_parameters([Parameter('speed', Parameter.Type.DOUBLE, 0.15)])` | 노드 스스로 값 바꾸기 |
| `self.add_on_set_parameters_callback(cb)` | 누가 값을 바꾸려 할 때 **먼저 검사**. `SetParametersResult(successful=False)`를 돌려주면 거부 |

선언하지 않은 파라미터는 `get_parameter`에서 예외가 납니다. 명령행이나 YAML로 준 값은 `declare_parameter`의 기본값보다 우선합니다.

원본 `param_demo`는 1초마다 `my_parameter`를 출력한 뒤 **곧바로 다시 `'hiwonder'`로 되돌립니다.** 그래서 `ros2 param set minimal_param_node my_parameter world`를 입력하면 `Hello world!`가 **한 번만** 찍히고 다시 `Hello hiwonder!`로 돌아갑니다. 실습 ①에서 확인합니다.

### 명령행과 YAML

```bash
ros2 param list /minimal_param_node
ros2 param get  /minimal_param_node my_parameter
ros2 param set  /minimal_param_node my_parameter world
ros2 param dump /odom_publisher > odom_params.yaml        # 현재 값을 YAML로 저장
ros2 param load /odom_publisher odom_params.yaml          # 파일의 값을 적용
ros2 run param_demo param_demo --ros-args -p my_parameter:=mentorpi   # 시작할 때 지정
ros2 run param_demo param_demo --ros-args --params-file my.yaml
```

YAML 형식은 **노드 이름 → `ros__parameters` → 이름: 값**입니다(밑줄 두 개). 원본 `launch_demo/config/turtlesim.yaml`:

```yaml
/turtlesim2/sim:              # 네임스페이스/노드이름
   ros__parameters:
      background_b: 0
      background_g: 0
      background_r: 0
```

## Launch: 여러 노드를 한 번에

실물 로봇에는 노드가 수십 개 있습니다. 터미널을 열 때마다 `ros2 run`을 입력할 수는 없으므로 **launch 파일**로 묶습니다. ROS 2 launch는 XML·YAML·Python을 지원하며, 조건문·경로 계산 같은 로직이 필요한 MentorPi 공식 launch는 모두 Python입니다. 기본 구조는 "**액션(action) 목록을 담은 `LaunchDescription`을 돌려주는 함수**"입니다.

```python
def generate_launch_description():
    return LaunchDescription([action_1, action_2, ...])
```

### 원본 launch_demo의 다섯 가지 패턴

| 파일 | 핵심 요소 | 효과 |
|---|---|---|
| `single_node.launch.py` | `Node(package, executable)` | 노드 1개 실행 |
| `multi_node.launch.py` | `Node` 두 개 | `topic_pub`와 `topic_sub` 동시 실행 |
| `remapping.launch.py` | `remappings=[("/topic", "topic_pub")]` | 토픽 이름을 코드 수정 없이 변경 |
| `param.launch.py` | `DeclareLaunchArgument` + `LaunchConfiguration` | `background_r:=255`처럼 **launch 인자**를 받아 노드 파라미터로 전달 |
| `param_yaml.launch.py` | `parameters=[config]`, `namespace` | YAML 파일로 파라미터 일괄 적용 |
| `launch_include.launch.py` | `IncludeLaunchDescription` | 다른 launch 파일을 부품처럼 포함 |

멀티 노드와 리매핑 예입니다.

```python
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(package='topic_demo', executable='topic_pub',
             remappings=[('/topic', '/chatter')]),            # 발행 토픽 이름 바꾸기
        Node(package='topic_demo', executable='topic_sub',
             remappings=[('/topic', '/chatter')]),            # 구독도 똑같이 바꿔야 연결됨
    ])
```

launch 인자와 YAML을 함께 쓰는 예입니다(원본 `param.launch.py`, `param_yaml.launch.py` 요약).

```python
import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node

def generate_launch_description():
    config = os.path.join(get_package_share_directory('launch_demo'), 'config', 'turtlesim.yaml')
    return LaunchDescription([
        DeclareLaunchArgument('background_r', default_value='0'),
        Node(package='turtlesim', executable='turtlesim_node', name='sim',
             parameters=[{'background_r': LaunchConfiguration('background_r')}]),
        Node(package='turtlesim', executable='turtlesim_node', name='sim',
             namespace='turtlesim2', parameters=[config]),
    ])
```

launch 파일과 YAML은 Python 모듈이 아니므로 `setup.py`의 `data_files`에 등록해야 `install/.../share/launch_demo/`로 복사되고, `ros2 launch`가 찾을 수 있습니다.

```python
(os.path.join('share', package_name, 'launch'), glob(os.path.join('launch', '*.launch.py'))),
(os.path.join('share', package_name, 'config'), glob(os.path.join('config', '*.*'))),
```

MentorPi 공식 `controller.launch.py`도 같은 부품으로 되어 있습니다. `odom_publisher.launch.py`와 `imu_filter.launch.py`를 `IncludeLaunchDescription`으로 포함하고, `robot_localization`의 `ekf_node`를 `remappings=[('odometry/filtered', 'odom'), ...]`로 띄워 **EKF 결과가 `/odom`이 되도록** 합니다.

## DDS와 QoS

### 데이터 중심 통신

DDS(Data Distribution Service)는 OMG가 2004년 표준화한 실시간 발행/구독 미들웨어입니다. 통신 구조를 네 가지로 나눠 보면 DDS의 위치가 보입니다.

| 모델 | 방식 | 문제 |
|---|---|---|
| 점대점(point-to-point) | 클라이언트가 서버 주소로 직접 연결 | 노드가 늘면 연결 수 폭증, 서버 주소 변경에 취약 |
| 브로커(broker) | 중앙 브로커가 중계 (ROS 1 마스터와 유사) | 브로커가 병목·단일 장애점 |
| 브로드캐스트 | 모두에게 방송 | 관계없는 메시지까지 모두 처리해야 함 |
| **데이터 중심(data-centric)** | 공유 데이터 공간에서 "토픽(데이터)"만 보고 발행·구독 | 탐색·QoS로 필요한 상대에게만 직접 전달 — **DDS** |

ROS 2의 토픽·서비스·액션은 모두 DDS 위에서 구현됩니다. ROS 2는 `rmw`(ROS middleware) 계층으로 DDS 구현을 교체할 수 있게 해 두었고, Humble 기본값은 eProsima **Fast DDS**입니다(`RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`로 Cyclone DDS 선택 가능).

:::info 전송 방식에 대한 정정
원본 교재의 분산 통신 비교에는 ROS 2가 ZeroMQ를 기본으로 쓴다는 문장이 있지만, ROS 2의 기본 통신은 **DDS 표준의 RTPS 프로토콜(주로 UDP 멀티캐스트 탐색 + UDP 유니캐스트 데이터)** 입니다. 같은 호스트 안에서는 공유 메모리 전송을 쓰기도 합니다.
:::

### QoS 정책

| 정책 | 값 | 의미 |
|---|---|---|
| Reliability | `RELIABLE` / `BEST_EFFORT` | 재전송으로 도착 보장 / 늦으면 버림(최신성 우선) |
| History | `KEEP_LAST` + depth / `KEEP_ALL` | 보관할 샘플 수 |
| Durability | `VOLATILE` / `TRANSIENT_LOCAL` | 늦게 합류한 구독자에게 과거 샘플을 줄지 |
| Deadline | 기간 | 이 기간 안에 새 샘플이 없으면 이벤트 발생 |
| Lifespan | 기간 | 오래된 샘플은 전달하지 않음 |
| Liveliness | `AUTOMATIC` 등 + lease | 발행자가 살아 있는지 판단 |

@fig[r05-qos] QoS 호환 규칙 — 발행자가 약속한 품질이 구독자가 요구한 품질보다 같거나 높아야 연결됩니다

호환 규칙은 "**요구(구독자) ≤ 제공(발행자)**"입니다. 구독자가 `RELIABLE`을 요구하는데 발행자가 `BEST_EFFORT`만 제공하면 연결되지 않고, 반대(발행 RELIABLE, 구독 BEST_EFFORT)는 연결됩니다. Durability도 같아서 구독자가 `TRANSIENT_LOCAL`을 요구하면 발행자도 `TRANSIENT_LOCAL`이어야 합니다.

원본 교재의 CLI 실험을 그대로 해 볼 수 있습니다.

```bash
ros2 topic pub /chatter std_msgs/msg/Int32 "data: 42" --qos-reliability best_effort   # 터미널 1
ros2 topic echo /chatter --qos-reliability reliable       # 터미널 2 → 아무것도 안 나옴 (+ 경고)
ros2 topic echo /chatter --qos-reliability best_effort    # 터미널 3 → data: 42
ros2 topic info /chatter -v                               # 양쪽 QoS 확인
```

원본 `DDS_qos_demo`는 발행·구독 모두 `QoSProfile(reliability=RELIABLE, history=KEEP_LAST, depth=1)`을 씁니다. 가장 최근 1개만 신뢰성 있게 전달하는 설정이라 **느린 구독자는 중간 메시지를 건너뛰고 최신 값만** 받습니다. 제어 명령에 알맞은 설정입니다.

## 분산 통신과 ROS_DOMAIN_ID

같은 네트워크에 있는 ROS 2 노드는 **같은 도메인 ID**이면 자동으로 서로를 찾습니다. 기본값은 0이므로 교실의 모든 로봇과 PC가 설정 없이 한 그래프로 섞입니다. 그룹을 나누려면 도메인 ID를 다르게 줍니다.

```bash
echo $ROS_DOMAIN_ID                            # 비어 있으면 0
echo "export ROS_DOMAIN_ID=25" >> ~/.bashrc    # 로봇 컨테이너와 PC 모두 같은 값
source ~/.bashrc
```

도메인 ID는 DDS가 쓰는 UDP 포트 번호를 정합니다(대략 $포트 = 7400 + 250 × ID + …$). 그래서 0~101 범위를 권장합니다(원본 교재 권장). 조별 실습이라면 "조 번호 + 10"처럼 겹치지 않게 정합니다.

| ROS 1 분산 통신 | ROS 2 분산 통신 |
|---|---|
| `ROS_MASTER_URI`로 마스터 주소 지정 | 마스터 없음, 멀티캐스트 탐색 |
| 마스터에 등록해야 상대를 찾음 | 노드끼리 직접 탐색·연결 |
| 마스터가 죽으면 새 연결 불가 | 한 노드가 꺼져도 나머지는 계속 통신 |
| `ROS_IP`/`ROS_HOSTNAME` 설정 필요 | 같은 서브넷·같은 `ROS_DOMAIN_ID`면 충분 |

:::warning 분산 통신이 안 될 때 확인할 것
1. 두 기기가 **같은 서브넷**인가(`ping`). 로봇이 AP 모드면 PC가 로봇 Wi-Fi에 접속해야 합니다.
2. **도메인 ID**가 같은가, `ROS_LOCALHOST_ONLY=1`이 켜져 있지 않은가.
3. Docker 컨테이너가 `--network=host`로 실행되었는가(공식 이미지는 그렇게 되어 있음).
4. 방화벽·공유기가 **UDP 멀티캐스트**를 막지 않는가(학교·회사 Wi-Fi에서 흔함).
5. **RMW 구현**이 같은가(서로 다른 DDS끼리도 대개 통신되지만 문제의 원인이 되기 쉬움).
:::

### ① 원본 param_demo 동작 확인

`ros2 param set`을 흉내 내려고 2.5초에 한 번 외부에서 값을 바꾸는 타이머를 추가했습니다.

```python run
import rclpy
from rclpy.node import Node
from rclpy.parameter import Parameter
import mentorpi_sim as sim                  # 시뮬 전용
sim.setup(world="empty", duration=4.6)     # 시뮬 전용


class MinimalParam(Node):
    def __init__(self):
        super().__init__('minimal_param_node')
        self.declare_parameter('my_parameter', 'hiwonder')
        self.timer = self.create_timer(1.0, self.timer_callback)

    def timer_callback(self):
        my_param = self.get_parameter('my_parameter').value
        self.get_logger().info('Hello %s!' % my_param)
        # 원본과 같이: 출력 후 곧바로 기본값으로 되돌림
        self.set_parameters([Parameter('my_parameter', Parameter.Type.STRING, 'hiwonder')])


rclpy.init()
node = MinimalParam()

def fake_cli_set():                          # "ros2 param set ... my_parameter world" 흉내
    node.set_parameters([Parameter('my_parameter', Parameter.Type.STRING, 'world')])
    print('>> ros2 param set minimal_param_node my_parameter world')
    once.cancel()

once = node.create_timer(2.5, fake_cli_set)
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.destroy_node()
    rclpy.shutdown()
```

### ② 안전한 파라미터: 속도 제한 검증기

주행 속도를 파라미터로 받되, 0.2 m/s를 넘는 값은 **콜백에서 거부**합니다. 실물 공식 노드의 속도 제한과 같은 목적을 파라미터 수준에서 구현하는 것입니다.

```python run
import rclpy
from rclpy.node import Node
from rclpy.parameter import Parameter
from rcl_interfaces.msg import SetParametersResult
from geometry_msgs.msg import Twist
from nav_msgs.msg import Odometry
import mentorpi_sim as sim                                        # 시뮬 전용
sim.setup(world="empty", duration=6.5, start=(0.0, 0.0, 0.0))   # 시뮬 전용

MAX_SPEED = 0.2


class SafeCruise(Node):
    def __init__(self):
        super().__init__('safe_cruise')
        self.declare_parameter('speed', 0.1)
        self.add_on_set_parameters_callback(self.check_params)
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_subscription(Odometry, '/odom', self.on_odom, 10)
        self.x = 0.0
        self.create_timer(0.1, self.on_timer)

    def check_params(self, params):
        for p in params:
            if p.name == 'speed' and not (0.0 <= p.value <= MAX_SPEED):
                return SetParametersResult(successful=False,
                                           reason='speed는 0~%.1f m/s' % MAX_SPEED)
        return SetParametersResult(successful=True)

    def on_odom(self, msg):
        self.x = msg.pose.pose.position.x

    def on_timer(self):
        cmd = Twist()
        cmd.linear.x = self.get_parameter('speed').value
        self.pub.publish(cmd)


rclpy.init()
node = SafeCruise()

def try_set(v):
    r = node.set_parameters([Parameter('speed', Parameter.Type.DOUBLE, v)])[0]
    print('speed=%.2f 요청 → %s %s' % (v, '적용' if r.successful else '거부:', r.reason))

steps = iter([0.15, 0.5, 0.0])
def change():
    try_set(next(steps, 0.0))
    print('   현재 speed=%.2f, x=%.2f m' % (node.get_parameter('speed').value, node.x))

node.create_timer(2.0, change)
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.pub.publish(Twist())
    node.destroy_node()
    rclpy.shutdown()
```

예상 출력(대략):

```text
speed=0.15 요청 → 적용
   현재 speed=0.15, x=0.20 m
speed=0.50 요청 → 거부: speed는 0~0.2 m/s
   현재 speed=0.15, x=0.50 m
speed=0.00 요청 → 적용
   현재 speed=0.00, x=0.80 m
```

실물에서는 `ros2 param set /safe_cruise speed 0.5`를 입력하면 `Setting parameter failed: speed는 0~0.2 m/s`가 나옵니다.

### ③ QoS 호환 실험

BEST_EFFORT 발행자 하나에 RELIABLE 구독자와 BEST_EFFORT 구독자를 붙여, 각각 몇 개를 받는지 셉니다.

```python run
import time
import rclpy
from rclpy.node import Node
from rclpy.qos import QoSProfile, ReliabilityPolicy, HistoryPolicy
from std_msgs.msg import Int32
import mentorpi_sim as sim                  # 시뮬 전용
sim.setup(world="empty", duration=5.0)     # 시뮬 전용

best_effort = QoSProfile(reliability=ReliabilityPolicy.BEST_EFFORT,
                         history=HistoryPolicy.KEEP_LAST, depth=10)
reliable = QoSProfile(reliability=ReliabilityPolicy.RELIABLE,
                      history=HistoryPolicy.KEEP_LAST, depth=10)

rclpy.init()
node = Node('qos_lab')
pub = node.create_publisher(Int32, '/chatter', best_effort)
got = {'reliable_sub': 0, 'best_effort_sub': 0}

def counter(key):
    def cb(msg):
        got[key] += 1
    return cb

node.create_subscription(Int32, '/chatter', counter('reliable_sub'), reliable)
node.create_subscription(Int32, '/chatter', counter('best_effort_sub'), best_effort)

n = {'sent': 0}
def tick():
    pub.publish(Int32(data=42))
    n['sent'] += 1
node.create_timer(0.1, tick)

t0 = time.time()
while time.time() - t0 < 2.0:
    rclpy.spin_once(node, timeout_sec=0.05)
print('발행: %d개 (BEST_EFFORT)' % n['sent'])
for k, v in got.items():
    print('%-16s 받음: %d' % (k, v))
node.destroy_node()
rclpy.shutdown()
```

예상 출력(대략):

```text
발행: 20개 (BEST_EFFORT)
reliable_sub     받음: 0
best_effort_sub  받음: 19
```

마지막 20번째 메시지는 루프가 끝나는 순간 발행되어 콜백이 아직 실행되지 않았기 때문에 19개입니다.

## 실습 (실물)

:::safety
- launch로 여러 노드를 띄우기 전에 `~/.stop_ros.sh`로 자동 실행을 멈춰 **같은 노드가 두 번 뜨지 않게** 합니다.
- 분산 통신 실습에서 PC가 로봇에 `/cmd_vel`을 보낼 수 있게 되면 **다른 조의 로봇도 움직일 수 있습니다.** 반드시 조마다 다른 `ROS_DOMAIN_ID`를 쓰고, 주행 명령 전에 `ros2 node list`로 내 로봇인지 확인합니다.
- ②를 실물에서 실행할 때는 앞쪽 1.5 m를 비웁니다.
:::

1. `launch_demo` 패키지를 만들고 launch·config 폴더를 등록합니다.

```bash
cd ~/hiwonder_ws/src
ros2 pkg create launch_demo --build-type ament_python --dependencies rclpy
mkdir -p launch_demo/launch launch_demo/config
# launch/*.launch.py, config/turtlesim.yaml 작성, setup.py data_files 등록
cd ~/hiwonder_ws && colcon build --packages-select launch_demo && source install/setup.bash
ros2 launch launch_demo multi_node.launch.py
ros2 launch launch_demo remapping.launch.py          # 다른 터미널: ros2 topic list → /topic_pub
ros2 launch launch_demo param.launch.py background_r:=255
ros2 launch launch_demo param_yaml.launch.py
ros2 launch launch_demo launch_include.launch.py
ros2 launch launch_demo param.launch.py --show-args  # 받을 수 있는 인자 목록
```

2. MentorPi 노드의 파라미터를 살펴봅니다.

```bash
ros2 launch controller controller.launch.py                   # 터미널 1
ros2 param list /odom_publisher                               # 터미널 2
ros2 param get /odom_publisher linear_correction_factor
ros2 param dump /odom_publisher > ~/odom_publisher.yaml
```

3. QoS 데모를 빌드해 실행하고, CLI로 QoS를 바꿔 구독해 봅니다.

```bash
ros2 run DDS_qos_demo DDS_qos_pub                              # 터미널 1
ros2 run DDS_qos_demo DDS_qos_sub                              # 터미널 2
ros2 topic info /topic -v                                      # Reliability: RELIABLE, depth 1
```

4. PC(ROS 2 Humble 설치)와 로봇을 같은 Wi-Fi에 두고 양쪽에 같은 `ROS_DOMAIN_ID`를 설정한 뒤, PC에서 로봇의 토픽을 봅니다.

```bash
# 로봇 컨테이너와 PC 모두
export ROS_DOMAIN_ID=25
# PC에서
ros2 topic list                # 로봇의 /odom, /imu ... 가 보이면 성공
ros2 topic hz /odom            # Wi-Fi에서는 로봇 내부보다 불규칙할 수 있음
```

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `ParameterNotDeclaredException` | `declare_parameter` 없이 `get_parameter` | 생성자에서 먼저 선언 |
| `InvalidParameterTypeException` | double로 선언한 파라미터에 정수 `1`을 설정 | `1.0`처럼 타입 맞추기, CLI는 `speed 0.1` |
| YAML이 적용되지 않음 | 최상위 키가 노드 이름과 다름, `ros__parameters` 오타(밑줄 1개) | `/네임스페이스/노드이름:` → `ros__parameters:` 확인 |
| `file 'x.launch.py' was not found in the share directory` | `setup.py` `data_files`에 launch 폴더 미등록 또는 재빌드 안 함 | `data_files` 등록 후 `colcon build` |
| 리매핑했더니 통신이 끊김 | 발행자만 리매핑하고 구독자는 옛 이름 | 양쪽 모두 같은 이름으로 리매핑 |
| `offering incompatible QoS` 경고, 메시지 없음 | 발행 BEST_EFFORT ↔ 구독 RELIABLE | 구독을 BEST_EFFORT(`qos_profile_sensor_data`)로 |
| 늦게 켠 노드가 `/map`을 못 받음 | Durability 불일치(발행 TRANSIENT_LOCAL, 구독 VOLATILE이면 과거 값 못 받음) | 구독도 `TRANSIENT_LOCAL` |
| PC에서 로봇 토픽이 안 보임 | 도메인 ID 불일치, 다른 서브넷, 멀티캐스트 차단 | 위 "분산 통신이 안 될 때" 5단계 점검, `ros2 doctor --report` |
| 남의 로봇 토픽이 보임 | 기본 도메인 0을 모두가 사용 | 조별 `ROS_DOMAIN_ID` 지정 |

## 과제

:::task 기본 과제
1. ②의 `SafeCruise`에 `angular` 파라미터(0~0.5 rad/s)를 추가하고, 두 파라미터를 YAML 파일로 한 번에 적용하는 launch 파일을 작성합니다.
2. `multi_node.launch.py`를 고쳐 `topic_pub` 두 개를 서로 다른 이름(`pub_a`, `pub_b`)과 서로 다른 리매핑으로 띄우고, `ros2 node list`·`ros2 topic list` 결과를 캡처합니다.
:::

:::task 심화 과제
3. ③을 확장해 depth=1과 depth=10, 발행 50 Hz·구독 처리 시간 50 ms인 상황에서 받은 메시지 수와 "가장 오래된 메시지의 나이"를 비교합니다. 제어 명령에 depth를 작게 쓰는 이유를 정리합니다.
4. 조별로 PC 1대 + 로봇 1대를 같은 도메인으로 묶고, PC에서 실행한 ② 노드가 로봇을 움직이게 합니다. Wi-Fi에서 `/odom`의 `ros2 topic hz`·`ros2 topic delay`를 측정해 로봇 내부와 비교합니다.
:::
