## 학습 목표

- ROS 2가 "운영체제"가 아니라 노드 사이의 통신을 맡는 **미들웨어(middleware)** 라는 점을 설명하고, ROS 1과의 차이(마스터 유무, DDS, 빌드 도구, Python 버전)를 표로 정리합니다.
- 노드(node)·토픽(topic)·서비스(service)·액션(action)·파라미터(parameter)로 이루어진 **ROS 2 계산 그래프**를 그림으로 그릴 수 있습니다.
- MentorPi가 ROS 2 Humble을 **Docker 컨테이너** 안에서 실행하는 구조를 이해하고, 컨테이너에 들어가 환경을 불러올(`source`) 수 있습니다.
- `ros2 pkg / run / node / topic / service / param / interface / bag` 명령으로 실행 중인 로봇의 그래프를 관찰합니다.
- Playground에서 첫 rclpy 노드를 실행하고, `ros2 topic echo`·`ros2 topic hz`가 하는 일을 Python 코드로 흉내 냅니다.

## ROS 2란 무엇인가

ROS(Robot Operating System)는 이름과 달리 Linux 같은 운영체제가 아닙니다. 로봇 소프트웨어를 **작은 프로그램(노드) 여러 개**로 나누고, 그 프로그램들이 정해진 형식의 데이터를 주고받게 해 주는 **통신 프레임워크 + 도구 모음 + 패키지 생태계**입니다.

MentorPi를 예로 들면 다음 프로그램들이 **각각 독립된 노드**로 동시에 돌아갑니다.

| 노드(예) | 하는 일 | 주고받는 데이터 |
|---|---|---|
| 라이다 드라이버 | LD19 라이다에서 거리값을 읽음 | `LaserScan` 발행 |
| `odom_publisher` (controller 패키지) | 속도 명령을 바퀴 속도로 바꾸고 오도메트리 계산 | `Twist` 구독, `Odometry` 발행 |
| `ros_robot_controller` | 확장보드(RRC Lite)와 시리얼 통신 | 모터·서보 명령 구독, IMU·배터리 발행 |
| 앱 노드 (라이다 회피 등) | 센서를 보고 판단 | `LaserScan` 구독, `Twist` 발행 |

노드를 나누면 한 노드가 죽어도 나머지는 살아 있고, 라이다 드라이버처럼 **남이 만든 노드를 그대로 가져다 쓸 수** 있습니다. 이 "느슨한 결합"이 ROS를 쓰는 가장 큰 이유입니다.

### ROS 1과 ROS 2

ROS 2는 2017년 첫 배포판(Ardent)이 나온 **2세대 ROS**입니다. ROS 1의 구조적 한계(단일 마스터, 실시간성 부족, 불안정한 무선망 대응)를 해결하려고 통신 계층을 처음부터 다시 설계했습니다.

| 항목 | ROS 1 | ROS 2 |
|---|---|---|
| 노드 연결 | `roscore`(마스터)에 등록한 뒤 연결 | 마스터 없음. **DDS 탐색(discovery)** 으로 서로 찾음 |
| 통신 계층 | 자체 TCPROS/UDPROS | DDS(Data Distribution Service) 표준, RTPS 프로토콜 |
| 통신 품질 설정 | 큐 크기 정도 | **QoS** 정책(신뢰성·내구성·이력·기한 등) |
| 지원 OS | 사실상 Ubuntu | Ubuntu, Windows, macOS, 임베디드 |
| 언어 | C++03, Python 2 | C++11/14 이상, Python 3 |
| 빌드 | `catkin_make` | `colcon build` |
| 실행 파일 묶음 | `.launch`(XML) | `.launch.py`(Python), XML, YAML |
| 여러 로봇 분리 | `ROS_MASTER_URI` | `ROS_DOMAIN_ID` |

마스터가 없다는 것은 **마스터가 죽으면 전체가 멈추는 단일 장애점(single point of failure)이 없다**는 뜻입니다. 대신 같은 네트워크·같은 도메인 ID의 노드는 자동으로 서로를 찾으므로, 여러 명이 한 교실에서 실습할 때는 도메인 ID를 나눠야 합니다(R05).

### 배포판과 Ubuntu 버전

ROS 2는 배포판(distribution)마다 대응하는 Ubuntu 버전이 정해져 있습니다.

| ROS 2 배포판 | Ubuntu | 비고 |
|---|---|---|
| Foxy Fitzroy | 20.04 | LTS, 지원 종료(2023-05) |
| Galactic Geochelone | 20.04 | 단기 지원, 종료 |
| **Humble Hawksbill** | **22.04** | LTS, 2027-05까지 지원 — **MentorPi 사용** |
| Jazzy Jalisco | 24.04 | 차기 LTS |

MentorPi의 Raspberry Pi 5는 호스트 OS가 Raspberry Pi OS(Debian 계열)입니다. Humble은 Ubuntu 22.04용으로 배포되므로, 공식 이미지는 **Ubuntu 22.04 + ROS 2 Humble이 설치된 Docker 컨테이너**를 띄워 그 안에서 모든 ROS 프로그램을 돌립니다(B10에서 배운 구조).

## ROS 2 계산 그래프

실행 중인 노드와 그 사이의 연결 전체를 **계산 그래프(computation graph)** 라고 부릅니다.

@fig[r01-graph] MentorPi의 ROS 2 계산 그래프 예 — 노드(둥근 상자)는 DDS 데이터 버스를 통해 토픽·서비스로 직접 연결되며 중앙 마스터가 없습니다

| 용어 | 뜻 | MentorPi 예 |
|---|---|---|
| 노드(Node) | 하나의 기능을 맡는 실행 단위. 한 프로세스에 여러 개가 있을 수도 있음 | `odom_publisher`, `lidar_controller` |
| 메시지(Message) | 정해진 필드를 가진 데이터 형식 | `geometry_msgs/msg/Twist` |
| 토픽(Topic) | 이름 붙은 **단방향·비동기** 데이터 흐름. 발행자(publisher) → 구독자(subscriber) | `/cmd_vel`, `/odom`, `/scan` |
| 서비스(Service) | **요청-응답** 한 번으로 끝나는 호출. 서버(server)와 클라이언트(client) | `/controller/load_calibrate_param` (`std_srvs/srv/Trigger`) |
| 액션(Action) | 오래 걸리는 작업. 목표(goal) → **피드백(feedback)** 반복 → 결과(result) | Nav2의 `navigate_to_pose` |
| 파라미터(Parameter) | 노드가 가진 설정값(이름-값 쌍). 실행 중 조회·변경 가능 | `linear_correction_factor` |
| 인터페이스(Interface) | `.msg`/`.srv`/`.action` 파일로 정의한 메시지 형식의 총칭 | R04에서 직접 정의 |
| DDS | 노드 탐색과 데이터 전달을 맡는 하부 통신 계층 | Humble 기본은 Fast DDS |

:::info 파일 시스템 쪽 용어
- **패키지(package)**: 노드 소스·설정·launch 파일을 묶는 배포 단위. `package.xml`(매니페스트: 이름·버전·의존성)을 반드시 가집니다.
- **워크스페이스(workspace)**: 패키지들을 모아 빌드하는 폴더(`src/`, `build/`, `install/`, `log/`). R02에서 만듭니다.
- 자주 보는 파일: `package.xml`, `setup.py`(Python 패키지), `CMakeLists.txt`(C++·인터페이스 패키지), `*.launch.py`, `*.urdf`, `msg/*.msg`, `srv/*.srv`.
:::

## MentorPi의 ROS 2 환경

### 컨테이너 들어가기

MentorPi 공식 이미지에서는 ROS 프로그램이 모두 `mentorpi`라는 이름의 컨테이너에 들어 있습니다. VNC로 데스크톱에 접속한 뒤 Terminator를 열고 다음과 같이 들어갑니다.

```bash
docker ps -a                                              # 컨테이너 목록 (이름 mentorpi 확인)
docker exec -it -u ubuntu -w /home/ubuntu mentorpi /bin/bash   # ubuntu 사용자로 컨테이너 셸 열기
```

컨테이너 ID로 들어가도 됩니다(ID는 겹치지 않는 앞부분만 적어도 됨). 공식 이미지의 Terminator는 **열자마자 이 명령이 실행되도록** 미리 설정되어 있어서, 새 창을 열면 곧바로 컨테이너 안입니다.

### 환경 불러오기(source)

ROS 2 명령과 패키지 경로는 `setup.bash`를 `source`해야 셸에 등록됩니다. 두 층이 있습니다.

```bash
source /opt/ros/humble/setup.bash          # ① 기반(underlay): ROS 2 Humble 자체
source ~/ros2_ws/install/setup.bash        # ② 오버레이(overlay): MentorPi 패키지 (app, controller, peripherals ...)
echo $ROS_DISTRO                           # humble 이 나오면 ①이 적용된 것
```

공식 이미지는 두 줄이 컨테이너의 `~/.bashrc`에 이미 들어 있습니다. 직접 만든 워크스페이스(R02의 `~/hiwonder_ws`)를 쓰려면 같은 방식으로 한 줄을 더합니다.

### PC에 직접 설치하려면 (참고)

실습용 PC(Ubuntu)에서 같은 환경을 만들 때는 원본 교재처럼 공식 `ros:humble` 이미지로 컨테이너를 만드는 방법이 가장 간단합니다. 로봇에는 이미 설치되어 있으므로 **로봇에서 다시 하지 마세요.**

```bash
docker pull ros:humble
docker run -it -d --network=host -v /dev:/dev -v /tmp/.X11-unix:/tmp/.X11-unix \
  -e DISPLAY=${DISPLAY} --restart=always --name humble ros:humble /bin/bash
xhost +                                   # 컨테이너의 GUI 창(turtlesim, rviz2)을 호스트 화면에 허용
docker exec -it humble /bin/bash
# --- 컨테이너 안 ---
useradd -m -s /bin/bash ubuntu && passwd ubuntu && usermod -aG sudo ubuntu
apt-get update && apt-get install -y sudo vim ros-humble-desktop-full
exit
docker exec -it -u ubuntu -w /home/ubuntu humble /bin/bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc && source ~/.bashrc
ros2 run turtlesim turtlesim_node          # 거북이 창이 뜨면 설치 성공
```

`--network=host`는 컨테이너가 호스트와 같은 네트워크를 쓰게 해서 **DDS 탐색 패킷(멀티캐스트)이 그대로 오가게** 합니다. 이 옵션이 없으면 PC와 로봇의 노드가 서로 보이지 않습니다.

## 명령행 도구 `ros2`

`ros2 <명령> <하위명령>` 형식이며, 탭(Tab) 자동완성이 됩니다. 실행 중인 그래프를 들여다보는 가장 빠른 방법입니다.

| 명령 | 자주 쓰는 형태 | 하는 일 |
|---|---|---|
| `ros2 pkg` | `list`, `executables <pkg>`, `prefix <pkg>`, `xml <pkg>`, `create` | 패키지 목록·실행파일·설치 경로·매니페스트 확인, 패키지 생성 |
| `ros2 run` | `ros2 run <pkg> <실행파일>` | 노드 하나 실행 |
| `ros2 launch` | `ros2 launch <pkg> <파일.launch.py>` | 여러 노드를 한꺼번에 실행(R05) |
| `ros2 node` | `list`, `info /노드` | 실행 중인 노드와 그 노드의 발행·구독·서비스·액션 |
| `ros2 topic` | `list -t`, `info`, `type`, `find`, `echo`, `hz`, `bw`, `delay`, `pub` | 토픽 관찰·주파수·대역폭·지연 측정, 직접 발행 |
| `ros2 service` | `list -t`, `type`, `call` | 서비스 목록, 직접 호출 |
| `ros2 action` | `list`, `info`, `send_goal` | 액션 목록, 목표 보내기 |
| `ros2 param` | `list`, `get`, `set`, `dump`, `load`, `delete` | 노드 파라미터 조회·변경·저장 |
| `ros2 interface` | `list`, `package`, `packages`, `show`, `proto` | 메시지·서비스·액션 형식 보기 |
| `ros2 bag` | `record`, `info`, `play` | 토픽을 파일에 녹화하고 재생 |
| `ros2 doctor` | `--report` | 환경·네트워크 진단 |

### turtlesim으로 연습하기

```bash
ros2 run turtlesim turtlesim_node            # 터미널 1: 거북이 시뮬레이터
ros2 run turtlesim turtle_teleop_key         # 터미널 2: 방향키로 조종
ros2 node list                               # 터미널 3: /turtlesim, /teleop_turtle
ros2 node info /turtlesim                    # 구독 /turtle1/cmd_vel, 발행 /turtle1/pose ...
ros2 topic echo /turtle1/pose                # 거북이 자세가 계속 출력
ros2 interface show geometry_msgs/msg/Twist  # linear(x,y,z), angular(x,y,z)
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 1.0}, angular: {z: 0.5}}"
ros2 service call /spawn turtlesim/srv/Spawn "{x: 2.0, y: 2.0, theta: 0.0, name: 'turtle2'}"
```

`ros2 topic pub`의 메시지는 **YAML** 형식입니다. 중괄호와 콜론 뒤 공백(`x: 1.0`)을 빠뜨리면 파싱 오류가 납니다.

### ros2 bag: 데이터 녹화와 재생

실험 데이터를 파일로 남겨 두면 로봇 없이도 알고리즘을 다시 돌려 볼 수 있습니다.

```bash
ros2 bag record -o drive_test /odom /scan_raw /imu   # Ctrl+C로 종료 → drive_test/ 폴더 생성
ros2 bag info drive_test                             # 기간, 메시지 수, 토픽별 타입
ros2 bag play drive_test --rate 0.5                  # 0.5배속 재생 (그동안 로봇 노드는 꺼 두기)
```

:::tip 교재와 이 사이트의 역할 분담
`ros2` 명령행 도구, `colcon`, `rqt`, `rviz2`는 **실물 로봇(컨테이너)이나 ROS 2가 설치된 PC** 에서만 됩니다. 이 사이트의 Playground는 rclpy **Python 코드**를 브라우저에서 돌려 주는 도구이므로, 아래 실습에서는 CLI가 하는 일을 코드로 직접 구현해 보며 원리를 익힙니다.
:::

### ① 첫 노드: Hello ROS 2

원본 `hello_world_demo`는 `while rclpy.ok(): ... time.sleep(0.5)` 루프로 로그를 찍습니다. ROS 2에서는 같은 일을 **타이머(timer)** 로 하는 것이 정석입니다(이유는 R02). 여기서는 타이머 버전을 먼저 실행해 봅니다.

```python run
import rclpy
from rclpy.node import Node
import mentorpi_sim as sim                     # 시뮬 전용
sim.setup(world="empty", duration=3.2)        # 시뮬 전용: 약 3초만 실행


class HelloWorldNode(Node):
    def __init__(self):
        super().__init__('hello_world_demo')   # 노드 이름
        self.count = 0
        self.timer = self.create_timer(0.5, self.on_timer)   # 0.5 s마다 호출

    def on_timer(self):
        self.count += 1
        self.get_logger().info('Hello World %d' % self.count)


rclpy.init()
node = HelloWorldNode()
try:
    rclpy.spin(node)             # 콜백을 기다리며 실행 (시뮬에서는 duration에서 끝남)
except KeyboardInterrupt:
    pass
finally:
    print('노드 이름:', node.get_name())
    node.destroy_node()
    rclpy.shutdown()
```

예상 출력(대략, 로그 앞의 타임스탬프 생략):

```text
[INFO] [hello_world_demo]: Hello World 1
[INFO] [hello_world_demo]: Hello World 2
[INFO] [hello_world_demo]: Hello World 3
[INFO] [hello_world_demo]: Hello World 4
[INFO] [hello_world_demo]: Hello World 5
[INFO] [hello_world_demo]: Hello World 6
노드 이름: hello_world_demo
```

3초 동안 0.5초 주기이므로 로그가 약 6번 찍힙니다. 실물에서는 `mentorpi_sim` 두 줄을 지우면 Ctrl+C를 누를 때까지 계속 찍힙니다.

### ② `ros2 topic echo`를 코드로: /odom 한 번 읽기

`ros2 topic echo /odom --once`는 "구독자를 하나 만들어 메시지 한 개를 받고 출력"하는 명령입니다. 똑같이 만들어 봅니다.

```python run
import rclpy
from rclpy.node import Node
from nav_msgs.msg import Odometry
import mentorpi_sim as sim                                   # 시뮬 전용
sim.setup(chassis="mecanum", world="room", duration=5.0)    # 시뮬 전용

rclpy.init()
node = Node('echo_once')
box = []
sub = node.create_subscription(Odometry, '/odom', lambda m: box.append(m), 10)

while rclpy.ok() and not box:          # 첫 메시지가 올 때까지 조금씩 돌린다
    rclpy.spin_once(node, timeout_sec=0.1)

m = box[0]
p = m.pose.pose.position
q = m.pose.pose.orientation
print('header.frame_id:', m.header.frame_id)
print('child_frame_id :', m.child_frame_id)
print('position       : x=%.3f y=%.3f z=%.3f' % (p.x, p.y, p.z))
print('orientation    : x=%.3f y=%.3f z=%.3f w=%.3f' % (q.x, q.y, q.z, q.w))
print('twist.linear.x : %.3f' % m.twist.twist.linear.x)
node.destroy_node()
rclpy.shutdown()
```

예상 출력(대략):

```text
header.frame_id: odom
child_frame_id : base_footprint
position       : x=0.000 y=0.000 z=0.000
orientation    : x=0.000 y=0.000 z=0.000 w=1.000
twist.linear.x : 0.000
```

로봇이 서 있으므로 위치가 0, 방향 쿼터니언이 단위값 `w=1`입니다. `frame_id`와 `child_frame_id`는 R06의 TF 트리에서 다시 만납니다.

### ③ `ros2 topic hz`를 코드로: 센서 주기 재기

`ros2 topic hz`는 받은 메시지 수를 시간으로 나눈 값입니다. 가상 MentorPi의 세 센서 토픽을 동시에 재 봅니다.

```python run
import time
import rclpy
from rclpy.node import Node
from nav_msgs.msg import Odometry
from sensor_msgs.msg import LaserScan, Imu
import mentorpi_sim as sim                    # 시뮬 전용
sim.setup(world="room", duration=6.0)        # 시뮬 전용

rclpy.init()
node = Node('hz_meter')
count = {'/odom': 0, '/scan': 0, '/imu': 0}

def counter(name):
    def cb(msg):
        count[name] += 1
    return cb

node.create_subscription(Odometry, '/odom', counter('/odom'), 10)
node.create_subscription(LaserScan, '/scan', counter('/scan'), 10)
node.create_subscription(Imu, '/imu', counter('/imu'), 10)

t0 = time.time()
while rclpy.ok() and time.time() - t0 < 5.0:     # 5초 동안 수집
    rclpy.spin_once(node, timeout_sec=0.05)
dt = time.time() - t0
for name, n in count.items():
    print('%-6s %4d msgs  average rate: %5.1f Hz' % (name, n, n / dt))
node.destroy_node()
rclpy.shutdown()
```

예상 출력(대략):

```text
/odom   250 msgs  average rate:  50.0 Hz
/scan    50 msgs  average rate:  10.0 Hz
/imu    250 msgs  average rate:  50.0 Hz
```

:::check 체크포인트
- [ ] 로그가 0.5초마다 한 번씩 찍히는 이유를 타이머 주기로 설명할 수 있다.
- [ ] /odom의 `frame_id`와 `child_frame_id`를 말할 수 있다.
- [ ] /scan이 /odom보다 느린 이유(라이다 회전 속도)를 추측할 수 있다.
:::

## 실습 (실물)

:::safety
- 실습 전 배터리 전압을 확인합니다(저전압 경고음이 울리면 충전 후 진행).
- `ros2 topic pub`으로 속도를 보낼 때는 **로봇을 바닥에서 들어 올리거나 바퀴가 뜨도록 받침대 위에** 두고 시작합니다.
- 속도는 선속도 0.1 m/s, 각속도 0.3 rad/s 이하로 시작하고, 끝나면 반드시 0 속도를 한 번 보냅니다.
- `--rate` 옵션으로 계속 발행하는 명령은 Ctrl+C로 멈춘 뒤에도 **마지막 속도가 유지될 수 있으므로** 정지 명령을 따로 보냅니다.
:::

1. 로봇 전원을 켜고 VNC로 접속한 뒤 Terminator를 엽니다(컨테이너 안으로 바로 들어갑니다).
2. 앱 자동 실행 서비스를 멈춥니다. 켜 둔 채로 노드를 또 띄우면 같은 이름의 노드가 둘이 되어 충돌합니다.

```bash
~/.stop_ros.sh
```

3. 모션 제어(섀시 드라이버 + 오도메트리 + IMU 필터 + EKF)를 실행합니다.

```bash
ros2 launch controller controller.launch.py
```

4. 새 터미널에서 그래프를 관찰합니다.

```bash
ros2 node list
ros2 topic list -t                     # 타입까지 함께 표시
ros2 topic info /cmd_vel -v            # 누가 구독하는지 (odom_publisher)
ros2 topic hz /odom
ros2 topic echo /odom --once
ros2 service list -t | grep controller
ros2 param list /odom_publisher
ros2 interface show nav_msgs/msg/Odometry
```

5. 속도 명령을 한 번 보내 보고, 곧바로 정지 명령을 보냅니다. `/cmd_vel`은 원본 `app_cmd_vel_callback`이 선속도 ±0.2 m/s, 각속도 ±0.5 rad/s로 **잘라 주는** 입력입니다.

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.1}, angular: {z: 0.0}}"
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"      # 모든 필드 0 = 정지
```

6. 라이다를 켜고 녹화해 봅니다.

```bash
ros2 launch peripherals lidar.launch.py          # 또 다른 터미널
ros2 topic list | grep scan                      # /scan_raw (이미지 구성에 따라 /scan 도)
ros2 bag record -o first_bag /odom /imu /scan_raw   # 10초 후 Ctrl+C
ros2 bag info first_bag
```

7. 실습을 마치면 각 터미널에서 Ctrl+C로 노드를 끄고, 앱 기능을 다시 쓰려면 로봇을 재부팅합니다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `ros2: command not found` | 컨테이너 밖(호스트 Raspberry Pi OS)에서 실행했거나 `setup.bash`를 source하지 않음 | 프롬프트가 `ubuntu@...` 컨테이너인지 확인. `source /opt/ros/humble/setup.bash` |
| `Package 'controller' not found` | 오버레이 워크스페이스를 source하지 않음 | `source ~/ros2_ws/install/setup.bash` 후 다시 실행 |
| `ros2 node list`에 같은 이름 노드가 2개, 경고 발생 | 자동 실행 앱과 직접 띄운 launch가 겹침 | `~/.stop_ros.sh`로 자동 실행을 멈춘 뒤 다시 launch |
| `ros2 topic echo`에 아무것도 안 나옴 | 발행 노드가 없음 / 토픽 이름 오타 / QoS 불일치 | `ros2 topic info -v /토픽`으로 발행자 수와 QoS 확인(R05) |
| `ros2 topic pub`에서 `yaml` 파싱 오류 | 콜론 뒤 공백 누락, 따옴표 누락 | `"{linear: {x: 0.1}}"`처럼 전체를 큰따옴표로 감싸고 `키: 값` 형식 지키기 |
| turtlesim·rviz2 창이 안 뜸 (`could not connect to display`) | 컨테이너가 X 서버에 접근 못함 | 호스트에서 `xhost +`, 컨테이너 `DISPLAY` 환경변수와 `/tmp/.X11-unix` 마운트 확인 |
| 옆자리 로봇의 토픽이 내 목록에 보임 | 같은 네트워크·같은 `ROS_DOMAIN_ID`(기본 0) | 로봇마다 다른 `ROS_DOMAIN_ID`를 지정(R05) |
| Playground에서 출력이 끝나지 않음 | `while` 루프 종료 조건 없음 | `rclpy.ok()`와 시간 조건을 함께 쓰고, `sim.setup(duration=...)`을 짧게 |
