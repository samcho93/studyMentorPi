## 학습 목표

- 로봇 비전 처리의 4단계(획득 → 전처리 → 특징 추출 → 판단)를 MentorPi의 카메라 토픽과 연결해 설명합니다.
- OpenCV 이미지가 **NumPy 배열**(`shape = (H, W, 3)`, BGR 순서, `uint8`)이라는 점을 이용해 픽셀·ROI·채널을 읽고 바꿉니다.
- `imread`·`imshow`·`waitKey`·`VideoCapture`로 이미지·동영상·카메라 영상을 읽고 표시합니다.
- `line`·`rectangle`·`circle`·`polylines`·`putText`로 인식 결과를 화면에 그려 넣습니다.
- 실물 MentorPi에서 카메라 노드를 켜고 ROS 2 이미지 토픽을 OpenCV 배열로 바꿔 저장합니다.

## 로봇은 어떻게 “보는가”

카메라의 이미지 센서(CMOS)는 빛을 전기 신호로 바꾸고, 이 신호는 **픽셀 격자**의 숫자 배열이 됩니다. 로봇은 이 숫자 배열에서 필요한 정보만 뽑아 “빨간 공이 오른쪽에 있다”, “선이 왼쪽으로 휘었다” 같은 판단을 내립니다. 이 흐름을 머신 비전(machine vision)이라고 부르며, 보통 네 단계로 나눕니다.

@fig[r08-pipeline] 로봇 비전 처리의 4단계와 이 강좌에서 다루는 챕터

| 단계 | 하는 일 | OpenCV 함수 예 | 이 과정의 챕터 |
|---|---|---|---|
| 1. 영상 획득 (acquisition) | 카메라 프레임을 배열로 받기 | `VideoCapture`, `cv_bridge` | R08 |
| 2. 전처리 (preprocessing) | 크기 조정, 잡음 제거, 색 공간 변환 | `resize`, `GaussianBlur`, `cvtColor` | R09 |
| 3. 특징 추출 (feature extraction) | 엣지·영역·윤곽선·코너·특징점 | `Canny`, `inRange`, `findContours`, `ORB` | R10, R11 |
| 4. 판단·분류 (decision) | 위치·크기·종류를 결정하고 로봇 명령으로 | 규칙, PID, 분류기 | A01~A04 |

MentorPi에서 1단계는 깊이 카메라 노드가 담당합니다. 카메라 노드는 컬러 영상을 `/ascamera/camera_publisher/rgb0/image` 토픽(`sensor_msgs/msg/Image`)으로 발행하고, 색 인식·라인 트레이싱·QR 인식 같은 예제 노드가 모두 이 토픽을 구독합니다. 이번 챕터에서는 그 배열을 다루는 기본기를 익힙니다.

:::info OpenCV란
OpenCV(Open Source Computer Vision Library)는 영상 처리·컴퓨터 비전 알고리즘 2,500여 개를 모은 오픈소스 라이브러리입니다. 내부는 C++로 작성되어 빠르고, 파이썬에서는 `import cv2`로 씁니다. 파이썬 바인딩은 이미지를 **NumPy 배열**로 주고받기 때문에 NumPy 연산과 자연스럽게 섞어 쓸 수 있습니다.
:::

## OpenCV 모듈 구조

OpenCV는 여러 층으로 이루어집니다. 가장 아래에는 CPU·GPU 명령을 최적화하는 HAL(Hardware Acceleration Layer)이 있고, 그 위에 핵심 모듈과 확장 모듈(opencv_contrib), 언어 바인딩(Python·Java), 운영체제와 연결되는 입출력 계층이 있습니다. 로봇 코드에서 실제로 자주 만나는 모듈은 다음과 같습니다.

| 모듈 | 내용 | 대표 함수 |
|---|---|---|
| `core` | 기본 자료구조(Mat), 배열 연산 | `add`, `split`, `merge`, `normalize` |
| `imgproc` | 필터·기하 변환·색 변환·윤곽선 | `cvtColor`, `GaussianBlur`, `warpAffine`, `findContours` |
| `imgcodecs` / `videoio` / `highgui` | 파일 입출력, 카메라, 창 표시 | `imread`, `VideoCapture`, `imshow` |
| `video` | 움직임 분석·추적 | `calcOpticalFlowPyrLK` |
| `calib3d` | 카메라 보정, 3차원 재구성 | `calibrateCamera`, `findHomography` |
| `features2d` / `flann` | 특징점 검출·기술·매칭 | `ORB_create`, `BFMatcher`, `FlannBasedMatcher` |
| `objdetect` | 얼굴·QR 코드 등 특정 물체 검출 | `CascadeClassifier`, `QRCodeDetector` |
| `ml` / `dnn` | 고전 머신러닝, 딥러닝 추론 | `ml.SVM_create`, `dnn.readNet` |
| `photo` / `stitching` | 계산 사진학, 파노라마 | `inpaint`, `Stitcher_create` |

특허 문제로 따로 관리되던 알고리즘(예전의 SIFT·SURF)은 `opencv_contrib`의 `xfeatures2d`에 있었습니다. SIFT는 특허가 만료되어 OpenCV 4.4부터 기본 모듈로 들어왔습니다(R11).

## 이미지는 배열이다

OpenCV가 읽은 컬러 이미지는 `(행 수, 열 수, 채널 수)` 모양의 3차원 NumPy 배열입니다. 흑백(grayscale) 이미지는 채널 축이 없는 2차원 배열입니다.

@fig[r08-array] 이미지 좌표와 배열 인덱스 — `img[y, x]`는 (행, 열) 순서이고 채널은 B, G, R 순서입니다

꼭 기억할 규칙이 세 가지 있습니다.

1. **인덱스는 `img[y, x]`(행, 열) 순서**입니다. 반면 `cv2.circle(img, (x, y), …)` 같은 그리기 함수의 좌표는 `(x, y)` 순서입니다. 둘을 섞으면 점이 대각선 반대편에 찍힙니다.
2. **채널 순서는 BGR**입니다. `img[y, x] = [255, 0, 0]`은 파란색입니다. ROS의 `cv_bridge`로 받을 때 `"bgr8"`을 지정하는 것도 이 때문입니다. (MentorPi의 라인 트레이싱 노드처럼 `"rgb8"`로 받는 코드도 있으니, 코드마다 어느 쪽인지 확인해야 합니다.)
3. **자료형은 `uint8`(0~255)**입니다. 255를 넘거나 0보다 작아지는 계산은 NumPy에서는 **순환(wrap-around)**, OpenCV 함수에서는 **포화(saturation)**가 일어납니다.

```python run
import cv2
import numpy as np

img = np.zeros((240, 320, 3), np.uint8)     # 검은 캔버스: 높이 240, 너비 320
img[:, :] = (40, 40, 40)                    # 모든 픽셀을 어두운 회색으로
img[100, 200] = (0, 0, 255)                 # (x=200, y=100) 한 점을 빨강으로
img[20:60, 30:130] = (255, 0, 0)            # ROI(행 20~59, 열 30~129)를 파랑으로

print("shape:", img.shape, " size:", img.size, " dtype:", img.dtype)
print("img[100, 200] =", img[100, 200], "(B, G, R)")
print("빨강 채널만:", img[100, 200, 2])

b, g, r = cv2.split(img)                    # 채널 분리 → 2차원 배열 3개
print("b.shape:", b.shape, " 파랑 픽셀 수:", int(np.count_nonzero(b == 255)))
swapped = cv2.merge([r, g, b])              # 채널 순서를 바꿔 다시 합치기
print("merge 후 ROI 색:", swapped[30, 50])

gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
print("gray.shape:", gray.shape, " ROI 밝기:", gray[30, 50])
cv2.imshow("canvas", img)
cv2.imshow("swapped", swapped)
```

```text
shape: (240, 320, 3)  size: 230400  dtype: uint8
img[100, 200] = [  0   0 255] (B, G, R)
빨강 채널만: 255
b.shape: (240, 320)  파랑 픽셀 수: 4000
merge 후 ROI 색: [  0   0 255]
gray.shape: (240, 320)  ROI 밝기: 29
```

- `img.size`는 `H × W × 채널`의 원소 수입니다. 흑백 이미지인지 알고 싶으면 `len(img.shape) == 2`로 확인합니다.
- `cv2.merge([r, g, b])`는 채널 순서를 바꿔 파랑 사각형을 빨강으로 만듭니다. BGR ↔ RGB 혼동이 생기면 화면에서 **빨강과 파랑이 뒤바뀌어** 보이는 이유입니다.
- 회색 변환 값 29는 `0.114·B + 0.587·G + 0.299·R = 0.114 × 255`에서 나옵니다(R09).

### ROI는 “뷰(view)”다

`roi = img[y1:y2, x1:x2]`는 **새 배열을 만들지 않고 원본의 일부를 가리키는 뷰**입니다. ROI에 그림을 그리면 원본도 바뀝니다. 원본을 보존하려면 `.copy()`를 붙입니다. 라인 트레이싱 노드가 화면 아래쪽 몇 줄만 잘라 처리하는 것(A03)도 이 슬라이싱입니다.

```python run
import cv2
import numpy as np

img = np.full((100, 100), 50, np.uint8)
roi_view = img[10:30, 10:30]           # 뷰
roi_copy = img[60:80, 60:80].copy()    # 복사본
roi_view[:] = 255
roi_copy[:] = 255
print("뷰를 바꾼 뒤 원본 img[20, 20] =", img[20, 20])
print("복사본을 바꾼 뒤 원본 img[70, 70] =", img[70, 70])

# uint8 산술: NumPy는 순환, OpenCV는 포화
a = np.array([[250, 10]], np.uint8)
b = np.array([[10, 20]], np.uint8)
print("numpy a + b =", a + b, "  cv2.add =", cv2.add(a, b))
print("numpy b - a =", b - a, "  cv2.subtract =", cv2.subtract(b, a))
cv2.imshow("view vs copy", img)
```

```text
뷰를 바꾼 뒤 원본 img[20, 20] = 255
복사본을 바꾼 뒤 원본 img[70, 70] = 50
numpy a + b = [[ 4 30]]   cv2.add = [[255  30]]
numpy b - a = [[16 10]]   cv2.subtract = [[ 0 10]]
```

밝기를 더하는 코드를 NumPy `+`로 쓰면 밝은 픽셀이 **검게 뒤집히는** 버그가 생깁니다. 영상 산술에는 `cv2.add`/`cv2.subtract`를 쓰거나, `int16`으로 바꿔 계산한 뒤 `np.clip`으로 자르세요.

## 이미지·동영상 읽기와 표시

### 이미지 파일

```python
img = cv2.imread("camera.png", cv2.IMREAD_COLOR)   # 3채널 BGR (알파 채널 버림)
gray = cv2.imread("camera.png", cv2.IMREAD_GRAYSCALE)
rgba = cv2.imread("logo.png", cv2.IMREAD_UNCHANGED) # 알파 채널까지 그대로
cv2.imshow("window name", img)                      # 창 이름이 같으면 같은 창을 갱신
cv2.waitKey(0)                                      # 키 입력까지 대기 (ms 단위, 0 = 무한)
cv2.destroyAllWindows()
cv2.imwrite("out.jpg", img)                         # 확장자로 형식 결정
```

| 함수 | 주의할 점 |
|---|---|
| `imread(path, flag)` | 파일이 없으면 **예외 없이 `None`**을 돌려줍니다. 바로 `img.shape`를 부르면 `AttributeError`가 납니다. |
| `imshow(name, img)` | 창을 실제로 그리는 것은 `waitKey`입니다. `waitKey` 없이 루프를 돌면 창이 멈춘 것처럼 보입니다. |
| `waitKey(ms)` | 눌린 키의 코드를 돌려주고, 시간 안에 입력이 없으면 `-1`입니다. `ord('q')`와 비교해 종료 키를 만듭니다. |
| `imwrite(path, img)` | 성공 여부를 `True/False`로 돌려줍니다. 폴더가 없으면 `False`입니다. |

Playground에서는 `imshow`가 오른쪽 이미지 패널에 결과를 보여 주고, `waitKey()`는 곧바로 `-1`을 돌려줍니다. 샘플 이미지(`shapes.png`, `colors.png`, `track.png`, `lane.png`, `qr.png`, `scene.png`, `coins.png`)는 `imread`로 바로 읽을 수 있습니다.

```python run
import cv2

for name in ["shapes.png", "colors.png", "track.png", "scene.png"]:
    img = cv2.imread(name)
    if img is None:
        print(name, "읽기 실패")
        continue
    h, w = img.shape[:2]
    print("%-11s %d x %d, 채널 %d, 평균 밝기 %.0f" % (name, w, h, img.shape[2], img.mean()))

img = cv2.imread("scene.png")
small = cv2.resize(img, (320, 240))
cv2.imshow("scene (320x240)", small)
cv2.imshow("scene gray", cv2.cvtColor(small, cv2.COLOR_BGR2GRAY))
```

```text
shapes.png  640 x 480, 채널 3, 평균 밝기 219
colors.png  640 x 480, 채널 3, 평균 밝기 115
track.png   640 x 480, 채널 3, 평균 밝기 205
scene.png   640 x 480, 채널 3, 평균 밝기 147
```

### 동영상과 USB 카메라

동영상은 이미지를 빠르게 바꿔 보여 주는 것이므로, **프레임을 한 장씩 읽어 처리하는 루프**가 기본 구조입니다.

```python robot
import cv2

cap = cv2.VideoCapture(0)          # 0번 카메라 (동영상이면 파일 경로)
while cap.isOpened():
    ok, frame = cap.read()         # ok=False면 프레임을 못 받은 것
    if not ok:
        break
    cv2.imshow("camera", frame)
    if cv2.waitKey(1) & 0xFF == ord('q'):   # 1 ms 대기 → 화면 갱신 + 키 확인
        break
cap.release()
cv2.destroyAllWindows()
```

`waitKey(1)`의 1 ms는 “다음 프레임을 보여 주기 전 기다리는 시간”입니다. 동영상 파일을 원래 속도로 재생하려면 `1000 / fps` ms를 기다립니다. MentorPi에서는 카메라를 ROS 2 드라이버 노드가 점유하므로 `VideoCapture` 대신 **이미지 토픽을 구독**합니다(아래 실물 실습).

## 도형과 글자 그리기

인식 결과를 눈으로 확인하려면 영상 위에 표시를 그려야 합니다. 모든 그리기 함수는 **원본 배열을 직접 바꾸고**, 좌표는 `(x, y)`, 색은 BGR 튜플입니다. `thickness`가 음수(`-1` 또는 `cv2.FILLED`)이면 내부를 채웁니다.

| 함수 | 인자 | 용도 예 |
|---|---|---|
| `cv2.line(img, pt1, pt2, color, thickness)` | 시작·끝점 | 화면 중앙 기준선, 오차 표시 |
| `cv2.rectangle(img, pt1, pt2, color, thickness)` | 대각 두 꼭짓점 | 검출 박스 |
| `cv2.circle(img, center, radius, color, thickness)` | 중심·반지름 | 색 블록 외접원, 중심점 |
| `cv2.polylines(img, [pts], isClosed, color, thickness)` | 꼭짓점 배열 `(N,1,2)` 또는 `(N,2)`, `int32` | QR 코드 테두리, 회전 사각형 |
| `cv2.putText(img, text, org, font, scale, color, thickness)` | `org`는 글자 **왼쪽 아래** | 인식 결과 문자열 |

아래 코드는 MentorPi 색 인식 예제(`color_detect_demo.py`)가 결과를 표시하는 방식을 흉내 낸 HUD입니다. 원본도 검출한 물체에 원을 그리고 화면 왼쪽 아래 `(10, h - 10)`에 `"Color: red"`를 씁니다.

```python run
import cv2
import numpy as np

h, w = 240, 320
img = np.full((h, w, 3), 30, np.uint8)
cv2.line(img, (w // 2, 0), (w // 2, h), (200, 200, 200), 1)            # 화면 중앙선
cv2.rectangle(img, (40, 60), (120, 140), (0, 255, 0), 2)               # 검출 박스
cv2.circle(img, (220, 110), 35, (0, 0, 255), 2)                        # 외접원
cv2.circle(img, (220, 110), 4, (0, 0, 255), -1)                        # 중심점 (채움)
pts = np.array([[150, 200], [190, 170], [230, 200], [190, 230]], np.int32)
cv2.polylines(img, [pts], True, (255, 255, 0), 2)                      # 닫힌 다각형
err = 220 - w // 2
cv2.arrowedLine(img, (w // 2, 110), (220, 110), (0, 255, 255), 2, tipLength=0.2)
cv2.putText(img, "Color: red", (10, h - 10), cv2.FONT_HERSHEY_SIMPLEX, 0.65, (0, 0, 255), 2)
cv2.putText(img, "err_x = %+d px" % err, (10, 25), cv2.FONT_HERSHEY_SIMPLEX, 0.5, (255, 255, 255), 1)
print("원 중심 x = 220, 화면 중앙 x = %d → x 오차 %+d px" % (w // 2, err))
cv2.imshow("HUD", img)
```

```text
원 중심 x = 220, 화면 중앙 x = 160 → x 오차 +60 px
```

:::tip 글자 위치 계산
`cv2.getTextSize(text, font, scale, thickness)`는 `((너비, 높이), baseline)`을 돌려줍니다. 글자를 박스 위쪽에 딱 붙이거나 오른쪽 정렬할 때 씁니다. 한글은 기본 Hershey 폰트로 그릴 수 없으므로 화면 표시는 영문으로 합니다.
:::

## 실습 (실물)

MentorPi의 카메라 노드를 켜고, ROS 2 이미지 메시지를 OpenCV 배열로 바꿔 화면에 표시하고 저장합니다.

:::safety 실물 실습 전 확인
- 이 실습은 바퀴를 움직이지 않지만, 로봇을 **책상 가장자리에서 떨어진 곳**에 두고 배터리 전압을 확인합니다(저전압 경고음이 나면 충전).
- 카메라 케이블(USB)을 전원이 켜진 상태에서 뽑고 꽂지 않습니다.
- `~/.stop_ros.sh`로 앱 자동 실행 서비스를 끄면 휴대폰 앱 기능이 멈춥니다. 실습이 끝나면 반드시 되살립니다.
:::

1. 로봇을 켜고 VNC로 접속한 뒤 터미널에서 앱 자동 실행 서비스를 끕니다.

```bash
~/.stop_ros.sh
```

2. 카메라 노드를 실행하고, 다른 터미널에서 토픽이 나오는지 확인합니다.

```bash
ros2 launch peripherals depth_camera.launch.py
# 새 터미널
ros2 topic list | grep ascamera
ros2 topic hz /ascamera/camera_publisher/rgb0/image
```

3. 아래 노드를 `~/snapshot_node.py`로 저장해 실행합니다. `s` 키를 누르면 현재 프레임을 저장하고, `q`로 끝냅니다.

```python robot
import cv2
import rclpy
from rclpy.node import Node
from cv_bridge import CvBridge
from sensor_msgs.msg import Image


class SnapshotNode(Node):
    def __init__(self):
        super().__init__('snapshot_node')
        self.bridge = CvBridge()
        self.count = 0
        self.create_subscription(Image, '/ascamera/camera_publisher/rgb0/image', self.on_image, 1)

    def on_image(self, msg):
        frame = self.bridge.imgmsg_to_cv2(msg, 'bgr8')   # ROS Image → BGR uint8 배열
        h, w = frame.shape[:2]
        view = frame.copy()
        cv2.putText(view, '%dx%d' % (w, h), (10, h - 10), cv2.FONT_HERSHEY_SIMPLEX, 0.6, (0, 255, 0), 2)
        cv2.imshow('camera', view)
        key = cv2.waitKey(1) & 0xFF
        if key == ord('s'):
            name = '/home/ubuntu/snap_%02d.png' % self.count
            cv2.imwrite(name, frame)
            self.get_logger().info('saved %s' % name)
            self.count += 1
        elif key == ord('q'):
            raise KeyboardInterrupt


def main():
    rclpy.init()
    node = SnapshotNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        cv2.destroyAllWindows()
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

```bash
python3 ~/snapshot_node.py
```

4. 실습이 끝나면 **Docker 컨테이너 밖(시스템 터미널)**에서 앱 서비스를 다시 켭니다. 부저가 울리면 준비된 것입니다.

```bash
sudo systemctl restart start_node.service
```

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `AttributeError: 'NoneType' object has no attribute 'shape'` | `imread` 경로가 틀려 `None`을 받음 | 절대 경로를 쓰거나 `os.path.exists`로 먼저 확인하고, `if img is None:`으로 처리 |
| 창이 뜨지 않거나 회색으로 멈춤 | `waitKey`를 부르지 않음 / SSH 터미널에는 화면이 없음 | 루프마다 `cv2.waitKey(1)`, 화면 표시는 VNC 터미널에서 실행 |
| 빨강과 파랑이 뒤바뀌어 보임 | RGB 배열을 BGR로 해석(또는 반대) | `cv_bridge` 인코딩(`"bgr8"`/`"rgb8"`)을 확인하고 `cv2.cvtColor(img, cv2.COLOR_RGB2BGR)` |
| 점이 엉뚱한 위치에 찍힘 | `img[x, y]`처럼 인덱스 순서를 뒤바꿈 | 배열 인덱스는 `img[y, x]`, 그리기 함수 좌표는 `(x, y)` |
| 밝은 부분이 검게 뒤집힘 | `uint8` NumPy 덧셈의 순환 | `cv2.add`를 쓰거나 `int16`으로 계산 후 `np.clip(…, 0, 255)` |
| `cv2.error: ... (-215:Assertion failed)` in `polylines` | 좌표 배열이 `float` 또는 모양이 틀림 | `np.array(pts, np.int32)`로 바꾸고 `[pts]`처럼 리스트로 감싸기 |
| 카메라 토픽이 안 보임 | 카메라 노드 미실행, 앱 서비스가 카메라 점유 | `~/.stop_ros.sh` 후 `ros2 launch peripherals depth_camera.launch.py` |

## 과제

:::task 기본 과제
1. 320×240 캔버스에 “과녁”(동심원 5개, 바깥부터 흰색·검정·파랑·빨강·노랑)을 그리고, 가운데에 `putText`로 점수를 씁니다. 원의 반지름은 반복문으로 계산합니다.
2. `scene.png`를 읽어 왼쪽 위 1/4 영역만 잘라 채널별 평균(B, G, R)을 출력합니다. 같은 값을 `cv2.mean(roi)`로도 구해 비교합니다.
:::

:::task 심화 과제
3. 실물 스냅숏 노드를 고쳐, 화면 가운데 20×20 픽셀의 평균 BGR 값을 매 프레임 `putText`로 표시하게 만듭니다. 빨강·초록·파랑 물체를 비춰 값이 어떻게 바뀌는지 기록합니다(A01의 색 임계값 조정 준비).
4. `numpy` 브로드캐스팅만으로(반복문 없이) 가로 방향으로 검정 → 흰색이 되는 256×100 그라디언트 이미지를 만들고, `cv2.add`로 밝기 +100을 더한 결과와 NumPy `+ 100` 결과를 나란히 표시해 차이를 설명합니다.
:::
